# [C++] 데이터 연산: 비트 연산자와 상태 관리 최적화

## 1. 소스 코드 (Source Code)

비트 연산자를 활용한 데이터 조작과, **BitFlag**를 이용해 하나의 변수로 여러 논리적 상태(State)를 효율적으로 관리하는 기법

```cpp
#include <iostream>
using namespace std;

// 전역 변수 선언
// unsigned 사용 이유: 우측 시프트(>>) 시 부호 비트(MSB)가 채워지는 현상(Arithmetic Shift)을 방지하기 위함
unsigned char flag;

int main()
{
    // 1. 비트 연산자 (Bitwise Operators) 기초

    // ~ (NOT): 모든 비트 반전 (0->1, 1->0) (1의 보수)
    // & (AND): 두 비트가 모두 1일 때만 1
    // | (OR) : 두 비트 중 하나라도 1이면 1
    // ^ (XOR): 두 비트가 서로 다를 때 1 (같으면 0)

    // << (Left Shift)
    // - 비트 열을 N만큼 왼쪽으로 이동
    // - 빈 공간은 0으로 채움, 값은 2^N 배 증가
    // - 예: 1 << 1 (1 * 2), 1 << 2 (1 * 4)

    // >> (Right Shift)
    // - 비트 열을 N만큼 오른쪽으로 이동
    // - unsigned의 경우 빈 공간 0 채움 (Logical Shift)
    // - signed의 경우 부호 비트에 따라 0 또는 1 채움 (Arithmetic Shift)

    // 2. 비트 플래그 (BitFlag) 활용
    // 시나리오: 4개의 상태를 1바이트로 관리
    // 0b0000 [3:무적] [2:변이] [1:스턴] [0:공중부양]

    // 2-1) 상태 활성화 (Set) - OR(|) 연산 사용

    // 무적 상태 켜기 (3번 비트 활성화)
    flag = (1 << 3);  // 0000 1000 (값: 8)

    // 변이 상태 추가 (2번 비트 활성화)
    flag |= (1 << 2); // 0000 1000 | 0000 0100 => 0000 1100 (값: 12)

    // 2-2) 상태 확인 (Check) - AND(&) 연산 사용

    // 특정 비트(3번)가 켜져 있는지 확인 (Masking)
    bool bInvincible = (flag & (1 << 3)) != 0;
    // (1100 & 1000) => 1000 (!= 0) -> true

    // 2-3) 복합 상태 확인

    // 무적(3)이거나 스턴(1) 상태인지 확인
    // 마스크 생성: (1000 | 0010) => 1010
    unsigned char checkMask = (1 << 3) | (1 << 1);

    bool bStunOrInvincible = (flag & checkMask) != 0;

    return 0;
}
```

## 2. 이론 정리 (Study Notes)

### 2.1 비트 연산자 (Bitwise Operators)
컴퓨터의 최소 데이터 단위인 비트(Bit)를 직접 조작하는 연산자

| 연산자 | 명칭 (Name) | 수식 표현 | 설명 | 활용 예시 |
| :---: | :---: | :--- | :--- | :--- |
| `&` | AND | $A \land B$ | 둘 다 1이면 1 | 특정 비트 확인(Masking), 비트 끄기(Clear) |
| `\|` | OR | $A \lor B$ | 하나라도 1이면 1 | 특정 비트 켜기(Set), 값 합치기 |
| `^` | XOR | $A \oplus B$ | 서로 다르면 1 | 암호화, 두 값 교체(Swap), 같은 값 확인 |
| `~` | NOT | $\neg A$ | 0 $\leftrightarrow$ 1 반전 | 보수 구하기, 비트 반전 |
| `<<` | L-Shift | $A \times 2^n$ | 좌측 이동 | 고속 곱셈 ($2^n$배) |
| `>>` | R-Shift | $A \div 2^n$ | 우측 이동 | 고속 나눗셈 ($2^n$배) |

### 2.2 시프트 연산의 특징 (Shift Operation)
* **Left Shift (`<<`)**: 비트가 왼쪽으로 밀리며, 오른쪽 빈 공간은 항상 **0**으로 채워짐
* **Right Shift (`>>`)**: 데이터 타입에 따라 동작이 다름
  * **Unsigned (Logical Shift)**: 빈 공간을 무조건 **0**으로 채움
  * **Signed (Arithmetic Shift)**: 빈 공간을 **부호 비트(MSB)**로 채움 (음수 유지 목적)

### 2.3 비트 플래그 (Bit Flag)
여러 개의 `bool` 변수 대신 하나의 정수형 변수 비트 필드를 사용하여 상태를 관리하는 기법
* **메모리 절약**: `bool`(1 Byte) 8개를 `unsigned char`(1 Byte) 하나로 대체 가능함
* **연산 효율**: 한 번의 `&`, `|` 연산으로 여러 상태를 동시에 체크하거나 변경할 수 있음

| 동작 | 연산자 | 코드 예시 ($k$번째 비트) | 비고 |
| :--- | :---: | :--- | :--- |
| **상태 켜기 (Set)** | `\|` (OR) | `flag \|= (1 << k);` | 해당 비트만 1로 변경 |
| **상태 끄기 (Clear)** | `& ~` (AND NOT) | `flag &= ~(1 << k);` | 해당 비트만 0으로 변경 |
| **상태 뒤집기 (Toggle)** | `^` (XOR) | `flag ^= (1 << k);` | 1 $\leftrightarrow$ 0 토글 |
| **상태 확인 (Check)** | `&` (AND) | `(flag & (1 << k)) != 0` | 0이 아니면 켜진 상태 |

## 3. 종합 의견 (Review)

### 핵심 요약 및 주의사항
* **연산자 우선순위**: 비트 연산자(`&`, `|`, `^`)는 비교 연산자(`==`, `!=`)보다 우선순위가 낮음
  * **잘못된 예**: `if (flag & mask != 0)` $\rightarrow$ `mask != 0`이 먼저 연산됨
  * **올바른 예**: `if ((flag & mask) != 0)` $\rightarrow$ **반드시 괄호로 감싸야 함**
* **부호 없는 자료형 사용**: 비트 플래그나 시프트 연산을 할 때는 `unsigned` 형(예: `unsigned int`, `unsigned char`)을 사용하는 것이 안전함. `signed` 형 사용 시 우측 시프트(`>>`)에서 부호 비트 확장이 발생하여 의도치 않은 값이 될 수 있음

### Tip
* **최적화 (Optimization)**: 곱셈(`*`)과 나눗셈(`/`)은 CPU 사이클을 많이 소모함. $2^n$ 단위의 연산이라면 시프트 연산(`<<`, `>>`)을 사용하는 것이 성능상 유리함 (단, 현대 컴파일러는 이를 자동으로 최적화해주기도 함)
* **가독성**: `(1 << 3)`과 같은 매직 넘버보다는 `const`나 `enum`을 활용하여 `const int STATE_INVINCIBLE = (1 << 3);` 처럼 명명하여 사용하는 것을 권장
