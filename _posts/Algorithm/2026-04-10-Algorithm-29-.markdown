Kruskal 알고리즘은 모든 정점을 최소 비용으로 연결하는 간선 집합을 만든다. 격자 맵에서는 각 방을 정점, 두 방 사이에 뚫을 수 있는 벽을 간선으로 해석할 수 있다.

```text
격자 셀                 그래프

[0][1][2]              0 ─ 1 ─ 2
[3][4][5]      →       │   │   │
[6][7][8]              3 ─ 4 ─ 5
                       │   │   │
                       6 ─ 7 ─ 8
```

인접한 모든 셀 사이에 무작위 우선순위를 부여하고 Kruskal로 사이클 없는 연결을 선택한다. 선택된 간선 위치의 벽만 제거하면 모든 방이 연결되면서 순환 통로가 없는 미로를 만들 수 있다.

이번 글의 코드는 특정 프로젝트 구현이 아니라, 2차원 격자와 Kruskal의 연결 방식을 설명하기 위한 독립적인 예제다.

## 논리 셀과 출력 타일을 구분한다

먼저 이동 가능한 방 단위를 논리 셀이라고 하자.

```text
논리 크기: width = 3, height = 2

(0,0) (0,1) (0,2)
(1,0) (1,1) (1,2)
```

방 사이의 벽까지 문자 타일로 표현하려면 각 셀 사이에 한 칸의 벽 공간이 필요하다. 바깥 테두리까지 포함한 출력 크기는 다음과 같다.

$$
tileWidth = 2 \times width + 1
$$

$$
tileHeight = 2 \times height + 1
$$

논리 셀 `(y, x)`의 중심 타일은 다음 위치다.

```cpp
int tileY = static_cast<int>(y * 2 + 1);
int tileX = static_cast<int>(x * 2 + 1);
```

```text
논리 셀 3×2를 벽 타일로 표현

#######
#.#.#.#
#######
#.#.#.#
#######

#: 벽
.: 셀 중심
```

아직 방 사이의 벽은 모두 막혀 있다. Kruskal이 선택한 연결만 `.`으로 바꾼다.

## 좌표를 Disjoint Set 인덱스로 변환한다

Disjoint Set은 0부터 시작하는 하나의 인덱스로 원소를 관리한다. 2차원 좌표를 1차원 정점 번호로 변환한다.

```cpp
std::size_t ToIndex(std::size_t y, std::size_t x, std::size_t width)
{
    return y * width + x;
}
```

반대로 정점 번호에서 좌표를 복원할 수 있다.

```cpp
std::pair<std::size_t, std::size_t> ToPosition(std::size_t index, std::size_t width)
{
    return {index / width, index % width};
}
```

```text
width = 3

(0,0) → 0    (0,1) → 1    (0,2) → 2
(1,0) → 3    (1,1) → 4    (1,2) → 5
```

전체 정점 수는 `width * height`다. 두 값의 곱과 이후 타일 크기 계산이 `std::size_t` 범위를 넘지 않는 입력이라는 전제가 필요하다.

## 인접 셀 사이의 후보 간선을 만든다

각 셀에서 오른쪽과 아래쪽 이웃만 확인한다.

```cpp
struct Edge
{
    std::size_t from;
    std::size_t to;
    std::uint32_t priority;
};
```

```cpp
std::vector<Edge> BuildCandidates(std::size_t width, std::size_t height, std::mt19937& engine)
{
    std::uniform_int_distribution<std::uint32_t> priority;
    std::vector<Edge> edges;

    for (std::size_t y = 0; y < height; ++y)
    {
        for (std::size_t x = 0; x < width; ++x)
        {
            std::size_t current = ToIndex(y, x, width);

            if (x + 1 < width)
            {
                edges.push_back(Edge{current, ToIndex(y, x + 1, width), priority(engine)});
            }

            if (y + 1 < height)
            {
                edges.push_back(Edge{current, ToIndex(y + 1, x, width), priority(engine)});
            }
        }
    }

    return edges;
}
```

왼쪽과 위쪽까지 다시 추가하면 같은 무방향 연결이 두 번 들어간다. 오른쪽과 아래쪽만 만들면 모든 인접 관계를 한 번씩 포함할 수 있다.

가로 후보 수와 세로 후보 수는 각각 다음과 같다.

$$
E_{horizontal} = height(width-1)
$$

$$
E_{vertical} = width(height-1)
$$

전체 후보 수는 $O(width \times height)$다.

## 무작위 값은 거리보다 선택 순서에 가깝다

일반적인 MST에서 가중치는 실제 건설 비용을 뜻한다. 이 예제의 `priority`는 다양한 통로 모양을 만들기 위한 무작위 선택 순서다.

```text
낮은 priority
→ Kruskal에서 먼저 검토

높은 priority
→ 나중에 검토
```

같은 seed를 사용하면 같은 난수열과 같은 맵을 재현할 수 있다.

```cpp
std::mt19937 engine(seed);
```

매번 다른 맵이 필요하더라도 생성에 사용한 seed를 저장하면 버그가 발생한 맵을 다시 만들 수 있다.

무작위 우선순위 기반 Kruskal이 가능한 모든 스패닝 트리를 동일한 확률로 생성하는 것은 아니다. 다양한 미로를 만드는 방법이지 균등 랜덤 스패닝 트리를 보장하는 알고리즘은 아니다.

## Kruskal로 V-1개의 통로를 선택한다

후보를 우선순위 오름차순으로 정렬한다.

```cpp
std::sort(edges.begin(), edges.end(), [](const Edge& a, const Edge& b)
{
    return std::tie(a.priority, a.from, a.to) < std::tie(b.priority, b.from, b.to);
});
```

서로 다른 두 집합을 연결하는 간선만 통로로 선택한다.

```cpp
std::vector<Edge> SelectPassages(std::size_t vertexCount, const std::vector<Edge>& edges)
{
    DisjointSet sets(vertexCount);
    std::vector<Edge> passages;
    passages.reserve(vertexCount > 0 ? vertexCount - 1 : 0);

    for (const Edge& edge : edges)
    {
        if (!sets.Union(edge.from, edge.to))
        {
            continue;
        }

        passages.push_back(edge);

        if (passages.size() + 1 == vertexCount)
        {
            break;
        }
    }

    return passages;
}
```

직사각형 격자는 폭과 높이가 모두 1 이상이면 연결 그래프다. 따라서 선택된 통로 수는 정확히 `vertexCount - 1`이어야 한다.

```text
모든 셀 연결
+
사이클 없음
=
두 셀 사이의 단순 경로가 정확히 하나인 perfect maze
```

## 선택된 간선을 실제 벽 제거로 바꾼다

처음에는 모든 타일을 벽으로 채우고 각 셀의 중심을 바닥으로 만든다.

```cpp
std::vector<std::string> CreateClosedGrid(std::size_t width, std::size_t height)
{
    std::vector<std::string> tiles(height * 2 + 1, std::string(width * 2 + 1, '#'));

    for (std::size_t y = 0; y < height; ++y)
    {
        for (std::size_t x = 0; x < width; ++x)
        {
            tiles[y * 2 + 1][x * 2 + 1] = '.';
        }
    }

    return tiles;
}
```

간선의 두 셀 중심 사이에 있는 한 칸이 제거할 벽이다.

```text
가로 연결

#.?#
  ↑
가운데 ?를 .으로 변경

세로 연결

#.#
#?#
#.#
 ↑
가운데 ?를 .으로 변경
```

두 셀의 논리 좌표를 더하고 1을 더하면 중심 타일 사이의 중간 위치가 된다.

```cpp
void CarvePassage(std::vector<std::string>& tiles, const Edge& edge, std::size_t width)
{
    auto [fromY, fromX] = ToPosition(edge.from, width);
    auto [toY, toX] = ToPosition(edge.to, width);
    std::size_t wallY = fromY + toY + 1;
    std::size_t wallX = fromX + toX + 1;
    tiles[wallY][wallX] = '.';
}
```

인접 셀만 후보 간선으로 만들었다는 전제가 중요하다. 멀리 떨어진 두 좌표에 이 공식을 적용하면 실제 두 셀 사이의 전체 통로를 만들지 못한다.

## 전체 생성 흐름

```cpp
struct MazeResult
{
    std::vector<std::string> tiles;
    std::vector<Edge> passages;
};

MazeResult GenerateMaze(std::size_t width, std::size_t height, std::uint32_t seed)
{
    if (width == 0 || height == 0)
    {
        return {};
    }

    std::mt19937 engine(seed);
    std::vector<Edge> candidates = BuildCandidates(width, height, engine);

    std::sort(candidates.begin(), candidates.end(), [](const Edge& a, const Edge& b)
    {
        return std::tie(a.priority, a.from, a.to) < std::tie(b.priority, b.from, b.to);
    });

    std::size_t vertexCount = width * height;
    std::vector<Edge> passages = SelectPassages(vertexCount, candidates);
    std::vector<std::string> tiles = CreateClosedGrid(width, height);

    for (const Edge& passage : passages)
    {
        CarvePassage(tiles, passage, width);
    }

    return MazeResult{std::move(tiles), std::move(passages)};
}
```

생성 단계는 다음처럼 나뉜다.

```text
논리 셀 생성
→ 인접 후보 간선 생성
→ 무작위 priority 부여
→ Kruskal로 통로 선택
→ 닫힌 타일 격자 생성
→ 선택된 간선 위치의 벽 제거
```

그래프 연결 계산과 타일 변경을 분리하면 선택된 간선 수, 사이클 여부와 타일 좌표 변환을 각각 검증하기 쉽다.

## MST만 사용하면 순환 통로가 없다

MST 간선은 사이클을 만들지 않으므로 두 방 사이의 경로가 하나뿐이다.

```text
장점
→ 모든 방 도달 보장
→ 막다른 길과 되돌아가기 구조가 명확함
→ 통로 수가 V-1로 예측 가능

한계
→ 우회 경로가 없음
→ 플레이어 동선이 지나치게 선형일 수 있음
→ 특정 통로가 항상 병목이 됨
```

게임 맵에 순환 경로가 필요하면 먼저 MST로 연결성을 보장한 뒤, 제외된 후보 간선 일부를 추가로 선택한다.

```cpp
for (const Edge& edge : rejectedEdges)
{
    if (extraPassage(engine))
    {
        CarvePassage(tiles, edge, width);
    }
}
```

이 단계에서 추가되는 간선은 의도적으로 사이클을 만든다. `Union` 결과를 다시 요구하면 이미 같은 집합이므로 모든 추가 간선이 거부된다.

추가 통로 비율은 맵의 우회 가능성과 막다른 길 밀도를 조절하는 디자인 매개변수다. 확률뿐 아니라 최소 거리, 방 종류와 통로 폭 같은 규칙을 함께 적용할 수 있다.

## 방 사이의 실제 비용을 사용할 수도 있다

격자 미로가 아니라 크기와 위치가 다른 방을 연결한다면 간선 가중치에 실제 통로 비용을 사용할 수 있다.

```text
방 중심 사이의 Manhattan 거리
방 중심 사이의 Euclidean 거리
통로가 지나야 하는 장애물 비용
높이 차이 또는 문 설치 비용
```

이 경우 Kruskal은 단순히 무작위 모양을 만드는 것이 아니라 정의한 비용의 합이 최소인 연결을 선택한다.

하지만 모든 방 쌍을 후보로 만들면 간선 수가 $O(V^2)$가 된다. 방 수가 많다면 가까운 방만 연결하거나 공간 분할, Delaunay triangulation 같은 방법으로 후보 수를 줄이는 방식을 고려할 수 있다.

후보 그래프를 너무 적게 만들면 그래프가 연결되지 않아 모든 방을 연결할 수 없다. 성능을 위해 후보를 줄이더라도 연결 가능성 검증이 필요하다.

## 시작점과 출구는 연결 뒤에 정한다

맵이 연결된 뒤 시작점과 출구를 선택한다. 단순히 좌상단과 우하단을 사용할 수도 있지만 실제 통로 거리가 짧을 수 있다.

다음과 같은 방법을 사용할 수 있다.

```text
1. 임의 셀에서 BFS로 가장 먼 셀 A를 찾는다.
2. A에서 다시 BFS해 가장 먼 셀 B를 찾는다.
3. A와 B를 입구와 출구로 사용한다.
```

트리에서는 이 두 번의 탐색으로 지름의 양 끝점을 찾을 수 있다. MST 뒤에 추가 통로를 넣어 일반 그래프가 됐다면 같은 방식은 먼 두 점의 유용한 근사일 수 있지만 항상 그래프 지름을 보장하지는 않는다.

입구와 출구 위치는 그래프 연결 생성과 별도 단계로 두면 맵 목적에 따라 교체하기 쉽다.

## 생성 결과를 검증한다

화면으로 미로를 한 번 보는 것만으로는 연결 오류를 찾기 어렵다. 구조 조건을 직접 검사한다.

### MST 간선 수

```cpp
assert(passages.size() == width * height - 1);
```

### 모든 셀 연결

선택된 통로만으로 BFS 또는 DFS를 실행해 방문한 셀 수가 전체 셀 수와 같은지 확인한다.

### 사이클 없음

새 Disjoint Set에 선택된 통로를 다시 넣었을 때 모든 `Union`이 true여야 한다. false가 나오면 사이클이 있다.

### 타일 통로 연결

출력 타일에서 하나의 셀 중심부터 이동 가능한 `.`을 탐색하고 모든 셀 중심에 도달하는지 확인한다. 그래프 간선 선택이 맞아도 벽 좌표 계산이 틀리면 실제 타일은 끊길 수 있다.

### Seed 재현성

같은 크기와 seed로 두 번 생성한 결과가 같은지 확인한다.

```text
GenerateMaze(20, 20, 1234)
GenerateMaze(20, 20, 1234)
→ 동일한 tiles와 passages
```

표준 라이브러리 배포 환경과 구현까지 넘어선 완전한 바이너리 재현성이 필요하다면 난수 분포와 셔플 방식의 재현 조건도 별도로 관리해야 한다.

## 시간 복잡도

논리 셀 수를 $V=width \times height$라고 하자. 격자 인접 후보 간선 수 $E$도 $O(V)$다.

```text
후보 생성      O(V)
간선 정렬      O(E log E) = O(V log V)
Kruskal        O(E α(V))
타일 초기화    O(V)
벽 제거        O(V)
```

전체 시간은 간선 정렬이 지배해 $O(V\log V)$이다. 타일 배열과 후보·선택 간선, Disjoint Set에 $O(V)$ 추가 공간을 사용한다.

## 맵 생성에서 확인할 기준

1. 논리 셀과 출력 타일 좌표를 구분하는가?
2. 2차원 좌표와 Disjoint Set 인덱스를 일관되게 변환하는가?
3. 같은 무방향 후보 간선을 중복 생성하지 않는가?
4. 후보 그래프가 모든 셀을 연결할 수 있는가?
5. 동일 seed에서 같은 후보 우선순위를 만드는가?
6. Kruskal이 정확히 $V-1$개의 통로를 선택하는가?
7. 선택된 간선의 두 셀이 실제로 인접한가?
8. 두 셀 중심 사이의 벽 타일을 정확히 제거하는가?
9. 그래프 연결과 실제 타일 연결을 각각 검증하는가?
10. MST만 사용할지 추가 통로로 사이클을 만들지 정했는가?
11. 입구와 출구 선택을 연결 생성과 분리했는가?
12. 빈 크기와 크기 곱의 오버플로를 처리하는가?
13. 무작위 Kruskal이 균등 랜덤 스패닝 트리를 보장하지 않는다는 점을 구분하는가?

Kruskal 맵 생성의 핵심은 알고리즘의 결과를 그대로 화면에 그리는 것이 아니다. 맵의 방과 통로 후보를 그래프로 변환하고, 선택된 간선을 다시 정확한 벽 좌표로 옮기는 두 번의 모델 변환에 있다. MST는 연결성을 보장하는 뼈대를 만들고, 그 뒤의 추가 통로와 입구·출구 규칙이 실제 플레이 구조를 결정한다.
