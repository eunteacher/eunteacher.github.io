수열에서 일부 원소를 골라 원래 순서를 유지하면서 값이 계속 증가하도록 만들 수 있다. 이때 가능한 수열 중 길이가 가장 긴 것을 **최장 증가 부분 수열(Longest Increasing Subsequence, LIS)**이라고 한다.

```text
입력: 10 20 10 30 20 50

가능한 증가 부분 수열: 10 20 30 50
길이: 4
```

부분 수열은 원소가 연속해서 붙어 있을 필요가 없다. 다만 원래 수열에서의 순서는 바꿀 수 없다.

```text
10 20 [10] 30 [20] 50
└────── 10 20 30 50 ──────┘

정렬해서 10 10 20 20 30 50으로 만드는 문제는 아니다.
```

## 마지막 원소를 기준으로 상태를 정의한다

LIS를 동적 계획법으로 풀려면 먼저 `dp[i]`의 의미를 정확히 정해야 한다.

```text
dp[i] = i번째 원소를 마지막으로 사용하는 증가 부분 수열의 최대 길이
```

`i` 앞에 있는 원소 `j`를 살펴보자. `values[j] < values[i]`라면 `j`에서 끝난 증가 부분 수열 뒤에 `values[i]`를 붙일 수 있다.

$$
dp[i] = 1 + \max_{0 \le j < i,\; values[j] < values[i]} dp[j]
$$

앞에 붙일 수 있는 원소가 하나도 없다면 자기 자신만 선택하므로 `dp[i] = 1`이다.

```cpp
int LongestIncreasingSubsequence(const std::vector<int>& values)
{
    if (values.empty())
    {
        return 0;
    }

    std::vector<int> dp(values.size(), 1);
    int answer = 1;

    for (std::size_t i = 0; i < values.size(); ++i)
    {
        for (std::size_t j = 0; j < i; ++j)
        {
            if (values[j] < values[i])
            {
                dp[i] = std::max(dp[i], dp[j] + 1);
            }
        }

        answer = std::max(answer, dp[i]);
    }

    return answer;
}
```

정답이 반드시 마지막 원소에서 끝난다는 보장은 없다. 따라서 `dp.back()`이 아니라 모든 `dp[i]` 중 최댓값을 구해야 한다.

## 표를 채우며 점화식을 확인한다

수열이 `{10, 20, 10, 30, 20, 50}`일 때의 계산 과정은 다음과 같다.

| `i` | 값 | 앞에 연결할 수 있는 값 | `dp[i]` |
|---:|---:|---|---:|
| 0 | 10 | 없음 | 1 |
| 1 | 20 | 10 | 2 |
| 2 | 10 | 없음 | 1 |
| 3 | 30 | 10, 20, 10 | 3 |
| 4 | 20 | 10, 10 | 2 |
| 5 | 50 | 10, 20, 10, 30, 20 | 4 |

`values[i]`보다 작은 앞쪽 원소를 전부 확인하므로 시간 복잡도는 $O(N^2)$이고, DP 배열에는 $O(N)$ 공간이 필요하다. 구현이 단순하고 실제 수열을 복원하기도 쉬워 입력 크기가 충분히 작다면 좋은 방법이다.

## 이전 위치를 저장하면 수열을 복원할 수 있다

길이뿐 아니라 어떤 원소를 골랐는지 알고 싶다면 `dp[i]`를 갱신할 때 직전 원소의 위치를 함께 저장한다.

```cpp
std::vector<int> RestoreLIS(const std::vector<int>& values)
{
    if (values.empty())
    {
        return {};
    }

    std::vector<int> dp(values.size(), 1);
    std::vector<int> previous(values.size(), -1);
    int lastIndex = 0;

    for (std::size_t i = 0; i < values.size(); ++i)
    {
        for (std::size_t j = 0; j < i; ++j)
        {
            if (values[j] < values[i] && dp[j] + 1 > dp[i])
            {
                dp[i] = dp[j] + 1;
                previous[i] = static_cast<int>(j);
            }
        }

        if (dp[i] > dp[lastIndex])
        {
            lastIndex = static_cast<int>(i);
        }
    }

    std::vector<int> sequence;

    for (int index = lastIndex; index != -1; index = previous[index])
    {
        sequence.push_back(values[index]);
    }

    std::reverse(sequence.begin(), sequence.end());
    return sequence;
}
```

`previous[i]`에는 `i` 앞에 선택한 원소의 인덱스가 들어간다. 마지막 위치부터 연결을 거꾸로 따라가면 수열도 역순으로 만들어지므로 마지막에 한 번 뒤집는다.

같은 최대 길이를 만드는 LIS가 여러 개라면 이 코드는 탐색 중 먼저 유지된 수열 하나를 반환한다. 모든 LIS를 찾는 코드는 아니다.

## 마지막 값만 관리하면 탐색 범위를 줄일 수 있다

$O(N^2)$ 방식은 모든 이전 원소를 비교한다. 길이가 같은 증가 부분 수열이라면 마지막 값이 작을수록 뒤에 더 많은 값을 붙일 수 있다는 점을 이용하면 비교 횟수를 줄일 수 있다.

```text
길이가 3인 후보

1 4 8  → 마지막 값 8
1 3 5  → 마지막 값 5

뒤에 6이 들어온다면 두 번째 후보에만 연결할 수 있다.
```

`tails[k]`를 다음과 같이 정의한다.

```text
tails[k] = 길이가 k + 1인 증가 부분 수열이 가질 수 있는 가장 작은 마지막 값
```

새 값 `value`가 들어올 때 `tails`에서 `value` 이상인 첫 위치를 이진 탐색으로 찾는다.

- 그런 위치가 없으면 뒤에 추가하여 LIS의 최대 길이를 늘린다.
- 위치가 있으면 그 값을 `value`로 교체하여 같은 길이의 더 유리한 후보를 만든다.

```cpp
int LongestIncreasingSubsequenceFast(const std::vector<int>& values)
{
    std::vector<int> tails;

    for (int value : values)
    {
        auto position = std::lower_bound(tails.begin(), tails.end(), value);

        if (position == tails.end())
        {
            tails.push_back(value);
        }
        else
        {
            *position = value;
        }
    }

    return static_cast<int>(tails.size());
}
```

`tails`는 항상 정렬된 상태이므로 `std::lower_bound`를 사용할 수 있다. 원소마다 $O(\log N)$ 탐색을 수행하여 전체 시간 복잡도는 $O(N\log N)$이고, 공간 복잡도는 $O(N)$이다.

## tails는 계산용 정보이지 정답 수열이 아니다

`tails`의 크기는 LIS 길이와 같지만, 배열에 남은 값들이 원래 수열에서 하나의 부분 수열을 이룬다고 보장할 수는 없다.

```text
입력: 3 5 7 1 2 8

진행 중 tails
3
3 5
3 5 7
1 5 7
1 2 7
1 2 7 8
```

최종 `tails`는 `{1, 2, 7, 8}`이지만 입력에서 `7`은 `1`, `2`보다 앞에 있으므로 이 순서대로 고른 부분 수열이 아니다. 이 배열이 알려 주는 것은 길이가 4인 LIS가 존재한다는 사실이다.

$O(N\log N)$ 방식에서도 실제 수열을 복원하려면 각 원소가 들어간 `tails` 위치와 그때의 이전 원소 인덱스를 별도로 기록해야 한다.

## 엄격한 증가와 비감소를 구분한다

LIS에서 증가의 의미에 따라 이진 탐색 함수가 달라진다.

| 원하는 수열 | 조건 | 탐색 함수 |
|---|---|---|
| 엄격한 증가 | 이전 값 `<` 다음 값 | `std::lower_bound` |
| 비감소 | 이전 값 `<=` 다음 값 | `std::upper_bound` |

```text
입력: 2 2 2

엄격한 증가 LIS 길이: 1
비감소 부분 수열 길이: 3
```

문제에서 단순히 증가 수열이라고 표현하더라도 같은 값을 허용하는지 반드시 확인해야 한다. 이 조건 하나로 점화식의 비교 연산자와 이진 탐색 방식이 모두 달라진다.

## 두 풀이를 비교한다

| 방식 | 시간 복잡도 | 공간 복잡도 | 특징 |
|---|---:|---:|---|
| DP | $O(N^2)$ | $O(N)$ | 상태와 점화식이 명확하고 복원이 간단하다 |
| 이진 탐색 | $O(N\log N)$ | $O(N)$ | 큰 입력에 적합하지만 복원 정보가 추가로 필요하다 |

처음부터 빠른 풀이만 외우면 `tails`를 왜 교체해도 되는지 이해하기 어렵다. 먼저 `dp[i]`를 **i에서 끝나는 LIS 길이**로 정의하고, 같은 길이의 후보 중 마지막 값이 작은 것만 남겨도 길이 계산에는 문제가 없다는 사실을 연결하면 두 풀이의 관계가 보인다.

## 검증 코드

```cpp
#include <algorithm>
#include <cassert>
#include <vector>

// LongestIncreasingSubsequence, RestoreLIS,
// LongestIncreasingSubsequenceFast 구현은 앞의 코드와 같다.

int main()
{
    std::vector<int> values{10, 20, 10, 30, 20, 50};

    assert(LongestIncreasingSubsequence(values) == 4);
    assert(LongestIncreasingSubsequenceFast(values) == 4);
    assert((RestoreLIS(values) == std::vector<int>{10, 20, 30, 50}));

    assert(LongestIncreasingSubsequence({}) == 0);
    assert(LongestIncreasingSubsequenceFast({3, 3, 3}) == 1);
    assert(LongestIncreasingSubsequenceFast({5, 4, 3, 2, 1}) == 1);
    assert(LongestIncreasingSubsequenceFast({1, 2, 3, 4, 5}) == 5);
}
```

빈 수열, 중복 값, 내림차순, 오름차순처럼 경계가 분명한 입력을 함께 검사하면 초기값과 비교 조건의 실수를 찾기 쉽다. 두 구현을 만들었다면 임의의 작은 수열을 생성해 결과 길이가 같은지 비교하는 방법도 유용하다.
