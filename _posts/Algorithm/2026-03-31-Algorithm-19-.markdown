이진 탐색은 정렬된 배열의 가운데를 기준으로 탐색 구간을 절반씩 줄였다. 빠른 탐색이 가능하지만 배열 중간에 원소를 삽입하거나 삭제하면 뒤의 원소를 이동해야 한다.

이진 탐색 트리(Binary Search Tree, BST)는 대소 관계를 노드의 연결 방향으로 표현한다.

```text
        30
      /    \
    10      40
      \       \
      20       50
        \
        25
          \
          26
```

현재 노드보다 작은 키는 왼쪽으로, 크거나 같은 키는 오른쪽으로 내려간다. 검색과 삽입은 한 경로만 따라가고, 삭제는 자식 수에 따라 연결을 다시 구성한다.

## 왼쪽과 오른쪽 서브트리의 규칙

이번 구현은 중복 키를 허용하고 같은 키를 오른쪽에 삽입한다. 따라서 각 노드의 규칙은 다음과 같다.

```text
왼쪽 서브트리의 모든 키 < 현재 키
오른쪽 서브트리의 모든 키 ≥ 현재 키
```

```text
        20
      /    \
    10      20
           / \
         20   30
```

중복을 허용하지 않는 집합 형태의 BST라면 같은 키를 발견했을 때 삽입하지 않는 정책을 사용할 수 있다. 어느 방식이든 비교와 삽입, 검색, 삭제가 같은 정책을 따라야 한다.

BST 규칙은 직계 자식에만 적용되는 것이 아니다. 왼쪽 **서브트리 전체**와 오른쪽 **서브트리 전체**가 조건을 만족해야 한다.

## 노드는 부모와 두 자식을 연결한다

원본 실습은 연결 변경을 직접 확인할 수 있도록 원시 포인터를 사용한다.

```cpp
struct Node
{
    Node* parent = nullptr;
    Node* left = nullptr;
    Node* right = nullptr;
    int key = 0;
};
```

`left`와 `right`만 있어도 루트부터 아래로 탐색할 수 있다. `parent`는 중위 순회의 다음 노드를 찾거나 노드를 교체할 때 위쪽으로 이동하기 위해 사용한다.

```text
parent
  ↑
[node]
 ↙  ↘
left right
```

한 연결을 바꿀 때 반대 방향도 함께 갱신해야 한다.

```text
parent->left = child
child->parent = parent
```

둘 중 하나만 바꾸면 위에서 내려갈 때와 아래에서 올라갈 때 서로 다른 구조가 보인다.

## 검색은 한쪽 서브트리만 선택한다

현재 키와 목표 키를 비교해 다음 노드를 정한다.

```cpp
Node* Search(Node* node, int key)
{
    while (node != nullptr && node->key != key)
    {
        if (key < node->key)
        {
            node = node->left;
        }
        else
        {
            node = node->right;
        }
    }

    return node;
}
```

키를 찾으면 해당 노드를 반환하고, 내려갈 자식이 없으면 `nullptr`을 반환한다.

```text
Search(25)

30: 25 < 30 → left
10: 25 > 10 → right
20: 25 > 20 → right
25: 발견
```

같은 키가 여러 개라면 탐색 경로에서 처음 만난 노드를 반환한다. 중위 순서의 첫 번째나 마지막 중복 노드가 필요하다면 별도의 경계 탐색 규칙이 필요하다.

재귀로도 같은 흐름을 표현할 수 있다.

```cpp
Node* SearchRecursive(Node* node, int key)
{
    if (node == nullptr || node->key == key)
    {
        return node;
    }

    if (key < node->key)
    {
        return SearchRecursive(node->left, key);
    }

    return SearchRecursive(node->right, key);
}
```

반복 구현은 트리가 깊어져도 검색 자체가 호출 스택을 추가로 사용하지 않는다. 재귀 구현은 BST의 정의가 코드에 직접 드러난다는 장점이 있다.

## 삽입은 비어 있는 자리를 찾는다

새 키가 들어갈 방향을 따라가며 마지막으로 확인한 노드를 부모로 기억한다.

```cpp
void Insert(int key)
{
    Node* parent = nullptr;
    Node* current = root_;

    while (current != nullptr)
    {
        parent = current;
        current = key < current->key ? current->left : current->right;
    }

    Node* node = new Node{};
    node->key = key;
    node->parent = parent;

    if (parent == nullptr)
    {
        root_ = node;
    }
    else if (key < parent->key)
    {
        parent->left = node;
    }
    else
    {
        parent->right = node;
    }
}
```

트리가 비어 있으면 `parent`가 `nullptr`이므로 새 노드가 루트가 된다. 그 외에는 마지막 비교 결과에 따라 부모의 왼쪽이나 오른쪽에 연결한다.

```text
Insert(26)

30 → left
10 → right
20 → right
25 → right
빈자리 발견

25.right = 26
26.parent = 25
```

새 노드는 항상 리프 위치에 들어간다. 삽입 뒤에도 기존 노드의 상대적인 위치는 바뀌지 않는다.

## 최솟값과 최댓값은 한 방향 끝에 있다

BST의 가장 작은 키는 왼쪽 자식이 더 이상 없는 노드다. 가장 큰 키는 오른쪽 끝에 있다.

```cpp
Node* Min(Node* node)
{
    if (node == nullptr)
    {
        return nullptr;
    }

    while (node->left != nullptr)
    {
        node = node->left;
    }

    return node;
}

Node* Max(Node* node)
{
    if (node == nullptr)
    {
        return nullptr;
    }

    while (node->right != nullptr)
    {
        node = node->right;
    }

    return node;
}
```

빈 서브트리를 받을 수 있으므로 먼저 `nullptr`을 처리한다.

## 중위 순회는 키를 정렬된 순서로 방문한다

왼쪽 서브트리, 현재 노드, 오른쪽 서브트리 순서로 방문한다.

```cpp
void PrintInorder(Node* node)
{
    if (node == nullptr)
    {
        return;
    }

    PrintInorder(node->left);
    std::cout << node->key << '\n';
    PrintInorder(node->right);
}
```

왼쪽의 모든 키가 현재 키보다 작고 오른쪽의 모든 키가 크거나 같으므로 결과는 비내림차순이다.

```text
10 20 25 26 30 40 50
```

중복 키를 허용한다면 같은 값이 연속해서 출력될 수 있다.

## 후속자는 중위 순회에서 바로 다음 노드다

후속자(Successor)는 중위 순회 순서에서 현재 노드 다음에 오는 노드다.

### 오른쪽 서브트리가 있는 경우

오른쪽 서브트리에서 가장 작은 노드가 후속자다.

```text
        20
          \
          40
         /
       30

Successor(20) = 30
```

```cpp
if (node->right != nullptr)
{
    return Min(node->right);
}
```

### 오른쪽 서브트리가 없는 경우

현재 노드가 부모의 오른쪽 자식인 동안 위로 올라간다. 처음으로 현재 서브트리가 부모의 왼쪽에 놓이는 지점의 부모가 후속자다.

```cpp
Node* Successor(Node* node)
{
    if (node == nullptr)
    {
        return nullptr;
    }

    if (node->right != nullptr)
    {
        return Min(node->right);
    }

    Node* parent = node->parent;

    while (parent != nullptr && node == parent->right)
    {
        node = parent;
        parent = parent->parent;
    }

    return parent;
}
```

가장 큰 노드는 다음 노드가 없으므로 `nullptr`을 반환한다.

## Replace는 한 서브트리를 다른 서브트리로 교체한다

삭제 로직에서 반복되는 연결 변경을 `Replace`로 분리한다. `oldNode`가 차지하던 위치에 `newNode` 서브트리를 연결한다.

```cpp
void Replace(Node* oldNode, Node* newNode)
{
    if (oldNode->parent == nullptr)
    {
        root_ = newNode;
    }
    else if (oldNode == oldNode->parent->left)
    {
        oldNode->parent->left = newNode;
    }
    else
    {
        oldNode->parent->right = newNode;
    }

    if (newNode != nullptr)
    {
        newNode->parent = oldNode->parent;
    }
}
```

세 상황을 구분해야 한다.

1. 기존 노드가 루트다.
2. 기존 노드가 부모의 왼쪽 자식이다.
3. 기존 노드가 부모의 오른쪽 자식이다.

새 서브트리가 있다면 그 루트의 `parent`도 기존 노드의 부모로 바꾼다. `Replace`는 연결만 담당하고 메모리 해제는 호출한 삭제 함수가 담당하게 하면 역할이 분명해진다.

## 삭제는 자식 수에 따라 나뉜다

### 왼쪽 자식이 없는 경우

오른쪽 자식이 있으면 그 서브트리로 교체하고, 오른쪽 자식도 없다면 `nullptr`로 교체한다. 리프 삭제도 이 경우에 포함된다.

```cpp
if (node->left == nullptr)
{
    Replace(node, node->right);
    delete node;
    return;
}
```

### 오른쪽 자식이 없는 경우

왼쪽 서브트리로 교체한다.

```cpp
if (node->right == nullptr)
{
    Replace(node, node->left);
    delete node;
    return;
}
```

### 자식이 둘인 경우

노드를 바로 제거하면 왼쪽과 오른쪽 두 서브트리를 한 자리에 연결해야 한다. 대신 후속자의 키를 삭제 대상에 복사하고 후속자 노드를 삭제한다.

```text
삭제 대상: 20

        20
      /    \
    10      40
           /
         30  ← 후속자

20의 키를 30으로 교체

        30
      /    \
    10      40
           /
         30  ← 이 노드를 삭제
```

오른쪽 서브트리의 최솟값인 후속자는 왼쪽 자식을 가질 수 없다. 왼쪽 자식이 있었다면 그 노드가 더 작은 후속자여야 하기 때문이다. 따라서 후속자 삭제는 자식이 없거나 오른쪽 자식 하나만 있는 단순한 경우로 환원된다.

```cpp
Node* successor = Successor(node);
node->key = successor->key;
Replace(successor, successor->right);
delete successor;
```

키 외에 여러 데이터 필드가 있다면 키만 복사해서는 객체의 의미가 달라질 수 있다. 노드 전체를 구조적으로 옮기는 방식이나 저장 데이터 전체를 함께 이전하는 방식을 설계해야 한다.

## 삭제 함수의 전체 흐름

```cpp
void Delete(Node* node)
{
    if (node == nullptr)
    {
        return;
    }

    if (node->left == nullptr)
    {
        Replace(node, node->right);
        delete node;
        return;
    }

    if (node->right == nullptr)
    {
        Replace(node, node->left);
        delete node;
        return;
    }

    Node* successor = Successor(node);
    node->key = successor->key;
    Replace(successor, successor->right);
    delete successor;
}

void Delete(int key)
{
    Delete(Search(root_, key));
}
```

존재하지 않는 키를 검색하면 `nullptr`이 전달되고 아무 작업도 하지 않는다. 중복 키가 있다면 `Search`가 처음 발견한 노드 하나만 삭제한다.

## 원시 포인터를 사용하면 트리 전체를 해제해야 한다

개별 삭제에서 제거한 노드는 `delete`하지만, 트리 객체가 사라질 때 남아 있는 모든 노드도 해제해야 한다.

```cpp
void Clear(Node* node)
{
    if (node == nullptr)
    {
        return;
    }

    Clear(node->left);
    Clear(node->right);
    delete node;
}
```

자식을 먼저 해제한 뒤 부모를 해제하는 후위 순회를 사용한다.

```cpp
~BinarySearchTree()
{
    Clear(root_);
}
```

소유 포인터가 있는 클래스를 기본 복사하면 두 트리가 같은 노드를 가리키고 각각 해제하려 할 수 있다. 깊은 복사를 구현하지 않는다면 복사를 막는다.

```cpp
BinarySearchTree(const BinarySearchTree&) = delete;
BinarySearchTree& operator=(const BinarySearchTree&) = delete;
```

실제 소유권을 더 명확히 표현하려면 자식에 `std::unique_ptr<Node>`를 사용할 수 있다. 다만 삭제 시 소유 포인터를 이동해야 하므로 연결 변경 코드는 원시 포인터 예제와 다른 형태가 된다. 이번 실습에서는 BST의 링크 변경 자체에 집중한다.

## 트리 높이가 연산 비용을 결정한다

검색, 삽입과 삭제는 모두 루트에서 하나의 경로를 따라간다. 트리 높이를 $H$라고 하면 시간 복잡도는 $O(H)$다.

### 균형에 가까운 경우

```text
        40
      /    \
    20      60
   /  \    / \
 10   30  50  70
```

높이가 $O(\log N)$이므로 주요 연산도 $O(\log N)$이다.

### 한쪽으로 편향된 경우

정렬된 값을 그대로 삽입하면 연결 리스트와 비슷한 모양이 될 수 있다.

```text
10
  \
  20
    \
    30
      \
      40
```

높이가 $N$이 되어 검색, 삽입과 삭제가 모두 $O(N)$까지 느려진다. 기본 BST는 균형을 자동으로 복구하지 않으므로 $O(\log N)$을 보장하지 않는다.

평균 $O(\log N)$이라는 설명도 입력 순서가 충분히 무작위라는 등의 가정이 있을 때 성립한다. 최악의 입력에서도 로그 시간을 보장하려면 AVL 트리나 레드 블랙 트리 같은 자가 균형 트리가 필요하다.

## 배열 이진 탐색과 비교한다

| 비교 | 정렬된 vector + 이진 탐색 | Binary Search Tree |
|---|---|---|
| 검색 | $O(\log N)$ | $O(H)$ |
| 중간 삽입·삭제 | $O(N)$ | 위치 탐색 포함 $O(H)$ |
| 메모리 | 연속 저장 | 노드와 포인터 |
| 캐시 지역성 | 좋음 | 일반적으로 낮음 |
| 최악 검색 | $O(\log N)$ | 기본 BST는 $O(N)$ |
| 정렬 순회 | 배열 순서 | 중위 순회 $O(N)$ |

BST의 노드 삭제가 항상 $O(1)$인 것은 아니다. 삭제할 노드를 먼저 찾고 후속자를 찾는 시간이 트리 높이에 비례한다. 또한 포인터 재연결이 적다는 것과 전체 연산이 상수 시간이라는 것은 다른 이야기다.

## 구현할 때 확인할 기준

1. 중복 키를 허용하는지, 허용한다면 어느 방향에 넣는지 정했는가?
2. 검색과 삽입이 같은 대소 관계를 사용하는가?
3. 빈 트리에 처음 삽입할 때 루트를 설정하는가?
4. 자식 연결과 부모 연결을 함께 갱신하는가?
5. `Min`, `Max`, `Successor`가 `nullptr` 입력을 처리하는가?
6. 후속자의 두 가지 경우를 구분하는가?
7. 삭제 대상이 루트인지 확인하는가?
8. 삭제 대상이 부모의 왼쪽·오른쪽 자식인지 구분하는가?
9. 자식이 0개, 1개, 2개인 삭제를 모두 처리하는가?
10. 자식 둘인 노드의 후속자가 왼쪽 자식을 갖지 않는 이유를 이해했는가?
11. 존재하지 않는 키와 중복 키 삭제 정책이 명확한가?
12. 원시 포인터를 사용한다면 전체 노드의 해제와 복사 정책을 정의했는가?
13. 현재 트리가 편향됐을 때의 최악 복잡도를 고려했는가?

이진 탐색 트리의 핵심은 이진 탐색의 비교 규칙을 노드 연결에 유지하는 것이다. 검색과 삽입은 비교 결과에 따라 한 방향을 선택하고, 삭제는 남은 서브트리가 같은 규칙을 계속 만족하도록 부모와 자식 링크를 다시 연결한다.

## 다음 학습: 레드 블랙 트리

다음 글에서는 삽입과 삭제 뒤에도 트리 높이가 한쪽으로 치우치지 않도록 색상 규칙과 회전을 사용하는 레드 블랙 트리를 다룬다. 기본 BST의 검색 규칙을 유지하면서 높이를 $O(\log N)$ 범위로 제한하는 방법을 살펴본다.
