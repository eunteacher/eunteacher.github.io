여러 지점을 도로나 네트워크로 모두 연결하려고 한다. 연결 비용의 합은 최소여야 하고, 이미 연결된 지점 사이에 불필요한 순환 경로를 추가할 필요는 없다고 하자.

```text
정점: 도시 또는 서버
간선: 연결 가능한 도로 또는 케이블
가중치: 건설 비용 또는 연결 비용
```

Kruskal 알고리즘은 가중치가 작은 간선부터 확인하고, 서로 다른 두 연결 집합을 잇는 간선만 선택한다. Disjoint Set으로 두 정점이 이미 같은 집합인지 확인하면 사이클을 빠르게 판별할 수 있다.

## 스패닝 트리는 모든 정점을 잇는 트리다

연결된 무방향 그래프에서 모든 정점을 포함하는 부분 그래프 중 트리인 것을 스패닝 트리(Spanning Tree)라고 한다.

```text
원래 그래프

0 ─── 1
| \   |
|  \  |
2 ─── 3

가능한 스패닝 트리

0 ─── 1
|
|
2 ─── 3
```

정점이 $V$개인 스패닝 트리는 다음 성질을 가진다.

- 모든 정점을 포함한다.
- 모든 정점 사이가 연결된다.
- 사이클이 없다.
- 간선 수는 정확히 $V-1$개다.

스패닝 트리 중 간선 가중치 합이 가장 작은 것을 최소 스패닝 트리(Minimum Spanning Tree, MST)라고 한다.

```text
목적
→ 시작점에서 목적지까지의 최단 경로 하나를 찾는 것 아님
→ 모든 정점을 연결하는 전체 간선 비용을 최소화
```

다익스트라의 최단 경로 트리와 MST는 목적이 다르다. 최단 경로 트리는 특정 시작점에서 각 정점까지의 거리를 최소화하지만, MST는 선택한 전체 간선 가중치의 합을 최소화한다.

## 가장 싼 간선부터 선택한다

Kruskal은 다음 greedy 선택을 반복한다.

```text
1. 모든 간선을 가중치 오름차순으로 정렬한다.
2. 가장 싼 간선부터 하나씩 확인한다.
3. 두 끝점이 서로 다른 집합이면 선택하고 합친다.
4. 이미 같은 집합이면 사이클이 생기므로 건너뛴다.
5. 간선을 V-1개 선택하면 종료한다.
```

간선은 두 끝점과 가중치를 저장한다.

```cpp
struct Edge
{
    std::size_t from;
    std::size_t to;
    int weight;
};
```

## Disjoint Set이 현재 연결 상태를 기억한다

처음에는 모든 정점이 서로 다른 집합이다.

```text
{0} {1} {2} {3} {4}
```

간선 `(0, 1)`을 선택하면 두 집합을 합친다.

```text
{0, 1} {2} {3} {4}
```

이후 `(1, 2)`를 선택하면 다음 상태가 된다.

```text
{0, 1, 2} {3} {4}
```

이 상태에서 `(0, 2)`를 추가하면 이미 같은 집합 안의 두 정점을 연결한다.

```text
0 ─ 1
 \ /
  2

사이클 생성
```

`Union(0, 2)`가 false를 반환하므로 이 간선을 건너뛴다.

```cpp
if (!sets.Union(edge.from, edge.to))
{
    continue;
}
```

별도의 DFS로 매번 사이클을 찾지 않아도 된다. 이전에 선택한 간선의 연결 관계가 Disjoint Set의 대표 정보에 누적된다.

## 예제 그래프를 비용순으로 확인한다

다음 무방향 가중치 그래프를 사용한다.

```text
0 ──1── 1 ──2── 2
 \      |      / \
  3     4     5   7
   \    |    /     \
        3 ──6────── 4
```

간선을 오름차순으로 나열하면 다음과 같다.

```text
(0, 1, 1)
(1, 2, 2)
(0, 2, 3)
(1, 3, 4)
(2, 3, 5)
(3, 4, 6)
(2, 4, 7)
```

### 비용 1: 0-1 선택

```text
{0, 1} {2} {3} {4}
누적 비용 = 1
```

### 비용 2: 1-2 선택

```text
{0, 1, 2} {3} {4}
누적 비용 = 3
```

### 비용 3: 0-2 제외

0과 2는 이미 같은 집합이다. 추가하면 사이클이 생긴다.

```text
선택 간선 유지: 0-1, 1-2
누적 비용 = 3
```

### 비용 4: 1-3 선택

```text
{0, 1, 2, 3} {4}
누적 비용 = 7
```

### 비용 5: 2-3 제외

2와 3은 이미 같은 집합이다.

### 비용 6: 3-4 선택

```text
{0, 1, 2, 3, 4}
누적 비용 = 13
```

정점이 5개이고 선택한 간선이 4개이므로 모든 정점을 잇는 스패닝 트리가 완성됐다.

```text
선택 간선
0-1 (1)
1-2 (2)
1-3 (4)
3-4 (6)

전체 비용 = 13
```

## 왜 가장 싼 안전한 간선을 선택해도 되는가

현재 선택한 간선들이 만든 연결 요소 중 하나를 $S$, 나머지 정점을 $V-S$라고 하자. 두 집합 사이를 가로지르는 간선 중 가중치가 가장 작은 간선을 생각한다.

최소 스패닝 트리가 그 간선을 포함하지 않는다고 가정해도, 두 집합을 연결하는 다른 간선은 반드시 포함해야 한다. 더 비싸거나 같은 그 간선을 현재의 가장 싼 간선으로 교체하면 연결은 유지되고 비용은 증가하지 않는다.

이를 Cut Property로 설명할 수 있다.

> 어떤 cut을 가로지르는 최소 가중치 간선은 최소 스패닝 트리에 안전하게 포함할 수 있다.

Kruskal에서 Disjoint Set의 서로 다른 두 집합은 현재 선택된 forest의 두 컴포넌트다. 그 둘을 연결하는 아직 확인하지 않은 간선 중 가장 싼 간선을 전체 정렬 순서로 선택하므로 greedy 선택이 안전하다.

## 전체 알고리즘 구현

이전 글의 경로 압축과 크기 기반 합치기를 사용하는 `DisjointSet`을 이용한다.

```cpp
struct KruskalResult
{
    long long totalWeight = 0;
    std::vector<Edge> selectedEdges;
    bool connected = false;
};

KruskalResult Kruskal(std::size_t vertexCount, std::vector<Edge> edges)
{
    std::sort(edges.begin(), edges.end(), [](const Edge& a, const Edge& b)
    {
        return std::tie(a.weight, a.from, a.to) < std::tie(b.weight, b.from, b.to);
    });

    DisjointSet sets(vertexCount);
    KruskalResult result;

    for (const Edge& edge : edges)
    {
        assert(edge.from < vertexCount && edge.to < vertexCount);

        if (!sets.Union(edge.from, edge.to))
        {
            continue;
        }

        result.selectedEdges.push_back(edge);
        result.totalWeight += edge.weight;

        if (result.selectedEdges.size() + 1 == vertexCount)
        {
            break;
        }
    }

    result.connected = vertexCount == 0 || result.selectedEdges.size() == vertexCount - 1;
    return result;
}
```

가중치 합은 여러 간선을 더하므로 `long long`을 사용한다. 입력의 최대 간선 수와 가중치 범위를 확인해 실제 누적 비용을 담을 수 있는 타입인지 판단해야 한다.

동일 가중치에서는 끝점 순서까지 비교해 실행 결과를 일정하게 만들었다. MST의 정확성을 위해 끝점 tie-break가 필요한 것은 아니지만 테스트와 출력 순서를 예측하기 쉬워진다.

## 연결 여부를 간선 수로 확인한다

연결된 그래프의 스패닝 트리는 정확히 $V-1$개의 간선을 가진다.

```cpp
result.connected = vertexCount == 0 || result.selectedEdges.size() == vertexCount - 1;
```

간선을 모두 확인했는데 선택한 수가 $V-1$보다 작다면 입력 그래프가 연결돼 있지 않다.

```text
0 ─ 1       2 ─ 3

두 컴포넌트 사이의 간선 없음
→ 하나의 스패닝 트리를 만들 수 없음
```

Kruskal이 실패한 것은 아니다. 각 연결 컴포넌트 안에서 최소 비용 트리를 만든 최소 스패닝 포리스트(Minimum Spanning Forest)를 반환한 것이다.

호출자는 하나의 MST가 반드시 필요한지, 분리된 컴포넌트별 forest도 유효한 결과인지 요구사항을 정해야 한다.

## 전체 검증 예제

```cpp
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <numeric>
#include <tuple>
#include <vector>

// DisjointSet은 이전 글의 구현과 같다.
// Edge, KruskalResult와 Kruskal은 앞의 구현과 같다.

int main()
{
    const std::vector<Edge> edges{
        Edge{0, 1, 1}, Edge{1, 2, 2}, Edge{0, 2, 3}, Edge{1, 3, 4},
        Edge{2, 3, 5}, Edge{3, 4, 6}, Edge{2, 4, 7}
    };

    KruskalResult result = Kruskal(5, edges);

    assert(result.connected);
    assert(result.selectedEdges.size() == 4);
    assert(result.totalWeight == 13);

    const std::vector<Edge> disconnected{
        Edge{0, 1, 1}, Edge{2, 3, 2}
    };

    KruskalResult forest = Kruskal(4, disconnected);
    assert(!forest.connected);
    assert(forest.selectedEdges.size() == 2);
    assert(forest.totalWeight == 3);
}
```

연결 그래프의 최소 비용뿐 아니라 연결되지 않은 입력에서 `connected`가 false인지도 확인한다.

간선 목록을 함수에 값으로 전달했으므로 내부 정렬이 호출자의 원본 순서를 바꾸지 않는다. 간선 수가 매우 많고 복사를 피해야 한다면 호출자가 이동하거나 정렬용 인덱스를 사용하는 인터페이스를 선택할 수 있다.

## 음수 가중치도 사용할 수 있다

Kruskal은 다익스트라와 달리 음수 가중치를 금지하지 않는다.

```text
가중치 -5인 간선
→ 가장 먼저 검토
→ 사이클을 만들지 않으면 선택
```

MST는 단순 경로의 누적 거리를 반복해서 완화하는 문제가 아니다. 모든 정점을 연결할 간선 집합의 합을 최소화하므로 음수 간선도 정렬 순서에 따라 정상적으로 처리할 수 있다.

무방향 그래프의 간선을 입력할 때 `(u, v)`와 `(v, u)`를 둘 다 별도 간선으로 넣으면 같은 연결을 중복 검사하게 된다. 두 방향이 같은 하나의 무방향 간선이라면 한 번만 저장하는 편이 명확하다.

## Self-loop와 평행 간선

### Self-loop

한 정점에서 자기 자신으로 이어지는 간선이다.

```text
(2, 2, weight)
```

두 끝점의 대표가 항상 같으므로 `Union`이 false를 반환하고 선택되지 않는다.

### 평행 간선

같은 두 정점 사이에 가중치가 다른 여러 간선이 있을 수 있다.

```text
(0, 1, 3)
(0, 1, 8)
```

비용 3 간선이 먼저 선택되면 비용 8 간선은 이후 같은 집합을 연결하므로 제외된다. Kruskal은 평행 간선을 별도 전처리 없이 처리할 수 있다.

## MST는 하나가 아닐 수 있다

같은 가중치의 간선이 여러 개면 서로 다른 스패닝 트리가 같은 최소 비용을 가질 수 있다.

```text
삼각형의 모든 간선 비용이 1

세 간선 중 어느 두 개를 선택해도
전체 비용 2인 MST
```

간선 정렬의 tie-break에 따라 선택되는 구체적인 간선 집합은 달라질 수 있다. MST가 유일해야 한다는 요구사항과 최소 비용 하나만 필요하다는 요구사항을 구분해야 한다.

모든 간선 가중치가 서로 다르면 MST는 유일하다. 반대는 성립하지 않는다. 같은 가중치가 있다고 해서 반드시 여러 MST가 존재하는 것은 아니다.

## 시간 복잡도

간선 수를 $E$, 정점 수를 $V$라고 하자.

### 간선 정렬

$$
O(E\log E)
$$

### Disjoint Set 연산

각 간선에서 최대 두 번의 `Find`와 한 번의 `Union`을 수행한다. 경로 압축과 크기 기반 합치기를 사용하면 전체 비용은 다음과 같다.

$$
O(E\alpha(V))
$$

따라서 전체 시간은 정렬 비용이 지배한다.

$$
O(E\log E)
$$

단순 무방향 그래프에서는 $E \le V^2$이므로 흔히 $O(E\log V)$로도 표현한다. 구현과 입력 그래프의 조건을 밝힌 뒤 복잡도를 사용한다.

추가 공간은 간선 정렬 저장소와 Disjoint Set의 부모·크기 배열, 선택한 간선 목록에 사용된다.

## Kruskal을 구현할 때 확인할 기준

1. 입력이 무방향 가중치 그래프인가?
2. 모든 정점 인덱스가 `[0, vertexCount)` 범위인가?
3. 간선을 가중치 오름차순으로 정렬하는가?
4. 서로 다른 두 집합을 연결하는 간선만 선택하는가?
5. 선택한 간선에서만 누적 비용을 더하는가?
6. 선택 간선이 $V-1$개가 되면 종료하는가?
7. 비용 합 타입이 오버플로되지 않는가?
8. 연결되지 않은 그래프의 결과를 별도로 표시하는가?
9. Self-loop와 평행 간선이 들어올 수 있는지 확인했는가?
10. 같은 가중치에서 MST가 여러 개일 수 있음을 고려하는가?
11. 음수 가중치를 불필요하게 금지하지 않는가?
12. Disjoint Set에 경로 압축과 크기·랭크 기반 합치기를 사용하는가?
13. 최단 경로 트리와 최소 스패닝 트리의 목적을 구분하는가?

Kruskal의 핵심은 싼 간선을 무조건 선택하는 것이 아니다. 현재까지 선택한 간선과 사이클을 만들지 않는 가장 싼 간선만 선택한다. Disjoint Set은 이 간선이 서로 다른 두 컴포넌트를 연결하는 안전한 선택인지 빠르게 알려준다.
