스택(Stack)은 한쪽 끝에서만 원소를 넣고 꺼내는 선형 자료구조다. 가장 나중에 넣은 원소를 가장 먼저 꺼내므로 LIFO(Last-In, First-Out) 구조라고 부른다.

```text
push(1) → push(2) → push(3)

Top
┌───┐
│ 3 │  ← 가장 먼저 꺼냄
├───┤
│ 2 │
├───┤
│ 1 │
└───┘
Bottom

pop 순서: 3 → 2 → 1
```

스택은 원소를 어떻게 저장하는지보다 **어느 위치의 원소에 접근할 수 있는지**를 제한하는 인터페이스가 핵심이다.

## 스택이 제공하는 기본 연산

스택에서는 가장 위에 있는 원소를 Top이라고 한다.

| 연산 | 역할 |
|---|---|
| `push(value)` | Top에 새 원소를 추가한다. |
| `pop()` | Top 원소를 제거한다. |
| `top()` | Top 원소를 제거하지 않고 확인한다. |
| `empty()` | 원소가 없는지 확인한다. |
| `size()` | 저장된 원소 수를 반환한다. |

가운데 원소를 인덱스로 읽거나 삭제하는 연산은 스택 인터페이스에 포함되지 않는다. 제한된 인터페이스 덕분에 사용하는 쪽에서도 “가장 최근 원소만 처리한다”는 규칙을 코드로 표현할 수 있다.

```cpp
std::stack<int> values;
values.push(1);
values.push(2);
values.push(3);

while (!values.empty())
{
    std::cout << values.top() << ' ';
    values.pop();
}
```

출력 순서는 삽입 순서의 반대인 `3 2 1`이다.

## std::stack은 컨테이너 어댑터다

`std::stack`은 원소를 저장하는 독자적인 메모리 구조를 직접 노출하지 않는다. 내부 컨테이너의 기능 중 스택에 필요한 연산만 골라서 제공하는 컨테이너 어댑터(Container Adapter)다.

```text
std::stack 인터페이스
push / pop / top / empty / size
            │
            ▼
내부 컨테이너
push_back / pop_back / back / empty / size
```

기본 기반 컨테이너는 `std::deque<T>`다.

```cpp
std::stack<int> first;
std::stack<int, std::deque<int>> second;
```

두 선언은 같은 기반 컨테이너를 사용한다. 필요한 연산을 제공한다면 `std::vector`나 `std::list`도 선택할 수 있다.

```cpp
std::stack<int, std::vector<int>> vectorStack;
std::stack<int, std::list<int>> listStack;
```

스택은 내부 컨테이너의 뒤쪽을 Top으로 사용한다. 따라서 기반 컨테이너에는 `back()`, `push_back()`과 `pop_back()`이 필요하다.

## vector로 스택을 직접 표현한다

`vector`의 마지막 원소를 Top으로 정하면 스택의 각 연산을 간단히 대응시킬 수 있다.

```cpp
template<typename T>
class Stack
{
public:
    void Push(const T& value)
    {
        container_.push_back(value);
    }

    void Pop()
    {
        container_.pop_back();
    }

    T& Top()
    {
        return container_.back();
    }

    const T& Top() const
    {
        return container_.back();
    }

    bool Empty() const
    {
        return container_.empty();
    }

    std::size_t Size() const
    {
        return container_.size();
    }

private:
    std::vector<T> container_;
};
```

컨테이너를 private 멤버로 두기 때문에 사용자는 중간 원소에 접근할 수 없다. `vector`가 제공하는 기능을 전부 공개하지 않고 LIFO 규칙에 필요한 기능만 남긴 것이다.

`Top()`은 원소를 복사하지 않고 접근할 수 있도록 참조를 반환한다. const 객체에서도 값을 읽을 수 있도록 const 오버로드도 함께 둔다.

## top과 pop을 나눈 이유

C++의 `std::stack::pop()`은 제거한 값을 반환하지 않는다.

```cpp
int value = values.top();
values.pop();
```

값 확인과 제거를 분리하면 다음처럼 참조로 원소를 읽은 뒤 필요한 시점에 제거할 수 있다. 값을 반환하는 과정에서 복사나 이동이 필요하지 않다는 점도 중요하다.

반환값이 필요한 `pop()`을 직접 설계할 수도 있지만, 값의 이동 또는 복사가 예외를 던질 때 원소 제거와 반환 중 어느 상태를 보장할지 함께 정해야 한다. `top()`과 `pop()`이 분리된 인터페이스는 이 두 작업의 책임을 명확히 나눈다.

단, `top()`이 반환한 참조는 해당 원소를 `pop()`한 뒤에는 더 이상 사용할 수 없다.

```cpp
int& value = values.top();
values.pop();
// value 사용 불가
```

## 빈 스택에서는 top과 pop을 호출하지 않는다

`top()`과 `pop()`은 스택이 비어 있지 않다는 전제에서 사용한다.

```cpp
if (!values.empty())
{
    int value = values.top();
    values.pop();
}
```

빈 `std::stack`에서 `top()`이나 `pop()`을 호출하는 것은 전제 조건을 어기는 동작이며, 일반적으로 Undefined Behavior로 이어진다. 반드시 예외가 발생하거나 프로그램이 즉시 종료된다고 기대할 수 없다.

직접 만든 스택이라면 다음 중 하나를 인터페이스 정책으로 선택할 수 있다.

```text
1. 호출자가 Empty()를 먼저 확인하도록 전제한다.
2. 비어 있으면 예외를 던진다.
3. 성공 여부와 값을 함께 반환한다.
```

표준 `std::stack`과 같은 형태를 학습할 때는 첫 번째 방식을 사용한다.

## 연산의 시간 복잡도는 기반 컨테이너에 따라 달라진다

`std::stack`의 각 연산은 내부 컨테이너의 대응 연산과 같은 복잡도를 가진다.

`std::deque`를 기반으로 할 때 대표적인 연산은 다음과 같다.

| 스택 연산 | 내부 연산 | 시간 복잡도 |
|---|---|---:|
| `push()` | `push_back()` | $O(1)$ |
| `pop()` | `pop_back()` | $O(1)$ |
| `top()` | `back()` | $O(1)$ |
| `empty()` | `empty()` | $O(1)$ |
| `size()` | `size()` | $O(1)$ |

`vector`를 기반으로 하면 `push_back()`은 재할당이 없는 경우 $O(1)$이고, 재할당이 발생한 한 번은 기존 원소를 옮겨야 하므로 $O(N)$이다. 여러 번의 연속 추가를 기준으로는 분할 상환 $O(1)$이다.

```text
vector 기반 Push
개별 최악: O(N)
분할 상환: O(1)
```

따라서 “스택의 push는 무조건 최악 $O(1)$”이라고 쓰기보다 어떤 기반 컨테이너와 비용 기준을 사용하는지 함께 본다.

스택에 원소가 $N$개 들어 있다면 저장 공간은 $O(N)$이다.

## 괄호 짝 검사에 스택을 사용하는 이유

문자열의 여는 괄호를 만날 때마다 스택에 넣고, 닫는 괄호를 만나면 가장 최근의 여는 괄호와 짝이 맞는지 확인한다.

```text
입력: {[()]}

{  → push('{')
[  → push('[')
(  → push('(')
)  → top '('와 짝 확인 후 pop
]  → top '['와 짝 확인 후 pop
}  → top '{'와 짝 확인 후 pop

마지막에 스택이 비어 있음 → 모든 괄호가 올바르게 닫힘
```

닫는 괄호는 가장 가까운 아직 닫히지 않은 여는 괄호와 짝을 이뤄야 한다. “가장 최근에 들어온 미완료 작업을 먼저 처리한다”는 규칙이 LIFO와 정확히 맞는다.

```cpp
bool IsOpening(char value)
{
    return value == '(' || value == '[' || value == '{';
}

bool IsPair(char opening, char closing)
{
    return (opening == '(' && closing == ')') || (opening == '[' && closing == ']') || (opening == '{' && closing == '}');
}

bool HasBalancedBrackets(std::string_view text)
{
    Stack<char> openings;

    for (char value : text)
    {
        if (IsOpening(value))
        {
            openings.Push(value);
        }
        else if (value == ')' || value == ']' || value == '}')
        {
            if (openings.Empty() || !IsPair(openings.Top(), value))
            {
                return false;
            }

            openings.Pop();
        }
    }

    return openings.Empty();
}
```

문자열을 한 번 순회하고 각 괄호를 최대 한 번 넣고 꺼낸다.

```text
시간 복잡도: O(N)
공간 복잡도: O(N), 모든 문자가 여는 괄호인 최악의 경우
```

마지막에 스택이 비었는지도 확인해야 한다. 입력이 `(((`라면 순회 중 잘못된 닫는 괄호는 없지만 아직 닫히지 않은 괄호가 남아 있기 때문이다.

## 스택이 자연스럽게 사용되는 문제

### 실행 취소

문서 편집기의 각 작업을 스택에 넣으면 가장 최근 작업부터 역순으로 취소할 수 있다.

```text
문자 입력 → 색상 변경 → 이미지 삽입
                         ↑ 가장 먼저 취소
```

실행 취소와 다시 실행을 모두 지원할 때는 Undo 스택과 Redo 스택을 따로 둘 수 있다. 새로운 작업을 실행하면 이전 Redo 기록을 비우는 정책도 함께 필요하다.

### 깊이 우선 탐색

DFS는 앞으로 탐색할 정점을 스택에 저장해 반복문으로 구현할 수 있다. 재귀 DFS도 함수 호출이 중첩되는 구조를 이용해 가장 최근 호출부터 복귀한다.

### 후위 표기식 계산

피연산자를 스택에 넣고 연산자를 만나면 필요한 값을 꺼내 계산 결과를 다시 넣는다. 중위 표기식을 후위 표기식으로 변환할 때도 연산자 우선순위와 괄호 처리를 위해 스택을 사용한다.

### 이전 상태로 되돌아가기

미로 탐색, 경로 복원과 backtracking에서는 선택한 상태를 스택에 쌓고 막다른 길에서 최근 선택으로 돌아갈 수 있다.

## 자료구조 스택과 호출 스택은 구분한다

자료구조 스택은 `push`, `pop`, `top`이라는 LIFO 인터페이스를 가진 추상 자료형이다. 호출 스택(Call Stack)은 실행 중인 함수의 반환 위치, 매개변수와 지역 상태 등을 관리하는 런타임 메커니즘이다.

중첩 호출이 가장 최근 함수부터 반환된다는 점에서는 LIFO 원리가 나타난다.

```text
Main 호출
  └─ A 호출
       └─ B 호출

반환 순서: B → A → Main
```

하지만 C++의 모든 지역 변수가 반드시 물리적인 스택 메모리에 저장된다고 단정할 수는 없다. 컴파일러는 레지스터를 사용하거나 값을 제거할 수 있고, 언어 표준은 특정한 물리 메모리 배치를 요구하지 않는다. 자료구조 `std::stack`과 호출 스택도 서로 다른 개념이다.

재귀 깊이가 지나치게 커지면 호출 스택 공간이 부족해질 수 있다. 반복문과 명시적인 자료구조 스택으로 바꾸면 저장 공간을 heap 기반 컨테이너가 관리하게 할 수 있지만, 알고리즘의 최대 저장량 자체가 사라지는 것은 아니다.

## 전체 예제

다음 코드는 `vector`를 기반으로 만든 스택의 LIFO 순서와 괄호 짝 검사를 함께 확인한다.

```cpp
#include <cstddef>
#include <iostream>
#include <string_view>
#include <vector>

template<typename T>
class Stack
{
public:
    void Push(const T& value) { container_.push_back(value); }
    void Pop() { container_.pop_back(); }
    T& Top() { return container_.back(); }
    const T& Top() const { return container_.back(); }
    bool Empty() const { return container_.empty(); }
    std::size_t Size() const { return container_.size(); }

private:
    std::vector<T> container_;
};

bool IsOpening(char value)
{
    return value == '(' || value == '[' || value == '{';
}

bool IsPair(char opening, char closing)
{
    return (opening == '(' && closing == ')') || (opening == '[' && closing == ']') || (opening == '{' && closing == '}');
}

bool HasBalancedBrackets(std::string_view text)
{
    Stack<char> openings;

    for (char value : text)
    {
        if (IsOpening(value))
        {
            openings.Push(value);
        }
        else if (value == ')' || value == ']' || value == '}')
        {
            if (openings.Empty() || !IsPair(openings.Top(), value))
            {
                return false;
            }

            openings.Pop();
        }
    }

    return openings.Empty();
}

int main()
{
    Stack<int> numbers;
    numbers.Push(1);
    numbers.Push(2);
    numbers.Push(3);

    std::cout << "pop order:";

    while (!numbers.Empty())
    {
        std::cout << ' ' << numbers.Top();
        numbers.Pop();
    }

    std::cout << '\n';
    std::cout << std::boolalpha;
    std::cout << "{[()]}: " << HasBalancedBrackets("{[()]}") << '\n';
    std::cout << "{[(])}: " << HasBalancedBrackets("{[(])}") << '\n';
    std::cout << "remaining numbers: " << numbers.Size() << '\n';
}
```

실행 결과는 다음과 같다.

```text
pop order: 3 2 1
{[()]}: true
{[(])}: false
remaining numbers: 0
```

첫 번째 출력은 가장 나중에 넣은 3부터 꺼내지는 LIFO 순서를 보여준다. 두 번째 문자열은 모든 괄호가 올바르게 중첩되지만, 세 번째 문자열은 `(`이 열린 상태에서 `]`가 나오므로 실패한다.

## 스택을 사용할 때 확인할 기준

1. 가장 최근에 들어온 원소를 먼저 처리하는 문제가 맞는가?
2. 중간 원소에 접근하지 않고 Top만으로 문제를 해결할 수 있는가?
3. `top()`과 `pop()`을 호출하기 전에 비어 있지 않은지 확인했는가?
4. `top()`이 반환한 참조를 `pop()` 이후에 사용하지 않는가?
5. `pop()`은 값을 반환하지 않는다는 점을 알고 있는가?
6. 기반 컨테이너가 필요한 뒤쪽 연산을 제공하는가?
7. 기반 컨테이너에 따라 `push()`의 최악 복잡도가 달라질 수 있음을 구분하는가?
8. 괄호 검사에서는 닫는 괄호의 짝뿐 아니라 마지막 빈 상태도 확인하는가?
9. 재귀 호출 스택의 깊이가 입력에 따라 얼마나 증가하는지 고려했는가?
10. 자료구조 스택과 런타임 호출 스택을 같은 개념으로 단정하지 않는가?

스택의 핵심은 데이터를 저장하는 컨테이너의 종류가 아니다. 접근 가능한 위치를 Top 하나로 제한해 가장 최근 작업을 먼저 처리한다는 규칙을 표현하는 데 있다.
