레드 블랙 트리는 일반 BST와 같은 위치에 새 노드를 삽입한 뒤 색상 규칙을 복구한다. 새 노드를 검정으로 넣으면 그 노드를 지나는 경로의 Black Height가 즉시 증가하므로, 새 노드는 빨간색으로 시작한다.

```text
빨간 노드 삽입

Black Height 변화 없음
부모가 검정이면 모든 규칙 유지
부모가 빨강이면 빨강 연속 규칙만 위반
```

삽입 직후 확인할 핵심은 새 노드의 부모가 빨간색인지다. 부모가 검정이면 더 할 일이 없다. 부모도 빨강이면 조부모와 삼촌의 색, 새 노드가 놓인 방향에 따라 색상 변경과 회전을 수행한다.

## 검정 NIL 센티널을 전제로 한다

경우를 단순하게 다루기 위해 모든 빈 자식 자리에 하나의 검정 NIL 센티널이 연결된 구현을 가정한다.

```cpp
enum class Color
{
    Red,
    Black
};

struct Node
{
    int key = 0;
    Color color = Color::Red;
    Node* parent = nullptr;
    Node* left = nullptr;
    Node* right = nullptr;
};
```

```text
실제 노드의 빈 자식 → nil_
nil_->color        → Black
root_->parent      → nil_
```

센티널을 사용하면 `nullptr`인지 확인한 뒤 색을 읽는 분기를 반복하지 않아도 된다. `nil_`은 키를 가진 실제 데이터 노드가 아니며 중위 순회와 크기 계산에서 제외한다.

`nullptr`을 검정으로 취급하는 구현도 가능하지만, 아래 코드처럼 `uncle->color`와 `node->parent->color`를 바로 읽으려면 센티널 연결이 올바르게 유지되어야 한다.

## BST 위치에 빨간 노드를 삽입한다

이번 예제는 `std::set`처럼 중복 키를 삽입하지 않는 정책을 사용한다.

```cpp
bool Insert(int key)
{
    Node* parent = nil_;
    Node* current = root_;

    while (current != nil_)
    {
        parent = current;

        if (key == current->key)
        {
            return false;
        }

        current = key < current->key ? current->left : current->right;
    }

    Node* node = new Node{};
    node->key = key;
    node->color = Color::Red;
    node->parent = parent;
    node->left = nil_;
    node->right = nil_;

    if (parent == nil_)
    {
        root_ = node;
    }
    else if (key < parent->key)
    {
        parent->left = node;
    }
    else
    {
        parent->right = node;
    }

    FixInsert(node);
    return true;
}
```

삽입 위치를 찾는 과정은 기본 BST와 같다. 차이는 새 노드의 두 자식을 검정 NIL로 연결하고, 빨간색으로 삽입한 뒤 `FixInsert`를 호출한다는 점이다.

## 삽입 직후 가능한 상태를 나눈다

새 노드를 `N`, 부모를 `P`, 조부모를 `G`, 삼촌을 `U`라고 하자.

```text
          G
        /   \
       P     U
      /
     N
```

### 새 노드가 루트인 경우

부모가 NIL이므로 새 노드를 검정으로 바꾼다.

```text
N(R) → N(B)
```

루트가 검정으로 바뀌면 모든 NIL 경로에 같은 검정 노드 하나가 추가되므로 Black Height 규칙은 유지된다.

### 부모가 검정인 경우

새 노드가 빨강이어도 빨간 노드가 연속하지 않는다. Black Height도 바뀌지 않았으므로 종료한다.

```text
    P(B)
    /
  N(R)
```

### 부모가 빨강인 경우

빨간 부모와 빨간 자식이 연속되어 규칙을 위반한다.

```text
      G(B)
      /
    P(R)
    /
  N(R)
```

삽입 전 트리가 유효했다면 `P`가 빨강일 때 `G`는 반드시 검정이다. 이제 `U`의 색과 노드 배치를 확인한다.

## 삼촌이 빨강이면 색상 문제를 위로 올린다

부모와 삼촌이 모두 빨강인 경우다.

```text
복구 전

          G(B)
        /      \
      P(R)     U(R)
      /
    N(R)
```

`P`와 `U`를 검정으로 바꾸면 `N-P`의 빨강 연속이 사라진다. 두 경로에 검정 노드가 하나씩 추가되므로 `G`를 빨강으로 바꿔 Black Height 증가를 상쇄한다.

```text
색상 변경 후

          G(R)
        /      \
      P(B)     U(B)
      /
    N(R)
```

현재 서브트리 내부의 규칙은 복구됐지만 `G`의 부모도 빨강이라면 새로운 빨강 연속이 생길 수 있다. 따라서 검사 위치를 `G`로 올리고 같은 과정을 반복한다.

```cpp
parent->color = Color::Black;
uncle->color = Color::Black;
grandparent->color = Color::Red;
node = grandparent;
```

색상 문제가 루트까지 올라가면 마지막에 루트를 검정으로 바꾼다.

## 삼촌이 검정이면 회전으로 모양을 바꾼다

삼촌이 검정 또는 NIL이면 부모 쪽 경로에만 빨간 노드가 연속되어 있다. 이 경우 조부모를 중심으로 회전하고 색을 조정한다.

방향은 네 가지지만 좌우 대칭 관계가 있다.

```text
LL ↔ RR
LR ↔ RL
```

먼저 부모가 조부모의 왼쪽 자식인 경우를 살펴본다.

## LL 형태는 조부모에서 오른쪽 회전한다

새 노드가 부모의 왼쪽에 있다.

```text
복구 전

          G(B)
         /    \
       P(R)   U(B)
       /
     N(R)
```

`P`를 검정, `G`를 빨강으로 바꾸고 `G`에서 오른쪽 회전한다.

```text
복구 후

          P(B)
        /      \
      N(R)     G(R)
                 \
                 U(B)
```

중위 순서는 `N < P < G < U`로 유지된다. 새 서브트리 루트 `P`가 검정이므로 바깥 경로의 Black Height도 이전과 같다.

```cpp
parent->color = Color::Black;
grandparent->color = Color::Red;
RotateRight(grandparent);
```

## LR 형태는 부모 회전 후 LL로 바꾼다

부모는 조부모의 왼쪽 자식이지만 새 노드는 부모의 오른쪽 자식이다.

```text
          G(B)
         /
       P(R)
          \
          N(R)
```

바로 `G`를 오른쪽 회전하면 중간 노드 `N`이 원하는 위치에 올라오지 않는다. 먼저 `P`에서 왼쪽 회전해 일직선 형태로 바꾼다.

```text
P에서 왼쪽 회전

          G(B)
         /
       N(R)
       /
     P(R)
```

이제 `N`을 부모 역할로 보고 LL 처리를 적용한다. `N`을 검정, `G`를 빨강으로 바꾸고 `G`에서 오른쪽 회전한다.

```text
          N(B)
        /      \
      P(R)     G(R)
```

```cpp
node = parent;
RotateLeft(node);

parent = node->parent;
grandparent = parent->parent;
parent->color = Color::Black;
grandparent->color = Color::Red;
RotateRight(grandparent);
```

삼각형 형태는 부모에서 한 번 회전해 일직선으로 만든 뒤 조부모에서 반대 방향으로 한 번 더 회전한다.

## RR과 RL은 좌우를 뒤집는다

부모가 조부모의 오른쪽 자식인 경우는 앞선 두 경우의 대칭이다.

### RR 형태

```text
복구 전                 복구 후

    G(B)                    P(B)
      \                    /    \
      P(R)       →       G(R)   N(R)
        \
        N(R)
```

`P`를 검정, `G`를 빨강으로 바꾸고 `G`에서 왼쪽 회전한다.

### RL 형태

```text
    G(B)
      \
      P(R)
      /
    N(R)
```

`P`에서 오른쪽 회전해 RR 형태로 만든 뒤, 색을 바꾸고 `G`에서 왼쪽 회전한다.

```text
P에서 오른쪽 회전      G에서 왼쪽 회전과 색상 변경

    G(B)                       N(B)
      \                       /    \
      N(R)          →       G(R)   P(R)
        \
        P(R)
```

## FixInsert의 전체 흐름

다음 코드는 NIL 센티널이 검정이고, 왼쪽·오른쪽 회전이 부모와 루트 연결까지 처리한다는 전제의 구현이다.

```cpp
void FixInsert(Node* node)
{
    while (node->parent->color == Color::Red)
    {
        Node* parent = node->parent;
        Node* grandparent = parent->parent;

        if (parent == grandparent->left)
        {
            Node* uncle = grandparent->right;

            if (uncle->color == Color::Red)
            {
                parent->color = Color::Black;
                uncle->color = Color::Black;
                grandparent->color = Color::Red;
                node = grandparent;
                continue;
            }

            if (node == parent->right)
            {
                node = parent;
                RotateLeft(node);
                parent = node->parent;
                grandparent = parent->parent;
            }

            parent->color = Color::Black;
            grandparent->color = Color::Red;
            RotateRight(grandparent);
        }
        else
        {
            Node* uncle = grandparent->left;

            if (uncle->color == Color::Red)
            {
                parent->color = Color::Black;
                uncle->color = Color::Black;
                grandparent->color = Color::Red;
                node = grandparent;
                continue;
            }

            if (node == parent->left)
            {
                node = parent;
                RotateRight(node);
                parent = node->parent;
                grandparent = parent->parent;
            }

            parent->color = Color::Black;
            grandparent->color = Color::Red;
            RotateLeft(grandparent);
        }
    }

    root_->color = Color::Black;
}
```

`while` 조건은 현재 노드가 아니라 부모의 색을 검사한다. 새 노드가 검정으로 바뀌지 않았더라도 부모가 검정이면 빨강 연속 문제가 없기 때문이다.

삼촌이 빨간 경우에는 `node`를 조부모로 올려 반복할 수 있다. 삼촌이 검정인 회전 경우에는 현재 지역의 위반이 해결되므로 추가 전파 없이 반복 조건이 끝난다.

마지막의 `root_->color = Black`은 새 노드가 처음 루트가 된 경우와 색상 전파가 기존 루트까지 올라간 경우를 함께 처리한다.

## 회전 횟수와 시간 복잡도

BST 삽입 위치를 찾는 데 $O(\log N)$이 걸린다. 색상 변경은 조부모 방향으로 여러 단계 전파될 수 있으므로 최악 $O(\log N)$이다.

삽입 복구에서 구조 회전은 최대 두 번이다.

```text
LL 또는 RR → 회전 1번
LR 또는 RL → 회전 2번
삼촌 빨강  → 색상 변경 후 위로 이동, 회전은 아직 없음
```

따라서 전체 삽입 시간은 $O(\log N)$이고 회전 자체는 각 $O(1)$이다.

색상 변경이 여러 번 발생할 수 있다는 사실과 회전 횟수가 상수로 제한된다는 사실을 구분해야 한다.

## 복구 뒤 검증해야 할 규칙

삽입 결과가 BST 순서만 만족한다고 끝난 것이 아니다.

```text
1. 루트는 검정인가?
2. 모든 NIL은 검정으로 취급되는가?
3. 빨간 노드의 부모와 자식은 검정인가?
4. 모든 노드에서 각 NIL까지 Black Height가 같은가?
5. 중위 순회 결과가 정렬돼 있는가?
6. 모든 자식의 parent가 실제 부모를 가리키는가?
```

작은 삽입 순서를 사용해 각 경우를 따로 만들 수 있다.

```text
LL: 30, 20, 10
LR: 30, 10, 20
RR: 10, 20, 30
RL: 10, 30, 20
```

삼촌이 빨간 색상 변경은 다음 순서 등으로 확인할 수 있다.

```text
10, 5, 15, 1
```

`1`을 삽입하면 부모 `5`와 삼촌 `15`가 모두 빨강이므로 색상 변경이 발생한다.

## 삽입 복구에서 확인할 기준

1. NIL 센티널이 항상 검정인가?
2. 새 노드의 부모와 두 자식을 올바르게 연결했는가?
3. 새 노드를 빨간색으로 시작하는가?
4. 부모가 검정이면 즉시 종료하는가?
5. 부모가 빨강일 때 조부모가 존재하는가?
6. 부모가 조부모의 왼쪽인지 오른쪽인지 구분하는가?
7. 삼촌의 위치를 부모 반대편에서 찾는가?
8. 삼촌이 빨강이면 부모·삼촌·조부모를 올바르게 재색칠하는가?
9. 재색칠 후 검사 위치를 조부모로 올리는가?
10. LR과 RL을 먼저 일직선 형태로 바꾸는가?
11. LL과 RR에서 부모와 조부모의 색을 바꾼 뒤 회전하는가?
12. 회전 중 루트와 중간 서브트리의 부모 연결을 갱신하는가?
13. 복구 마지막에 루트를 검정으로 만드는가?
14. 삽입 후 BST 순서와 모든 색상 규칙을 함께 검증하는가?

삽입 복구의 핵심은 네 방향을 서로 다른 공식으로 외우는 것이 아니다. 부모가 조부모의 어느 쪽인지 먼저 나누고, 삼촌이 빨강이면 색상 문제를 위로 올리며, 삼촌이 검정이면 꺾인 형태를 일직선으로 만든 뒤 조부모를 회전한다는 흐름을 이해하는 데 있다.
