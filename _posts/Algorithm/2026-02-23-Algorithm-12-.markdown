격자 미로에서 입구부터 출구까지 가장 적은 칸을 이동하는 경로를 찾고 싶다. 모든 상하좌우 이동 비용이 같다면 BFS로 최단 이동 횟수를 구할 수 있다.

```text
#########
#S..#..G#
#.#...#.#
#.......#
#########

S: 시작점
G: 목적지
.: 이동 가능한 칸
#: 벽
```

그래프 BFS에서는 정점 번호를 큐에 넣었다. 격자에서는 `(y, x)` 좌표가 정점 번호의 역할을 한다.

## 격자를 그래프로 해석한다

이동 가능한 각 칸을 정점으로 보고 상하좌우로 이동할 수 있는 두 칸을 간선으로 연결한다.

```text
격자 좌표             그래프 관계

(1,1) ─ (1,2)        (1,1)과 (1,2)가 간선으로 연결
  │
(2,1)                (1,1)과 (2,1)이 간선으로 연결
```

벽과 격자 바깥은 정점으로 사용하지 않는다.

```text
정점: 이동 가능한 좌표
간선: 상하좌우 한 칸 이동
간선 비용: 모두 1
```

따라서 시작점에서 목적지까지의 최소 간선 수가 미로의 최소 이동 횟수다.

## 좌표 순서는 y, x로 통일한다

2차원 배열은 `grid[y][x]`로 접근한다.

```cpp
struct Pos
{
    int y;
    int x;

    friend bool operator==(const Pos&, const Pos&) = default;
};
```

```text
(0,0) ─────────→ x
  │
  │
  ↓
  y
```

상하좌우 이동량도 `{y 변화량, x 변화량}` 순서로 저장한다.

```cpp
constexpr std::array<Pos, 4> Directions{{{-1, 0}, {0, -1}, {1, 0}, {0, 1}}};
```

```text
{-1,  0}: 위
{ 0, -1}: 왼쪽
{ 1,  0}: 아래
{ 0,  1}: 오른쪽
```

좌표 구조체의 멤버 순서, 방향 배열과 2차원 배열 접근 순서가 모두 같아야 한다.

## 이동 가능한 칸인지 먼저 확인한다

다음 좌표를 큐에 넣기 전에 격자 범위 안이고 벽이 아닌지 확인한다.

```cpp
bool CanGo(const std::vector<std::string>& grid, Pos position)
{
    int height = static_cast<int>(grid.size());
    int width = static_cast<int>(grid[0].size());

    return position.y >= 0 && position.y < height && position.x >= 0 && position.x < width && grid[position.y][position.x] != '#';
}
```

범위 조건은 실제 배열 접근보다 먼저 검사한다. C++의 `&&`는 왼쪽부터 평가하며 앞의 조건이 false면 뒤쪽 표현식을 평가하지 않으므로 범위를 벗어난 좌표로 `grid[y][x]`를 읽지 않는다.

모든 행의 너비가 같다는 전제도 필요하다. 일반적인 직사각형 격자 입력에서는 읽는 단계에서 행 길이를 확인한다.

## 발견 배열은 좌표를 큐에 한 번만 넣게 한다

그래프의 `discovered[vertex]`가 격자에서는 2차원 배열이 된다.

```cpp
std::vector<std::vector<bool>> discovered(height, std::vector<bool>(width, false));
```

시작점을 큐에 넣는 순간 발견 표시한다.

```cpp
std::queue<Pos> pending;
pending.push(start);
discovered[start.y][start.x] = true;
```

다음 칸도 큐에 넣을 때 바로 표시한다.

```cpp
if (!CanGo(grid, next) || discovered[next.y][next.x])
{
    continue;
}

discovered[next.y][next.x] = true;
pending.push(next);
```

격자에서는 같은 칸으로 들어오는 경로가 여러 개일 수 있다. 발견 표시를 큐에서 꺼낼 때까지 미루면 그 칸이 중복으로 들어갈 수 있다.

## 거리 배열로 발견 여부까지 표현할 수 있다

각 좌표의 최단 거리를 `-1`로 초기화하면 아직 발견하지 않은 상태도 함께 나타낼 수 있다.

```cpp
std::vector<std::vector<int>> distance(height, std::vector<int>(width, -1));
distance[start.y][start.x] = 0;
```

새 칸을 발견할 때 현재 거리보다 1 크게 기록한다.

```cpp
distance[next.y][next.x] = distance[current.y][current.x] + 1;
```

```text
distance == -1 → 아직 발견하지 않음
distance >= 0  → 시작점에서 해당 칸까지의 최단 이동 횟수
```

이렇게 하면 별도의 `discovered` 배열 없이 거리 배열 하나로 중복 발견을 막을 수 있다.

## 부모 좌표는 어디에서 왔는지 기록한다

목적지까지의 거리만 필요하면 distance 배열로 충분하다. 실제 이동 좌표가 필요하면 각 칸을 처음 발견한 이전 좌표를 저장한다.

```cpp
std::vector<std::vector<Pos>> parent(height, std::vector<Pos>(width, {-1, -1}));
parent[start.y][start.x] = start;
```

```cpp
parent[next.y][next.x] = current;
```

```text
Parent[자식 좌표] = 자식을 처음 발견한 부모 좌표
```

예를 들어 출구가 `(1,7)`이고 부모 관계가 다음과 같다고 하자.

```text
(1,7) ← (2,7) ← (3,7) ← ... ← (1,1)
 출구                                  입구
```

출구에서 부모를 따라가면 입구까지 역순으로 이동할 수 있다.

## BFS 탐색 흐름

한 좌표를 큐에서 꺼낸 뒤 네 방향을 확인한다.

```cpp
while (!pending.empty())
{
    Pos current = pending.front();
    pending.pop();

    if (current == goal)
    {
        break;
    }

    for (Pos direction : Directions)
    {
        Pos next{current.y + direction.y, current.x + direction.x};

        if (!CanGo(grid, next) || distance[next.y][next.x] != -1)
        {
            continue;
        }

        distance[next.y][next.x] = distance[current.y][current.x] + 1;
        parent[next.y][next.x] = current;
        pending.push(next);
    }
}
```

큐에는 시작점에서 가까운 좌표부터 들어 있다. 목적지를 큐에서 꺼낸 시점에는 최단 거리와 부모가 이미 확정돼 있으므로 탐색을 종료할 수 있다.

목적지를 처음 발견해 큐에 넣는 순간 종료해도 최단 경로 하나를 구할 수 있다. 큐에서 꺼낼 때 종료하는 방식은 흐름이 단순하고 목적지 상태가 다른 정점과 같은 방식으로 처리된다는 장점이 있다.

## 출구에 도달했는지 먼저 확인한다

벽으로 완전히 막힌 출구는 발견되지 않는다.

```text
#####
#S#G#
#####
```

탐색이 끝난 뒤 다음 값으로 도달 여부를 확인한다.

```cpp
if (distance[goal.y][goal.x] == -1)
{
    return std::nullopt;
}
```

도달하지 못했는데 부모 배열을 역추적하면 `{-1, -1}` 같은 sentinel 좌표를 읽게 된다. 부모를 map으로 관리하면서 `operator[]`를 사용하면 존재하지 않는 목적지 키에 기본값이 새로 삽입될 수도 있다.

따라서 순서는 다음과 같아야 한다.

```text
BFS 종료
→ 목적지 발견 여부 확인
→ 도달했을 때만 부모 역추적
```

## 목적지에서 시작점까지 역추적한다

출구에 도달했다면 부모를 따라 좌표를 모은다.

```cpp
std::vector<Pos> path;

for (Pos current = goal; current != start; current = parent[current.y][current.x])
{
    path.push_back(current);
}

path.push_back(start);
std::reverse(path.begin(), path.end());
```

처음에는 목적지에서 입구 방향으로 저장된다.

```text
역추적: G → ... → S
reverse: S → ... → G
```

시작점과 목적지가 같다면 반복문은 실행되지 않고 시작 좌표 하나만 결과에 들어간다. 이때 최단 이동 횟수는 0, 경로 좌표 수는 1이다.

경로에 시작점과 목적지를 모두 넣었다면 다음 관계가 성립한다.

```text
이동 횟수 = 경로에 포함된 좌표 수 - 1
```

## 방향 순서는 최단 거리보다 경로 모양에 영향을 준다

최단 경로가 여러 개라면 먼저 발견한 부모에 따라 결과가 달라진다.

```cpp
Up → Left → Down → Right
```

이 순서로 이웃을 확인하면 같은 거리의 후보 중 위쪽, 왼쪽, 아래쪽, 오른쪽 순서가 부모 선택에 영향을 준다.

방향 배열의 순서를 바꿔도 BFS가 구한 이동 횟수는 최단이지만, 여러 최단 경로 중 선택되는 모양은 달라질 수 있다. 테스트에서 경로 좌표 전체를 비교한다면 방향 순서도 입력 조건의 일부로 고정해야 한다.

## 2차원 배열과 map으로 부모를 저장하는 차이

격자 크기가 정해져 있으면 부모를 2차원 배열로 만들 수 있다.

```cpp
std::vector<std::vector<Pos>> parent(height, std::vector<Pos>(width));
```

좌표로 바로 접근하므로 조회는 $O(1)$이고 모든 칸의 공간을 미리 사용한다.

```text
공간: O(height × width)
조회: O(1)
```

`std::map<Pos, Pos>`은 실제로 발견한 좌표만 키로 저장할 수 있지만 균형 이진 탐색 트리 기반이므로 삽입과 조회가 $O(\log V)$이고 노드별 메모리도 필요하다. `Pos`의 정렬 기준인 `operator<`도 정의해야 한다.

격자처럼 좌표 범위가 조밀하고 인덱스로 변환하기 쉬운 데이터는 2차원 배열이 자연스럽다. 매우 넓은 좌표 공간에서 실제 방문 칸이 적다면 hash map 같은 희소 저장 방식도 검토할 수 있다.

## 오른손 법칙과 BFS의 차이

| 비교 | 오른손 법칙 | BFS |
|---|---|---|
| 다음 이동 | 현재 방향과 벽을 기준으로 결정 | 같은 거리의 모든 후보를 큐에 저장 |
| 기록 | 실제 이동 Walk | 발견한 좌표와 부모 관계 |
| 막다른 길 | 직접 들어갔다가 되돌아옴 | 이미 발견한 상태를 유지하며 다른 후보 처리 |
| 최단 경로 | 일반적으로 보장하지 않음 | 모든 이동 비용이 같으면 보장 |
| 추가 공간 | 경로 기록 방식에 따라 다름 | 최대 $O(HW)$ |

BFS에서 큐에 들어간 여러 좌표는 플레이어가 동시에 실제로 이동한다는 뜻이 아니다. 가능한 탐색 상태를 거리 순서대로 처리하는 알고리즘 내부 데이터다. 최종적으로 부모를 역추적한 좌표만 실제 이동 경로로 사용할 수 있다.

## 경로 계산과 화면 재생을 분리한다

BFS는 초기화 단계에서 최단 경로를 한 번 계산할 수 있다. 이후 Update에서는 일정 시간마다 다음 좌표를 꺼내 플레이어 위치에 반영한다.

```text
BFS
→ Path에 S부터 G까지 좌표 저장
→ PathIndex = 0

Update(deltaTime)
→ 이동 간격이 지났는지 확인
→ Position = Path[PathIndex]
→ PathIndex 증가
```

알고리즘 계산과 애니메이션 재생을 나누면 BFS의 정확성을 화면 속도와 독립적으로 확인할 수 있다. 같은 객체에서 경로를 다시 계산한다면 Path, PathIndex와 누적 시간도 함께 초기화한다.

## 전체 검증 예제

다음 코드는 5×9 격자에서 BFS로 최단 경로를 구한다. 경로에 포함된 중간 칸을 `*`로 표시하고 이동 횟수와 좌표 수를 확인한다.

```cpp
#include <algorithm>
#include <array>
#include <cassert>
#include <iostream>
#include <optional>
#include <queue>
#include <string>
#include <utility>
#include <vector>

struct Pos
{
    int y;
    int x;

    friend bool operator==(const Pos&, const Pos&) = default;
};

struct PathResult
{
    int distance;
    std::vector<Pos> path;
};

bool CanGo(const std::vector<std::string>& grid, Pos position)
{
    int height = static_cast<int>(grid.size());
    int width = static_cast<int>(grid[0].size());

    return position.y >= 0 && position.y < height && position.x >= 0 && position.x < width && grid[position.y][position.x] != '#';
}

std::optional<PathResult> FindShortestPath(const std::vector<std::string>& grid, Pos start, Pos goal)
{
    if (grid.empty() || grid[0].empty() || !CanGo(grid, start) || !CanGo(grid, goal))
    {
        return std::nullopt;
    }

    int height = static_cast<int>(grid.size());
    int width = static_cast<int>(grid[0].size());
    constexpr std::array<Pos, 4> directions{{{-1, 0}, {0, -1}, {1, 0}, {0, 1}}};
    std::vector<std::vector<int>> distance(height, std::vector<int>(width, -1));
    std::vector<std::vector<Pos>> parent(height, std::vector<Pos>(width, {-1, -1}));
    std::queue<Pos> pending;

    pending.push(start);
    distance[start.y][start.x] = 0;
    parent[start.y][start.x] = start;

    while (!pending.empty())
    {
        Pos current = pending.front();
        pending.pop();

        if (current == goal)
        {
            break;
        }

        for (Pos direction : directions)
        {
            Pos next{current.y + direction.y, current.x + direction.x};

            if (!CanGo(grid, next) || distance[next.y][next.x] != -1)
            {
                continue;
            }

            distance[next.y][next.x] = distance[current.y][current.x] + 1;
            parent[next.y][next.x] = current;
            pending.push(next);
        }
    }

    if (distance[goal.y][goal.x] == -1)
    {
        return std::nullopt;
    }

    std::vector<Pos> path;

    for (Pos current = goal; current != start; current = parent[current.y][current.x])
    {
        path.push_back(current);
    }

    path.push_back(start);
    std::reverse(path.begin(), path.end());
    return PathResult{distance[goal.y][goal.x], std::move(path)};
}

int main()
{
    std::vector<std::string> grid
    {
        "#########",
        "#S..#..G#",
        "#.#...#.#",
        "#.......#",
        "#########"
    };

    Pos start{1, 1};
    Pos goal{1, 7};
    std::optional<PathResult> result = FindShortestPath(grid, start, goal);

    assert(result.has_value());
    assert(result->distance == 8);
    assert(result->path.size() == 9);
    assert(result->path.front() == start);
    assert(result->path.back() == goal);

    for (Pos position : result->path)
    {
        if (position != start && position != goal)
        {
            grid[position.y][position.x] = '*';
        }
    }

    for (const std::string& row : grid)
    {
        std::cout << row << '\n';
    }

    std::cout << "shortest moves: " << result->distance << '\n';
    std::cout << "path positions: " << result->path.size() << '\n';
}
```

실행 결과는 다음과 같다.

```text
#########
#S**#**G#
#.#***#.#
#.......#
#########
shortest moves: 8
path positions: 9
```

이 격자에서는 시작점 오른쪽 통로와 가운데 연결 구간을 지나 목적지에 도달한다. 방향을 위, 왼쪽, 아래, 오른쪽 순서로 확인했으며, 같은 길이의 최단 경로가 여러 개 있는 격자에서는 이 순서에 따라 출력되는 경로 모양이 달라질 수 있다.

## 복잡도

격자의 높이를 $H$, 너비를 $W$라고 하자.

이동 가능한 각 칸은 최대 한 번 큐에 들어간다. 한 칸에서 상하좌우 네 방향만 확인하므로 간선 확인 횟수도 칸 수에 비례한다.

$$
V \leq HW, \qquad E \leq 4HW
$$

```text
시간 복잡도: O(HW)
추가 공간:   O(HW)
```

distance, parent와 queue가 각각 최악에 격자 칸 수에 비례하는 공간을 사용한다. 경로 자체는 최대 $O(HW)$개의 좌표를 가진다.

## 격자 BFS를 구현할 때 확인할 기준

1. 좌표와 배열 접근 순서를 `y, x`로 일관되게 사용하는가?
2. 모든 행의 너비가 같은 직사각형 격자인가?
3. 배열을 읽기 전에 범위를 검사하는가?
4. 벽과 이동 가능한 칸을 정확히 구분하는가?
5. 시작점과 목적지도 이동 가능한 칸인지 확인하는가?
6. 좌표를 큐에 넣는 순간 발견 또는 거리 표시를 하는가?
7. 새 좌표의 거리를 현재 거리보다 1 크게 기록하는가?
8. 부모 좌표를 처음 발견했을 때 한 번만 저장하는가?
9. 출구 도달 여부를 확인한 뒤에만 역추적하는가?
10. 역추적한 좌표를 시작점부터 사용하도록 뒤집는가?
11. 방향 순서가 여러 최단 경로 중 선택에 영향을 준다는 점을 아는가?
12. 모든 이동 비용이 같은 문제인지 확인하는가?
13. 경로 좌표 수와 이동 횟수의 차이를 구분하는가?
14. 경로 계산 상태와 화면 재생 상태를 각각 초기화하는가?

격자 BFS의 핵심은 2차원 배열을 큐로 순회하는 것만이 아니다. 좌표를 처음 발견한 순간 최단 거리와 부모를 함께 확정하고, 목적지에 도달한 뒤 그 부모 관계를 역순으로 따라가 실제 이동 경로를 만드는 데 있다.

## 다음 학습: 다익스트라 최단 경로
