카트는 게임이 시작되면 기본 속도인 초속 1로 달리고, 주어진 시간 `T` 동안 최대한 멀리 이동해야 한다. 경기 중에는 여러 신발 아이템이 정해진 시각에 생성된다.

신발 하나의 정보는 네 값으로 주어진다.

```text
a: 신발이 생성되는 시각
b: 신발을 착용하는 데 필요한 시간
c: 신발 효과가 유지되는 시간
d: 효과가 적용되는 동안의 속도
```

신발을 선택하면 `b`초 동안 제자리에 멈춰 착용한 뒤 `c`초 동안 속도 `d`로 달린다. 효과가 끝나면 다시 기본 속도로 돌아온다. 새 신발이 생성됐을 때 선택하지 않고 지나치면 나중에 다시 주울 수 없다.

또한 신발은 하나만 착용할 수 있다. 기존 신발의 효과가 남아 있어도 새 신발로 바꿀 수 있으며, 이때도 새 신발의 착용 시간만큼 멈춰야 한다.

## 신발을 신는 선택에는 손해와 이득이 함께 있다

속도가 높은 신발이라고 항상 좋은 것은 아니다.

```text
착용 전: b초 동안 이동 거리 0
착용 후: c초 동안 속도 d
```

남은 시간이 짧은데 착용 시간이 길다면 기본 속도로 계속 달리는 편이 더 멀리 갈 수 있다. 지금 가장 빠른 신발을 고르는 선택이 이후에 등장할 더 좋은 신발의 착용 기회를 막을 수도 있다.

```text
현재 신발의 속도가 빠름
        ↓
착용 시간이 길어 다음 신발의 생성 시각을 지나침
        ↓
전체 거리에서는 손해가 될 수 있음
```

각 신발을 선택하거나 지나치는 모든 조합을 단순 탐색할 수도 있지만 같은 신발을 선택한 이후의 계산이 여러 경로에서 반복된다.

## 시간 정보를 구간으로 바꾼다

신발의 입력값으로 효과 시작과 종료 시각을 미리 계산한다.

```text
생성 시각: spawn = a
효과 시작: start = a + b
효과 종료: end = a + b + c
속도: speed = d
```

```cpp
struct Shoe
{
    long long spawn;
    long long start;
    long long end;
    long long speed;

    Shoe(long long a, long long b, long long c, long long d) : spawn(a), start(a + b), end(a + b + c), speed(d)
    {
    }
};
```

현재 신발을 착용하기 시작한 시각은 `spawn`이고, `start`까지는 멈춘다. DP에서는 착용 대기 시간이 끝난 `start`부터의 이동 거리를 계산한다. `spawn`부터 `start`까지의 거리는 항상 0이므로 합계에서 생략할 수 있다.

## 현재 신발 이후의 최적 선택을 상태로 둔다

신발을 생성 시각 기준으로 정렬한 뒤 상태를 다음과 같이 정의한다.

```text
dp[i] = i번째 신발의 착용을 마친 시점부터 경기 종료까지 이동할 수 있는 최대 거리
```

`i`번째 신발을 선택했다면 두 가지 방향을 비교한다.

```text
1. 다른 신발을 선택하지 않고 T까지 달린다.
2. 이후 생성되는 신발 j로 갈아타고 dp[j]를 이어 붙인다.
```

어떤 경로로 `i`번째 신발을 선택했더라도 그 신발의 효과 시작 시각, 종료 시각, 속도는 같다. 이후 최적 결과는 이전 선택에 영향을 받지 않으므로 신발 인덱스 하나만 상태로 충분하다.

## 특정 구간에서 현재 신발로 이동한 거리를 구한다

현재 신발의 착용을 마친 시각부터 어떤 시각 `until`까지의 거리를 계산하는 함수를 만들자.

```cpp
long long DistanceUntil(const Shoe& shoe, long long until)
{
    if (until <= shoe.start)
    {
        return 0;
    }

    long long boostedEnd = std::min(until, shoe.end);
    long long boostedDistance = (boostedEnd - shoe.start) * shoe.speed;
    long long normalDistance = std::max(0LL, until - shoe.end);
    return boostedDistance + normalDistance;
}
```

구간은 두 부분으로 나뉜다.

```text
shoe.start ───── shoe.end ───── until
       속도 d             기본 속도 1
```

`until`이 효과 종료 전이라면 신발 속도로 달린 구간만 계산한다. 효과 종료 후라면 남은 구간에는 기본 속도 1을 적용한다.

## 착용 중에 생성된 신발은 선택할 수 없다

현재 신발의 착용이 끝나기 전에 다음 신발이 생성되면 그 신발을 주울 수 없다.

```text
현재 신발 생성        현재 신발 착용 완료
      a ├──── b초 정지 ────┤ a+b
                 ↑
           이 사이에 생성된 신발은 지나침
```

따라서 다음 신발 `j`를 선택하려면 최소한 다음 조건을 만족해야 한다.

```cpp
shoes[j].spawn >= shoes[i].start
```

선택할 수 있다면 현재 신발의 효과 시작부터 다음 신발의 생성 시각까지 이동한 뒤, `j`번째 신발을 착용하고 얻는 최적 결과를 이어 붙인다.

```text
후보 거리 = DistanceUntil(shoes[i], shoes[j].spawn) + dp[j]
```

`dp[j]`는 `j`의 착용 완료 시점부터 계산된다. `j`의 생성부터 착용 완료까지는 정지하므로 두 거리 사이에 더할 값은 없다.

## Top-down으로 선택을 탐색한다

```cpp
long long Solve(int current, long long totalTime, const std::vector<Shoe>& shoes, std::vector<long long>& memo)
{
    long long& result = memo[current];

    if (result != -1)
    {
        return result;
    }

    const Shoe& shoe = shoes[current];
    result = DistanceUntil(shoe, totalTime);

    for (int next = current + 1; next < static_cast<int>(shoes.size()); ++next)
    {
        if (shoes[next].spawn < shoe.start || shoes[next].spawn >= totalTime || shoes[next].start > totalTime)
        {
            continue;
        }

        long long distanceToNext = DistanceUntil(shoe, shoes[next].spawn);
        result = std::max(result, distanceToNext + Solve(next, totalTime, shoes, memo));
    }

    return result;
}
```

먼저 다른 신발을 더 신지 않고 종료 시각까지 달리는 경우를 기본값으로 둔다. 그다음 선택 가능한 모든 후속 신발을 시험해 더 먼 결과로 갱신한다.

신발은 생성 시각 순으로 정렬돼 있고 `next > current`인 방향으로만 이동한다. 상태 사이에 순환이 없는 DAG이므로 재귀 탐색과 메모이제이션을 사용할 수 있다.

## 기본 주행을 가상의 신발로 표현한다

게임 시작 상태도 별도로 처리하지 않고 같은 DP에 넣을 수 있다.

```text
가상 신발
생성 시각 0
착용 시간 0
효과 시간 T
속도 1
```

```cpp
long long MaximumDistance(long long totalTime, std::vector<Shoe> shoes)
{
    if (totalTime <= 0)
    {
        return 0;
    }

    std::sort(shoes.begin(), shoes.end(), [](const Shoe& left, const Shoe& right)
    {
        if (left.spawn != right.spawn)
        {
            return left.spawn < right.spawn;
        }

        return left.speed < right.speed;
    });

    shoes.insert(shoes.begin(), Shoe(0, 0, totalTime, 1));

    std::vector<long long> memo(shoes.size(), -1);
    return Solve(0, totalTime, shoes, memo);
}
```

가상 신발에서 종료 시각까지 달리는 선택은 아무 아이템도 줍지 않는 기본 주행을 뜻한다. 실제 신발로 전환하는 선택은 해당 신발의 생성 시각까지 기본 속도로 이동한 뒤 착용하는 경우가 된다.

실제 신발을 먼저 정렬한 뒤 가상 신발을 맨 앞에 넣었으므로 생성 시각이 0인 실제 신발도 시작 상태에서 선택할 수 있다. 가상 상태를 배열 밖의 별도 시작 상태로 두어도 같은 구조로 구현할 수 있다.

## 같은 시각에 생성되는 신발을 주의한다

여러 신발이 같은 시각에 생성될 수 있다면 단순히 정렬된 인덱스만으로 전이를 제한할 때 선택 가능한 후보가 정렬 순서에 따라 달라져서는 안 된다.

현재 구현에서는 하나의 신발을 선택하는 즉시 그 신발의 착용이 시작된다. 같은 시각에 생성된 다른 신발로 연속해서 갈아타는 것은 허용하지 않으며, 다음 신발의 생성 시각이 현재 신발의 착용 완료 시각 이상이어야 한다.

```text
b > 0인 신발을 선택
→ 같은 시각에 생성된 나머지 신발은 착용 중에 지나감
```

반면 착용 시간이 0인 신발 사이의 즉시 교체까지 허용하는 규칙이라면 같은 시각 상태 사이에 순환이나 정렬 의존성이 생길 수 있다. 그런 입력을 허용하는지는 문제 조건에서 별도로 확인해야 한다. 이 글의 구현은 실제 신발의 착용 시간이 양수라는 조건을 전제로 사용하거나, 같은 시각의 즉시 연속 교체를 허용하지 않는 규칙에 맞는다.

## 예제의 선택을 따라가 본다

```text
총 경기 시간 T = 20

(a=3,  b=4, c=10, d=3)
(a=4,  b=1, c=4,  d=2)
(a=10, b=2, c=5,  d=5)
(a=15, b=1, c=3,  d=7)
```

예를 들어 시각 3에 첫 번째 신발을 선택하면 시각 7까지 멈춘다. 따라서 시각 4에 생성되는 두 번째 신발은 선택할 수 없다. 이후 시각 10에 세 번째 신발이 생성될 때는 첫 번째 신발을 이미 착용한 상태이므로 세 번째 신발로 교체할 수 있다.

```text
0 ── 3      7 ── 10      12 ───── 17 ── 20
기본   착용 정지   속도 3   착용 정지   속도 5   기본
```

DP는 이 선택뿐 아니라 첫 번째 신발을 지나치고 두 번째 신발을 고르는 경우, 기본 속도로 계속 달리는 경우, 더 뒤의 신발부터 선택하는 경우를 모두 비교한다.

## 복잡도를 계산한다

신발이 $N$개라면 상태는 가상 신발을 포함해 $N+1$개다. 각 상태에서 뒤에 있는 모든 신발을 확인하므로 시간 복잡도는 $O(N^2)$이다. 메모 배열과 재귀 호출 스택은 $O(N)$ 공간을 사용한다.

```text
상태 수: O(N)
상태당 다음 신발 탐색: O(N)
전체 시간: O(N²)
```

입력 크기가 매우 크다면 생성 시각과 상태 값을 이용한 추가 최적화를 검토해야 한다. 하지만 전이 비용이 현재 신발의 효과 종료 시각에 따라 달라지므로 단순히 가장 큰 `dp[next]` 하나만 보관해서는 안 된다.

## 입력과 시간 범위를 검증한다

계산 전에 다음 조건을 확인해야 한다.

- 총 경기 시간과 네 입력값이 음수가 아닌가?
- 실제 신발의 착용 시간이 0일 수 있는가?
- `a + b + c`가 자료형의 범위를 넘지 않는가?
- 같은 생성 시각의 신발 선택 규칙이 명확한가?
- 경기 종료 이후 생성되거나 착용이 끝나는 신발을 어떻게 처리할 것인가?

거리에는 시간과 속도의 곱이 들어간다. 각각 `int` 범위여도 곱은 넘을 수 있으므로 시간, 속도, 거리 계산에 `long long`을 사용했다. 경기 종료 뒤까지 이어지는 효과는 `DistanceUntil`에서 `T`까지만 잘라 계산한다.

## 전체 검증 코드

```cpp
#include <algorithm>
#include <cassert>
#include <vector>

// Shoe, DistanceUntil, Solve, MaximumDistance 구현은 앞의 코드와 같다.

int main()
{
    assert(MaximumDistance(20, {}) == 20);

    std::vector<Shoe> example{
        Shoe(3, 4, 10, 3),
        Shoe(4, 1, 4, 2),
        Shoe(10, 2, 5, 5),
        Shoe(15, 1, 3, 7)
    };

    assert(MaximumDistance(20, example) == 50);
    assert(MaximumDistance(5, {Shoe(1, 10, 10, 100)}) == 5);
    assert(MaximumDistance(10, {Shoe(2, 2, 3, 1)}) == 10);
    assert(MaximumDistance(0, example) == 0);
}
```

아이템이 없는 경우에는 기본 속도로 `T`만큼 이동한다. 착용이 경기 안에 끝나지 않는 신발과 기본 속도보다 이득이 없는 신발은 지나쳐야 한다. 예제에서는 여러 선택을 비교한 최대 거리가 50인지 확인한다.

## 동적 계획법 파트를 마치며

동적 계획법은 문제에 `DP`라는 표시가 있어서 사용하는 기술이 아니다. 이전 선택의 모든 내용을 기억하는 대신, 앞으로의 결과를 결정하는 정보만 상태로 남기는 방법이다.

```text
ENCHANT    → 현재 강화 수치
LIS        → 현재 원소에서 끝나는 최대 길이
삼각형 경로 → 현재 칸까지의 최대 합
틱택토      → 보드 배치와 현재 차례
KART-RIDER → 현재 선택한 신발
```

각 문제의 겉모습은 다르지만 상태의 의미를 한 문장으로 정의하고, 가능한 다음 선택을 전이로 만들고, 종료 조건을 정한다는 흐름은 같다. 마지막으로 상태 수와 상태당 전이 수를 곱해 전체 복잡도가 입력 범위 안에 들어오는지 확인해야 한다.
