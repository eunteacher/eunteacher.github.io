버블·선택·삽입 정렬은 최악의 경우 $O(N^2)$번 비교하거나 원소를 이동한다. 입력 크기가 두 배가 되면 작업량이 약 네 배로 늘어날 수 있다.

힙 정렬(Heap Sort)과 병합 정렬(Merge Sort)은 서로 다른 방식으로 $O(N\log N)$ 정렬을 만든다.

```text
힙 정렬
→ 최댓값을 빠르게 꺼내 배열 뒤부터 확정

병합 정렬
→ 배열을 절반으로 나누고 정렬된 두 구간을 병합
```

시간 복잡도만 보면 같지만 메모리 사용과 안정성, 데이터 접근 방식은 다르다. 이번 글에서는 두 알고리즘의 정렬 완료 구간이 어떻게 만들어지는지 비교한다.

## 힙 정렬은 최대 힙을 이용한다

오름차순 정렬에서는 최대 힙을 만든다. 루트에는 현재 범위의 최댓값이 놓인다.

```text
배열: [8, 5, 7, 1, 4, 3]

최대 힙

        8
      /   \
     5     7
    / \   /
   1   4 3
```

루트의 최댓값을 배열 끝으로 보내면 마지막 위치를 정렬 완료 상태로 만들 수 있다.

```text
[8, 5, 7, 1, 4, 3]
 ↑              ↑
 root          end

교환
[3, 5, 7, 1, 4 | 8]
                  정렬 완료
```

정렬된 마지막 원소를 힙 범위에서 제외하고, 새 루트 `3`을 아래로 내려 남은 범위의 최대 힙 조건을 복구한다.

## SiftDown으로 힙 조건을 복구한다

`root`의 두 자식 중 더 큰 값을 선택한다. 선택한 자식이 부모보다 크면 교환하고 아래에서 같은 과정을 반복한다.

```cpp
void SiftDown(std::vector<int>& values, std::size_t root, std::size_t size)
{
    while (true)
    {
        std::size_t left = root * 2 + 1;

        if (left >= size)
        {
            break;
        }

        std::size_t right = left + 1;
        std::size_t largest = root;

        if (values[largest] < values[left])
        {
            largest = left;
        }

        if (right < size && values[largest] < values[right])
        {
            largest = right;
        }

        if (largest == root)
        {
            break;
        }

        std::swap(values[root], values[largest]);
        root = largest;
    }
}
```

`size`는 벡터 전체 크기가 아니라 현재 힙으로 사용하는 반열린 구간 `[0, size)`의 끝이다. 배열 뒤의 정렬 완료 구간을 실수로 다시 힙에 포함하지 않아야 한다.

## 배열 전체를 최대 힙으로 만든다

리프 노드는 자식이 없어 그 자체로 힙 조건을 만족한다. 자식을 가진 마지막 노드부터 루트 방향으로 `SiftDown`을 적용한다.

```cpp
for (std::size_t start = values.size() / 2; start > 0; --start)
{
    SiftDown(values, start - 1, values.size());
}
```

0 기반 배열에서 자식을 가진 마지막 노드는 `size / 2 - 1`이다. `std::size_t`는 부호 없는 타입이므로 `start >= 0`처럼 작성하면 0 아래로 내려가지 않고 매우 큰 값으로 돌아가 무한 반복할 수 있다. `start > 0`을 검사하고 실제 인덱스로 `start - 1`을 사용한다.

각 원소를 빈 힙에 하나씩 넣으면 $O(N\log N)$이지만, 아래 내부 노드부터 `SiftDown`하는 Build Heap은 $O(N)$이다. 리프에 가까운 많은 노드는 거의 이동하지 않고 루트에 가까운 적은 노드만 긴 거리를 이동하기 때문이다.

## 최댓값을 뒤로 보내며 힙 범위를 줄인다

```cpp
void HeapSort(std::vector<int>& values)
{
    for (std::size_t start = values.size() / 2; start > 0; --start)
    {
        SiftDown(values, start - 1, values.size());
    }

    for (std::size_t end = values.size(); end > 1; --end)
    {
        std::swap(values[0], values[end - 1]);
        SiftDown(values, 0, end - 1);
    }
}
```

반복이 시작될 때 유지되는 상태는 다음과 같다.

```text
[0, end)       → 최대 힙
[end, size)    → 오름차순 정렬 완료
```

한 번의 교환으로 현재 최댓값을 `end - 1`에 놓고, `SiftDown`으로 줄어든 힙을 복구한다.

```text
최대 힙: [8, 5, 7, 1, 4, 3]

1회: [7, 5, 3, 1, 4 | 8]
2회: [5, 4, 3, 1 | 7, 8]
3회: [4, 1, 3 | 5, 7, 8]
...
완료: [1, 3, 4, 5, 7, 8]
```

## 힙 정렬의 성질

Build Heap은 $O(N)$이고, 최댓값을 뒤로 보내는 작업을 $N-1$번 수행한다. 각 `SiftDown`은 $O(\log N)$이다.

$$
O(N) + O(N\log N) = O(N\log N)
$$

입력 상태와 관계없이 최악 $O(N\log N)$이며, 재귀 호출이나 별도 배열 없이 제자리에서 정렬할 수 있다.

일반적인 힙 정렬은 안정 정렬이 아니다. 루트와 배열 끝의 먼 원소를 교환하면서 같은 키를 가진 원소의 상대 순서가 바뀔 수 있다.

```text
(A, 3) (B, 3) (C, 1)

힙 구성과 루트 교환 과정에서 A와 B의 순서가 바뀔 수 있음
```

또한 힙의 부모·자식 인덱스를 오가므로 인접 구간을 순차적으로 읽는 알고리즘보다 캐시 지역성이 불리할 수 있다. 공간 복잡도와 최악 시간 보장이 장점이지만, 실제 성능은 표준 정렬 구현보다 빠르다고 단정할 수 없다.

## 병합 정렬은 구간을 절반으로 나눈다

병합 정렬은 분할 정복(Divide and Conquer) 구조를 사용한다.

```text
[8, 5, 7, 1, 4, 3]

분할
[8, 5, 7] [1, 4, 3]

다시 분할
[8] [5, 7] [1] [4, 3]

원소 하나가 되면 이미 정렬된 구간
```

각 절반을 재귀적으로 정렬한 뒤 정렬된 두 구간을 하나로 합친다.

```text
[5, 7] + [8]       → [5, 7, 8]
[1, 3] + [4]       → [1, 3, 4]
[5, 7, 8] + [1, 3, 4] → [1, 3, 4, 5, 7, 8]
```

## 반열린 구간으로 재귀 범위를 표현한다

`[left, right)` 구간을 정렬한다고 정의한다. 원소 수는 `right - left`다.

```cpp
void MergeSort(std::vector<int>& values, std::vector<int>& buffer, std::size_t left, std::size_t right)
{
    if (right - left <= 1)
    {
        return;
    }

    std::size_t mid = left + (right - left) / 2;
    MergeSort(values, buffer, left, mid);
    MergeSort(values, buffer, mid, right);
    Merge(values, buffer, left, mid, right);
}
```

구간의 원소가 0개나 1개면 이미 정렬돼 있으므로 종료한다. 두 재귀 호출이 끝난 시점에는 `[left, mid)`와 `[mid, right)`가 각각 정렬돼 있다.

## 정렬된 두 구간을 병합한다

두 구간의 앞 원소를 비교해 작은 값을 버퍼에 넣는다.

```text
왼쪽:  [2, 5, 8]
오른쪽: [1, 3, 7]

2와 1 비교 → 1
2와 3 비교 → 2
5와 3 비교 → 3
5와 7 비교 → 5
8과 7 비교 → 7
오른쪽 소진 → 남은 8

결과: [1, 2, 3, 5, 7, 8]
```

```cpp
void Merge(std::vector<int>& values, std::vector<int>& buffer, std::size_t left, std::size_t mid, std::size_t right)
{
    std::size_t leftIndex = left;
    std::size_t rightIndex = mid;
    std::size_t output = left;

    while (leftIndex < mid && rightIndex < right)
    {
        if (values[leftIndex] <= values[rightIndex])
        {
            buffer[output++] = values[leftIndex++];
        }
        else
        {
            buffer[output++] = values[rightIndex++];
        }
    }

    while (leftIndex < mid)
    {
        buffer[output++] = values[leftIndex++];
    }

    while (rightIndex < right)
    {
        buffer[output++] = values[rightIndex++];
    }

    for (std::size_t i = left; i < right; ++i)
    {
        values[i] = buffer[i];
    }
}
```

한쪽 구간이 먼저 소진되면 다른 구간의 남은 원소는 이미 정렬된 순서이므로 그대로 복사한다. 마지막에 버퍼의 병합 결과를 원래 배열 구간으로 옮긴다.

## 같은 값에서는 왼쪽 원소를 먼저 선택한다

병합 비교에 `<=`를 사용하면 값이 같은 경우 왼쪽 구간의 원소를 먼저 가져온다.

```text
왼쪽:  (A, 3)
오른쪽: (B, 3)

A와 B의 키가 같음
→ 왼쪽 A를 먼저 출력
→ 분할 전 상대 순서 유지
```

각 재귀 구간도 안정적으로 정렬되고 병합도 왼쪽의 같은 값을 먼저 선택하므로 전체 병합 정렬은 안정 정렬이 된다.

비교를 `<`로 작성해 같은 값에서 오른쪽을 먼저 선택하면 이 구현의 안정성이 깨진다.

## 버퍼는 한 번만 할당해 재사용한다

재귀 호출마다 새 벡터를 만들면 여러 메모리 할당이 발생한다. 정렬을 시작할 때 입력 크기의 버퍼를 한 번 만들고 모든 병합에서 재사용한다.

```cpp
void MergeSort(std::vector<int>& values)
{
    std::vector<int> buffer(values.size());
    MergeSort(values, buffer, 0, values.size());
}
```

배열 기반 병합 정렬은 원소 저장용 $O(N)$ 추가 공간과 $O(\log N)$ 재귀 호출 스택을 사용한다.

연결 리스트에서는 노드를 복사하는 대신 링크를 바꿔 병합할 수 있어 배열과 다른 공간 특성을 가질 수 있다. 자료구조에 따라 같은 알고리즘의 구현 방식이 달라진다.

## 이미 이어진 두 구간이면 병합을 생략할 수 있다

두 절반이 각각 정렬된 뒤 왼쪽의 마지막 값이 오른쪽의 첫 값보다 작거나 같다면 전체 구간도 이미 정렬돼 있다.

```cpp
if (values[mid - 1] <= values[mid])
{
    return;
}
```

이 검사는 두 재귀 호출 뒤, `Merge` 전에 둘 수 있다. 이미 정렬된 입력에서는 큰 병합 작업을 생략할 수 있다.

원소가 둘 이상인 경우에만 이 위치에 도달하므로 `mid - 1`은 유효하다. 최적화를 넣을 때도 구간 전제를 확인해야 한다.

## 병합 정렬의 시간 복잡도

배열은 원소 하나가 될 때까지 절반으로 나뉜다. 재귀 깊이는 $O(\log N)$이다.

각 깊이에서 모든 병합 구간의 원소 수를 합하면 $N$이다.

```text
깊이 0: N개 병합
깊이 1: N/2 + N/2 = N개 병합
깊이 2: N/4 × 4 = N개 병합
...
깊이 수: log N
```

따라서 전체 시간은 다음과 같다.

$$
T(N) = 2T(N/2) + O(N) = O(N\log N)
$$

기본 병합 정렬은 입력 순서와 관계없이 $O(N\log N)$이다. 앞서 설명한 병합 생략 최적화를 적용하면 이미 정렬된 입력에서 실제 작업량을 줄일 수 있지만, 일반적인 복잡도 비교에서는 최악과 평균 $O(N\log N)$으로 본다.

## 두 정렬을 비교한다

| 비교 | Heap Sort | Merge Sort |
|---|---:|---:|
| 최악 시간 | $O(N\log N)$ | $O(N\log N)$ |
| 평균 시간 | $O(N\log N)$ | $O(N\log N)$ |
| 추가 공간 | $O(1)$ | 배열 구현은 $O(N)$ |
| 안정성 | 불안정 | 안정적으로 구현 가능 |
| 접근 형태 | 부모·자식 인덱스 이동 | 두 정렬 구간을 순차 접근 |
| 핵심 구조 | 최대 힙 | 분할 정복과 병합 |

메모리 사용을 제한하면서 최악 시간을 보장해야 하면 힙 정렬의 성질이 유용하다. 같은 키의 순서를 유지해야 하거나 순차적인 병합이 데이터 접근 방식에 잘 맞으면 병합 정렬이 적합할 수 있다.

실제 C++ 코드에서는 요구사항에 따라 `std::sort`와 `std::stable_sort`를 우선 검토한다. 표준은 복잡도와 결과 성질을 규정하지만 내부에서 반드시 이 글의 구현 하나만 사용하도록 강제하지는 않는다.

## 전체 검증 예제

```cpp
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <vector>

// SiftDown, HeapSort, Merge와 재귀 MergeSort는 앞의 구현과 같다.

template<typename Sort>
void VerifySort(Sort sort)
{
    const std::vector<std::vector<int>> inputs{
        std::vector<int>{},
        std::vector<int>{1},
        std::vector<int>{1, 2, 3, 4, 5},
        std::vector<int>{5, 4, 3, 2, 1},
        std::vector<int>{8, 5, 7, 1, 4, 3},
        std::vector<int>{3, 1, 3, 2, 1}
    };

    for (std::vector<int> values : inputs)
    {
        std::vector<int> expected = values;
        std::sort(expected.begin(), expected.end());
        sort(values);
        assert(values == expected);
    }
}

int main()
{
    VerifySort(HeapSort);
    VerifySort([](std::vector<int>& values) { MergeSort(values); });
}
```

정렬 결과 검사는 값의 순서만 확인한다. 병합 정렬의 안정성까지 검증하려면 같은 키와 서로 다른 원래 순번을 가진 구조체를 사용해야 한다.

## 구현할 때 확인할 기준

1. 힙 범위와 뒤쪽 정렬 완료 범위를 구분하는가?
2. Build Heap을 마지막 내부 노드부터 시작하는가?
3. 부호 없는 인덱스를 0 아래로 감소시키지 않는가?
4. 하향 이동에서 두 자식 중 더 큰 값을 선택하는가?
5. 루트 교환 뒤 줄어든 힙 크기로 복구하는가?
6. 병합 정렬의 구간을 `[left, right)`로 일관되게 사용하는가?
7. 원소가 0개나 1개일 때 재귀를 종료하는가?
8. 두 절반을 정렬한 뒤 병합하는가?
9. 한쪽 구간이 소진된 뒤 남은 원소를 복사하는가?
10. 안정성이 필요하면 같은 값에서 왼쪽 원소를 먼저 선택하는가?
11. 병합 버퍼를 재귀마다 할당하지 않고 재사용하는가?
12. 빈 배열, 역순과 중복 입력을 모두 테스트하는가?
13. 메모리 제한과 안정성 중 어떤 요구사항이 중요한가?

힙 정렬과 병합 정렬은 같은 $O(N\log N)$에 도달하지만 그 이유가 다르다. 힙 정렬은 최댓값을 하나씩 확정하면서 매번 로그 시간에 힙을 복구하고, 병합 정렬은 로그 단계로 구간을 나눈 뒤 각 단계에서 전체 원소를 선형 시간에 병합한다.
