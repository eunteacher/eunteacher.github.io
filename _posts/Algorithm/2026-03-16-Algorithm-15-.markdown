# [Algorithm] 힙 트리(Heap Tree) 자료구조의 특징 및 배열 기반 구현

완전 이진 트리(Complete Binary Tree)의 일종으로, 부모와 자식 노드 간의 크기 관계를 이용해 우선순위 큐 등을 구현하는 데 최적화된 자료구조


## 1. 이론 정리 (Study Notes)

### 이진 트리(Binary Tree)의 기초
* **정의**: 모든 노드가 최대 2개의 자식 노드(Left, Right)만을 가질 수 있는 트리 구조
* **이진 검색 트리(BST)**: 데이터 탐색에 특화된 구조로, 특정 규칙에 따라 노드를 배치

| 구분 | 특징 및 조건 |
| :--- | :--- |
| **탐색 규칙** | 왼쪽 자식 < 부모 < 오른쪽 자식 관계를 유지함 |
| **시간 복잡도** | 균형 상태 시 $O(\log N)$, 불균형 시 $O(N)$까지 저하됨 |
| **한계점** | 삽입 순서에 따라 트리가 한쪽으로 치우치는 편향(Skewed) 문제 발생 |
| **해결책** | AVL 트리, Red-Black 트리 등을 통한 자가 균형(Self-Balancing) 유지 필요 |



### 힙 트리(Heap Tree)의 핵심 법칙
힙은 데이터의 최댓값 또는 최솟값을 빠르게 찾아내기 위해 고안된 완전 이진 트리

1. **힙의 1법칙 (Heap Property)**: 부모 노드의 값은 항상 자식 노드의 값보다 크거나 같음(Max Heap) 또는 작거나 같음(Min Heap)
2. **힙의 2법칙 (Shape Property)**: 마지막 레벨을 제외한 모든 노드가 채워져 있어야 하며, 마지막 레벨은 왼쪽부터 차례대로 채워져야 함(완전 이진 트리)
3. **구조적 특징**: 노드의 개수만 알면 트리의 전체적인 형태가 유일하게 결정

### 배열을 이용한 힙의 수식적 표현
힙은 완전 이진 트리이므로 별도의 포인터 없이 배열(Vector)만으로 효율적인 구현이 가능함

* **인덱스 관계식 ($i$번 노드 기준)**:
  * **왼쪽 자식(Left Child)**: $2i + 1$
  * **오른쪽 자식(Right Child)**: $2i + 2$
  * **부모 노드(Parent)**: $\lfloor (i - 1) / 2 \rfloor$


## 2. 종합 의견 (Review)

### 핵심 요약 및 주의사항
* **정렬 상태의 오해**: 힙은 형제 노드 간의 크기 순서를 보장하지 않으며, 오직 부모-자식 간의 수직적 관계만 유지하는 '느슨한 정렬' 상태
* **완전 이진 트리 준수**: 중간에 노드가 비어 있는 형태는 힙 트리로 간주하지 않으므로, 데이터 삭제 시 가장 마지막 노드를 루트로 옮긴 후 재정렬(Heapify)하는 과정이 필수
* **BST와의 목적 차이**: BST는 '전체 탐색/검색'에 유리하고, 힙은 '최댓값/최솟값 확인' 및 '우선순위 관리'에 특화되어 있음

### Tip
* **배열 기반 구현의 장점**: 포인터 연산을 생략하고 인덱스 산술만으로 노드에 접근하므로 캐시 적중률(Cache Locality)이 높고 메모리 효율성이 뛰어남
* **C++ STL 활용**: 실무에서는 직접 구현하기보다 `<algorithm>` 헤더의 `push_heap`, `pop_heap` 함수나 `<queue>`의 `priority_queue`를 사용하는 것이 안전하고 빠름
* **복잡도**: 삽입과 삭제 모두 $O(\log N)$의 시간 복잡도를 보장하므로 대량의 데이터 처리 시 성능 이점이 큼
