일반 트리는 노드마다 자식 목록을 가지고 계층 구조를 표현했다. 힙(Heap)은 트리의 모양과 부모·자식 사이의 우선순위에 제약을 추가해 최댓값이나 최솟값을 빠르게 꺼내는 데 사용한다.

```text
최대 힙(Max Heap)

        50
      /    \
    40      30
   /  \
 10    20
```

루트의 `50`은 전체 원소 중 최댓값이다. 하지만 힙이 모든 원소를 정렬해 두는 것은 아니다. `40`의 오른쪽에 있는 `30`보다 `20`이 작다는 식의 전체 순서는 보장하지 않는다.

힙을 이해하려면 다음 두 조건을 구분해야 한다.

1. 완전 이진 트리라는 **모양 조건**
2. 부모와 자식 사이의 **힙 조건**

두 조건을 함께 유지하기 때문에 배열 하나만으로 트리를 저장하면서 루트의 우선순위를 빠르게 확인할 수 있다.

## 완전 이진 트리는 왼쪽부터 채운다

이진 트리(Binary Tree)는 한 노드가 최대 두 자식을 가지는 트리다. 완전 이진 트리(Complete Binary Tree)는 여기에 노드가 채워지는 순서를 제한한다.

- 마지막 레벨을 제외한 레벨은 모두 채운다.
- 마지막 레벨은 왼쪽부터 빈자리 없이 채운다.

```text
완전 이진 트리          완전 이진 트리가 아님

      A                       A
    /   \                   /   \
   B     C                 B     C
  / \   /                   \   /
 D   E F                     E F
```

오른쪽 자식이 있는데 왼쪽 자식이 비어 있거나, 앞 레벨에 빈자리가 있는데 다음 레벨에 노드가 있으면 완전 이진 트리가 아니다.

노드 수가 $N$이면 완전 이진 트리의 높이는 $O(\log N)$이다. 새 노드를 항상 마지막 위치에 붙일 수 있고 마지막 노드도 배열의 끝에서 바로 찾을 수 있다.

## 최대 힙과 최소 힙

힙 조건은 부모와 직계 자식 사이에만 적용된다.

### 최대 힙

모든 부모가 자식보다 크거나 같다.

$$
parent \ge child
$$

따라서 루트에는 전체 최댓값이 놓인다.

```text
        50
      /    \
    40      30
   /  \
 10    20
```

### 최소 힙

모든 부모가 자식보다 작거나 같다.

$$
parent \le child
$$

따라서 루트에는 전체 최솟값이 놓인다.

```text
        10
      /    \
    20      30
   /  \
 50    40
```

같은 값을 여러 개 저장해도 된다. 최대 힙에서 부모와 자식의 값이 같아도 `부모 ≥ 자식` 조건을 만족한다.

## 힙은 정렬된 트리가 아니다

최대 힙에서는 부모가 자신의 자식보다 크다는 사실만 알 수 있다. 왼쪽 서브트리와 오른쪽 서브트리 사이의 대소 관계는 알 수 없다.

```text
        50
      /    \
    20      40
   /  \    /
 10   15  30
```

이 구조도 올바른 최대 힙이다. `20`이 오른쪽 형제 `40`보다 작아도 힙 조건에는 문제가 없다.

이 때문에 최대 힙에서 `30`을 찾으려면 최악의 경우 모든 노드를 확인해야 한다. 힙이 보장하는 빠른 연산은 루트의 최댓값 또는 최솟값 확인과 그 우선순위를 유지하는 삽입·삭제다.

## 완전 이진 트리를 배열로 저장한다

완전 이진 트리는 중간 빈자리가 없으므로 위에서 아래, 왼쪽에서 오른쪽 순서로 배열에 담을 수 있다.

```text
트리

        50
      /    \
    40      30
   /  \
 10    20

배열

index   0   1   2   3   4
value  50  40  30  10  20
```

0번 인덱스를 루트로 사용하면 `i`번 노드의 가족 인덱스는 다음과 같다.

$$
left(i) = 2i + 1
$$

$$
right(i) = 2i + 2
$$

$$
parent(i) = \left\lfloor\frac{i-1}{2}\right\rfloor \quad (i > 0)
$$

예를 들어 1번 인덱스의 자식은 3번과 4번이고, 4번 인덱스의 부모는 1번이다.

```cpp
int left = index * 2 + 1;
int right = index * 2 + 2;
int parent = (index - 1) / 2;
```

부모 공식은 루트가 아닌 `index > 0`에서만 사용한다. C++ 정수 나눗셈에서 `(0 - 1) / 2`가 수학적 바닥 함수와 같은 의미로 동작한다고 기대해서는 안 된다.

포인터와 별도 노드 객체가 없어도 인덱스 계산만으로 부모와 자식에 접근할 수 있다. 연속된 저장 공간을 사용하는 `std::vector`와도 잘 맞는다.

## 삽입은 마지막에서 위로 이동한다

최대 힙 `[50, 40, 30, 10, 20]`에 `45`를 삽입해 본다.

완전 이진 트리의 모양을 유지하려면 새 원소를 배열 끝에 추가한다.

```text
[50, 40, 30, 10, 20, 45]

        50
      /    \
    40      30
   /  \    /
 10   20  45
```

모양 조건은 만족하지만 부모 `30`보다 자식 `45`가 크므로 최대 힙 조건이 깨졌다. 두 값을 교환한다.

```text
[50, 40, 45, 10, 20, 30]

        50
      /    \
    40      45
   /  \    /
 10   20  30
```

`45`의 새 부모는 `50`이다. 부모가 더 크므로 이동을 멈춘다.

```text
1. 배열 끝에 삽입한다.
2. 부모와 힙 조건을 비교한다.
3. 조건이 깨졌으면 부모와 교환한다.
4. 조건을 만족하거나 루트에 도착할 때까지 반복한다.
```

이 과정을 상향 이동(Sift Up, Up-heap)이라고 한다. 완전 이진 트리의 높이만큼 이동하므로 시간 복잡도는 $O(\log N)$이다.

## 루트 삭제는 마지막 원소를 옮긴 뒤 아래로 이동한다

최대 힙에서 가장 우선순위가 높은 원소는 루트다.

```text
[50, 40, 45, 10, 20, 30]
```

루트만 제거하면 배열 앞에 빈자리가 생겨 완전 이진 트리의 모양이 깨진다. 먼저 마지막 값 `30`을 루트로 옮기고 배열 끝을 제거한다.

```text
[30, 40, 45, 10, 20]

        30
      /    \
    40      45
   /  \
 10    20
```

이제 모양은 유지됐지만 힙 조건이 깨졌다. 두 자식 중 더 큰 `45`와 교환한다.

```text
[45, 40, 30, 10, 20]

        45
      /    \
    40      30
   /  \
 10    20
```

```text
1. 루트 값을 보관한다.
2. 마지막 원소를 루트로 옮기고 배열 끝을 제거한다.
3. 두 자식 중 우선순위가 높은 자식을 고른다.
4. 부모의 우선순위가 낮으면 선택한 자식과 교환한다.
5. 힙 조건을 만족하거나 리프에 도착할 때까지 반복한다.
```

이 과정을 하향 이동(Sift Down, Down-heap)이라고 한다. 역시 트리 높이만큼 이동하므로 $O(\log N)$이다.

두 자식 중 아무 자식이나 선택하면 안 된다. 최대 힙에서는 더 큰 자식, 최소 힙에서는 더 작은 자식과 비교해야 한 번의 교환으로 현재 위치의 힙 조건을 회복할 수 있다.

## 힙의 주요 연산 비용

| 연산 | 시간 복잡도 | 이유 |
|---|---:|---|
| 루트 확인 | $O(1)$ | 배열의 0번 인덱스 |
| 원소 삽입 | $O(\log N)$ | 마지막에서 루트 방향으로 이동 |
| 루트 삭제 | $O(\log N)$ | 루트에서 리프 방향으로 이동 |
| 임의 값 검색 | $O(N)$ | 서브트리 사이의 전체 순서가 없음 |
| 마지막 원소 추가·제거 | 분할 상환 $O(1)$ | 동적 배열의 끝 사용 |

`std::vector`의 재할당이 일어나는 한 번의 `push_back`은 $O(N)$일 수 있다. 하지만 여러 번의 추가를 평균 내면 끝 삽입은 분할 상환(Amortized) $O(1)$이고, 힙 삽입 전체 비용은 상향 이동 때문에 $O(\log N)$으로 본다.

이미 존재하는 $N$개 원소를 아래쪽 내부 노드부터 차례로 하향 이동해 힙으로 만드는 Build Heap은 $O(N)$에 가능하다. 각 원소를 빈 힙에 하나씩 삽입하는 $O(N\log N)$ 방식과 구분해야 한다.

## 이진 탐색 트리와 목적이 다르다

힙과 이진 탐색 트리(Binary Search Tree)는 모두 이진 트리지만 유지하는 규칙이 다르다.

| 비교 | Heap | Binary Search Tree |
|---|---|---|
| 모양 | 완전 이진 트리 | 기본 BST는 모양 제한 없음 |
| 값의 규칙 | 부모와 자식의 우선순위 | 왼쪽 서브트리 < 노드 < 오른쪽 서브트리 |
| 빠른 작업 | 최댓값 또는 최솟값 확인 | 특정 키 검색 |
| 임의 값 검색 | $O(N)$ | 균형 상태에서 $O(\log N)$ |
| 배열 표현 | 자연스러움 | 일반적으로 연결 노드 사용 |

BST에서는 현재 값과 찾는 값을 비교해 왼쪽이나 오른쪽 중 한쪽을 버릴 수 있다. 힙에서는 부모보다 작은 값이 양쪽 서브트리 어디에나 있을 수 있어 같은 방식의 탐색이 불가능하다.

반대로 BST의 최댓값이나 최솟값은 트리 높이만큼 이동해야 하지만 힙은 필요한 극값을 항상 루트에 둔다. 어느 구조가 더 좋은지가 아니라 어떤 연산을 우선할지에 따라 선택한다.

## C++ 표준 라이브러리에서 확인하기

`<algorithm>`은 배열 범위를 힙으로 다루는 함수를 제공한다. 기본 비교는 최대 힙이다.

```cpp
#include <algorithm>
#include <cassert>
#include <vector>

int main()
{
    std::vector<int> heap{40, 10, 30, 50, 20};
    std::make_heap(heap.begin(), heap.end());

    assert(heap.front() == 50);
    assert(std::is_heap(heap.begin(), heap.end()));

    heap.push_back(45);
    std::push_heap(heap.begin(), heap.end());
    assert(heap.front() == 50);

    std::pop_heap(heap.begin(), heap.end());
    int highest = heap.back();
    heap.pop_back();

    assert(highest == 50);
    assert(heap.front() == 45);
    assert(std::is_heap(heap.begin(), heap.end()));
}
```

`std::pop_heap`은 마지막 원소를 직접 제거하지 않는다. 루트 원소를 범위의 끝으로 옮기고, 그 앞 범위가 다시 힙이 되도록 재배치한다. 실제 삭제는 이어지는 `pop_back`이 담당한다.

힙의 내부 배열 순서는 하나로 고정되지 않는다. `heap` 전체가 특정 배열과 같다고 검사하기보다 루트 값과 `std::is_heap`으로 힙 조건을 확인하는 편이 적절하다.

## 힙을 다룰 때 확인할 기준

1. 최대 힙과 최소 힙 중 어떤 우선순위가 필요한가?
2. 완전 이진 트리의 모양과 힙 조건을 따로 확인했는가?
3. 0 기반 인덱스 공식을 사용하고 있는가?
4. 루트에서 부모 인덱스를 계산하지 않는가?
5. 삽입 전에 배열 끝에 원소를 추가했는가?
6. 삭제 전에 힙이 비어 있지 않은지 확인했는가?
7. 하향 이동에서 두 자식 중 우선순위가 높은 쪽을 선택했는가?
8. 오른쪽 자식이 존재하는지 범위를 검사했는가?
9. 힙의 전체 배열이 정렬돼 있다고 가정하지 않는가?
10. 임의 값 검색이 필요하다면 힙이 목적에 맞는 자료구조인가?

힙의 핵심은 완전 이진 트리 덕분에 부모와 자식을 배열 인덱스로 찾고, 삽입과 삭제로 깨진 한 경로의 힙 조건만 복구하는 것이다. 전체를 정렬하지 않기 때문에 적은 비용으로 가장 높은 우선순위를 루트에 유지할 수 있다.
