이번 실습은 콘솔 격자에 미로를 만들고 플레이어가 입구에서 출구까지 이동할 경로를 미리 계산한다. 하나의 화면에서 동작하지만 실제 책임은 두 부분으로 나뉜다.

```text
Board::GenerateMap() → 벽과 통로로 이루어진 미로 생성
Player::Init()       → 오른손 법칙으로 이동 경로 계산
Player::Update()     → 계산된 경로를 일정 시간 간격으로 재생
```

미로 생성은 문제 공간을 만들고 오른손 법칙은 그 공간을 탐색한다. 두 알고리즘을 분리해서 봐야 생성된 미로가 왜 연결되는지, 탐색이 언제 끝나는지와 찾은 경로가 최단 경로인지 판단할 수 있다.

## 격자는 Tile[y][x]로 저장한다

이번 실습의 `Board`는 고정 크기 2차원 배열에 타일을 저장한다.

```cpp
enum class TileType
{
    None,
    Empty,
    Wall
};

TileType tiles[BoardMaxSize][BoardMaxSize]{};
```

첫 번째 인덱스 `y`는 행, 두 번째 인덱스 `x`는 열이다.

```text
y 증가: 아래쪽
x 증가: 오른쪽

(0,0) ─────────→ x
  │
  │
  ↓
  y
```

입구와 출구는 외곽 벽 안쪽의 홀수 좌표에 둔다.

```cpp
Pos GetEnterPos() const { return Pos{1, 1}; }
Pos GetExitPos() const { return Pos{size_ - 2, size_ - 2}; }
```

`Pos`는 멤버가 `y`, `x` 순서로 선언돼 `{y, x}`로 생성된다. 초기화 순서와 배열 접근 순서를 섞지 않도록 한 글 안에서 좌표 규칙을 일관되게 사용해야 한다.

## 맵 크기는 홀수여야 한다

이 구현은 짝수 좌표를 벽, 홀수 좌표를 방으로 사용한다.

```text
# # # # # # #
# . # . # . #
# # # # # # #
# . # . # . #
# # # # # # #
# . # . # . #
# # # # # # #
```

`.`은 방, `#`은 벽이다. 외곽을 벽으로 유지하면서 `(size - 2, size - 2)`를 방으로 만들려면 `size`가 3 이상의 홀수여야 한다.

```cpp
assert(size >= 3);
assert(size % 2 == 1);
assert(size <= BoardMaxSize);
```

고정 배열의 최대 크기가 100이라면 `size`는 그 범위를 넘을 수 없다. 짝수 크기에서는 입구·출구와 방 좌표 규칙도 성립하지 않으므로 초기화 단계에서 범위와 홀수 조건을 함께 확인한다.

## 첫 단계는 서로 막힌 방을 만든다

모든 좌표를 순회하면서 `x` 또는 `y`가 짝수면 벽으로 만든다.

```cpp
for (int y = 0; y < size; ++y)
{
    for (int x = 0; x < size; ++x)
    {
        if (x % 2 == 0 || y % 2 == 0)
        {
            tiles[y][x] = TileType::Wall;
        }
        else
        {
            tiles[y][x] = TileType::Empty;
        }
    }
}
```

홀수 좌표의 각 방 사이에는 벽 한 칸이 있다. 아직은 어떤 방에서도 다른 방으로 이동할 수 없다.

```text
방 중심 간 거리: 2칸

(1,1)  벽  (1,3)
  .     #     .
```

두 방을 연결하려면 가운데 벽 한 칸을 `Empty`로 바꾼다.

## 각 방에서 동쪽 또는 남쪽 벽 하나를 연다

이번 실습에서 사용하는 방식은 Binary Tree Maze 생성 알고리즘의 한 방향 변형이다. 각 방은 동쪽 또는 남쪽 중 하나를 선택해 통로를 만든다.

```cpp
for (int y = 1; y < size - 1; y += 2)
{
    for (int x = 1; x < size - 1; x += 2)
    {
        if (y == size - 2 && x == size - 2)
        {
            continue;
        }

        if (y == size - 2)
        {
            tiles[y][x + 1] = TileType::Empty;
        }
        else if (x == size - 2)
        {
            tiles[y + 1][x] = TileType::Empty;
        }
        else if (ChooseEast())
        {
            tiles[y][x + 1] = TileType::Empty;
        }
        else
        {
            tiles[y + 1][x] = TileType::Empty;
        }
    }
}
```

일반 방에서는 동쪽과 남쪽을 무작위로 선택한다. 경계에서는 선택할 수 있는 방향이 하나뿐이다.

```text
마지막 행의 방    → 동쪽으로 연결
마지막 열의 방    → 남쪽으로 연결
우하단 마지막 방  → 더 이상 연결하지 않음
```

방을 연결할 때는 전체 타일을 순회하며 짝수 좌표를 건너뛰거나, 홀수인 방 좌표만 `+= 2`로 순회할 수 있다. 두 반복 방식은 같은 방을 처리한다.

## 생성된 통로가 하나의 트리가 되는 이유

방을 정점, 방 사이에 연 벽을 간선으로 생각해 보자. 우하단 방을 제외한 모든 방은 동쪽이나 남쪽의 방으로 간선 하나를 만든다.

동쪽이나 남쪽으로 이동하면 좌표 합 `x + y`가 항상 증가한다. 따라서 이전 방으로 되돌아오는 방향 순환을 만들 수 없다.

```text
(y, x) → (y, x + 2) 또는 (y + 2, x)
x + y는 항상 증가
```

경계 규칙 때문에 모든 방에서 연결을 계속 따라가면 결국 우하단 방에 도달한다. 방의 개수를 $R$이라고 하면 다음 성질을 가진다.

```text
모든 방이 우하단 방과 연결됨
우하단을 제외한 각 방이 간선 하나 생성
전체 간선 수 = R - 1
순환 없음
```

연결된 정점 $R$개와 간선 $R-1$개를 가지므로 통로 그래프는 트리다. 따라서 임의의 두 방 사이 경로가 하나뿐인 perfect maze가 만들어진다.

여기서 “동쪽과 남쪽만 벽을 연다”는 뜻은 북쪽·서쪽 경계가 절대 열리지 않는다는 뜻이 아니다. 위쪽이나 왼쪽 이웃이 자신의 동쪽·남쪽 벽을 열면 현재 방의 서쪽·북쪽 통로가 될 수 있다.

## 생성 방식에는 방향 편향이 있다

각 방의 선택지가 동쪽과 남쪽으로 제한돼 미로 모양에도 편향이 생긴다. 마지막 행은 동쪽으로 이어지고 마지막 열은 남쪽으로 이어지는 긴 통로가 만들어진다.

```text
동일 확률 선택 ≠ 모든 미로 모양이 동일한 확률
```

단순하고 추가 탐색 상태가 거의 필요 없다는 장점이 있지만 자연스럽고 다양한 미로 분포가 필요한 경우에는 DFS 기반 backtracking, Prim이나 Kruskal 기반 생성 알고리즘을 비교해야 한다.

## 난수와 재현 가능성을 구분한다

간단한 구현에서는 다음 표현으로 방향을 선택할 수 있다.

```cpp
int randomValue = std::rand() % 2;
```

간단한 학습용 선택에는 사용할 수 있지만 전역 상태에 의존하고 시드 관리와 분포 품질을 제어하기 어렵다. 실행마다 다른 미로가 목적이라면 시드를 한 번 설정해야 하고, 버그 재현과 테스트가 목적이라면 고정 시드가 더 유용하다.

```cpp
std::mt19937 random(seed);
std::bernoulli_distribution chooseEast(0.5);
```

생성 함수 안에서 현재 시간을 매번 시드로 넣으면 짧은 시간에 여러 번 생성할 때 같은 결과가 나오거나 테스트 재현이 어려워질 수 있다. 난수 엔진의 소유 위치와 시드 정책을 호출 측에서 정한다.

## 방향 배열의 순서가 회전 공식을 결정한다

플레이어는 방향을 다음 순서로 저장한다.

```cpp
enum Direction
{
    Up,
    Left,
    Down,
    Right,
    DirectionCount
};

const Pos front[DirectionCount]
{
    {-1, 0},
    {0, -1},
    {1, 0},
    {0, 1}
};
```

인덱스가 증가하면 왼쪽으로 90도 회전한다.

```text
Up(0) → Left(1) → Down(2) → Right(3) → Up(0)
```

따라서 왼쪽 회전은 1을 더하고 오른쪽 회전은 1을 뺀다.

```cpp
int TurnLeft(int direction)
{
    return (direction + 1) % DirectionCount;
}

int TurnRight(int direction)
{
    return (direction - 1 + DirectionCount) % DirectionCount;
}
```

`+ DirectionCount`는 `Up`에서 1을 뺀 음수에 `%`를 적용하지 않도록 한다. 방향 배열을 `Up, Right, Down, Left` 순서로 바꾸면 회전 공식도 반대로 바뀐다. 공식만 복사하지 않고 enum 순서와 함께 유지한다.

## 오른손 법칙은 방향까지 상태로 사용한다

같은 위치에 있어도 어느 방향을 바라보는지에 따라 다음 행동이 달라진다.

```text
탐색 상태 = (현재 y, 현재 x, 바라보는 방향)
```

한 단계의 우선순위는 다음과 같다.

```text
1. 오른쪽 칸으로 갈 수 있다 → 오른쪽 회전 후 한 칸 전진
2. 오른쪽이 막히고 앞이 열렸다 → 직진
3. 오른쪽과 앞이 막혔다 → 제자리에서 왼쪽 회전
```

```cpp
while (current != destination)
{
    int right = TurnRight(direction);

    if (CanGo(current + front[right]))
    {
        direction = right;
        current += front[direction];
        path.push_back(current);
    }
    else if (CanGo(current + front[direction]))
    {
        current += front[direction];
        path.push_back(current);
    }
    else
    {
        direction = TurnLeft(direction);
    }
}
```

막다른 길에서는 왼쪽 회전이 여러 번 반복되고 뒤쪽 통로가 앞에 오면 이동한다. 회전만 한 상태는 위치 경로에 추가하지 않고 실제로 한 칸 움직였을 때만 좌표를 기록한다.

## CanGo는 격자 경계와 타일 종류를 함께 검사한다

`Board::GetTileType`은 범위를 벗어난 좌표에 `TileType::None`을 반환한다.

```cpp
TileType Board::GetTileType(Pos position) const
{
    if (position.x < 0 || position.x >= size_ || position.y < 0 || position.y >= size_)
    {
        return TileType::None;
    }

    return tiles_[position.y][position.x];
}
```

플레이어는 `Empty`인 칸만 이동 가능하다고 판단한다.

```cpp
bool Player::CanGo(Pos position) const
{
    return board_->GetTileType(position) == TileType::Empty;
}
```

이렇게 하면 탐색 코드가 배열을 직접 읽지 않고 보드가 경계 정책을 책임진다. 출구 좌표도 `Empty`여야 목적지에 도달할 수 있다.

## 오른손 법칙은 최단 경로 알고리즘이 아니다

벽을 따라가는 방식은 지나온 길을 되돌아가거나 목적지와 반대 방향의 통로를 먼저 탐색할 수 있다.

```text
도착 가능한 경로를 찾음 ≠ 이동 횟수가 가장 적은 경로
```

생성된 미로의 방 그래프는 트리이므로 방 사이의 단순 경로는 하나뿐이다. 하지만 오른손 법칙은 막다른 가지에 들어갔다 돌아올 수 있어 기록된 이동 경로에는 같은 칸이 반복될 수 있다.

가중치가 없는 격자에서 실제 최단 이동 경로가 필요하면 BFS로 각 칸의 부모를 기록한 뒤 목적지에서 시작점까지 역추적하는 방법이 적합하다. 이 내용은 알고리즘 12편에서 다룬다.

## 종료가 보장되지 않는 미로도 고려한다

고전적인 벽 따라가기 방법은 벽 구조와 입구·출구 조건에 따라 성공 여부가 달라진다. 서로 분리된 벽 섬이나 순환 통로가 있는 일반 미로에서는 목적지에 도달하지 못한 채 같은 상태를 반복할 수 있다.

이번 생성 방식은 연결되고 순환이 없는 통로 트리를 만들기 때문에 오른손 법칙과 함께 사용하기 좋은 조건이다. 다른 방식으로 만든 일반 미로까지 탐색하려면 반복 상태 검사로 성공과 실패를 구분할 수 있다.

```cpp
if (visited[current.y][current.x][direction])
{
    return false;
}

visited[current.y][current.x][direction] = true;
```

위치만 방문 처리하면 같은 칸을 다른 방향으로 다시 통과해야 하는 정상적인 벽 따라가기까지 막을 수 있다. 반복 여부는 `(위치, 방향)` 전체 상태로 판단한다.

## 경로 계산과 화면 재생을 분리한다

`Player::Init`은 미로를 한 번에 탐색해 `Path`를 만든다. `Player::Update`는 프레임마다 탐색을 다시 하지 않고 누적 시간이 이동 간격을 넘었을 때 다음 좌표를 꺼낸다.

```cpp
void Player::Update(std::uint64_t deltaTick)
{
    if (pathIndex_ >= path_.size())
    {
        return;
    }

    sumTick_ += deltaTick;

    if (sumTick_ >= MoveTick)
    {
        sumTick_ = 0;
        position_ = path_[pathIndex_];
        ++pathIndex_;
    }
}
```

```text
탐색 단계: Board를 읽어 Path 생성
재생 단계: Path를 시간 간격에 따라 Position에 반영
렌더 단계: 현재 Position을 색상으로 출력
```

알고리즘 검증과 애니메이션 속도를 분리할 수 있다는 장점이 있다.

같은 `Player` 객체를 새로운 미로에서 다시 사용한다면 `Path`뿐 아니라 `pathIndex`, `sumTick`과 초기 방향도 함께 초기 상태로 되돌려야 한다.

## 복잡도

보드의 높이와 너비가 모두 $S$인 정사각 격자라고 하자.

### 미로 생성

전체 타일 초기화는 $S^2$칸을 한 번씩 처리한다. 방 연결도 방 개수에 비례하며 방 개수는 $O(S^2)$이다.

```text
시간 복잡도: O(S²)
타일 저장 공간: O(S²)
추가 작업 공간: O(1), 타일 배열 제외
```

### 오른손 법칙

이번 생성 방식의 통로 그래프는 트리다. 벽 따라가기는 막다른 가지를 왕복할 수 있지만 트리의 통로를 상수 횟수 이내로 따라가므로 목적지까지 최악 이동량은 통로 크기에 선형인 $O(S^2)$로 볼 수 있다.

```text
탐색 시간: O(S²), 현재 생성된 perfect maze 기준
기록 경로: O(S²)
반복 상태 배열: O(S²)
```

임의의 순환 미로에서 종료 검사를 하지 않으면 시간 복잡도를 유한하게 보장할 수 없다. 상태 반복 검사를 넣으면 가능한 `(위치, 방향)` 수가 최대 $4S^2$이므로 그 안에서 성공 또는 실패를 결정할 수 있다.

## 전체 검증 예제

다음 코드는 고정 시드로 9×9 미로를 만들고 빈 타일 그래프가 트리인지 확인한 뒤 오른손 법칙으로 출구까지 이동한다. 생성과 탐색의 핵심 조건을 한 번에 확인하는 예제다.

```cpp
#include <array>
#include <cassert>
#include <cstdint>
#include <iostream>
#include <queue>
#include <random>
#include <string>
#include <utility>
#include <vector>

struct Pos
{
    int y;
    int x;

    friend bool operator==(const Pos&, const Pos&) = default;
};

class Maze
{
public:
    Maze(int size, std::uint32_t seed) : tiles_(size, std::string(size, '#'))
    {
        assert(size >= 3 && size % 2 == 1);
        Generate(seed);
    }

    int Size() const { return static_cast<int>(tiles_.size()); }
    Pos Enter() const { return {1, 1}; }
    Pos Exit() const { return {Size() - 2, Size() - 2}; }

    bool CanGo(Pos position) const
    {
        return position.y >= 0 && position.y < Size() && position.x >= 0 && position.x < Size() && tiles_[position.y][position.x] == '.';
    }

    bool IsPassageTree() const
    {
        int openCount = 0;
        int edgeCount = 0;

        for (int y = 0; y < Size(); ++y)
        {
            for (int x = 0; x < Size(); ++x)
            {
                if (!CanGo({y, x}))
                {
                    continue;
                }

                ++openCount;

                if (CanGo({y + 1, x}))
                {
                    ++edgeCount;
                }

                if (CanGo({y, x + 1}))
                {
                    ++edgeCount;
                }
            }
        }

        std::vector<std::vector<bool>> visited(Size(), std::vector<bool>(Size(), false));
        std::queue<Pos> pending;
        pending.push(Enter());
        visited[Enter().y][Enter().x] = true;
        int reachedCount = 0;

        while (!pending.empty())
        {
            Pos current = pending.front();
            pending.pop();
            ++reachedCount;

            for (Pos offset : Directions)
            {
                Pos next{current.y + offset.y, current.x + offset.x};

                if (CanGo(next) && !visited[next.y][next.x])
                {
                    visited[next.y][next.x] = true;
                    pending.push(next);
                }
            }
        }

        return reachedCount == openCount && edgeCount == openCount - 1;
    }

private:
    void Generate(std::uint32_t seed)
    {
        for (int y = 1; y < Size() - 1; y += 2)
        {
            for (int x = 1; x < Size() - 1; x += 2)
            {
                tiles_[y][x] = '.';
            }
        }

        std::mt19937 random(seed);
        std::bernoulli_distribution chooseEast(0.5);

        for (int y = 1; y < Size() - 1; y += 2)
        {
            for (int x = 1; x < Size() - 1; x += 2)
            {
                if (y == Size() - 2 && x == Size() - 2)
                {
                    continue;
                }

                if (y == Size() - 2)
                {
                    tiles_[y][x + 1] = '.';
                }
                else if (x == Size() - 2)
                {
                    tiles_[y + 1][x] = '.';
                }
                else if (chooseEast(random))
                {
                    tiles_[y][x + 1] = '.';
                }
                else
                {
                    tiles_[y + 1][x] = '.';
                }
            }
        }
    }

    inline static constexpr std::array<Pos, 4> Directions{{{-1, 0}, {0, -1}, {1, 0}, {0, 1}}};
    std::vector<std::string> tiles_;
};

struct SearchResult
{
    bool reached;
    std::vector<Pos> path;
};

SearchResult FollowRightWall(const Maze& maze)
{
    constexpr int directionCount = 4;
    constexpr std::array<Pos, directionCount> front{{{-1, 0}, {0, -1}, {1, 0}, {0, 1}}};

    Pos current = maze.Enter();
    int direction = 0;
    std::vector<Pos> path{current};
    std::vector<std::vector<std::array<bool, directionCount>>> visited(maze.Size(), std::vector<std::array<bool, directionCount>>(maze.Size()));

    while (current != maze.Exit())
    {
        if (visited[current.y][current.x][direction])
        {
            return {false, std::move(path)};
        }

        visited[current.y][current.x][direction] = true;
        int right = (direction - 1 + directionCount) % directionCount;
        Pos rightPosition{current.y + front[right].y, current.x + front[right].x};
        Pos frontPosition{current.y + front[direction].y, current.x + front[direction].x};

        if (maze.CanGo(rightPosition))
        {
            direction = right;
            current = rightPosition;
            path.push_back(current);
        }
        else if (maze.CanGo(frontPosition))
        {
            current = frontPosition;
            path.push_back(current);
        }
        else
        {
            direction = (direction + 1) % directionCount;
        }
    }

    return {true, std::move(path)};
}

int main()
{
    Maze maze(9, 2026);
    SearchResult result = FollowRightWall(maze);

    assert(maze.IsPassageTree());
    assert(result.reached);
    assert(result.path.front() == maze.Enter());
    assert(result.path.back() == maze.Exit());

    std::cout << std::boolalpha;
    std::cout << "Passage graph is a tree: " << maze.IsPassageTree() << '\n';
    std::cout << "Reached exit: " << result.reached << '\n';
    std::cout << "Recorded positions: " << result.path.size() << '\n';
}
```

고정 시드로 실행한 결과는 다음과 같다.

```text
Passage graph is a tree: true
Reached exit: true
Recorded positions: 13
```

`IsPassageTree`는 모든 빈 타일이 입구에서 연결되고 빈 타일 간 간선 수가 정점 수보다 하나 적은지 확인한다. 오른손 탐색은 같은 `(위치, 방향)` 상태가 반복되면 실패를 반환하며, 이 미로에서는 출구에 도달한다.

`Recorded positions`에는 시작 좌표와 실제 이동한 좌표만 들어가며 제자리 회전은 포함하지 않는다. 이 값은 고정 시드로 생성된 특정 미로의 결과일 뿐 모든 9×9 미로에서 같은 길이를 의미하지 않는다.

## 미로 생성과 탐색을 검토할 때 확인할 기준

1. `Tile[y][x]`의 좌표 순서를 모든 함수에서 일관되게 사용하는가?
2. 보드 크기가 홀수이고 고정 배열 범위 안인지 초기화할 때 검사하는가?
3. 방 좌표와 방 사이 벽 좌표를 구분하는가?
4. 마지막 행·열과 우하단 방의 경계 처리가 배열을 벗어나지 않는가?
5. 모든 방이 연결되고 간선 수가 방 수보다 하나 적은 이유를 설명할 수 있는가?
6. 동쪽·남쪽 선택이 미로 모양에 방향 편향을 만든다는 점을 아는가?
7. 난수 시드를 무작위 실행과 재현 가능한 테스트 목적에 맞게 관리하는가?
8. 방향 enum 순서와 좌·우 회전 공식이 일치하는가?
9. 탐색 상태를 위치뿐 아니라 바라보는 방향까지 포함해 판단하는가?
10. 오른손 법칙이 최단 경로를 보장하지 않는다는 점을 구분하는가?
11. 생성기가 바뀌어도 무한 반복하지 않도록 실패 조건이 있는가?
12. 경로 계산과 시간 기반 화면 재생을 분리하는가?
13. 재초기화할 때 경로 인덱스, 누적 시간과 방향도 초기화하는가?
14. 렌더 반복 범위가 하드코딩된 값이 아니라 실제 보드 크기를 사용하는가?

이 실습의 핵심은 무작위 벽 몇 개를 지우는 데 있지 않다. 생성 단계에서는 모든 방이 하나의 트리로 연결된다는 불변식을 만들고, 탐색 단계에서는 `(위치, 방향)` 상태와 오른쪽 우선 규칙으로 그 통로를 따라간다. 생성된 공간의 성질을 알아야 탐색의 종료 조건과 한계도 함께 설명할 수 있다.
