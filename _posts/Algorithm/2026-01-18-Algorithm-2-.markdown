이 글은 15 × 15 콘솔 미로를 만들고, 엔터를 누를 때마다 플레이어가 오른손 법칙으로 한 차례 행동하도록 구현하는 복습 기록이다. 실습 코드는 `.code/AlgorithmDay02/main.cpp`를 기준으로 한다.

**해야 할 일을 말로 정리하고 → 짧게 구현하고 → 실행 결과를 확인하는 순서**로 진행한다. 미로 생성과 플레이어 이동을 나누고, 처음에는 배열과 함수만 사용한다.

방향 순서는 `Up → Right → Down → Left`로 통일한다. 오른쪽 회전은 `+1`, 왼쪽 회전은 `+3`이다. 다른 코드의 방향 순서와 회전 공식을 섞지 않는다.

목표는 빈 C++ 프로젝트에서 미로를 만들고, 플레이어가 오른손 법칙으로 도착점까지 걷게 만드는 것이다. 완성 코드를 보지 않고 아래 설명과 짧은 힌트만으로 구현해보자.

한 단계를 구현하면 실행해서 확인하고 다음 단계로 넘어간다. 함수 이름과 변수 이름은 바꿔도 된다. 중요한 것은 각 코드가 하는 일을 설명할 수 있는 것이다.

## 1. 전체를 두 덩어리로 생각하기

| 구분 | 해야 할 일 |
| --- | --- |
| 미로 생성 | 벽과 방을 만들고, 방 사이 벽을 뚫어 연결한다. |
| 플레이어 | 위치와 방향을 기억하고, 길을 확인해서 이동하거나 회전한다. |

출력은 이 둘이 잘 작동하는지 확인하는 도구다. 처음에는 미로만 출력하고, 나중에 플레이어와 방향 표시를 붙인다.

최종 실행 흐름은 다음과 같다.

```text
미로 생성
플레이어 시작 위치와 방향 설정
시작 화면 출력
도착할 때까지 반복
  엔터 입력 기다리기
  한 차례 판단해서 이동 또는 회전
  이전 화면을 지우고 현재 상태 출력
도착 안내
```

## 2. 좌표와 데이터부터 정하기

미로는 15 × 15 크기의 배열로 만든다. 크기는 3 이상의 홀수로 정한다. 아래 설명에서 좌표는 항상 `(y, x)` 순서다.

```cpp
enum class TileType
{
  Wall,
  Empty
};

constexpr int boardSize = 15;
TileType tiles[boardSize][boardSize]{};
```

`tiles[y][x]`에서 `y`는 행, `x`는 열이다. 화면의 왼쪽 위가 `(0, 0)`이다.

| 이동 | 좌표 변화 |
| --- | --- |
| 위 | y가 1 감소 |
| 오른쪽 | x가 1 증가 |
| 아래 | y가 1 증가 |
| 왼쪽 | x가 1 감소 |

주의: `TileType` 배열의 `{}` 초기화는 첫 번째 값인 `Wall`로 채운다. 아래 초기화 함수에서는 모든 칸에 값을 직접 넣어서 규칙을 분명히 하자.

## 3. 미로 생성: 벽과 방 만들기

먼저 가로·세로 반복문으로 모든 칸을 방문한다.

- y와 x가 모두 홀수이면 빈 방으로 만든다.
- 나머지는 벽으로 만든다.

조건 힌트:

```cpp
y % 2 == 1 && x % 2 == 1
```

5 × 5로 생각하면 초기 모습은 다음과 같다. 실제 출력에서는 빈칸을 공백으로 표시해도 된다.

```text
#####
# # #
#####
# # #
#####
```

방은 `(1, 1)`, `(1, 3)`, `(3, 1)`, `(3, 3)`에 있다. 두 방 사이에는 벽 한 칸이 있다.

직접 할 일:

1. 초기화 함수를 작성한다.
2. 출력 함수를 작성한다. 벽은 `#`, 길은 공백으로 표시한다.
3. 각 행의 출력이 끝나면 줄을 바꾼다.

확인: 바깥 테두리가 전부 벽이고, 빈 방들이 서로 떨어져 있으면 성공이다.

## 4. 미로 생성: 방 사이의 벽 뚫기

이번 실습은 각 방에서 **오른쪽 또는 아래쪽**으로 연결하는 방식이다. 미로 생성 방향과 나중에 플레이어가 움직이는 방향은 별개다. 플레이어는 네 방향으로 다닐 수 있다.

방만 방문하려면 y와 x를 1부터 시작해 2씩 증가시킨다. 마지막 방의 좌표는 `boardSize - 2`다.

반복문 한쪽의 힌트:

```cpp
for (int y = 1; y < boardSize - 1; y += 2)
```

현재 방이 `(y, x)`일 때 벽과 다음 방의 위치를 구별하자.

| 방향 | 뚫을 벽 | 연결되는 방 |
| --- | --- | --- |
| 오른쪽 | `(y, x + 1)` | `(y, x + 2)` |
| 아래쪽 | `(y + 1, x)` | `(y + 2, x)` |

주요 코드 힌트:

```cpp
tiles[y][x + 1] = TileType::Empty; // 오른쪽 벽
tiles[y + 1][x] = TileType::Empty; // 아래쪽 벽
```

위 두 줄을 매번 모두 실행하는 것이 아니다. 아래 규칙에 따라 필요한 방향 하나를 선택한다.

| 현재 방 | 처리 |
| --- | --- |
| 오른쪽 아래 마지막 방 | 연결할 다음 방이 없으므로 건너뛴다. |
| 마지막 행의 방 | 아래에 방이 없으므로 오른쪽으로 연결한다. |
| 마지막 열의 방 | 오른쪽에 방이 없으므로 아래로 연결한다. |
| 그 밖의 방 | 오른쪽 또는 아래쪽 중 하나를 무작위로 고른다. |

### 먼저 구별하기: 마지막 방과 바깥 벽

크기가 15라면 배열의 좌표는 `0 ~ 14`다. 방의 좌표는 `1, 3, 5, 7, 9, 11, 13`이다.

- `boardSize - 1`, 즉 14는 바깥 벽의 좌표다.
- `boardSize - 2`, 즉 13은 마지막 방이 있는 행 또는 열의 좌표다.
- 여기서 '마지막 행'은 바깥 벽인 14행이 아니라 **방이 있는 마지막 행인 13행**을 말한다. 마지막 열도 마찬가지다.

각 방에서 물어볼 것은 **오른쪽에 연결할 방이 있는가? 아래쪽에 연결할 방이 있는가?** 두 가지다. 그 조합으로 아래 네 가지 상황이 생긴다.

| 상황 | 오른쪽에 방 | 아래쪽에 방 | 선택 |
| --- | --- | --- | --- |
| 오른쪽 아래 마지막 방 | 없음 | 없음 | 벽을 뚫지 않는다. |
| 마지막 행이지만 마지막 열은 아닌 방 | 있음 | 없음 | 오른쪽만 가능하다. |
| 마지막 열이지만 마지막 행은 아닌 방 | 없음 | 있음 | 아래쪽만 가능하다. |
| 마지막 행도 마지막 열도 아닌 방 | 있음 | 있음 | 두 방향 중 하나를 고른다. |

### 조건 1: 오른쪽 아래 마지막 방인가?

예: `(13, 13)`. 오른쪽과 아래쪽이 모두 미로 바깥을 향하므로 새로 연결할 방이 없다. 이 방에서는 아무 벽도 뚫지 않는다. 왼쪽이나 위쪽 방에서 이 방으로 연결해주므로 고립되는 것은 아니다.

조건 힌트:

```cpp
y == boardSize - 2 && x == boardSize - 2
```

이 방은 마지막 행과 마지막 열에도 해당한다. `continue;`로 이후 연결 처리를 건너뛰어 바깥 벽을 뚫지 않도록 한다.

### 조건 2: 방이 있는 마지막 행인가?

예: `(13, 5)`. 아래쪽 벽 `(14, 5)` 너머에 방이 없다. 그 벽을 뚫으면 방을 연결하는 것이 아니라 바깥 테두리에 구멍을 내게 된다.

반면 오른쪽에는 `(13, 7)` 방이 있으므로, 사이의 `(13, 6)` 벽을 뚫는다.

조건 힌트:

```cpp
y == boardSize - 2
```

마지막 모서리 방은 조건 1에서 이미 건너뛰었다. 따라서 여기까지 온 마지막 행의 방에는 반드시 오른쪽 방이 있다. 무작위 선택은 필요 없다.

### 조건 3: 방이 있는 마지막 열인가?

예: `(5, 13)`. 오른쪽 벽 `(5, 14)` 너머에 방이 없다. 오른쪽 바깥 벽은 그대로 둔다.

아래쪽에는 `(7, 13)` 방이 있으므로, 사이의 `(6, 13)` 벽을 뚫는다.

조건 힌트:

```cpp
x == boardSize - 2
```

이 경우에도 선택 가능한 방향은 아래쪽 하나뿐이다.

### 조건 4: 오른쪽과 아래쪽에 모두 방이 있는가?

예: `(5, 5)`. 오른쪽 `(5, 7)`과 아래쪽 `(7, 5)`에 모두 방이 있다. 이제 무작위로 한 방향을 고를 수 있다.

- 오른쪽을 골랐다면 `(5, 6)`의 벽만 뚫는다.
- 아래쪽을 골랐다면 `(6, 5)`의 벽만 뚫는다.

이 상황은 앞의 세 가지에 해당하지 않는 나머지 방이다. 별도로 복잡한 좌표 조건을 쓰지 않아도 된다. `chooseEast(random)`의 결과에 따라 한쪽만 선택하자.

### 검사 순서가 중요한 이유

`(13, 13)`은 마지막 방이면서 마지막 행에도, 마지막 열에도 속한다. 따라서 **가장 구체적인 조건인 마지막 모서리 방부터 처리**해야 한다.

만약 마지막 행부터 검사하면 `(13, 13)`에서도 오른쪽 벽 `(13, 14)`을 뚫어버린다. 배열 범위를 벗어난 것은 아니지만, 바깥 벽을 유지한다는 규칙을 어긴다.

전체 코드를 작성하기 전에 다음 순서를 말로 설명해보자.

```text
마지막 모서리 방이면 → 건너뛰기

마지막 행이면 → 오른쪽 벽 뚫기
그렇지 않고 마지막 열이면 → 아래쪽 벽 뚫기
그 밖의 방이면 → 무작위로 오른쪽 또는 아래쪽 벽 하나 뚫기
```

코드 구조는 `if (마지막 모서리) { continue; }` 다음에, 마지막 행부터 `if / else if / else`로 이어보자. 마지막 모서리 검사 뒤에 독립된 `if`를 쓸 수 있는 이유는, 모서리에서는 이미 `continue`로 아래 코드를 건너뛰었기 때문이다.

확인 질문: `(13, 5)`, `(5, 13)`, `(5, 5)`, `(13, 13)`에서 각각 어떤 처리를 해야 하는지 먼저 적어보고 코드를 작성하자.

난수 도구 힌트 (`#include <random>` 필요):

```cpp
std::random_device seed;
std::mt19937 random(seed());
std::bernoulli_distribution chooseEast(0.5);
```

이 준비 코드는 방을 순회하는 반복문 밖에 둔다. `chooseEast(random)`은 약 50% 확률로 `true`를 반환한다. `true`면 오른쪽, `false`면 아래쪽으로 연결해보자.

확인:

- 실행할 때마다 내부 모양이 달라지는가?
- 바깥 테두리는 그대로 벽인가?
- 마지막 행의 방들은 가로로 연결되는가?
- 마지막 열의 방들은 세로로 연결되는가?

이 방식에서는 각 방에서 오른쪽이나 아래쪽 연결을 따라가면 마지막 방에 도달한다. 좌표가 커지는 방향으로만 연결하므로 같은 방을 맴도는 연결도 생기지 않는다. 따라서 모든 방이 하나의 미로로 연결된다.

## 5. 플레이어: 위치와 방향 표시

플레이어는 미로 배열과 별도로 위치와 방향을 기억한다. 이동할 때 타일을 `P`로 바꿀 필요는 없다.

```cpp
enum class Direction
{
  Up,
  Right,
  Down,
  Left
};
```

시작 위치는 `(1, 1)`, 시작 방향은 `Up`으로 정한다. 도착점은 오른쪽 아래 방 `(boardSize - 2, boardSize - 2)`이다.

출력 함수에서는 현재 출력 중인 좌표가 플레이어 위치인지 **벽 검사보다 먼저** 확인한다. 플레이어 위치라면 방향에 맞는 문자를 출력한다.

| 방향 | 문자 |
| --- | --- |
| Up | `^` |
| Right | `>` |
| Down | `v` |
| Left | `<` |

확인: 시작 화면에서 두 번째 줄, 두 번째 칸에 `^`가 표시되어야 한다. `(0, 0)`은 바깥 벽이다.

## 6. 플레이어: 벽을 확인하고 한 칸 이동

실제 위치를 바로 바꾸지 말고, 먼저 **이동 후보 좌표**를 만든다.

```cpp
int nextY = playerY;
int nextX = playerX;
```

현재 방향에 따라 후보 좌표만 한 칸 변경한다. 예를 들어 위를 보고 있다면:

```cpp
nextY -= 1;
```

나머지 세 방향은 앞의 좌표 변화 표를 보고 직접 작성한다.

검사 순서는 다음과 같다.

1. 후보 좌표가 배열 범위 안인지 확인한다.
2. 범위 안이라면 그 칸이 `Empty`인지 확인한다.
3. 길일 때만 실제 위치를 후보 좌표로 바꾼다.

범위 조건 힌트:

```cpp
nextY >= 0 && nextY < boardSize && nextX >= 0 && nextX < boardSize
```

범위를 확인하기 전에 `tiles[nextY][nextX]`에 접근하지 않는다.

위치 반영 힌트:

```cpp
playerY = nextY;
playerX = nextX;
```

확인: `(1, 1)`에서 위로 이동을 시도하면 제자리에 있어야 한다. 앞선 코드에서 `playerY -= 1`을 먼저 실행해두면 벽 검사 전에 이동해버리므로 주의한다.

## 7. 플레이어: 회전과 오른손 법칙

오른쪽은 화면 기준이 아니라 **플레이어가 바라보는 방향 기준**이다.

```text
오른쪽 회전: Up → Right → Down → Left → Up
왼쪽 회전:   Up → Left → Down → Right → Up
```

앞에서 선언한 enum은 순서대로 `0, 1, 2, 3`이다. 이 순서를 유지하면 다음 계산을 사용할 수 있다.

```cpp
Direction rightDir = static_cast<Direction>((static_cast<int>(playerDir) + 1) % 4);
```

- `static_cast<int>`: 방향을 숫자로 바꾼다.
- `+ 1`: 오른쪽으로 한 번 돌린 방향을 구한다.
- `% 4`: 4가 되면 0으로 돌아오게 한다.
- `static_cast<Direction>`: 숫자를 다시 방향 타입으로 바꾼다.

왼쪽 회전은 `+ 1` 대신 `+ 3`을 사용한다. `0 - 1`로 계산하면 음수가 생길 수 있으므로 이번에는 이 방법을 쓴다.

`rightDir`을 계산하는 것만으로 플레이어가 회전하지는 않는다. 실제 회전은 `playerDir`에 새 방향을 넣을 때 일어난다.

한 차례 행동을 다음 순서로 구현하자.

```text
현재 방향을 기준으로 오른쪽 방향 구하기
오른쪽 칸의 좌표 구하기

오른쪽 칸이 길이면
  오른쪽으로 회전하고 그 칸으로 이동
그렇지 않으면
  현재 방향의 앞쪽 칸 구하기
  앞쪽이 길이면 직진
  앞쪽도 막혔으면 제자리에서 왼쪽으로 회전
```

오른쪽 후보를 계산할 때는 `rightDir`, 앞쪽 후보를 계산할 때는 `playerDir`을 기준으로 한다. 오른쪽으로 이동한 차례에는 직진까지 추가로 하지 않는다.

왼쪽 회전만 한 차례에는 위치가 그대로다. 다음 차례에 바뀐 방향으로 다시 오른쪽과 앞을 확인한다. 막다른 길에서는 여러 차례 회전한 뒤 들어왔던 길로 돌아갈 수 있다.

## 8. main을 짧게 유지하기

함수는 다음 역할로 나눠보자. 처음부터 클래스나 여러 파일로 나눌 필요는 없다.

| 함수 이름 예시 | 역할 |
| --- | --- |
| ResetBoard | 모든 칸을 벽 또는 방으로 초기화 |
| GenerateMaze | 초기화 후 방 사이 벽을 뚫기 |
| PrintBoard | 미로와 플레이어 방향 출력 |
| StepPlayer | 오른손 법칙으로 한 차례 행동 |

한 차례 행동 함수의 매개변수 힌트:

```cpp
void StepPlayer(const TileType(&tiles)[boardSize][boardSize], int& playerY, int& playerX, Direction& playerDir)
```

`const`는 여기서 미로를 바꾸지 않겠다는 뜻이다. `int&`, `Direction&`는 호출한 쪽의 위치와 방향을 직접 바꾸기 위해 사용한다. 값만 복사해서 받으면 함수 안에서 이동해도 `main`의 플레이어는 그대로다.

## 9. 도착할 때까지 한 차례씩 실행하기

위치와 방향 초기화는 반복문 밖에 둔다. 반복문 안에 넣으면 매번 출발점으로 돌아간다.

반복 조건 힌트:

```cpp
while (playerY != goalY || playerX != goalX)
```

두 좌표 중 하나라도 도착점과 다르면 계속 진행한다. `&&`를 쓰면 한 좌표만 도착점과 같아져도 너무 일찍 끝날 수 있다.

반복문 안에서 할 일은 다음 네 가지다.

1. 엔터 입력을 기다린다.
2. `StepPlayer`를 한 번 호출한다.
3. 이전 화면을 지운다.
4. 현재 미로와 플레이어를 출력한다.

매 차례 오른쪽 방향과 후보 좌표를 다시 계산해야 한다. 따라서 그 계산은 반복 호출되는 `StepPlayer` 안에 둔다.

입력·출력 힌트:

```cpp
std::cout << "Press Enter for the next action.\n";
std::cin.get();
```

입력이 종료되면 반복을 끝내도록 `std::cin.get()`의 성공 여부도 확인하면 좋다. 이 실습에서는 다른 `cin >>` 입력을 섞지 않는다.

Windows 콘솔 화면 지우기 힌트 (`#include <cstdlib>` 필요):

```cpp
std::system("cls");
```

시작 화면은 반복 전에 한 번 출력한다. 도착한 뒤에는 `Goal reached!`를 출력한다. 콘솔 인코딩 설정에 영향을 덜 받도록 실행 안내 문구는 영어로 작성한다.

## 10. 랜덤 때문에 헷갈릴 때 확인하는 방법

미로 전체를 보면서 추측하기보다, 아래 상황을 하나씩 확인하자. 필요하면 미로 생성 뒤 잠시 주변 타일을 직접 지정해서 상황을 만들고, 확인 후 테스트 설정을 지운다.

| 시험 상황 | 기대 결과 |
| --- | --- |
| 위를 보며 오른쪽 칸이 길 | 오른쪽 칸으로 이동하고 `>` 표시 |
| 오른쪽과 앞쪽이 모두 길 | 오른쪽 길을 먼저 선택 |
| 오른쪽이 벽이고 앞쪽이 길 | 방향을 유지하고 한 칸 직진 |
| 오른쪽과 앞쪽이 모두 벽 | 위치는 그대로, 왼쪽 방향으로 표시 변경 |
| 시작 위치에서 위로 이동만 시도 | 바깥 벽을 통과하지 않음 |
| 한 좌표만 도착점과 같음 | 반복을 계속함 |
| 두 좌표 모두 도착점과 같음 | 도착 안내 후 반복 종료 |

예를 들어 `(1, 1)`에서 위를 보게 하고, 오른쪽 타일인 `tiles[1][2]`를 `Empty`로 지정하면 첫 행동의 결과를 확실하게 확인할 수 있다. 회전만 확인하려면 같은 타일을 `Wall`로 지정한다. 앞쪽 `(0, 1)`은 이미 바깥 벽이므로 왼쪽으로 회전해야 한다.

같은 랜덤 미로로 반복 확인하고 싶다면 난수 엔진을 잠시 고정값으로 만들 수도 있다.

```cpp
std::mt19937 random(42);
```

같은 실행 환경에서는 같은 미로를 재현하기 편하다. 확인이 끝나면 원래의 무작위 초기화로 되돌린다.

## 11. 완성 후 스스로 설명해보기

- 왜 미로 크기를 홀수로 정했는가?
- 왜 방을 방문할 때는 2칸씩, 플레이어는 1칸씩 움직이는가?
- 마지막 행과 마지막 열에서 무작위 방향을 그대로 고르면 왜 안 되는가?
- 왜 실제 위치를 바꾸기 전에 후보 좌표를 계산하는가?
- 오른쪽이 길일 때 왜 `playerDir`도 바꿔야 하는가?
- 왜 왼쪽으로 회전한 뒤 바로 이동하지 않아도 되는가?
- 왜 오른쪽 후보 좌표를 매 차례 다시 구해야 하는가?
- 왜 반복 조건에 `||`를 사용하는가?
- 왜 위치와 방향을 참조로 전달하는가?

이번처럼 모든 길이 연결되고 길의 고리가 없는 미로에서는 오른손 법칙으로 도착점을 찾을 수 있다. 다만 가장 짧은 경로를 구하는 알고리즘은 아니다. 임의의 다른 미로에서도 항상 도착한다고 일반화하지는 말자.

문서를 보며 한 번 완성한 다음, 다음 연습에서는 코드 힌트를 가리고 위의 실행 흐름과 행동 규칙만 보고 다시 구현해보자. 각 분기의 이유를 설명하고, 문제가 생겼을 때 후보 좌표와 실제 위치를 구별해서 고칠 수 있다면 스스로 구현하는 힘이 붙은 것이다.

## 12. 복습 중 막혔던 부분: 움직이지 않는 플레이어

오른쪽 후보 좌표를 구하고 벽 여부까지 확인했는데, 엔터를 눌러도 움직이지 않는 문제가 있었다. 당시에는 다음처럼 `else`를 범위 검사 바로 뒤에 붙였다.

```cpp
if (rightY >= 0 && rightY < boardSize && rightX >= 0 && rightX < boardSize)
{
  canMoveRight = (tiles[rightY][rightX] == TileType::Empty);
}
else
{
  // 앞쪽 확인
}
```

이 `else`는 **오른쪽 칸이 벽일 때**가 아니라 **후보 좌표가 배열 범위 밖일 때** 실행된다.

시작 위치 `(1, 1)`에서 위를 보면 오른쪽 후보는 `(1, 2)`다. 그 칸이 벽이어도 좌표는 범위 안이다. 따라서 `canMoveRight`에 `false`만 저장하고 함수가 끝난다. 길이어도 `true`만 저장할 뿐 실제 위치를 바꾸는 코드가 없으므로 이동하지 않는다.

빠진 것은 범위 검사 다음의 **이동 가능 여부에 따른 행동 분기**였다.

```cpp
bool canMoveRight = false;

// 1. 안전하게 타일을 읽고 판단 결과를 저장한다.
if (rightY >= 0 && rightY < boardSize && rightX >= 0 && rightX < boardSize)
{
  canMoveRight = (tiles[rightY][rightX] == TileType::Empty);
}

// 2. 판단 결과에 따라 실제 행동을 선택한다.
if (canMoveRight)
{
  playerDir = rightDir;
  playerY = rightY;
  playerX = rightX;
}
else
{
  // 앞쪽 확인
}
```

**범위 검사와 행동 선택은 서로 다른 조건이다.** `else`가 무엇의 반대 상황인지 헷갈리면 연결된 `if`를 그대로 말로 읽어본다.

```text
범위 검사에 연결된 else → 범위 밖이면
canMoveRight에 연결된 else → 오른쪽으로 이동할 수 없으면
```

## 13. 전체 코드와 대조하기

각 단계를 구현한 뒤 실습 원본과 비교한다. 특히 `StepPlayer`에서는 후보 좌표 계산, 범위 검사, 행동 분기의 중괄호 위치를 확인한다.

아래 코드는 유효한 빈 방에서 시작하고 바깥 테두리를 벽으로 유지한다. 앞쪽 후보는 범위 안의 길 또는 벽이 된다. 임의의 시작 좌표나 테두리 없는 보드로 확장한다면 앞쪽 후보가 범위 밖인 경우에도 회전하거나 실패를 처리하도록 보완해야 한다.

```cpp
#include <iostream>
#include <random>
#include <cstdlib>
using namespace std;

// 변수 선언이 아니라, 타일 종류를 나타내는 타입 정의
enum class TileType
{
  Wall,
  Empty
};

enum class Direction
{
  Up,
  Right,
  Down,
  Left
};

constexpr int boardSize = 15;
static_assert(boardSize >= 3 && boardSize % 2 == 1, "boardSize must be an odd number >= 3");

void PrintBoard(const TileType(&tiles)[boardSize][boardSize], int playerY = -1, int playerX = -1, Direction playerDir = Direction::Up)
{
  for (int y = 0; y < boardSize; ++y)
  {
    for (int x = 0; x < boardSize; ++x)
    {
      if (y == playerY && x == playerX)
      {
        if (playerDir == Direction::Up)
        {
          std::cout << '^';
        }
        else if (playerDir == Direction::Right)
        {
          std::cout << '>';
        }
        else if (playerDir == Direction::Down)
        {
          std::cout << 'v';
        }
        else if (playerDir == Direction::Left)
        {
          std::cout << '<';
        }
      }
      else if (tiles[y][x] == TileType::Wall)
      {
        std::cout << '#';
      }
      else if (tiles[y][x] == TileType::Empty)
      {
        std::cout << ' ';
      }
    }

    std::cout << '\n';
  }
}

void ResetBoard(TileType(&tiles)[boardSize][boardSize])
{
  for (int y = 0; y < boardSize; ++y)
  {
    for (int x = 0; x < boardSize; ++x)
    {
      if (y % 2 == 1 && x % 2 == 1)
      {
        tiles[y][x] = TileType::Empty;
      }
      else
      {
        tiles[y][x] = TileType::Wall;
      }
    }
  }
}

// 방을 초기화하고 무작위로 연결해서 미로를 만든다.
void GenerateMaze(TileType(&tiles)[boardSize][boardSize])
{
  ResetBoard(tiles);

  // 반복문 밖에서 난수 엔진을 한 번 만든다.
  std::random_device seed;
  std::mt19937 random(seed());
  std::bernoulli_distribution chooseEast(0.5);

  for (int y = 1; y < boardSize - 1; y += 2)
  {
    for (int x = 1; x < boardSize - 1; x += 2)
    {
      // 1. 오른쪽 아래 마지막 방: 연결할 방향이 없음
      if (y == boardSize - 2 && x == boardSize - 2)
      {
        continue;
      }

      // 2. 마지막 행: 아래에 방이 없으므로 오른쪽으로 연결
      if (y == boardSize - 2)
      {
        tiles[y][x + 1] = TileType::Empty;
      }
      // 3. 마지막 열: 오른쪽에 방이 없으므로 아래로 연결
      else if (x == boardSize - 2)
      {
        tiles[y + 1][x] = TileType::Empty;
      }
      // 4. 나머지 방: 오른쪽 또는 아래쪽을 무작위 선택
      else if (chooseEast(random))
      {
        tiles[y][x + 1] = TileType::Empty;
      }
      else
      {
        tiles[y + 1][x] = TileType::Empty;
      }
    }
  }
}

// 오른손 법칙으로 한 차례 이동하거나 회전한다.
// 참조(&)로 받아 호출한 쪽의 위치와 방향을 변경한다.
void StepPlayer(const TileType(&tiles)[boardSize][boardSize], int& playerY, int& playerX, Direction& playerDir)
{
  Direction rightDir = static_cast<Direction>((static_cast<int>(playerDir) + 1) % 4);

  // 플레이어 기준 오른쪽 칸의 좌표를 계산한다.
  int rightY = playerY;
  int rightX = playerX;

  if (rightDir == Direction::Up)
  {
    rightY -= 1;
  }
  else if (rightDir == Direction::Right)
  {
    rightX += 1;
  }
  else if (rightDir == Direction::Down)
  {
    rightY += 1;
  }
  else if (rightDir == Direction::Left)
  {
    rightX -= 1;
  }

  bool canMoveRight = false;

  if (rightY >= 0 && rightY < boardSize && rightX >= 0 && rightX < boardSize)
  {
    canMoveRight = (tiles[rightY][rightX] == TileType::Empty);
  }

  if (canMoveRight)
  {
    playerDir = rightDir;
    playerY = rightY;
    playerX = rightX;
  }
  else
  {
    // 오른쪽이 막혔으니 앞쪽 칸을 확인한다.
    int nextY = playerY;
    int nextX = playerX;

    if (playerDir == Direction::Up)
    {
      nextY -= 1;
    }
    else if (playerDir == Direction::Right)
    {
      nextX += 1;
    }
    else if (playerDir == Direction::Down)
    {
      nextY += 1;
    }
    else if (playerDir == Direction::Left)
    {
      nextX -= 1;
    }

    if (nextY >= 0 && nextY < boardSize && nextX >= 0 && nextX < boardSize)
    {
      if (tiles[nextY][nextX] == TileType::Empty)
      {
        playerY = nextY;
        playerX = nextX;
      }
      else
      {
        // 오른쪽과 앞쪽이 모두 벽이면 제자리에서 왼쪽으로 회전한다.
        playerDir = static_cast<Direction>((static_cast<int>(playerDir) + 3) % 4);
      }
    }
  }
}

int main()
{
  std::system("cls");
  std::cout << "Algorithm Day 02 - Maze\n\n";

  TileType tiles[boardSize][boardSize]{};
  GenerateMaze(tiles);

  int playerY = 1;
  int playerX = 1;
  Direction playerDir = Direction::Up;

  int goalY = boardSize - 2;
  int goalX = boardSize - 2;

  PrintBoard(tiles, playerY, playerX, playerDir);

  while (playerY != goalY || playerX != goalX)
  {
    std::cout << "\nPress Enter for the next action.\n";
    if (!std::cin.get())
    {
      return 0;
    }

    StepPlayer(tiles, playerY, playerX, playerDir);
    // Windows 콘솔을 지우고 현재 미로만 다시 출력한다.
    std::system("cls");
    std::cout << "Algorithm Day 02 - Maze\n\n";
    PrintBoard(tiles, playerY, playerX, playerDir);
  }

  std::cout << "\nGoal reached!\n";

  return 0;
}
```

## 14. 구현한 뒤 이해할 내용

### 모든 방이 연결되는 이유

방을 점, 방 사이에 뚫은 벽을 연결선으로 생각해보자. 오른쪽 아래 마지막 방을 제외한 각 방은 오른쪽이나 아래쪽으로 연결선 하나를 만든다.

그 방향으로 연결을 계속 따라가면 좌표가 커지고, 경계에서는 가능한 방향으로만 연결하므로 결국 오른쪽 아래 마지막 방에 도달한다. 모든 방이 같은 마지막 방에 연결되는 셈이다.

방이 R개라면 연결선은 R - 1개다. 모든 방이 연결되고 연결선이 R - 1개인 구조는 트리다. 두 방 사이에 같은 방을 반복하지 않는 경로는 하나뿐이다. 이런 미로를 perfect maze라고 한다.

생성할 때 오른쪽과 아래쪽으로만 벽을 뚫어도 플레이어는 네 방향으로 이동할 수 있다. 왼쪽 방에서 오른쪽 벽을 뚫었다면 현재 방에서는 왼쪽 통로가 된다.

### 무작위 선택에도 방향 편향이 있다

각 방의 선택지는 오른쪽과 아래쪽으로 제한된다. 마지막 행과 마지막 열에는 긴 통로가 생긴다. 두 방향을 50% 확률로 고른다는 것이 모든 미로 모양을 같은 확률로 만든다는 뜻은 아니다.

더 다양한 생성 방식이 필요할 때는 DFS 기반 backtracking, Prim 또는 Kruskal 기반 생성 방식을 비교할 수 있다.

### 오른손 법칙은 최단 경로를 보장하지 않는다

막다른 길에 들어갔다 돌아올 수 있으므로 출구에 도착했다는 사실이 가장 적게 움직였다는 뜻은 아니다. 이동 비용이 같은 격자의 최단 경로는 이후 BFS에서 다룬다.

이번처럼 통로가 트리인 미로에서는 도착할 수 있다. 순환 통로나 분리된 벽 구조가 있는 다른 미로에서도 임의의 목적지에 항상 도착한다고 일반화하면 안 된다.

다른 생성기로 만든 미로도 처리하려면 `(y, x, 방향)` 상태가 반복되는지 검사해 실패를 판단할 수 있다. 위치만 검사하면 같은 칸을 다른 방향으로 다시 지나는 정상 동작까지 막는다.

### 생성과 탐색의 복잡도

가로·세로 크기를 S라고 하면 초기화는 S²칸을 방문하고 방 연결도 방 개수에 비례한다.

| 작업 | 시간 | 공간 |
| --- | --- | --- |
| 미로 생성 | O(S²) | 타일 배열 O(S²), 그 외 추가 작업 공간 O(1) |
| 이번 트리 미로의 오른손 탐색 | O(S²) | 위치와 방향만 보관하면 추가 공간 O(1) |

트리의 가지를 들어갔다 돌아오더라도 통로 크기에 비례하는 횟수 안에서 도착한다. 표의 탐색 시간은 입력 대기와 화면 출력을 제외한 판단·이동 연산 기준이다. 매 행동마다 S²칸을 전부 다시 출력하면 전체 출력 작업은 최악 O(S⁴)까지 늘어날 수 있다.

이동 경로를 모두 저장하거나 반복 상태 검사 배열을 추가하면 추가 공간도 O(S²)이 된다. 종료 처리가 없는 일반 순환 미로에서는 유한한 탐색 시간을 보장할 수 없다.

### 경로 계산과 화면 재생은 나중에 분리할 수 있다

지금은 엔터마다 판단하고 바로 화면에 반영한다. 익숙해진 뒤에는 탐색을 먼저 끝내 좌표 목록을 저장하고, 일정 시간마다 다음 좌표를 표시하는 방식으로 확장할 수 있다.

```text
현재 실습: 입력 → 한 차례 판단 → 위치 반영 → 출력
확장 방식: 전체 경로 계산 → 저장한 경로를 시간 간격에 따라 재생
```

경로 재생 방식에서는 새 미로를 시작할 때 저장 경로, 재생 인덱스, 누적 시간과 시작 방향도 함께 초기화한다.
