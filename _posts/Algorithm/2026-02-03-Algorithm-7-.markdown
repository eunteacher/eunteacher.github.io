큐(Queue)는 한쪽 끝에 원소를 넣고 반대쪽 끝에서 꺼내는 선형 자료구조다. 먼저 들어온 원소를 먼저 꺼내므로 FIFO(First-In, First-Out) 구조라고 부른다.

```text
꺼내는 쪽                                      넣는 쪽
Front                                            Back
  ↓                                                ↓
  ← [10] [20] [30] [40] ← push(50)

pop 순서: 10 → 20 → 30 → 40 → 50
```

먼저 요청한 작업부터 처리하는 대기열, 너비 우선 탐색과 메시지 버퍼처럼 **도착 순서를 유지해야 하는 문제**에 큐가 자연스럽게 사용된다.

## 큐가 제공하는 기본 연산

| 연산 | 역할 |
|---|---|
| `push(value)` | Back에 새 원소를 추가한다. |
| `pop()` | Front 원소를 제거한다. |
| `front()` | 가장 먼저 들어온 원소를 확인한다. |
| `back()` | 가장 나중에 들어온 원소를 확인한다. |
| `empty()` | 원소가 없는지 확인한다. |
| `size()` | 저장된 원소 수를 반환한다. |

```cpp
std::queue<int> values;
values.push(10);
values.push(20);
values.push(30);

while (!values.empty())
{
    std::cout << values.front() << ' ';
    values.pop();
}
```

출력은 삽입한 순서와 같은 `10 20 30`이다.

스택은 삽입과 삭제가 모두 Top에서 일어나지만 큐는 삽입 위치인 Back과 삭제 위치인 Front가 나뉜다.

```text
Stack: push / pop 모두 Top
Queue: push는 Back, pop은 Front
```

## 배열에서 앞 원소를 매번 당기면 O(N)이다

배열의 0번 인덱스를 항상 Front로 유지하려면 `pop()`할 때 뒤에 있는 모든 원소를 한 칸씩 앞으로 옮겨야 한다.

```text
pop 전
[10] [20] [30] [40]
 ↑ Front

10 제거 후 이동
     [20] → [30] → [40] →

pop 후
[20] [30] [40] [  ]
 ↑ Front
```

원소가 $N$개라면 이동 비용은 $O(N)$이다. 큐의 앞쪽 삭제를 자주 수행할수록 같은 데이터를 반복해서 옮기게 된다.

원소는 그대로 두고 Front 인덱스만 증가시키면 `pop()`은 $O(1)$이 된다.

```text
초기
[10] [20] [30] [40] [  ] [  ]
 ↑ Front                   ↑ Back

두 번 pop
[  ] [  ] [30] [40] [  ] [  ]
           ↑ Front         ↑ Back
```

하지만 Back이 배열 끝에 도달하면 앞쪽에 비어 있는 칸이 있어도 새 원소를 넣을 수 없다. 이 공간을 다시 사용하려면 인덱스를 배열의 처음으로 순환시켜야 한다.

## 원형 큐는 배열의 끝을 처음과 연결한다

원형 큐(Circular Queue)는 실제로 원형 메모리를 사용하는 것이 아니다. 연속된 배열을 사용하되 인덱스가 capacity에 도달하면 0으로 돌아가게 만든다.

$$
\text{next index} = (\text{current index} + 1) \bmod \text{capacity}
$$

capacity가 5일 때 인덱스는 다음처럼 움직인다.

```text
0 → 1 → 2 → 3 → 4 → 0 → 1 → ...
```

```cpp
front = (front + 1) % capacity;
back = (back + 1) % capacity;
```

배열을 펼쳐 보면 데이터가 두 구간으로 나뉘어 보일 수 있다. capacity가 6이고 원소가 네 개라면 다음처럼 연속된 순환 구간을 이룬다.

```text
index   0    1    2    3    4    5
       [60] [  ] [  ] [30] [40] [50]
             ↑ Back    ↑ Front

논리 순서: 30(index 3) → 40(index 4) → 50(index 5) → 60(index 0)
```

논리적인 $i$번째 원소의 실제 배열 인덱스는 다음과 같다.

$$
\text{physical index}(i) = (\text{front} + i) \bmod \text{capacity}
$$

```text
i = 0 → (3 + 0) % 6 = 3 → 30
i = 1 → (3 + 1) % 6 = 4 → 40
i = 2 → (3 + 2) % 6 = 5 → 50
i = 3 → (3 + 3) % 6 = 0 → 60
```

원형 큐를 디버깅할 때는 화면에 보이는 배열 순서가 아니라 `front`, `size`와 modulo 공식으로 논리 순서를 확인한다.

## Front, Back과 Size의 의미를 먼저 정한다

이번 구현에서는 세 상태를 다음 의미로 사용한다.

```text
front : 가장 오래된 원소의 인덱스
back  : 다음 원소를 넣을 빈 인덱스
size  : 현재 저장된 원소 수
```

항상 다음 불변식을 유지한다.

$$
0 \leq size \leq capacity
$$

```text
size == 0        → 빈 큐
size == capacity → 가득 찬 큐
```

원형 큐에서는 빈 상태와 가득 찬 상태 모두 `front == back`이 될 수 있다.

```text
빈 큐:     front == back, size == 0
가득 찬 큐: front == back, size == capacity
```

따라서 이번 구현은 size를 함께 저장해 두 상태를 구분한다. 다른 설계로는 항상 한 칸을 비워 두거나 별도의 `full` 값을 저장할 수도 있다. 어떤 방식을 사용하든 인덱스의 의미를 끝까지 일관되게 유지해야 한다.

## push는 Back에 넣고 다음 빈 칸으로 이동한다

저장 공간이 남아 있다면 다음 두 단계면 충분하다.

```cpp
storage[back] = value;
back = (back + 1) % capacity;
++size;
```

`back`은 마지막 원소가 아니라 **다음 원소가 들어갈 위치**다. 값을 넣은 뒤 이동시킨다.

## pop은 Front 원소를 제거하고 이동한다

```cpp
storage[front].reset();
front = (front + 1) % capacity;
--size;
```

`std::optional<T>`로 각 칸을 표현하면 `reset()`으로 그 위치의 `T` 객체를 파괴하면서 capacity는 유지할 수 있다. 원소를 앞쪽으로 이동하지 않으므로 `pop()`은 $O(1)$이다.

빈 큐에서 `front()`나 `pop()`을 호출할 수는 없다. `std::queue`도 이 전제 조건을 요구한다. 직접 구현할 때는 호출자가 `empty()`를 확인하게 하거나, 예외 또는 성공 여부를 반환하는 정책을 정할 수 있다.

## 가득 차면 논리 순서대로 새 배열에 옮긴다

원형 큐가 가득 찬 상태에서 `push()`하려면 capacity를 늘린다. 데이터가 배열 끝에서 처음으로 감겨 있을 수 있으므로 물리 배열을 0번부터 그대로 복사하면 FIFO 순서가 달라진다.

```text
증설 전: capacity 4, size 4

물리 배열
index    0    1    2    3
        [50] [60] [30] [40]
                    ↑ Front

논리 순서
30 → 40 → 50 → 60
```

`front`부터 size개를 modulo 인덱스로 읽어 새 배열의 0번부터 배치한다.

```text
증설 후: capacity 8, size 4

index    0    1    2    3    4    5    6    7
        [30] [40] [50] [60] [  ] [  ] [  ] [  ]
         ↑ Front             ↑ Back
```

```cpp
for (std::size_t i = 0; i < size; ++i)
{
    std::size_t source = (front + i) % oldCapacity;
    newStorage[i] = std::move(storage[source]);
}

front = 0;
back = size;
```

증설 직후에는 데이터가 선형으로 정리되므로 front는 0, back은 size가 된다.

capacity를 두 배씩 늘리면 증설 한 번은 $O(N)$이지만 연속된 `push()`의 분할 상환 비용은 $O(1)$이다. 이는 동적 배열의 성장 분석과 같다.

## std::queue도 컨테이너 어댑터다

`std::queue`는 기반 컨테이너의 기능을 FIFO 인터페이스로 제한한다.

```text
std::queue 인터페이스
push / pop / front / back / empty / size
                   │
                   ▼
기반 컨테이너
push_back / pop_front / front / back
```

기본 기반 컨테이너는 `std::deque<T>`다.

```cpp
std::queue<int> first;
std::queue<int, std::deque<int>> second;
```

`deque`는 여러 메모리 블록을 관리하며 앞과 뒤의 삽입·삭제를 효율적으로 제공한다. `vector`는 `pop_front()`를 제공하지 않으므로 `std::queue`의 기반 컨테이너로 직접 사용할 수 없다.

`std::list`는 필요한 연산을 제공하므로 다음 선언은 가능하다.

```cpp
std::queue<int, std::list<int>> listQueue;
```

다만 각 노드의 링크와 개별 할당 비용, 캐시 지역성까지 고려하면 연결 리스트가 언제나 더 빠른 것은 아니다. 일반적인 용도에서는 기본 `deque`가 자연스러운 선택이다.

## 큐가 자연스럽게 사용되는 문제

### 너비 우선 탐색

BFS는 현재 정점과 가까운 정점부터 차례로 방문한다. 발견한 정점을 큐의 Back에 넣고 Front부터 꺼내면 먼저 발견한 정점이 먼저 처리된다.

```text
시작 A

queue: [A]
A 처리 → B, C 발견
queue: [B, C]
B 처리 → D, E 발견
queue: [C, D, E]
```

가중치가 없는 그래프에서 BFS가 최소 간선 수 경로를 찾는 이유도 거리 순서대로 처리되는 FIFO 성질과 연결된다.

### 작업 대기열

프린터 요청, 서버 작업과 이벤트를 도착한 순서대로 처리할 때 큐를 사용할 수 있다. 실제 시스템에서는 우선순위, 취소와 동시성 정책이 추가될 수 있지만 기본 순서는 FIFO다.

### 생산자와 소비자 사이의 버퍼

데이터를 만드는 쪽과 처리하는 쪽의 속도가 다르면 큐가 중간에서 대기 데이터를 보관한다. 고정 크기 원형 버퍼에서는 큐가 가득 찼을 때 생산자를 기다리게 할지, 새 데이터를 버릴지, 가장 오래된 데이터를 덮어쓸지도 정해야 한다.

## 전체 원형 큐 구현

다음 예제는 `std::optional<T>` 배열을 사용해 빈 슬롯과 실제 원소를 구분한다. `push()`가 capacity를 넘으면 두 배로 증설하고, 감겨 있던 데이터를 논리 순서대로 펼친다.

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <optional>
#include <stdexcept>
#include <utility>
#include <vector>

template<typename T>
class CircularQueue
{
public:
    void Push(T value)
    {
        if (size_ == storage_.size())
        {
            Grow();
        }

        storage_[back_].emplace(std::move(value));
        back_ = Next(back_);
        ++size_;
    }

    void Pop()
    {
        if (Empty())
        {
            throw std::out_of_range("queue is empty");
        }

        storage_[front_].reset();
        front_ = Next(front_);
        --size_;
    }

    T& Front()
    {
        if (Empty())
        {
            throw std::out_of_range("queue is empty");
        }

        return *storage_[front_];
    }

    const T& Front() const
    {
        if (Empty())
        {
            throw std::out_of_range("queue is empty");
        }

        return *storage_[front_];
    }

    bool Empty() const { return size_ == 0; }
    std::size_t Size() const { return size_; }
    std::size_t Capacity() const { return storage_.size(); }

private:
    std::size_t Next(std::size_t index) const
    {
        return (index + 1) % storage_.size();
    }

    void Grow()
    {
        std::size_t oldCapacity = storage_.size();
        std::size_t newCapacity = std::max<std::size_t>(1, oldCapacity * 2);
        std::vector<std::optional<T>> newStorage(newCapacity);

        for (std::size_t i = 0; i < size_; ++i)
        {
            std::size_t source = (front_ + i) % oldCapacity;
            newStorage[i].emplace(std::move_if_noexcept(*storage_[source]));
        }

        storage_.swap(newStorage);
        front_ = 0;
        back_ = size_;
    }

    std::vector<std::optional<T>> storage_;
    std::size_t front_ = 0;
    std::size_t back_ = 0;
    std::size_t size_ = 0;
};

int main()
{
    CircularQueue<int> values;
    values.Push(10);
    values.Push(20);
    values.Push(30);
    values.Push(40);

    std::cout << "first pops: " << values.Front();
    values.Pop();
    std::cout << ' ' << values.Front() << '\n';
    values.Pop();

    values.Push(50);
    values.Push(60);
    values.Push(70);

    std::cout << "queue order:";

    while (!values.Empty())
    {
        std::cout << ' ' << values.Front();
        values.Pop();
    }

    std::cout << '\n';
    std::cout << "capacity after growth: " << values.Capacity() << '\n';
    std::cout << "remaining size: " << values.Size() << '\n';
}
```

고정된 입력으로 실행한 결과는 다음과 같다.

```text
first pops: 10 20
queue order: 30 40 50 60 70
capacity after growth: 8
remaining size: 0
```

10과 20을 제거한 뒤 50과 60이 배열 앞쪽의 빈 공간에 들어가면서 데이터가 물리적으로 감긴다. 70을 추가할 때 큐가 가득 차 있으므로 capacity가 4에서 8로 늘고, 논리 순서 `30 40 50 60`이 새 배열의 0번부터 배치된다.

## 복잡도

원소 수를 $N$이라고 할 때 동적 원형 큐의 대표 비용은 다음과 같다.

| 연산 | 시간 복잡도 | 설명 |
|---|---:|---|
| `Front()` | $O(1)$ | front 인덱스로 접근 |
| `Pop()` | $O(1)$ | 원소 제거 후 front 이동 |
| `Push()` | 분할 상환 $O(1)$ | 증설이 발생한 한 번은 $O(N)$ |
| `Empty()`, `Size()` | $O(1)$ | 저장된 size 확인 |
| 증설 | $O(N)$ | 논리 순서대로 원소 이동 |
| 저장 공간 | $O(capacity)$ | 원형 배열 전체 |

고정 크기 원형 큐라면 증설하지 않으므로 모든 기본 연산을 $O(1)$로 유지할 수 있다. 대신 가득 찼을 때 수행할 정책이 필요하다.

## 원형 큐를 구현할 때 확인할 기준

1. front가 첫 원소를 가리키는지, 그 앞을 가리키는지 정했는가?
2. back이 마지막 원소인지, 다음 빈 위치인지 정했는가?
3. 빈 상태와 가득 찬 상태를 size, 빈 칸 또는 별도 상태로 구분하는가?
4. 인덱스가 capacity에 도달했을 때 0으로 순환하는가?
5. 논리적인 $i$번째 원소를 `(front + i) % capacity`로 찾을 수 있는가?
6. 빈 큐에서 `front()`와 `pop()`을 호출하지 않는가?
7. 제거한 위치의 객체 수명을 끝내는가?
8. 증설할 때 물리 배열이 아니라 논리적인 FIFO 순서로 옮기는가?
9. 증설 후 front를 0, back을 size로 다시 설정하는가?
10. `std::queue`의 기본 기반 컨테이너가 `deque`임을 알고 있는가?
11. push의 개별 최악 비용과 분할 상환 비용을 구분하는가?
12. 고정 크기 큐가 가득 찼을 때의 정책을 정했는가?

원형 큐의 핵심은 `%` 연산 하나가 아니다. front, back과 size의 의미를 먼저 정하고, 배열에 데이터가 감겨 있어도 논리적인 FIFO 순서를 계속 유지하는 것이 중요하다.
