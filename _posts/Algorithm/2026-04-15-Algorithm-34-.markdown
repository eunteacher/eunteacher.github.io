틱택토는 3×3 보드에 두 플레이어가 번갈아 표시를 놓고, 가로·세로·대각선 중 한 줄을 먼저 완성하면 이기는 게임이다.

```text
X | O | X
--+---+--
  | X | O
--+---+--
  |   |
```

빈칸마다 가능한 수를 모두 시도하면 게임의 승패를 판단할 수 있다. 하지만 서로 다른 수의 순서가 같은 보드에 도달할 수 있으므로 동일한 상태를 반복해서 탐색하게 된다. 보드 상태의 결과를 저장하면 이 중복을 제거할 수 있다.

## 결과는 현재 차례의 플레이어를 기준으로 본다

게임 탐색에서는 반환값의 의미를 한쪽 플레이어에게 고정하기보다 **현재 차례인 플레이어의 관점**으로 정의하면 전환이 단순해진다.

```text
 1: 현재 플레이어가 최선의 수를 두면 승리
 0: 양쪽 모두 최선의 수를 두면 무승부
-1: 상대가 최선으로 대응하면 현재 플레이어가 패배
```

현재 플레이어가 수를 둔 뒤에는 상대의 차례가 된다. 상대 관점의 결과가 `-1`이라면 현재 플레이어에게는 `1`이다.

```text
현재 수의 결과 = -(그 수를 둔 다음 상태에서 상대가 얻는 결과)
```

이처럼 관점이 바뀔 때 결과의 부호를 뒤집는 방식을 Negamax라고 부른다. 두 플레이어의 이익이 정확히 반대인 게임에서 Minimax를 간결하게 표현할 수 있다.

## 매 순간 가장 좋은 결과를 선택한다

현재 플레이어는 모든 빈칸에 자신의 표시를 놓아 보고 가장 좋은 결과를 선택한다.

```text
승리할 수 있는 수가 하나라도 있다 → 승리
승리는 없지만 비길 수 있다       → 무승부
모든 수가 상대의 승리로 이어진다  → 패배
```

결과의 순서를 `승리 > 무승부 > 패배`로 두었으므로 각 후보의 최댓값을 구하면 된다.

```cpp
enum class Result
{
    Lose = -1,
    Draw = 0,
    Win = 1
};
```

## 승리 여부를 먼저 판정한다

한 수를 둔 직후 해당 플레이어가 한 줄을 완성했는지 확인한다.

```cpp
using Board = std::array<int, 9>;

bool HasWon(const Board& board, int player)
{
    constexpr int Lines[8][3]{
        {0, 1, 2}, {3, 4, 5}, {6, 7, 8},
        {0, 3, 6}, {1, 4, 7}, {2, 5, 8},
        {0, 4, 8}, {2, 4, 6}
    };

    for (const auto& line : Lines)
    {
        if (board[line[0]] == player && board[line[1]] == player && board[line[2]] == player)
        {
            return true;
        }
    }

    return false;
}
```

보드에서는 빈칸을 0, X를 1, O를 2로 표현한다. 승리 조건은 8줄뿐이므로 한 상태에서의 판정 비용은 상수다.

## 보드를 3진수 하나로 압축한다

각 칸이 `0`, `1`, `2` 중 하나이므로 9칸의 보드는 9자리 3진수로 나타낼 수 있다.

$$
key = board[0] \times 3^0 + board[1] \times 3^1 + \cdots + board[8] \times 3^8
$$

```cpp
int Encode(const Board& board)
{
    int key = 0;
    int placeValue = 1;

    for (int cell : board)
    {
        key += cell * placeValue;
        placeValue *= 3;
    }

    return key;
}
```

가능한 보드 표현은 최대 $3^9 = 19,683$개다. 같은 보드라도 누구의 차례인지에 따라 의미가 달라질 수 있으므로 메모이제이션 키에는 현재 플레이어도 포함한다.

```cpp
int StateKey(const Board& board, int player)
{
    return Encode(board) * 2 + (player - 1);
}
```

실제 정상 게임에서는 보드의 X와 O 개수로 다음 차례를 알아낼 수도 있다. 여기서는 탐색 함수의 상태가 무엇인지 명확히 드러내기 위해 플레이어를 키에 직접 포함한다.

## 재귀 탐색에 결과를 저장한다

아직 계산하지 않은 상태는 결과 범위에 없는 값 `2`로 표시한다.

```cpp
int Solve(Board& board, int player, std::vector<int>& memo)
{
    int key = StateKey(board, player);

    if (memo[key] != 2)
    {
        return memo[key];
    }

    int best = static_cast<int>(Result::Lose);
    bool hasEmptyCell = false;

    for (int index = 0; index < static_cast<int>(board.size()); ++index)
    {
        if (board[index] != 0)
        {
            continue;
        }

        hasEmptyCell = true;
        board[index] = player;
        int score;

        if (HasWon(board, player))
        {
            score = static_cast<int>(Result::Win);
        }
        else
        {
            int opponent = player == 1 ? 2 : 1;
            score = -Solve(board, opponent, memo);
        }

        board[index] = 0;
        best = std::max(best, score);

        if (best == static_cast<int>(Result::Win))
        {
            break;
        }
    }

    if (!hasEmptyCell)
    {
        best = static_cast<int>(Result::Draw);
    }

    memo[key] = best;
    return best;
}
```

승리 결과를 찾은 뒤에는 다른 수를 더 볼 필요가 없다. 이미 얻을 수 있는 가장 좋은 결과이기 때문이다.

수를 시험한 뒤 `board[index] = 0`으로 되돌리는 것도 중요하다. 재귀 호출은 하나의 보드 배열을 공유하므로 원상 복구하지 않으면 다음 후보가 이전 후보의 표시가 남은 보드에서 시작하게 된다.

## 종료 조건의 순서를 살펴본다

마지막 빈칸에 수를 놓아 승리한 경우도 있다. 따라서 수를 둔 직후 승리를 먼저 검사하고, 승리가 아닐 때만 다음 상태를 탐색한다.

```text
현재 수를 둠
   ↓
한 줄 완성? ── 예 ─→ 현재 플레이어 승리
   │
  아니오
   ↓
상대 차례 탐색
```

현재 상태에 빈칸이 처음부터 없다면 더 둘 수 없으므로 무승부다. 입력 보드에 이미 승자가 있는 경우는 탐색 함수에 넘기기 전에 별도로 처리해야 한다. `Solve`는 아직 승부가 나지 않았고 현재 플레이어가 수를 둘 차례인 정상 상태를 전제로 한다.

## 최선의 수까지 찾는다

승패뿐 아니라 실제로 둘 위치가 필요하다면 각 빈칸의 결과를 비교해 가장 높은 점수를 만드는 위치를 반환한다.

```cpp
int FindBestMove(Board& board, int player, std::vector<int>& memo)
{
    int bestMove = -1;
    int bestScore = static_cast<int>(Result::Lose) - 1;

    for (int index = 0; index < static_cast<int>(board.size()); ++index)
    {
        if (board[index] != 0)
        {
            continue;
        }

        board[index] = player;
        int opponent = player == 1 ? 2 : 1;
        int score = HasWon(board, player) ? static_cast<int>(Result::Win) : -Solve(board, opponent, memo);
        board[index] = 0;

        if (score > bestScore)
        {
            bestScore = score;
            bestMove = index;
        }
    }

    return bestMove;
}
```

같은 결과를 만드는 수가 여러 개라면 인덱스가 가장 작은 수를 선택한다. 승리까지 남은 턴 수는 점수에 포함하지 않았으므로 더 빠른 승리나 더 늦은 패배를 구분하지는 않는다. 이를 구분하려면 결과와 거리 정보를 함께 저장하거나 점수에 깊이를 반영해야 한다.

## 메모이제이션이 줄이는 작업

빈 보드에서 가능한 수의 순서만 세면 첫 수는 9개, 다음 수는 8개, 그다음은 7개로 뻗는다. 실제 게임은 중간에 승리하면 끝나지만 같은 보드에 도달하는 순서가 여전히 많이 존재한다.

```text
X가 0번 칸, O가 4번 칸, X가 8번 칸
X가 8번 칸, O가 4번 칸, X가 0번 칸

두 경로의 최종 보드와 다음 차례는 같음
```

메모이제이션을 적용하면 동일한 `(보드, 현재 플레이어)` 상태는 한 번만 계산한다. 표현상 상태 수의 상한은 $2 \times 3^9$개이며 각 상태에서 최대 9칸을 확인하므로 이 작은 게임은 충분히 빠르게 완전 탐색할 수 있다. 이 상한에는 정상적인 게임 진행으로 도달할 수 없는 보드도 포함된다.

## 입력 보드는 정상 상태인지 확인해야 한다

외부에서 임의의 보드를 받는다면 다음 조건을 검사해야 한다.

- 각 칸의 값이 빈칸, X, O 중 하나인가?
- X와 O의 개수 차이가 정상적인가?
- 두 플레이어가 동시에 승리한 상태는 아닌가?
- 이미 승리한 뒤에 수를 더 둔 형태는 아닌가?
- 현재 플레이어가 표시 개수와 일치하는가?

게임 탐색이 논리적으로 맞더라도 불가능한 보드를 입력하면 결과의 의미가 없어진다. 알고리즘의 상태 조건과 입력 유효성 검사는 별개의 책임이다.

## 전체 검증 코드

```cpp
#include <algorithm>
#include <array>
#include <cassert>
#include <vector>

// Result, Board, HasWon, Encode, StateKey,
// Solve, FindBestMove 구현은 앞의 코드와 같다.

int main()
{
    constexpr int StateCount = 19683 * 2;
    std::vector<int> memo(StateCount, 2);

    Board empty{};
    assert(Solve(empty, 1, memo) == static_cast<int>(Result::Draw));

    Board winningMove{
        1, 1, 0,
        2, 2, 0,
        0, 0, 0
    };
    assert(FindBestMove(winningMove, 1, memo) == 2);

    Board blockingMove{
        2, 2, 0,
        1, 0, 0,
        1, 0, 0
    };
    assert(FindBestMove(blockingMove, 1, memo) == 2);

    Board draw{
        1, 2, 1,
        1, 2, 2,
        2, 1, 1
    };
    assert(Solve(draw, 2, memo) == static_cast<int>(Result::Draw));
}
```

빈 보드의 결과가 무승부인지, 즉시 이기는 수를 찾는지, 상대의 즉시 승리를 막는지, 빈칸 없는 보드를 무승부로 처리하는지를 확인한다. 테스트마다 새 메모 배열을 만들 필요는 없다. 캐시에 저장된 결과는 보드와 현재 플레이어만으로 결정되므로 여러 탐색에서 재사용할 수 있다.
