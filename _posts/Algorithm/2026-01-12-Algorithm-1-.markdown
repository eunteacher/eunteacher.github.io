몬스터가 10마리일 때는 문제없이 실행되던 코드가 10만 마리가 되면 느려질 수 있다. 확인해야 할 대상이 많아졌기 때문이다.

그런데 모든 코드가 같은 속도로 느려지는 것은 아니다. 몬스터 수만큼 일이 늘어나는 코드도 있고, 그보다 훨씬 빠르게 작업량이 늘어나는 코드도 있다.

이번에는 짧은 코드로 **데이터 개수가 늘어날 때 작업량이 어떻게 달라지는지** 살펴보자.

## 복잡도란?

시간 복잡도는 **입력 크기가 커질 때 필요한 작업량이 얼마나 늘어나는지** 나타낸다.

여기서 `n`은 입력 크기다. 이 글에서는 배열의 요소 수나 몬스터 수처럼 **데이터 개수**라고 생각하면 된다.

복잡도는 “이 코드가 몇 초 걸린다”를 뜻하지 않는다. 같은 코드도 컴퓨터 성능과 실행 환경에 따라 걸리는 시간이 다르기 때문이다.

대신 다음과 같이 생각한다.

> 데이터가 10배가 되면, 해야 할 일도 10배가 될까? 아니면 100배가 될까?

이 증가 형태를 표현할 때 `O(1)`, `O(n)` 같은 **Big-O 표기법**을 사용한다.

엄밀하게 Big-O는 입력이 충분히 커졌을 때 작업량 증가의 **상한**을 나타낸다. 여기서는 복잡한 정의보다 대표적인 증가 형태부터 익혀 보자.

아래 코드는 필요한 부분만 발췌한 예제다. `std::vector`에는 `<vector>`, `std::cout`에는 `<iostream>` 헤더가 필요하다.

## O(1) — 개수가 늘어도 하는 일은 일정하다

배열에서 첫 번째 값만 가져오는 코드다. 배열은 비어 있지 않다고 가정한다.

```cpp
int GetFirst(const std::vector<int>& values)
{
    return values[0];
}
```

데이터가 10개든 100만 개든 첫 번째 값만 가져오면 끝이다. 배열 전체를 확인할 필요가 없다.

| 데이터 개수 | 첫 번째 요소 접근 횟수 |
|---:|---:|
| 10개 | 1번 |
| 100개 | 1번 |
| 1,000개 | 1번 |

이렇게 입력 크기가 늘어도 작업량이 일정하면 **O(1), 상수 시간**이라고 한다.

여기서 `1`은 “정확히 한 번만 실행한다”는 뜻이 아니다. 고정된 작업을 몇 번 하더라도 데이터 개수에 따라 늘어나지 않으면 O(1)이다.

## O(n) — 개수가 늘어난 만큼 일이 늘어난다

이번에는 배열의 모든 값을 출력한다.

```cpp
void PrintAll(const std::vector<int>& values)
{
    for (int value : values)
    {
        std::cout << value << '\n';
    }
}
```

데이터가 `n`개라면 출력문도 `n`번 실행된다. 여기서는 요소 하나를 출력하는 비용을 일정하다고 보고, 출력문 실행 횟수를 센다.

| 데이터 개수 | 출력문 실행 횟수 |
|---:|---:|
| 10개 | 10번 |
| 100개 | 100번 |
| 1,000개 | 1,000번 |

**데이터가 10배가 되면 작업도 10배가 된다.** 이런 증가 형태를 O(n), 선형 시간이라고 한다.

배열의 합계를 구하거나 모든 요소를 한 번씩 확인하는 코드도 같은 방식으로 생각할 수 있다.

특정 값을 찾다가 중간에 멈추는 탐색이라면 실제 확인 횟수는 달라질 수 있다. 그래도 값이 마지막에 있거나 없다면 전체를 확인하므로, 그 탐색의 **최악 시간 복잡도는 O(n)**이다.

## O(n²) — 하나마다 전체를 다시 확인한다

몬스터 하나마다 다른 몬스터들을 확인한다고 생각해 보자.

아래 코드는 원리를 보기 위해 자기 자신과의 조합과 순서가 반대인 조합까지 모두 확인한다. `CheckPair`는 두 대상을 확인하는 함수이며, 한 번의 비용은 일정하다고 가정한다.

```cpp
for (int i = 0; i < n; ++i)
{
    for (int j = 0; j < n; ++j)
    {
        CheckPair(i, j);
    }
}
```

바깥 반복문이 한 번 실행될 때마다 안쪽 반복문이 `n`번 실행된다.

- 바깥 반복: n번
- 바깥 반복 한 번당 안쪽 반복: n번
- 전체 확인 횟수: n × n = n²번

| 데이터 개수 | 확인 횟수 |
|---:|---:|
| 10개 | 100번 |
| 100개 | 10,000번 |
| 1,000개 | 1,000,000번 |

**데이터가 10배가 되면 작업은 100배가 된다.** 이런 증가 형태를 O(n²)이라고 한다.

데이터가 적을 때는 괜찮던 코드가, 많아지면 크게 느려질 수 있는 이유다.

단, **반복문이 중첩됐다고 무조건 O(n²)은 아니다.** 안쪽 반복문이 항상 3번만 돈다면 전체는 `3n`번이다. 반복문의 개수보다 실제 실행 횟수를 봐야 한다.

## O(log n) — 한 번 할 때마다 후보가 절반으로 줄어든다

1부터 100까지 숫자 맞히기를 한다고 해보자. 답이 아니면 상대방이 “더 크다” 또는 “더 작다”라고 알려준다.

1, 2, 3을 차례대로 묻는 대신 가운데 숫자를 물어보면 어떨까?

> “50이야?” → 더 크다.  
> 이제 1부터 50까지는 확인할 필요가 없다.

다음에도 남은 범위의 가운데를 물으면 후보를 다시 크게 줄일 수 있다. 이런 식으로 찾는 방법이 **이진 탐색**이다.

범위가 절반씩 줄어드는 과정은 다음과 같다.

```text
후보 16개 → 8개 → 4개 → 2개 → 1개
```

이 과정을 단순하게 코드로 표현하면 다음과 같다. 실제 값을 찾는 코드는 아니고, 범위가 줄어드는 모습만 나타낸 예제다.

```cpp
int remaining = 16;

while (remaining > 1)
{
    remaining /= 2;
}
```

| 처음 후보 수 | 1개까지 절반으로 줄이는 횟수 |
|---:|---:|
| 16개 | 4번 |
| 1,024개 | 10번 |
| 1,048,576개 | 20번 |

후보가 약 1,000개에서 약 100만 개로 늘어도, 절반으로 줄이는 횟수는 10번에서 20번으로 늘어난다.

이렇게 한 번 처리할 때마다 남은 범위를 절반으로 줄여 나가는 형태가 **O(log n), 로그 시간**이다. 여기서 로그는 “몇 번 절반으로 나누면 1이 되는가?”로 이해하면 된다.

정렬된 배열의 이진 탐색은 최악의 경우에도 O(log n)번 수준의 비교로 값을 찾거나 없다는 것을 확인한다. 단, **배열이 정렬되어 있어야 한다.** 정렬되지 않았다면 정렬하는 비용은 별도로 생각해야 한다.

## 왜 2n도 O(n)일까?

배열 전체를 한 번이 아니라 두 번 확인하면 어떻게 될까?

아래의 두 함수는 각각 한 번 호출하는 비용이 일정하다고 가정한다.

```cpp
for (int value : values)
{
    DoSomething(value);
}

for (int value : values)
{
    DoSomethingElse(value);
}
```

첫 번째 반복문에서 `n`번, 두 번째에서도 `n`번 처리하므로 총 `2n`번이다.

그런데 이것도 O(n)이라고 표현한다.

| 데이터 개수 | 한 번 순회 | 두 번 순회 |
|---:|---:|---:|
| 10개 | 10번 | 20번 |
| 100개 | 100번 | 200번 |
| 1,000개 | 1,000번 | 2,000번 |

두 경우 모두 **데이터가 10배가 되면 작업도 10배가 된다.** 실제 작업 횟수는 다르지만 증가 형태는 같기 때문에, 고정된 배수인 `2`는 생략한다.

같은 이유로 작업 횟수가 `4n² + 3n + 7`이라면 O(n²)으로 표현한다. `n`이 커질수록 `n²` 부분이 나머지보다 훨씬 빠르게 커지므로, 가장 빠르게 커지는 항을 기준으로 정리하는 것이다.

그렇다고 실제 성능에서 배수가 중요하지 않다는 뜻은 아니다. `n`번 하는 코드와 `1000n`번 하는 코드는 둘 다 O(n)이지만 실제 작업량에는 큰 차이가 있다.

**Big-O가 같다는 것은 실행 시간이 같다는 뜻이 아니다.**

## 복습 정리

| 복잡도 | 기억할 느낌 | 이 글의 예제 |
|---|---|---|
| O(1) | 개수가 늘어도 하는 일은 일정 | 첫 번째 요소 가져오기 |
| O(n) | 개수가 늘어난 만큼 작업도 증가 | 전체 요소 한 번 출력하기 |
| O(n²) | 하나마다 전체를 다시 확인 | n번 안에서 다시 n번 반복하기 |
| O(log n) | 한 번 할 때마다 후보가 절반으로 감소 | 정렬된 배열의 이진 탐색 |

처음에는 코드를 보면서 다음 세 가지부터 확인하면 된다.

1. **n은 무엇의 개수인가?**
2. **반복문 안의 작업은 총 몇 번 실행되는가?**
3. **데이터가 늘면 그 횟수는 어떻게 달라지는가?**

복잡도 이름부터 붙이려고 하기보다는, **“이 코드가 몇 번 실행되지?”**부터 세어 보자.
