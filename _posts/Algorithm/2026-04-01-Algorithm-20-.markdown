기본 이진 탐색 트리는 키의 대소 관계만 유지한다. 검색·삽입·삭제 비용은 트리 높이 $H$에 비례하지만, 높이를 제한하는 규칙은 없다.

```text
10, 20, 30, 40, 50 순서로 삽입

10
  \
  20
    \
    30
      \
      40
        \
        50
```

이 트리의 높이는 노드 수와 같은 수준까지 커진다. 한 번의 비교로 한쪽 서브트리를 제외하더라도 실제로는 다음 노드가 하나뿐이어서 연결 리스트처럼 $O(N)$에 탐색하게 된다.

레드 블랙 트리(Red-Black Tree)는 각 노드에 빨강 또는 검정 색을 추가하고 몇 가지 규칙을 유지한다. 완벽하게 좌우 대칭인 트리를 만들지는 않지만, 가장 긴 루트 경로가 지나치게 길어지지 않도록 제한해 검색·삽입·삭제를 $O(\log N)$에 보장한다.

이번 글에서는 레드 블랙 트리의 균형 규칙과 회전의 역할을 먼저 살펴본다. 삽입과 삭제 뒤에 규칙을 복구하는 구체적인 경우는 다음 글에서 이어간다.

## BST의 대소 관계는 그대로 유지한다

레드 블랙 트리도 먼저 이진 탐색 트리다.

```text
왼쪽 서브트리의 키 < 현재 키
오른쪽 서브트리의 키 > 현재 키
```

중복 키를 허용한다면 별도의 삽입 정책이 필요하지만, 색상 규칙이 중복 정책을 대신 정해 주지는 않는다.

검색은 기본 BST와 똑같다.

```cpp
Node* Search(Node* node, int key)
{
    while (node != nullptr && node->key != key)
    {
        node = key < node->key ? node->left : node->right;
    }

    return node;
}
```

레드 블랙 트리의 색상과 회전은 검색 경로를 선택하기 위한 정보가 아니다. 트리 높이를 제한하기 위한 구조 관리 정보다.

## 노드에 색상 정보를 추가한다

개념적인 노드는 다음과 같이 표현할 수 있다.

```cpp
enum class Color
{
    Red,
    Black
};

struct Node
{
    int key = 0;
    Color color = Color::Red;
    Node* parent = nullptr;
    Node* left = nullptr;
    Node* right = nullptr;
};
```

새 노드를 빨간색으로 시작하는 이유는 삽입 복구에서 다룬다. 지금은 색상 하나만 추가한다고 자동으로 균형이 맞춰지는 것은 아니라는 점이 중요하다. 삽입과 삭제로 규칙이 깨지면 색을 바꾸거나 트리를 회전해야 한다.

## NIL 리프를 포함해 규칙을 정의한다

레드 블랙 트리를 설명할 때 자식이 없는 `nullptr` 위치를 검정 NIL 리프로 본다.

```text
      10(B)
      /   \
   NIL(B) NIL(B)
```

구현에서는 모든 빈자리에 실제 객체를 둘 수도 있고 `nullptr`을 검정으로 취급할 수도 있다. 어떤 표현을 사용하든 논리적인 NIL 리프는 검정이라는 규칙은 같다.

레드 블랙 트리는 다음 조건을 유지한다.

1. 모든 노드는 빨강 또는 검정이다.
2. 루트는 검정이다.
3. 모든 NIL 리프는 검정이다.
4. 빨간 노드의 자식은 모두 검정이다.
5. 한 노드에서 자손 NIL 리프까지 가는 모든 경로의 검정 노드 수가 같다.

마지막 조건에서 세는 검정 노드 수를 Black Height라고 한다. 정의에 따라 시작 노드 자체를 포함할지 제외할지는 다를 수 있으므로 구현과 설명에서 기준을 통일해야 한다.

## 빨간 노드는 연속할 수 없다

빨간 노드의 자식은 검정이어야 한다.

```text
허용

    20(B)
    /
 10(R)
 /
5(B)

위반

    20(B)
    /
 10(R)
 /
5(R)  ← 빨강이 연속됨
```

검정 노드 사이에 빨간 노드가 하나 들어갈 수는 있지만 빨간 노드가 두 개 이상 연속해서 경로를 늘릴 수는 없다. 이 규칙이 가장 긴 경로의 길이를 제한하는 데 사용된다.

색상은 키의 크기와 관계없다. 빨간 노드가 더 크다거나 검정 노드가 우선순위가 높다는 의미가 아니다.

## 모든 루트 경로의 Black Height가 같다

다음 트리는 각 NIL까지 검정 노드 수가 같다.

```text
          20(B)
        /       \
     10(R)      30(B)
     /   \          \
   5(B) 15(B)       40(R)
  /  \  /  \       /   \
 NIL NIL NIL NIL   NIL  NIL
```

루트 `20`에서 각 NIL까지 이동할 때 만나는 검정 노드 수는 같은 기준으로 세면 동일하다. 어떤 경로에 빨간 노드가 더 포함될 수는 있지만 검정 노드 수는 같아야 한다.

반대로 한쪽에 검정 노드만 계속 추가하면 Black Height가 달라진다.

```text
      20(B)
      /   \
   10(B)  NIL
   /
 5(B)

왼쪽과 오른쪽 NIL까지의 검정 노드 수가 다름
```

이 규칙 때문에 한쪽 경로만 제한 없이 길어질 수 없다.

## 가장 긴 경로는 가장 짧은 경로의 두 배를 넘지 않는다

어떤 노드의 Black Height가 $b$라고 하자.

- 가장 짧은 경로는 검정 노드만 지나며 길이가 $b$ 수준이다.
- 가장 긴 경로는 검정 노드 사이마다 빨간 노드가 하나씩 들어갈 수 있다.
- 빨간 노드는 연속할 수 없으므로 가장 긴 경로는 $2b$를 넘지 않는다.

```text
짧은 경로
B - B - B - NIL

가능한 가장 긴 형태
B - R - B - R - B - R - NIL
```

Black Height가 $b$인 서브트리는 적어도 $2^b-1$개의 내부 노드를 가진다. 전체 노드 수를 $N$이라고 하면 다음 관계를 얻을 수 있다.

$$
N \ge 2^b - 1
$$

$$
b \le \log_2(N+1)
$$

트리 전체 높이 $H$는 $2b$를 넘지 않으므로 다음 상한을 가진다.

$$
H \le 2\log_2(N+1)
$$

레드 블랙 트리는 완전 균형 트리가 아니어도 높이를 로그 범위에 유지한다. 이 느슨한 균형 덕분에 매번 트리를 완벽한 모양으로 재구성하지 않고도 연산의 최악 시간을 제한할 수 있다.

## 회전은 중위 순서를 유지하며 모양을 바꾼다

트리 회전(Rotation)은 노드 사이의 부모·자식 관계를 국소적으로 바꾸는 연산이다. 키의 정렬 순서는 유지하면서 한쪽으로 기운 높이를 다른 쪽으로 옮긴다.

### 왼쪽 회전

노드 `x`의 오른쪽 자식 `y`를 위로 올린다.

```text
회전 전                 x에서 왼쪽 회전 후

      x                         y
     / \                       / \
    A   y          →          x   C
       / \                   / \
      B   C                 A   B
```

중위 순서는 회전 전후 모두 같다.

```text
A < x < B < y < C
```

`B`는 `x`보다 크고 `y`보다 작으므로 회전 뒤 `x`의 오른쪽 서브트리에 놓을 수 있다.

```cpp
void RotateLeft(Node* x)
{
    Node* y = x->right;
    x->right = y->left;

    if (y->left != nullptr)
    {
        y->left->parent = x;
    }

    y->parent = x->parent;

    if (x->parent == nullptr)
    {
        root_ = y;
    }
    else if (x == x->parent->left)
    {
        x->parent->left = y;
    }
    else
    {
        x->parent->right = y;
    }

    y->left = x;
    x->parent = y;
}
```

연결 변경 순서가 중요하다.

1. `y`의 왼쪽 서브트리 `B`를 `x`의 오른쪽으로 옮긴다.
2. `y`를 `x`가 있던 부모 위치에 연결한다.
3. `x`를 `y`의 왼쪽 자식으로 연결한다.

루트에서 회전할 수 있으므로 `x->parent == nullptr`인 경우 `root_`도 갱신해야 한다.

### 오른쪽 회전

오른쪽 회전은 좌우가 반대다. `x`의 왼쪽 자식 `y`를 위로 올린다.

```text
회전 전                 x에서 오른쪽 회전 후

        x                       y
       / \                     / \
      y   C        →          A   x
     / \                         / \
    A   B                       B   C
```

```cpp
void RotateRight(Node* x)
{
    Node* y = x->left;
    x->left = y->right;

    if (y->right != nullptr)
    {
        y->right->parent = x;
    }

    y->parent = x->parent;

    if (x->parent == nullptr)
    {
        root_ = y;
    }
    else if (x == x->parent->left)
    {
        x->parent->left = y;
    }
    else
    {
        x->parent->right = y;
    }

    y->right = x;
    x->parent = y;
}
```

왼쪽 회전과 오른쪽 회전은 서로 역연산 관계다. 하지만 실제 복구에서는 회전만 하거나 색상만 바꾸는 것이 아니라 위반 상황에 맞춰 두 작업을 함께 사용한다.

## 회전만으로 색상 규칙이 자동 복구되지는 않는다

회전은 BST의 키 순서를 유지하지만 노드의 색을 바꾸지 않는다.

```text
      30(B)
      /
   20(R)
   /
10(R)
```

빨간 부모 `20`과 빨간 자식 `10`이 연속되어 규칙을 위반한다. 오른쪽 회전으로 모양을 바꿀 수 있지만 색을 그대로 두면 다른 위치에서 색상 규칙이 여전히 깨질 수 있다.

```text
회전과 색상 교환 후

      20(B)
     /    \
  10(R)  30(R)
```

이 예에서는 회전과 함께 기존 부모·조부모의 색을 조정해야 Black Height와 빨강 연속 규칙을 모두 복구할 수 있다.

어떤 회전과 색상 변경이 필요한지는 새 노드의 부모, 조부모와 삼촌(Uncle)의 색 및 배치에 따라 달라진다.

## 새 노드는 빨간색으로 삽입한다

BST 규칙에 따라 새 노드를 리프 위치에 넣은 뒤 레드 블랙 규칙을 복구한다. 새 노드는 일반적으로 빨간색으로 시작한다.

```text
검정 노드로 삽입
→ 새 노드를 포함하는 경로의 Black Height가 즉시 1 증가

빨간 노드로 삽입
→ Black Height는 유지
→ 부모도 빨간색일 때만 빨강 연속 위반 가능
```

빨간색 삽입은 발생 가능한 문제를 새 노드와 부모 주변으로 제한한다.

```text
부모가 검정
→ 규칙 유지, 종료

새 노드가 루트
→ 루트를 검정으로 변경

부모가 빨강
→ 조부모와 삼촌의 색 및 방향을 확인해 복구
```

부모가 빨강이라면 조부모는 반드시 검정이다. 삽입 전 트리가 유효했다면 빨간 부모의 부모까지 빨강일 수 없기 때문이다.

## 삼촌의 색이 삽입 복구 방향을 나눈다

부모의 형제 노드를 삼촌(Uncle)이라고 한다.

```text
          G
        /   \
       P     U
      /
     N

G: Grandparent
P: Parent
U: Uncle
N: 새 노드
```

부모가 빨강일 때 크게 두 방향으로 나뉜다.

### 삼촌이 빨강

부모와 삼촌을 검정으로 바꾸고 조부모를 빨강으로 바꾼다. 현재 서브트리의 Black Height를 유지하면서 빨강 연속 문제를 조부모 위치로 올려 보낸다.

### 삼촌이 검정 또는 NIL

색상 변경만으로 해결하기 어렵다. 새 노드와 부모가 일직선인지 꺾인 형태인지 확인하고 한 번 또는 두 번 회전한 뒤 색을 조정한다.

```text
일직선: LL, RR
꺾인 형태: LR, RL
```

구체적인 경우별 복구 과정은 다음 글에서 단계별로 살펴본다.

## 기본 BST와 비교한다

| 비교 | 기본 BST | Red-Black Tree |
|---|---|---|
| 검색 규칙 | 키의 대소 관계 | 동일 |
| 추가 정보 | 없음 | 노드 색상 |
| 균형 복구 | 없음 | 색상 변경과 회전 |
| 트리 높이 | 최악 $O(N)$ | $O(\log N)$ 보장 |
| 검색 | $O(H)$ | $O(\log N)$ |
| 삽입·삭제 | 구조는 단순하지만 편향 가능 | 복구 과정이 추가됨 |

레드 블랙 트리는 AVL 트리보다 비교적 느슨한 균형을 유지한다. 일반적으로 검색만 극단적으로 많이 하는 상황과 삽입·삭제가 자주 일어나는 상황에서 두 균형 트리의 회전 빈도와 높이 특성이 다를 수 있지만, 실제 선택은 구현과 사용 패턴을 함께 측정해야 한다.

C++의 `std::map`과 `std::set`은 정렬된 연관 컨테이너이며 표준이 주요 연산의 로그 복잡도를 요구한다. 많은 구현이 레드 블랙 트리를 사용하지만 C++ 표준이 내부 자료구조 자체를 레드 블랙 트리로 강제하는 것은 아니다.

## 첫 단계에서 확인할 기준

1. 레드 블랙 트리가 먼저 BST 규칙을 만족하는가?
2. 중복 키 정책을 색상 규칙과 별도로 정했는가?
3. NIL 리프를 검정으로 취급하는가?
4. 루트가 검정인가?
5. 빨간 노드 아래에 빨간 자식이 없는가?
6. 모든 자손 NIL 경로의 Black Height가 같은가?
7. Black Height를 셀 때 시작·NIL 포함 기준을 통일했는가?
8. 회전 전후에 중위 순서가 유지되는가?
9. 회전할 노드의 부모가 없을 때 루트를 갱신하는가?
10. 이동한 중간 서브트리의 부모 포인터도 갱신하는가?
11. 회전과 색상 변경의 역할을 구분하는가?
12. 새 노드를 빨간색으로 삽입하는 이유를 설명할 수 있는가?

레드 블랙 트리의 핵심은 트리를 완벽하게 대칭으로 만드는 것이 아니다. 빨강 연속 금지와 동일한 Black Height 규칙으로 경로 길이의 차이를 제한하고, 규칙이 깨졌을 때 중위 순서를 보존하는 회전과 색상 변경으로 국소적인 구조를 복구하는 데 있다.
