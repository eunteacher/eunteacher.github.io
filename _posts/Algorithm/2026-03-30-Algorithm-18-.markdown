# [Algorithm] 이진 탐색(Binary Search) 알고리즘 구현

정렬된 배열에서 탐색 범위를 절반씩 좁혀가며 데이터를 찾는 이진 탐색 알고리즘의 원리와 자료구조별 한계점 분석

## 1. 소스 코드 (Source Code)

```cpp
#include <iostream>
#include <vector>
using namespace std;

// 탐색 대상이 되는 동적 배열
// 이진 탐색을 적용하기 위해서는 데이터가 반드시 정렬된 상태여야 함
vector<int> numbers;

// 이진 탐색 알고리즘 (Time Complexity: O(log N))
void BinarySearch(int N)
{
    int left = 0;
    int right = (int)numbers.size() - 1;

    // 탐색 범위가 역전될 때까지 반복 수행
    while (left <= right)
    {
        cout << "탐색 범위: " << left << "~" << right << '\n';

        // 오버플로우를 방지하는 안전한 중앙값 계산 방식 적용 권장
        // 실무에서는 left + (right - left) / 2 형태로 사용하는 것이 안전함
        int mid = (left + right) / 2;

        if (N < numbers[mid])
        {
            // 찾고자 하는 값이 중앙값보다 작으면 탐색 범위를 왼쪽 절반으로 축소
            cout << N << " < " << numbers[mid] << '\n';
            right = mid - 1;
        }
        else if (N > numbers[mid])
        {
            // 찾고자 하는 값이 중앙값보다 크면 탐색 범위를 오른쪽 절반으로 축소
            cout << N << " > " << numbers[mid] << '\n';
            left = mid + 1;
        }
        else
        {
            // 값을 찾은 경우 탐색 종료
            cout << "데이터를 찾음: 인덱스 " << mid << '\n';
            break;
        }
    }
}

int main()
{
    // 오름차순으로 정렬된 데이터 초기화
    numbers = vector<int>{ 1, 8, 15, 23, 32, 44, 56, 63, 81, 91 };

    // 타겟 숫자 81 탐색 시작
    BinarySearch(81);

    return 0;
}
```

## 2. 이론 정리 (Study Notes)

이진 탐색(Binary Search)은 오름차순 또는 내림차순으로 정렬된 데이터 집합에서 특정 값을 찾을 때 탐색 범위를 매번 절반으로 줄여나가는 고속 탐색 알고리즘

### 자료구조별 이진 탐색 적용 가능 여부 및 특징

| 자료구조 | 이진 탐색 가능 여부 | 임의 접근(Random Access) | 삽입/삭제 성능 | 종합 특징 |
| :--- | :--- | :--- | :--- | :--- |
| **배열 (Array/Vector)** | 가능 | $O(1)$ | $O(N)$ | 인덱스를 통한 빠른 접근이 가능하여 이진 탐색에 적합하나, 데이터의 중간 삽입/삭제 시 오버헤드가 큼 |
| **연결 리스트 (Linked List)** | 불가능 | $O(N)$ | $O(1)$ | 임의 접근이 불가하여 중앙값을 단번에 찾을 수 없으므로 이진 탐색을 적용할 수 없음 |
| **이진 탐색 트리 (BST)** | 대체 가능 | 트리 구조 | $O(\log N)$ | 배열과 연결 리스트의 장점을 결합하여 탐색, 삽입, 삭제 모두 균형 잡힌 성능을 제공함 |

### 이진 탐색의 시간 복잡도와 수식

데이터의 총 개수를 $N$이라고 할 때, 매 탐색마다 검색 대상이 $\frac{1}{2}$로 줄어듦
최악의 경우 남은 데이터가 1개가 될 때까지 탐색을 수행하므로, 탐색 횟수 $K$에 대한 관계식은 다음과 같음

$$N \times \left(\frac{1}{2}\right)^K = 1$$
$$2^K = N \implies K = \log_2 N$$

따라서 이진 탐색의 시간 복잡도는 $O(\log N)$을 보장

## 3. 종합 의견 (Review)

### 핵심 요약 및 주의사항
* 이진 탐색을 수행하기 전 데이터 집합은 반드시 정렬(Sorting)되어 있어야 함
* 중앙값 인덱스를 구하는 로직 `(left + right) / 2`는 `left`와 `right`의 합이 정수 한계치를 초과할 경우 정수 오버플로우(Integer Overflow)를 유발할 수 있으므로 주의가 필요
* 검색 속도는 매우 빠르지만 배열 기반이므로 동적인 데이터 추가나 삭제가 빈번한 환경에서는 정렬 상태를 유지하기 위한 비용이 탐색 이점을 상쇄할 수 있음

### Tip
* `mid` 계산 시 오버플로우를 방지하려면 `int mid = left + (right - left) / 2;` 형태로 작성하는 것이 실무적인 표준
