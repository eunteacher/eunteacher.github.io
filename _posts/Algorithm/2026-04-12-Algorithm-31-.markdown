재귀 함수는 큰 문제를 작은 문제로 표현하기 좋다. 하지만 서로 다른 재귀 경로가 같은 작은 문제를 반복해서 계산하면 호출 수가 빠르게 증가한다.

```text
F(5)
├─ F(4)
│  ├─ F(3)
│  └─ F(2)
└─ F(3)  ← 이미 위에서 계산한 문제
   ├─ F(2)
   └─ F(1)
```

동적 계획법(Dynamic Programming, DP)은 문제의 상태를 정의하고, 작은 상태의 답으로 큰 상태의 답을 계산하며, 한 번 구한 결과를 저장해 재사용한다.

핵심은 배열을 만드는 것 자체가 아니다.

```text
무엇이 하나의 작은 문제인가?       → 상태
작은 답으로 큰 답을 어떻게 구하는가? → 점화식
가장 작은 문제의 답은 무엇인가?      → 기저값
필요한 답을 어떤 순서로 계산하는가?   → 계산 순서
```

이 네 가지가 일관되게 정의돼야 DP 테이블의 각 값이 무엇을 의미하는지 설명할 수 있다.

## DP가 잘 맞는 두 가지 성질

### 중복되는 부분 문제

같은 상태의 답이 여러 경로에서 반복해서 필요하다.

```text
F(5) 계산 중 F(3) 필요
F(4) 계산 중에도 F(3) 필요
```

한 번 계산한 `F(3)`을 저장하면 이후 호출은 즉시 같은 값을 사용할 수 있다.

### 최적 부분 구조

전체 문제의 최적 답을 작은 문제의 최적 답으로 구성할 수 있다.

```text
금액 x를 만드는 최소 동전 수

마지막 동전이 coin이라면
1 + 금액 x-coin을 만드는 최소 동전 수
```

작은 문제의 최적 답을 사용하지 않고도 더 좋은 전체 답이 나올 수 있다면 해당 점화식은 올바르지 않다.

모든 재귀 문제가 DP인 것은 아니다. 부분 문제가 거의 겹치지 않는 분할 정복에서는 결과 저장이 큰 이점을 주지 않을 수 있다. 반대로 재귀로 작성하지 않더라도 테이블의 상태 전이를 계산하면 DP다.

## 피보나치 재귀에서 중복을 확인한다

피보나치 수는 다음 점화식으로 정의한다.

$$
F(0)=0, \quad F(1)=1
$$

$$
F(n)=F(n-1)+F(n-2) \quad (n\ge2)
$$

점화식을 그대로 재귀 함수로 옮길 수 있다.

```cpp
long long FibonacciRecursive(int n)
{
    if (n <= 1)
    {
        return n;
    }

    return FibonacciRecursive(n - 1) + FibonacciRecursive(n - 2);
}
```

코드는 정의와 비슷하지만 같은 `F(k)`를 반복 계산한다. 호출 수는 피보나치 수와 비슷한 속도로 증가하며 시간 복잡도는 $O(\varphi^N)$ 수준이다. 흔히 더 느슨한 상한으로 $O(2^N)$이라고도 표현한다.

```text
n이 1 증가할 때
→ 단순히 호출 하나만 추가되는 것이 아님
→ 두 재귀 가지 아래의 중복 호출이 함께 증가
```

## Top-down은 필요한 상태를 재귀로 계산한다

메모이제이션(Memoization)은 재귀 함수의 결과를 저장한다.

```cpp
long long FibonacciMemo(int n, std::vector<long long>& memo)
{
    if (memo[n] != -1)
    {
        return memo[n];
    }

    memo[n] = FibonacciMemo(n - 1, memo) + FibonacciMemo(n - 2, memo);
    return memo[n];
}
```

기저값을 먼저 저장한다.

```cpp
long long FibonacciTopDown(int n)
{
    assert(n >= 0 && n <= 92);

    std::vector<long long> memo(static_cast<std::size_t>(n) + 1, -1);
    memo[0] = 0;

    if (n >= 1)
    {
        memo[1] = 1;
    }

    return FibonacciMemo(n, memo);
}
```

`-1`은 피보나치 결과로 나올 수 없는 값이므로 미계산 상태 표시로 사용할 수 있다. 문제의 유효한 답에 음수가 포함될 수 있다면 별도의 방문 배열이나 `std::optional` 같은 표현이 필요하다.

각 `F(k)`는 처음 한 번만 실제로 계산된다. 상태가 `0`부터 `n`까지 $n+1$개이고 각 상태 전이는 상수 시간이므로 시간 복잡도는 $O(N)$이다. 메모 배열과 재귀 호출 스택에 $O(N)$ 공간을 사용한다.

`long long`에는 `F(92)`까지 담을 수 있고 `F(93)`부터 signed 64-bit 범위를 넘는다. DP로 시간 문제를 해결해도 결과 타입의 범위 문제는 별도로 확인해야 한다.

## Bottom-up은 작은 상태부터 테이블을 채운다

Tabulation은 의존하는 상태가 먼저 계산되도록 반복 순서를 정한다.

```cpp
long long FibonacciBottomUp(int n)
{
    assert(n >= 0 && n <= 92);

    if (n <= 1)
    {
        return n;
    }

    std::vector<long long> dp(static_cast<std::size_t>(n) + 1, 0);
    dp[1] = 1;

    for (int i = 2; i <= n; ++i)
    {
        dp[i] = dp[i - 1] + dp[i - 2];
    }

    return dp[n];
}
```

```text
dp[0] = 0
dp[1] = 1
dp[2] = dp[1] + dp[0]
dp[3] = dp[2] + dp[1]
...
```

`dp[i]`를 계산할 때 필요한 `dp[i-1]`, `dp[i-2]`가 이미 채워져 있다. 시간은 $O(N)$이고 테이블 공간은 $O(N)$이다.

## 이전 두 상태만 필요하면 공간을 줄일 수 있다

최종 값만 필요하고 중간 테이블을 다시 사용하지 않는다면 최근 두 값만 보관한다.

```cpp
long long Fibonacci(int n)
{
    assert(n >= 0 && n <= 92);

    if (n <= 1)
    {
        return n;
    }

    long long previous = 0;
    long long current = 1;

    for (int i = 2; i <= n; ++i)
    {
        long long next = previous + current;
        previous = current;
        current = next;
    }

    return current;
}
```

시간은 $O(N)$이고 추가 공간은 $O(1)$이다.

모든 DP 테이블을 무조건 압축할 수 있는 것은 아니다. 최종 경로를 복원하거나 이후 단계에서 여러 과거 상태가 필요하면 중간 정보도 저장해야 한다.

## Top-down과 Bottom-up을 비교한다

| 비교 | Top-down | Bottom-up |
|---|---|---|
| 시작점 | 최종 상태에서 재귀 호출 | 기저 상태에서 반복 시작 |
| 계산 상태 | 실제로 도달한 상태 | 반복 범위의 상태를 채움 |
| 코드 구조 | 점화식과 가까움 | 계산 순서가 직접 드러남 |
| 호출 스택 | 사용 | 일반적으로 사용하지 않음 |
| 깊은 상태 | 스택 한도 고려 | 반복문으로 처리 가능 |
| 상태 순서 | 재귀 의존성이 결정 | 직접 올바른 순서를 설계 |

희소한 상태 공간에서 일부 상태만 도달한다면 Top-down이 불필요한 계산을 피할 수 있다. 모든 상태가 필요하고 계산 순서가 명확하면 Bottom-up이 호출 오버헤드와 스택 깊이 문제를 피하기 쉽다.

두 방식의 결과가 달라서는 안 된다. 상태 정의와 점화식이 같고 필요한 상태를 모두 올바르게 계산한다면 접근 방향만 다르다.

## 최소 동전 문제로 최적화 DP를 만든다

동전 종류를 여러 번 사용할 수 있고 목표 금액을 만드는 최소 동전 수를 구한다고 하자.

```text
coins = {1, 3, 4}
target = 6

4 + 1 + 1 → 3개
3 + 3     → 2개, 최소
```

가장 큰 동전부터 고르는 단순 greedy는 이 동전 체계에서 최적 답을 놓친다.

### 상태

```text
dp[x] = 금액 x를 만드는 최소 동전 수
```

### 기저값

```text
dp[0] = 0
```

금액 0을 만드는 데 동전이 필요하지 않다.

### 점화식

마지막으로 사용한 동전이 `coin`이라면 그 전에는 `x - coin`을 만들었다.

$$
dp[x] = \min_{coin \le x}(dp[x-coin]+1)
$$

단, `x - coin`을 만들 수 있는 경우만 후보로 사용한다.

## 만들 수 없는 상태를 안전하게 표시한다

목표 금액보다 큰 값을 `Infinity`로 사용한다. 모든 동전 가치가 양수라면 최소 동전 수는 목표 금액을 넘을 필요가 없으므로 `target + 1`이면 충분하다.

```cpp
int MinCoins(const std::vector<int>& coins, int target)
{
    assert(target >= 0);

    int infinity = target + 1;
    std::vector<int> dp(static_cast<std::size_t>(target) + 1, infinity);
    dp[0] = 0;

    for (int amount = 1; amount <= target; ++amount)
    {
        for (int coin : coins)
        {
            assert(coin > 0);

            if (coin <= amount && dp[amount - coin] != infinity)
            {
                dp[amount] = std::min(dp[amount], dp[amount - coin] + 1);
            }
        }
    }

    return dp[target] == infinity ? -1 : dp[target];
}
```

`dp[amount - coin]`이 만들 수 없는 상태라면 `+1` 후보로 사용하지 않는다. 매우 큰 정수 최댓값을 Infinity로 사용하면서 그대로 1을 더하면 오버플로가 발생할 수 있다.

```text
coins = {1, 3, 4}

dp[0] = 0
dp[1] = 1                 {1}
dp[2] = 2                 {1,1}
dp[3] = 1                 {3}
dp[4] = 1                 {4}
dp[5] = 2                 {1,4}
dp[6] = 2                 {3,3}
```

상태 수는 `target + 1`, 각 상태에서 모든 동전 $C$개를 확인하므로 시간 복잡도는 $O(target \times C)$이고 공간은 $O(target)$이다.

## 반복 순서가 문제의 의미를 바꿀 수 있다

동전 DP에서는 반복문의 순서에 따라 조합 수와 순열 수처럼 서로 다른 문제를 풀 수 있다.

```text
동전별로 금액 증가
→ 일반적으로 조합 수 계산에 사용

금액별로 모든 동전 확인
→ 일반적으로 순서가 다른 경우까지 세는 전이에 사용
```

최솟값 문제에서는 모든 이전 금액이 먼저 계산되기만 하면 위 코드의 순서가 유효하다. 하지만 경우의 수 문제로 바뀌면 같은 배열과 비슷한 점화식을 사용해도 반복 순서가 답의 중복 계산 방식을 결정한다.

DP 코드를 외워 옮기지 않고 `dp[state]`가 정확히 무엇을 세거나 최적화하는지 먼저 정의해야 한다.

## 답뿐 아니라 선택을 복원할 수 있다

최소 동전 개수뿐 아니라 실제 선택한 동전도 필요하면 갱신할 때 마지막 선택을 저장한다.

```cpp
if (dp[amount - coin] + 1 < dp[amount])
{
    dp[amount] = dp[amount - coin] + 1;
    choice[amount] = coin;
}
```

목표 금액부터 선택한 동전을 빼며 0까지 이동한다.

```text
amount = 6, choice[6] = 3
amount = 3, choice[3] = 3
amount = 0, 종료

선택: 3, 3
```

값만 저장하는 DP와 경로·선택을 복원하는 DP는 필요한 메모리가 다르다. 공간 최적화를 하기 전에 최종 출력 요구사항을 확인한다.

## DP 설계 순서

문제를 보자마자 재귀 함수부터 작성하기보다 다음 순서로 정리한다.

### 1. 상태 정의

```text
dp[i]는 무엇을 의미하는가?
dp[y][x]는 어느 범위의 어떤 답인가?
```

상태 설명에 모호한 표현이 있으면 점화식도 흔들린다.

### 2. 선택과 전이

현재 상태에 도달하기 직전 또는 현재 상태에서 할 수 있는 선택을 나눈다.

```text
마지막 동전으로 무엇을 사용했는가?
현재 칸에 위에서 왔는가, 왼쪽에서 왔는가?
현재 원소를 선택했는가, 건너뛰었는가?
```

### 3. 기저값

더 작은 상태로 나눌 수 없는 문제의 답을 정한다.

### 4. 계산 순서

전이에 필요한 상태가 현재 상태보다 먼저 계산되는 순서를 찾는다. 순환 의존이 생기면 상태 정의나 접근 방식을 다시 확인한다.

### 5. 불가능 상태

최솟값에서는 충분히 큰 값, 최댓값에서는 충분히 작은 값, 경우의 수에서는 0처럼 문제에 맞는 표시를 정한다. 전이 중 해당 표시와 산술 연산할 때 오버플로가 없는지도 확인한다.

### 6. 답의 위치와 복원 정보

최종 답이 `dp[n]` 하나인지 전체 상태의 최댓값인지 확인한다. 실제 선택 과정이 필요하면 부모나 선택 배열을 함께 저장한다.

## DP가 항상 가장 좋은 방법은 아니다

상태 수가 너무 많으면 각 상태를 한 번만 계산해도 시간과 메모리가 부족하다.

```text
상태 차원 5개
각 차원 크기 100
→ 최대 10,000,000,000개 상태
```

상태에서 불필요한 정보를 제거하거나 대칭 상태를 합치고, 도달 가능한 상태만 메모이제이션하는 방법을 검토한다.

Greedy가 성립하는 문제에 큰 DP를 사용하면 불필요한 비용이 들 수 있고, 그래프의 최단 경로 문제라면 BFS나 Dijkstra가 상태 전이를 더 자연스럽게 처리할 수 있다. 문제 구조에 맞는 알고리즘을 선택한다.

## 전체 검증 예제

```cpp
#include <algorithm>
#include <cassert>
#include <vector>

// Fibonacci와 MinCoins 구현은 앞의 코드와 같다.

int main()
{
    assert(FibonacciTopDown(0) == 0);
    assert(FibonacciTopDown(1) == 1);
    assert(FibonacciTopDown(10) == 55);
    assert(FibonacciBottomUp(10) == 55);
    assert(Fibonacci(10) == 55);

    assert(MinCoins(std::vector<int>{1, 3, 4}, 6) == 2);
    assert(MinCoins(std::vector<int>{2, 4}, 7) == -1);
    assert(MinCoins(std::vector<int>{5}, 0) == 0);
}
```

기저 상태와 일반 상태, 만들 수 없는 상태를 함께 확인한다. Top-down과 Bottom-up으로 같은 상태 정의를 구현했다면 여러 입력에서 결과가 같은지도 비교할 수 있다.

## 동적 계획법을 설계할 때 확인할 기준

1. `dp[state]`의 의미를 한 문장으로 정확히 설명할 수 있는가?
2. 같은 상태가 여러 경로에서 반복되는가?
3. 작은 문제의 최적 답으로 큰 문제의 최적 답을 만들 수 있는가?
4. 모든 선택을 빠뜨리지 않고 점화식에 포함했는가?
5. 서로 같은 결과를 만드는 선택을 중복 계산하지 않는가?
6. 기저값이 점화식과 일관되는가?
7. 전이에 필요한 상태가 먼저 계산되는가?
8. 미계산 상태와 유효한 답을 구분할 수 있는가?
9. 불가능 상태에 산술 연산할 때 오버플로되지 않는가?
10. 결과 타입이 가능한 답의 범위를 담는가?
11. 재귀 깊이가 스택 한도를 넘지 않는가?
12. 실제 선택을 복원할 정보가 필요한가?
13. 공간 압축 뒤에도 필요한 과거 상태가 남는가?
14. 상태 수와 상태당 전이 수를 곱해 전체 복잡도를 계산했는가?

동적 계획법의 핵심은 계산 결과를 배열에 저장하는 행위가 아니다. 같은 작은 문제를 다시 풀지 않도록 상태를 구분하고, 그 상태 사이의 의존 관계를 점화식으로 표현한 뒤 올바른 순서로 한 번씩 계산하는 데 있다.

## 다음 학습: LIS

다음 글에서는 수열의 순서를 유지하면서 값이 증가하는 가장 긴 부분 수열을 찾는 LIS 문제를 다룬다. $O(N^2)$ DP의 상태와 점화식을 먼저 만들고, 마지막 값 후보를 이진 탐색하는 $O(N\log N)$ 방법과 차이를 살펴본다.
