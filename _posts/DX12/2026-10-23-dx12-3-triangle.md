이전 프로젝트에서는 DX12 장치와 화면 출력에 필요한 객체를 만들고 배경색을 출력했다. 이번에는 위치와 색상을 가진 정점 세 개를 준비해서 삼각형을 그린다.

핵심은 **CPU에서 준비한 정점 데이터가 GPU의 렌더링 파이프라인을 거쳐 화면의 색으로 바뀌는 과정**이다. `Mesh::Init()`으로 데이터를 준비하고, 셰이더와 파이프라인을 설정한 다음, `Mesh::Render()`로 그리기 명령을 기록한다.

## 1. 이전 프로젝트에서 달라진 점

| 항목 | 이전 프로젝트: 장치 초기화 | 이번 프로젝트: 삼각형 출력 |
|---|---|---|
| 그릴 데이터 | 없음 | 위치와 색상을 가진 정점 세 개 |
| Mesh | 없음 | 정점 버퍼 생성과 그리기 명령 기록 |
| Shader | 없음 | HLSL 컴파일과 PSO 생성 |
| Root Signature | 없음 | 셰이더 리소스 연결 규칙 생성 |
| 프레임 처리 | 배경색 지우기와 화면 표시 | 배경색 위에 삼각형 그리기 |

추가된 주요 파일의 역할은 다음과 같다.

| 파일 | 역할 |
|---|---|
| `Mesh.h / Mesh.cpp` | 정점 버퍼와 Vertex Buffer View 관리 |
| `Shader.h / Shader.cpp` | 정점·픽셀 셰이더 컴파일과 PSO 설정 |
| `RootSignature.h / RootSignature.cpp` | Root Signature 생성 |
| `Resources/Shader/default.hlsli` | GPU에서 실행할 HLSL 코드 |

`EnginePch.h`에는 `Vertex` 구조체와 엔진 접근용 매크로가 추가되었다.

```cpp
#define DEVICE GEngine->GetDevice()->GetDevice()
#define CMD_LIST GEngine->GetCmdQueue()->GetCmdList()
#define ROOT_SIGNATURE GEngine->GetRootSignature()->GetSignature()
```

매크로는 새로운 DX12 기능이 아니라 기존 객체에 접근하는 표현을 짧게 만든 것이다.

이전 프로젝트의 `DescriptorHeap` 클래스가 담당하던 RTV 생성 기능은 이번 프로젝트에서 `SwapChain::CreateRTV()`로 이동했다.

## 2. 삼각형의 재료: 정점 세 개

정점 하나에는 위치와 색상이 들어간다.

```cpp
struct Vertex
{
  Vec3 pos;
  Vec4 color;
};
```

`Game::Init()`에서는 정점 세 개를 다음과 같이 지정한다.

| 정점 | 위치 `(x, y, z)` | 색상 `(r, g, b, a)` |
|---|---|---|
| 0 | `(0, 0.5, 0.5)` | `(1, 0, 0, 1)` — 빨강 |
| 1 | `(0.5, -0.5, 0.5)` | `(0, 1, 0, 1)` — 초록 |
| 2 | `(-0.5, -0.5, 0.5)` | `(0, 0, 1, 1)` — 파랑 |

```text
             0: 빨강
                /\
               /  \
              /    \
     2: 파랑 /______\ 1: 초록
```

정점 세 개를 저장하는 것만으로 화면에 삼각형이 나타나지는 않는다. GPU에 데이터를 전달하고, 각 데이터의 의미와 정점을 묶는 방식, 위치와 색상을 계산할 셰이더를 설정해야 한다.

## 3. Mesh::Init(): 정점 버퍼 준비

`Mesh::Init()`의 작업은 세 단계로 나눌 수 있다.

```text
정점 버퍼 생성
  → 정점 데이터 복사
  → Vertex Buffer View 설정
```

### 정점 버퍼 생성

먼저 정점 개수와 필요한 메모리 크기를 계산한다.

```cpp
_vertexCount = static_cast<uint32>(vec.size());
uint32 bufferSize = _vertexCount * sizeof(Vertex);
```

이번 `Vertex`는 위치의 float 세 개와 색상의 float 네 개로 구성된다. 정점 하나가 28바이트이고, 세 개를 저장하므로 버퍼 크기는 84바이트다.

버퍼는 `CreateCommittedResource()`로 생성한다. 설정에 사용하는 보조 구조체는 다음과 같다.

```cpp
D3D12_HEAP_PROPERTIES heapProperty = CD3DX12_HEAP_PROPERTIES(D3D12_HEAP_TYPE_UPLOAD);
D3D12_RESOURCE_DESC desc = CD3DX12_RESOURCE_DESC::Buffer(bufferSize);
```

UPLOAD Heap은 CPU가 데이터를 쓸 수 있고 GPU가 읽을 수 있는 메모리다. 이번 예제에서는 이 버퍼를 정점 버퍼로 직접 사용한다.

### 정점 데이터 복사

```cpp
void* vertexDataBuffer = nullptr;
CD3DX12_RANGE readRange(0, 0);

_vertexBuffer->Map(0, &readRange, &vertexDataBuffer);
::memcpy(vertexDataBuffer, &vec[0], bufferSize);
_vertexBuffer->Unmap(0, nullptr);
```

| 코드 | 역할 |
|---|---|
| `Map()` | CPU에서 버퍼에 접근할 주소를 얻는다 |
| `memcpy()` | 정점 배열을 해당 메모리에 복사한다 |
| `Unmap()` | CPU의 매핑 사용을 마친다 |

`readRange(0, 0)`은 CPU에서 이 리소스의 데이터를 읽을 의도가 없다는 뜻이다. 여기서는 쓰기만 수행한다.

`Unmap()`이 별도의 GPU 복사 명령을 실행하는 것은 아니다. 이번 코드는 UPLOAD 버퍼에 데이터를 쓰고 GPU가 그 버퍼를 읽는 구조다.

### Vertex Buffer View 설정

```cpp
_vertexBufferView.BufferLocation = _vertexBuffer->GetGPUVirtualAddress();
_vertexBufferView.StrideInBytes = sizeof(Vertex);
_vertexBufferView.SizeInBytes = bufferSize;
```

| 항목 | 의미 |
|---|---|
| `BufferLocation` | 정점 데이터의 GPU 가상 주소 |
| `StrideInBytes` | 다음 정점으로 이동할 바이트 간격 |
| `SizeInBytes` | 버퍼의 전체 바이트 크기 |

**Vertex Buffer는 실제 데이터이고, Vertex Buffer View는 그 버퍼를 읽기 위한 정보**다. Vertex Buffer View는 RTV처럼 Descriptor Heap에 생성하는 디스크립터가 아니라, 주소와 크기 등을 담아 명령 기록 시 전달하는 구조체다.

## 4. Input Layout: 정점 데이터의 의미 설명

정점 버퍼에는 바이트들이 저장되어 있다. GPU가 위치와 색상을 구분하려면 각 데이터의 형식과 시작 위치를 알아야 한다.

```text
정점 하나: 28바이트

[ 위치 x, y, z ][ 색상 r, g, b, a ]
0             12                28
```

`Shader::Init()`에서 만드는 Input Layout이 이 구조를 설명한다.

| 시맨틱 | 데이터 형식 | 입력 슬롯 | 시작 오프셋 |
|---|---|---|---|
| `POSITION` | `R32G32B32_FLOAT` | 0 | 0바이트 |
| `COLOR` | `R32G32B32A32_FLOAT` | 0 | 12바이트 |

HLSL 입력 구조체도 같은 의미로 선언한다.

```hlsl
struct VS_IN
{
  float3 pos : POSITION;
  float4 color : COLOR;
};
```

`POSITION`, `COLOR`는 시맨틱이다. Input Layout에서 설명한 데이터와 정점 셰이더의 입력을 연결한다.

Vertex Buffer View의 Stride가 **정점과 정점 사이의 간격**을 설명한다면, Input Layout은 **정점 하나 안에서 각 항목을 어떻게 읽는지** 설명한다.

## 5. 셰이더: GPU에서 실행하는 프로그램

이번 프로젝트는 `default.hlsli`에 작성한 두 함수를 각각 컴파일한다.

| 함수 | 셰이더 단계 | 컴파일 대상 |
|---|---|---|
| `VS_Main` | Vertex Shader | `vs_5_0` |
| `PS_Main` | Pixel Shader | `ps_5_0` |

```cpp
CreateVertexShader(path, "VS_Main", "vs_5_0");
CreatePixelShader(path, "PS_Main", "ps_5_0");
```

내부에서는 `D3DCompileFromFile()`로 HLSL을 컴파일한다. 컴파일 결과 바이트코드는 PSO를 만들 때 사용한다. 파일 확장자는 `.hlsli`이지만 이 예제에서는 해당 파일을 직접 컴파일한다.

### 정점 셰이더: 위치와 속성 계산

출력 구조체와 정점 셰이더는 다음과 같다.

```hlsl
struct VS_OUT
{
  float4 pos : SV_Position;
  float4 color : COLOR;
};

VS_OUT VS_Main(VS_IN input)
{
  VS_OUT output = (VS_OUT)0;

  output.pos = float4(input.pos, 1.f);
  output.color = input.color;

  return output;
}
```

정점 셰이더는 입력 정점의 출력 위치와 속성을 계산한다. 이번에는 위치에 `w = 1`을 붙이고 색상을 그대로 전달한다.

정점 셰이더가 `SV_Position`으로 출력하는 값은 **클립 공간의 위치**다. 이후 x, y, z를 w로 나누는 원근 나눗셈을 거쳐 정규화 장치 좌표가 된다.

이번에는 w가 1이므로 나눗셈 후에도 x, y, z가 유지된다. 이때 화면에 대응하는 좌표 범위는 x와 y가 `-1~1`, z가 `0~1`이다. 정점에 지정한 값은 픽셀 단위의 화면 좌표가 아니다.

카메라나 행렬 변환은 아직 사용하지 않는다. 입력한 위치를 바로 클립 공간 위치로 사용하는 단순한 셰이더다.

### 래스터화와 색상 보간

정점 셰이더를 거친 정점들로 삼각형이 구성되면, 래스터라이저는 삼각형이 화면의 어떤 샘플들을 덮는지 판단한다.

또한 정점의 색상 같은 속성을 삼각형 내부 위치에 맞게 보간해서 픽셀 셰이더에 전달한다.

```text
빨간 정점 근처 → 빨강의 영향이 큼
초록 정점 근처 → 초록의 영향이 큼
파란 정점 근처 → 파랑의 영향이 큼
삼각형 내부   → 정점 색상이 부드럽게 섞임
```

따라서 정점에는 색 세 개만 지정했어도 삼각형 내부에 그라데이션이 나타난다. 픽셀 셰이더에서 세 정점을 직접 찾아 색을 섞는 코드를 작성한 것은 아니다.

### 픽셀 셰이더: 출력 색상 계산

```hlsl
float4 PS_Main(VS_OUT input) : SV_Target
{
  return input.color;
}
```

픽셀 셰이더는 보간되어 들어온 색상을 그대로 반환한다. `SV_Target`은 이 반환값이 렌더 타깃에 출력할 색상임을 나타낸다.

## 6. PSO와 Root Signature

셰이더만 준비해서는 그리기 명령에 필요한 설정이 모두 갖춰지지 않는다. 입력 데이터 형식과 래스터화 방식, 출력 형식 등도 지정해야 한다.

PSO(Pipeline State Object)는 이러한 렌더링 설정을 묶은 객체다. 이번 `Shader` 클래스는 셰이더 컴파일과 PSO 생성까지 담당한다.

| 이번 PSO의 주요 항목 | 설정 내용 |
|---|---|
| VS / PS | 컴파일한 정점·픽셀 셰이더 |
| Input Layout | 위치와 색상의 데이터 형식 |
| Root Signature | 셰이더 리소스 연결 규칙 |
| Rasterizer / Blend | 기본 설정 |
| Depth / Stencil | 사용하지 않음 |
| Primitive Topology Type | 삼각형 계열 |
| Render Target | 1개, `R8G8B8A8_UNORM` |
| Sample Count | 1 |

`CreateGraphicsPipelineState()`로 PSO를 만든 뒤, 매 프레임 다음 코드로 선택한다.

```cpp
void Shader::Update()
{
  CMD_LIST->SetPipelineState(_pipelineState.Get());
}
```

이 함수는 셰이더를 다시 컴파일하지 않는다. 초기화 때 만들어 둔 PSO를 현재 명령 리스트에 설정한다.

Root Signature는 셰이더에 상수나 텍스처 같은 리소스를 어떤 방식으로 연결할지 정의한다. 이번에는 추가 셰이더 리소스가 없어 루트 매개변수가 없는 구성을 만든다.

**Input Layout은 정점 데이터 해석 규칙이고, Root Signature는 셰이더 리소스 연결 규칙**이다. 정점의 위치와 색상은 이번 코드에서 Input Assembler를 통해 전달된다.

## 7. Mesh::Render(): 그리기 명령 기록

```cpp
void Mesh::Render()
{
  CMD_LIST->IASetPrimitiveTopology(D3D_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
  CMD_LIST->IASetVertexBuffers(0, 1, &_vertexBufferView);
  CMD_LIST->DrawInstanced(_vertexCount, 1, 0, 0);
}
```

### 정점을 어떤 도형으로 묶을지 설정

`IA`는 Input Assembler를 뜻한다. 정점 데이터를 읽어 파이프라인에 공급하는 단계다.

`TRIANGLELIST`는 정점 세 개마다 독립적인 삼각형을 만드는 방식이다.

```text
정점 0, 1, 2 → 삼각형 하나
정점 3, 4, 5 → 다음 삼각형
```

PSO에서 삼각형 계열을 지정하고, 여기서는 그 계열 중 구체적으로 Triangle List 방식을 선택한다.

### 사용할 정점 버퍼 연결

```cpp
CMD_LIST->IASetVertexBuffers(0, 1, &_vertexBufferView);
```

| 인수 | 의미 |
|---|---|
| `0` | 시작 입력 슬롯 |
| `1` | 연결할 버퍼 개수 |
| `&_vertexBufferView` | 버퍼 주소·크기·간격 정보 |

슬롯은 정점 번호가 아니라 버퍼를 연결하는 자리다. 이번 Input Layout의 위치와 색상은 모두 입력 슬롯 0의 버퍼에서 읽는다.

### 그리기 명령 기록

```cpp
CMD_LIST->DrawInstanced(_vertexCount, 1, 0, 0);
```

| 인수 | 이번 값의 의미 |
|---|---|
| `_vertexCount` | 인스턴스 하나에 사용할 정점 3개 |
| `1` | 그릴 인스턴스 1개 |
| `0` | 시작 정점 위치 |
| `0` | 시작 인스턴스 위치 |

이번에는 인덱스 버퍼 없이 정점 버퍼의 정점을 순서대로 사용한다.

**`DrawInstanced()`는 그리기 명령을 기록한다.** GPU가 실제 작업을 수행하려면 명령 리스트를 종료하고 명령 큐에 제출해야 한다.

## 8. 렌더링 과정을 두 관점으로 보기

### CPU에서 한 프레임을 준비하는 흐름

`Game::Update()`는 다음 순서로 호출한다.

```cpp
GEngine->RenderBegin();

shader->Update();
mesh->Render();

GEngine->RenderEnd();
```

```text
RenderBegin()
  → 명령 할당자와 명령 리스트 Reset
  → 백 버퍼를 RENDER_TARGET 상태로 전환
  → Viewport와 Scissor Rect 설정
  → 배경색 지우기와 렌더 타깃 지정

Shader::Update()
  → 사용할 PSO 설정

Mesh::Render()
  → Primitive Topology 설정
  → 정점 버퍼 연결
  → DrawInstanced 명령 기록

RenderEnd()
  → 백 버퍼를 PRESENT 상태로 전환
  → 명령 리스트 Close
  → ExecuteCommandLists로 GPU에 제출
  → Present
  → Fence로 GPU 작업 완료 대기
  → 다음 백 버퍼 선택
```

이전 프로젝트에서 만들었던 프레임 흐름 사이에 PSO 설정과 삼각형 그리기 명령이 들어갔다.

### GPU에서 삼각형을 처리하는 흐름

제출된 그리기 명령은 개념적으로 다음 단계를 거친다.

```text
정점 버퍼 읽기
  → 정점 셰이더 실행
  → 정점들을 삼각형으로 조립
  → 클리핑·원근 나눗셈·화면 영역 변환
  → 래스터화와 색상 보간
  → 픽셀 셰이더 실행
  → 렌더 타깃에 결과 기록
```

CPU의 함수 호출 순서와 GPU의 그래픽 파이프라인은 구분해서 이해해야 한다. CPU는 사용할 데이터와 처리 방법을 설정하고 명령을 제출한다. GPU는 그 설정에 따라 정점과 픽셀을 처리한다.

이번 삼각형의 색이 만들어지는 과정은 다음과 같이 연결된다.

```text
CPU에서 위치와 색상 지정
  → 정점 버퍼에 복사
  → Input Layout에 따라 정점 읽기
  → 정점 셰이더가 위치와 색상 출력
  → 래스터화 과정에서 색상 보간
  → 픽셀 셰이더가 보간된 색상 반환
  → 백 버퍼에 기록한 결과를 Present
```

## 9. 예제 소스에서 확인할 점

제공된 소스에는 Root Signature를 생성하고 PSO 생성 정보에 넣는 코드는 있지만, 명령 리스트에 `SetGraphicsRootSignature()`로 설정하는 호출은 보이지 않는다.

**PSO를 설정하는 것과 명령 리스트에 Root Signature를 설정하는 것은 별도 작업**이다. 실행을 확인할 때 이 부분도 살펴봐야 한다. Microsoft 문서에서도 PSO 설정이 명령 리스트의 Root Signature를 변경하지 않는다고 설명한다.

또한 셰이더 컴파일이 실패하면 메시지 상자를 띄운 뒤에도 바이트코드에 접근하는 흐름이 이어진다. 셰이더 파일 경로나 문법 문제를 확인할 때는 컴파일 실패 이후의 접근과 오류 메시지도 함께 살펴본다.
