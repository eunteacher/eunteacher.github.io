# 컴퓨터 구조 Day 3 - 비트와 바이트, 메모리 주소

Day 2에서는 CPU 내부의 레지스터, 산술논리장치, 제어장치와 명령어 실행 흐름을 살펴봤다.

CPU가 메모리에서 데이터를 가져오려면 두 가지가 필요하다. 데이터가 어떤 형태로 담겨 있는지, 그리고 어디에 있는지 알아야 한다.

오늘의 목표는 **비트와 바이트의 관계를 이해하고, 메모리에 담긴 값과 그 값의 위치를 구분할 수 있는 것**이다.

## 컴퓨터는 정보를 0과 1의 조합으로 표현한다

컴퓨터는 서로 구분할 수 있는 두 상태를 이용해 정보를 표현한다. 이 두 상태를 각각 `0`과 `1`로 나타낸다.

여기서 정보를 표현하는 가장 작은 단위가 **비트(Bit)**다. 비트 하나는 `0` 또는 `1` 중 하나의 값을 가진다.

스위치 하나에 꺼짐과 켜짐이라는 두 상태가 있는 것처럼 생각하면 쉽다. 실제 장치에서는 전압이나 전하 등으로 상태를 구분하지만, 지금은 `0`과 `1`이라는 표현에 집중한다.

비트를 여러 개 묶으면 더 많은 경우를 구분할 수 있다.

| 비트 수 | 가능한 조합 | 조합의 수 |
|---|---|---|
| 1비트 | `0`, `1` | 2가지 |
| 2비트 | `00`, `01`, `10`, `11` | 4가지 |
| 3비트 | `000`부터 `111`까지 | 8가지 |

비트가 하나 늘 때마다 각 조합 뒤에 `0`이나 `1`을 붙일 수 있으므로 가능한 조합의 수는 두 배가 된다.

## 0과 1로 숫자를 나타내는 방법

우리가 평소 쓰는 수는 `0`부터 `9`까지 열 개의 숫자로 표현하는 **십진수**다. 반면 `0`과 `1` 두 개의 숫자로 수를 표현하는 방식을 **이진수(Binary Number)**라고 한다.

십진수에서 자릿값이 오른쪽부터 `1`, `10`, `100`으로 커지는 것처럼, 이진수에서는 `1`, `2`, `4`, `8`로 커진다.

예를 들어 이진수 `0101`을 살펴보자.

| 자릿값 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|
| 각 자리의 숫자 | 0 | 1 | 0 | 1 |

`1`이 있는 자리의 값을 더하면 `4 + 1 = 5`가 된다. 따라서 이진수 `0101`은 십진수 `5`를 나타낸다.

```text
이진수 0000 → 십진수 0
이진수 0001 → 십진수 1
이진수 0010 → 십진수 2
이진수 0011 → 십진수 3
이진수 0100 → 십진수 4
이진수 0101 → 십진수 5
```

오늘은 복잡한 변환보다 **각 자리의 값이 오른쪽부터 두 배씩 커진다**는 원리를 이해하면 된다.

## 8비트를 묶으면 1바이트다

비트 8개를 묶은 단위를 **바이트(Byte)**라고 한다.

```text
1바이트 = 8비트
```

예를 들어 다음은 1바이트 크기의 비트 조합이다.

```text
00000101
```

이를 음수가 없는 정수로 해석하면 `5`다. 앞에 붙은 `0`들은 숫자의 크기를 바꾸지 않는다.

8비트로 만들 수 있는 조합은 256가지다. 이 조합들을 음수가 없는 정수에 대응시키면 `0`부터 `255`까지 표현할 수 있다.

```text
00000000 → 0
00000001 → 1
...
11111111 → 255
```

**256은 표현할 수 있는 값의 개수이고, 이때 가장 큰 값은 255다.** `0`도 한 가지 값으로 포함되기 때문이다.

단, 모든 1바이트 데이터를 항상 정수로 해석하는 것은 아니다. 같은 비트 조합도 사용하는 규칙에 따라 숫자나 문자의 일부 등으로 해석할 수 있다. 오늘은 음수가 없는 정수를 예로 든다.

## 메모리를 바이트 단위의 칸으로 생각하기

일반적인 PC의 메모리는 **1바이트마다 위치를 구분할 수 있는 공간**으로 생각할 수 있다.

각 바이트 위치를 구분하는 번호를 **메모리 주소(Memory Address)**라고 한다. 집 주소로 집의 위치를 구분하듯, 메모리 주소로 데이터가 담긴 위치를 구분한다.

이해를 위해 주소를 십진수로 표시하고, 각 칸에 담긴 1바이트를 음수가 없는 정수로 읽어 보자.

| 메모리 주소 | 담긴 값 |
|---|---|
| 1000 | 10 |
| 1001 | 20 |
| 1002 | 30 |
| 1003 | 40 |

이 예시에서 `1000`과 `10`은 의미가 다르다.

- **주소 `1000`:** 데이터가 담긴 위치
- **값 `10`:** 그 위치에 담긴 내용

CPU가 주소 `1001`에 있는 값을 읽으면, 가져오는 데이터는 `20`이다.

주소가 연속으로 `1`씩 증가하는 이유는 이 예시에서 각 주소가 1바이트 위치를 가리키기 때문이다. **한 주소의 칸에 모든 크기의 데이터가 들어간다는 뜻은 아니다.**

## 하나의 데이터가 여러 바이트를 사용할 수 있다

데이터 하나가 반드시 1바이트인 것은 아니다. 크기가 4바이트인 정수 데이터라면 메모리에서 연속된 네 바이트를 사용한다.

시작 주소가 `1000`이라면 다음과 같은 범위를 차지한다.

```text
주소        1000   1001   1002   1003
           ┌──────┬──────┬──────┬──────┐
각 칸      │1바이트│1바이트│1바이트│1바이트│
           └──────┴──────┴──────┴──────┘
           ← 하나의 4바이트 정수 데이터 →
```

위 그림은 각 바이트에 어떤 값이 들어가는지보다, **하나의 데이터가 여러 주소에 걸쳐 저장될 수 있다는 점**을 보여준다.

이 데이터를 읽으려면 시작 위치뿐 아니라 몇 바이트를 읽을지, 읽은 비트들을 어떤 규칙으로 해석할지도 알아야 한다.

| 필요한 정보 | 의미 |
|---|---|
| 시작 주소 | 어디서부터 읽을 것인가 |
| 크기 | 몇 바이트를 읽을 것인가 |
| 해석 규칙 | 읽은 비트들을 어떤 값으로 볼 것인가 |

## CPU가 메모리를 읽는 흐름에 연결하기

Day 2에서 CPU가 메모리의 값을 레지스터로 가져온다고 설명했다. 오늘 배운 내용을 연결하면 다음과 같다.

```text
명령어에 따라 읽을 메모리 위치를 정한다.
    ↓
그 위치에서 필요한 크기만큼 데이터를 읽는다.
    ↓
읽은 데이터를 레지스터에 담아 처리에 사용한다.
```

예를 들어 “주소 `1001`에서 1바이트를 읽어 레지스터에 넣는다”는 작업이라면, 앞의 표에서는 값 `20`을 가져온다.

이 과정은 메모리 읽기의 기본 개념을 설명하기 위해 단순화한 것이다. 주소를 계산하거나 실제 데이터를 전달하는 세부 과정은 이후에 살펴본다.

## 핵심 정리

| 개념 | 기억할 내용 |
|---|---|
| 비트 | `0` 또는 `1`을 나타내는 정보의 최소 단위 |
| 이진수 | `0`과 `1`로 수를 표현하는 방식 |
| 바이트 | 8비트를 묶은 단위 |
| 메모리 주소 | 메모리에서 데이터의 위치를 구분하는 번호 |
| 데이터의 크기 | 데이터를 담거나 읽는 데 필요한 바이트 수 |

**데이터는 비트의 조합으로 표현되고, 일반적인 PC의 메모리는 바이트 단위로 주소를 구분한다.**

메모리를 이해할 때는 그 위치를 나타내는 주소와 그곳에 담긴 값을 구분해야 한다. 하나의 데이터는 크기에 따라 여러 바이트를 사용할 수 있다.
