# 컴퓨터 구조 Day 2 - CPU는 명령어를 어떻게 실행할까?

Day 1에서는 CPU가 명령어를 실행하고, 메모리는 실행에 필요한 명령어와 데이터를 담는다는 것을 배웠다.

이번에는 CPU 내부로 한 단계 들어가 본다. 오늘의 목표는 **CPU 내부의 세 구성 요소와 명령어 실행 흐름을 설명할 수 있는 것**이다.

## CPU 안에서도 역할이 나뉜다

CPU가 두 숫자를 더하려면 숫자를 잠시 둘 공간, 실제로 계산하는 장치, 각 작업을 진행하도록 지시하는 장치가 필요하다.

먼저 다음 세 가지 구성 요소를 살펴보자.

| 구성 요소 | 역할 |
|---|---|
| 레지스터 | 처리에 필요한 값이나 실행 정보를 잠시 보관 |
| 산술논리장치 | 계산과 논리 연산 수행 |
| 제어장치 | 명령어를 해석하고 각 부분의 동작을 제어 |

## 레지스터는 CPU 내부의 작은 보관 공간이다

CPU 내부에는 처리에 필요한 값과 정보를 잠시 담는 공간이 있다. 이것을 **레지스터(Register)**라고 한다.

예를 들어 메모리에 있는 두 숫자를 더할 때, CPU는 그 값을 내부 레지스터로 가져와 계산에 사용할 수 있다.

```text
메모리에 있는 값
    ↓
CPU 내부의 레지스터에 보관
    ↓
계산에 사용
```

레지스터와 RAM은 모두 정보를 담지만 위치와 용도가 다르다.

| 구분 | 레지스터 | 메모리(RAM) |
|---|---|---|
| 위치 | CPU 내부 | CPU와 구분되는 주기억장치 |
| 용량 | 매우 작음 | 레지스터보다 훨씬 큼 |
| 접근 속도 | 일반적으로 RAM보다 빠름 | 레지스터보다 느림 |
| 용도 | CPU가 바로 사용할 값과 실행 정보 보관 | 실행 중인 프로그램의 명령어와 데이터 보관 |

레지스터에는 계산할 숫자뿐 아니라 **다음에 실행할 명령어의 위치 같은 정보**도 담을 수 있다. 레지스터마다 맡는 역할이 다르지만, 오늘은 종류별 이름보다 기본 역할을 이해하는 데 집중한다.

## 산술논리장치는 실제 계산을 담당한다

CPU 내부에서 덧셈이나 뺄셈 같은 계산을 수행하는 부분을 **산술논리장치(ALU, Arithmetic Logic Unit)**라고 한다.

이름을 나누면 다음과 같다.

- **산술:** 덧셈과 뺄셈 같은 수 계산
- **논리:** AND, OR처럼 정해진 논리 규칙에 따른 연산

오늘은 논리 연산의 자세한 규칙보다, **ALU가 CPU 안에서 계산과 논리 연산을 담당한다**는 점에 집중한다.

Day 1에서 “CPU가 `10 + 20`을 계산한다”고 표현했다. CPU 내부에서 그 덧셈을 맡는 부분이 ALU다.

## 제어장치는 명령어를 해석하고 동작을 지시한다

덧셈을 하려면 값을 준비하고, 계산한 다음, 결과를 보관해야 한다. 각 부분이 필요한 일을 하도록 제어하는 부분을 **제어장치(CU, Control Unit)**라고 한다.

제어장치는 명령어를 해석해서 어떤 동작이 필요한지 파악하고, CPU 내부의 각 부분에 제어 신호를 보낸다.

덧셈 명령어라면 다음과 같은 동작을 지시한다고 생각하면 된다.

```text
계산에 사용할 값을 준비한다.
    ↓
ALU가 덧셈을 수행하도록 한다.
    ↓
결과를 레지스터에 보관하도록 한다.
```

**ALU는 계산을 수행하고, 제어장치는 그 동작이 이루어지도록 제어한다.**

## CPU는 가져오기, 해석하기, 실행하기를 반복한다

CPU가 명령어를 처리하는 기본 흐름은 세 단계로 이해할 수 있다.

| 단계 | 하는 일 | 정식 명칭 |
|---|---|---|
| 가져오기 | 메모리에서 실행할 명령어를 가져옴 | 인출(Fetch) |
| 해석하기 | 명령어가 어떤 작업을 요구하는지 파악 | 해독(Decode) |
| 실행하기 | 명령어에 따른 작업을 수행 | 실행(Execute) |

이렇게 명령어를 처리하는 반복 과정을 **명령어 사이클(Instruction Cycle)**이라고 한다.

```text
명령어 가져오기 → 해석하기 → 실행하기
       ↑                       │
       └──── 다음 명령어 ───────┘
```

위 흐름은 기본 원리를 이해하기 위해 단순화한 것이다. 실제 CPU는 더 복잡하게 동작하지만, 처음에는 이 흐름을 기준으로 이해하면 된다.

## 10 + 20으로 연결해 보기

이해를 위해 다음과 같은 명령어들이 있다고 가정하자. 실제 CPU의 명령어 문법이 아니라 역할을 보여주는 예시다. 레지스터 A와 B도 설명을 위해 붙인 이름이다.

```text
① 메모리의 숫자 10을 레지스터 A로 가져온다.
② 메모리의 숫자 20을 레지스터 B로 가져온다.
③ 두 레지스터의 값을 더해 결과를 레지스터 A에 넣는다.
④ 레지스터 A의 결과를 메모리에 저장한다.
```

CPU는 **①부터 ④까지 각 명령어를 가져오고, 해석하고, 실행한다.** 네 명령어 전체가 하나의 명령어 사이클인 것은 아니다.

③의 덧셈이 실행될 때는 다음처럼 역할이 연결된다.

1. **레지스터**에 계산할 `10`과 `20`이 담겨 있다.
2. **제어장치**가 덧셈 명령어에 맞게 필요한 동작을 지시한다.
3. **ALU**가 `10 + 20`을 계산한다.
4. **레지스터 A**가 계산 결과인 `30`을 보관한다.

이후 ④의 저장 명령어가 실행되면 결과가 메모리에 기록된다.

**모든 명령어가 계산을 하거나 메모리에 결과를 쓰는 것은 아니다.** 어떤 동작을 하는지는 명령어에 따라 달라진다.

## 핵심 정리

| 개념 | 기억할 내용 |
|---|---|
| 레지스터 | CPU 내부에서 값과 실행 정보를 잠시 담는 공간 |
| 산술논리장치(ALU) | 계산과 논리 연산을 수행하는 부분 |
| 제어장치(CU) | 명령어를 해석하고 각 부분의 동작을 제어하는 부분 |
| 명령어 사이클 | 명령어를 가져오고, 해석하고, 실행하는 반복 과정 |

**레지스터가 값을 담고, ALU가 계산하고, 제어장치가 동작을 제어한다.**

이 구성 요소들이 함께 일하면서 CPU는 명령어를 가져오고, 해석하고, 실행하는 과정을 반복한다.
