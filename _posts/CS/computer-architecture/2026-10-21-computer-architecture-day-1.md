# 컴퓨터 구조 Day 1 - CPU와 메모리, 프로그램이 실행되는 기본 흐름

컴퓨터에서 프로그램을 실행하면 CPU, 메모리, 저장장치가 함께 일한다. 각 장치의 역할을 구분하면 프로그램이 어떻게 실행되는지 이해하는 출발점이 된다.

오늘의 목표는 **CPU가 무엇을 처리하고, 메모리와 저장장치가 각각 무엇을 담는지 설명할 수 있는 것**이다.

## 컴퓨터는 명령어에 따라 데이터를 처리한다

컴퓨터에서 사용하는 숫자, 글자, 이미지 같은 정보를 **데이터(Data)**라고 한다.

데이터를 가지고 무엇을 할지 알려주는 지시는 **명령어(Instruction)**라고 한다.

두 숫자를 더하는 상황에서는 다음과 같이 구분할 수 있다.

| 구분 | 예시 |
|---|---|
| 데이터 | 숫자 `10`과 `20` |
| 명령어 | 두 숫자를 더하라는 지시 |
| 처리 결과 | `30` |

우리가 작성한 프로그램은 컴퓨터가 해야 할 일을 표현한 것이다. C++로 작성한 소스 코드는 빌드 과정을 거쳐 CPU가 실행할 수 있는 명령어가 포함된 실행 파일로 만들어진다.

CPU가 C++ 문장을 그대로 읽는 것은 아니다. CPU는 자신이 이해할 수 있는 형태의 명령어를 실행한다.

## CPU는 명령어를 읽고 실행한다

명령어를 읽고 그 지시에 따라 일을 처리하는 장치가 **중앙처리장치(CPU, Central Processing Unit)**다.

대표적으로 다음과 같은 일을 한다.

- **계산:** `10 + 20`을 계산한다.
- **비교:** 캐릭터의 체력이 `0`인지 확인한다.
- **실행 흐름 변경:** 비교 결과에 따라 다음에 실행할 명령어를 바꾼다.

게임에서 다음과 같은 규칙을 구현했다고 생각해 보자.

```text
체력이 0 이하라면 사망 처리를 한다.
그렇지 않다면 플레이를 계속한다.
```

CPU는 체력 값을 비교하고, 그 결과에 맞는 명령어를 실행한다. 스스로 게임 규칙을 이해해서 판단하는 것이 아니라, **프로그램에 담긴 명령어에 따라 처리하는 것**이다.

## 메모리는 실행에 필요한 명령어와 데이터를 담는다

실행 중인 프로그램의 명령어와 데이터를 담아 두는 공간이 **메모리(Memory)**다. 이 글에서 메모리는 **주기억장치인 RAM(Random Access Memory)**을 뜻한다.

게임을 실행하고 있다면 메모리에는 다음과 같은 내용이 들어갈 수 있다.

- 게임을 실행하는 명령어
- 캐릭터의 현재 체력과 위치
- 현재 사용 중인 아이템 정보

CPU는 메모리에 있는 명령어와 데이터를 읽어 일을 처리하고, 처리한 결과를 다시 메모리에 저장할 수 있다.

### RAM은 전원이 꺼지면 내용이 사라진다

RAM은 일반적으로 전원이 꺼지면 담겨 있던 내용이 사라진다. 이처럼 전원이 끊어지면 저장한 내용을 유지하지 못하는 성질을 **휘발성**이라고 한다.

따라서 게임 실행 중 체력이 바뀌었다고 해서 그 값이 자동으로 영구 보관되는 것은 아니다. 다음 실행에서도 필요한 정보라면 별도로 저장하는 과정이 필요하다.

## 저장장치는 프로그램과 파일을 보관한다

컴퓨터를 껐다 켜도 설치한 게임, 사진, 문서는 남아 있다. 이런 정보를 보관하는 장치가 **저장장치**다. SSD와 HDD가 대표적이며, **보조기억장치**라고도 한다.

전원이 꺼져도 저장한 내용이 유지되는 성질을 **비휘발성**이라고 한다.

메모리와 저장장치는 모두 정보를 담지만, 주된 역할과 성질이 다르다.

| 구분 | 메모리(RAM) | 저장장치(SSD·HDD) |
|---|---|---|
| 주된 역할 | 실행 중 필요한 명령어와 데이터를 담음 | 프로그램과 파일을 보관 |
| 접근 속도 | 일반적으로 SSD·HDD보다 빠름 | 일반적으로 RAM보다 느림 |
| 전원이 꺼지면 | 내용이 사라짐 | 내용이 유지됨 |
| 게임 예시 | 현재 플레이 중인 캐릭터의 체력 | 설치된 게임 파일, 저장된 진행 상황 |

일상적으로 말하는 게임의 저장 기능은, 다음에 이어서 플레이하는 데 필요한 정보를 저장장치에 기록하는 기능으로 이해할 수 있다. 여기서는 내 컴퓨터에 진행 상황을 저장하는 게임을 예로 든다.

## 프로그램을 실행하면 세 장치가 함께 일한다

설치된 게임을 실행하고, 피해를 받은 뒤 진행 상황을 저장하는 과정을 살펴보자.

### 1. 실행 전에는 게임 파일이 저장장치에 있다

게임 프로그램은 SSD 같은 저장장치에 파일로 보관되어 있다. 파일이 저장되어 있다는 것만으로 CPU가 그 게임의 명령어를 실행하고 있는 것은 아니다.

### 2. 실행에 필요한 내용이 메모리에 올라온다

게임을 실행하면 필요한 명령어와 데이터가 메모리로 옮겨진다. 이처럼 저장된 내용을 메모리로 가져오는 것을 **적재 또는 로드(Load)**라고 한다.

큰 게임의 모든 내용을 한꺼번에 가져온다는 뜻은 아니다. 우선 실행에 필요한 부분을 메모리로 가져온다고 이해하면 된다.

### 3. CPU가 명령어와 데이터를 읽고 처리한다

현재 체력이 `100`이고 피해량이 `20`이라고 가정하자.

CPU는 명령어에 따라 `100 - 20`을 계산한다. 계산 결과는 `80`이다.

### 4. 처리 결과를 메모리에 반영한다

계산 결과인 `80`을 현재 체력으로 메모리에 반영한다. 게임을 계속 진행하는 동안 이 값은 다시 사용되거나 바뀔 수 있다.

### 5. 저장 기능이 실행되면 필요한 정보를 저장장치에 기록한다

게임의 저장 기능이 실행되면, 나중에도 필요한 진행 정보를 저장장치에 기록한다.

**메모리의 값이 바뀌는 것과 저장 파일에 기록하는 것은 별개의 과정**이다.

## 기본 흐름으로 연결하기

```text
저장장치(SSD·HDD)
프로그램과 파일 보관
    ↓ 실행에 필요한 부분을 메모리로 가져옴
메모리(RAM)
실행할 명령어와 데이터 보관
    ↕ 명령어·데이터를 읽고 처리 결과를 기록
CPU
명령어 실행
```

위 그림은 각 장치의 역할을 이해하기 위해 단순화한 것이다. 실제 내부에는 이 과정을 돕는 장치와 세부 단계가 더 있지만, 첫 단계에서는 세 장치의 역할과 기본 흐름을 구분하는 데 집중한다.

## 핵심 정리

| 개념 | 기억할 내용 |
|---|---|
| 데이터 | 처리에 사용하는 숫자, 글자 등의 정보 |
| 명령어 | 컴퓨터가 무엇을 할지 알려주는 지시 |
| CPU | 명령어를 읽고 실행하는 장치 |
| 메모리(RAM) | 실행 중 필요한 명령어와 데이터를 담는 공간 |
| 저장장치 | 프로그램과 파일을 전원이 꺼져도 보관하는 장치 |

**게임은 SSD에 설치되어 있고, 실행에 필요한 내용은 RAM에 올라오며, CPU가 명령어를 실행한다.**

이 흐름을 이해하면 CPU, 메모리, 저장장치의 역할을 서로 연결해서 설명할 수 있다.
