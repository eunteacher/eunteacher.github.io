# 컴퓨터 구조 Day 4 - 캐시 메모리와 메모리 계층

Day 3에서는 메모리에 담긴 데이터와 그 위치를 나타내는 주소를 구분했다. CPU는 명령어에 따라 필요한 위치의 데이터를 읽어 처리에 사용한다.

그런데 CPU가 데이터를 사용할 때마다 RAM에서 가져와야 한다면 어떤 일이 생길까? CPU의 처리 속도에 비해 RAM에 접근하는 시간이 길기 때문에, 데이터를 기다리는 시간이 성능에 영향을 줄 수 있다.

오늘의 목표는 **캐시가 필요한 이유와 데이터를 여러 단계의 기억장치에 나누어 두는 이유를 설명할 수 있는 것**이다.

## 빠른 기억장치 하나만 사용하기 어려운 이유

Day 2에서 배운 레지스터는 CPU 내부에 있으며, CPU가 바로 사용할 값과 실행 정보를 담는다. 접근이 빠르지만 용량이 매우 작다.

RAM은 레지스터보다 훨씬 많은 내용을 담을 수 있지만, CPU가 접근하는 데 더 긴 시간이 걸린다. SSD나 HDD는 더 많은 내용을 보관하는 데 적합하지만 RAM보다 접근이 느리다.

빠른 기억장치는 일반적으로 같은 용량을 만드는 데 드는 비용이 높다. 따라서 컴퓨터 전체의 데이터를 레지스터처럼 빠른 공간에 모두 담는 방식은 현실적으로 어렵다.

대신 **작고 빠른 공간에는 곧 사용할 내용을 두고, 더 크고 느린 공간에는 더 많은 내용을 담는 방식**을 사용한다.

## 캐시는 RAM의 일부 내용을 가까이 보관한다

CPU가 사용할 가능성이 높은 명령어와 데이터의 일부를 RAM보다 빠르게 접근할 수 있는 곳에 보관한다. 이 역할을 하는 기억장치가 **캐시 메모리(Cache Memory)**다.

일반적인 현대 CPU에는 캐시가 내장되어 있다. 이 글에서는 CPU와 RAM 사이에서 접근 속도 차이를 줄여 주는 하드웨어 캐시를 다룬다.

```text
CPU가 사용할 명령어와 데이터
    ↓
필요한 내용이 캐시에 있으면 빠르게 가져옴
    ↓ 없으면
RAM 등 다음 단계에서 가져옴
```

캐시는 RAM 전체를 복사해 두는 공간이 아니다. 용량이 제한되어 있으므로 일부 내용만 담으며, 필요에 따라 보관하는 내용이 바뀐다.

일반적인 프로그램에서는 개발자가 매번 캐시에 넣고 뺄 데이터를 직접 지정하지 않아도 하드웨어가 이 과정을 관리한다.

## 필요한 내용이 캐시에 있는지에 따라 달라진다

설명을 위해 캐시가 한 단계만 있다고 가정하자.

CPU가 읽으려는 내용이 캐시에 있으면 캐시에서 가져올 수 있다. 이를 **캐시 적중(Cache Hit)**이라고 한다.

반대로 필요한 내용이 캐시에 없으면 다음 단계인 RAM에서 가져와야 한다. 이를 **캐시 미스(Cache Miss)**라고 한다.

| 상황 | 의미 | 기본 동작 |
|---|---|---|
| 캐시 적중 | 필요한 내용이 캐시에 있음 | 캐시에서 가져옴 |
| 캐시 미스 | 필요한 내용이 캐시에 없음 | 다음 단계에서 가져옴 |

캐시 미스가 발생해 RAM에서 내용을 가져오면, 일반적으로 해당 내용을 포함한 일정 크기의 묶음을 캐시에도 넣는다. 이후 같은 내용이나 가까운 위치를 다시 사용할 때 도움이 될 수 있다.

캐시가 가득 차 있다면 기존 내용 중 일부를 내보내고 새 내용을 넣어야 한다. 어떤 내용을 내보낼지 정하는 자세한 규칙은 오늘 다루지 않는다.

**캐시의 목적은 모든 접근을 빠르게 만드는 것이 아니라, 평균적으로 데이터를 기다리는 시간을 줄이는 것이다.**

## 작은 캐시가 도움이 되는 이유: 사용 위치가 몰리는 성질

프로그램은 메모리의 모든 위치를 매번 똑같이 사용하지 않는다. 최근 사용한 내용을 다시 사용하거나, 방금 사용한 위치 근처를 이어서 사용하는 경우가 많다.

이처럼 접근이 특정 시간이나 위치에 모이는 성질을 **지역성(Locality)**이라고 한다.

### 시간 지역성: 최근 사용한 내용을 다시 사용한다

한 번 사용한 내용을 가까운 시간 안에 다시 사용하는 성질을 **시간 지역성(Temporal Locality)**이라고 한다.

예를 들어 반복 작업에서는 같은 명령어를 여러 번 실행할 수 있다.

```text
같은 반복문 안의 명령어 실행
    ↓
다음 반복에서도 같은 명령어 실행
    ↓
그다음 반복에서도 같은 명령어 실행
```

이 명령어들이 캐시에 남아 있다면 RAM에서 매번 가져오는 일을 줄일 수 있다.

### 공간 지역성: 가까운 위치를 이어서 사용한다

사용한 메모리 위치의 주변을 이어서 사용하는 성질을 **공간 지역성(Spatial Locality)**이라고 한다.

예를 들어 배열은 같은 타입의 원소들이 메모리에 연속으로 놓이는 구조다. 배열의 값을 앞에서부터 읽는다면 가까운 위치에 차례로 접근한다.

```text
배열 원소: [0번] → [1번] → [2번] → [3번]
접근 위치: 메모리에서 가까운 위치를 차례로 읽음
```

캐시는 필요한 바이트 하나만 가져오기보다 주변 내용을 일정 크기로 묶어 가져오는 경우가 일반적이다. 이 전송·보관 단위를 **캐시 라인(Cache Line)**이라고 한다.

따라서 첫 번째 원소를 읽으면서 가까운 원소들이 캐시에 함께 들어오면, 이어지는 접근에서 도움이 될 수 있다. 다만 배열 전체가 한 번에 들어오거나 모든 접근이 반드시 적중한다는 뜻은 아니다.

| 지역성 | 핵심 | 예시 |
|---|---|---|
| 시간 지역성 | 같은 내용을 곧 다시 사용 | 반복문에서 같은 명령어 재실행 |
| 공간 지역성 | 가까운 위치를 이어서 사용 | 배열 원소를 순서대로 읽기 |

## 캐시도 여러 단계로 나뉜다

일반적인 CPU에서는 캐시를 여러 단계로 구성한다. 대표적으로 **L1, L2, L3 캐시**라고 부르며, L은 단계라는 뜻의 Level을 줄인 말이다.

기본적인 읽기 흐름은 다음처럼 이해할 수 있다.

```text
L1 캐시 확인
    ↓ 없으면
L2 캐시 확인
    ↓ 없으면
L3 캐시 확인
    ↓ 없으면
RAM에서 가져옴
```

일반적으로 L1은 가장 작고 빠르며, L2와 L3로 갈수록 용량이 커지고 접근 시간도 길어진다. 실제 단계 수와 구성은 CPU에 따라 다르다.

L1에 없더라도 L2나 L3에서 찾을 수 있다. 따라서 **캐시 한 단계에서 미스가 발생했다고 곧바로 RAM에 접근하는 것은 아니다.**

## 여러 기억장치를 단계별로 사용하는 것이 메모리 계층이다

속도, 용량, 비용이 다른 기억장치를 여러 단계로 구성하는 방식을 **메모리 계층(Memory Hierarchy)**이라고 한다.

지금까지 배운 장치들을 연결하면 다음과 같다.

```text
레지스터
    ↕
캐시(L1 → L2 → L3)
    ↕
메모리(RAM)
    ↕
저장장치(SSD·HDD)
```

위쪽으로 갈수록 일반적으로 접근이 빠르고 용량은 작다. 아래쪽으로 갈수록 접근은 느리지만 더 많은 내용을 담는 데 적합하다.

| 구성 요소 | 주된 역할 |
|---|---|
| 레지스터 | CPU가 바로 처리할 값과 실행 정보 보관 |
| 캐시 | 다시 사용할 가능성이 높은 명령어와 데이터의 일부 보관 |
| RAM | 실행 중 필요한 명령어와 데이터 보관 |
| SSD·HDD | 프로그램과 파일을 전원이 꺼져도 보관 |

이 그림은 역할과 단계의 관계를 보여준다. 모든 데이터가 사용될 때마다 저장장치부터 각 단계를 순서대로 거친다는 뜻은 아니다.

또한 캐시 미스만으로 SSD에서 데이터를 읽는 것도 아니다. 캐시에 없더라도 RAM에 있다면 RAM에서 가져온다. 실행 중 저장장치의 내용을 RAM으로 가져오는 관리는 이후 운영체제에서 자세히 다룬다.

## 핵심 정리

- **캐시:** RAM의 일부 내용을 빠르게 접근할 수 있도록 보관하는 공간
- **캐시 적중:** 필요한 내용이 확인한 캐시에 있는 상황
- **캐시 미스:** 필요한 내용이 확인한 캐시에 없어 다음 단계에서 찾아야 하는 상황
- **시간 지역성:** 최근 사용한 내용을 가까운 시간 안에 다시 사용하는 성질
- **공간 지역성:** 사용한 위치 근처를 이어서 사용하는 성질
- **메모리 계층:** 속도와 용량이 다른 기억장치를 여러 단계로 구성하는 방식

**CPU가 자주 사용할 내용을 작고 빠른 공간에 두면, 더 느린 기억장치에서 데이터를 기다리는 시간을 줄일 수 있다.**

캐시는 프로그램의 지역성을 활용하고, 메모리 계층은 속도와 용량을 함께 확보하기 위한 구조다.
