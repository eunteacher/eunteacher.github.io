# 서버 Day 02 - 스레드 생성과 실행 관리

C++에서는 `std::thread`를 사용해 새로운 스레드를 만들 수 있다. 실행할 함수를 전달하면 새 스레드가 그 함수를 실행하고, 기존 스레드는 다음 작업을 진행할 수 있다.

스레드를 사용할 때는 생성 방법뿐 아니라 **실행이 끝날 때까지 기다리는 방법과 객체를 정리하는 규칙**도 함께 알아야 한다.

## 스레드가 실행할 함수 준비하기

```cpp
#include <iostream>
#include <thread>

void HelloThread()
{
    std::cout << "Hello Thread\n";
}
```

`HelloThread()`는 일반 함수다. 어떻게 호출하느냐에 따라 이 함수를 실행하는 스레드가 달라진다.

```cpp
HelloThread();
```

일반적인 함수 호출에서는 현재 스레드가 함수를 실행하고, 함수가 끝나면 다음 코드로 넘어간다.

```cpp
std::thread t(HelloThread);
```

이렇게 작성하면 새 스레드가 `HelloThread()`를 실행한다. 호출한 스레드는 다음 코드로 진행할 수 있다.

여기서 `HelloThread`는 **실행할 함수를 전달한다**는 뜻이다. `HelloThread()`처럼 괄호를 붙이면 현재 위치에서 함수를 호출한다는 의미가 된다.

위 코드는 생성 방법을 보여주는 부분 코드다. 실제로는 생성한 스레드를 `join()`이나 `detach()`로 정리해야 한다.

## 빈 스레드 객체는 실행 흐름을 만들지 않는다

```cpp
std::thread t;
```

기본 생성한 `t`에는 연결된 스레드가 없다. 객체만 만들어졌으며, 새로운 실행 흐름은 아직 시작되지 않았다.

이후 다음과 같이 스레드를 생성해 연결할 수 있다.

```cpp
t = std::thread(HelloThread);
t.join();
```

오른쪽에서 새 스레드를 만들고, 그 스레드를 관리하는 책임을 `t`로 옮긴다. 이 과정은 복사가 아니라 **이동**이다.

`std::thread`는 복사할 수 없다. 대신 스레드를 관리하는 책임을 다른 객체로 옮길 수 있다.

단, `t`가 이미 정리하지 않은 스레드를 관리하고 있다면 새 스레드를 바로 대입하면 안 된다. `joinable()`이 `true`인 객체에 다른 스레드를 이동 대입하면 `std::terminate()`가 호출된다.

## get_id(): 스레드 식별자 확인하기

`get_id()`는 객체에 연결된 스레드의 식별자를 반환한다. 어떤 스레드인지 구분하거나 로그를 확인할 때 사용할 수 있다.

```cpp
std::thread t;
auto emptyId = t.get_id();

t = std::thread(HelloThread);
auto workerId = t.get_id();

t.join();
```

기본 생성 직후의 `emptyId`는 연결된 스레드가 없음을 나타내는 값이다. 스레드를 생성한 뒤의 `workerId`는 해당 스레드의 식별자다.

스레드 ID는 실행 순서나 우선순위를 뜻하지 않는다.

## hardware_concurrency(): 하드웨어의 동시 실행 능력 확인하기

```cpp
unsigned int count = std::thread::hardware_concurrency();
```

`hardware_concurrency()`는 **동시에 실행할 수 있는 하드웨어 스레드 수에 대한 힌트**를 반환한다.

일반적인 환경에서는 논리 프로세서 수에 해당하지만, 물리 코어 수와 반드시 같지는 않다. 예를 들어 물리 코어 하나가 두 개의 하드웨어 스레드를 제공하는 CPU도 있다.

값을 알 수 없으면 `0`을 반환할 수 있다. 또한 이 숫자가 프로그램에 가장 적합한 작업 스레드 수를 보장하는 것은 아니다. 작업이 계산을 많이 하는지, 입출력을 기다리는지에 따라서도 적절한 스레드 수는 달라진다.

이 함수는 정적 멤버 함수이므로, 특정 객체 대신 `std::thread::hardware_concurrency()` 형태로 호출하면 의미가 분명하다.

## joinable(): 정리할 스레드가 연결되어 있는지 확인하기

```cpp
if (t.joinable())
{
    t.join();
}
```

`joinable()`은 **객체에 아직 정리할 스레드가 연결되어 있는지** 확인한다.

| 상태 | joinable() |
|---|---|
| 기본 생성한 빈 객체 | false |
| 스레드 생성 후 아직 join이나 detach를 하지 않음 | true |
| 실행 함수는 끝났지만 아직 join하지 않음 | true |
| join 완료 | false |
| detach 완료 | false |

중요한 점은 **작업 함수가 끝나도 자동으로 `false`가 되지 않는다**는 것이다. 따라서 `joinable()`을 현재 실행 중인지 확인하는 용도로 사용하면 안 된다.

## join(): 스레드가 끝날 때까지 기다리기

```cpp
int main()
{
    std::thread t(HelloThread);

    t.join();

    std::cout << "Hello Main\n";
}
```

`join()`은 연결된 스레드의 실행이 끝날 때까지 **호출한 스레드가 기다리게 하는 함수**다.

위 코드에서는 메인 스레드가 `join()`을 호출하므로 작업 스레드의 종료를 기다린다.

```text
메인 스레드 : 작업 스레드 생성 → join에서 기다림 → Hello Main 출력
작업 스레드 : Hello Thread 출력 → 종료
```

`join()`이 스레드의 실행을 시작하는 것은 아니다. **스레드는 생성할 때 실행을 시작하고, `join()`은 종료를 기다린다.**

작업 스레드가 이미 끝났다면 종료 확인과 정리를 마친다. `join()`이 정상적으로 끝나면 해당 객체의 `joinable()`은 `false`가 된다.

### 스레드 객체를 정리해야 하는 이유

`std::thread` 객체가 `joinable()`인 상태로 소멸하면 `std::terminate()`가 호출된다. 일반적으로 프로그램이 비정상 종료되는 결과로 이어진다.

작업 함수가 이미 끝났더라도 아직 `join()`이나 `detach()`를 하지 않았다면 마찬가지다.

따라서 스레드를 만들 때는 **어디에서 기다리고 정리할지**도 함께 정해야 한다.

## 스레드 함수에 인자 전달하기

```cpp
void PrintNumber(int num)
{
    std::cout << num << "\n";
}

int main()
{
    std::thread t(PrintNumber, 10);
    t.join();
}
```

첫 번째 인자는 실행할 함수이고, 뒤에 오는 인자는 그 함수에 전달할 값이다.

```text
실행할 함수 : PrintNumber
전달할 값   : 10
```

새 스레드에서 `PrintNumber(10)`을 실행한다고 이해하면 된다. 이 예제에서는 정수 값을 복사해 전달한다.

## 여러 스레드를 먼저 만들고 모두 기다리기

다음은 스레드 10개에 각각 다른 숫자를 전달하는 전체 예제다. 별도 프로젝트 헤더 없이 실행할 수 있도록 표준 헤더와 `int`를 사용한다.

```cpp
#include <iostream>
#include <thread>
#include <vector>

void PrintNumber(int num)
{
    std::cout << num << "\n";
}

int main()
{
    std::vector<std::thread> threads;

    for (int i = 0; i < 10; i++)
    {
        threads.push_back(std::thread(PrintNumber, i));
    }

    for (int i = 0; i < 10; i++)
    {
        if (threads[i].joinable())
        {
            threads[i].join();
        }
    }

    std::cout << "Hello Main\n";
}
```

### 첫 번째 반복문: 스레드 생성

각 스레드에는 `0`부터 `9`까지 서로 다른 값을 전달한다.

```text
스레드 0 → PrintNumber(0)
스레드 1 → PrintNumber(1)
...
스레드 9 → PrintNumber(9)
```

각 스레드는 생성되면 실행을 시작할 수 있다. 따라서 첫 번째 반복문이 끝나기 전에 출력을 마친 스레드도 있을 수 있다.

`push_back()`에서는 생성한 `std::thread`의 관리 책임이 벡터 안으로 이동한다.

### 두 번째 반복문: 모든 스레드의 종료 대기

메인 스레드는 벡터의 각 스레드에 대해 `join()`을 호출한다.

`threads[0]`부터 기다린다고 해서 작업 스레드가 그 순서대로 실행되는 것은 아니다. **정해진 것은 메인 스레드가 기다리는 순서다.** 메인이 0번 스레드를 기다리는 동안 다른 스레드들도 실행될 수 있다.

생성과 대기를 서로 다른 반복문으로 나누었기 때문에 여러 작업이 함께 진행될 수 있다.

반대로 다음처럼 생성 직후 바로 기다리면 작업을 하나씩 끝내게 된다.

```cpp
for (int i = 0; i < 10; i++)
{
    std::thread t(PrintNumber, i);
    t.join();
}
```

이 경우 이전 작업 스레드가 끝나야 다음 작업 스레드를 만든다.

이 예제는 모든 스레드 생성이 성공하는 정상 흐름을 중심으로 설명한다. 실제 프로그램에서는 생성 도중 예외가 발생할 때도 이미 생성한 스레드가 안전하게 정리되도록 설계해야 한다.

## 출력 순서는 보장되지 않는다

스레드를 `0`부터 `9` 순서로 생성하더라도 숫자가 그 순서로 출력된다는 보장은 없다. 실행 순서는 운영체제의 스케줄링에 따라 달라질 수 있다.

또한 다음 문장에서는 숫자와 줄바꿈을 각각 스트림에 넣는다.

```cpp
std::cout << num << "\n";
```

여러 스레드의 출력이 그 사이에 끼어들 수 있으므로, 반드시 한 줄에 숫자 하나씩 출력된다고 가정하면 안 된다. 출력 한 묶음의 순서를 지키려면 별도의 동기화가 필요하다.

다만 전체 예제의 `Hello Main`은 모든 `join()`이 끝난 다음 출력한다. 따라서 **작업 스레드의 출력이 모두 끝난 뒤 `Hello Main`이 출력된다.**

## detach(): 스레드 객체와 실행 흐름 분리하기

```cpp
std::thread t(HelloThread);
t.detach();
```

`detach()`는 `std::thread` 객체와 실제 스레드의 연결을 끊는다. 분리된 스레드는 계속 실행할 수 있으며, 종료 시 실행 자원은 회수된다.

분리한 뒤에는 해당 객체로 `join()`할 수 없다. 또한 `detach()`는 프로그램을 계속 켜 두는 기능이 아니다. `main()`이 끝나 프로그램이 종료되면 분리된 스레드의 작업 완료를 기다려 주지 않는다.

분리된 스레드가 지역 변수에 접근한다면, 그 변수가 먼저 사라지지 않도록 수명도 관리해야 한다.

`detach()` 역시 `joinable()`이 `true`인 객체에서 호출해야 한다. 기본 생성한 빈 객체에서 호출하면 `std::system_error` 예외가 발생한다.

| 함수 | 역할 | 호출 후 객체 상태 |
|---|---|---|
| join() | 연결된 스레드가 끝날 때까지 기다림 | 연결된 스레드 없음 |
| detach() | 객체와 스레드의 연결을 끊음 | 연결된 스레드 없음 |

처음 스레드를 사용할 때는 `join()`으로 작업 완료를 기다리는 흐름부터 익히는 것이 좋다. 스레드의 생성 시점과 종료를 기다리는 시점을 구분하면, 여러 작업이 언제 함께 진행되고 언제 다음 단계로 넘어가는지 이해할 수 있다.
