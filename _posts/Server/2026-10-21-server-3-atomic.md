# 서버 Day 03 - 공유 데이터와 원자적 연산

여러 스레드가 같은 변수를 수정하면 어떤 일이 생길까? 값을 증가시키는 작업과 감소시키는 작업을 같은 횟수만큼 수행하더라도, 동기화가 없다면 올바른 결과를 보장할 수 없다.

이번에는 **공유 데이터에 동시에 접근할 때 생기는 문제와 `atomic`으로 이를 해결하는 방법**을 알아본다.

## 같은 작업도 실행 방식에 따라 결과가 달라진다

먼저 일반 정수 변수로 생각해 보자.

```cpp
int sum = 0;
```

`Add()`는 `sum`을 100만 번 증가시키고, `Sub()`는 100만 번 감소시킨다.

```cpp
void Add()
{
    for (int i = 0; i < 1'000'000; i++)
    {
        sum++;
    }
}

void Sub()
{
    for (int i = 0; i < 1'000'000; i++)
    {
        sum--;
    }
}
```

숫자에 들어간 작은따옴표는 자릿수를 구분하는 표시다. `1'000'000`은 `1000000`과 같은 값이다.

```cpp
Add();
Sub();
```

이렇게 순서대로 호출하면 증가 작업이 모두 끝난 다음 감소 작업을 한다. 따라서 최종 결과는 `0`이다.

반면 두 스레드로 실행하면 같은 변수에 동시에 접근할 수 있다.

```cpp
std::thread t1(Add);
std::thread t2(Sub);

t1.join();
t2.join();
```

일반 정수에 동기화 없이 `sum++`와 `sum--`를 수행하면 **데이터 레이스(Data Race)**가 발생한다.

C++에서 데이터 레이스는 **정의되지 않은 동작**이다. 결과가 항상 `0`이라고 보장할 수 없고, 단순히 숫자가 조금 틀리는 문제로만 생각해서도 안 된다.

## 한 줄의 코드가 하나의 작업을 뜻하지는 않는다

`sum++`는 개념적으로 다음 과정으로 이해할 수 있다.

```cpp
int temp = sum;
temp = temp + 1;
sum = temp;
```

감소도 마찬가지다.

```cpp
int temp = sum;
temp = temp - 1;
sum = temp;
```

실제 기계어는 컴파일러와 CPU에 따라 달라질 수 있지만, **값을 읽고 수정한 뒤 저장하는 사이에 다른 스레드가 끼어들 수 있다**는 것이 핵심이다.

예를 들어 `sum`이 `0`일 때 다음 상황을 생각할 수 있다.

| 순서 | 증가 스레드 | 감소 스레드 |
|---|---|---|
| 1 | sum에서 0 읽기 | |
| 2 | | sum에서 0 읽기 |
| 3 | 계산한 1 저장 | |
| 4 | | 계산한 -1 저장 |

증가와 감소를 한 번씩 했지만, 마지막 저장이 앞선 변경을 덮어썼다.

이 표는 변경이 사라지는 원리를 설명하기 위한 예시다. 데이터 레이스가 있는 C++ 프로그램의 결과가 이 표대로만 나온다는 뜻은 아니다.

## 동기화는 공유 데이터에 접근하는 규칙이다

**동기화(Synchronization)는 여러 스레드가 공유 데이터에 안전하게 접근하도록 실행 순서나 접근 방식을 조정하는 것**이다.

모든 작업의 순서를 하나하나 고정해야 하는 것은 아니다. 이번 코드에서는 증가와 감소 중 어느 쪽이 먼저 실행되든, **각 변경이 사라지지 않고 반영되면 된다.**

이를 위한 방법 중 하나가 `atomic`이다.

## atomic은 연산의 원자성을 보장한다

```cpp
#include <atomic>

std::atomic<int> sum = 0;
```

**원자성(Atomicity)**이란 다른 스레드의 관점에서 하나의 연산을 쪼개지지 않는 작업처럼 다루는 성질이다.

증가에는 다음 코드를 사용할 수 있다.

```cpp
sum.fetch_add(1);
```

현재 값을 읽고, `1`을 더하고, 저장하는 과정을 하나의 원자적 연산으로 수행한다. 두 스레드의 증가 작업이 겹쳐도 한쪽 변경이 사라지지 않는다.

감소는 다음 두 표현 중 하나를 사용할 수 있다.

```cpp
sum.fetch_add(-1);
```

```cpp
sum.fetch_sub(1);
```

`fetch_add()`와 `fetch_sub()`는 **변경 전 값**을 반환한다. 이번 코드에서는 반환값을 사용하지 않고 값만 수정한다.

또한 `sum`이 정수형 `atomic`이라면 `sum++`와 `sum--`도 원자적 연산이다. 원자성을 위해 반드시 `fetch_add()`만 써야 하는 것은 아니다.

## atomic을 적용한 전체 코드

다음은 별도의 프로젝트 헤더 없이 실행할 수 있도록 표준 헤더와 `int`를 사용한 예제다.

```cpp
#include <atomic>
#include <iostream>
#include <thread>

std::atomic<int> sum = 0;

void Add()
{
    for (int i = 0; i < 1'000'000; i++)
    {
        sum.fetch_add(1);
    }
}

void Sub()
{
    for (int i = 0; i < 1'000'000; i++)
    {
        sum.fetch_sub(1);
    }
}

int main()
{
    Add();
    Sub();

    std::cout << sum.load() << "\n";

    std::thread t1(Add);
    std::thread t2(Sub);

    t1.join();
    t2.join();

    std::cout << sum.load() << "\n";
}
```

`load()`는 원자 변수의 현재 값을 읽는 함수다.

첫 번째 출력은 순차 실행 결과이므로 `0`이다. 두 번째 출력도 각 증가·감소가 원자적으로 반영되고, 두 스레드가 모두 끝난 뒤 값을 읽으므로 `0`이다.

여기서 `atomic`과 `join()`의 역할을 구분하면 이해하기 쉽다.

| 기능 | 역할 |
|---|---|
| atomic의 증가·감소 연산 | 공유 값의 변경이 사라지지 않도록 처리 |
| join() | 작업 스레드가 끝날 때까지 기다림 |

**`join()`만으로 작업 도중 발생하는 데이터 레이스를 막을 수는 없다.** 일반 정수에 대한 동시 수정을 끝낸 뒤 기다리더라도, 이미 발생한 잘못된 접근이 해결되는 것은 아니다.

## 원자 연산 여러 개가 자동으로 하나가 되지는 않는다

다음 코드는 주의해야 한다.

```cpp
sum.store(sum.load() + 1);
```

`store()`는 원자 변수에 값을 저장하는 함수다. 여기서 읽기와 저장은 각각 원자적이지만, **읽기 → 계산 → 저장 전체가 하나의 원자적 연산은 아니다.**

그 사이에 다른 스레드가 값을 바꾸면 변경이 사라질 수 있다. 개별 접근은 원자적이므로 일반 정수 예제와 같은 데이터 레이스는 없지만, 의도한 증가 결과는 보장되지 않는다.

증가 작업 전체를 하나의 원자적 연산으로 수행하려면 다음처럼 작성해야 한다.

```cpp
sum.fetch_add(1);
```

마찬가지로 여러 변수의 값을 함께 바꾸는 복잡한 작업은 변수 하나를 `atomic`으로 선언했다고 전부 안전해지지 않는다. 이런 경우에는 뮤텍스 같은 다른 동기화 방법도 필요하다.

## atomic에도 비용은 있다

여러 스레드가 같은 원자 변수를 계속 수정하면 CPU 사이에서 해당 값을 조율하는 비용이 발생한다. 그래서 스레드를 늘려도 빨라지지 않거나 오히려 느려질 수 있다.

다만 `atomic`은 무조건 느리다고 단정할 수는 없다. 연산 종류와 하드웨어, 같은 값에 접근하는 스레드 수에 따라 성능이 달라진다.

공유 변수의 단순한 증가·감소도 동기화가 필요하다. `atomic`을 사용할 때는 **개별 연산의 원자성과 여러 연산으로 구성된 작업 전체의 안전성을 구분하는 것**이 중요하다.
