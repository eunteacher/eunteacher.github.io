이전 글에서는 여러 비트를 하나의 정수로 보고 사칙연산을 수행했다. 이번에는 정수를 구성하는 비트 각각을 직접 이동하거나 조합한다.

비트 연산은 단순히 곱셈이나 나눗셈을 빠르게 수행하기 위한 도구가 아니다. 데이터의 일부 필드를 추출하거나, 여러 상태를 하나의 정수에 저장하고, 특정 상태만 켜거나 끄는 작업에 사용된다.

이번 글에서는 **시프트 과정에서 어떤 비트가 사라지는지**, 그리고 **비트 마스크를 이용해 원하는 상태만 제어하는 방법**을 확인한다.

## 비트를 이동하는 시프트 명령어

시프트(Shift)는 레지스터나 메모리 값의 비트를 지정한 횟수만큼 왼쪽 또는 오른쪽으로 이동한다.

| 명령어 | 이동 방향 | 새로 생긴 빈 비트 | 특징 |
| :--- | :---: | :---: | :--- |
| `SHL` / `SAL` | 왼쪽 | 0 | 두 명령어는 같은 동작 |
| `SHR` | 오른쪽 | 0 | 논리 오른쪽 시프트 |
| `SAR` | 오른쪽 | 기존 최상위 비트 | 산술 오른쪽 시프트 |

왼쪽 시프트에는 논리와 산술 동작의 차이가 없으므로 `SHL`과 `SAL`은 같은 명령으로 동작한다. 반면 오른쪽 시프트는 빈 상위 비트를 무엇으로 채울지에 따라 `SHR`과 `SAR`이 구분된다.

### `SHL`: 왼쪽으로 이동

```nasm
mov al, 0b00010110
shl al, 1
```

```text
이동 전: 0001 0110
이동 후: 0010 1100
         ←       0
```

모든 비트가 왼쪽으로 한 칸 이동하고 새로 생긴 최하위 비트에는 0이 들어간다. 범위 밖으로 밀려난 최상위 비트는 AL에 남지 않는다.

### `SHR`: 오른쪽을 0으로 채우기

```nasm
mov al, 0b10010110
shr al, 1
```

```text
이동 전: 1001 0110
이동 후: 0100 1011
         0       →
```

`SHR`은 오른쪽으로 비트를 옮기고 새로 생긴 최상위 비트를 0으로 채운다. 따라서 값을 부호 없는 정수로 다룰 때 적합하다.

### `SAR`: 기존 최상위 비트 유지

```nasm
mov al, 0b10010110
sar al, 1
```

```text
이동 전: 1001 0110
이동 후: 1100 1011
         1       →
```

`SAR`은 기존 최상위 비트를 새로 생긴 상위 비트에 복제한다. 2의 보수로 표현된 음수의 부호 비트를 유지하면서 오른쪽으로 이동할 때 사용한다.

## 시프트 과정에서 사라지는 비트

시프트는 값의 위치를 옮기는 연산이지, 모든 비트를 보존한 채 이동하는 연산이 아니다.

```nasm
mov eax, 0x12345678
shl eax, 8
shr eax, 8
```

각 단계에서 EAX는 다음과 같이 변한다.

```text
처음        : 0x12345678
SHL EAX, 8 : 0x34567800
SHR EAX, 8 : 0x00345678
```

첫 번째 시프트에서 상위 바이트 `0x12`가 32비트 범위 밖으로 밀려나 사라졌다. 이후 오른쪽으로 다시 이동해도 이미 잃어버린 바이트는 복구되지 않는다.

시프트로 값을 분리하거나 합칠 때는 목적지의 비트 폭을 넘어가는 데이터가 없는지 먼저 확인해야 한다.

## 시프트와 곱셈·나눗셈의 관계

값이 표현 범위를 벗어나지 않는다면 왼쪽 시프트는 2의 거듭제곱을 곱한 것과 같은 비트 결과를 만든다.

```nasm
mov eax, 3
shl eax, 3       ; 3 × 2³ = 24
```

부호 없는 정수의 오른쪽 시프트는 2의 거듭제곱으로 나눈 몫과 같은 결과를 만든다.

```nasm
mov eax, 25
shr eax, 3       ; 25 ÷ 8 = 3, 나머지는 버려짐
```

하지만 시프트를 일반적인 곱셈과 나눗셈의 완전한 대체로 생각하면 안 된다.

- 왼쪽 시프트에서 범위를 벗어난 비트는 사라진다.
- `SHR`은 상위 비트를 0으로 채우므로 부호 있는 음수에 사용할 수 없다.
- `SAR`은 음수에서 아래쪽 방향으로 값을 내리는 효과가 있어, 0 방향으로 절삭하는 C++의 부호 있는 정수 나눗셈과 결과가 다를 수 있다.

예를 들어 일반적인 2의 보수 환경에서 `-3`을 비교하면 다음과 같다.

```text
C++의 -3 / 2 : -1
SAR로 1비트  : -2
```

고수준 언어에서 `x * 8`을 무조건 `x << 3`으로 직접 바꿀 필요도 없다. 현대 컴파일러는 값의 타입과 주변 코드를 고려해 적절한 명령어를 선택한다. 시프트는 수동 성능 최적화보다 비트 위치 이동, 필드 추출, 비트 패킹처럼 비트 구조 자체를 다룰 때 사용하는 것이 의도를 분명하게 보여준다.

## `AND`, `OR`, `XOR`, `NOT`

논리 연산은 같은 위치에 있는 비트들을 각각 비교해 결과를 만든다.

| 연산 | 결과가 1이 되는 조건 | 대표 용도 |
| :--- | :--- | :--- |
| `AND` | 두 비트가 모두 1 | 필요한 비트만 남기기 |
| `OR` | 하나 이상의 비트가 1 | 원하는 비트 켜기 |
| `XOR` | 두 비트가 서로 다름 | 원하는 비트 반전 |
| `NOT` | 입력 비트가 0 | 모든 비트 반전 |

같은 두 값을 이용해 각 연산 결과를 비교해 본다.

```text
AL: 1001 0101
BL: 0111 1100
```

### `AND`: 두 값에서 공통으로 켜진 비트만 남기기

```nasm
mov al, 0b10010101
mov bl, 0b01111100
and al, bl              ; AL = 00010100
```

```text
  1001 0101
& 0111 1100
-----------
  0001 0100
```

### `OR`: 둘 중 하나라도 켜진 비트 남기기

```nasm
mov al, 0b10010101
mov bl, 0b01111100
or al, bl               ; AL = 11111101
```

```text
  1001 0101
| 0111 1100
-----------
  1111 1101
```

### `XOR`: 서로 다른 비트만 남기기

```nasm
mov al, 0b10010101
mov bl, 0b01111100
xor al, bl              ; AL = 11101001
```

```text
  1001 0101
^ 0111 1100
-----------
  1110 1001
```

### `NOT`: 모든 비트 뒤집기

```nasm
mov al, 0b10010101
not al                  ; AL = 01101010
```

```text
~ 1001 0101
------------
  0110 1010
```

`NOT`은 피연산자 크기 안에 있는 모든 비트를 반전한다. AL에 적용하면 8비트를, EAX에 적용하면 32비트를 반전한다.

## 비트 마스크로 상태 관리하기

비트 마스크(Bit Mask)는 특정 비트 위치를 선택하기 위해 사용하는 값이다. 각 비트를 하나의 상태로 약속하면 한 정수 안에 여러 참·거짓 상태를 저장할 수 있다.

게임 캐릭터의 상태 세 가지를 AL의 하위 비트에 배치해 본다.

```nasm
STATE_STUNNED      equ 1 << 0
STATE_POISONED     equ 1 << 1
STATE_INVINCIBLE   equ 1 << 2
CLEAR_STUNNED_MASK equ 0xFF ^ STATE_STUNNED
```

```text
비트 위치:  2            1          0
상태     : Invincible  Poisoned   Stunned
마스크   :    100         010        001
```

`equ`는 이름에 상수 값을 부여하는 NASM 지시어다. `1 << n`을 사용하면 비트 하나만 켜진 마스크를 만들 수 있다.

### 상태 켜기: `OR`

```nasm
xor eax, eax

or al, STATE_STUNNED     ; AL = 0000 0001
or al, STATE_POISONED    ; AL = 0000 0011
```

OR 연산은 마스크에서 1인 비트를 켜고, 다른 비트의 기존 상태는 유지한다.

### 상태 끄기: 반전된 마스크와 `AND`

특정 비트를 끄려면 해당 위치만 0이고 나머지는 1인 마스크가 필요하다.

```text
STATE_STUNNED      : 0000 0001
CLEAR_STUNNED_MASK: 1111 1110
```

```nasm
and al, CLEAR_STUNNED_MASK    ; Stunned 비트만 0으로 변경
```

AND 연산에서 마스크가 1인 위치는 기존 값을 유지하고, 0인 위치는 꺼진다. `CLEAR_STUNNED_MASK`는 8비트 범위에서 Stunned 마스크를 반전해 만든 값이다.

### 상태 반전: `XOR`

```nasm
xor al, STATE_INVINCIBLE
```

XOR은 마스크가 1인 위치만 반전한다. 따라서 같은 명령을 한 번 실행하면 Invincible 상태가 켜지고, 다시 실행하면 꺼진다.

## `TEST`로 값을 바꾸지 않고 상태 확인하기

특정 비트가 켜져 있는지 확인하려고 `AND`를 사용하면 원본 값도 변경된다.

```nasm
and al, STATE_POISONED
```

값을 유지하면서 결과만 Flags에 반영하려면 `test`를 사용한다.

```nasm
test al, STATE_POISONED
```

`TEST`는 내부적으로 두 피연산자의 비트 AND 결과를 계산하지만 그 결과를 AL에 저장하지 않는다.

- Poisoned 비트가 꺼져 있으면 AND 결과가 0이므로 ZF = 1
- Poisoned 비트가 켜져 있으면 AND 결과가 0이 아니므로 ZF = 0
- AL에 저장된 전체 상태 값은 유지됨

다음 글에서는 이 ZF를 조건 점프와 연결해 실제 실행 흐름을 나눈다.

```nasm
test al, STATE_POISONED
jz NOT_POISONED
```

여기서는 `jz`가 ZF가 1일 때 이동한다는 흐름만 확인하고, 조건 분기의 세부 규칙은 다음 글에서 다룬다.

## 비트 연산과 Flags

비트 연산도 RFLAGS에 영향을 준다.

- `AND`, `OR`, `XOR`, `TEST`는 결과에 따라 ZF, SF, PF를 갱신하고 CF와 OF를 0으로 만든다.
- `NOT`은 Flags를 변경하지 않는다.
- 시프트에서 마지막으로 범위 밖으로 밀려난 비트는 CF에 저장된다.
- 1비트 시프트에서 OF는 명령어별 규칙에 따라 갱신되지만, 여러 비트를 한 번에 이동했을 때 OF는 정의되지 않는다.

따라서 비트 연산 직후 조건 분기를 사용한다면 어떤 명령이 어떤 플래그를 변경했는지 확인해야 한다.

## `xor eax, eax`와 `mov eax, 0`

자기 자신과 XOR한 결과는 항상 0이다.

```nasm
xor eax, eax
```

EAX에 값을 쓰면 RAX의 상위 32비트도 0이 되므로 이 명령은 RAX 전체를 0으로 만든다. `xor eax, eax`는 인코딩이 짧고, 현대 x86 CPU가 이전 EAX 값에 대한 의존성을 끊는 zero idiom으로 인식할 수 있어 레지스터 초기화에 자주 사용된다.

하지만 다음 명령과 모든 효과가 같은 것은 아니다.

```nasm
mov eax, 0
```

두 명령 모두 RAX를 0으로 만들지만 Flags에 미치는 영향이 다르다.

- `xor eax, eax`: 연산 결과에 따라 Flags를 변경
- `mov eax, 0`: Flags를 변경하지 않음

직전에 계산한 Flags를 이후 조건 분기에서 사용해야 한다면 중간에 `xor`를 실행해서는 안 된다. 단순히 “항상 `mov`보다 빠르다”는 이유로 바꾸기보다 Flags 보존 여부와 코드의 의도를 함께 고려해야 한다.

## XOR을 두 번 적용하면 원래 값으로 돌아온다

XOR에는 같은 마스크를 두 번 적용하면 원래 값으로 복구되는 성질이 있다.

```text
(A XOR B) XOR B = A
```

```nasm
mov al, 0b10010101
mov bl, 0b01111100

xor al, bl              ; AL = 11101001
xor al, bl              ; AL = 10010101
```

이 성질은 데이터 변환이나 암호 알고리즘의 구성 요소로 사용될 수 있다. 하지만 고정된 값과 단순히 XOR하는 것만으로는 패턴을 쉽게 분석할 수 있으므로 안전한 암호화가 되지 않는다.

## 전체 실습 코드

```nasm
%include "io64.inc"

STATE_STUNNED      equ 1 << 0
STATE_POISONED     equ 1 << 1
STATE_INVINCIBLE   equ 1 << 2
CLEAR_STUNNED_MASK equ 0xFF ^ STATE_STUNNED

section .text
global CMAIN

CMAIN:
    ; 시프트 과정의 데이터 손실 확인
    mov eax, 0x12345678
    shl eax, 8               ; EAX = 0x34567800
    shr eax, 8               ; EAX = 0x00345678

    ; 논리 연산 결과 비교
    mov al, 0b10010101
    mov bl, 0b01111100
    and al, bl               ; AL = 00010100

    mov al, 0b10010101
    or al, bl                ; AL = 11111101

    mov al, 0b10010101
    xor al, bl               ; AL = 11101001

    mov al, 0b10010101
    not al                   ; AL = 01101010

    ; 캐릭터 상태 초기화 및 설정
    xor eax, eax
    or al, STATE_STUNNED
    or al, STATE_POISONED

    ; Poisoned 상태 확인: AL은 유지되고 ZF만 결과에 맞게 갱신
    test al, STATE_POISONED

    ; Stunned 상태 끄기
    and al, CLEAR_STUNNED_MASK

    ; Invincible 상태 반전
    xor al, STATE_INVINCIBLE

    ; 마지막 상태를 확인한 다음 실행 환경에 0 반환
    xor rax, rax
    ret
```

마지막 `xor rax, rax`는 AL에 만든 상태 값과 직전 연산의 Flags를 모두 변경한다. 디버거에서는 각 비트 연산 직후 값을 확인해야 한다.

## 디버거에서 확인할 것

1. EAX를 왼쪽으로 8비트 이동할 때 상위 바이트 `0x12`가 사라지는가?
2. 다시 오른쪽으로 이동해도 원래 값으로 돌아오지 않는가?
3. 같은 AL과 BL에 AND, OR, XOR를 적용했을 때 예상한 비트 결과가 나오는가?
4. `NOT AL`이 AL의 8비트만 반전하는가?
5. OR 연산으로 기존 상태를 유지하면서 원하는 비트만 켤 수 있는가?
6. 반전된 마스크와 AND로 원하는 비트만 끌 수 있는가?
7. XOR을 반복할 때 지정한 상태 비트만 켜졌다 꺼지는가?
8. `TEST` 실행 전후 AL은 같고 ZF만 상태에 맞게 바뀌는가?
9. `xor eax, eax`와 `mov eax, 0`이 Flags에 서로 다른 영향을 주는가?

## 다음 학습: Flags를 이용한 조건 분기

이번 글에서 확인한 핵심은 다음과 같다.

- `SHL`과 `SAL`은 같은 왼쪽 시프트 명령이다.
- `SHR`은 빈 상위 비트를 0으로 채우고 `SAR`은 기존 최상위 비트를 복제한다.
- 범위 밖으로 밀려난 비트는 원래 레지스터에서 사라진다.
- 시프트를 곱셈과 나눗셈처럼 해석하려면 값의 부호와 표현 범위를 고려해야 한다.
- `AND`, `OR`, `XOR`, `NOT`으로 원하는 비트를 남기거나 켜고 끌 수 있다.
- `TEST`는 원본을 변경하지 않고 비트 상태를 Flags에 반영한다.
- `xor eax, eax`는 자주 쓰이는 초기화 방식이지만 Flags를 변경한다.
- 단순한 XOR만으로는 안전한 암호화를 만들 수 없다.
