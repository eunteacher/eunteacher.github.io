# [어셈블리] 변수 선언과 메모리 접근 방식

프로그램이 실행될 때의 메모리 구조와 변수를 선언하는 방법(Data vs BSS), 그리고 변수의 **주소값**과 **실제 데이터**를 구분하여 접근하는 방법에 대해 정리

---

## 1. 소스 코드 (Source Code)

데이터 세그먼트(`.data`)와 BSS 세그먼트(`.bss`)에 변수를 선언하고, `mov` 명령어를 통해 해당 변수의 주소와 값을 가져오는 예제

```nasm
%include "io64.inc"

section .text
global CMAIN
CMAIN:
    mov rbp, rsp        ; 디버깅을 위한 스택 프레임

    ; 주소 vs 값
    mov rax, a          ; 'a' 변수의 [주소값]을 rax에 복사
    mov rax, [a]        ; 'a' 변수 주소 안에 있는 [실제 값]을 rax에 복사

    ; 크기 지정 복사
    mov al, [a]         ; a의 값 중 1바이트만 가져와서 al에 저장

    ; 메모리에 값 쓰기 (크기 지정 필수)
    mov [a], byte 0x55  ; a의 주소에 1바이트 크기로 0x55 저장
    mov [a], word 0x6666; a의 주소에 2바이트 크기로 0x6666 저장
    mov [a], cl         ; 레지스터(cl) 크기에 맞춰서 저장됨

    xor rax, rax
    ret

; 초기화된 전역 변수
section .data
    a db 0x11                   ; 1 byte
    b dw 0x2222                 ; 2 byte
    c dd 0x33333333             ; 4 byte
    d dq 0x4444444444444444     ; 8 byte

; 초기화되지 않은 전역 변수
section .bss
    e resb 10                   ; 10 byte 공간 확보 (값은 0)
```

## 2. 이론 정리 (Study Notes)

### 1) 프로세스 메모리 구조 (Memory Layout)

프로그램이 실행될 때 메모리는 데이터의 성격에 따라 다음과 같이 영역이 나눔

* **Text (Code):** 실행할 기계어 코드가 저장되는 영역 (읽기 전용)
* **Data:** **초기화된** 전역 변수 및 정적(Static) 변수
* **BSS:** **초기화되지 않은** 전역 변수 및 정적 변수 (자동으로 0으로 초기화됨)
* **Heap:** 프로그래머가 동적으로 할당하는 영역 (런타임에 크기 결정)
* **Stack:** 함수 호출 시 지역 변수, 매개 변수 등이 저장되는 임시 영역

### 2) Data 영역 vs BSS 영역
두 영역 모두 전역 변수를 저장하지만, **초기값의 유무**에 따라 구분

| 구분 | Data Section | BSS Section |
| :--- | :--- | :--- |
| **내용** | 초기값(`10`, `Hello` 등)이 있는 변수 | 초기값이 없는(`0`으로 시작할) 변수 |
| **실행 파일 크기** | 변수의 크기만큼 파일 용량을 차지함 | 파일 용량을 차지하지 않음 (크기 정보만 기록) |
| **이유** | 초기값 데이터를 저장해야 하므로 | 어차피 0이므로, "100MB 공간 줘"라는 정보만 있으면 됨 |

> **핵심:** 초기화되지 않은 거대한 배열을 Data 영역에 넣으면 실행 파일(.exe) 크기가 불필요하게 커짐. 이를 방지하기 위해 BSS 영역을 사용

### 3) 변수 선언 문법
어셈블리에서 변수(메모리 공간)를 선언하는 단위

* **초기화 데이터 (`section .data`)**
  * `db` (Define Byte): 1바이트
  * `dw` (Define Word): 2바이트
  * `dd` (Define Double word): 4바이트
  * `dq` (Define Quad word): 8바이트
* **비초기화 데이터 (`section .bss`)**
  * `resb` (Reserve Byte): 바이트 단위 예약
  * `resw`, `resd`, `resq`: 워드, 더블워드, 쿼드워드 단위 예약

### 4) 메모리 접근 지정자 (`[]`)
변수 이름과 대괄호의 차이를 이해하는 것이 중요

* **`mov rax, a`**: 변수 `a`의 **메모리 주소(Address)**를 가져옴 (예: `0x403010`)
* **`mov rax, [a]`**: 주소 `a`가 가리키는 곳의 **실제 값(Value)**을 가져옴 (예: `0x11`)
* **크기 지정자 (Size Directives):** 메모리에 상수를 넣을 때는 크기를 명시
  * `mov [a], 0x55` (X) -> 몇 바이트를 써야 할지 몰라 에러 발생
  * `mov [a], byte 0x55` (O) -> 1바이트만큼 씀

## 3. 종합 의견 (Review)

* **주소 vs 값의 혼동:** C언어의 포인터 개념과 유사. `a`는 포인터(주소), `[a]`는 역참조(값)라고 생각하면 이해가 쉬움. 어셈블리에서는 이 둘을 명확히 구분해서 코딩하기
* **실행 파일 최적화:** 왜 굳이 Data와 BSS를 나누는지 이해하는 것이 중요. 실행 파일(HDD 저장)의 크기를 줄이고, 로딩 속도를 높이기 위한 설계
* **메모리 오염 주의:** `mov [a], word 0x6666` 처럼 `a`는 1바이트(`db`)로 선언했는데 2바이트(`word`)를 써버리면, 인접한 메모리(`b` 변수 등)를 덮어쓰는 문제가 발생할 수 있음

## 4. 심화 학습 (Deep Dive)

### 1) 리틀 엔디안 (Little Endian)
x86 아키텍처는 데이터를 메모리에 저장할 때 **리틀 엔디안** 방식을 사용. 이는 **낮은 자릿수(하위 바이트)가 낮은 주소에 먼저 저장**되는 방식

* **예시:** `mov [a], dword 0x12345678` 명령을 실행했을 때
* **우리 생각:** `12` `34` `56` `78` 순서로 저장될 것 같지만...
* **실제 메모리:** `78` `56` `34` `12` 순서로 뒤집혀서 저장
> **Tip:** 메모리 창(Memory View)에서 값을 확인할 때 숫자가 거꾸로 보이는 이유가 바로 이 때문

### 2) C/C++ 자료형과 어셈블리 크기 비교
C++ 공부를 병행한다면 아래 표를 통해 매핑해보면 이해가 쉬움

| 단위 | 크기 | 어셈블리 명령어 | C/C++ 자료형 (Windows 기준) |
| :--- | :--- | :--- | :--- |
| **Byte** | 1 byte | `db` / `al` | `char`, `bool` |
| **Word** | 2 byte | `dw` / `ax` | `short` |
| **Dword** | 4 byte | `dd` / `eax` | `int`, `long`, `float` |
| **Qword** | 8 byte | `dq` / `rax` | `long long`, `double`, `포인터` |
