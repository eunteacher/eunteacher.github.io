# [어셈블리] 데이터 표현과 레지스터 기초

컴퓨터가 데이터를 저장하는 방식(진법, 단위)과 CPU가 연산을 위해 사용하는 고속 저장 공간인 **레지스터(Register)**의 구조에 대해 정리

---

## 1. 소스 코드 (Source Code)

데이터 이동 명령어(`mov`)를 통해 레지스터의 크기별(64bit ~ 8bit) 사용법을 확인하는 코드

```nasm
%include "io64.inc"

section .text
global CMAIN
CMAIN:
    mov rbp, rsp        ; 디버깅을 위한 스택 프레임 설정

    ; 데이터 이동 (mov dst, src)
    mov eax, 0x1234     ; EAX(32bit)에 16진수 1234 저장
    mov rbx, 0x12345678 ; RBX(64bit)에 값 저장
    mov cl, 0xff        ; CL(8bit)에 값 저장

    ; 부분 레지스터의 동작 확인
    ; RAX가 0x...1234 라고 가정할 때,
    mov al, 0x00
    ; AL은 RAX의 가장 하위 1바이트를 의미함.
    ; 따라서 AL을 00으로 바꾸면 RAX의 값은 0x...1200 으로 변경됨.

    mov rax, rdx        ; 레지스터끼리의 데이터 이동

    xor rax, rax        ; 종료
    ret
```

## 2. 이론 정리 (Study Notes)

작성한 코드의 핵심 개념인 데이터 표현 방식과 레지스터의 구조에 대한 정리

### 1) 컴퓨터의 데이터 표현 (Data Representation)
컴퓨터는 전기 신호의 On/Off를 통해 데이터를 저장하므로, 모든 정보를 **0과 1**로 처리

* **비트 (Bit):** 정보 처리의 최소 단위 (0 또는 1)
    * `0`: False (꺼짐)
    * `1`: True (켜짐)
* **바이트 (Byte):** 8개의 비트가 모인 단위 (1 Byte = 8 Bit). 영문자 한 글자를 저장할 수 있는 크기
* **진법 (Number Systems):**
    * **2진수 (Binary):** 컴퓨터의 언어. 접두사 `0b` 사용 (예: `0b1010`)
    * **16진수 (Hexadecimal):** 2진수를 사람이 보기 편하게 축약한 형태. 접두사 `0x` 사용 (예: `0x1234`)
    * **관계:** 2진수 4자리(4bit)는 16진수 1자리와 정확히 대응 (예: `0b1001 0101` = `0x95`)
* **2의 보수 (Two's Complement):** 최상위 비트(MSB)를 부호 비트로 사용하여 **음수**를 표현하는 방식

### 2) 데이터 크기 단위 (Data Size)
어셈블리어에서 데이터를 다룰 때 사용하는 크기 단위

| 단위 (Unit) | 크기 (Bit) | 크기 (Byte) | 설명 |
| :--- | :--- | :--- | :--- |
| **Byte** | 8 bit | 1 byte | `db` (Define Byte) |
| **Word** | 16 bit | 2 byte | `dw` (Define Word) |
| **Dword** (Double Word) | 32 bit | 4 byte | `dd` (Define Dword), int형 크기 |
| **Qword** (Quad Word) | 64 bit | 8 byte | `dq` (Define Qword), 포인터 크기 |

### 3) 컴퓨터 하드웨어 구조 (Hardware Hierarchy)
데이터 저장 장치는 CPU(ALU)와의 거리에 따라 속도와 용량이 반비례

1.  **레지스터 (Register):** CPU 내부의 초고속 저장소. 연산에 필요한 데이터를 임시 저장
2.  **메인 메모리 (RAM):** 실행 중인 프로그램이 로드되는 공간. 휘발성 메모리
3.  **하드 디스크 (HDD/SSD):** 데이터 영구 저장소. 용량은 크지만 속도가 가장 느림

### 4) 레지스터 (Register) 상세
CPU가 연산을 수행하기 위해 사용하는 가장 빠른 데이터 임시 저장 공간

#### ① 범용 레지스터 (General Purpose Registers)
64비트 환경에서 주로 사용되는 레지스터들(`R`로 시작)
* **RAX (Accumulator):** 산술 연산, 함수 반환값 저장
* **RBX (Base):** 메모리 주소 지정을 위한 베이스 주소 저장
* **RCX (Counter):** 반복문(`loop`)의 카운터로 사용
* **RDX (Data):** 연산의 보조 데이터, I/O 등에 사용

#### ② 레지스터의 부분 사용 (Register Hierarchy)

64비트 레지스터(RAX)는 전체를 다 쓸 수도 있고, 필요에 따라 일부분만 쪼개서 사용

| 명칭 | 사용 크기 | 설명 |
| :--- | :--- | :--- |
| **RAX** | 64 bit (8 Byte) | 전체 공간 사용 |
| **EAX** | 32 bit (4 Byte) | RAX의 하위 4바이트 (Extended AX) |
| **AX** | 16 bit (2 Byte) | RAX의 하위 2바이트 |
| **AH** | 8 bit (1 Byte) | AX의 상위 1바이트 (High) |
| **AL** | 8 bit (1 Byte) | AX의 하위 1바이트 (Low) |

> **주의:** 이들은 서로 다른 레지스터가 아니라 **하나의 공간을 공유**. 즉, `AL`(작은 컵)에 값을 넣으면 `RAX`(큰 물통)의 전체 값도 영향을 받음

## 3. 종합 의견 (Review)

* **진법 변환의 중요성:** 디버깅 시 메모리 주소나 값은 대부분 16진수로 표시. 2진수 4비트가 16진수 1자리가 된다는 규칙(`1111` = `F`)
* **레지스터의 포함 관계:** `mov al, 0x00`을 수행했을 때 왜 `rax`의 값 전체가 바뀌는 것처럼 보이는지 이해가 필요. 이는 별개의 변수가 아니라, **큰 상자(RAX) 안에 들어있는 작은 상자(AL)**를 건드렸기 때문. 이 구조를 이해하는 것이 레지스터 조작의 핵심
