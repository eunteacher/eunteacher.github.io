첫 번째 글에서는 어셈블리 파일에 명령어, 지시어, 레이블, 매크로가 함께 들어 있다는 것을 확인했다. 이제 CPU가 명령어를 실행할 때 값을 어디에 보관하는지 살펴본다.

이번 글의 목표는 레지스터의 이름을 모두 외우는 것이 아니다. **레지스터에 저장된 비트 패턴을 16진수로 읽고, RAX의 일부를 수정했을 때 전체 값이 어떻게 달라지는지 디버거로 확인하는 것**이 핵심이다.

## CPU가 연산할 값을 보관하는 곳

레지스터(Register)는 CPU 내부에 있는 작은 저장 공간이다. CPU는 명령어를 실행하는 동안 연산에 사용할 값, 메모리 주소, 중간 결과 등을 레지스터에 보관한다.

x86-64에는 `RAX`, `RBX`, `RCX`, `RDX`를 비롯한 여러 범용 레지스터가 있다. 이름에는 과거부터 이어진 대표 용도가 남아 있지만, 일반적인 코드에서 반드시 그 용도로만 사용해야 하는 것은 아니다.

다만 일부 명령어와 호출 규약은 특정 레지스터에 역할을 부여한다. 이전 글에서 프로그램을 마치기 전 `RAX`를 0으로 만든 것도 현재 실행 환경에서 반환값을 전달하는 약속과 관련이 있다.

이번 실습에서는 여러 레지스터를 넓게 살펴보는 대신 `RAX` 하나에 집중한다.

## 같은 값을 표현하는 여러 방법

10진수, 2진수, 16진수는 서로 다른 데이터가 아니다. 같은 값을 사람이 읽기 좋은 방식으로 다르게 표기한 것이다.

```text
10진수: 18
2진수 : 0001 0010
16진수: 0x12
```

2진수는 각 비트를 직접 보여주지만 값이 조금만 커져도 길어진다. 16진수 한 자리는 2진수 네 자리와 정확히 대응하기 때문에 비트 패턴을 짧게 표현할 수 있다.

```text
2진수 : 0001 0010 1010 1111
16진수:    1    2    A    F
```

그래서 어셈블리 코드, 디버거의 레지스터 창, 메모리 주소에서는 16진수를 자주 사용한다. 접두사 `0x`는 뒤의 값이 16진수라는 뜻이다.

## 값을 다루는 크기

비트(Bit)는 0 또는 1 하나를 나타내는 가장 작은 단위이고, 8비트가 모이면 1바이트(Byte)가 된다. x86 계열에서는 데이터 크기를 다음과 같은 이름으로 표현한다.

| 단위 | 비트 | 바이트 | RAX에서 접근하는 이름 |
| :--- | ---: | ---: | :--- |
| Byte | 8비트 | 1바이트 | `AL` 또는 `AH` |
| Word | 16비트 | 2바이트 | `AX` |
| Dword | 32비트 | 4바이트 | `EAX` |
| Qword | 64비트 | 8바이트 | `RAX` |

여기서 `RAX`, `EAX`, `AX`, `AH`, `AL`은 서로 독립된 다섯 개의 레지스터가 아니다. 하나의 64비트 레지스터에서 서로 다른 범위를 가리키는 이름이다.

## RAX의 일부분에 접근하기

각 이름이 가리키는 범위를 단순하게 나타내면 다음과 같다.

```text
비트 위치  63                              32 31              16 15       8 7        0
          ┌──────────────────────────────────┬──────────────────┬──────────┬──────────┐
RAX       │                         전체 64비트                                      │
          └──────────────────────────────────┴──────────────────┴──────────┴──────────┘
EAX                                             └──────── 하위 32비트 ────────────────┘
AX                                                                    └─ 하위 16비트 ─┘
AH                                                                    └ 8~15비트 ┘
AL                                                                               └ 0~7비트 ┘
```

- `RAX`: 전체 64비트
- `EAX`: RAX의 하위 32비트
- `AX`: RAX의 하위 16비트
- `AH`: AX의 상위 8비트, 즉 RAX의 8~15번 비트
- `AL`: RAX의 가장 낮은 8비트

부분 레지스터에 값을 쓰면 해당 범위가 RAX에도 반영된다. 다만 **EAX에 값을 쓰는 경우에는 RAX의 상위 32비트도 0으로 초기화**된다는 점이 중요하다.

## 부분 레지스터의 변화를 확인하는 실습

다음 코드를 디버거에서 한 줄씩 실행하면서 RAX 값을 관찰한다.

```nasm
%include "io64.inc"

section .text
global CMAIN

CMAIN:
    mov rax, 0x1122334455667788

    mov al, 0xAA
    mov ah, 0xBB
    mov ax, 0xCCCC
    mov eax, 0xDDDDDDDD

    mov rbx, 0x1234
    mov rax, rbx

    xor rax, rax
    ret
```

처음에는 `RAX` 전체에 `0x1122334455667788`을 저장한다. 이후 부분 레지스터를 차례대로 수정하면 RAX의 값은 다음과 같이 변한다.

| 실행한 명령어 | 실행 후 RAX | 관찰할 점 |
| :--- | :--- | :--- |
| `mov rax, 0x1122334455667788` | `0x1122334455667788` | 전체 64비트 설정 |
| `mov al, 0xAA` | `0x11223344556677AA` | 하위 8비트만 변경 |
| `mov ah, 0xBB` | `0x112233445566BBAA` | 8~15번 비트만 변경 |
| `mov ax, 0xCCCC` | `0x112233445566CCCC` | 하위 16비트 변경 |
| `mov eax, 0xDDDDDDDD` | `0x00000000DDDDDDDD` | 하위 32비트를 기록하고 상위 32비트를 0으로 초기화 |

`mov eax, 0xDDDDDDDD`의 결과는 다른 부분 레지스터 쓰기와 다르다. `AL`이나 `AX`에 쓸 때는 지정한 범위 밖의 비트가 유지되지만, 32비트 범용 레지스터인 `EAX`에 쓰면 대응하는 64비트 레지스터의 상위 절반이 0이 된다.

이 동작을 알고 있으면 디버깅 중 RAX의 상위 값이 갑자기 사라진 이유를 찾는 데 도움이 된다.

## `mov`는 값을 복사한다

`mov`의 기본 형태는 다음과 같다.

```nasm
mov 목적지, 원본
```

예제의 다음 두 줄은 먼저 `RBX`에 값을 넣고, 그 값을 `RAX`로 복사한다.

```nasm
mov rbx, 0x1234
mov rax, rbx
```

실행 후에는 RAX와 RBX가 모두 `0x1234`를 가진다. 이름은 `move`이지만 원본 레지스터의 값이 사라지는 것은 아니다.

또한 두 피연산자의 크기는 서로 맞아야 한다.

```nasm
mov rax, rbx    ; 64비트끼리 복사
mov eax, ebx    ; 32비트끼리 복사
mov al, bl      ; 8비트끼리 복사
```

## 레지스터에는 자료형이 없다

레지스터가 저장하는 것은 정수나 문자의 의미가 아니라 비트 패턴이다. 같은 8비트 패턴도 어떻게 해석하느냐에 따라 다른 값으로 읽을 수 있다.

```text
비트 패턴       : 1111 1111
16진수 표기     : 0xFF
부호 없는 8비트 : 255
부호 있는 8비트 : -1
```

마지막 해석은 음수를 표현하는 2의 보수(Two's Complement) 방식을 기준으로 한다. 중요한 점은 레지스터 안의 비트가 바뀐 것이 아니라, **명령어와 출력 방식이 같은 비트를 다르게 해석했다는 것**이다.

C++에서는 변수의 자료형이 값의 크기와 해석 방식을 표현해 주지만, 어셈블리에서는 어떤 크기의 명령어를 사용하고 그 결과를 어떻게 해석할지 프로그래머가 더 직접적으로 결정해야 한다.

## 디버거에서 확인할 것

코드를 한 번에 실행하기보다 각 `mov` 명령에서 중단하며 다음 내용을 확인해 본다.

1. `AL`을 변경했을 때 RAX의 마지막 두 자리만 바뀌는가?
2. `AH`는 RAX의 어느 두 자리를 변경하는가?
3. `AX`를 변경해도 RAX의 상위 48비트는 유지되는가?
4. `EAX`에 값을 쓴 뒤 RAX의 상위 32비트는 어떻게 되는가?
5. `mov rax, rbx`를 실행한 뒤에도 RBX의 원래 값이 유지되는가?

16진수 두 자리가 1바이트를 나타낸다는 점을 함께 생각하면, 어떤 비트 범위가 바뀌었는지 레지스터 창에서 쉽게 찾을 수 있다.
