# [어셈블리] 문자열 저장 방식과 리틀 엔디안

메모리에 연속된 데이터를 저장하는 방법(배열, 문자열)과, 1바이트를 넘는 데이터를 메모리에 배치하는 순서인 **엔디안(Endianness)**의 개념에 대해 정리

---

## 1. 소스 코드 (Source Code)

데이터 정의(`db`, `dd`)를 통해 배열과 문자열을 만들고, 4바이트 데이터가 메모리에 거꾸로 저장되는 현상을 확인하는 코드

```nasm
%include "io64.inc"

section .text
global CMAIN
CMAIN:
    mov rbp, rsp        ; 디버깅을 위한 스택 프레임

    PRINT_STRING msg    ; 문자열 출력

    xor rax, rax
    ret

section .data
    ; 1. 데이터의 해석
    ; a db 0x11
    ; 메모리에 있는 0x11은 16진수로 보면 0x11, 10진수로 보면 17이 됨
    ; 즉, 데이터는 그대로지만 관점에 따라 해석이 달라짐

    ; 2. 배열 (Array)
    a db 0x11, 0x11, 0x11, 0x11 ; 콤마(,)로 구분하여 연속된 데이터를 저장

    ; 3. 문자열 (String)
    msg db 'Hello World', 0x00
    ; 문자가 연속적으로 이어진 배열
    ; 끝은 항상 NULL(0x00)로 마무리해야 함
    ; 아스키 코드: 0x48(H), 0x65(e), ... , 0x00(NULL)

    ; 4. 엔디안 (Endianness)
    b dd 0x12345678
    ; 실제 메모리 저장 순서: 0x78 0x56 0x34 0x12 (거꾸로 저장됨)
```

---
## 2. 이론 정리 (Study Notes)

### 1) 배열과 문자열 (Array & String)
* **배열:** 동일한 크기의 데이터가 메모리에 연속적으로 나열된 구조
  * `db 0x11, 0x22` 처럼 콤마(`,`)로 이어 쓰면 연속된 메모리 주소에 저장됨
* **문자열:** 문자의 배열. 컴퓨터는 문자를 **아스키 코드(ASCII)**라는 숫자 규칙으로 저장함
  * **Null Termination:** 문자열의 끝을 알리기 위해 마지막에 반드시 `0x00`을 넣어야 함. `PRINT_STRING` 같은 함수들은 `0x00`을 만날 때까지 출력함

### 2) 엔디안 (Endianness)

메모리와 같은 1차원 공간에 **1바이트를 넘는 데이터**(Word, Dword 등)를 배열하는 순서

| 구분 | 빅 엔디안 (Big Endian) | 리틀 엔디안 (Little Endian) |
| :--- | :--- | :--- |
| **저장 방식** | **큰 단위(MSB)**가 낮은 주소(앞)에 저장 | **작은 단위(LSB)**가 낮은 주소(앞)에 저장 |
| **순서** | 사람이 읽는 순서와 같음 | 사람이 읽는 순서와 반대 (거꾸로) |
| **예시 (0x12345678)** | `12 34 56 78` | `78 56 34 12` |
| **사용처** | 네트워크 프로토콜 (TCP/IP), UNIX 서버 | **Intel/AMD CPU (x86, x64)**, Windows |
| **장점** | 숫자 비교(대소 비교)에 유리 | 캐스팅(형변환), 산술 연산에 유리 |

> **핵심:** 우리가 사용하는 x86 아키텍처(Intel, AMD)는 **리틀 엔디안**을 사용하므로 메모리 뷰에서 값이 거꾸로 보임

---

## 3. 종합 의견 (Review)

* **메모리 뷰의 혼란:** 디버깅 시 `0x12345678`을 넣었는데 메모리 창에는 `78 56 34 12`로 보여서 당황할 수 있음. 이는 오류가 아니라 **리틀 엔디안** 방식 때문임을 명심해야 함
* **문자열의 끝:** C/C++나 어셈블리에서 문자열 뒤에 `0x00`(Null)을 깜빡하면, 프로그램은 멈추지 않고 쓰레기 값을 계속 출력하다가 메모리 오류로 뻗어버릴 수 있음

---

## 4. 심화 학습 (Deep Dive)

### 1) 리틀 엔디안이 '캐스팅'에 유리한 이유
데이터의 주소 위치를 변경하지 않고도 작은 단위로 형변환이 가능함

* **상황:** 4바이트 `0x00000012`를 1바이트로 읽고 싶을 때
* **리틀 엔디안:** `12 00 00 00` (시작 주소가 그대로 값 `12`를 가리킴 → 주소 수정 없이 바로 읽으면 됨)
* **빅 엔디안:** `00 00 00 12` (시작 주소는 `00`을 가리킴 → 실제 값을 읽으려면 주소를 뒤로 이동시켜야 함)

### 2) 네트워크 프로그래밍 시 주의점 (Network Byte Order)
네트워크(인터넷)는 표준적으로 **빅 엔디안**을 사용함.
따라서 내 컴퓨터(리틀 엔디안)에서 서버(빅 엔디안)로 데이터를 보낼 때는 반드시 **엔디안 변환 함수**(`htons`, `htonl` 등)를 사용하여 순서를 뒤집어서 보내야 함
