# [어셈블리] 배열 선언과 메모리 주소 접근 방식

데이터의 묶음인 배열(Array)을 어셈블리에서 선언하는 방법과, 반복문을 통해 각 요소(Element)에 접근하는 주소 연산(`Base + Index * Scale`) 방식을 정리

---

## 1. 소스 코드 (Source Code)

`db`와 `times`를 이용한 배열 선언, 그리고 반복문을 이용해 배열의 요소를 순회하는 두 가지 방법(주소 직접 가산 vs 인덱스 레지스터 활용)을 구현한 예제

```nasm
%include "io64.inc"

section .text
global CMAIN
CMAIN:
    mov rbp, rsp        ; 디버깅을 위한 스택 프레임 설정

    ; 1. 배열과 주소의 이해
    ; mov rax, a -> 'a'라는 변수의 [주소값]이 rax에 들어감
    ; mov rax, [a] -> 주소 'a'에 있는 [실제 값]이 rax에 들어감

    ; [Manual Debug] 배열 요소 직접 접근해보기
    PRINT_HEX 1, [a]        ; a[0]
    NEWLINE
    PRINT_HEX 1, [a + 1]    ; a[1] (1바이트 뒤)
    NEWLINE
    PRINT_HEX 1, [a + 2]    ; a[2]
    NEWLINE

    ; 2. 연습문제: a 배열(1byte 단위)의 모든 데이터 출력
    ; 방법 1) 인덱스 레지스터를 직접 1씩 증가
    xor ecx, ecx            ; 인덱스(i) = 0

LABEL_PRINT_A:
    PRINT_HEX 1, [a + ecx]  ; [Base + Index]
    NEWLINE
    inc ecx                 ; i++
    cmp ecx, 5              ; 배열 길이(5)와 비교
    jne LABEL_PRINT_A


    ; 3. 연습문제: b 배열(2byte 단위)의 모든 데이터 출력
    ; b는 dw(2byte) 타입이므로 주소 계산 시 주의 필요

    ; 방법 1) 주소 포인터를 직접 증가시키는 방식
    mov ebx, 0              ; 오프셋 레지스터
    mov ecx, 10             ; 최대 바이트 크기 (5개 * 2byte = 10)

LABEL_LOOP_ARRAY_B_MANUAL:
    PRINT_DEC 2, [b + ebx]
    NEWLINE
    add ebx, 2              ; 2바이트 데이터이므로 주소를 +2 해줌
    cmp ebx, ecx
    jl LABEL_LOOP_ARRAY_B_MANUAL


    ; 방법 2) 인덱스와 스케일 팩터(Scale Factor) 활용 [권장]
    xor ecx, ecx            ; i = 0

LABEL_PRINT_B_SCALE:
    ; [시작 주소 + 인덱스 * 크기] 공식을 활용
    PRINT_HEX 2, [b + ecx * 2]
    NEWLINE
    inc ecx                 ; i++
    cmp ecx, 5              ; 요소 개수(5)만큼 반복
    jne LABEL_PRINT_B_SCALE

    xor rax, rax
    ret

section .data
    ; 1) 기본 배열 선언 (초기값 지정)
    ; 1바이트 * 5개 = 5바이트 할당
    a db 0x01, 0x02, 0x03, 0x04, 0x05

    ; 2) times 키워드 활용
    ; 5개 공간을 잡고 모두 1(word)로 초기화
    ; 5 * 2바이트 = 10바이트 할당
    ; 메모리(리틀 엔디안): 01 00, 01 00, ...
    b times 5 dw 1

    ; 3) 2차원 배열 느낌의 데이터
    ; 메모리상에서는 결국 일자로 쭉 나열됨
    map1 db '#########', 0x00
    map2 db '#  ###  #', 0x00
    map3 db '#       #', 0x00
    map4 db '#########', 0x00

```

## 2. 이론 정리 (Study Notes)

### 2.1 배열 (Array)의 선언
동일한 데이터 타입의 연속된 집합. 어셈블리에서는 단순히 메모리를 연속으로 할당하는 행위에 불과함

* **기본 선언**: 콤마(`,`)로 값을 나열
  * `a db 0x01, 0x02, ...`
* **`times` 지시어**: 반복되는 값으로 초기화할 때 사용
  * **문법**: `[변수명] times [반복횟수] [크기] [초기값]`
  * **예시**: `b times 5 dw 1` $\rightarrow$ 2바이트(`dw`) 크기의 `1`을 5번 반복해서 생성

### 2.2 주소 접근 방식 (Addressing Modes)
배열의 요소(Element)에 접근하기 위해 메모리 주소를 계산하는 방법

* **공식**:
  $$Address = Base + (Index \times Scale) + Displacement$$
* **구성 요소**:
  * **Base**: 배열의 시작 주소 (예: `a`, `b`)
  * **Index**: 몇 번째 요소인지 나타내는 카운터 (예: `ecx`)
  * **Scale**: 데이터 타입의 크기 (1, 2, 4, 8만 가능)
* **예시 (Word 배열 접근)**:
  * `mov ax, [b + ecx * 2]`
  * `ecx`가 1 증가할 때마다, 실제 주소는 2바이트씩 건너뛰게 됨

## 3. 종합 의견 (Review)

### 핵심 요약
* **배열은 연속된 메모리**: C언어처럼 `a[i]`라는 문법이 자동으로 주소를 찾아주는 것이 아님. 프로그래머가 **(시작 주소 + 떨어진 거리)**를 직접 계산해야 함
* **주소 vs 값**:
  * `mov rax, a`: 배열의 **시작 주소**를 가져옴 (Pointer)
  * `mov rax, [a]`: 배열의 **첫 번째 값**을 가져옴 (Value)
* **단위의 중요성**: `dw`(2byte)나 `dd`(4byte) 배열을 다룰 때, 단순히 인덱스를 1씩 더해서 접근(`[b+ecx]`)하면 데이터가 엇갈리거나(Unaligned) 엉뚱한 값을 읽게 됨. 반드시 **데이터 크기(Scale)**를 고려해야 함

### Tip
* **2차원 배열**: 소스 코드의 `map` 예제처럼 2차원 배열도 메모리상에는 **1차원(선형)**으로 저장됨
  * $y$행 $x$열에 접근하려면: `[Base + (y * 가로길이) + x]` 형태로 계산
* **배열 범위**: 어셈블리어는 인덱스 범위를 체크해주지 않음 (`Out of bounds` 에러 없음). 반복문 조건(`cmp ecx, 5`)을 잘못 설정하면 다른 변수의 메모리를 침범하여 덮어쓸 위험이 있음
