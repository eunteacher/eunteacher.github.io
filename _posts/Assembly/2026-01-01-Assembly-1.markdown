# [어셈블리] Hello World 출력 및 기초 CS 이론 정리

어셈블리 언어를 공부하며 작성한 `Hello World` 출력 코드와, 이 과정에서 이해해야 할 기초 컴퓨터 과학(CS) 이론들(컴파일러, 실행 파일 구조, 메모리 구조 등)을 정리

---

## 1. 소스 코드 (Source Code)

`io64.inc` 라이브러리를 포함하여 문자열을 출력하는 기본적인 어셈블리 코드

```nasm
%include "io64.inc"

section .text
global CMAIN

CMAIN:
    ; write your code here

    PRINT_STRING msg    ; 'Hello World' 문자열 출력

    xor rax, rax        ; RAX 레지스터를 0으로 초기화 (반환값)
    ret                 ; 함수 종료 및 반환

section .data
    msg db 'Hello World', 0x00  ; 문자열 정의 (Null로 종료)
```

---

## 2. 이론 정리 (Study Notes)

코드를 작성하면서 함께 공부한 시스템 및 메모리 구조에 대한 내용

### 1) 어셈블러와 컴파일러
사람이 작성한 코드를 컴퓨터가 이해할 수 있는 언어로 변환하는 과정
* **컴파일러/어셈블러:** 위와 같이 작성한 소스 코드를 **기계어(Machine Language)**로 번역해 주는 역할

### 2) 실행 파일 구조 (Executable File Structure)
Windows의 실행 파일(PE 파일)이 저장되고 실행될 때의 구조

* **File (하드 디스크 저장 상태)**
  * 구조: `DOS stub - NT Header - Section header(".text") - Section header(".data") - Section header(".rsrc") - NULL - Section(".text") - NULL - Section(".data") - NULL - Section(".rsrc") - NULL`
  * 특징: 실행되지 않은 상태로 디스크에 저장된 형태
* **Memory (실행 중인 상태)**
  * 구조: `DOS stub - NT Header - Section header(".text") - Section header(".data") - Section header(".rsrc") - NULL - Section(".text") - NULL - Section(".data") - NULL - Section(".rsrc") - NULL`
  * 특징: 파일이 실행되면 파일의 내용이 메모리에 올라가며(Load), 각 섹션이 메모리 주소에 매핑
* **실행 파일 구조의 NULL의 의미**
  * NULL이 존재하는 이유는 정렬(Alignment)
  * 파일에서는 용량을 아끼기 위해 촘촘하게(예: 512byte 단위) 저장하지만, 메모리에서는 처리 속도를 위해 페이지 단위(예: 4KB)로 간격을 벌려서 저장


### 3) 컴퓨터 구조 (Computer Architecture)
프로그램 실행에 관여하는 하드웨어의 특성

* **주요 구성:** CPU / 메인 메모리(RAM) / 하드 디스크(HDD/SSD)
* **하드 디스크 vs 메인 메모리**
  * **하드 디스크:** **비휘발성**, 전원이 꺼져도 데이터가 보존되지만 속도가 느림
  * **메인 메모리:** **휘발성**, 전원이 꺼지면 데이터가 날아가지만, 하드 디스크보다 접근 속도가 월등히 빠름
* **동작 원리:** 프로그램을 실행하면 하드 디스크에 저장된 데이터를 메인 메모리로 복사한 뒤, CPU가 이를 처리

### 4) 프로세스 메모리 구조 (Process Memory Structure)
프로그램이 실행되어 프로세스가 되었을 때 할당받는 4가지 핵심 메모리 영역

| 영역 (Segment) | 역할 | 특징 |
| :--- | :--- | :--- |
| **Code (Text)** | 코드 저장 | 프로그래머가 작성한 코드가 기계어로 저장되는 영역 |
| **Data** | 데이터 저장 | 초기화된 **전역 변수**, **정적(Static) 변수**가 저장됨 |
| **BSS** | 데이터 저장 | 초기화되지 않은 전역 변수, 정적 변수가 저장됨 (0으로 초기화) |
| **Heap** | 동적 할당 | 프로그래머가 필요 시 할당하는 영역 (낮은 주소 → 높은 주소) |
| **Stack** | 정적 할당 | 지역 변수, 매개 변수 등이 저장됨 (높은 주소 → 낮은 주소) |

> **참고:** Heap과 Stack은 메모리 공간을 공유하며 서로 반대 방향으로 자라나는 구조 (`Heap <-> Stack`)

## 3. 종합 의견 (Review)

* **코드 분석:** `section .data`에 문자열 상수를 정의하고, `section .text`에서 코드를 실행하는 전형적인 구조. `xor rax, rax`는 `mov rax, 0`보다 명령어가 짧고 빠르기 때문에 자주 사용되는 레지스터 초기화 방식
* **핵심 포인트:** 어셈블리 프로그래밍에서는 내가 작성한 코드가 메모리의 어느 영역(Code, Data, Stack 등)에 위치하고 어떻게 CPU에 의해 처리되는지 이해하는 것이 가장 중요! 위에서 정리한 **프로세스 메모리 구조**는 앞으로 배울 포인터나 메모리 관리의 기초가 되므로 확실히 숙지할 것!
