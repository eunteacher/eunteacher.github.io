앞에서는 가위바위보의 선택과 결과를 `enum class`로 표현했다. 정수 1, 2, 3만 사용했을 때보다 값의 의미와 종류가 코드에 분명하게 드러났다.

C++에는 값에 이름을 붙이는 방법이 여러 가지다. `const`와 `constexpr` 변수, 기존 `enum`, `enum class`, 전처리 매크로는 비슷해 보이는 결과를 만들 수 있지만 언어가 이해하는 방식은 서로 다르다.

이번에는 연관된 선택지를 타입으로 표현하는 열거형과, 컴파일 전에 토큰을 바꾸는 전처리 매크로를 비교한다.

## 정수 상수만으로도 이름은 붙일 수 있다

가위바위보 선택을 개별 정수 상수로 표현할 수 있다.

```cpp
constexpr int Rock = 1;
constexpr int Paper = 2;
constexpr int Scissors = 3;
```

숫자를 직접 사용하는 것보다는 의미가 분명하다.

```cpp
int playerHand = Rock;
```

하지만 세 상수는 타입 관점에서 서로 연관돼 있지 않다. 모두 평범한 `int`일 뿐이다.

```cpp
constexpr int Win = 1;
constexpr int Rock = 1;

int playerHand = Win; // 컴파일 가능
```

`Win`은 게임 결과이고 `Rock`은 손 모양이지만 둘 다 같은 정수 타입이므로 잘못 섞어도 컴파일러가 구분하지 못한다.

연관된 값의 집합 자체를 하나의 타입으로 만들고 싶다면 열거형이 필요하다.

## 기존 `enum`은 연관된 열거자를 정의한다

기존 형태의 열거형을 Unscoped enum이라고 부른다.

```cpp
enum Hand
{
    Rock,
    Paper,
    Scissors
};
```

값을 직접 지정하지 않으면 첫 열거자는 0이고 이후 값은 앞의 값에서 1씩 증가한다.

```text
Rock     = 0
Paper    = 1
Scissors = 2
```

첫 값을 지정하면 그다음 값도 이어서 증가한다.

```cpp
enum Hand
{
    Rock = 1,
    Paper,
    Scissors
};
```

```text
Rock     = 1
Paper    = 2
Scissors = 3
```

각 열거자의 값을 모두 직접 지정할 수도 있다.

```cpp
enum HttpStatus
{
    Ok = 200,
    NotFound = 404,
    ServerError = 500
};
```

자동 증가 규칙은 편리하지만 외부 데이터 형식이나 네트워크 프로토콜처럼 숫자값 자체가 계약이라면 각 값을 명시하는 편이 안전하다.

## 기존 `enum`의 이름은 바깥 스코프로 나온다

Unscoped enum의 열거자 이름은 열거형 이름 안에만 갇히지 않고 둘러싼 스코프로 나온다.

```cpp
enum Color
{
    Red,
    Green,
    Blue
};

Color color = Red;
```

이 때문에 같은 스코프에서 다른 열거형이 같은 열거자 이름을 사용할 수 없다.

```cpp
enum TrafficLight
{
    // Red, // Color의 Red와 이름 충돌
    Yellow
};
```

접두사를 붙여 충돌을 피하는 기존 코드를 볼 수 있다.

```cpp
enum Color
{
    Color_Red,
    Color_Green,
    Color_Blue
};
```

이름 충돌은 줄지만 모든 열거자에 타입 이름을 반복해야 한다.

## 기존 `enum`은 정수로 암시적 변환될 수 있다

Unscoped enum의 값은 정수 타입으로 암시적 변환될 수 있다.

```cpp
enum Hand
{
    Rock = 1,
    Paper = 2,
    Scissors = 3
};

int value = Rock;
```

이 특성 때문에 산술 연산에도 바로 참여할 수 있다.

```cpp
int nextValue = Rock + 1;
```

기존 C API나 정수 기반 인터페이스와 연결할 때 편리할 수 있지만, 서로 다른 의미의 값을 실수로 섞기도 쉽다.

```cpp
enum Hand
{
    Rock = 1,
    Paper = 2,
    Scissors = 3
};

enum GameResult
{
    Win = 1,
    Lose = 2,
    Draw = 3
};

bool sameValue = Rock == Win; // 정수로 변환된 값을 비교
```

손 모양과 게임 결과는 서로 비교할 개념이 아니지만 암시적 정수 변환 때문에 코드가 성립할 수 있다.

## `enum class`는 열거자를 타입 스코프 안에 둔다

C++11부터 Scoped enum인 `enum class`를 사용할 수 있다.

```cpp
enum class Hand
{
    Rock,
    Paper,
    Scissors
};
```

열거자는 열거형의 스코프 안에 있으므로 타입 이름과 범위 지정 연산자를 함께 사용한다.

```cpp
Hand hand = Hand::Rock;
```

서로 다른 열거형에서 같은 열거자 이름을 사용할 수 있다.

```cpp
enum class Color
{
    Red,
    Green,
    Blue
};

enum class TrafficLight
{
    Red,
    Yellow,
    Green
};

Color color = Color::Red;
TrafficLight light = TrafficLight::Red;
```

`Color::Red`와 `TrafficLight::Red`는 이름과 타입이 모두 구분된다.

## `enum class`는 정수로 자동 변환되지 않는다

`enum class`의 값은 정수로 암시적 변환되지 않는다.

```cpp
enum class Hand
{
    Rock = 1,
    Paper = 2,
    Scissors = 3
};

Hand hand = Hand::Rock;

// int value = hand; // 컴파일 오류
```

정수값이 정말 필요하다면 변환을 명시한다.

```cpp
int value = static_cast<int>(hand);
```

서로 다른 열거형도 직접 비교할 수 없다.

```cpp
enum class GameResult
{
    Win,
    Lose,
    Draw
};

GameResult result = GameResult::Win;

// bool same = hand == result; // 서로 다른 타입
```

명시적 변환을 사용하면 결국 정수로 바꿀 수 있지만, 변환 지점이 코드에 드러난다. 컴파일러가 의도하지 않은 혼합을 자동으로 허용하지 않는 것이 핵심이다.

## 기반 타입은 열거 값을 저장할 정수 타입이다

열거형은 열거 값을 표현하기 위한 기반 정수 타입(Underlying type)을 가진다.

```cpp
#include <cstdint>

enum class PlayerState : std::uint8_t
{
    Idle,
    Moving,
    Attacking
};
```

콜론 뒤의 `std::uint8_t`가 기반 타입이다.

```text
enum class PlayerState : std::uint8_t
                       └── 기반 타입
```

`enum class`에서 기반 타입을 생략하면 기본 기반 타입은 `int`다. Unscoped enum은 기반 타입을 명시하지 않았을 때 표현할 열거자 값에 맞춰 구현이 선택할 수 있다.

기반 타입을 명시하면 다음 의도를 표현할 수 있다.

- 외부 데이터와 정수 폭을 맞춘다.
- 직렬화 형식을 고정한다.
- 표현 가능한 열거 값의 범위를 제한한다.
- 비트 플래그의 저장 타입을 정한다.

하지만 작은 기반 타입을 사용한다고 객체 전체 메모리가 반드시 그만큼 줄어드는 것은 아니다. 구조체의 정렬과 패딩도 함께 확인해야 한다.

## 열거 값은 기반 타입이 표현할 수 있어야 한다

`std::uint8_t`가 제공되는 환경이라면 0부터 255까지 표현할 수 있다.

```cpp
#include <cstdint>

enum class PacketType : std::uint8_t
{
    Login = 1,
    Move = 2,
    Attack = 3
};
```

기반 타입 범위를 벗어나는 열거자 값은 사용할 수 없다.

```cpp
enum class PacketType : std::uint8_t
{
    // Invalid = 300 // 기반 타입으로 표현할 수 없음
};
```

외부 프로토콜과 연결된 열거형에서는 기존 숫자값을 중간에 바꾸거나 재사용해서도 안 된다.

```text
1 = Login
2 = Move
3 = Attack
```

이미 저장되거나 전송된 데이터가 있다면 이 숫자와 의미의 대응이 외부 계약의 일부다.

## 열거형 변수에도 정의하지 않은 값이 들어갈 수 있다

열거형을 사용한다고 런타임의 모든 값이 자동으로 열거자 목록에 제한되는 것은 아니다. 정수에서 명시적으로 변환하면 이름 붙이지 않은 값이 들어갈 수 있다.

```cpp
enum class Hand
{
    Rock = 1,
    Paper = 2,
    Scissors = 3
};

Hand hand = static_cast<Hand>(100);
```

이후 `switch`에서 어느 `case`에도 일치하지 않을 수 있다.

```cpp
const char* ToString(Hand hand)
{
    switch (hand)
    {
    case Hand::Rock:
        return "Rock";
    case Hand::Paper:
        return "Paper";
    case Hand::Scissors:
        return "Scissors";
    }

    return "Unknown";
}
```

사용자 입력이나 파일·네트워크에서 읽은 정수를 열거형으로 바꿀 때는 먼저 유효성을 검사한다.

```cpp
bool TryParseHand(int input, Hand& hand)
{
    switch (input)
    {
    case 1:
        hand = Hand::Rock;
        return true;
    case 2:
        hand = Hand::Paper;
        return true;
    case 3:
        hand = Hand::Scissors;
        return true;
    default:
        return false;
    }
}
```

타입이 값의 종류를 표현하더라도 외부 경계의 검증 책임까지 자동으로 해결하지는 않는다.

## 같은 정수값을 가진 열거자를 정의할 수도 있다

서로 다른 열거자에 같은 값을 지정할 수 있다.

```cpp
enum class ErrorCode
{
    None = 0,
    Success = 0,
    FileNotFound = 1
};
```

`ErrorCode::None`과 `ErrorCode::Success`는 이름은 다르지만 값은 같다.

```cpp
bool same = ErrorCode::None == ErrorCode::Success; // true
```

이런 별칭이 외부 명칭 호환이나 의미 전환에 필요할 수 있지만 `switch`에서는 같은 값을 가진 두 `case`를 모두 작성할 수 없다.

```cpp
switch (code)
{
case ErrorCode::None:
    break;
// case ErrorCode::Success: // 같은 case 값 중복
//     break;
case ErrorCode::FileNotFound:
    break;
}
```

같은 값을 공유하는 열거자는 출력이나 역변환 시 어느 이름을 대표로 사용할지도 결정해야 한다.

## 열거형은 모든 상태 조합을 자동으로 막아 주지 않는다

서로 독립적인 상태가 동시에 존재할 수 있다면 하나의 일반 열거형만으로 표현하기 어렵다.

```cpp
enum class PlayerState
{
    Airborne,
    Stunned,
    Invincible
};
```

플레이어가 공중에 있으면서 동시에 무적일 수 있다면 `PlayerState` 변수 하나에는 두 값을 함께 저장할 수 없다.

이런 경우 선택지는 요구사항에 따라 달라진다.

- 상태들이 서로 배타적이면 일반 열거형 하나를 사용한다.
- 여러 상태가 독립적으로 동시에 켜지면 개별 `bool`을 사용한다.
- 여러 상태를 조합·저장해야 하면 비트 플래그를 사용한다.
- 상태 전이가 복잡하면 상태 객체나 별도의 상태 머신을 고려한다.

열거형은 관련된 이름을 타입으로 묶지만 실제 도메인의 상태 관계를 대신 설계해 주지는 않는다.

## 비트 플래그 열거형에는 값을 2의 거듭제곱으로 지정한다

열거자를 비트 마스크로 사용하려면 각 값이 서로 다른 비트 하나를 가져야 한다.

```cpp
#include <cstdint>

enum class PlayerFlag : std::uint32_t
{
    None = 0,
    Airborne = 1u << 0,
    Stunned = 1u << 1,
    Transformed = 1u << 2,
    Invincible = 1u << 3
};
```

자동 증가값 0, 1, 2, 3을 그대로 사용하면 2진수에서 비트가 겹친다.

```text
0 → 0000
1 → 0001
2 → 0010
3 → 0011  두 비트가 켜진 조합
```

비트 플래그 값은 다음처럼 각 위치를 하나씩 사용한다.

```text
1 << 0 → 0001
1 << 1 → 0010
1 << 2 → 0100
1 << 3 → 1000
```

`enum class`는 정수나 다른 열거형과 자동으로 섞이지 않으므로 비트 연산자도 자동 제공되지 않는다.

```cpp
// PlayerFlag flags = PlayerFlag::Airborne | PlayerFlag::Invincible;
```

필요하다면 해당 타입에서 허용할 연산자를 직접 정의한다.

```cpp
constexpr PlayerFlag operator|(PlayerFlag left, PlayerFlag right)
{
    using Underlying = std::underlying_type_t<PlayerFlag>;
    Underlying result = static_cast<Underlying>(left) | static_cast<Underlying>(right);
    return static_cast<PlayerFlag>(result);
}
```

이를 위해 `<type_traits>`가 필요하다.

```cpp
#include <type_traits>
```

연산자를 정의한 뒤에는 타입을 유지하면서 플래그를 조합할 수 있다.

```cpp
PlayerFlag flags = PlayerFlag::Airborne | PlayerFlag::Invincible;
```

모든 열거형에 비트 연산자를 제공해서는 안 된다. 방향, 메뉴 선택, 게임 결과처럼 하나만 선택해야 하는 열거형에는 OR 조합이 의미가 없다.

## `std::underlying_type_t`로 기반 타입을 얻는다

열거형의 기반 타입을 직접 반복해서 적지 않고 타입 특성으로 얻을 수 있다.

```cpp
#include <type_traits>

using PlayerFlagValue = std::underlying_type_t<PlayerFlag>;
```

변환 함수로 이름을 붙일 수도 있다.

```cpp
constexpr std::underlying_type_t<PlayerFlag> ToUnderlying(PlayerFlag value)
{
    return static_cast<std::underlying_type_t<PlayerFlag>>(value);
}
```

C++23부터는 표준 라이브러리의 `std::to_underlying`을 사용할 수 있다.

```cpp
#include <utility>

auto value = std::to_underlying(PlayerFlag::Invincible);
```

프로젝트가 사용하는 C++ 표준 버전에 맞는 방식을 선택한다.

## `constexpr` 상수는 C++ 타입 시스템 안에 있다

단일 상수값에는 `constexpr` 변수가 자연스럽다.

```cpp
constexpr int MaxPlayerCount = 4;
constexpr double AttackCooldownSeconds = 0.5;
```

`constexpr` 변수는 다음 특성을 가진다.

- 타입이 있다.
- 선언된 스코프가 있다.
- 컴파일러가 이름과 타입을 이해한다.
- 상수 표현식이 필요한 곳에 사용할 수 있다.
- 디버거와 코드 탐색 도구가 언어 요소로 다룰 수 있다.

연관된 선택지의 집합이라면 `enum class`, 하나의 상수값이라면 `constexpr`를 먼저 고려할 수 있다.

```text
하나의 이름 있는 값       → constexpr
서로 배타적인 선택지 집합  → enum class
독립 상태의 조합           → bool 또는 비트 플래그
```

## `#define`은 C++ 변수가 아니다

전처리 매크로는 `#define`으로 정의한다.

```cpp
#define MAX_PLAYER_COUNT 4
```

`MAX_PLAYER_COUNT`는 `int` 변수나 `constexpr` 객체가 아니다. 전처리 단계에서 해당 토큰을 다른 토큰으로 바꾸는 규칙이다.

```cpp
int players[MAX_PLAYER_COUNT];
```

전처리 뒤의 소스를 개념적으로 보면 다음과 같다.

```cpp
int players[4];
```

매크로 이름 자체는 컴파일러의 C++ 타입 시스템에 들어가지 않는다. 컴파일러는 치환된 결과를 분석한다.

## 매크로는 일반적인 C++ 스코프를 따르지 않는다

변수와 열거형 이름은 namespace와 블록 스코프를 따른다.

```cpp
namespace Game
{
    constexpr int MaxPlayerCount = 4;
}

int count = Game::MaxPlayerCount;
```

매크로는 일반적인 namespace 멤버가 아니다.

```cpp
#define MAX_PLAYER_COUNT 4
```

정의된 지점부터 `#undef`되거나 번역 단위의 전처리가 끝날 때까지 토큰 치환에 영향을 줄 수 있다.

```cpp
#undef MAX_PLAYER_COUNT
```

헤더에 정의한 일반적인 매크로는 그 헤더를 포함한 소스의 이후 부분에도 영향을 준다. 짧고 흔한 이름의 매크로가 라이브러리나 사용자 코드의 식별자와 충돌할 수 있는 이유다.

## 객체형 매크로보다 `constexpr`를 우선한다

단순 숫자 상수를 매크로로 정의할 수 있다.

```cpp
#define MAX_COUNT 10
```

하지만 C++ 코드에서는 타입과 스코프가 있는 `constexpr` 변수가 더 많은 검사를 받을 수 있다.

```cpp
inline constexpr int MaxCount = 10;
```

헤더에 프로그램 전체에서 공유할 상수를 정의한다면 C++17의 `inline constexpr`를 사용할 수 있다. 소스 파일이나 함수 내부에서만 사용한다면 필요한 가장 좁은 스코프에 `constexpr`를 선언한다.

매크로는 이름을 namespace로 한정할 수 없고 주소를 갖는 객체로 사용할 수도 없으며 C++ 타입을 가진 인자로 전달되지도 않는다.

## 함수형 매크로는 괄호가 없으면 연산 순서가 달라진다

함수 호출처럼 인자를 받는 매크로를 함수형 매크로라고 한다.

```cpp
#define SQUARE(x) x * x
```

단순한 호출은 예상대로 보일 수 있다.

```cpp
int result = SQUARE(3); // 3 * 3
```

하지만 표현식을 전달하면 치환 결과의 묶음이 달라진다.

```cpp
int result = SQUARE(1 + 2);
```

전처리 결과는 다음과 같다.

```cpp
int result = 1 + 2 * 1 + 2;
```

곱셈이 먼저 계산되므로 결과는 9가 아니라 5다.

매개변수와 매크로 전체에 괄호를 추가할 수 있다.

```cpp
#define SQUARE(x) ((x) * (x))
```

하지만 괄호만으로 함수형 매크로의 모든 문제가 해결되지는 않는다.

## 함수형 매크로는 인자를 여러 번 평가할 수 있다

다음 매크로는 `x`를 두 번 치환한다.

```cpp
#define SQUARE(x) ((x) * (x))
```

증감식이나 함수 호출처럼 부작용이 있는 표현식을 전달하면 그 표현식이 여러 번 나타난다.

```cpp
int value = 3;

// int result = SQUARE(value++);
```

치환된 코드는 개념적으로 다음과 같다.

```cpp
int result = ((value++) * (value++));
```

한 표현식에서 같은 값을 여러 번 변경하는 문제가 생기고 C++ 버전에 따라 정의되지 않거나 예측하기 어려운 동작이 될 수 있다.

함수나 함수 템플릿은 인자를 호출 시점에 한 번 평가하고 매개변수로 전달한다.

```cpp
template <typename T>
constexpr T Square(T value)
{
    return value * value;
}
```

```cpp
int value = 3;
int result = Square(value++);
```

`value++`는 함수 호출 인자로 한 번 평가된다. 타입 검사와 디버깅도 일반 C++ 함수 규칙을 따른다.

## 여러 문장을 담는 매크로는 제어문과 충돌할 수 있다

다음 매크로는 두 출력문을 치환한다.

```cpp
#define PRINT_PLAYER() std::cout << "Player\n"; std::cout << "Ready\n";
```

조건문에서 사용하면 첫 문장만 `if`에 속한다.

```cpp
if (isReady)
    PRINT_PLAYER();
```

전처리 뒤의 구조는 다음과 비슷하다.

```cpp
if (isReady)
    std::cout << "Player\n";
std::cout << "Ready\n";
```

전통적으로 `do { ... } while (false)` 형태로 여러 문장 매크로를 하나의 문장처럼 감싸기도 한다.

```cpp
#define PRINT_PLAYER() do { std::cout << "Player\n"; std::cout << "Ready\n"; } while (false)
```

하지만 일반 출력 작업이라면 매크로보다 함수를 사용하는 것이 더 자연스럽다.

```cpp
void PrintPlayer()
{
    std::cout << "Player\n";
    std::cout << "Ready\n";
}
```

여러 문장을 안전하게 담는 매크로 작성법을 외우기 전에 C++ 함수로 표현할 수 있는지 먼저 확인한다.

## 매크로 정의 끝에 세미콜론을 넣지 않는다

다음 매크로는 치환문 끝에 세미콜론을 포함한다.

```cpp
#define PRINT_HELLO() std::cout << "Hello\n";
```

호출부에서도 세미콜론을 작성하면 두 개가 생긴다.

```cpp
PRINT_HELLO();
```

전처리 결과는 다음과 같다.

```cpp
std::cout << "Hello\n";;
```

빈 문장이 하나 추가되는 것만으로 끝날 수도 있지만 `if`·`else` 같은 문법과 결합하면 문제가 생길 수 있다. 함수형 매크로를 문장처럼 사용해야 한다면 호출부가 세미콜론을 담당하도록 정의 끝에는 넣지 않는다.

가능하다면 매크로 자체를 함수로 바꾼다.

## 매크로 인자 안의 쉼표도 문제를 만들 수 있다

전처리기는 괄호 깊이를 기준으로 함수형 매크로 인자를 나눈다. 템플릿 인자의 쉼표가 매크로 인자 구분자로 해석될 수 있다.

```cpp
#define CALL(expression) expression

// CALL(std::pair<int, int>{1, 2});
```

전처리기는 `<int, int>`의 꺾쇠괄호를 C++ 템플릿 문법으로 이해하지 않는다. 이런 문제는 매크로가 C++ 구문을 완전히 이해한 뒤 처리되는 기능이 아니라는 사실에서 나온다.

## 매크로가 필요한 대표적인 경우

매크로를 항상 제거해야 하는 것은 아니다. 전처리 단계에서만 할 수 있는 작업에는 여전히 필요하다.

### 조건부 컴파일

플랫폼이나 빌드 설정에 따라 다른 코드를 포함할 수 있다.

```cpp
#if defined(_WIN32)
    std::cout << "Windows\n";
#else
    std::cout << "Other platform\n";
#endif
```

전처리 조건은 컴파일러가 C++ 문장을 분석하기 전에 코드의 포함 여부를 결정한다.

### 헤더 중복 포함 방지

Include guard는 헤더 내용이 같은 번역 단위에 여러 번 포함되는 것을 막는다.

```cpp
#ifndef PLAYER_H
#define PLAYER_H

struct Player
{
    int hp;
};

#endif
```

`#pragma once`도 많은 컴파일러에서 같은 목적으로 지원한다.

```cpp
#pragma once
```

`#pragma once`는 널리 지원되지만 C++ 표준이 정의한 전처리 지시문은 아니다. 대상 컴파일러 지원 범위를 확인해 사용한다.

### 소스 위치 정보

`__FILE__`, `__LINE__` 같은 사전 정의 매크로는 로그에 소스 위치를 남길 때 사용할 수 있다.

```cpp
std::cout << __FILE__ << ':' << __LINE__ << '\n';
```

현대 표준에서는 `std::source_location`처럼 일부 용도를 타입 안전한 C++ 기능으로 대체할 수 있다. 하지만 프로젝트의 지원 표준 버전과 로깅 시스템에 따라 매크로가 실용적인 경우도 있다.

## 전처리는 컴파일보다 먼저 동작한다

소스 파일은 개념적으로 다음 단계를 거쳐 실행 파일이 된다.

```text
소스 파일
   │
   ▼
전처리
#include, #define, #if 처리
   │
   ▼
번역 단위
   │
   ▼
컴파일
C++ 문법·타입 검사, 목적 코드 생성
   │
   ▼
링크
여러 목적 파일과 라이브러리 연결
   │
   ▼
실행 파일
```

`#include`를 단순히 파일 내용을 복사한다고 설명하면 기본 그림은 이해할 수 있지만, 실제 표준은 헤더 이름을 찾고 전처리 토큰을 처리하는 규칙으로 정의한다. 중요한 점은 포함과 매크로 치환이 C++ 타입 검사 전에 이루어진다는 것이다.

매크로가 타입을 갖지 않는 이유도 이 처리 순서에서 나온다. 컴파일러는 매크로 이름이 아니라 전처리 후 치환된 C++ 코드를 검사한다.

## 전처리 결과를 확인하면 매크로 문제를 찾기 쉽다

함수형 매크로의 결과가 예상과 다르면 머릿속으로만 추측하지 않고 전처리된 출력을 확인할 수 있다.

Visual Studio의 MSVC에서는 `/P` 옵션으로 전처리 결과 파일을 생성할 수 있다. GCC와 Clang 계열에서는 일반적으로 `-E` 옵션을 사용한다.

```text
MSVC   cl /P source.cpp
GCC    g++ -E source.cpp
Clang  clang++ -E source.cpp
```

생성되는 출력은 포함된 헤더까지 펼쳐져 매우 길 수 있다. 문제가 되는 매크로 이름이나 호출 주변을 검색해 실제로 어떤 토큰으로 바뀌었는지 확인한다.

도구 옵션은 컴파일러 버전과 빌드 환경에 따라 세부 동작이 달라질 수 있으므로 실제 프로젝트의 설정을 함께 확인한다.

## 선택 기준을 정리한다

이름 있는 값을 표현하는 방법은 목적에 따라 선택한다.

| 필요한 것 | 우선 고려할 방법 |
| :--- | :--- |
| 하나의 컴파일 시간 상수 | `constexpr` 변수 |
| 서로 배타적인 선택지 집합 | `enum class` |
| 동시에 조합되는 여러 상태 | 개별 `bool` 또는 비트 플래그 |
| 짧은 계산 함수 | `constexpr` 함수 또는 함수 템플릿 |
| 플랫폼별 코드 포함 여부 | 조건부 컴파일 매크로 |
| 헤더 중복 포함 방지 | Include guard 또는 지원되는 `#pragma once` |
| 소스 위치 기반 로깅 | 표준 기능 또는 프로젝트 로깅 매크로 |

핵심 기준은 “짧게 작성할 수 있는가”가 아니라 컴파일러가 타입과 스코프를 이해하고 잘못된 사용을 검사할 수 있는가다.

## 전체 실습 코드

`enum class`, 기반 타입, 비트 플래그 연산, `constexpr` 함수를 함께 사용하는 예제다.

```cpp
#include <cstdint>
#include <iostream>
#include <type_traits>

enum class Hand : std::uint8_t
{
    Rock = 1,
    Paper = 2,
    Scissors = 3
};

enum class PlayerFlag : std::uint32_t
{
    None = 0,
    Airborne = 1u << 0,
    Stunned = 1u << 1,
    Invincible = 1u << 2
};

constexpr std::underlying_type_t<PlayerFlag> ToUnderlying(PlayerFlag value)
{
    return static_cast<std::underlying_type_t<PlayerFlag>>(value);
}

constexpr PlayerFlag operator|(PlayerFlag left, PlayerFlag right)
{
    std::uint32_t result = ToUnderlying(left) | ToUnderlying(right);
    return static_cast<PlayerFlag>(result);
}

constexpr bool HasAnyFlag(PlayerFlag flags, PlayerFlag mask)
{
    return (ToUnderlying(flags) & ToUnderlying(mask)) != 0;
}

bool TryParseHand(int input, Hand& hand)
{
    switch (input)
    {
    case 1:
        hand = Hand::Rock;
        return true;
    case 2:
        hand = Hand::Paper;
        return true;
    case 3:
        hand = Hand::Scissors;
        return true;
    default:
        return false;
    }
}

const char* ToString(Hand hand)
{
    switch (hand)
    {
    case Hand::Rock:
        return "Rock";
    case Hand::Paper:
        return "Paper";
    case Hand::Scissors:
        return "Scissors";
    }

    return "Unknown";
}

int main()
{
    constexpr int MaxPlayerCount = 4;
    std::cout << "Max players: " << MaxPlayerCount << '\n';

    Hand hand = Hand::Rock;

    if (TryParseHand(2, hand))
    {
        std::cout << "Selected hand: " << ToString(hand) << '\n';
        std::cout << "Underlying value: " << static_cast<int>(hand) << '\n';
    }

    PlayerFlag flags = PlayerFlag::Airborne | PlayerFlag::Invincible;
    std::cout << std::boolalpha;
    std::cout << "Airborne: " << HasAnyFlag(flags, PlayerFlag::Airborne) << '\n';
    std::cout << "Stunned: " << HasAnyFlag(flags, PlayerFlag::Stunned) << '\n';
    std::cout << "Invincible: " << HasAnyFlag(flags, PlayerFlag::Invincible) << '\n';
}
```

이 예제에서는 다음 내용을 확인할 수 있다.

- `Hand`는 서로 배타적인 선택지 하나를 표현한다.
- 정수 입력은 검증한 뒤 `Hand`로 변환한다.
- 열거 값을 정수로 사용할 때는 변환을 명시한다.
- `PlayerFlag`는 여러 상태를 OR로 조합한다.
- 열거형에 필요한 비트 연산자만 직접 제공한다.
- `MaxPlayerCount`는 단일 컴파일 시간 상수이므로 `constexpr`로 표현한다.

## 다음 학습: 동작을 함수로 묶기

`constexpr`는 하나의 상수값을, `enum class`는 연관된 선택지의 집합을 타입 시스템 안에서 표현한다. 매크로는 C++ 타입이 아니라 전처리 단계의 토큰 치환이므로 조건부 컴파일처럼 전처리가 필요한 상황에 좁게 사용한다.

다음 글에서는 반복해서 사용하는 동작을 함수로 묶고, 함수의 이름·매개변수·반환 타입이 호출자와 어떤 계약을 만드는지 살펴본다.
