앞에서는 포인터 하나만 함수에 전달하면 대상의 길이, 수명과 소유권 정보가 자동으로 따라오지 않는다는 점을 살펴봤다. 함수 매개변수에서 값, 포인터와 참조 중 무엇을 선택할 때도 같은 질문이 필요하다.

흔히 “작은 데이터는 값, 큰 데이터는 포인터나 참조”라는 성능 공식부터 떠올린다. 하지만 매개변수 타입은 그보다 먼저 **함수에 대상이 반드시 필요한지, 원본을 수정하는지, 복사본이 필요한지, 소유권을 넘기는지**를 호출자에게 알려야 한다.

## 매개변수 타입은 함수가 요구하는 관계를 표현한다

하나의 `Character` 타입을 여러 함수가 사용한다고 가정하자.

```cpp
struct Character
{
    const char* name;
    int hp;
    int attack;
    int defence;
};
```

함수의 역할에 따라 자연스러운 매개변수 형태가 달라진다.

```cpp
Character CreateMonster(const char* name, int hp, int attack, int defence);
int CalculateDamage(const Character& attacker, const Character& defender);
void ApplyDamage(Character& target, int damage);
bool TryApplyBonus(Character* target, int bonusHp);
```

| 함수 | 인터페이스가 표현하는 계약 |
| :--- | :--- |
| `CreateMonster` | 입력값으로 새 객체를 만들어 값으로 반환한다. |
| `CalculateDamage` | 두 대상이 반드시 존재하며 읽기만 한다. |
| `ApplyDamage` | 대상이 반드시 존재하며 원본을 수정한다. |
| `TryApplyBonus` | 대상이 없을 수 있고, 존재하면 수정한다. |

어느 방식이 가장 빠른지보다 함수가 무엇을 요구하고 허용하는지가 선언에 먼저 드러난다.

## 값 매개변수는 별도의 객체다

값 매개변수는 인자의 값으로 초기화된 별도 매개변수 객체다.

```cpp
void ResetHp(Character character)
{
    character.hp = 100;
}
```

호출자의 객체를 전달해도 매개변수 `character`를 수정할 뿐 원본 `player`의 멤버를 직접 바꾸지 않는다.

```cpp
Character player{"Player", 50, 20, 10};
ResetHp(player);
```

```text
호출자 객체                  매개변수 객체
player ── 값으로 초기화 ──▶ character
hp = 50                     hp = 50 → 100
```

함수가 끝나면 매개변수 복사본의 수명이 끝난다. 호출자가 변경된 값을 받으려면 함수가 결과를 반환하고 호출자가 사용해야 한다.

```cpp
Character ResetHp(Character character)
{
    character.hp = 100;
    return character;
}
```

```cpp
player = ResetHp(player);
```

호출부에 새 결과를 원본에 반영한다는 흐름이 드러난다.

## 값 전달은 원본을 그대로 보존한 계산에 적합하다

작고 복사하기 쉬운 기본 타입은 값으로 받는 것이 자연스럽다.

```cpp
int CalculateRemainingHp(int hp, int damage)
{
    return hp > damage ? hp - damage : 0;
}
```

`hp`와 `damage`는 함수 안에서 독립적으로 사용할 값이다. `const int&`로 바꾸면 원본을 읽기만 한다는 사실보다 불필요한 간접 관계가 추가될 수 있다.

```cpp
int remainingHp = CalculateRemainingHp(100, 30);
```

리터럴과 계산식도 별도 지역 변수를 만들지 않고 바로 전달할 수 있다.

값 전달이 잘 맞는 대표적인 경우는 다음과 같다.

- `int`, `double`, 열거형처럼 작고 독립적인 값
- 함수가 내부에서 수정할 복사본이 필요한 타입
- 함수가 인자의 소유권을 받아 내부에 저장할 타입
- 호출자와 상태를 공유하지 않는다는 계약이 중요한 경우

## 값 전달이 언제나 깊은 복사를 뜻하지는 않는다

매개변수 객체 자체는 별도 객체지만, 타입 내부가 다른 객체를 가리키면 가리키는 대상까지 자동으로 복제된다고 단정할 수 없다.

```cpp
struct CharacterView
{
    int* hp;
};

void ApplyDamage(CharacterView view, int damage)
{
    *view.hp -= damage;
}
```

`view`는 값으로 전달되지만 내부 포인터가 호출자의 HP를 가리키면 역참조를 통해 원본 HP를 변경한다.

값 전달이 보장하는 것은 매개변수 객체 자체가 인자 객체와 별개라는 점이다. 복사했을 때 내부 자원과 대상이 공유되는지는 타입의 복사 의미에 달려 있다.

`std::string`, `std::vector`, 스마트 포인터처럼 자원을 관리하는 타입은 각각 정의된 복사·이동 규칙을 가진다. 인터페이스를 선택할 때 객체 크기뿐 아니라 이 의미도 확인해야 한다.

## 값 전달에는 복사 또는 이동이 사용될 수 있다

클래스 타입의 값 매개변수는 인자의 종류와 타입의 기능에 따라 복사 또는 이동으로 초기화될 수 있다.

```cpp
#include <string>
#include <utility>

class Player
{
public:
    void SetName(std::string name)
    {
        Name = std::move(name);
    }

private:
    std::string Name;
};
```

`SetName`은 문자열을 자신의 멤버에 저장해야 하므로 값으로 받아 이동하는 인터페이스를 선택할 수 있다.

```cpp
Player player;
std::string name = "Knight";
player.SetName(name);
player.SetName("Archer");
```

lvalue인 `name`을 전달하면 매개변수를 만들기 위한 복사가 필요할 수 있고, 임시 문자열을 전달하면 이동을 활용할 수 있다. 함수가 어차피 독립된 복사본을 저장해야 하는 상황에서는 값으로 받은 뒤 이동하는 패턴이 단순할 수 있다.

모든 큰 타입을 무조건 값으로 받으라는 뜻은 아니다. 함수가 저장하지 않고 잠시 읽기만 한다면 `const T&`가 더 자연스러운 계약일 수 있다.

## 반환값으로 새 객체를 전달하는 것은 자연스럽다

새 몬스터를 만드는 함수는 호출자가 미리 빈 객체를 준비하게 만들 필요가 없다.

```cpp
Character CreateMonster(const char* name, int hp, int attack, int defence)
{
    return {name, hp, attack, defence};
}
```

호출자는 반환값으로 바로 객체를 초기화한다.

```cpp
Character slime = CreateMonster("Slime", 30, 25, 5);
```

다음처럼 출력 매개변수로 객체를 채우는 방식도 가능하다.

```cpp
void CreateMonster(Character& output, const char* name, int hp, int attack, int defence)
{
    output = {name, hp, attack, defence};
}
```

하지만 결과 하나를 만드는 함수라면 반환값이 더 직접적이다. 현대 C++ 컴파일러는 반환값 최적화와 이동을 활용할 수 있으며, “구조체를 반환하면 반드시 임시 객체 전체를 여러 번 복사한다”라고 가정할 필요가 없다.

먼저 결과를 반환하는 명확한 인터페이스를 선택하고, 실제 성능 문제가 확인됐을 때 대상 타입과 생성 코드를 측정한다.

## `const T&`는 반드시 존재하는 대상을 읽기만 한다

함수가 객체를 저장하지 않고 호출 동안 읽기만 한다면 상수 참조를 사용할 수 있다.

```cpp
int CalculateDamage(const Character& attacker, const Character& defender)
{
    return attacker.attack > defender.defence ? attacker.attack - defender.defence : 0;
}
```

두 참조는 호출 시 유효한 `Character` 객체에 바인딩되어야 한다. 함수 안에서는 이 참조를 통해 두 객체를 수정할 수 없다.

```cpp
Character player{"Player", 100, 20, 10};
Character monster{"Monster", 50, 15, 5};
int damage = CalculateDamage(player, monster);
```

상수 참조가 잘 맞는 조건은 다음과 같다.

- 대상이 반드시 존재한다.
- 함수가 대상을 읽기만 한다.
- 호출 동안 객체 전체의 별도 복사본이 필요하지 않다.
- 함수가 참조를 호출 이후까지 보관하지 않는다.

마지막 조건은 수명과 관련된다. 함수가 참조를 멤버나 전역 위치에 저장한다면 호출이 끝난 뒤에도 대상이 살아 있는지 별도의 수명 계약이 필요하다.

## 상수 참조는 임시 객체에도 바인딩될 수 있다

`const T&` 매개변수에는 임시 객체를 전달할 수 있다.

```cpp
void PrintCharacter(const Character& character)
{
    std::cout << character.name << " HP: " << character.hp << '\n';
}
```

```cpp
PrintCharacter(CreateMonster("Slime", 30, 25, 5));
```

이 호출에서 반환된 임시 `Character`는 함수 호출 동안 사용할 수 있다. `PrintCharacter`가 반환된 뒤에는 이 임시 객체를 계속 가리키는 포인터나 참조를 사용해서는 안 된다.

상수 참조가 항상 대상 수명을 무제한으로 연장하는 것은 아니다. 참조가 어디에 바인딩되고 얼마나 보관되는지에 따라 규칙이 달라지므로, 매개변수 참조를 함수 밖에 저장할 때는 특히 주의한다.

## `T&`는 반드시 존재하는 원본을 수정한다

비상수 참조 매개변수는 호출자의 객체를 직접 변경할 수 있다.

```cpp
void ApplyDamage(Character& target, int damage)
{
    int appliedDamage = damage > 0 ? damage : 0;
    target.hp = target.hp > appliedDamage ? target.hp - appliedDamage : 0;
}
```

호출부에서는 일반 변수처럼 전달한다.

```cpp
ApplyDamage(monster, damage);
```

함수 선언의 `Character&`는 다음 계약을 표현한다.

- 대상은 반드시 존재해야 한다.
- 함수가 대상 원본을 수정할 수 있다.
- 참조는 함수 안에서 다른 객체로 다시 바인딩되지 않는다.
- 대상은 함수가 접근하는 동안 살아 있어야 한다.

비상수 참조는 선택적 대상보다 필수 입출력(In-out) 대상에 적합하다.

## 수정 가능하다는 사실만으로 참조를 선택하지 않는다

계산 결과 하나를 만들기 위해 출력 참조를 사용할 수 있다.

```cpp
void CalculateDamage(const Character& attacker, const Character& defender, int& outputDamage)
{
    outputDamage = attacker.attack > defender.defence ? attacker.attack - defender.defence : 0;
}
```

하지만 결과가 하나라면 반환값이 더 간단하다.

```cpp
int CalculateDamage(const Character& attacker, const Character& defender)
{
    return attacker.attack > defender.defence ? attacker.attack - defender.defence : 0;
}
```

```cpp
int damage = CalculateDamage(player, monster);
```

반환값은 함수가 만든 결과라는 사실이 호출식에 드러난다. 비상수 참조는 기존 객체를 수정하는 것이 함수의 핵심 책임일 때 사용한다.

## 여러 결과는 하나의 결과 타입으로 묶을 수 있다

피해량과 사망 여부를 함께 반환해야 한다고 가정하자.

```cpp
struct AttackResult
{
    int damage;
    bool defeated;
};
```

함수는 결과 구조체를 반환할 수 있다.

```cpp
AttackResult ResolveAttack(const Character& attacker, Character& defender)
{
    int damage = CalculateDamage(attacker, defender);
    ApplyDamage(defender, damage);
    return {damage, defender.hp == 0};
}
```

```cpp
AttackResult result = ResolveAttack(player, monster);
```

`int& outputDamage`, `bool& outputDefeated`처럼 출력 매개변수를 계속 추가하는 것보다 두 값이 하나의 공격 결과라는 관계가 드러난다.

출력 참조가 항상 잘못된 것은 아니다. 기존 버퍼를 채우거나 성공 여부와 결과를 분리하는 `Try` 패턴처럼 자연스러운 경우도 있다. 결과가 새로 생성되는 데이터인지, 호출자가 제공한 기존 객체를 수정하는지 구분한다.

## `T*`는 대상이 없을 수 있는 비소유 관계를 표현할 수 있다

포인터 매개변수는 `nullptr`로 대상의 부재를 표현할 수 있다.

```cpp
bool TryApplyBonus(Character* target, int bonusHp)
{
    if (target == nullptr)
    {
        return false;
    }

    int appliedBonus = bonusHp > 0 ? bonusHp : 0;
    target->hp += appliedBonus;
    return true;
}
```

호출자는 대상이 있을 때 주소를 전달한다.

```cpp
TryApplyBonus(&player, 10);
```

선택된 대상이 없다면 null 포인터를 전달할 수 있다.

```cpp
Character* selectedTarget = nullptr;
bool applied = TryApplyBonus(selectedTarget, 10);
```

이 인터페이스에서 `nullptr`은 오류로 만들어진 잘못된 주소가 아니라 “보너스를 받을 선택 대상이 없음”이라는 정상적인 입력 상태다. 함수는 이 상태를 검사하고 `false`로 결과를 알린다.

## 포인터 매개변수 자체도 값으로 전달된다

포인터 매개변수는 호출자의 포인터값으로 초기화된 별도 객체다.

```cpp
void SelectDefaultTarget(Character* target, Character& fallback)
{
    if (target == nullptr)
    {
        target = &fallback;
    }
}
```

함수 안에서 `target`을 바꿔도 호출자의 포인터는 변경되지 않는다.

```cpp
Character* selectedTarget = nullptr;
SelectDefaultTarget(selectedTarget, player);
```

호출 뒤에도 `selectedTarget`은 `nullptr`이다. 매개변수 포인터 복사본만 `player`를 가리키도록 바뀌었다.

대상을 선택해 반환하려면 포인터값을 반환하는 편이 직접적이다.

```cpp
Character* SelectDefaultTarget(Character* target, Character& fallback)
{
    return target != nullptr ? target : &fallback;
}
```

```cpp
selectedTarget = SelectDefaultTarget(selectedTarget, player);
```

포인터가 가리키는 객체를 수정하는 것과 포인터값 자체를 새 결과로 만드는 것을 구분한다.

## 읽기 전용 선택 대상은 `const T*`로 표현한다

대상이 없을 수 있지만 존재할 때 읽기만 한다면 상수 대상 포인터를 사용한다.

```cpp
void PrintTarget(const Character* target)
{
    if (target == nullptr)
    {
        std::cout << "No target\n";
        return;
    }

    std::cout << target->name << " HP: " << target->hp << '\n';
}
```

여기서 `target`의 타입은 `const Character*`다. 포인터 매개변수 자체는 다른 대상을 가리키도록 바꿀 수 있지만, 이 포인터를 통해 `Character`를 수정할 수 없다.

다음 글에서는 `const T*`, `T* const`, `const T* const`가 각각 어느 변경 권한을 제한하는지 더 자세히 다룬다.

## 원시 포인터와 참조는 보통 소유권을 넘기지 않는다

다음 두 함수는 호출 동안 객체를 관찰하거나 수정하지만 대상의 수명을 관리하지 않는다.

```cpp
void PrintCharacter(const Character& character);
bool TryApplyBonus(Character* target, int bonusHp);
```

이런 원시 참조와 포인터 매개변수는 일반적으로 비소유 관계를 표현하는 데 사용한다. 호출자가 대상 객체를 소유하고 함수가 사용하는 동안 수명을 보장한다.

동적 객체의 소유권을 함수에 넘겨야 한다면 소유권을 표현하는 타입을 사용한다.

```cpp
#include <memory>

void RegisterMonster(std::unique_ptr<Character> monster)
{
    // monster의 소유권을 저장하거나 함수 안에서 소비
}
```

호출자는 `std::move`로 소유권 이전을 명시한다.

```cpp
auto monster = std::make_unique<Character>(Character{"Slime", 30, 25, 5});
RegisterMonster(std::move(monster));
```

호출 뒤 `monster`는 더 이상 해당 객체를 소유하지 않는다. 정확한 moved-from 상태는 타입의 계약을 따라야 하며, `std::unique_ptr`은 이동 후 null이 된다.

원시 포인터 하나만 값으로 받으면서 “함수가 알아서 `delete`한다”는 숨은 규칙을 만들지 않는다. 소유권 이전은 타입과 함수 이름에서 분명하게 표현한다.

## 참조가 포인터와 같은 기계 코드라는 보장은 없다

참조는 구현 수준에서 주소를 이용해 처리되는 경우가 많고, 단순한 함수에서는 포인터와 비슷한 기계 코드가 만들어질 수 있다. 하지만 C++ 표준은 참조가 반드시 포인터와 같은 크기의 저장 공간을 가지거나 동일한 명령으로 구현돼야 한다고 정하지 않는다.

```cpp
void SetByPointer(int* value)
{
    if (value != nullptr)
    {
        *value = 10;
    }
}

void SetByReference(int& value)
{
    value = 10;
}
```

두 함수는 계약이 다르다.

- 포인터 버전은 대상이 없을 수 있다.
- 참조 버전은 호출자가 유효한 대상을 제공해야 한다.

컴파일러가 같은 형태의 기계 코드를 생성할 수 있다는 사실은 두 인터페이스가 같은 의미라는 뜻이 아니다. 호출자가 지켜야 하는 조건을 기준으로 선택한다.

## 포인터와 참조가 항상 더 빠른 것은 아니다

값 전달 비용을 다음처럼 단순 계산할 수는 없다.

```text
값 전달 비용 = 항상 sizeof(T)
참조 전달 비용 = 항상 포인터 크기
```

실제 비용에는 더 많은 요소가 영향을 준다.

- 타입의 복사·이동 생성자가 어떤 작업을 하는가?
- 호출이 인라인되는가?
- 복사 생략이 적용되는가?
- 값이 레지스터에 전달될 수 있는가?
- 간접 접근과 메모리 지연이 발생하는가?
- 여러 포인터와 참조의 별칭 가능성이 최적화를 제한하는가?
- 함수가 결국 독립된 복사본을 만들어야 하는가?

작은 `int` 하나를 `const int&`로 받으면 복사를 줄였다고 말하기 어렵다. 값은 레지스터로 직접 전달될 수 있지만 참조는 원본 객체에 대한 간접 접근 관계를 유지해야 할 수 있다.

반대로 복사 비용이 큰 객체를 잠시 읽기만 한다면 `const T&`가 불필요한 복사를 피하는 좋은 출발점이다. 다만 타입 이름이나 겉보기 크기만으로 실제 병목이라고 단정하지 않고 필요한 구간을 측정한다.

## 객체 크기만으로 복사 비용을 판단하지 않는다

큰 배열을 직접 멤버로 가진 타입은 복사 시 많은 데이터를 복사할 수 있다.

```cpp
struct LargeData
{
    int values[1024];
};
```

반면 객체 자체는 작아 보여도 복사 생성자가 동적 자원을 복제하면 비용이 클 수 있다. 반대로 내부 자원을 공유하는 핸들 타입은 객체 크기보다 참조 횟수 갱신이나 동기화 비용이 중요할 수 있다.

따라서 “몇 바이트보다 크면 무조건 참조” 같은 기준만으로 인터페이스를 정하지 않는다.

1. 복사가 함수 의미에 맞는가?
2. 타입이 실제로 복사 가능하고 복사 비용은 어떤가?
3. 함수가 복사본을 수정하거나 저장해야 하는가?
4. 호출 빈도와 측정된 비용이 중요한가?

계약을 먼저 정한 뒤 성능 특성을 확인한다.

## 참조와 포인터도 대상 수명을 연장하지 않는다

함수에 포인터나 참조를 전달해도 대상 객체의 수명이 자동으로 늘어나지 않는다.

```cpp
const Character* SavedTarget = nullptr;

void SaveTarget(const Character& target)
{
    SavedTarget = &target;
}
```

지역 객체를 전달한 뒤 그 객체의 블록이 끝나면 `SavedTarget`은 댕글링 포인터가 된다.

```cpp
{
    Character monster{"Slime", 30, 25, 5};
    SaveTarget(monster);
}

// SavedTarget이 가리키던 monster의 수명은 끝났다.
```

매개변수 선언만으로 함수가 참조나 포인터를 호출 이후까지 보관하는지 알기 어려울 수 있다. 저장하는 함수라면 이름과 문서, 소유 타입을 통해 장기 수명 요구사항을 분명하게 만든다.

호출 동안만 빌리는 인터페이스와 호출 뒤에도 보관하는 인터페이스를 같은 방식으로 취급하지 않는다.

## 전체 예제에서 역할마다 다른 계약을 사용한다

Text RPG의 캐릭터 생성, 공격과 선택적 회복을 각 역할에 맞는 인터페이스로 구성한다.

```cpp
#include <algorithm>
#include <iostream>

struct Character
{
    const char* name;
    int hp;
    int maxHp;
    int attack;
    int defence;
};

struct AttackResult
{
    int damage;
    bool defeated;
};

Character CreateCharacter(const char* name, int hp, int attack, int defence)
{
    return {name, hp, hp, attack, defence};
}

int CalculateDamage(const Character& attacker, const Character& defender)
{
    return std::max(0, attacker.attack - defender.defence);
}

void ApplyDamage(Character& target, int damage)
{
    int appliedDamage = std::max(0, damage);
    target.hp = std::max(0, target.hp - appliedDamage);
}

AttackResult ResolveAttack(const Character& attacker, Character& defender)
{
    int damage = CalculateDamage(attacker, defender);
    ApplyDamage(defender, damage);
    return {damage, defender.hp == 0};
}

bool TryHeal(Character* target, int amount)
{
    if (target == nullptr)
    {
        return false;
    }

    int healing = std::max(0, amount);
    target->hp = std::min(target->maxHp, target->hp + healing);
    return true;
}

void PrintCharacter(const Character& character)
{
    std::cout << character.name << " HP: " << character.hp << " / " << character.maxHp << '\n';
}

int main()
{
    Character player = CreateCharacter("Player", 100, 25, 10);
    Character monster = CreateCharacter("Slime", 40, 15, 5);

    AttackResult result = ResolveAttack(player, monster);
    std::cout << "Damage: " << result.damage << '\n';
    PrintCharacter(monster);

    Character* healingTarget = result.defeated ? nullptr : &monster;

    if (TryHeal(healingTarget, 10))
    {
        PrintCharacter(*healingTarget);
    }
    else
    {
        std::cout << "No healing target\n";
    }
}
```

각 함수의 타입에서 요구사항을 읽을 수 있다.

| 함수 | 선택한 형태 | 이유 |
| :--- | :--- | :--- |
| `CreateCharacter` | 값 반환 | 새 캐릭터 객체를 만든다. |
| `CalculateDamage` | `const Character&` | 두 필수 대상을 읽기만 한다. |
| `ApplyDamage` | `Character&` | 필수 대상 원본을 변경한다. |
| `ResolveAttack` | 상수 참조 + 비상수 참조 | 공격자는 읽고 방어자는 수정한다. |
| `TryHeal` | `Character*` | 회복 대상이 없을 수 있고, 있으면 수정한다. |
| `PrintCharacter` | `const Character&` | 필수 대상을 읽기만 한다. |
| `AttackResult` | 값 반환 | 새로 만들어진 두 결과를 하나로 묶는다. |

이 코드는 각 인터페이스의 계약을 비교하기 위한 예제다. 실제 실행 결과를 확인했다고 가정하지 않으며, 정수 범위를 벗어나는 능력치나 턴 진행 같은 게임 규칙은 포함하지 않았다.

`TryHeal`의 덧셈은 현재 예제의 작은 양수 범위를 전제로 한다. 외부 입력으로 매우 큰 값을 받을 수 있다면 덧셈 전에 표현 범위를 검사해야 한다.

## 매개변수 타입을 선택할 때 확인할 순서

함수 매개변수를 정할 때 다음 질문을 순서대로 확인한다.

1. 함수가 새 결과를 만드는가, 기존 객체를 변경하는가?
2. 함수에 대상이 반드시 필요한가, 없을 수도 있는가?
3. 대상의 원본을 수정해야 하는가?
4. 함수 내부에서 독립된 복사본이 필요한가?
5. 함수가 인자를 호출 이후까지 저장하거나 소유하는가?
6. 포인터나 참조 대상의 수명을 누가 보장하는가?
7. 타입의 실제 복사·이동 의미와 비용은 무엇인가?
8. 성능 차이가 중요하다는 측정 결과가 있는가?

좋은 출발점을 정리하면 다음과 같다.

| 요구사항 | 우선 검토할 형태 |
| :--- | :--- |
| 작고 독립적인 입력값 | `T` |
| 내부에서 복사본을 수정하거나 소유할 입력 | `T` 후 필요하면 이동 |
| 반드시 존재하며 읽기만 할 대상 | `const T&` |
| 반드시 존재하며 수정할 대상 | `T&` |
| 없을 수 있으며 읽기만 할 비소유 대상 | `const T*` |
| 없을 수 있으며 수정할 비소유 대상 | `T*` |
| 새로 생성한 결과 하나 | 반환값 `T` |
| 서로 관련된 여러 결과 | 결과 구조체 반환 |
| 동적 객체의 독점 소유권 이전 | `std::unique_ptr<T>` 값 전달 |

이는 절대 규칙이 아니라 인터페이스 검토를 시작할 기준이다. 타입 특성, 기존 API와 수명 설계에 따라 다른 선택이 더 자연스러울 수 있다.

## 다음 학습: `const`가 제한하는 변경 경로

값, 포인터와 참조는 복사 여부만 다르게 표현하는 문법이 아니다. 대상의 필수 여부, 원본 수정, null 가능성과 소유 관계를 함수 선언에 기록한다. 포인터나 참조가 복사를 피할 수 있어도 대상 수명을 연장하지 않으며 항상 더 빠르다는 보장도 없다.

다음 글에서는 `const T&`, `const T*`, `T* const`, `const T* const`를 비교한다. `const`가 객체 전체를 영원히 불변으로 만드는 것이 아니라 특정 이름이나 포인터를 통한 변경 권한을 제한한다는 점을 코드로 확인한다.
