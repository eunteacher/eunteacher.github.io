정수, 실수와 문자열을 출력하는 함수의 동작이 모두 같아도 타입마다 오버로드를 작성하면 코드가 반복된다. 두 값을 더하는 함수도 `int`, `float`, `double` 버전의 본문이 같다면 타입만 달라질 뿐 알고리즘은 하나다.

함수 템플릿(Function template)은 타입을 매개변수로 받아 함수 집합을 만드는 규칙이다. 모든 타입을 무조건 처리하는 함수가 아니라, 템플릿 본문에 필요한 연산을 지원하는 타입에 대해 구체적인 함수가 만들어진다.

## 반복되는 타입 자리를 템플릿 매개변수로 바꾼다

타입만 다른 출력 함수들이 있다.

```cpp
void Print(int value)
{
    std::cout << value << '\n';
}

void Print(float value)
{
    std::cout << value << '\n';
}

void Print(double value)
{
    std::cout << value << '\n';
}
```

공통 본문에서 달라지는 타입을 `T`라는 템플릿 매개변수로 표현한다.

```cpp
template <typename T>
void Print(const T& value)
{
    std::cout << value << '\n';
}
```

`typename T`는 `T`가 타입을 나타내는 템플릿 매개변수라는 뜻이다. 같은 위치에서 `class T`라고 작성해도 의미는 같다.

```cpp
template <class T>
void Print(const T& value);
```

`T`라는 이름에는 특별한 기능이 없다. `ValueType`처럼 역할이 드러나는 이름도 사용할 수 있지만 짧은 범위의 대표 타입에는 `T`가 널리 쓰인다.

## 호출 인자에서 템플릿 타입을 추론한다

템플릿 인자를 직접 적지 않아도 함수 인자에서 `T`를 추론할 수 있다.

```cpp
Print(50);          // T는 int
Print(50.0f);       // T는 float
Print(50.0);        // T는 double
Print("Hello");     // 배열 타입과 참조 추론 규칙이 적용됨
```

이를 템플릿 인자 추론(Template argument deduction)이라고 한다. 컴파일러는 함수 매개변수 형태와 호출 인자의 타입을 비교해 `T`를 결정한다.

현재 매개변수는 `const T&`이므로 문자열 리터럴의 배열 타입 정보도 보존될 수 있다. 매개변수를 값 `T value`로 받으면 함수 매개변수 추론 과정에서 배열이 포인터로 조정되는 차이가 있다.

타입을 명시할 수도 있다.

```cpp
Print<int>(50);
Print<double>(50);
```

두 번째 호출은 정수 50을 `double` 매개변수에 맞게 변환해 `Print<double>`을 호출한다. 추론 결과가 의도와 다르거나 템플릿 인자를 인자만으로 추론할 수 없을 때 명시적으로 지정할 수 있다.

## 템플릿은 호출에 필요한 구체 함수를 만든다

다음 함수 템플릿이 있다.

```cpp
template <typename T>
T Add(T left, T right)
{
    return left + right;
}
```

호출된 타입에 맞는 함수가 인스턴스화(Instantiation)된다.

```cpp
int integerSum = Add(1, 2);
float floatSum = Add(1.5f, 2.5f);
```

개념적으로 다음과 같은 구체 함수가 필요해진다.

```cpp
int Add<int>(int left, int right);
float Add<float>(float left, float right);
```

소스 코드에 두 함수 본문을 직접 복사한다는 단순한 텍스트 치환은 아니다. 컴파일러는 각 템플릿 인자 조합에 대해 타입 검사를 수행하고 필요한 구체 함수를 생성한다.

같은 특수화가 여러 곳에서 필요할 때 컴파일러와 링커가 실제 코드 생성을 처리하는 방식은 구현과 최적화 설정에 따라 달라질 수 있다. “호출 횟수만큼 함수 코드가 무조건 복제된다”라고 단정하지 않는다.

## 같은 T를 사용하면 두 인자에서 같은 타입이 추론돼야 한다

`Add`의 두 매개변수는 모두 `T`다.

```cpp
template <typename T>
T Add(T left, T right);
```

같은 타입끼리 호출하면 추론이 명확하다.

```cpp
Add(1, 2);         // T = int
Add(1.0, 2.0);     // T = double
```

서로 다른 타입을 전달하면 두 인자가 서로 다른 `T`를 요구해 추론이 실패할 수 있다.

```cpp
// Add(1, 2.5); // 첫 인자는 int, 두 번째는 double을 요구
```

의도한 공통 타입을 명시할 수 있다.

```cpp
double sum = Add<double>(1, 2.5);
```

또는 템플릿 자체가 서로 다른 두 타입을 받도록 설계할 수 있다.

```cpp
template <typename Left, typename Right>
auto AddDifferent(Left left, Right right)
{
    return left + right;
}
```

두 타입을 허용하면 반환 타입과 변환 규칙이 더 복잡해진다. 요구사항이 같은 타입의 덧셈인지 혼합 타입 연산인지 먼저 정하고 템플릿 매개변수 수를 선택한다.

## auto 반환 타입은 실제 연산 결과 타입을 따를 수 있다

혼합 타입 덧셈에서는 결과가 왼쪽이나 오른쪽 타입과 다를 수 있다.

```cpp
template <typename Left, typename Right>
auto AddDifferent(const Left& left, const Right& right)
{
    return left + right;
}
```

```cpp
auto result = AddDifferent(1, 2.5); // 결과 타입은 double
```

C++14 이후 일반 함수의 `auto` 반환 타입은 반환 표현식에서 추론될 수 있다. 하지만 모든 분기의 반환 타입이 추론 규칙에 맞아야 하고 `left + right`가 유효해야 한다.

`auto`를 쓴다고 결과 타입에 대한 설계 책임이 사라지지는 않는다. 정수와 포인터처럼 문법적으로 가능한 조합이 도메인 의미에 맞는지도 확인한다.

## 템플릿 본문이 사용하는 연산이 타입의 요구사항이다

`Print`는 출력 스트림의 `<<` 연산을 사용한다.

```cpp
template <typename T>
void Print(const T& value)
{
    std::cout << value << '\n';
}
```

따라서 `T`는 `std::cout << value`가 유효한 타입이어야 한다. 직접 만든 `Knight`는 출력 연산을 제공하지 않으면 이 템플릿을 인스턴스화할 수 없다.

```cpp
class Knight
{
public:
    int Hp() const
    {
        return 100;
    }
};

// Print(Knight{}); // operator<<가 없어 오류
```

출력 의미가 자연스럽다면 스트림 연산자를 제공할 수 있다.

```cpp
std::ostream& operator<<(std::ostream& output, const Knight& knight)
{
    return output << "Knight HP: " << knight.Hp();
}
```

이제 일반 `Print` 템플릿을 그대로 사용할 수 있다.

```cpp
Print(Knight{});
```

템플릿은 타입만 맞으면 모든 작업을 자동으로 만들어 주지 않는다. 본문이 요구하는 연산을 타입이 제공해야 한다.

## 오류는 해당 타입으로 인스턴스화할 때 드러날 수 있다

템플릿을 선언했지만 아직 특정 타입으로 사용하지 않았다면 타입에 의존하는 표현식의 오류는 인스턴스화 시점에 드러날 수 있다.

```cpp
struct Item
{
};

template <typename T>
T Multiply(T left, T right)
{
    return left * right;
}

// Multiply(Item{}, Item{}); // Item에는 operator*가 없음
```

컴파일 오류가 호출 위치와 템플릿 본문을 함께 가리킬 수 있어 처음에는 메시지가 길게 보인다. 다음 순서로 읽는다.

```text
1. 어떤 템플릿 인자로 인스턴스화했는가?
2. 템플릿 본문의 어느 표현식이 실패했는가?
3. 전달 타입이 필요한 연산과 변환을 제공하는가?
4. 애초에 그 타입을 해당 알고리즘에 전달하는 것이 의미상 맞는가?
```

오류를 없애기 위해 관련 없는 연산자를 억지로 추가하지 않는다.

## 여러 템플릿 매개변수는 서로 독립적인 역할을 가진다

두 값을 한 줄에 출력한다.

```cpp
template <typename First, typename Second>
void PrintPair(const First& first, const Second& second)
{
    std::cout << first << ' ' << second << '\n';
}
```

각 인자에서 타입을 독립적으로 추론한다.

```cpp
PrintPair(10, "Gold");
PrintPair(Knight{}, 3);
```

`First`와 `Second`가 같을 필요는 없지만 두 타입 모두 각 출력 표현식을 지원해야 한다. 템플릿 매개변수를 늘릴수록 허용되는 조합은 많아지고 오류 조합도 많아질 수 있으므로 알고리즘이 실제로 요구하는 관계만 일반화한다.

## 함수 템플릿도 일반 함수와 함께 오버로드될 수 있다

특정 타입에 별도 동작을 제공하기 위해 일반 함수 오버로드를 추가할 수 있다.

```cpp
template <typename T>
void Print(const T& value)
{
    std::cout << value << '\n';
}

void Print(const Knight& knight)
{
    std::cout << "Knight HP: " << knight.Hp() << '\n';
}
```

`Print(knight)` 호출의 후보에는 함수 템플릿과 일반 함수가 함께 들어가며 오버로드 해석 규칙으로 가장 적합한 함수를 선택한다.

원본은 명시적 특수화를 사용한다.

```cpp
template <>
void Print<Knight>(const Knight& knight)
{
    std::cout << knight.Hp() << '\n';
}
```

명시적 특수화는 특정 템플릿 인자에 대한 구현을 별도로 정의하는 기능이다. 하지만 함수 템플릿 특수화는 오버로드와 상호작용하는 규칙이 복잡해질 수 있다. 단순히 한 타입만 다른 동작을 원한다면 일반 함수 오버로드가 더 명확한 경우가 많다.

타입 자체의 자연스러운 출력 표현을 제공하려는 목적이라면 앞서 본 `operator<<`도 선택지다. 어디에서 차이를 책임질지 타입의 의미를 기준으로 결정한다.

## 값·참조 매개변수에 따라 복사와 추론이 달라진다

값으로 받으면 호출 인자가 함수 매개변수로 복사되거나 이동된다.

```cpp
template <typename T>
void Process(T value);
```

읽기만 하고 큰 객체의 복사를 피하려면 `const T&`가 자연스러울 수 있다.

```cpp
template <typename T>
void Process(const T& value);
```

하지만 작은 정수에도 무조건 참조가 더 빠른 것은 아니며 함수가 값을 소유해야 한다면 값 전달이 맞다. 매개변수 형태는 복사 비용뿐 아니라 배열과 함수 타입의 조정, `const`와 참조 추론 결과에도 영향을 준다.

완벽한 전달과 참조 축약 규칙은 이후 전달 참조 편에서 자세히 다룬다. 지금은 템플릿에서도 일반 함수와 마찬가지로 함수가 값을 소유할지, 읽기만 할지, 수정할지를 먼저 정한다.

## 템플릿 정의는 보통 헤더에서 볼 수 있어야 한다

일반 함수는 헤더에 선언하고 `.cpp`에 정의해도 다른 번역 단위에서 호출할 수 있다. 함수 템플릿은 사용하는 타입으로 인스턴스화하는 위치에서 보통 전체 정의를 볼 수 있어야 한다.

```cpp
// Math.h
template <typename T>
T Add(T left, T right)
{
    return left + right;
}
```

선언만 헤더에 두고 템플릿 정의를 일반 `.cpp`로 숨기면 다른 번역 단위가 필요한 특수화를 만들지 못해 링크 오류로 이어질 수 있다.

사용할 타입 조합이 고정돼 있다면 `.cpp`에서 명시적으로 인스턴스화하는 설계도 가능하다. 일반적인 범용 템플릿은 정의를 헤더 또는 헤더에서 포함하는 구현 파일에 둔다.

이 때문에 템플릿 구현 변경은 해당 헤더를 포함하는 번역 단위의 재컴파일 범위를 넓힐 수 있다.

## C++20 제약 조건은 요구사항을 인터페이스에 표현할 수 있다

기본 템플릿은 본문에서 잘못된 연산을 만났을 때 오류가 드러난다. C++20에서는 `requires`와 개념(Concept)을 이용해 허용할 타입 조건을 선언에 표현할 수 있다.

```cpp
#include <concepts>

template <typename T>
requires std::integral<T>
T AddIntegral(T left, T right)
{
    return left + right;
}
```

이 함수는 정수 계열 타입만 후보가 된다.

```cpp
AddIntegral(1, 2);
// AddIntegral(1.5, 2.5); // integral 조건을 만족하지 않음
```

제약은 템플릿이 요구하는 의미를 정확히 표현할 때 유용하다. 단순히 컴파일 오류를 짧게 만들기 위해 실제 요구보다 지나치게 강한 조건을 붙이지 않는다. 사용자 정의 타입의 덧셈도 허용하려면 “정수 타입”보다 `left + right` 표현식의 유효성을 요구하는 개념이 더 적합할 수 있다.

## 전체 구현

출력, 같은 타입의 덧셈, 혼합 타입 덧셈과 두 타입 출력을 검증한다.

```cpp
#include <cassert>
#include <iostream>
#include <string>
#include <type_traits>

template <typename T>
void Print(const T& value)
{
    std::cout << value << '\n';
}

template <typename T>
T Add(T left, T right)
{
    return left + right;
}

template <typename Left, typename Right>
auto AddDifferent(const Left& left, const Right& right)
{
    return left + right;
}

template <typename First, typename Second>
void PrintPair(const First& first, const Second& second)
{
    std::cout << first << ' ' << second << '\n';
}

class Knight
{
public:
    explicit Knight(int hp) : hp_(hp)
    {
    }

    int Hp() const
    {
        return hp_;
    }

private:
    int hp_;
};

std::ostream& operator<<(std::ostream& output, const Knight& knight)
{
    return output << "Knight HP: " << knight.Hp();
}

void VerifyTemplates()
{
    int integerSum = Add(1, 2);
    double doubleSum = Add(1.5, 2.5);
    double mixedSum = AddDifferent(1, 2.5);

    assert(integerSum == 3);
    assert(doubleSum == 4.0);
    assert(mixedSum == 3.5);
    static_assert(std::is_same_v<decltype(mixedSum), double>);

    std::string first = "Hello, ";
    std::string second = "Template";
    assert(Add(first, second) == "Hello, Template");

    Knight knight{150};
    Print(knight);
    PrintPair("Item count:", 3);

    std::cout << "Integer sum: " << integerSum << '\n';
    std::cout << "Mixed sum: " << mixedSum << '\n';
}

int main()
{
    VerifyTemplates();
}
```

실행 결과는 다음과 같다.

```text
Knight HP: 150
Item count: 3
Integer sum: 3
Mixed sum: 3.5
```

`Add`는 두 인자의 타입이 같을 때 해당 타입으로 인스턴스화된다. `std::string`도 `operator+`를 제공하므로 같은 함수 템플릿을 사용할 수 있다.

`AddDifferent(1, 2.5)`는 서로 다른 타입을 받고 실제 덧셈 표현식의 결과인 `double`을 반환한다. `static_assert`로 반환 타입이 `double`인지 컴파일 시점에 확인한다.

`Knight`는 스트림 출력 연산자를 제공하므로 별도 `Print<Knight>` 특수화 없이 일반 출력 템플릿에 참여한다.

## 함수 템플릿을 검토할 때 확인할 기준

1. 타입만 다르고 알고리즘이 실제로 같은 코드인가?
2. 하나의 `T`가 모든 매개변수에서 같은 타입이어야 하는가?
3. 혼합 타입을 허용한다면 반환 타입과 변환 의미가 자연스러운가?
4. 템플릿 본문이 타입에 요구하는 연산을 설명할 수 있는가?
5. 관련 없는 타입에 연산자를 억지로 추가해 템플릿에 맞추고 있지 않은가?
6. 일반 함수 오버로드, 명시적 특수화와 타입의 `operator<<` 중 책임 위치가 적절한가?
7. 값과 참조 매개변수가 복사·수정·수명 요구에 맞는가?
8. 템플릿 정의가 인스턴스화 위치에서 보이는가?
9. 명시적 템플릿 인자가 의도하지 않은 변환을 숨기지 않는가?
10. C++20 제약 조건이 실제 요구보다 지나치게 강하거나 약하지 않은가?

함수 템플릿의 목표는 모든 함수를 템플릿으로 바꾸는 것이 아니다. 타입과 무관한 하나의 알고리즘을 표현하고, 그 알고리즘에 필요한 연산을 제공하는 타입에만 재사용하는 것이다.
