컨테이너는 데이터를 저장하고 수명을 관리한다. 알고리즘은 그 데이터 범위에서 찾기, 세기, 조건 검사, 변환과 정렬 같은 작업을 수행한다.

표준 알고리즘을 사용하면 컨테이너별로 같은 반복문을 다시 작성하지 않아도 된다. 하지만 함수 이름만 외우면 `end()` 검사 누락, 술어의 의미 반전, `remove` 뒤 크기가 줄었다는 오해처럼 미묘한 오류가 생길 수 있다.

이번 글에서는 `find`, `count_if`, `all_of`, `transform`, `sort`, `remove_if`를 중심으로 **반복자 범위와 반환값이 무엇을 의미하는지** 정리한다.

## 알고리즘은 반열린 반복자 범위를 받는다

많은 표준 알고리즘은 다음 형태의 범위를 받는다.

```text
[first, last)
```

`first`가 가리키는 요소는 포함하고 `last`가 가리키는 위치는 포함하지 않는다. 컨테이너 전체라면 `begin()`과 `end()`를 전달한다.

```cpp
std::vector<int> values{10, 20, 30, 40};
auto it = std::find(values.begin(), values.end(), 30);
```

```text
begin()                              end()
   ↓                                   ↓
 [10] [20] [30] [40] [범위 밖 경계]
  └──────── 검색 범위 ────────┘
```

부분 범위도 같은 규칙으로 표현할 수 있다.

```cpp
auto it = std::find(values.begin() + 1, values.end() - 1, 20);
```

이 검색 범위에는 20과 30만 포함된다. 두 반복자는 같은 유효 범위에서 왔고 `first`부터 `last`까지 이동할 수 있어야 한다.

## find는 값을 찾고 find_if는 조건을 찾는다

특정 값과 같은 첫 요소를 찾을 때는 `find`를 사용한다.

```cpp
auto it = std::find(values.begin(), values.end(), 30);

if (it != values.end())
{
    std::cout << "Found: " << *it << '\n';
}
```

찾지 못하면 두 번째 인자로 전달한 끝 반복자를 반환한다. 컨테이너 전체를 검색했다면 `values.end()`와 비교한 뒤 역참조한다.

값의 배수처럼 조건으로 찾을 때는 `find_if`에 술어(predicate)를 전달한다.

```cpp
auto divisibleByEleven = std::find_if(values.begin(), values.end(), [](int value)
{
    return value % 11 == 0;
});
```

술어는 현재 요소가 원하는 조건을 만족하면 `true`, 아니면 `false`를 반환한다. 함수 이름과 반환 조건이 일치해야 코드를 읽는 사람이 결과를 반대로 이해하지 않는다.

원본의 수동 풀이에는 다음 조건이 있다.

```cpp
int number = 11;

// if ((data % 11) == number)
```

11로 나눈 나머지는 0부터 10이므로 11과 같을 수 없다. “11로 나누어떨어지는가?”는 다음 조건이다.

```cpp
data % number == 0
```

## 컨테이너 멤버 탐색이 더 적합한 경우가 있다

표준 알고리즘 `find`는 범위를 앞에서부터 선형 탐색한다. 벡터나 리스트에서 값을 찾는 일반적인 동작에는 자연스럽다.

정렬 연관 컨테이너는 키 구조를 활용하는 멤버 `find`를 우선 사용한다.

```cpp
std::map<int, std::string> players;
auto it = players.find(100);
```

`players.find(100)`은 O(log n)이지만 다음 코드는 모든 요소를 차례로 확인하므로 O(n)이다.

```cpp
auto it = std::find_if(players.begin(), players.end(), [](const auto& entry)
{
    return entry.first == 100;
});
```

알고리즘이 범용이라는 이유만으로 컨테이너가 제공하는 더 적합한 멤버 함수를 무시하지 않는다.

## count_if는 조건을 만족하는 요소 수를 센다

특정 값의 개수는 `count`, 조건을 만족하는 요소 수는 `count_if`로 센다.

```cpp
std::vector<int> values{1, 4, 3, 5, 8, 2, 11};

auto oddCount = std::count_if(values.begin(), values.end(), [](int value)
{
    return value % 2 != 0;
});

assert(oddCount == 4);
```

원본의 `IsOdd`는 이름과 달리 `value % 2 == 0`을 반환해 짝수를 센다. 술어를 별도 함수나 함수 객체로 만들 때도 이름과 조건이 같은지 확인한다.

```cpp
struct IsOdd
{
    bool operator()(int value) const
    {
        return value % 2 != 0;
    }
};
```

개수의 반환 타입은 범위의 반복자 차이 타입이다. 컨테이너 크기와 비교할 때 무조건 `int`에 담기보다 `auto`를 사용하면 불필요한 축소를 피할 수 있다.

## all_of, any_of, none_of는 질문의 범위를 표현한다

세 함수는 같은 술어를 서로 다른 방식으로 검사한다.

```cpp
bool allPositive = std::all_of(values.begin(), values.end(), [](int value)
{
    return value > 0;
});

bool hasEven = std::any_of(values.begin(), values.end(), [](int value)
{
    return value % 2 == 0;
});

bool hasNoNegative = std::none_of(values.begin(), values.end(), [](int value)
{
    return value < 0;
});
```

```text
all_of  : 모든 요소가 조건을 만족하는가?
any_of  : 하나라도 조건을 만족하는가?
none_of : 조건을 만족하는 요소가 하나도 없는가?
```

빈 범위에서는 수학적인 전칭·존재 규칙에 따라 결과가 정해진다.

```cpp
std::vector<int> empty;

assert(std::all_of(empty.begin(), empty.end(), [](int) { return false; }));
assert(!std::any_of(empty.begin(), empty.end(), [](int) { return true; }));
assert(std::none_of(empty.begin(), empty.end(), [](int) { return true; }));
```

즉 빈 범위의 `all_of`와 `none_of`는 `true`, `any_of`는 `false`다. “모든 플레이어가 준비됐는가?” 같은 조건에서 빈 방을 어떻게 처리할지는 알고리즘 호출 전 별도의 게임 규칙으로 판단할 수 있다.

## for_each와 transform은 의도가 다르다

모든 요소에 작업을 실행하려면 `for_each`를 사용할 수 있다.

```cpp
std::for_each(values.begin(), values.end(), [](int& value)
{
    value *= 3;
});
```

단순한 범위 순회는 범위 기반 `for`문이 더 읽기 쉬울 수도 있다.

```cpp
for (int& value : values)
{
    value *= 3;
}
```

입력을 다른 값으로 변환해 출력 범위에 저장한다는 의도에는 `transform`이 더 직접적이다.

```cpp
std::vector<int> tripled(values.size());

std::transform(values.begin(), values.end(), tripled.begin(), [](int value)
{
    return value * 3;
});
```

출력 컨테이너에 공간이 없다면 `std::back_inserter`를 사용할 수 있다.

```cpp
std::vector<int> tripled;
tripled.reserve(values.size());

std::transform(values.begin(), values.end(), std::back_inserter(tripled), [](int value)
{
    return value * 3;
});
```

원본의 `MulAll`은 벡터를 참조로 받은 뒤 `pop_back()`으로 원본을 비우고, 꺼낸 값을 새 벡터에 넣어 결과 순서까지 반대로 만든다. 단순 변환이 목적이라면 입력을 파괴하지 않고 원래 순서를 유지하는 편이 함수 이름과 자연스럽게 맞는다.

## 알고리즘마다 필요한 반복자 능력이 다르다

모든 알고리즘을 모든 컨테이너에 적용할 수 있는 것은 아니다.

`find`, `count_if`, `all_of` 같은 순차 검사 알고리즘은 한 방향 순회가 가능하면 사용할 수 있다.

```cpp
std::list<int> linked{3, 1, 2};
auto it = std::find(linked.begin(), linked.end(), 1);
```

`std::sort`는 위치를 임의로 이동하며 요소를 재배치하므로 임의 접근 반복자가 필요하다.

```cpp
std::vector<int> contiguous{3, 1, 2};
std::deque<int> segmented{3, 1, 2};

std::sort(contiguous.begin(), contiguous.end());
std::sort(segmented.begin(), segmented.end());
```

`std::list`의 반복자는 양방향 반복자이므로 `std::sort`에 전달할 수 없다. 리스트는 노드 연결을 활용하는 멤버 `sort()`를 제공한다.

```cpp
std::list<int> linked{3, 1, 2};
linked.sort();
```

알고리즘을 선택할 때 함수 이름뿐 아니라 필요한 반복자 종류와 컨테이너 전용 멤버가 있는지 확인한다.

## sort의 비교 함수도 strict weak ordering이 필요하다

기본 `sort`는 오름차순으로 정렬한다.

```cpp
std::sort(values.begin(), values.end());
```

내림차순 비교는 다음처럼 작성할 수 있다.

```cpp
std::sort(values.begin(), values.end(), [](int left, int right)
{
    return left > right;
});
```

비교 함수는 “left가 right보다 먼저 와야 하는가?”를 반환하며 strict weak ordering을 만족해야 한다. 같은 값에서 `true`가 되는 `left >= right` 같은 조건은 올바른 정렬 비교가 아니다.

기존의 동일한 상대 순서를 유지해야 한다면 `stable_sort`를 고려한다. 안정 정렬이 필요하지 않다면 `sort`가 기본 선택이다.

## remove는 컨테이너의 요소를 실제로 지우지 않는다

`std::remove`와 `std::remove_if`는 조건에 맞지 않는 요소를 범위 앞쪽으로 옮기고 새로운 논리적 끝을 반환한다.

```cpp
std::vector<int> values{1, 4, 3, 5, 8, 2};
auto newEnd = std::remove_if(values.begin(), values.end(), [](int value)
{
    return value % 2 != 0;
});
```

개념적으로 앞부분에는 남길 요소가 모인다.

```text
호출 전: [1][4][3][5][8][2]
호출 후: [4][8][2][?][?][?]
                    ↑
                  newEnd
```

`newEnd` 뒤 요소들은 여전히 컨테이너 안에 존재하지만 값은 명시되지 않은 상태다. 벡터의 `size()`도 그대로 6이다.

```cpp
assert(values.size() == 6);
```

실제로 크기를 줄이려면 반환된 범위를 `erase`한다.

```cpp
values.erase(newEnd, values.end());
assert(values.size() == 3);
```

이 두 단계가 erase-remove 관용구다.

```cpp
values.erase(std::remove_if(values.begin(), values.end(), [](int value)
{
    return value % 2 != 0;
}), values.end());
```

`remove_if`를 호출한 뒤 반환값을 버리고 다시 전체 범위에 같은 알고리즘을 호출하면 첫 호출이 남긴 꼬리 구간까지 다시 처리하게 된다. 한 번 호출한 반환값을 바로 `erase`에 전달한다.

## C++20에서는 erase와 erase_if를 사용할 수 있다

C++20은 여러 표준 컨테이너에 비멤버 `std::erase`, `std::erase_if`를 제공한다.

```cpp
std::size_t removed = std::erase_if(values, [](int value)
{
    return value % 2 != 0;
});
```

벡터에서는 내부적으로 필요한 이동과 실제 크기 축소까지 수행하고 삭제된 요소 수를 반환한다. 삭제 의도가 단순하다면 erase-remove 표현보다 짧고 실수할 여지가 적다.

연결 리스트에는 기존부터 멤버 `remove`, `remove_if`가 있다.

```cpp
std::list<int> linked{1, 2, 3, 4};
linked.remove_if([](int value) { return value % 2 == 0; });
```

컨테이너의 요소 제거 API와 값 재배치 알고리즘 `std::remove_if`를 이름만 보고 혼동하지 않는다.

## 술어는 질문 하나를 정확히 표현한다

술어는 이름, 매개변수와 반환 조건이 일치해야 한다.

```cpp
auto isOdd = [](int value)
{
    return value % 2 != 0;
};
```

가능하면 다음 성질을 지킨다.

- 같은 입력에는 같은 판단을 제공한다.
- 조건 검사 중 컨테이너 구조를 변경하지 않는다.
- 이름이 `IsOdd`라면 홀수에서 `true`를 반환한다.
- 캡처한 외부 객체의 수명이 알고리즘 호출 동안 유지된다.
- 정렬 비교 함수라면 strict weak ordering을 만족한다.

검사 술어 안에서 같은 컨테이너에 요소를 추가하거나 삭제하면 반복자가 무효가 될 수 있다. 구조 변경은 알고리즘이 끝난 뒤 별도 단계로 수행한다.

## 전체 구현

고정된 입력을 사용해 탐색, 조건 검사, 변환, 삭제와 정렬 결과를 검증한다.

```cpp
#include <algorithm>
#include <cassert>
#include <iostream>
#include <iterator>
#include <vector>

void VerifyQueries(const std::vector<int>& values)
{
    bool containsFour = std::find(values.begin(), values.end(), 4) != values.end();
    bool hasMultipleOfEleven = std::any_of(values.begin(), values.end(), [](int value) { return value % 11 == 0; });
    auto oddCount = std::count_if(values.begin(), values.end(), [](int value) { return value % 2 != 0; });
    bool allPositive = std::all_of(values.begin(), values.end(), [](int value) { return value > 0; });

    assert(containsFour);
    assert(hasMultipleOfEleven);
    assert(oddCount == 4);
    assert(allPositive);

    std::cout << std::boolalpha;
    std::cout << "Contains 4: " << containsFour << '\n';
    std::cout << "Has multiple of 11: " << hasMultipleOfEleven << '\n';
    std::cout << "Odd count: " << oddCount << '\n';
    std::cout << "All positive: " << allPositive << '\n';
}

void VerifyTransform(const std::vector<int>& values)
{
    std::vector<int> tripled;
    tripled.reserve(values.size());

    std::transform(values.begin(), values.end(), std::back_inserter(tripled), [](int value) { return value * 3; });

    assert(tripled.size() == values.size());

    std::cout << "Tripled:";

    for (int value : tripled)
    {
        std::cout << ' ' << value;
    }

    std::cout << '\n';
}

void VerifyEraseAndSort(std::vector<int> values)
{
    std::size_t removed = std::erase_if(values, [](int value) { return value % 2 != 0; });
    std::sort(values.begin(), values.end());

    assert(removed == 4);
    assert((values == std::vector<int>{2, 4, 8}));

    std::cout << "Removed odd values: " << removed << '\n';
    std::cout << "Even values:";

    for (int value : values)
    {
        std::cout << ' ' << value;
    }

    std::cout << '\n';
}

int main()
{
    const std::vector<int> values{1, 4, 3, 5, 8, 2, 11};

    VerifyQueries(values);
    VerifyTransform(values);
    VerifyEraseAndSort(values);
}
```

실행 결과는 다음과 같다.

```text
Contains 4: true
Has multiple of 11: true
Odd count: 4
All positive: true
Tripled: 3 12 9 15 24 6 33
Removed odd values: 4
Even values: 2 4 8
```

입력에는 값 4와 11이 있으므로 두 존재 검사가 모두 `true`다. 홀수는 1, 3, 5, 11로 네 개이며 모든 값은 양수다.

`transform`은 원본을 변경하지 않고 같은 순서의 세 배 값을 새 벡터에 저장한다. `erase_if`는 홀수 네 개를 실제로 제거하고 남은 짝수를 `sort`로 오름차순 정렬한다.

## 표준 알고리즘을 사용할 때 확인할 기준

1. 범위가 `[first, last)`이고 `last`를 역참조하지 않는가?
2. 탐색 결과를 끝 반복자와 비교한 뒤 사용하는가?
3. 술어 이름과 `true`를 반환하는 조건이 일치하는가?
4. 단순 조회를 위해 컨테이너 전체를 값으로 복사하지 않는가?
5. 변환 함수가 의도치 않게 원본을 비우거나 순서를 뒤집지 않는가?
6. 알고리즘이 요구하는 반복자 종류를 컨테이너가 제공하는가?
7. `list::sort`, `map::find`처럼 더 적합한 컨테이너 멤버가 있는가?
8. 정렬 비교 함수가 strict weak ordering을 만족하는가?
9. `remove`와 `remove_if`가 컨테이너 크기를 줄이지 않는다는 점을 아는가?
10. erase-remove에서는 알고리즘 반환값을 즉시 `erase`에 전달하는가?
11. C++20 환경이라면 단순 값 삭제에 `std::erase`와 `std::erase_if`가 더 명확한가?
12. 술어 안에서 같은 컨테이너를 변경해 반복자를 무효로 만들지 않는가?

표준 알고리즘의 장점은 반복문을 짧게 만드는 데만 있지 않다. 검색, 검사, 변환, 재배치라는 의도를 이름으로 드러내고, 반복자 범위를 통해 여러 컨테이너에 같은 동작을 적용하는 데 있다. 그만큼 범위의 끝과 반환값, 반복자 요구 조건을 정확히 읽어야 한다.

## 다음 학습: auto 타입 추론

다음 글에서는 긴 반복자 타입과 알고리즘 반환 타입을 간결하게 표현하는 `auto`를 살펴본다. 값, 참조, const가 추론 과정에서 어떻게 달라지는지와 `auto`가 코드를 짧게 만들면서도 타입 의미를 숨길 수 있는 경우를 정리한다.
