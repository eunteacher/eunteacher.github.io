# [C++] 포인터는 객체를 가리키는 값이다
메모리 주소를 저장하는 포인터 변수의 특성을 이해하고, 함수 호출 시 원본 데이터를 수정하기 위한 주소 전달 방식 분석

## 주소 얻기와 역참조하기

```cpp
#include <iostream>
using namespace std;

/**
 * 주소 전달 방식(Call by Address)을 이용한 값 수정 함수
 * @param hp 수정할 대상의 메모리 주소를 담는 포인터 바구니
 */
void SetHP(int* hp)
{
	// 포인터가 가리키는 주소로 가서 해당 메모리 공간에 100을 대입함
	*hp = 100;
}

int main()
{
#pragma region 포인터의 기본 개념
	// 1) 일반 변수 선언
	// - int 객체 number를 만들고 값 1로 초기화함
	// - 'number = 1'은 해당 주소에 1이라는 데이터를 직접 넣는 행위임
	int number = 1;

	// 2) 포인터 변수 선언 및 주소 할당
	// - TYPE* : 해당 타입의 데이터가 저장된 '주소'를 저장하는 변수임을 명시함
	// - &연산자 : 변수의 메모리 시작 주소를 추출함
	// - 포인터 크기는 구현에 따라 정해지며 sizeof로 확인할 수 있음
	int* ptr = &number;

	// 3) 역참조(Dereference) 연산
	// - *ptr : ptr에 저장된 주소번지로 직접 찾아가서 그곳에 담긴 값을 읽거나 씀
	int value = *ptr; // 주소의 값을 복사하여 value에 할당함
	*ptr = 2;        // 주소의 실제 데이터를 2로 변경함 (원본 number가 수정됨)

	cout << "역참조를 통한 값 확인 : " << *ptr << endl;
#pragma endregion

#pragma region 타입 불일치와 메모리 오염
	// 포인터의 타입은 가리키는 주소의 데이터를 '어떻게 해석할지' 결정하는 기준임
	// __int64(8바이트) 포인터로 int(4바이트) 주소를 강제 캐스팅하여 조작할 경우 위험함
	__int64* ptr2 = (__int64*)&number;

	// 4바이트 영역을 넘어 인접한 다른 메모리 영역까지 덮어쓰는 메모리 오염 발생 가능
	// *ptr2 = 0xAABBCCDDEEFF;
#pragma endregion

#pragma region 실전 활용: 원본 값 변경
	int hp = 10;

	// hp의 주소값을 전달하여 함수 내부에서 외부 지역 변수를 직접 수정하도록 유도함
	SetHP(&hp);

	cout << "SetHP 호출 후 원본 HP : " << hp << endl;
#pragma endregion

	return 0;
}
```

## 타입, 대상, 유효한 수명

### 변수와 포인터의 메모리 구조 비교
일반 변수가 데이터를 직접 담는 바구니라면, 포인터는 그 바구니가 위치한 메모리 상의 '주소'를 저장하는 특수한 바구니



| 구분 | 일반 변수 (Variable) | 포인터 변수 (Pointer) |
| :--- | :--- | :--- |
| **저장 데이터** | 실제 값 (Value) | 메모리 주소 (Address) |
| **변수 크기** | 데이터 타입(int, double 등)에 따라 상이함 | 아키텍처에 따라 고정됨 (32bit: 4B, 64bit: 8B) |
| **핵심 연산** | 값의 대입 및 산술 연산 | 주소 추출(`&`), 역참조(`*`) |

### 포인터 타입(Type) 선언의 목적
포인터 변수 자체의 크기는 주소 저장용으로 고정되어 있으나, 앞에 붙는 타입(int, float 등)은 가리키는 주소에 도달했을 때 데이터를 어떻게 해석하고 처리할지를 결정

* **해석의 기준**: 해당 주소로부터 몇 바이트를 읽어 들일지(Size)와 어떤 형식(정수/실수)으로 읽을지를 명시
* **타입 불일치 위험**: 가리키는 대상보다 큰 타입을 선언하여 조작할 경우, 인접한 메모리 영역을 침범하는 메모리 오염(Memory Corruption)이 발생할 수 있음

### 아키텍처별 포인터 크기 수식
포인터 크기를 단순히 CPU 주소 버스 폭과 동일하다고 일반화할 수는 없다. 데이터 포인터 종류와 구현에 따라 표현 방식이 다를 수 있으므로 대상 환경에서 `sizeof`로 확인한다.

$$S = B / 8 \text{ (bytes)}$$

* **32-bit 환경**: $32 / 8 = 4 \text{ bytes}$
* **64-bit 환경**: $64 / 8 = 8 \text{ bytes}$

## 역참조 전에 확인할 조건

### 핵심 요약 및 주의사항
* **원본 수정의 필요성**: 포인터나 비const 참조를 전달하면 함수가 호출자의 객체를 변경할 수 있다. 포인터는 “대상이 없을 수 있음”도 `nullptr`로 표현할 수 있다는 차이가 있다.
* **메모리 오염 경계**: 포인터 타입을 강제로 캐스팅하여 다른 크기의 데이터를 덮어쓰는 행위는 매우 위험함. 이는 프로그램의 예기치 않은 종료나 보안 취약점을 유발하는 주원인이 됨
* **역참조(Dereference)의 개념**: `*ptr` 연산은 "ptr에 적힌 주소로 가서 그곳의 문을 열어라"는 의미와 같으며, 이를 통해 실제 메모리 공간에 직접 접근하여 값을 수정

### Tip
* **nullptr 초기화**: 당장 가리킬 대상이 없다면 `nullptr`로 초기화한다. 하지만 null 검사만으로 충분하지 않으며 대상 객체가 이미 소멸한 댕글링 포인터도 역참조하면 안 된다.
* **const 활용**: 주소에 담긴 값을 수정하지 않고 참조만 할 계획이라면 `const int* ptr`과 같이 선언하여 코드의 안정성을 높이는 것이 권장
* **포인터 vs 참조**: C++에서는 포인터의 강력한 제어 능력과 변수의 사용 편의성을 결합한 참조(Reference, `&`) 문법을 제공함. 단순 원본 수정이 목적이라면 참조 사용을 우선적으로 고려하는 것이 유지보수에 유리
