# [C++] 문자는 숫자이고, 문자열은 바이트의 해석이다

문자가 깨지는 문제는 대개 `char`의 크기보다 **같은 바이트를 서로 다른 인코딩으로 해석한 것**에서 시작한다. 이 글에서는 문자, 코드 포인트, 인코딩, C++ 문자열을 서로 구분한다.

## 1. 먼저 구분할 네 가지

- **문자(Character)**: 사람이 인식하는 글자라는 추상적인 개념
- **코드 포인트(Code point)**: 유니코드가 문자에 부여한 번호. 예: `가`는 `U+AC00`
- **인코딩(Encoding)**: 코드 포인트를 바이트열로 바꾸는 규칙. UTF-8, UTF-16 등이 있다.
- **코드 유닛(Code unit)**: 각 인코딩이 데이터를 다루는 기본 단위

유니코드는 문자 집합과 규칙을 정의하는 표준이고, UTF-8과 UTF-16은 그 값을 저장하는 방식이다. 둘을 같은 뜻으로 부르면 문자열 문제를 추적하기 어려워진다.

## 2. `char`가 의미하는 것

`char`는 정확히 1바이트 크기의 정수형이다. 하지만 그 바이트가 ASCII인지 UTF-8의 일부인지는 타입만 보고 알 수 없다.

```cpp
#include <iostream>

int main()
{
    char letter = 'A';

    std::cout << letter << '\n';
    std::cout << static_cast<int>(letter) << '\n';
}
```

실행 환경이 ASCII와 호환되는 문자 집합을 사용한다면 두 번째 줄에는 보통 `65`가 출력된다. 다만 C++ 표준이 모든 실행 환경에서 ASCII 자체를 강제하는 것은 아니다.

## 3. C 문자열과 널 문자

문자열 리터럴은 마지막에 널 문자 `\0`이 붙은 배열이다.

```cpp
#include <cstddef>
#include <iostream>

int main()
{
    char text[] = "Hello";

    std::cout << sizeof(text) << '\n'; // 6: 문자 5개 + \0
}
```

`\0`은 숫자 0인 한 개의 문자다. 문자 `'0'`과는 다르다. `strlen` 같은 C 문자열 함수는 첫 번째 `\0`을 문자열의 끝으로 해석하므로, 버퍼에 종료 문자가 없다면 범위를 벗어나 읽을 수 있다.

## 4. `std::string`은 길이를 따로 관리한다

`std::string`은 단순히 널 문자를 찾는 방식이 아니라 길이도 함께 관리한다. 따라서 문자열 내부에 `\0`을 담을 수 있다.

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string text{"A\0B", 3};

    std::cout << text.size() << '\n';   // 3
    std::cout << text.c_str() << '\n';  // C 문자열로 보면 A에서 끝남
}
```

`std::string`이 인코딩을 자동으로 이해해 주는 것은 아니다. UTF-8을 담았다면 `size()`는 글자 수가 아니라 **바이트 수**를 반환한다.

## 5. UTF-8에서 글자 수와 바이트 수는 다르다

UTF-8은 코드 포인트 하나를 1~4바이트로 표현한다. 영문 `A`는 1바이트지만 한글 `가`는 3바이트다. 화면에서 보이는 한 글자도 여러 코드 포인트가 결합한 결과일 수 있으므로 다음 세 값은 서로 다를 수 있다.

- 바이트 수
- 코드 포인트 수
- 사용자가 보는 글자 수(그래핌 클러스터 수)

문자열을 바이트 중간에서 자르면 UTF-8 시퀀스가 망가질 수 있다. 사용자에게 보이는 글자 단위 편집은 유니코드 처리를 지원하는 라이브러리가 필요하다.

## 6. `wchar_t`는 고정된 유니코드 타입이 아니다

`wchar_t`의 크기는 플랫폼마다 다르다. Windows에서는 보통 2바이트라 UTF-16 코드 유닛과 잘 맞지만, Unix 계열에서는 보통 4바이트다. 따라서 `wchar_t` 하나가 언제나 문자 하나를 나타낸다고 가정하면 안 된다.

리터럴 접두사도 저장 단위를 구분해서 사용한다.

```cpp
const char* narrow = "text";
const wchar_t* wide = L"text";
const char16_t* utf16 = u"text";
const char32_t* utf32 = U"text";

// C++20부터 u8 문자열 리터럴의 원소 타입은 char8_t이다.
const char8_t* utf8 = u8"한글";
```

## 7. 한글이 깨질 때 확인할 경계

소스 파일, 컴파일러, 프로그램 내부 문자열, 터미널, 파일, 네트워크가 모두 같은 인코딩을 사용한다고 가정하면 안 된다. 특히 `wcout`이나 특정 로캘 이름 하나로 모든 환경의 출력 문제가 해결되지는 않는다.

1. 소스 파일이 어떤 인코딩으로 저장됐는가?
2. 컴파일러가 소스와 실행 문자 집합을 어떻게 해석하는가?
3. 외부 API가 UTF-8, UTF-16 중 무엇을 요구하는가?
4. 터미널과 폰트가 해당 문자를 출력할 수 있는가?

## 마무리

`char`는 바이트를 담는 타입이고, 유니코드는 문자에 번호를 부여하며, UTF 계열은 그 번호를 바이트로 표현한다. 문자열 문제를 만났다면 타입 하나만 바꾸기 전에 **어느 경계에서 어떤 인코딩으로 변환되는지**부터 확인해야 한다.
