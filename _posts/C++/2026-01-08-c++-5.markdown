앞에서는 정수, `bool`, 부동소수점처럼 숫자를 저장하는 타입을 살펴봤다. 문자도 메모리에 저장하려면 결국 숫자로 표현해야 한다.

다만 문자에는 한 단계가 더 있다. 같은 바이트라도 어떤 **인코딩(Encoding)**으로 해석하느냐에 따라 전혀 다른 문자가 될 수 있다. 이번에는 `char`에서 출발해 C 스타일 문자열과 `std::string`, 유니코드와 UTF-8의 관계까지 이어서 살펴본다.

## 문자 하나와 문자열은 타입부터 다르다

C++에서 작은따옴표는 문자 리터럴, 큰따옴표는 문자열 리터럴을 만든다.

```cpp
char letter = 'A';
char text[] = "A";
```

겉으로는 같은 `A`지만 메모리에 놓이는 형태는 다르다.

```text
letter
+-----+
| 'A' |
+-----+

text
+-----+------+
| 'A' | '\0' |
+-----+------+
```

`letter`는 문자 한 개를 저장하는 `char` 객체다. 반면 `text`는 `A`와 문자열의 끝을 나타내는 널 문자 `\0`을 포함하는 배열이다.

```cpp
#include <iostream>

int main()
{
    char letter = 'A';
    char text[] = "A";

    std::cout << sizeof(letter) << '\n'; // 1
    std::cout << sizeof(text) << '\n';   // 2
}
```

문자 리터럴과 문자열 리터럴은 따옴표만 다른 같은 데이터가 아니다. 타입과 사용 목적이 서로 다르다.

## `char`도 정수 타입이다

컴퓨터는 `A`라는 모양을 메모리에 직접 그려 넣지 않는다. 문자 집합에서 `A`에 대응하는 정수 값을 저장한다.

```cpp
#include <iostream>

int main()
{
    char letter = 'A';

    std::cout << letter << '\n';
    std::cout << static_cast<int>(letter) << '\n';
}
```

첫 번째 출력은 `char`를 문자로 다루므로 `A`가 나온다. 두 번째 출력은 같은 값을 `int`로 변환해 숫자로 확인한다. ASCII와 호환되는 일반적인 환경에서는 `65`가 출력된다.

하지만 C++ 표준이 모든 실행 환경에서 ASCII 자체를 사용하도록 강제하는 것은 아니다. 특정 문자의 숫자 값을 직접 적기보다 다음처럼 문자 리터럴을 사용하는 편이 의도가 분명하다.

```cpp
char portable = 'A';
char assumption = 65; // ASCII 호환 환경을 가정한 코드
```

`char`는 정수 타입이므로 산술 연산에도 참여할 수 있다. 이때 작은 정수 타입은 대개 `int`로 승격된 뒤 계산된다.

```cpp
char current = 'A';
char next = static_cast<char>(current + 1);

std::cout << next << '\n'; // ASCII 호환 환경에서는 B
```

`sizeof(char)`는 정의상 항상 `1`이다. 여기서 1은 **1바이트**라는 뜻이며, 한 바이트가 몇 비트인지는 `CHAR_BIT`로 확인한다. 오늘날의 일반적인 환경에서는 8비트지만 C++ 표준이 모든 구현에 8비트를 요구하지는 않는다.

```cpp
#include <climits>
#include <iostream>

int main()
{
    std::cout << sizeof(char) << '\n'; // 항상 1
    std::cout << CHAR_BIT << '\n';     // 한 바이트의 비트 수
}
```

또한 평범한 `char`가 `signed char`처럼 동작할지 `unsigned char`처럼 동작할지는 구현이 정한다. 128 이상의 바이트 값을 숫자로 다뤄야 한다면 평범한 `char`의 부호를 가정하지 않는 것이 좋다.

## 이스케이프 시퀀스도 문자다

줄바꿈이나 탭처럼 소스 코드에 그대로 적기 어려운 문자는 백슬래시로 시작하는 이스케이프 시퀀스(Escape sequence)로 표현한다.

| 표현 | 의미 |
| :---: | :--- |
| `\n` | 줄바꿈 |
| `\t` | 수평 탭 |
| `\\` | 백슬래시 |
| `\'` | 작은따옴표 |
| `\"` | 큰따옴표 |
| `\0` | 값이 0인 널 문자 |

특히 문자 `'0'`과 널 문자 `\0`은 구분해야 한다.

```cpp
#include <iostream>

int main()
{
    char digit = '0';
    char nullCharacter = '\0';

    std::cout << static_cast<int>(digit) << '\n';
    std::cout << static_cast<int>(nullCharacter) << '\n';
}
```

ASCII 호환 환경에서 `'0'`의 값은 48이지만 `\0`의 값은 0이다. 생김새가 비슷해도 역할은 완전히 다르다.

## 문자열 리터럴은 널 문자를 포함한 배열이다

일반 문자열 리터럴 `"Hello"`의 타입은 `const char[6]`이다. 보이는 문자는 5개지만 마지막에 `\0`이 자동으로 추가된다.

```cpp
char first[] = {'H', 'e', 'l', 'l', 'o', '\0'};
char second[] = "Hello";
```

두 배열은 같은 문자 순서를 가진다.

```cpp
#include <cstring>
#include <iostream>

int main()
{
    char text[] = "Hello";

    std::cout << sizeof(text) << '\n'; // 배열 전체 크기: 6
    std::cout << std::strlen(text) << '\n'; // 첫 \0 전까지: 5
}
```

`sizeof(text)`는 배열 객체 전체의 바이트 수를 구한다. `std::strlen(text)`는 첫 번째 `\0`을 만날 때까지 문자 수를 센다.

이 규칙을 사용하는 문자열을 보통 **C 스타일 문자열(C-style string)**이라고 부른다. 문자 배열이라고 해서 항상 C 문자열인 것은 아니다.

```cpp
char characters[] = {'H', 'i'}; // 널 종료되지 않은 문자 배열
```

이 배열을 `strlen`이나 `cout << characters`처럼 널 종료를 기대하는 기능에 전달하면 배열 밖까지 읽을 수 있다. 그 결과는 정의되지 않은 동작이다.

## 문자열 리터럴을 직접 수정할 수는 없다

문자열 리터럴을 포인터로 가리킬 수는 있지만 리터럴의 문자를 수정할 수는 없다.

```cpp
const char* message = "Hello";

// message[0] = 'Y'; // 컴파일 오류
```

반면 문자 배열을 문자열 리터럴로 초기화하면 배열에 문자들이 복사되므로 배열의 요소를 바꿀 수 있다.

```cpp
char message[] = "Hello";
message[0] = 'Y';

std::cout << message << '\n'; // Yello
```

두 선언은 비슷해 보이지만 하나는 리터럴을 가리키는 포인터이고, 다른 하나는 문자들을 직접 소유하는 배열이다. 포인터와 배열의 차이는 이후 글에서 다시 자세히 다룬다.

## `std::string`은 문자열의 길이를 관리한다

C 스타일 문자열은 끝을 찾기 위해 `\0`에 의존한다. `std::string`은 문자열 데이터와 함께 길이도 관리하며 복사, 비교, 결합 같은 기능을 제공한다.

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string firstName = "Eun";
    std::string lastName = "Teacher";
    std::string fullName = firstName + lastName;

    std::cout << fullName << '\n';
    std::cout << fullName.size() << '\n';
}
```

`std::string`은 내부에 널 문자도 저장할 수 있다.

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string text{"A\0B", 3};

    std::cout << text.size() << '\n';  // 3
    std::cout << text << '\n';         // 세 문자 모두 스트림에 전달
    std::cout << text.c_str() << '\n'; // C 문자열로 해석하면 A에서 끝남
}
```

널 문자는 화면에 보이지 않지만 `text`의 두 번째 요소로 존재한다. `std::string` 자체는 길이 3을 알고 있으므로 그 뒤의 `B`도 문자열에 포함한다. 반면 `c_str()`이 반환한 포인터를 C 문자열 규칙으로 출력하면 첫 `\0`에서 끝난다.

여기서 중요한 점은 `std::string`이 **인코딩을 자동으로 해석하는 문자열 타입은 아니라는 것**이다. `std::string`은 `char`의 연속된 저장소를 관리하며, 그 바이트가 ASCII인지 UTF-8인지는 별도로 정한 규칙에 달려 있다.

## ASCII와 유니코드는 같은 종류의 이름이 아니다

ASCII는 영문 알파벳, 숫자, 일부 기호와 제어 문자에 번호를 부여한 문자 부호 체계다. 총 128개의 값을 사용하므로 7비트로 표현할 수 있다.

ASCII만으로는 한글이나 전 세계의 다양한 문자를 표현할 수 없다. 이를 해결하기 위해 유니코드(Unicode)는 문자마다 **코드 포인트(Code point)**라는 번호를 정의한다.

```text
문자 A  → U+0041
문자 가 → U+AC00
```

하지만 `U+AC00`이라는 번호를 파일이나 메모리에 어떤 바이트로 저장할지는 아직 정해지지 않았다. 그 변환 규칙이 인코딩이다.

```text
문자
  ↓
유니코드 코드 포인트
  ↓
UTF-8 또는 UTF-16 등의 인코딩
  ↓
실제 바이트 또는 코드 유닛
```

유니코드와 UTF-8을 같은 뜻으로 사용하면 안 된다. 유니코드는 문자와 코드 포인트를 정의하는 표준이고, UTF-8은 코드 포인트를 저장하는 인코딩 방식 중 하나다.

## UTF-8에서 글자 수와 바이트 수는 다르다

UTF-8은 코드 포인트 하나를 1~4바이트로 표현하는 가변 길이 인코딩이다. ASCII 영역은 같은 값을 1바이트로 표현하므로 기존 ASCII 텍스트와 호환성이 좋다.

```text
A  → U+0041 → 41          (1바이트)
가 → U+AC00 → EA B0 80    (3바이트)
```

UTF-8 바이트를 직접 만들어 크기를 확인할 수도 있다.

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string korean = "\xEA\xB0\x80"; // UTF-8로 인코딩한 '가'

    std::cout << korean << '\n';
    std::cout << korean.size() << '\n'; // 3
}
```

출력 환경이 UTF-8을 올바르게 해석한다면 `가`가 출력된다. 그렇지 않다면 같은 세 바이트도 깨진 문자로 보일 수 있다.

`std::string::size()`가 반환하는 값은 화면에 보이는 글자 수가 아니라 `char` 요소의 수, 즉 UTF-8 문자열에서는 바이트 수다. 따라서 다음 세 가지는 서로 다를 수 있다.

- 바이트 수
- 유니코드 코드 포인트 수
- 사용자가 화면에서 인식하는 글자 수

예를 들어 화면에 한 글자로 보이는 문자가 여러 코드 포인트의 조합일 수도 있다. 이런 사용자 인식 단위를 그래핌 클러스터(Grapheme cluster)라고 한다.

UTF-8 문자열을 임의의 바이트 위치에서 자르면 하나의 인코딩 시퀀스가 중간에서 끊길 수 있다. 사용자에게 보이는 문자 단위의 검색이나 편집이 필요하다면 유니코드를 이해하는 라이브러리를 사용해야 한다.

## UTF-16과 UTF-32

UTF 인코딩은 UTF-8만 있는 것이 아니다.

| 인코딩 | 코드 유닛 | 코드 포인트 하나를 표현하는 코드 유닛 수 |
| :--- | :--- | :--- |
| UTF-8 | 8비트 | 1~4개 |
| UTF-16 | 16비트 | 1개 또는 2개 |
| UTF-32 | 32비트 | 1개 |

UTF-16에서 자주 사용하는 문자 상당수는 코드 유닛 하나로 표현되지만, 모든 유니코드 문자가 2바이트 하나에 들어가는 것은 아니다. 기본 다국어 평면 밖의 코드 포인트는 서로게이트 페어(Surrogate pair)라는 두 코드 유닛을 사용한다.

UTF-32는 코드 포인트 하나를 코드 유닛 하나로 표현하지만, 이것이 곧 화면의 글자 하나와 항상 일치한다는 의미는 아니다. 결합 문자는 UTF-32에서도 여러 코드 포인트로 구성될 수 있다.

## `wchar_t`는 고정된 유니코드 문자 타입이 아니다

기존 C++ 코드에서는 넓은 문자 타입인 `wchar_t`와 `std::wstring`을 자주 볼 수 있다.

```cpp
wchar_t letter = L'가';
const wchar_t* message = L"안녕하세요";
```

하지만 `wchar_t`의 크기와 인코딩은 구현에 따라 달라진다.

- Windows에서는 일반적으로 2바이트이며 UTF-16 코드 유닛으로 사용된다.
- Linux와 같은 Unix 계열에서는 일반적으로 4바이트다.

따라서 `wchar_t` 하나가 언제나 유니코드 문자 하나를 표현한다고 가정할 수 없다. 특히 Windows의 UTF-16에서는 일부 코드 포인트가 `wchar_t` 두 개를 사용한다.

C++에는 인코딩별 코드 유닛을 표현하기 위한 문자 타입과 리터럴 접두사도 있다.

```cpp
const wchar_t* wide = L"text";
const char16_t* utf16 = u"text";
const char32_t* utf32 = U"text";
```

C++20부터 `u8"text"`의 원소 타입은 `char8_t`다.

```cpp
// C++20 이상
const char8_t* utf8 = u8"한글";
```

C++17까지는 `u8` 문자열 리터럴의 원소 타입이 `const char`였기 때문에, 같은 코드라도 사용하는 C++ 표준 버전에 따라 타입이 달라질 수 있다.

## `wcout`만 사용한다고 한글 문제가 해결되지는 않는다

`wchar_t`는 `std::cout`이 아니라 `std::wcout`으로 출력할 수 있다. 그러나 스트림 타입 하나를 바꾸거나 특정 로캘 이름을 설정하는 것만으로 모든 환경에서 한글 출력이 해결되지는 않는다.

문자열이 화면에 나오기까지 여러 단계가 서로 같은 규칙을 사용해야 한다.

```text
소스 파일
  ↓
컴파일러의 소스 문자 집합 해석
  ↓
프로그램 내부 문자열 표현
  ↓
출력 API와 터미널의 인코딩
  ↓
폰트가 표시한 문자
```

예를 들어 프로그램이 UTF-8 바이트를 출력해도 터미널이 다른 코드 페이지로 해석하면 문자가 깨질 수 있다. 반대로 터미널 설정이 올바르더라도 소스 파일을 컴파일러가 잘못 해석했다면 이미 프로그램 내부의 값이 달라져 있을 수 있다.

한글이 깨졌을 때는 무작정 `char`를 `wchar_t`로 바꾸기보다 다음 경계를 확인하는 편이 좋다.

1. 소스 파일은 어떤 인코딩으로 저장됐는가?
2. 컴파일러는 소스 문자 집합과 실행 문자 집합을 어떻게 해석하는가?
3. 프로그램 내부 문자열은 어떤 인코딩을 사용하기로 했는가?
4. 파일, 네트워크, 운영체제 API는 어떤 인코딩을 요구하는가?
5. 터미널과 출력 API는 받은 값을 어떤 인코딩으로 해석하는가?
6. 사용 중인 폰트가 해당 문자를 표시할 수 있는가?

문자 깨짐은 대개 타입 하나의 문제가 아니라 **인코딩이 바뀌는 경계의 문제**다.

## 전체 실습 코드

지금까지 확인한 내용을 하나의 코드로 모으면 다음과 같다.

```cpp
#include <climits>
#include <cstring>
#include <iostream>
#include <string>

int main()
{
    char letter = 'A';
    char cString[] = "Hello";

    std::cout << "letter: " << letter << '\n';
    std::cout << "letter as integer: " << static_cast<int>(letter) << '\n';

    std::cout << "sizeof(char): " << sizeof(char) << '\n';
    std::cout << "CHAR_BIT: " << CHAR_BIT << '\n';

    std::cout << "sizeof(cString): " << sizeof(cString) << '\n';
    std::cout << "strlen(cString): " << std::strlen(cString) << '\n';

    char digit = '0';
    char nullCharacter = '\0';

    std::cout << "'0': " << static_cast<int>(digit) << '\n';
    std::cout << "'\\0': " << static_cast<int>(nullCharacter) << '\n';

    std::string embeddedNull{"A\0B", 3};
    std::cout << "embeddedNull.size(): " << embeddedNull.size() << '\n';

    std::string utf8Korean = "\xEA\xB0\x80";
    std::cout << "UTF-8 text: " << utf8Korean << '\n';
    std::cout << "UTF-8 byte count: " << utf8Korean.size() << '\n';
}
```

일반적인 ASCII·UTF-8 호환 환경에서는 다음 내용을 확인할 수 있다.

- 문자 `A`의 값은 65다.
- `"Hello"` 배열은 널 문자를 포함해 6바이트다.
- `strlen`으로 확인한 C 문자열 길이는 5다.
- 문자 `'0'`과 널 문자 `\0`의 값은 다르다.
- `std::string`은 문자열 내부의 널 문자도 길이에 포함한다.
- UTF-8로 인코딩한 한글 `가`는 3바이트다.

구체적인 숫자 출력과 한글 표시 결과는 실행 문자 집합과 터미널 설정에 따라 달라질 수 있다.
