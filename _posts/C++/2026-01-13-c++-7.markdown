# [C++] 비트 연산은 최적화 요령보다 데이터 표현 방식이다

비트 연산은 정수의 각 비트를 직접 조작한다. 통신 프로토콜, 하드웨어 레지스터, 권한이나 상태 집합처럼 **여러 개의 독립적인 참/거짓 값을 하나의 정수로 표현할 때** 특히 유용하다.

## 1. 기본 연산자

| 연산자 | 의미 | 대표 용도 |
| :---: | :--- | :--- |
| `&` | 두 비트가 모두 1이면 1 | 필요한 비트 확인 |
| `\|` | 하나라도 1이면 1 | 비트 켜기 |
| `^` | 서로 다르면 1 | 비트 뒤집기 |
| `~` | 모든 비트 반전 | 마스크 반전 |
| `<<` | 왼쪽 시프트 | 비트 위치 만들기 |
| `>>` | 오른쪽 시프트 | 특정 위치의 비트 이동 |

```text
  1100
& 1010
------
  1000
```

비트 연산자를 논리 연산자 `&&`, `||`, `!`와 혼동하면 안 된다. 논리 연산은 표현식을 참과 거짓으로 판단하지만 비트 연산은 정수의 모든 비트에 각각 적용된다.

## 2. 이름이 있는 마스크 만들기

`1 << 3` 같은 숫자를 코드 곳곳에 반복하기보다 의미 있는 이름을 부여한다. 시프트는 부호 없는 타입에서 수행하는 편이 예측하기 쉽다.

```cpp
#include <cstdint>

using Flags = std::uint32_t;

constexpr Flags Airborne   = Flags{1} << 0;
constexpr Flags Stunned    = Flags{1} << 1;
constexpr Flags Transformed = Flags{1} << 2;
constexpr Flags Invincible = Flags{1} << 3;
```

`std::uint32_t`는 제공되는 구현에서 정확히 32비트인 부호 없는 정수형이다. 플래그의 저장 폭과 외부 데이터 형식을 명확히 하고 싶을 때 적합하다.

## 3. 켜기·끄기·뒤집기·확인하기

```cpp
Flags state = 0;

state |= Invincible;  // 켜기
state &= ~Invincible; // 끄기
state ^= Stunned;     // 뒤집기

bool isStunned = (state & Stunned) != 0;
```

`~`는 피연산자의 모든 비트를 뒤집는다. 마스크와 상태의 타입을 같은 부호 없는 타입으로 맞추면 정수 승격 때문에 예상보다 넓은 타입이 만들어지는 실수를 줄일 수 있다.

## 4. 하나라도 켜졌는지, 전부 켜졌는지

여러 플래그를 확인할 때는 질문을 분명히 해야 한다.

```cpp
Flags dangerMask = Stunned | Transformed;

bool hasAny = (state & dangerMask) != 0;
bool hasAll = (state & dangerMask) == dangerMask;
```

- `hasAny`: 지정한 상태 중 하나 이상이 켜졌는가?
- `hasAll`: 지정한 상태가 모두 켜졌는가?

두 조건은 비슷해 보여도 게임 로직에서는 완전히 다른 결과를 낸다.

## 5. 시프트에서 지켜야 할 범위

시프트 횟수가 음수이거나 타입의 비트 폭 이상이면 정의되지 않은 동작이다. 부호 있는 값의 왼쪽 시프트는 값의 범위에 따라 위험하며, 음수의 시프트도 의도를 파악하기 어렵다. 비트 패턴을 다룰 때는 부호 없는 타입을 우선 고려한다.

```cpp
constexpr unsigned BitWidth = 32;
unsigned index = 7;

if (index < BitWidth)
{
    std::uint32_t mask = std::uint32_t{1} << index;
}
```

`x << n`을 무조건 `x * 2^n`, `x >> n`을 무조건 나눗셈으로 이해해서도 안 된다. 오버플로, 부호, 나눗셈의 반올림 규칙 때문에 일반적인 산술과 결과가 다를 수 있다.

## 6. `enum class`로 상태 이름 묶기

플래그의 종류가 많아지면 열거형으로 의미와 범위를 묶을 수 있다.

```cpp
#include <cstdint>

enum class PlayerState : std::uint32_t
{
    Airborne   = 1u << 0,
    Stunned    = 1u << 1,
    Invincible = 1u << 2
};

constexpr std::uint32_t ToMask(PlayerState state)
{
    return static_cast<std::uint32_t>(state);
}

int main()
{
    std::uint32_t states = 0;
    states |= ToMask(PlayerState::Invincible);

    bool invincible =
        (states & ToMask(PlayerState::Invincible)) != 0;
}
```

실전에서는 `operator|`, `operator&`를 정의해 열거형끼리 자연스럽게 조합하기도 한다. 다만 먼저 어떤 연산을 허용할지 정한 뒤 제공해야 한다.

## 7. 비트 플래그가 항상 정답은 아니다

플래그는 직렬화 형식이나 여러 상태를 한 번에 검사할 때 강점이 있다. 반면 일반 객체에서 `bool` 여러 개를 플래그 하나로 바꾼다고 전체 객체 크기가 반드시 줄어드는 것은 아니다. 정렬과 패딩, 접근 방식, 디버깅 편의까지 함께 봐야 한다.

또한 `2`의 거듭제곱 곱셈을 손으로 시프트로 바꾸는 미세 최적화는 보통 필요 없다. 컴파일러가 의미가 같은 범위에서 최적화하며, 사람은 먼저 의도가 선명한 연산을 써야 한다.

## 마무리

비트 플래그의 핵심은 빠른 묘기가 아니라 **각 비트에 명확한 의미를 부여하고 안전한 범위에서 조작하는 것**이다. 부호 없는 고정 폭 타입, 이름 있는 마스크, `any`와 `all` 조건의 구분만 지켜도 흔한 오류를 크게 줄일 수 있다.
