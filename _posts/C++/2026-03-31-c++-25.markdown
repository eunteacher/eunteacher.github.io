앞에서는 반드시 존재하며 읽기만 할 대상은 `const T&`, 없을 수 있으며 읽기만 할 대상은 `const T*`로 표현할 수 있다는 점을 살펴봤다. 여기서 `const`를 단순히 “값이 절대 바뀌지 않는다”라고 이해하면 포인터와 참조가 결합될 때 혼란이 생긴다.

`const`는 특정 객체나 접근 경로를 통해 허용할 변경 연산을 제한한다. 어떤 이름에 `const`가 적용됐는지, 포인터 자체와 가리키는 대상 중 무엇을 제한하는지 구분해야 한다.

## `const` 객체는 해당 이름으로 수정할 수 없다

일반 객체는 값을 바꿀 수 있다.

```cpp
int hp = 100;
hp = 80;
```

`const` 객체는 초기화한 뒤 해당 객체를 수정하는 연산을 사용할 수 없다.

```cpp
const int MaxHp = 100;
// MaxHp = 200;
```

기본 타입의 `const` 지역 객체는 나중에 값을 대입할 수 없으므로 선언할 때 값을 제공해야 한다.

```cpp
// const int MaxHp;
```

클래스 타입은 사용할 수 있는 기본 생성자가 있다면 그 생성 과정을 통해 초기화될 수 있다. 핵심은 `const` 객체가 생성된 뒤 일반 대입으로 초기 상태를 채우는 방식에 의존할 수 없다는 점이다.

컴파일러는 `MaxHp`를 통한 대입을 거부한다. 이는 성능 최적화 요청이 아니라 소스 코드에서 허용되는 연산을 제한하는 타입 규칙이다.

## `const`와 `constexpr`는 같은 뜻이 아니다

`const`는 객체를 통한 수정을 제한하지만 모든 `const` 값이 컴파일 시간 상수라는 뜻은 아니다.

```cpp
int ReadMaxHp();

const int maxHp = ReadMaxHp();
```

`maxHp`는 초기화 이후 바꿀 수 없지만 값은 실행 중 함수 호출로 결정될 수 있다.

컴파일 시간 상수 표현식으로 사용할 값이라면 `constexpr`를 검토한다.

```cpp
constexpr int MaxPartySize = 4;
```

`constexpr` 객체도 수정할 수 없지만 추가로 상수 표현식 요구를 가진다. “수정 금지”와 “컴파일 시간 평가 가능”이라는 목적을 구분한다.

## `const T&`는 참조를 통한 변경을 막는다

상수 참조는 반드시 유효한 대상에 바인딩되며, 해당 참조를 통해 대상을 수정할 수 없다.

```cpp
struct Character
{
    int hp;
    int attack;
};

Character player{100, 20};
const Character& view = player;
```

`view`로 멤버를 읽을 수 있다.

```cpp
int hp = view.hp;
```

하지만 `view`를 통해 멤버를 수정할 수는 없다.

```cpp
// view.hp = 50;
```

원본 `player`가 처음부터 `const` 객체인 것은 아니다. 수정 가능한 다른 이름을 통해서는 값을 바꿀 수 있다.

```cpp
player.hp = 80;
```

이후 `view.hp`를 읽으면 변경된 80을 관찰한다. 상수 참조는 원본 객체 전체를 얼리는 장치가 아니라 **그 참조를 통한 수정 권한을 제거한 접근 경로**다.

## 상수 참조 매개변수는 읽기 전용 계약을 표현한다

출력 함수는 캐릭터 상태를 읽기만 한다.

```cpp
void PrintCharacter(const Character& character)
{
    std::cout << "HP: " << character.hp << " ATK: " << character.attack << '\n';
}
```

함수 안에서 `character.hp`에 대입하려 하면 컴파일 오류가 발생한다. 호출자는 수정 가능한 객체와 `const` 객체를 모두 전달할 수 있다.

```cpp
Character player{100, 20};
const Character boss{500, 50};

PrintCharacter(player);
PrintCharacter(boss);
```

함수 선언만 보고 다음 내용을 알 수 있다.

- 캐릭터 대상이 반드시 필요하다.
- 함수는 이 참조를 통해 캐릭터를 수정하지 않는다.
- 캐릭터 객체의 복사본을 요구하지 않는다.

하지만 이 함수가 프로그램의 다른 전역 상태까지 수정하지 않는다는 뜻은 아니다. `const`는 매개변수 접근 권한을 제한할 뿐 함수 전체를 순수 함수로 만들지 않는다.

## `const T&`는 다른 별칭의 변경까지 막지 않는다

한 객체에 수정 가능한 참조와 상수 참조가 함께 연결될 수 있다.

```cpp
int hp = 100;
int& writable = hp;
const int& readable = hp;

writable = 70;
int currentHp = readable;
```

`readable`을 통해서는 대입할 수 없지만 `writable`로 원본을 변경할 수 있다. `readable`은 그 변경을 관찰한다.

따라서 `const T&`를 받았다는 이유만으로 대상 값이 함수 실행 내내 절대 바뀌지 않는다고 일반화할 수 없다. 다른 별칭, 콜백이나 다른 스레드가 같은 객체에 접근할 수 있는 설계라면 별도의 동기화와 불변성 규칙이 필요하다.

데이터 경쟁이 발생하는 동시 접근은 `const`만으로 해결되지 않는다.

## 참조는 한 번 바인딩되면 다른 대상을 가리키지 않는다

참조는 선언할 때 대상에 바인딩된다.

```cpp
int playerHp = 100;
int monsterHp = 50;
int& targetHp = playerHp;
```

참조에 다른 변수를 대입하면 참조가 다시 바인딩되는 것이 아니라 현재 대상에 값을 대입한다.

```cpp
targetHp = monsterHp;
```

이 코드는 `playerHp`를 50으로 만든다. `targetHp`가 `monsterHp`의 별명으로 바뀌는 것이 아니다.

상수 참조도 다른 대상에 다시 바인딩할 수 없다.

```cpp
const int& observedHp = playerHp;
```

참조의 재바인딩 불가와 `const`를 통한 수정 제한은 서로 다른 규칙이다.

## `const T*`는 가리키는 대상을 수정하지 못하게 한다

포인터 선언에서는 `const`가 포인터 자체에 적용되는지, 가리키는 대상에 적용되는지 확인해야 한다.

```cpp
int playerHp = 100;
int monsterHp = 50;
const int* observedHp = &playerHp;
```

`observedHp`의 타입은 “`const int`를 가리키는 포인터”다. 포인터를 통해 값을 읽을 수 있지만 수정할 수는 없다.

```cpp
int currentHp = *observedHp;
// *observedHp = 80;
```

포인터 자체는 다른 대상을 가리키도록 바꿀 수 있다.

```cpp
observedHp = &monsterHp;
```

`const int*`와 `int const*`는 같은 타입 표기다.

```cpp
const int* first = &playerHp;
int const* second = &playerHp;
```

둘 다 포인터를 통한 `int` 수정은 금지하지만 포인터 재지정은 허용한다.

## `T* const`는 포인터 자체를 변경하지 못하게 한다

`const`가 `*` 뒤에서 포인터 이름을 한정하면 포인터 객체 자체가 상수가 된다.

```cpp
int* const fixedTarget = &playerHp;
```

`fixedTarget`은 선언할 때 가리킬 대상을 정해야 하고 이후 다른 주소나 `nullptr`을 대입할 수 없다.

```cpp
// fixedTarget = &monsterHp;
// fixedTarget = nullptr;
```

가리키는 `int`는 `const`가 아니므로 역참조를 통한 수정은 가능하다.

```cpp
*fixedTarget = 80;
```

이 코드는 `playerHp`를 80으로 만든다.

## `const T* const`는 대상 수정과 포인터 재지정을 모두 막는다

두 위치를 모두 `const`로 한정할 수 있다.

```cpp
const int* const fixedObservation = &playerHp;
```

`fixedObservation`을 통해 `playerHp`를 수정할 수 없고, 포인터가 다른 대상을 가리키도록 변경할 수도 없다.

```cpp
// *fixedObservation = 70;
// fixedObservation = &monsterHp;
```

네 가지 형태를 비교하면 다음과 같다.

| 선언 | 대상 수정 | 다른 대상 가리키기 |
| :--- | :---: | :---: |
| `T* pointer` | 가능 | 가능 |
| `const T* pointer` | 불가능 | 가능 |
| `T* const pointer` | 가능 | 불가능 |
| `const T* const pointer` | 불가능 | 불가능 |

어떤 동작을 제한하는지 각각 확인하면 “상수 포인터”라는 모호한 표현에 의존하지 않아도 된다.

## 포인터 선언은 이름에서 바깥쪽으로 읽는다

복잡한 포인터 선언은 포인터 이름에서 시작해 바깥쪽으로 읽을 수 있다.

```cpp
const Character* target;
```

`target`은 포인터이고, 그 포인터가 가리키는 대상은 `const Character`다.

```cpp
Character* const target = &player;
```

`target`은 `const` 포인터이고, 가리키는 대상은 수정 가능한 `Character`다.

```cpp
const Character* const target = &player;
```

`target`은 `const` 포인터이고, 가리키는 대상도 `const Character`로 접근한다.

타입 별칭을 사용하면 선언 의도를 더 분명하게 만들 수 있지만, 별칭 자체에 포함된 포인터와 바깥의 `const` 관계를 이해해야 한다.

```cpp
using CharacterPointer = Character*;
CharacterPointer const target = &player;
```

이 선언의 `target`은 `Character* const`다. `const Character*`가 아니다. `const`는 별칭이 나타내는 전체 포인터 타입을 한정한다.

## 값 매개변수의 top-level `const`는 구현 내부 제한이다

값 매개변수에 `const`를 붙일 수 있다.

```cpp
void PrintLevel(const int level)
{
    // level = 10;
    std::cout << level << '\n';
}
```

이 `const`는 함수 안에서 매개변수 복사본 `level`을 다시 대입하지 못하게 한다. 호출자의 원본과는 관계가 없다.

함수 타입을 구분할 때 값 매개변수의 top-level `const`는 제거된다. 따라서 다음 두 선언으로 오버로드를 만들 수 없다.

```cpp
void PrintLevel(int level);
// void PrintLevel(const int level);
```

두 선언은 호출자 관점에서 같은 함수다. 공개 헤더에는 보통 `int level`로 선언하고, 정의에서 매개변수 복사본을 바꾸지 않겠다는 구현 의도를 위해 `const int level`을 사용할 수 있다.

```cpp
// Game.h
void PrintLevel(int level);
```

```cpp
// Game.cpp
void PrintLevel(const int level)
{
    std::cout << level << '\n';
}
```

## 포인터 자체의 top-level `const`도 호출자 계약을 바꾸지 않는다

포인터 매개변수 자체를 `const`로 만들 수 있다.

```cpp
void ResetHp(int* const hp)
{
    if (hp != nullptr)
    {
        *hp = 100;
    }

    // hp = nullptr;
}
```

여기서 `int* const hp`는 매개변수 포인터 복사본을 함수 안에서 재지정하지 않겠다는 뜻이다. 가리키는 `int`는 수정할 수 있고 `nullptr`도 인자로 받을 수 있다.

함수 타입의 호출자 관점에서는 `int* hp`와 같은 매개변수다.

```cpp
void ResetHp(int* hp);
// void ResetHp(int* const hp);
```

반면 `const int* hp`는 가리키는 대상의 타입을 바꾸므로 호출자에게 보이는 인터페이스 차이다.

```cpp
void PrintHp(const int* hp);
```

top-level `const`가 매개변수 객체 자체를 제한하는지, 포인터가 가리키는 대상 타입에 포함되는지 구분한다.

## 수정 가능한 포인터는 읽기 전용 포인터로 변환할 수 있다

수정 가능한 객체를 읽기만 하는 함수에 전달하는 것은 안전하다.

```cpp
void PrintCharacter(const Character* character)
{
    if (character == nullptr)
    {
        return;
    }

    std::cout << "HP: " << character->hp << '\n';
}
```

```cpp
Character player{100, 20};
Character* writable = &player;
const Character* readable = writable;
PrintCharacter(writable);
```

`Character*`에서 `const Character*`로 변환하면 기존 수정 권한을 읽기 전용 접근 경로에 넘긴다.

반대 방향은 암시적으로 허용되지 않는다.

```cpp
const Character boss{500, 50};
const Character* bossPointer = &boss;
// Character* writableBoss = bossPointer;
```

허용한다면 `writableBoss`로 원래 `const` 객체를 수정할 수 있게 되므로 타입 시스템이 막는다.

참조도 같은 방향으로 권한을 줄일 수 있다.

```cpp
Character& writableReference = player;
const Character& readableReference = writableReference;
```

## 참조의 `const` 여부는 오버로드를 구분할 수 있다

값 매개변수의 top-level `const`와 달리, 참조가 가리키는 대상의 `const` 여부는 다른 매개변수 타입을 만든다.

```cpp
void Inspect(Character& character)
{
    std::cout << "Writable character\n";
}

void Inspect(const Character& character)
{
    std::cout << "Read-only character\n";
}
```

수정 가능한 객체를 전달하면 `Character&` 오버로드가 더 직접적으로 일치하고, `const Character` 객체를 전달하면 `const Character&` 버전만 사용할 수 있다.

```cpp
Character player{100, 20};
const Character boss{500, 50};

Inspect(player);
Inspect(boss);
```

문법적으로 가능하더라도 두 오버로드가 실제로 다른 동작을 제공해야 하는지는 별도로 판단한다. 읽기와 쓰기 버전의 의미 차이가 없다면 하나의 `const Character&` 함수만으로 충분할 수 있다.

## `const_cast`는 객체의 원래 const 여부를 바꾸지 않는다

`const_cast`로 포인터나 참조 타입의 `const` 한정을 제거할 수 있다. 하지만 원래 객체가 수정 가능한 객체였는지에 따라 결과가 달라진다.

원본이 수정 가능한 객체라면 다른 상수 접근 경로에서 `const`를 제거한 뒤 원본을 수정하는 것이 언어 규칙상 가능할 수 있다.

```cpp
int hp = 100;
const int* readableHp = &hp;
int* writableHp = const_cast<int*>(readableHp);
*writableHp = 80;
```

실제 객체 `hp`는 `const`로 정의되지 않았으므로 수정할 수 있다. 하지만 함수가 받은 `const` 계약을 임의로 제거하면 호출자가 기대한 읽기 전용 규칙을 깨뜨릴 수 있어 일반적인 설계에서는 피한다.

원래 객체가 `const`라면 캐스트 후 수정하는 것은 정의되지 않은 동작이다.

```cpp
const int MaxHp = 100;
const int* maxHpPointer = &MaxHp;
int* invalidPointer = const_cast<int*>(maxHpPointer);
// *invalidPointer = 200;
```

캐스트는 `MaxHp` 객체 자체를 수정 가능한 객체로 바꾸지 않는다. 오래된 C API와의 상호 운용처럼 제한된 상황이 아니라면 처음부터 필요한 수정 권한을 정확한 함수 타입으로 표현한다.

## `const`는 객체 그래프 전체에 자동으로 전파되지 않는다

`const` 객체가 포인터 멤버를 가지고 있다고 가정하자.

```cpp
struct HealthView
{
    int* hp;
};

int playerHp = 100;
const HealthView view{&playerHp};
```

`view`가 `const`이므로 멤버 포인터 `view.hp` 자체를 다른 주소로 바꿀 수는 없다.

```cpp
// view.hp = nullptr;
```

하지만 멤버 포인터가 가리키는 타입은 `int`이므로 그 대상을 수정할 수 있다.

```cpp
*view.hp = 80;
```

이를 얕은 const(Shallow const) 관점으로 설명할 수 있다. `const`가 현재 객체의 직접적인 수정 경로를 제한하지만 내부 포인터가 가리키는 별도 객체까지 자동으로 `const`로 만들지는 않는다.

대상까지 읽기 전용이어야 한다면 멤버 타입에 권한을 기록한다.

```cpp
struct ReadOnlyHealthView
{
    const int* hp;
};
```

```cpp
ReadOnlyHealthView readOnlyView{&playerHp};
// *readOnlyView.hp = 70;
```

타입이 가진 포인터, 참조와 스마트 포인터 멤버의 `const` 전파 규칙을 각각 확인해야 한다.

## `const`는 수명과 null 여부를 보장하지 않는다

`const` 포인터도 null일 수 있다.

```cpp
const Character* target = nullptr;
```

가리키던 객체의 수명이 끝나면 상수 대상 포인터도 댕글링된다.

```cpp
const Character* savedTarget = nullptr;

{
    Character monster{50, 15};
    savedTarget = &monster;
}

// monster의 수명은 끝났다.
```

`const`가 보장하지 않는 내용을 정리하면 다음과 같다.

- 포인터가 null이 아니라는 보장
- 대상 객체가 아직 살아 있다는 보장
- 다른 별칭이 객체를 수정하지 않는다는 보장
- 내부 포인터가 가리키는 객체까지 읽기 전용이라는 보장
- 여러 스레드가 동시에 안전하게 접근할 수 있다는 보장
- 함수가 외부 상태를 전혀 변경하지 않는다는 보장

`const`는 이런 조건을 대신하는 안전 장치가 아니라 하나의 접근 경로에서 허용할 연산을 줄이는 규칙이다.

## 아무 동작도 하지 않는 `OUT` 매크로는 권한을 표현하지 못한다

기존 예제는 출력 매개변수를 강조하기 위해 빈 매크로를 사용했다.

```cpp
#define OUT

void ChangeInfo(OUT Character& output)
{
    output.hp = 100;
}
```

전처리 후 `OUT`은 사라지므로 컴파일러는 어떤 추가 의미도 검사하지 않는다. 호출부에서도 매크로 정의를 모르면 단순한 장식처럼 보인다.

결과 하나를 만들면 반환값을 사용한다.

```cpp
Character CreateCharacter(int hp, int attack)
{
    return {hp, attack};
}
```

기존 객체 수정이 목적이라면 함수 이름과 비상수 참조 타입으로 표현한다.

```cpp
void ResetCharacter(Character& character)
{
    character.hp = 100;
}
```

프로젝트 코딩 규칙에서 출력 매개변수 표기를 사용하더라도 실제 타입 계약을 대신할 수는 없다.

## 전체 예제로 읽기와 수정 권한을 분리한다

Text RPG에서 두 캐릭터 중 체력이 낮은 대상을 관찰하고, 선택된 대상이 존재할 때만 회복하는 예제다.

```cpp
#include <algorithm>
#include <iostream>

struct Character
{
    const char* name;
    int hp;
    int maxHp;
};

void PrintCharacter(const Character& character)
{
    std::cout << character.name << " HP: " << character.hp << " / " << character.maxHp << '\n';
}

const Character* SelectLowerHp(const Character* first, const Character* second)
{
    if (first == nullptr)
    {
        return second;
    }

    if (second == nullptr)
    {
        return first;
    }

    return first->hp <= second->hp ? first : second;
}

bool TryHeal(Character* target, int amount)
{
    if (target == nullptr)
    {
        return false;
    }

    int healing = std::max(0, amount);
    target->hp = std::min(target->maxHp, target->hp + healing);
    return true;
}

int main()
{
    Character player{"Player", 60, 100};
    Character companion{"Companion", 40, 80};

    const Character* observedTarget = SelectLowerHp(&player, &companion);

    if (observedTarget != nullptr)
    {
        PrintCharacter(*observedTarget);
        // observedTarget->hp = 100;
    }

    Character* const healingTarget = &companion;

    if (TryHeal(healingTarget, 20))
    {
        PrintCharacter(*healingTarget);
    }

    const Character* const fixedObservation = &player;
    PrintCharacter(*fixedObservation);
}
```

각 선언이 허용하는 권한은 다음과 같다.

| 선언 | 의미 |
| :--- | :--- |
| `const Character* observedTarget` | 선택 결과가 없을 수 있고, 존재하면 읽기만 한다. 다른 관찰 대상으로 재지정할 수 있다. |
| `Character* const healingTarget` | 항상 같은 캐릭터를 가리키며, 해당 캐릭터를 수정할 수 있다. |
| `const Character* const fixedObservation` | 항상 같은 캐릭터를 읽기만 한다. |
| `const Character&` 매개변수 | 반드시 존재하는 캐릭터를 읽기만 한다. |
| `Character*` 매개변수 | 대상이 없을 수 있고, 존재하면 수정할 수 있다. |

`SelectLowerHp`는 입력을 `const Character*`로 받아 두 대상을 수정하지 않으며 반환 포인터도 읽기 전용으로 제한한다. `TryHeal`은 수정 가능한 포인터를 받아 실제 원본 체력을 변경한다.

이 코드는 권한 구분을 설명하는 예제이며 실행 결과를 확인했다고 가정하지 않는다. 회복 덧셈은 현재의 작은 양수 범위를 전제로 하므로 외부의 큰 정수를 받을 수 있다면 표현 범위 검사도 추가해야 한다.

## `const`를 적용할 때 확인할 기준

`const`를 붙이거나 읽을 때는 다음 질문을 순서대로 확인한다.

1. `const`가 객체 자체, 포인터 자체, 포인터가 가리키는 대상 중 어디에 적용되는가?
2. 이 이름이나 접근 경로로 어떤 변경을 막으려는가?
3. 수정 가능한 다른 별칭이 같은 객체를 가리키고 있지는 않은가?
4. 내부 포인터가 가리키는 대상까지 읽기 전용이어야 하는가?
5. 값 매개변수의 top-level `const`처럼 구현 내부에만 영향을 주는가?
6. 함수 타입과 오버로드 선택에 영향을 주는 `const`인가?
7. `const_cast`로 계약을 우회하고 있지는 않은가?
8. null, 수명과 스레드 안전성을 `const`가 보장한다고 오해하지 않았는가?

`const`는 붙일 수 있는 모든 위치에 기계적으로 추가하는 장식이 아니다. 함수가 필요로 하는 최소 권한을 타입에 기록하고, 컴파일러가 그 경계를 검사하도록 만드는 도구다.
