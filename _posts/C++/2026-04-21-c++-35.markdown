앞에서는 Text RPG의 능력치 구조체에 생성자와 멤버 함수를 추가했다. 이번에는 `Knight`라는 게임 개체를 클래스로 설계하며 클래스 정의, 객체 생성과 멤버 함수 호출이 어떤 관계인지 정리한다.

원본 코드는 체력, 공격력과 위치를 모두 `public`으로 열어 둔 뒤 외부에서 직접 값을 채운다. 작은 실습에서는 동작하지만 객체가 어떤 상태로 시작해야 하는지, 위치를 바꿀 때 어떤 경로를 사용해야 하는지가 타입에 드러나지 않는다.

클래스의 목적은 관련 코드를 한 중괄호 안에 모으는 데서 끝나지 않는다. 객체가 제공할 동작과 내부에서 유지할 상태의 경계를 하나의 타입으로 표현하는 데 있다.

## 클래스는 타입이고 객체는 그 타입의 인스턴스다

클래스 정의는 `Knight`라는 새로운 타입을 만든다.

```cpp
class Knight
{
};
```

이 정의만으로 실제 기사 객체가 생성되는 것은 아니다. 변수를 선언해야 해당 타입의 객체가 생긴다.

```cpp
Knight firstKnight;
Knight secondKnight;
```

관계를 단순화하면 다음과 같다.

```text
Knight 클래스
┌────────────────────────────┐
│ 어떤 상태와 동작을 가지는가 │
└────────────────────────────┘
          │
          ├─ firstKnight 객체
          └─ secondKnight 객체
```

두 객체는 같은 클래스 정의를 따르지만 서로 다른 상태를 가진다. 한 기사의 체력을 변경한다고 다른 기사 체력이 함께 바뀌지 않는다.

```cpp
Knight firstKnight;
Knight secondKnight;

firstKnight.Die();
```

`Die`가 현재 객체의 체력만 변경하도록 구현됐다면 `firstKnight`만 사망 상태가 된다.

## 타입을 설계하기 전에 상태와 동작을 나눈다

기사에게 필요한 내용을 먼저 정한다.

```text
상태
- 현재 체력
- 공격력
- 현재 x 좌표
- 현재 y 좌표

동작
- 위치 이동
- 공격 피해량 확인
- 사망 처리
- 현재 생존 여부 확인
```

클래스 안에서는 데이터 멤버와 멤버 함수로 표현한다.

```cpp
class Knight
{
public:
    void Move(int x, int y);
    int AttackDamage() const;
    void Die();
    bool IsDead() const;

private:
    int hp_ = 100;
    int attack_ = 10;
    int x_ = 0;
    int y_ = 0;
};
```

데이터 멤버는 객체가 보관하는 상태고 멤버 함수는 그 상태를 사용하거나 변경하는 동작이다.

기능 목록을 무조건 전부 멤버 함수로 만들지는 않는다. 기사 객체 하나의 상태와 직접 관련된 동작인지 먼저 판단한다. 전투 순서, 화면 출력과 사용자 입력처럼 여러 객체나 외부 시스템을 조정하는 기능은 별도 함수나 상위 객체의 책임일 수 있다.

## `class`의 기본 접근은 `private`이다

접근 지정자를 생략한 클래스 멤버는 기본적으로 `private`다.

```cpp
class Knight
{
    int hp_ = 100;
};
```

외부 코드는 `hp_`에 직접 접근할 수 없다.

```cpp
Knight knight;
// knight.hp_ = -100; // 접근할 수 없음
```

외부에 제공할 동작은 `public` 영역에 선언한다.

```cpp
class Knight
{
public:
    void Die();
    bool IsDead() const;

private:
    int hp_ = 100;
};
```

이제 호출자는 내부 체력 표현을 직접 바꾸는 대신 클래스가 제공한 동작을 사용한다.

```cpp
knight.Die();
bool dead = knight.IsDead();
```

이번 글에서는 공개 인터페이스와 내부 상태를 구분하는 정도만 적용한다. 접근 제한을 이용해 객체의 유효 상태를 강하게 보호하는 설계는 이후 캡슐화 편에서 더 자세히 다룬다.

## 기본 멤버 초기값으로 객체의 시작 상태를 정한다

생성자를 직접 선언하지 않아도 데이터 멤버에 기본 초기값을 지정할 수 있다.

```cpp
private:
    int hp_ = 100;
    int attack_ = 10;
    int x_ = 0;
    int y_ = 0;
```

`Knight knight;`로 객체를 만들면 암시적으로 제공되는 기본 생성 과정에서 이 초기값들이 사용된다.

```text
hp_     = 100
attack_ = 10
x_      = 0
y_      = 0
```

원본처럼 객체를 만든 뒤 멤버마다 값을 대입하면 초기화가 빠졌을 때 불완전한 상태가 남을 수 있다.

```cpp
Knight knight;
// knight.hp = 100;
// knight.attack = 10;
// knight.posX 대입을 빠뜨릴 수 있음
```

모든 기사가 같은 기본값으로 시작한다면 기본 멤버 초기값이 그 규칙을 한곳에 기록한다.

다음 글에서는 직접 생성자를 선언하고 여러 초기화 방식을 제공할 때 암시적으로 생성되던 함수들이 어떻게 달라지는지 살펴본다.

## 멤버 함수는 현재 객체의 상태를 사용한다

위치 이동 함수는 전달받은 좌표를 현재 기사 객체에 저장한다.

```cpp
void Move(int x, int y)
{
    x_ = x;
    y_ = y;
}
```

호출할 때 어느 객체의 상태를 변경할지 점 연산자 왼쪽에 나타난다.

```cpp
Knight firstKnight;
Knight secondKnight;

firstKnight.Move(2, 3);
secondKnight.Move(8, 1);
```

같은 `Move` 구현을 호출하지만 현재 객체가 다르므로 변경되는 `x_`, `y_`도 다르다.

```text
firstKnight.Move(2, 3)  → firstKnight의 위치 변경
secondKnight.Move(8, 1) → secondKnight의 위치 변경
```

비정적 멤버 함수 안에서는 현재 호출 대상 객체를 가리키는 `this` 포인터를 사용할 수 있다.

```cpp
void Move(int x, int y)
{
    this->x_ = x;
    this->y_ = y;
}
```

이름 충돌을 구분할 필요가 없다면 `this->`는 생략할 수 있다. 두 구현은 이번 경우 같은 멤버를 변경한다.

## 일반 함수와 멤버 함수는 호출 대상 표현이 다르다

원본에는 기사 포인터를 받는 일반 이동 함수와 멤버 이동 함수가 함께 있다.

```cpp
void Move(Knight* knight, int x, int y);
```

일반 함수는 변경할 객체를 명시적인 매개변수로 받는다.

```cpp
Move(&knight, 2, 3);
```

멤버 함수는 점 연산자 왼쪽의 객체가 호출 대상이다.

```cpp
knight.Move(2, 3);
```

개념적으로는 두 호출 모두 특정 기사 객체와 좌표를 사용한다.

```text
일반 함수: Move(&knight, 2, 3)
멤버 함수: knight.Move(2, 3)
```

하지만 두 문법이 언어 규칙상 완전히 같은 함수 타입이나 호출 방식이라는 뜻은 아니다. 비정적 멤버 함수 포인터와 일반 함수 포인터의 타입도 서로 다르다.

기사 내부 상태를 변경하는 대표 동작이라면 멤버 함수가 자연스럽다. 여러 타입을 함께 처리하거나 객체와 독립된 계산이라면 일반 함수가 더 적합할 수 있다.

## 클래스 밖에서 멤버 함수를 정의할 수 있다

클래스 안에는 함수 선언만 두고 본문을 밖으로 분리할 수 있다.

```cpp
class Knight
{
public:
    void Move(int x, int y);

private:
    int x_ = 0;
    int y_ = 0;
};
```

클래스 밖 정의에는 범위 지정 연산자 `::`를 사용한다.

```cpp
void Knight::Move(int x, int y)
{
    x_ = x;
    y_ = y;
}
```

`Knight::Move`는 이 함수가 `Knight` 클래스 범위에 선언된 멤버라는 뜻이다. 클래스 밖에 정의돼 있어도 `Knight`의 private 멤버에 접근할 수 있다.

헤더와 소스 파일을 나눌 때는 보통 헤더에 클래스 정의와 멤버 함수 선언을 두고 `.cpp`에 함수 정의를 둔다.

```text
Knight.h
└─ class Knight와 공개 멤버 함수 선언

Knight.cpp
└─ Knight::Move 등 멤버 함수 정의
```

짧은 멤버 함수를 클래스 안에서 정의하는 것도 가능하다. 함수 길이뿐 아니라 의존성, 컴파일 비용과 프로젝트 규칙을 함께 보고 위치를 정한다.

## `.`, `->`, `::`는 서로 다른 관계를 표현한다

비슷해 보이는 세 연산자를 구분한다.

```cpp
Knight knight;
Knight* knightPointer = &knight;
```

객체에서 멤버에 접근할 때는 점을 사용한다.

```cpp
knight.Move(2, 3);
```

객체를 가리키는 포인터에서 멤버에 접근할 때는 화살표를 사용한다.

```cpp
knightPointer->Move(2, 3);
```

화살표 표현은 역참조와 멤버 접근을 결합한 의미로 이해할 수 있다.

```cpp
(*knightPointer).Move(2, 3);
```

클래스 범위에 속한 이름을 지정할 때는 `::`를 사용한다.

```cpp
void Knight::Move(int x, int y)
{
}
```

| 연산자 | 왼쪽 대상 | 의미 |
| :--- | :--- | :--- |
| `.` | 객체 | 해당 객체의 멤버 접근 |
| `->` | 객체 포인터 | 가리키는 객체의 멤버 접근 |
| `::` | 클래스·네임스페이스 등의 범위 | 해당 범위에 속한 이름 지정 |

`knightPointer`가 `nullptr`이거나 더 이상 유효하지 않은 객체를 가리킨다면 `->`를 사용해 멤버 함수를 호출할 수 없다.

## 읽기 전용 멤버 함수에는 `const`를 붙인다

공격력과 상태를 확인하는 함수는 객체를 변경하지 않는다.

```cpp
int AttackDamage() const
{
    return attack_;
}

bool IsDead() const
{
    return hp_ == 0;
}
```

함수 뒤의 `const`는 이 호출을 통해 현재 객체의 비정적 데이터 멤버를 변경하지 않겠다는 뜻이다.

```cpp
const Knight knight;
int damage = knight.AttackDamage();
bool dead = knight.IsDead();
```

`const` 객체에서는 `const` 멤버 함수만 호출할 수 있다. 상태를 바꾸는 `Move`와 `Die`는 호출할 수 없다.

```cpp
// knight.Move(2, 3); // const 객체를 변경하려 하므로 불가
```

읽기 함수에 `const`를 붙이면 함수의 의도를 표현하면서 읽기 전용 객체에서도 사용할 수 있다.

## 명령과 조회를 구분한다

원본 `Attack`은 공격력을 콘솔에 출력한다.

```cpp
void Attack()
{
    std::cout << "Attack: " << attack_ << '\n';
}
```

이 함수는 게임 규칙과 출력 장치를 결합한다. 전투 계산이나 테스트에서 공격력만 필요해도 콘솔 출력이 발생한다.

이번 예제는 공격 피해량을 값으로 반환한다.

```cpp
int AttackDamage() const
{
    return attack_;
}
```

호출자가 반환값을 필요한 방식으로 사용한다.

```cpp
int damage = knight.AttackDamage();
std::cout << "Attack: " << damage << '\n';
```

상태를 바꾸는 명령과 상태를 읽는 조회를 구분하면 클래스가 입출력 방식에 불필요하게 의존하지 않는다.

## 각 객체는 자신의 데이터 멤버를 가진다

기사 두 명을 만들면 각 객체에 `hp_`, `attack_`, `x_`, `y_` 상태가 존재한다.

```text
firstKnight
┌─────┬─────────┬────┬────┐
│ hp_ │ attack_ │ x_ │ y_ │
└─────┴─────────┴────┴────┘

secondKnight
┌─────┬─────────┬────┬────┐
│ hp_ │ attack_ │ x_ │ y_ │
└─────┴─────────┴────┴────┘
```

비정적 멤버 함수의 기계 코드가 객체마다 한 벌씩 저장된다고 생각하지 않는다. 함수는 호출 대상 객체를 통해 해당 객체의 데이터에 접근한다.

다만 C++ 표준이 클래스 객체의 크기를 단순히 데이터 멤버 크기의 합으로 보장하지도 않는다. 정렬 조건에 따른 패딩이 추가될 수 있고, 가상 함수를 가진 클래스는 구현이 동적 디스패치를 위한 정보를 객체에 둘 수 있다.

```cpp
std::cout << sizeof(Knight) << '\n';
```

`sizeof` 결과는 현재 컴파일러와 대상 환경에서 확인할 수 있지만 모든 환경에 같은 숫자를 일반화하지 않는다. 클래스 크기는 멤버 변수의 선언만 보고 무조건 그 합과 같다고 단정할 수 없다.

## 외부 코드는 공개 인터페이스만 사용한다

위치를 확인할 수 있도록 읽기 전용 조회 함수를 제공한다.

```cpp
int X() const
{
    return x_;
}

int Y() const
{
    return y_;
}
```

이제 객체의 사용 코드는 private 멤버 이름을 알 필요가 없다.

```cpp
Knight knight;
knight.Move(2, 3);

assert(knight.X() == 2);
assert(knight.Y() == 3);
```

나중에 위치를 별도 `Position` 타입으로 바꾸더라도 공개 함수 계약을 유지하면 호출부 변경을 줄일 수 있다.

Getter와 Setter를 모든 멤버에 기계적으로 만들 필요는 없다. 외부 코드에 실제로 필요한 동작을 공개하고, 내부 표현을 그대로 노출하는 함수인지 객체의 의미 있는 동작인지 구분한다.

## 고정된 상태 변화로 객체별 독립성을 검증한다

두 기사 객체에 서로 다른 동작을 적용한다.

```cpp
#include <cassert>

void VerifyKnight()
{
    Knight firstKnight;
    Knight secondKnight;

    firstKnight.Move(2, 3);
    secondKnight.Move(8, 1);
    firstKnight.Die();

    assert(firstKnight.X() == 2);
    assert(firstKnight.Y() == 3);
    assert(firstKnight.IsDead());

    assert(secondKnight.X() == 8);
    assert(secondKnight.Y() == 1);
    assert(!secondKnight.IsDead());
    assert(secondKnight.AttackDamage() == 10);
}
```

첫 번째 객체의 사망 처리가 두 번째 객체의 상태를 바꾸지 않는지 확인한다. 같은 클래스의 객체라도 비정적 데이터 멤버는 각 객체에 따로 존재한다.

## 전체 구현

클래스 선언과 멤버 함수 정의를 한 파일에서 구분해 작성한 예제다.

```cpp
#include <cassert>
#include <iostream>

class Knight
{
public:
    void Move(int x, int y);
    int AttackDamage() const;
    void Die();
    bool IsDead() const;
    int X() const;
    int Y() const;

private:
    int hp_ = 100;
    int attack_ = 10;
    int x_ = 0;
    int y_ = 0;
};

void Knight::Move(int x, int y)
{
    x_ = x;
    y_ = y;
}

int Knight::AttackDamage() const
{
    return attack_;
}

void Knight::Die()
{
    hp_ = 0;
}

bool Knight::IsDead() const
{
    return hp_ == 0;
}

int Knight::X() const
{
    return x_;
}

int Knight::Y() const
{
    return y_;
}

void VerifyKnight()
{
    Knight firstKnight;
    Knight secondKnight;

    firstKnight.Move(2, 3);
    secondKnight.Move(8, 1);
    firstKnight.Die();

    assert(firstKnight.X() == 2);
    assert(firstKnight.Y() == 3);
    assert(firstKnight.IsDead());

    assert(secondKnight.X() == 8);
    assert(secondKnight.Y() == 1);
    assert(!secondKnight.IsDead());
    assert(secondKnight.AttackDamage() == 10);
}

int main()
{
    VerifyKnight();

    Knight knight;
    knight.Move(4, 7);

    std::cout << "Position: (" << knight.X() << ", " << knight.Y() << ")\n";
    std::cout << "Attack damage: " << knight.AttackDamage() << '\n';
}
```

이 예제는 생성자 오버로딩, 상속과 가상 함수를 아직 사용하지 않는다. 하나의 클래스가 어떤 상태를 소유하고 외부에 어떤 동작을 제공하는지 확인하는 데 집중한다.

## 클래스를 설계할 때 확인할 기준

1. 클래스가 나타내는 개체와 책임을 한 문장으로 설명할 수 있는가?
2. 각 객체가 독립적으로 가져야 하는 상태가 데이터 멤버로 묶였는가?
3. 객체 하나의 상태를 직접 사용하는 동작이 멤버 함수로 표현됐는가?
4. 외부에 필요하지 않은 데이터가 `public`으로 노출되지 않았는가?
5. 기본 생성 직후 데이터 멤버가 유효한 값을 가지는가?
6. 읽기만 하는 멤버 함수에 `const`가 붙어 있는가?
7. 객체, 객체 포인터와 클래스 범위에 맞게 `.`, `->`, `::`를 구분하는가?
8. 출력과 입력을 객체의 핵심 규칙에 불필요하게 결합하지 않았는가?
9. 클래스 크기를 단순한 멤버 크기의 합으로 단정하지 않는가?
10. 모든 멤버에 Getter와 Setter를 자동으로 추가하지 않고 필요한 인터페이스만 공개하는가?

클래스는 현실 사물을 그대로 복사하는 도구라기보다 프로그램에서 함께 유지돼야 하는 상태와 그 상태를 다루는 규칙에 이름을 붙이는 타입 설계 도구다.

## 다음 학습: 생성자와 소멸자로 객체 수명을 관리한다

다음 글에서는 객체가 만들어질 때 호출되는 생성자와 수명이 끝날 때 호출되는 소멸자를 살펴본다. 기본 생성자, 복사 생성자, 인자 하나를 받는 변환 생성자와 `explicit`의 관계를 구분하고, 객체 생성과 단순 대입을 같은 동작으로 오해하지 않도록 정리한다.
