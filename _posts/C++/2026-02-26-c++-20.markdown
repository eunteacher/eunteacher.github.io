# [C++] 같은 이름의 선택지와 자기 호출의 종료 조건

다양한 조건의 함수 정의 기법(오버로딩, 기본값)을 알아보고, 재귀 호출 시 발생하는 메모리 스택 구조의 특성과 오버플로우 현상을 분석

## 세 문법이 해결하는 서로 다른 문제

```cpp
#include <iostream>
using namespace std;

// 1. 함수 오버로딩 (Function Overloading)
// - 동일한 이름의 함수를 매개변수 타입이나 개수를 다르게 하여 중복 정의함
// - 반환 형식(Return Type)만 다를 경우에는 오버로딩이 불가능함
int Add(int a, int b)
{
    return a + b;
}

float Add(float a, float b)
{
    return a + b;
}

// 2. 기본 매개변수 (Default Parameter)
// - 매개변수에 기본값을 지정하면 호출 시 생략이 가능함
// - 조심해야 할 점은 기본값 지정은 항상 오른쪽(마지막) 매개변수부터 순차적으로 이루어져야 함
void SetPlayerInformation(int hp, int mp, int power = 10, int guildId = 0)
{
    // 로직 수행 생략
}

// 3. 재귀 함수 (Recursive Function)와 스택 오버플로우
// - 함수 내부에서 자기 자신을 다시 호출하는 구조 (예: 팩토리얼 연산)
// - n! = n * (n - 1)!
int Factorial(int n)
{
    // 명확한 탈출 조건(Base Case)이 없으면 무한 루프에 빠짐
    if (n <= 1)
    {
        return 1;
    }
    return n * Factorial(n - 1);
}

int main()
{
    // [오버로딩 테스트]
    // 매개변수 타입에 따라 적절한 함수가 자동 바인딩됨
    int resultInt = Add(1, 2);
    cout << "정수 덧셈: " << resultInt << endl;

    float resultFloat = Add(1.5f, 2.1f);
    cout << "실수 덧셈: " << resultFloat << endl;

    // [기본 매개변수 테스트]
    // power와 guildId는 지정된 기본값(10, 0)으로 자동 대입됨
    SetPlayerInformation(100, 40);

    // [재귀 함수 테스트]
    int factor = Factorial(5);
    cout << "5! 결과: " << factor << endl;

    // [스택 오버플로우 유발 예시]
    // 너무 큰 값을 넣으면 함수가 과도하게 호출되어 스택 메모리가 가득 차서 터짐
    // Factorial(100000000);

    return 0;
}
```

## 호출할 함수를 고르는 규칙



### 함수 오버로딩 (Function Overloading) 성립 조건

함수의 이름이 같더라도 매개변수의 시그니처가 다르면 다른 함수로 취급하여 컴파일러가 알아서 분기 처리

| 조건 | 오버로딩 가능 여부 | 비고 |
| :--- | :--- | :--- |
| **매개변수 개수가 다름** | 가능 | `Add(int a)`, `Add(int a, int b)` |
| **매개변수 타입이 다름** | 가능 | `Add(int a, int b)`, `Add(float a, float b)` |
| **반환 타입만 다름** | 불가능 | 컴파일 에러 발생 (호출 시 모호함) |

### 기본 매개변수 (Default Parameter) 규칙

기본값을 설정할 때는 반드시 매개변수 목록의 가장 오른쪽 끝에서부터 왼쪽으로 채워나가야 하고,
이는 함수 호출 시 전달되는 인자가 왼쪽에서 오른쪽으로 순서대로 매핑되기 때문임



### 재귀 함수와 스택 오버플로우 (Stack Overflow)

* 팩토리얼과 같은 재귀적 연산을 구현할 때 유용하며 수학적 점화식을 그대로 코드로 옮길 수 있음
  $$n! = n \times (n - 1)!$$
* 함수가 호출될 때 메모리의 스택(Stack) 영역에 스택 프레임(Stack Frame)이 독립적인 공간으로 할당
* 재귀 함수(Recursive Function)를 구현할 때 명확한 탈출 조건(Base Case)이 없거나 호출 깊이가 너무 깊으면, 스택 프레임이 무한히 쌓여 스택 메모리 한계를 초과하는 스택 오버플로우(Stack Overflow) 에러가 발생

## 모호한 호출과 깊은 재귀 점검하기

### 핵심 요약 및 주의사항

* **기본 매개변수 선언 위치**: 기본 매개변수는 함수의 원형(선언부)과 구현부(정의부) 중 한 곳에만 지정해야 하며, 보통 헤더 파일의 선언부에 작성하는 것이 관례
* **오버로딩 모호성**: 여러 후보에 필요한 변환의 우선순위가 같으면 호출이 모호해진다. `1.0`은 `double`, `1.0f`는 `float`이므로 리터럴 타입도 후보 선택에 영향을 준다.
* **탈출 조건 필수**: 재귀 함수 설계 시 무한 루프를 막기 위한 기저 조건(Base Case)을 함수 최상단에 배치

### Tip

* 호출 깊이가 입력에 비례하고 크게 자랄 수 있다면 반복문 변환을 검토한다. 재귀가 항상 느리거나 반복문이 항상 낫다는 뜻은 아니며, 트리 탐색처럼 문제 구조를 잘 표현하는 경우도 있다. C++은 꼬리 호출 최적화를 보장하지 않는다.
* 매개변수가 많은 함수의 경우, 기본 매개변수를 무분별하게 사용하기보다는 구조체(Struct)나 클래스(Class)로 연관된 데이터를 묶어서 전달하는 것이 가독성을 높이는 방법

기본 인자는 호출 지점에서 채워지며 가상 함수처럼 동적 디스패치되지 않는다. 공개 API의 기본값을 바꾸면 이미 빌드된 호출 코드에는 이전 값이 남을 수 있다는 점도 기억한다.

## 마무리

오버로딩은 타입에 따른 인터페이스 선택, 기본 인자는 흔한 호출의 축약, 재귀는 문제의 자기 유사 구조를 표현한다. 편리함보다 호출이 모호하지 않은지와 종료·깊이 조건이 명확한지를 먼저 확인한다.
