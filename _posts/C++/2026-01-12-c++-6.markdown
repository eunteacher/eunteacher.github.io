# [C++] 계산식보다 먼저 알아야 할 연산 규칙

`+`, `-`, `*`, `/`는 익숙하지만 피연산자의 타입과 평가 규칙에 따라 결과가 달라진다. 특히 초기화와 대입, 정수 나눗셈, 증감 연산자의 차이를 정확히 구분해야 한다.

## 1. 초기화와 대입은 다르다

```cpp
int score = 10; // 선언과 동시에 초기화
score = 20;     // 이미 존재하는 객체에 새 값을 대입
```

기본 정수에서는 비슷해 보이지만 사용자 정의 타입에서는 생성과 대입이 서로 다른 함수를 호출할 수 있다. 지역 기본형 변수를 초기화하지 않고 읽으면 정의되지 않은 동작이 발생할 수 있으므로, 사용할 값으로 바로 초기화하는 습관이 안전하다.

대입 연산자는 오른쪽 결합이므로 연쇄 대입도 가능하다.

```cpp
int a = 0;
int b = 0;

a = b = 3; // b = 3을 수행한 뒤 그 결과를 a에 대입
```

## 2. 같은 `/`라도 타입에 따라 결과가 다르다

```cpp
#include <iostream>

int main()
{
    std::cout << 5 / 2 << '\n';                    // 2
    std::cout << 5.0 / 2.0 << '\n';                // 2.5
    std::cout << static_cast<double>(5) / 2 << '\n'; // 2.5
}
```

정수끼리 나누면 결과도 정수이며 소수 부분은 **0 방향으로 절삭**된다. 나눗셈이 끝난 뒤 결과를 `double`에 저장해도 잃어버린 소수 부분은 돌아오지 않는다.

```cpp
double wrong = 5 / 2;   // 정수 2를 double 2.0으로 변환
double right = 5.0 / 2; // 2.5
```

`%`는 정수형에 사용하는 나머지 연산자다. C++에서 `(a / b) * b + a % b == a` 관계를 만족하며, 나눗셈 결과가 0 방향으로 절삭되므로 나머지의 부호는 피제수 `a`를 따른다.

## 3. 0으로 나누면 무조건 같은 결과가 아니다

정수의 0 나눗셈과 0 나머지는 정의되지 않은 동작이다. 단순히 “항상 예외가 발생한다”거나 “항상 프로그램이 종료된다”고 보장할 수 없다.

```cpp
int Divide(int numerator, int denominator)
{
    if (denominator == 0)
    {
        // 실제 코드에서는 오류 전달 방식을 정책에 맞게 선택한다.
        return 0;
    }

    return numerator / denominator;
}
```

부호 있는 정수에서는 최솟값을 `-1`로 나눠 결과를 표현할 수 없는 경우도 정의되지 않은 동작이다. 부동소수점 0 나눗셈은 구현이 IEC 60559(IEEE 754)를 지원하는지와 예외 환경에 따라 무한대나 NaN 등이 될 수 있으므로 별개의 규칙으로 다뤄야 한다.

## 4. 복합 대입은 단순 축약 이상의 의미가 있다

```cpp
int value = 10;
value += 3;
value *= 2;
```

기본적인 경우 `value += 3`은 `value = value + 3`과 같은 결과를 내지만, 좌항은 한 번만 평가된다. 타입 변환 규칙에도 차이가 생길 수 있으므로 복잡한 표현식을 기계적으로 치환해서 이해해서는 안 된다.

```cpp
int values[] = {10, 20};
int index = 0;

values[index++] += 5; // 좌항의 index++는 한 번 평가됨
```

## 5. 전위와 후위 증감

```cpp
int a = 10;
int before = a++; // before는 10, a는 11
int after  = ++a; // a를 12로 만든 뒤 after도 12
```

반환값을 쓰지 않는 기본 정수 연산에서는 현대 컴파일러가 전위와 후위를 대개 같은 코드로 최적화한다. “전위는 언제나 빠르다”는 식으로 외울 필요는 없다. 다만 반복자나 사용자 정의 타입의 후위 연산은 이전 값을 복사해야 할 수 있어, 반환값이 필요 없다면 전위를 쓰는 관례가 합리적이다.

## 6. 우선순위와 평가 순서는 다른 개념이다

```cpp
int result = 2 + 3 * 4;   // 14
int clear  = (2 + 3) * 4; // 20
```

우선순위는 표현식이 어떻게 묶이는지를 정한다. 함수 인자나 하위 표현식이 실제로 어느 순서에 평가되는지는 별도의 규칙이다. 한 표현식에서 같은 값을 여러 번 변경하는 코드는 버전별 규칙까지 따져야 하므로 문장을 나누는 편이 낫다.

```cpp
int value = 1;
int oldValue = value;
++value;
int sum = oldValue + value;
```

## 전체 예제

```cpp
#include <iostream>

int main()
{
    int total = 17;
    int players = 4;

    int quotient = total / players;
    int remainder = total % players;
    double average = static_cast<double>(total) / players;

    std::cout << "몫: " << quotient << '\n';
    std::cout << "나머지: " << remainder << '\n';
    std::cout << "평균: " << average << '\n';
}
```

## 마무리

연산자의 모양보다 중요한 것은 **어떤 타입끼리 계산하는지**, **언제 값이 바뀌는지**, **결과를 표현할 수 있는지**다. 가독성을 위한 괄호와 중간 변수는 불필요한 장식이 아니라 실수를 막는 도구다.
