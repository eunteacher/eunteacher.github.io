지금까지 정수, `bool`, 부동소수점, 문자와 문자열을 변수에 저장하는 방법을 살펴봤다. 이제 저장한 값을 실제로 변경하고 계산할 차례다.

`+`, `-`, `*`, `/`는 수학에서도 사용하는 익숙한 기호다. 하지만 C++에서는 같은 연산자라도 피연산자의 타입에 따라 계산 방법과 결과 타입이 달라진다. 특히 초기화와 대입, 정수 나눗셈, 증감 연산의 평가 시점은 익숙한 모양 때문에 오히려 놓치기 쉽다.

## 초기화와 대입은 서로 다른 작업이다

다음 두 문장은 모두 `=`를 사용하지만 같은 작업이 아니다.

```cpp
int score = 10; // 초기화
score = 20;     // 대입
```

첫 번째 문장은 `score`라는 객체를 만들면서 초기값 10을 지정한다. 두 번째 문장은 이미 존재하는 `score` 객체의 값을 20으로 바꾼다.

```text
초기화
객체가 없음 ──→ score 객체 생성 ──→ 초기값 10

대입
score 객체가 이미 존재함 ──→ 기존 값을 20으로 교체
```

`int`처럼 단순한 타입에서는 결과만 보면 비슷해 보인다. 이후 클래스와 객체를 배우면 초기화는 생성자, 대입은 대입 연산자와 연결될 수 있으므로 둘을 구분하는 것이 중요하다.

C++에는 여러 초기화 문법이 있다.

```cpp
int first = 10;
int second(10);
int third{10};
int fourth = {10};
```

네 변수는 모두 10으로 초기화된다. 입문 단계에서는 중괄호 초기화가 좁히기 변환을 막아 준다는 점이 유용하다.

```cpp
int first = 3.14; // 컴파일 가능: 3으로 변환될 수 있음
// int second{3.14}; // 컴파일 오류: 좁히기 변환
```

`double`의 소수 부분을 잃어버리는 변환이 의도하지 않은 실수라면 중괄호 초기화가 컴파일 단계에서 발견해 준다.

## 초기화하지 않은 지역 변수는 읽지 않는다

기본 정수 타입의 지역 변수를 초기값 없이 선언하면 사용할 수 있는 값이 자동으로 들어간다고 기대해서는 안 된다.

```cpp
#include <iostream>

int main()
{
    int score;

    // std::cout << score << '\n'; // 초기화되지 않은 값을 읽음
}
```

디버그 환경에서 특정한 숫자가 보이거나 0처럼 보이더라도 그것은 프로그램이 의존할 수 있는 값이 아니다. 값을 사용하기 전에 목적에 맞는 초기값을 지정한다.

```cpp
int score = 0;
int playerCount{0};
```

모든 변수를 무조건 0으로 만드는 것이 정답은 아니다. 객체를 생성하는 시점에 실제 의미가 있는 값을 알고 있다면 그 값으로 바로 초기화하는 편이 좋다.

```cpp
int maxHp = 100; // 의미 있는 값으로 바로 초기화
```

## 대입 연산의 결과도 값처럼 사용할 수 있다

대입 연산자 `=`는 오른쪽 값을 왼쪽 객체에 저장하고, 그 왼쪽 객체를 결과로 돌려준다. 이 때문에 연쇄 대입이 가능하다.

```cpp
int a = 0;
int b = 0;

a = b = 3;
```

대입 연산자는 오른쪽 결합성을 가진다. 따라서 위 표현식은 다음과 같이 묶인다.

```cpp
a = (b = 3);
```

동작 순서는 다음과 같다.

1. `b = 3`을 수행한다.
2. 그 대입 결과를 `a`에 대입한다.
3. 최종적으로 `a`와 `b`는 모두 3이 된다.

서로 같은 값을 넣을 때는 편리하지만, 타입이 서로 다르면 각 대입 단계에서 변환이 일어날 수 있다.

```cpp
double precise = 0.0;
int whole = 0;

precise = whole = 3.75;
```

먼저 `3.75`가 `int`인 `whole`에 대입되면서 3으로 변환된다. 그 대입 결과인 정수 3이 `precise`에 전달되므로 `precise`도 3.0이 된다.

```text
3.75
  ↓ int로 변환
whole = 3
  ↓ 대입 결과 3
precise = 3.0
```

표현식이 짧다고 해서 변환 과정까지 단순한 것은 아니다. 타입이 다른 연쇄 대입은 문장을 나누는 편이 의도를 읽기 쉽다.

## 기본 산술 연산자

C++의 기본 산술 연산자는 다음과 같다.

| 연산자 | 의미 | 예제 |
| :---: | :--- | :--- |
| `+` | 덧셈 | `a + b` |
| `-` | 뺄셈 | `a - b` |
| `*` | 곱셈 | `a * b` |
| `/` | 나눗셈 | `a / b` |
| `%` | 나머지 | `a % b` |

단항 `+`와 `-`도 있다.

```cpp
int value = 10;
int positive = +value;
int negative = -value;
```

`-value`는 부호를 반대로 만든다. 다만 부호 있는 정수의 최솟값은 같은 타입의 양수로 표현하지 못할 수 있다. 예를 들어 일반적인 32비트 `int`에서 `INT_MIN`에 단항 `-`를 적용하면 표현 범위를 벗어난다.

## 계산 전에 작은 정수 타입이 승격될 수 있다

C++은 피연산자를 그대로 계산하지 않고 먼저 타입을 변환할 수 있다. `char`와 `short` 같은 작은 정수 타입은 대개 `int`로 승격된다.

```cpp
#include <type_traits>

int main()
{
    short left = 10;
    short right = 20;

    auto result = left + right;

    static_assert(std::is_same_v<decltype(result), int>);
}
```

`short + short`라고 해서 결과까지 반드시 `short`인 것은 아니다. 두 피연산자가 `int`로 승격된 뒤 계산되므로 `result`의 타입은 `int`다.

정수와 실수를 함께 계산하면 정수 쪽이 실수 타입으로 변환된다.

```cpp
int count = 5;
double scale = 0.5;

auto result = count * scale; // double 2.5
```

이러한 변환 덕분에 서로 다른 타입도 계산할 수 있지만, 부호 있는 정수와 부호 없는 정수를 섞거나 더 좁은 타입에 결과를 다시 저장하면 예상과 다른 값이 생길 수 있다. 계산식에서는 피연산자와 결과의 타입을 함께 확인해야 한다.

## 정수 나눗셈은 소수 부분을 만들지 않는다

같은 `/` 연산자라도 피연산자의 타입에 따라 결과가 달라진다.

```cpp
#include <iostream>

int main()
{
    std::cout << 5 / 2 << '\n';       // 2
    std::cout << 5.0 / 2.0 << '\n';   // 2.5
}
```

`5 / 2`는 양쪽 모두 `int`이므로 정수 나눗셈을 수행한다. 정확한 수학 결과인 2.5에서 소수 부분을 제거하고 2를 얻는다.

중요한 점은 나눗셈 결과를 어디에 저장하느냐가 아니라 **나눗셈을 수행할 때 피연산자가 어떤 타입인가**다.

```cpp
double wrong = 5 / 2;   // 정수 2를 double 2.0으로 변환
double right = 5.0 / 2; // 실수 나눗셈 결과 2.5
```

첫 번째 문장에서는 정수 나눗셈이 이미 끝난 뒤 결과 2가 `double`로 변환된다. 잃어버린 소수 부분은 결과 변수의 타입을 바꾼다고 돌아오지 않는다.

명시적 타입 변환으로 피연산자 하나를 먼저 `double`로 만들 수도 있다.

```cpp
int total = 5;
int count = 2;

double average = static_cast<double>(total) / count;
```

한쪽이 `double`이 되면 다른 쪽도 `double`로 변환된 뒤 실수 나눗셈을 수행한다.

## 음수 정수 나눗셈은 0 방향으로 절삭한다

C++의 정수 나눗셈은 결과의 소수 부분을 **0 방향으로 절삭**한다.

```cpp
#include <iostream>

int main()
{
    std::cout << 7 / 3 << '\n';   // 2
    std::cout << -7 / 3 << '\n';  // -2
}
```

`-7 / 3`의 수학 결과는 약 -2.333이지만, 0에 가까운 방향으로 소수 부분을 제거하므로 -2가 된다. 단순히 항상 아래 정수로 내리는 바닥 함수(Floor)와는 다르다.

```text
수학 결과: -2.333...

0 방향 절삭 → -2
바닥 처리   → -3
```

음수를 포함한 나눗셈 로직에서는 두 방식을 혼동하지 않아야 한다.

## 나머지 연산자는 정수에 사용한다

나머지 연산자 `%`는 정수형 피연산자에 사용한다.

```cpp
int quotient = 17 / 4;  // 4
int remainder = 17 % 4; // 1
```

나누는 값이 0이 아니고 몫을 해당 타입으로 표현할 수 있다면 다음 관계가 성립한다.

```text
(a / b) * b + (a % b) == a
```

음수가 포함되면 나머지의 부호는 왼쪽 피연산자, 즉 피제수의 부호를 따른다.

```cpp
std::cout << 7 % 3 << '\n';   // 1
std::cout << -7 % 3 << '\n';  // -1
```

나머지 연산은 짝수·홀수 판별이나 일정한 주기의 반복에 자주 사용한다.

```cpp
bool isEven = number % 2 == 0;
int wrappedIndex = index % 4;
```

단, `index`가 음수가 될 수 있다면 `% 4`의 결과도 음수가 될 수 있다. 배열 인덱스를 순환시키는 코드에서는 입력 범위와 원하는 나머지 정의를 따로 확인해야 한다.

## 정수를 0으로 나누면 정의되지 않은 동작이다

정수의 나눗셈과 나머지 연산에서 오른쪽 피연산자가 0이면 정의되지 않은 동작(Undefined Behavior)이다.

```cpp
int value = 10;
int divisor = 0;

// int quotient = value / divisor;
// int remainder = value % divisor;
```

이를 “항상 예외가 발생한다” 또는 “항상 프로그램이 종료된다”고 설명할 수는 없다. 실행 중 충돌할 수도 있고, 전혀 다른 결과가 나타날 수도 있으며, 컴파일러 최적화에 의해 주변 코드까지 예상과 다르게 동작할 수 있다.

나눗셈 전에 분모를 검사한다.

```cpp
#include <iostream>

bool TryDivide(int numerator, int denominator, int& result)
{
    if (denominator == 0)
    {
        return false;
    }

    result = numerator / denominator;
    return true;
}

int main()
{
    int result = 0;

    if (TryDivide(10, 2, result))
    {
        std::cout << result << '\n';
    }
    else
    {
        std::cout << "0으로 나눌 수 없습니다.\n";
    }
}
```

오류를 `bool`로 알릴지, 예외나 별도의 결과 타입을 사용할지는 프로그램의 오류 처리 정책에 따라 결정한다. 중요한 점은 정상적인 계산 결과와 실패를 구분하는 것이다.

부호 있는 정수에는 분모가 0이 아닌데도 문제가 되는 한 가지 경계가 더 있다. 타입의 최솟값을 `-1`로 나누면 양수 결과를 같은 타입으로 표현할 수 없으므로 정의되지 않은 동작이다.

```cpp
#include <limits>

int minimum = std::numeric_limits<int>::min();

// int overflow = minimum / -1;
```

부동소수점의 0 나눗셈은 정수와 같은 규칙으로 단정하면 안 된다. IEC 60559, 흔히 IEEE 754라고 부르는 방식을 지원하는 일반적인 환경에서는 유한한 0이 아닌 값을 0.0으로 나누면 무한대가 되고, 0.0을 0.0으로 나누면 NaN이 될 수 있다. 구체적인 동작은 구현과 부동소수점 환경의 영향을 받는다.

## 정수 오버플로 규칙은 타입에 따라 다르다

산술 연산 결과가 타입의 표현 범위를 벗어날 수도 있다.

```cpp
#include <limits>

int maximum = std::numeric_limits<int>::max();

// int overflow = maximum + 1;
```

부호 있는 정수의 산술 오버플로는 정의되지 않은 동작이다. 값이 최대에서 최소로 돌아올 것이라고 가정하면 안 된다.

반면 부호 없는 정수는 표현 가능한 값의 개수를 법으로 계산하므로 최대값 다음에 0으로 돌아간다.

```cpp
#include <iostream>
#include <limits>

int main()
{
    unsigned int value = std::numeric_limits<unsigned int>::max();

    ++value;

    std::cout << value << '\n'; // 0
}
```

부호 없는 정수의 순환은 정의된 동작이지만, 언제나 의도한 결과라는 뜻은 아니다. 체력이나 재고처럼 음수가 되면 안 되는 값을 `unsigned`로 만들었을 때 0에서 1을 빼면 최대값으로 돌아갈 수 있다.

## 복합 대입 연산자는 왼쪽을 한 번만 평가한다

산술 연산과 대입을 함께 표현하는 복합 대입 연산자가 있다.

```cpp
int value = 10;

value += 3; // value = value + 3
value -= 2; // value = value - 2
value *= 4; // value = value * 4
value /= 2; // value = value / 2
value %= 5; // value = value % 5
```

기본적인 경우 `value += 3`은 `value = value + 3`과 같은 결과를 낸다. 중요한 차이는 복합 대입에서 왼쪽 피연산자가 한 번만 평가된다는 점이다.

```cpp
int values[] = {10, 20, 30};
int index = 0;

values[index++] += 5;
```

위 표현식에서 `index++`는 한 번만 평가된다. 따라서 첫 번째 요소는 15가 되고 `index`는 1이 된다.

다만 복잡한 부작용이 들어간 표현식은 문법적으로 가능하더라도 읽기 어렵다. 다음처럼 대상을 먼저 정하면 평가 시점을 추적하기 쉽다.

```cpp
int currentIndex = index++;
values[currentIndex] += 5;
```

복합 대입에서도 계산 과정에 정수 승격이 적용되고, 최종 결과는 다시 왼쪽 객체의 타입으로 변환되어 저장된다.

```cpp
#include <cstdint>

std::uint8_t value = 250;
value += 10;
```

`value + 10`에 해당하는 계산은 정수 승격 이후 수행되고, 결과는 다시 `std::uint8_t`에 저장된다. 정확히 8비트인 부호 없는 타입이 제공되는 환경이라면 결과는 4가 된다. 코드가 컴파일된다는 사실과 값이 의도한 범위에 있다는 사실은 별개다.

## 전위와 후위 증감은 결과를 사용하는 시점이 다르다

`++`와 `--`는 값을 1만큼 증가시키거나 감소시킨다.

```cpp
int value = 10;

++value; // 11
--value; // 10
value++; // 11
value--; // 10
```

반환 결과를 사용하지 않는 위 코드에서는 전위와 후위가 같은 최종 값을 만든다. 차이는 연산 결과를 다른 표현식에서 사용할 때 드러난다.

```cpp
int value = 10;

int before = value++; // before는 10, value는 11
int after = ++value;  // value를 12로 만든 뒤 after도 12
```

후위 증감은 변경 전의 값을 결과로 사용한 뒤 객체를 변경한다.

```text
before = value++

1. 기존 value인 10을 결과로 준비
2. value를 11로 증가
3. 준비한 10을 before에 저장
```

전위 증감은 객체를 먼저 변경하고 변경된 값을 결과로 사용한다.

```text
after = ++value

1. value를 12로 증가
2. 변경된 12를 after에 저장
```

반복문의 기본 정수처럼 반환값을 버리는 상황에서는 현대 컴파일러가 전위와 후위를 대개 같은 코드로 최적화한다.

```cpp
for (int i = 0; i < 10; ++i)
{
    // 반복 작업
}
```

따라서 기본 정수에서 “전위 증감은 무조건 빠르다”고 외울 필요는 없다. 다만 반복자나 사용자 정의 타입의 후위 연산은 변경 전 값을 반환하기 위한 복사가 필요할 수 있다. 이전 값이 필요하지 않다면 전위를 사용하는 관례는 합리적이다.

## 한 표현식에서 같은 값을 여러 번 변경하지 않는다

증감 연산자를 다른 연산과 지나치게 섞으면 평가 순서를 판단하기 어려워진다.

```cpp
int value = 1;

// int result = value++ + value++;
```

이와 같은 코드는 C++ 버전별 순서 규칙을 따져야 할 뿐 아니라, 읽는 사람도 각 연산이 어느 값을 사용하는지 쉽게 알 수 없다. 한 문장에 여러 부작용을 넣지 않고 단계별로 분리한다.

```cpp
int value = 1;

int first = value;
++value;

int second = value;
++value;

int result = first + second;
```

코드가 몇 줄 늘어나더라도 값의 변화가 명확해진다.

## 연산자 우선순위는 표현식이 묶이는 방법이다

곱셈과 나눗셈은 덧셈과 뺄셈보다 우선순위가 높다.

```cpp
int first = 2 + 3 * 4;   // 14
int second = (2 + 3) * 4; // 20
```

첫 번째 표현식은 다음과 같이 묶인다.

```cpp
int first = 2 + (3 * 4);
```

우선순위는 연산자가 어떤 피연산자와 결합하는지를 정한다. 결합성은 같은 우선순위의 연산자가 연속될 때 어느 방향으로 묶이는지를 정한다.

```cpp
int subtraction = 10 - 3 - 2;
```

뺄셈은 왼쪽 결합성이므로 다음과 같다.

```cpp
int subtraction = (10 - 3) - 2; // 5
```

반면 대입 연산자는 오른쪽 결합성이므로 앞에서 본 `a = b = 3`이 가능하다.

우선순위를 모두 외우기보다 의도한 묶음을 괄호로 드러내는 편이 좋다. 다만 이미 명확한 간단한 계산까지 괄호로 감싸 표현을 복잡하게 만들 필요는 없다.

## 우선순위와 평가 순서는 다른 개념이다

우선순위가 높다는 말이 그 부분이 항상 시간상 먼저 실행된다는 뜻은 아니다.

```cpp
int result = FunctionA() + FunctionB() * FunctionC();
```

이 표현식은 다음과 같이 묶인다.

```cpp
int result = FunctionA() + (FunctionB() * FunctionC());
```

하지만 함수 호출 자체가 어떤 순서로 평가되는지는 우선순위만 보고 결정할 수 없다. 연산자 우선순위는 문법적인 묶음을 설명하고, 평가 순서는 각 하위 표현식을 실제로 언제 계산하는지를 설명하는 별도의 규칙이다.

함수가 외부 상태를 바꾸는 경우 평가 순서가 결과에 영향을 줄 수 있다. 이런 코드는 호출을 분리해 순서를 명시한다.

```cpp
int a = FunctionA();
int b = FunctionB();
int c = FunctionC();

int result = a + b * c;
```

## 전체 실습 코드

지금까지 다룬 연산 규칙을 한 번에 확인하면 다음과 같다.

```cpp
#include <iostream>
#include <limits>
#include <type_traits>

bool TryDivide(int numerator, int denominator, int& result)
{
    if (denominator == 0)
    {
        return false;
    }

    if (numerator == std::numeric_limits<int>::min()
        && denominator == -1)
    {
        return false;
    }

    result = numerator / denominator;
    return true;
}

int main()
{
    int a = 0;
    int b = 0;

    a = b = 3;
    std::cout << "a: " << a << ", b: " << b << '\n';

    short left = 10;
    short right = 20;
    auto promoted = left + right;

    static_assert(std::is_same_v<decltype(promoted), int>);

    int total = 17;
    int count = 4;

    std::cout << "integer division: " << total / count << '\n';
    std::cout << "remainder: " << total % count << '\n';
    std::cout << "floating-point division: " << static_cast<double>(total) / count << '\n';

    int quotient = 0;

    if (TryDivide(total, count, quotient))
    {
        std::cout << "checked quotient: " << quotient << '\n';
    }

    int value = 10;
    int before = value++;
    int after = ++value;

    std::cout << "before: " << before << '\n';
    std::cout << "after: " << after << '\n';
    std::cout << "value: " << value << '\n';
}
```

실행하면 다음 내용을 확인할 수 있다.

- 연쇄 대입은 오른쪽부터 묶인다.
- `short + short`의 결과가 `int`로 승격된다.
- 정수 나눗셈과 실수 나눗셈의 결과가 다르다.
- 나머지 연산은 나눗셈의 나머지를 구한다.
- 나눗셈 전에 잘못된 입력을 검사할 수 있다.
- 후위 증감은 변경 전 값을, 전위 증감은 변경 후 값을 결과로 사용한다.
