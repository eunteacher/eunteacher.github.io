앞에서는 비트 연산자를 이용해 정수 안의 각 비트를 조작했다. 이번에는 두 값을 비교하고 여러 조건을 조합해 하나의 `bool` 결과를 만드는 방법을 살펴본다.

조건식은 이후에 배울 `if`, `while`, `for` 같은 제어문의 출발점이다. 연산자 모양만 외우기보다 **무엇을 먼저 비교하는지**, **어떤 타입으로 변환되는지**, **오른쪽 조건이 실제로 실행되는지**를 함께 이해해야 한다.

## 비교 연산의 결과는 `bool`이다

비교 연산자는 두 피연산자의 관계를 확인하고 `true` 또는 `false`를 반환한다.

```cpp
int playerHp = 80;
int monsterHp = 100;

bool hasSameHp = playerHp == monsterHp;
bool hasDifferentHp = playerHp != monsterHp;
bool playerHasMoreHp = playerHp > monsterHp;
bool playerHasLessHp = playerHp < monsterHp;
```

비교 결과의 타입이 정말 `bool`인지 컴파일 단계에서 확인할 수도 있다.

```cpp
#include <type_traits>

int main()
{
    int a = 10;
    int b = 20;
    auto result = a < b;

    static_assert(std::is_same_v<decltype(result), bool>);
}
```

비교 연산자는 다음 여섯 가지다.

| 연산자 | 의미 | 예제 |
| :---: | :--- | :--- |
| `==` | 두 값이 같은가? | `a == b` |
| `!=` | 두 값이 다른가? | `a != b` |
| `<` | 왼쪽이 더 작은가? | `a < b` |
| `>` | 왼쪽이 더 큰가? | `a > b` |
| `<=` | 왼쪽이 작거나 같은가? | `a <= b` |
| `>=` | 왼쪽이 크거나 같은가? | `a >= b` |

`a < b`와 `b > a`는 같은 관계를 표현한다. 코드에서는 조건을 읽는 사람이 자연스럽게 이해할 수 있는 방향을 선택한다.

```cpp
bool isDead = hp <= 0;
bool reachedMaxLevel = level >= maxLevel;
```

변수 이름까지 합치면 각각 “체력이 0 이하인가?”, “최대 레벨에 도달했는가?”라는 질문처럼 읽힌다.

## `=`와 `==`는 완전히 다른 연산자다

대입 연산자 `=`는 왼쪽 객체의 값을 변경한다. 동등 비교 연산자 `==`는 두 값이 같은지 검사한다.

```cpp
int score = 0;

score = 100;             // score를 100으로 변경
bool isPerfect = score == 100; // score가 100인지 비교
```

조건식에서 `==` 대신 `=`를 잘못 입력해도 항상 컴파일 오류가 발생하는 것은 아니다.

```cpp
int score = 0;

if (score = 100)
{
    // score에 100을 대입한 뒤, 대입 결과 100을 true로 변환한다.
}
```

대입 결과인 100은 0이 아니므로 `bool`로 변환하면 `true`다. 결국 조건이 참이 될 뿐만 아니라 `score`의 값까지 바뀐다.

의도적으로 조건식 안에서 대입하는 코드도 작성할 수 있지만, 단순한 오타와 구분하기 어렵다. 컴파일러 경고를 활성화하고 대입과 비교의 목적을 분명히 나누는 편이 좋다.

## 비교하기 전에 타입 변환이 일어날 수 있다

서로 다른 산술 타입을 비교하면 C++은 공통으로 비교할 수 있는 타입을 찾기 위해 변환을 수행한다.

```cpp
int count = 10;
double limit = 10.5;

bool result = count < limit;
```

이 비교에서는 `count`가 `double`로 변환된 뒤 10.0과 10.5를 비교한다.

작은 정수 타입도 비교 전에 정수 승격을 거칠 수 있다.

```cpp
char first = 'A';
char second = 'B';

bool result = first < second;
```

일반적인 환경에서는 두 `char`가 `int`로 승격된 뒤 문자 집합의 정수 값을 비교한다. 문자열의 사전식 정렬이나 언어별 문자 정렬 규칙을 수행하는 것은 아니다.

## Signed와 Unsigned 비교는 특히 주의한다

부호 있는 정수와 부호 없는 정수를 비교하면 음수가 매우 큰 양수로 변환될 수 있다.

```cpp
#include <iostream>

int main()
{
    int signedValue = -1;
    unsigned int unsignedValue = 1;

    std::cout << std::boolalpha;
    std::cout << (signedValue < unsignedValue) << '\n';
}
```

일반적인 `int`와 `unsigned int` 비교에서는 `signedValue`가 `unsigned int`로 변환된다. `-1`은 해당 부호 없는 타입의 최대값으로 변환되므로 비교 결과는 예상과 달리 `false`가 된다.

```text
signedValue = -1
        ↓ unsigned int로 변환
UINT_MAX

UINT_MAX < 1 → false
```

컨테이너의 `size()`처럼 크기를 나타내는 값은 대개 부호 없는 타입이다. 반복문의 정수 인덱스와 비교할 때 경고가 발생한다면 경고를 숨기기 위한 캐스트부터 추가하지 말고, 두 값이 정말 같은 범위의 개념인지 먼저 확인한다.

```cpp
#include <string>

std::string text = "Hello";

for (std::string::size_type i = 0; i < text.size(); ++i)
{
    // text[i] 사용
}
```

범위 기반 반복문이나 C++20의 `std::ssize`를 사용할 수 있는 상황이라면 부호 혼합 자체를 피할 수도 있다.

## 정수 비교와 부동소수점 비교는 기준이 다르다

정수는 표현 범위 안에서 값을 정확히 저장하므로 동일한 값인지 `==`로 직접 비교하기 자연스럽다.

```cpp
int currentLevel = 10;
int requiredLevel = 10;

bool canEnter = currentLevel == requiredLevel;
```

부동소수점은 많은 실수를 근삿값으로 저장한다. 계산을 거친 두 값이 수학적으로 같아야 하더라도 실제 비트 표현이 조금 다를 수 있다.

```cpp
#include <iomanip>
#include <iostream>

int main()
{
    double calculated = 0.1 + 0.2;
    double expected = 0.3;

    std::cout << std::setprecision(17);
    std::cout << calculated << '\n';
    std::cout << expected << '\n';
    std::cout << std::boolalpha << (calculated == expected) << '\n';
}
```

일반적인 IEEE 754 `double` 환경에서는 마지막 비교가 `false`가 될 수 있다. 그렇다고 부동소수점에 `==`를 절대 사용하면 안 되는 것은 아니다.

다음처럼 정확히 같은 표현을 기대하는 상황에서는 직접 비교가 의도에 맞을 수 있다.

- 같은 변수나 그대로 복사한 값 비교
- 특정 센티널 값을 검사하도록 명확히 설계한 경우
- 정수에서 정확히 표현 가능한 값만 사용하는 경우
- 비트 단위로 동일한 결과가 요구되는 테스트

계산 오차를 허용해야 한다면 문제의 단위와 값의 크기에 맞는 허용 오차를 정한다.

```cpp
#include <algorithm>
#include <cmath>

bool NearlyEqual(double a, double b, double absoluteTolerance, double relativeTolerance)
{
    if (a == b)
    {
        return true;
    }

    if (!std::isfinite(a) || !std::isfinite(b))
    {
        return false;
    }

    double difference = std::abs(a - b);
    double scale = std::max(std::abs(a), std::abs(b));
    double tolerance = std::max(absoluteTolerance, relativeTolerance * scale);
    return difference <= tolerance;
}
```

먼저 정확히 같은 값은 바로 `true`로 처리한다. 덕분에 같은 부호의 무한대도 비교할 수 있다. 둘 중 하나가 유한한 값이 아니라면 이후의 허용 오차 계산을 수행하지 않는다.

절대 오차는 0 근처의 값을 비교할 때 필요하고, 상대 오차는 값의 크기가 커질 때 허용 범위를 함께 조정한다. 두 허용 오차에는 0 이상의 값을 전달해야 한다. 허용 오차를 아무 값이나 복사해 사용하지 말고 좌표, 시간, 화폐처럼 데이터가 가진 의미에 맞춰 정해야 한다.

## NaN은 일반적인 순서 비교를 따르지 않는다

부동소수점의 NaN(Not a Number)은 숫자로 정의할 수 없는 결과를 표현한다. NaN이 포함된 동등 비교와 순서 비교는 대부분 `false`다.

```cpp
#include <cmath>
#include <iostream>
#include <limits>

int main()
{
    double value = std::numeric_limits<double>::quiet_NaN();

    std::cout << std::boolalpha;
    std::cout << (value == value) << '\n'; // false
    std::cout << (value < 10.0) << '\n';   // false
    std::cout << (value > 10.0) << '\n';   // false
    std::cout << (value != value) << '\n'; // true
    std::cout << std::isnan(value) << '\n'; // true
}
```

NaN 여부를 확인하려고 `value == NaN`처럼 비교하지 않는다. 의도를 드러내는 `std::isnan`을 사용한다.

## C 문자열에서 `==`는 문자 내용을 비교하지 않는다

문자열 비교에서도 타입을 확인해야 한다. `const char*` 두 개에 `==`를 사용하면 문자열 내용이 아니라 포인터 값, 즉 두 포인터가 같은 주소를 가리키는지 비교한다.

```cpp
const char first[] = "Hello";
const char second[] = "Hello";

bool sameAddress = first == second; // 서로 다른 배열의 주소 비교
```

두 배열의 문자 내용은 같지만 별개의 배열이므로 주소가 다르다. C 문자열의 내용을 비교하려면 `std::strcmp` 같은 함수를 사용한다.

```cpp
#include <cstring>

bool sameText = std::strcmp(first, second) == 0;
```

`std::string`은 비교 연산자를 문자열 내용에 맞게 제공한다.

```cpp
#include <string>

std::string first = "Hello";
std::string second = "Hello";

bool sameText = first == second; // true
```

`std::string`의 `<`, `>` 같은 순서 비교는 문자 요소를 앞에서부터 비교하는 사전식 비교다. 사용자의 언어와 문화권에 맞는 정렬 순서를 자동으로 처리하는 것은 아니다.

## C++의 연쇄 비교는 수학식처럼 동작하지 않는다

수학에서는 다음과 같이 하나의 식으로 범위를 표현한다.

```text
0 ≤ hp ≤ 100
```

하지만 이를 C++ 코드에 그대로 옮기면 의도한 범위 검사가 되지 않는다.

```cpp
bool isValid = 0 <= hp <= 100;
```

관계 연산자는 왼쪽 결합성이므로 다음과 같이 묶인다.

```cpp
bool isValid = (0 <= hp) <= 100;
```

먼저 `0 <= hp`가 `bool` 값을 만든다. 그 `false` 또는 `true`가 각각 정수 0 또는 1로 변환되어 100과 비교된다. 0과 1은 모두 100 이하이므로 사실상 항상 `true`가 된다.

두 비교를 각각 작성하고 논리 AND로 연결해야 한다.

```cpp
bool isValid = 0 <= hp && hp <= 100;
```

같은 값을 두 번 적는 것이 불편하더라도 C++의 비교 연산자는 수학의 연쇄 부등식을 직접 표현하지 않는다.

## 논리 연산자는 조건을 조합한다

논리 연산자는 피연산자를 참 또는 거짓으로 판단하고 새로운 `bool` 결과를 만든다.

| 연산자 | 이름 | 결과가 `true`인 경우 |
| :---: | :--- | :--- |
| `!` | NOT | 피연산자가 `false`일 때 |
| `&&` | AND | 양쪽이 모두 `true`일 때 |
| `\|\|` | OR | 한쪽 이상이 `true`일 때 |

`&&`의 진리표는 다음과 같다.

| A | B | `A && B` |
| :---: | :---: | :---: |
| false | false | false |
| false | true | false |
| true | false | false |
| true | true | true |

`||`의 진리표는 다음과 같다.

| A | B | `A \|\| B` |
| :---: | :---: | :---: |
| false | false | false |
| false | true | true |
| true | false | true |
| true | true | true |

게임 상태를 조합하면 다음처럼 읽을 수 있다.

```cpp
bool isDead = hp <= 0 && !isInvincible;
bool canAct = hp > 0 && !isStunned;
bool survives = hp > 0 || isInvincible;
```

- 체력이 0 이하이면서 무적이 아니면 사망한다.
- 체력이 남아 있고 스턴 상태가 아니면 행동할 수 있다.
- 체력이 남아 있거나 무적이면 생존한다.

조건식과 변수 이름이 자연어 질문처럼 읽히도록 작성하면 긴 주석 없이도 의도를 전달할 수 있다.

## 논리 NOT은 참과 거짓을 반전한다

`!`는 피연산자를 `bool`로 판단한 뒤 결과를 반전한다.

```cpp
bool isAlive = true;
bool isDead = !isAlive;
```

정수에도 사용할 수 있다.

```cpp
bool first = !0;  // true
bool second = !5; // false
```

0은 `false`, 0이 아닌 정수는 `true`로 변환된 뒤 반전된다.

이미 `bool`인 값은 `== false` 또는 `== true`와 비교하지 않고 그대로 조건으로 사용할 수 있다.

```cpp
if (isInvincible)
{
    // 무적 상태
}

if (!isInvincible)
{
    // 무적 상태가 아님
}
```

다만 복잡한 표현에서 `!`가 어디까지 적용되는지 한눈에 보이지 않는다면 의미 있는 변수로 분리한다.

```cpp
bool hasNoHealth = hp <= 0;
bool isVulnerable = !isInvincible;
bool isDead = hasNoHealth && isVulnerable;
```

## `&&`는 왼쪽이 거짓이면 오른쪽을 실행하지 않는다

논리 AND `&&`는 왼쪽 피연산자를 먼저 평가한다. 왼쪽이 `false`라면 전체 결과가 이미 `false`로 결정되므로 오른쪽 피연산자는 평가하지 않는다. 이를 단축 평가(Short-circuit evaluation)라고 한다.

```cpp
int numerator = 10;
int denominator = 0;

bool isLargeQuotient = denominator != 0 && numerator / denominator > 3;
```

`denominator != 0`이 `false`이므로 오른쪽의 나눗셈은 실행되지 않는다. 검사 순서 덕분에 정수의 0 나눗셈을 피할 수 있다.

조건의 순서를 반대로 적으면 안전하지 않다.

```cpp
// bool isLargeQuotient = numerator / denominator > 3 && denominator != 0;
```

왼쪽의 나눗셈이 먼저 평가되므로 0 검사가 실행되기 전에 정의되지 않은 동작이 발생한다. `&&`에서는 먼저 확인해야 하는 안전 조건을 왼쪽에 둔다.

이후 포인터를 배우면 같은 원리로 대상의 존재를 먼저 검사한 뒤 접근할 수 있다.

```cpp
// player != nullptr가 true일 때만 player->hp를 읽는다.
bool canAct = player != nullptr && player->hp > 0;
```

## `||`는 왼쪽이 참이면 오른쪽을 실행하지 않는다

논리 OR `||`도 왼쪽을 먼저 평가한다. 왼쪽이 `true`라면 전체 결과가 이미 `true`이므로 오른쪽 피연산자는 평가하지 않는다.

```cpp
bool canOpenDoor = hasKey || TryConsumeLockPick();
```

`hasKey`가 `true`라면 `TryConsumeLockPick()`은 호출되지 않는다. 열쇠가 없을 때만 자물쇠 따개 사용을 시도한다는 의도라면 단축 평가가 로직의 일부가 된다.

반면 함수 호출이 중요한 상태 변경을 숨기고 있다면 코드를 읽기 어려워질 수 있다. 특히 오른쪽 함수가 반드시 실행돼야 하는 작업이라면 논리식 안에 넣으면 안 된다.

```cpp
bool opened = false;

if (hasKey)
{
    opened = true;
}
else
{
    opened = TryConsumeLockPick();
}
```

몇 줄 길어지더라도 실행 조건과 부작용이 더 명확해질 수 있다.

## `&`와 `&&`, `|`와 `||`를 혼동하지 않는다

비트 AND `&`와 논리 AND `&&`는 모두 조건식에서 컴파일될 수 있어 오타를 놓치기 쉽다.

```cpp
bool first = false;
bool second = CheckCondition();

bool bitwiseResult = first & second;
bool logicalResult = first && second;
```

`bool`에 비트 AND를 적용해도 결과값 자체는 AND 진리표와 같을 수 있다. 하지만 `&`는 양쪽 피연산자를 모두 평가하고 `&&`는 왼쪽이 `false`면 오른쪽을 평가하지 않는다.

위 예제에서 `CheckCondition()`을 식에 직접 작성했다면 `&`에서는 호출되고 `&&`에서는 호출되지 않을 수 있다. 조건 조합에는 논리 연산자를 사용하고, 정수 비트 패턴 조작에는 비트 연산자를 사용한다.

같은 차이가 `|`와 `||`에도 적용된다.

## 여러 조건의 우선순위는 괄호와 이름으로 드러낸다

논리 연산자의 우선순위는 `!`, `&&`, `||` 순서다.

```cpp
bool canEnter = isAdmin || hasTicket && !isBanned;
```

이 식은 다음과 같이 묶인다.

```cpp
bool canEnter = isAdmin || (hasTicket && !isBanned);
```

관리자라면 입장할 수 있고, 관리자가 아니라면 티켓이 있으면서 차단 상태가 아니어야 한다는 뜻이다.

조건의 정책이 중요하다면 괄호를 명시하거나 중간 변수로 의미를 붙인다.

```cpp
bool regularUserCanEnter = hasTicket && !isBanned;
bool canEnter = isAdmin || regularUserCanEnter;
```

이름을 붙이면 단순히 우선순위만 보여주는 것이 아니라 각 조건 묶음의 의미도 전달할 수 있다.

## 드모르간 법칙으로 부정된 조건을 읽는다

여러 조건 전체를 부정할 때는 드모르간 법칙(De Morgan's laws)이 적용된다.

```text
!(A && B) == !A || !B
!(A || B) == !A && !B
```

예를 들어 “살아 있고 스턴 상태가 아닌 경우”를 부정하면 다음과 같다.

```cpp
bool canAct = isAlive && !isStunned;
bool cannotAct = !(isAlive && !isStunned);
```

드모르간 법칙으로 풀면 다음과 같은 의미다.

```cpp
bool cannotAct = !isAlive || isStunned;
```

죽어 있거나 스턴 상태라면 행동할 수 없다는 조건이다. 두 표현 중 업무 규칙이 더 자연스럽게 읽히는 쪽을 선택한다.

## 조건식에 중요한 상태 변경을 숨기지 않는다

단축 평가는 검사 비용을 줄일 수도 있지만 가장 중요한 역할은 필요 없는 평가를 생략하는 것이다. 이를 단순한 성능 기법으로만 이해하면 조건식 안에 너무 많은 작업을 넣게 된다.

```cpp
bool success = ValidateInput() && SaveData() && SendNotification();
```

이 코드는 앞의 함수가 `false`를 반환하면 뒤의 함수를 호출하지 않는다. 이것이 정말 원하는 작업 흐름이라면 사용할 수 있지만, 실패 원인을 기록하거나 일부 작업을 반드시 수행해야 한다면 단계별로 나누는 편이 낫다.

```cpp
bool isValid = ValidateInput();

if (!isValid)
{
    // 입력 오류 처리
}
else
{
    bool saved = SaveData();

    if (saved)
    {
        SendNotification();
    }
}
```

조건식은 가능하면 판단에 집중시키고, 프로그램 상태를 크게 바꾸는 작업은 실행 흐름이 보이도록 분리한다.

## 전체 실습 코드

플레이어가 행동하고 던전에 입장할 수 있는지를 여러 조건으로 판단하는 예제다.

```cpp
#include <algorithm>
#include <cmath>
#include <iostream>
#include <string>

bool NearlyEqual(double a, double b, double absoluteTolerance, double relativeTolerance)
{
    if (a == b)
    {
        return true;
    }

    if (!std::isfinite(a) || !std::isfinite(b))
    {
        return false;
    }

    double difference = std::abs(a - b);
    double scale = std::max(std::abs(a), std::abs(b));
    double tolerance = std::max(absoluteTolerance, relativeTolerance * scale);
    return difference <= tolerance;
}

bool IsWithinRange(int value, int minimum, int maximum)
{
    return minimum <= value && value <= maximum;
}

int main()
{
    int hp = 75;
    int level = 12;
    int requiredLevel = 10;
    bool isStunned = false;
    bool isInvincible = false;
    bool hasTicket = true;
    bool isBanned = false;

    bool isAlive = hp > 0 || isInvincible;
    bool canAct = isAlive && !isStunned;
    bool hasRequiredLevel = level >= requiredLevel;
    bool canEnterDungeon = hasRequiredLevel && hasTicket && !isBanned;
    bool hasValidHp = IsWithinRange(hp, 0, 100);

    std::cout << std::boolalpha;
    std::cout << "Alive: " << isAlive << '\n';
    std::cout << "Can act: " << canAct << '\n';
    std::cout << "Can enter dungeon: " << canEnterDungeon << '\n';
    std::cout << "Valid HP: " << hasValidHp << '\n';

    std::string firstName = "Player";
    std::string secondName = "Player";
    std::cout << "Same name: " << (firstName == secondName) << '\n';

    double calculatedTime = 0.1 + 0.2;
    double expectedTime = 0.3;
    std::cout << "Exact time match: " << (calculatedTime == expectedTime) << '\n';
    std::cout << "Near time match: " << NearlyEqual(calculatedTime, expectedTime, 1e-12, 1e-12) << '\n';

    int numerator = 10;
    int denominator = 0;
    bool isLargeQuotient = denominator != 0 && numerator / denominator > 3;
    std::cout << "Large quotient: " << isLargeQuotient << '\n';
}
```

실행하면 다음 내용을 확인할 수 있다.

- 비교 연산의 결과는 `bool`이다.
- `&&`, `||`, `!`로 여러 상태를 조합할 수 있다.
- 범위 비교는 두 조건을 `&&`로 연결해야 한다.
- `std::string`의 `==`는 문자열 내용을 비교한다.
- 부동소수점의 정확한 비교와 허용 오차 비교는 결과가 다를 수 있다.
- 단축 평가로 분모가 0일 때 나눗셈을 실행하지 않는다.
