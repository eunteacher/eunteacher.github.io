앞에서는 내장 배열이 요소 개수가 타입에 포함된 객체이고, 많은 표현식에서 첫 요소 포인터로 변환된다는 점을 살펴봤다. 문자 데이터를 다루면 배열과 포인터의 차이에 한 가지 규칙이 더해진다. C 스타일 문자열은 문자 배열이기만 해서는 부족하고, 문자열의 끝을 나타내는 null 문자 `\0`도 필요하다.

`const char* text = "Hello";`와 `char text[] = "Hello";`는 같은 문장을 표현하지만 서로 다른 객체 관계를 만든다. 하나는 문자열 리터럴을 가리키는 포인터이고, 다른 하나는 문자들을 복사해 초기화한 별도의 배열이다.

## 문자열 리터럴은 null 문자를 포함한 배열이다

큰따옴표로 작성한 일반 문자열 리터럴은 문자 배열이다.

```cpp
"Hello"
```

C++에서 이 리터럴의 타입은 `const char[6]`이다. 화면에 보이는 문자는 다섯 개지만 끝에 null 문자가 하나 더 포함된다.

```text
문자열 리터럴 "Hello"
┌─────┬─────┬─────┬─────┬─────┬──────┐
│ 'H' │ 'e' │ 'l' │ 'l' │ 'o' │ '\0' │
└─────┴─────┴─────┴─────┴─────┴──────┘
  [0]   [1]   [2]   [3]   [4]    [5]
```

null 문자는 값이 0인 문자이며 C 스타일 문자열의 끝을 표시한다. 문자 `'0'`과는 다르다.

```cpp
char digit = '0';
char terminator = '\0';
```

`'0'`은 숫자 모양의 문자이고 `\0`은 문자열 종료에 사용하는 null 문자다.

## 문자열 리터럴은 프로그램 실행 동안 존재한다

문자열 리터럴 객체는 정적 저장 기간을 가진다. 함수 안에 리터럴 표현식이 있어도 해당 리터럴의 수명이 함수 호출이 끝날 때 종료되는 것은 아니다.

```cpp
const char* GetDefaultName()
{
    return "Unknown";
}
```

반환된 포인터는 정적 저장 기간의 문자열 리터럴을 가리키므로 함수가 반환된 뒤에도 리터럴의 수명은 유지된다.

리터럴이 구체적으로 실행 파일의 어느 섹션에 배치되는지, 같은 내용을 가진 리터럴이 하나의 객체로 합쳐지는지는 구현이 정할 수 있다. C++ 코드에서는 정적 저장 기간의 수정할 수 없는 문자 배열이라는 규칙에 의존한다.

## 문자열 리터럴을 수정하면 정의되지 않은 동작이다

문자열 리터럴의 요소를 변경하려 해서는 안 된다.

```cpp
const char* text = "Hello";
// text[0] = 'Y';
```

`const char*` 타입이 이 포인터를 통한 수정을 컴파일 단계에서 막는다.

강제로 `const`를 제거해도 리터럴 객체가 수정 가능한 배열로 바뀌지 않는다.

```cpp
const char* text = "Hello";
char* writable = const_cast<char*>(text);
// writable[0] = 'Y';
```

마지막 대입을 실행하면 정의되지 않은 동작이다. 반드시 특정한 세그멘테이션 폴트가 발생한다고 보장되지 않으며, 우연히 동작한 것처럼 보여도 올바른 코드가 아니다.

수정이 필요하다면 수정 가능한 별도 저장소를 만들어야 한다.

## `const char*`는 리터럴을 가리키는 포인터 객체다

다음 선언은 포인터 객체 `text`를 만들고 문자열 리터럴의 첫 요소를 가리키게 한다.

```cpp
const char* text = "Hello";
```

```text
text 포인터                  문자열 리터럴
┌──────────────┐              ┌─────┬─────┬─────┬─────┬─────┬──────┐
│ 첫 문자 가리킴├─────────────▶│ 'H' │ 'e' │ 'l' │ 'l' │ 'o' │ '\0' │
└──────────────┘              └─────┴─────┴─────┴─────┴─────┴──────┘
```

`text`의 타입은 `const char*`이며 배열 크기 6은 포인터 타입에 포함되지 않는다. 포인터 자체는 다른 문자열을 가리키도록 바꿀 수 있다.

```cpp
text = "World";
text = nullptr;
```

포인터를 재지정해도 원래 문자열 리터럴이 수정되거나 소멸하는 것은 아니다.

`const char*`는 문자열을 소유한다는 뜻도 아니다. 단지 이 포인터를 통해 문자를 수정하지 않겠다는 접근 권한과 가리키는 문자 타입을 표현한다.

## `char text[]`는 문자들을 가진 별도 배열이다

문자 배열을 문자열 리터럴로 초기화할 수 있다.

```cpp
char text[] = "Hello";
```

컴파일러는 null 문자를 포함한 리터럴의 문자들로 새 배열을 초기화한다. `text`의 타입은 `char[6]`이다.

```text
문자열 리터럴의 문자들로 초기화
              │
              ▼
text 배열
┌─────┬─────┬─────┬─────┬─────┬──────┐
│ 'H' │ 'e' │ 'l' │ 'l' │ 'o' │ '\0' │
└─────┴─────┴─────┴─────┴─────┴──────┘
```

이 배열 요소는 `const`가 아니므로 수정할 수 있다.

```cpp
text[0] = 'Y';
```

배열의 문자 내용은 이제 `"Yello"`가 된다. 문자열 리터럴을 수정한 것이 아니라 `text`가 소유한 별도 문자 배열의 첫 요소를 변경한 것이다.

## 배열의 저장 기간은 선언 위치에 따라 결정된다

`char text[]`가 항상 스택에 저장된다고 설명하면 정확하지 않다.

```cpp
char GlobalText[] = "Global";

void PrintText()
{
    char localText[] = "Local";
    static char savedText[] = "Saved";
}
```

- `GlobalText`는 정적 저장 기간을 가진다.
- `localText`는 일반적으로 자동 저장 기간을 가진다.
- `savedText`는 함수 안에 선언됐지만 정적 저장 기간을 가진다.

배열이 문자를 소유한다는 말은 배열 객체 안에 문자 요소들이 포함된다는 뜻이다. 배열 객체의 수명은 선언 위치와 저장 기간 규칙에 따라 달라진다.

## 같은 표기라도 포인터와 배열의 타입은 다르다

두 선언을 나란히 비교한다.

```cpp
const char* pointer = "Hello";
char array[] = "Hello";
```

| 항목 | `const char* pointer` | `char array[6]` |
| :--- | :--- | :--- |
| 객체 자체 | 포인터 객체 | 문자 6개를 포함한 배열 객체 |
| 가리키거나 포함하는 문자 | 문자열 리터럴을 가리킴 | 별도 문자 요소를 포함함 |
| 문자 수정 | 이 포인터를 통해 불가능 | 가능 |
| 다른 문자열로 재지정·대입 | 포인터 재지정 가능 | 배열 전체 대입 불가 |
| `sizeof` | 포인터 객체 크기 | 문자 배열 전체 크기 6 |
| 저장소 소유 | 리터럴을 소유하지 않음 | 문자 요소를 배열이 포함함 |

둘 다 `pointer[1]`, `array[1]`처럼 인덱스 문법을 사용할 수 있지만 그 사실이 둘을 같은 타입으로 만들지는 않는다.

## `sizeof`는 배열 크기와 포인터 크기의 차이를 보여준다

배열 타입이 유지되는 위치에서 `sizeof`를 비교한다.

```cpp
const char* pointer = "Hello";
char array[] = "Hello";

std::size_t pointerBytes = sizeof(pointer);
std::size_t arrayBytes = sizeof(array);
```

`arrayBytes`는 null 문자를 포함한 6이다. `sizeof(char)`는 정의상 1이므로 문자 배열에서는 바이트 수와 요소 개수가 같다.

`pointerBytes`는 포인터 객체의 크기이며 문자열 길이와 관계없다. 흔한 환경에서 4 또는 8일 수 있지만 C++이 모든 포인터 크기를 그 두 값으로 제한하지는 않는다.

배열의 요소 개수는 `std::size`로 구할 수 있다.

```cpp
#include <iterator>

std::size_t arrayCount = std::size(array);
```

`arrayCount`도 null 문자를 포함한 6이다.

## 배열 크기와 문자열 길이는 다른 값이다

C 스타일 문자열 길이는 첫 null 문자 앞에 있는 문자 개수다. `std::strlen`으로 구할 수 있다.

```cpp
#include <cstring>

char text[] = "Hello";
std::size_t arrayCount = std::size(text);
std::size_t textLength = std::strlen(text);
```

```text
arrayCount = 6  배열 요소 전체 개수
textLength = 5  첫 null 문자 전까지의 문자 개수
```

관계를 단순화하면 다음과 같다.

$$BufferSize = TextLength + 1$$

이 식은 버퍼가 정확히 하나의 null 종료 문자열만 담고 추가 여유 공간이나 중간 null 문자가 없을 때 성립한다.

더 큰 버퍼에 짧은 문자열을 저장하면 배열 크기와 문자열 길이 차이가 더 커진다.

```cpp
char buffer[32] = "Hello";
```

```text
배열 요소 개수: 32
문자열 길이: 5
사용 중인 null 문자 위치: buffer[5]
```

버퍼 용량과 현재 문자열 길이를 같은 값으로 취급하지 않는다.

## null 문자가 없는 문자 배열은 C 스타일 문자열이 아니다

문자 배열이 모두 C 스타일 문자열인 것은 아니다.

```cpp
char letters[5] = {'H', 'e', 'l', 'l', 'o'};
```

이 배열은 문자 다섯 개를 가지고 있지만 null 종료 문자가 없다. 배열 요소를 인덱스로 처리하는 것은 가능하지만 `std::strlen`이나 C 문자열 출력 함수에 넘기면 배열 밖에서 null 문자를 찾으려 할 수 있다.

```cpp
// std::cout << letters;
// std::size_t length = std::strlen(letters);
```

두 사용은 유효한 null 종료 문자열을 요구하므로 이 배열에는 사용할 수 없다.

문자열로 사용하려면 종료 문자를 위한 공간을 포함한다.

```cpp
char text[6] = {'H', 'e', 'l', 'l', 'o', '\0'};
```

문자열 리터럴 초기화를 사용하면 null 문자가 자동으로 포함된다.

```cpp
char text[] = "Hello";
```

## 배열 크기를 직접 적을 때는 null 문자 공간도 포함한다

`"Hello"`를 문자 배열에 담으려면 요소가 6개 필요하다.

```cpp
char text[6] = "Hello";
```

null 문자 공간이 없는 크기는 올바른 C++ 초기화가 아니다.

```cpp
// char invalid[5] = "Hello";
```

크기를 생략하면 컴파일러가 null 문자를 포함한 정확한 배열 크기를 추론한다.

```cpp
char text[] = "Hello";
```

특별히 고정된 버퍼 용량이 필요하지 않다면 크기를 직접 반복하지 않는 편이 안전하다.

## 문자열 안에도 null 문자가 들어갈 수 있다

문자열 리터럴 중간에 명시적인 null 문자를 넣을 수 있다.

```cpp
char text[] = "AB\0CD";
```

배열 요소는 다음과 같다.

```text
'A', 'B', '\0', 'C', 'D', '\0'
```

배열 크기는 6이지만 C 스타일 문자열 함수는 첫 null 문자에서 끝난 것으로 해석한다.

```cpp
std::size_t arrayCount = std::size(text);
std::size_t textLength = std::strlen(text);
```

`arrayCount`는 6이고 `textLength`는 2다. C 스타일 문자열은 임의의 문자 버퍼와 달리 null 문자를 내용 중간에 그대로 표현하면서 전체 길이를 자동으로 전달할 수 없다.

길이를 별도로 가진 `std::string`과 `std::string_view`는 중간 null 문자를 포함한 범위도 표현할 수 있다.

```cpp
std::string owned{"AB\0CD", 5};
std::string_view viewed{"AB\0CD", 5};
```

길이를 생략하고 `const char*`만으로 string view를 만들면 C 문자열 길이 규칙을 사용해 첫 null 문자까지만 범위에 포함한다. C 문자열 API에 넘겨도 첫 null 문자까지만 처리될 수 있다는 점을 고려해야 한다.

## 함수 매개변수의 `char text[]`는 `char*`로 조정된다

문자 배열을 수정하는 함수를 배열 표기로 선언할 수 있다.

```cpp
void ChangeFirstCharacter(char text[])
{
    text[0] = 'Y';
}
```

함수 매개변수에서 `char text[]`는 `char* text`로 조정된다.

```cpp
void ChangeFirstCharacter(char* text);
```

호출할 때 수정 가능한 문자 배열은 첫 요소 포인터로 변환된다.

```cpp
char greeting[] = "Hello";
ChangeFirstCharacter(greeting);
```

함수가 변경한 것은 포인터가 가리키는 호출자의 배열 요소다. 배열 전체가 값으로 복사되어 전달된 것이 아니다.

```text
greeting 배열 ── 첫 요소 포인터 전달 ──▶ text 매개변수
     ▲                                      │
     └──────────── text[0] 수정 ────────────┘
```

## 포인터 매개변수만으로는 버퍼 크기를 알 수 없다

함수 안의 `sizeof(text)`는 호출자가 가진 배열 전체 크기가 아니라 포인터 매개변수의 크기다.

```cpp
void ClearText(char text[])
{
    // std::size_t wrongSize = sizeof(text);

    if (text != nullptr)
    {
        text[0] = '\0';
    }
}
```

매개변수에 숫자를 적어도 크기를 보존하지 않는다.

```cpp
void ClearText(char text[32]);
```

이 선언도 매개변수 타입 관점에서는 `char*`다. 함수는 실제로 32개짜리 배열이 전달됐는지 일반적으로 확인할 수 없다.

버퍼에 여러 문자를 쓸 함수라면 포인터와 용량을 함께 받는다.

```cpp
bool TryWriteGreeting(char* buffer, std::size_t capacity)
{
    constexpr char Greeting[] = "Hello";
    constexpr std::size_t RequiredSize = sizeof(Greeting);

    if (buffer == nullptr || capacity < RequiredSize)
    {
        return false;
    }

    for (std::size_t index = 0; index < RequiredSize; ++index)
    {
        buffer[index] = Greeting[index];
    }

    return true;
}
```

`RequiredSize`는 null 문자를 포함한다. 호출자는 실제 배열 용량을 전달한다.

```cpp
char buffer[16]{};
bool written = TryWriteGreeting(buffer, std::size(buffer));
```

포인터와 용량이 분리된 인터페이스에서는 호출자가 올바른 조합을 전달해야 한다. 일반적인 문자열 소유와 조작이라면 직접 버퍼를 관리하기보다 `std::string`을 우선 검토한다.

## 읽기 전용 C 문자열 포인터도 null과 종료 조건이 필요하다

읽기만 하는 함수는 `const char*`를 받을 수 있다.

```cpp
void PrintText(const char* text)
{
    if (text == nullptr)
    {
        std::cout << "(null)";
        return;
    }

    std::cout << text;
}
```

null 검사는 대상이 없다는 상태를 처리하지만 충분한 문자열 유효성 검사가 아니다. `text`가 다음 조건도 만족해야 한다.

- 포인터가 가리키는 문자 객체들이 살아 있다.
- 첫 요소부터 접근 가능한 범위 안에 null 문자가 존재한다.
- 출력이 진행되는 동안 저장소가 유효하다.

`const char*` 타입 하나에는 최대 길이와 저장소 수명 정보가 포함되지 않는다.

## 지역 문자 배열의 포인터를 반환하면 댕글링된다

함수 안에서 만든 일반 지역 배열의 수명은 함수가 반환될 때 끝난다.

```cpp
const char* CreateName()
{
    char name[] = "Slime";
    return name;
}
```

반환된 포인터는 수명이 끝난 배열을 가리키므로 사용할 수 없다.

문자열 리터럴을 반환하는 함수와 비교한다.

```cpp
const char* GetDefaultName()
{
    return "Slime";
}
```

문자열 리터럴은 정적 저장 기간이므로 포인터의 대상 수명은 유지된다. 하지만 호출자가 리터럴을 소유하거나 수정할 수 있다는 뜻은 아니다.

호출자에게 새 문자열 소유권을 전달하려면 `std::string`을 값으로 반환하는 편이 자연스럽다.

```cpp
#include <string>

std::string CreateName()
{
    return "Slime";
}
```

## 포인터가 같다는 것과 문자열 내용이 같다는 것은 다르다

두 C 문자열 포인터에 `==`를 사용하면 문자 내용을 비교하는 것이 아니라 포인터값을 비교한다.

```cpp
const char* first = "Slime";
const char* second = "Slime";

bool samePointer = first == second;
```

컴파일러는 같은 내용을 가진 문자열 리터럴의 저장소를 합칠 수도 있고 별도로 둘 수도 있다. 따라서 `samePointer`의 결과로 문자열 내용의 동일성을 판단하지 않는다.

null 종료 C 문자열의 내용을 비교하려면 `std::strcmp`를 사용할 수 있다.

```cpp
#include <cstring>

bool sameText = std::strcmp(first, second) == 0;
```

두 인자가 null이 아니고 유효한 null 종료 문자열이라는 전제가 필요하다.

`std::string`과 `std::string_view`는 `==`로 문자 범위의 내용을 비교할 수 있어 의도가 더 직접적이다.

## 배열은 다른 문자열을 가리키도록 바꿀 수 없다

포인터는 다른 저장소를 가리키도록 재지정할 수 있다.

```cpp
const char* text = "Hello";
text = "World";
```

내장 배열은 다른 배열을 대입받을 수 없다.

```cpp
char text[] = "Hello";
// text = "World";
```

문자 배열의 내용을 바꾸려면 각 요소를 수정하거나 용량을 확인한 뒤 복사해야 한다. C 문자열 복사 함수는 대상 버퍼 용량과 null 종료 조건을 잘못 다루면 경계를 벗어날 수 있다.

문자열 값을 자유롭게 대입하고 이어 붙이는 일반 코드라면 `std::string`이 저장소와 길이를 함께 관리한다.

```cpp
#include <string>

std::string text = "Hello";
text = "World";
text += "!";
```

## `std::string`은 문자 저장소를 소유한다

`std::string` 객체는 문자열의 문자 저장소와 길이를 관리한다.

```cpp
#include <string>

std::string name = "Knight";
name[0] = 'N';
name += " Captain";
```

현재 문자 개수는 `size()`로 구한다.

```cpp
std::size_t length = name.size();
```

`std::string`은 길이를 별도로 관리하므로 중간 null 문자도 저장할 수 있다.

```cpp
std::string data{"AB\0CD", 5};
```

이 문자열의 `size()`는 5다. 다만 C 문자열 함수에 `data.c_str()`을 전달하면 첫 null 문자에서 끝난 것으로 처리될 수 있다.

`std::string`의 복사본은 독립적인 문자열 값으로 사용할 수 있고 이동을 통해 소유 자원을 효율적으로 이전할 수도 있다. 구체적인 저장 방식은 표준 라이브러리 구현에 맡겨져 있으므로 항상 힙 할당이 발생한다고 단정하지 않는다.

## `c_str()`은 소유권을 넘기지 않는다

C 스타일 API에 문자열을 전달해야 한다면 `c_str()`으로 null 종료 문자 배열의 포인터를 얻을 수 있다.

```cpp
const char* pointer = name.c_str();
```

이 포인터는 `name`이 관리하는 저장소를 가리키며 별도 문자열을 소유하지 않는다. 문자열 객체가 소멸하거나 저장소를 무효화하는 수정이 일어나면 기존 포인터를 계속 사용할 수 없다.

```cpp
std::string name = "Knight";
const char* pointer = name.c_str();
name += " Captain";
// pointer를 다시 사용하기 전에 name.c_str()에서 새 포인터를 얻는다.
```

구체적으로 어떤 연산이 포인터를 무효화하는지는 사용 중인 표준과 해당 멤버 함수의 무효화 규칙을 확인한다. 보관이 필요하면 `std::string` 자체를 소유하거나 복사한다.

## `std::string_view`는 소유하지 않는 문자 범위다

C++17부터 `std::string_view`로 문자 저장소를 소유하지 않고 시작 위치와 길이를 함께 관찰할 수 있다.

```cpp
#include <string_view>

void PrintLabel(std::string_view label)
{
    std::cout << label << '\n';
}
```

문자열 리터럴, `std::string`과 문자 배열의 내용을 전달할 수 있다.

```cpp
std::string name = "Knight";
char title[] = "Captain";

PrintLabel("Player");
PrintLabel(name);
PrintLabel(title);
```

`std::string_view`는 문자 범위의 길이를 알고 있으므로 부분 문자열과 중간 null 문자도 범위로 표현할 수 있다. 그러나 저장소를 소유하지 않고 대상 수명을 연장하지 않는다.

```cpp
std::string_view view;

{
    std::string localName = "Slime";
    view = localName;
}

// localName이 소멸했으므로 view를 사용하면 안 된다.
```

문자열 뷰를 함수 호출 동안만 읽는 매개변수로 사용하면 수명 관계를 좁게 유지하기 쉽다. 멤버나 전역 상태에 저장한다면 원본 문자열이 더 오래 살아 있는지 확인해야 한다.

## `string_view::data()`는 C 문자열 포인터와 같은 계약이 아니다

`std::string_view`는 문자 범위이므로 마지막에 null 문자가 있다는 보장이 없다. 원본 문자열의 일부만 가리킬 수도 있다.

```cpp
std::string_view full = "Hello World";
std::string_view firstWord = full.substr(0, 5);
```

`firstWord.size()`는 5지만 `firstWord.data()` 다음에는 원본의 공백과 나머지 문자들이 이어져 있다. `data()`를 null 종료 문자열로 가정해 출력하면 뷰의 길이에서 멈추지 않을 수 있다.

```cpp
std::cout << firstWord << '\n';
// std::cout << firstWord.data() << '\n';
```

첫 번째 출력은 string view의 길이를 사용하고, 두 번째 주석 처리된 출력은 `const char*`를 C 문자열로 해석한다.

null 종료 문자열이 필요한 API에 넘길 때는 소유 문자열을 만들어 종료 조건을 보장할 수 있다.

```cpp
std::string owned(firstWord);
const char* cText = owned.c_str();
```

`owned`가 살아 있고 저장소를 무효화하는 변경이 없는 동안 `cText`를 사용한다.

## 문자열 타입은 소유권과 수정 요구로 선택한다

| 요구사항 | 우선 검토할 형태 |
| :--- | :--- |
| 문자열 리터럴을 잠시 가리킴 | `const char*` 또는 `std::string_view` |
| 고정된 수정 가능 문자 버퍼가 필요함 | `char[N]` 또는 `std::array<char, N>` |
| 문자열 값을 소유하고 수정함 | `std::string` |
| 소유하지 않고 길이와 함께 읽음 | `std::string_view` |
| C API가 null 종료 문자열을 요구함 | 수명이 유효한 `const char*`와 종료 조건 보장 |

C API와의 상호 운용, 임베디드 환경, 고정 버퍼처럼 문자 배열과 포인터가 필요한 상황은 분명히 있다. 일반 애플리케이션 코드에서는 소유권과 길이를 타입에 보존하는 `std::string`과 `std::string_view`가 실수를 줄이는 경우가 많다.

## 전체 예제로 소유 문자열과 비소유 뷰를 구분한다

Text RPG의 캐릭터 이름과 출력 접두사를 처리하는 예제다.

```cpp
#include <iostream>
#include <string>
#include <string_view>
#include <utility>

struct Character
{
    std::string name;
    int hp;
};

void PrintCharacter(const Character& character, std::string_view prefix)
{
    std::cout << prefix << character.name << " HP: " << character.hp << '\n';
}

bool HasPrefix(std::string_view text, std::string_view prefix)
{
    return text.size() >= prefix.size() && text.substr(0, prefix.size()) == prefix;
}

void Rename(Character& character, std::string newName)
{
    character.name = std::move(newName);
}

int main()
{
    constexpr char DefaultName[] = "Unknown";
    const char* defaultNamePointer = DefaultName;
    Character player{defaultNamePointer, 100};

    PrintCharacter(player, "[Player] ");
    Rename(player, "Knight");

    if (HasPrefix(player.name, "Kni"))
    {
        PrintCharacter(player, "[Matched] ");
    }

    char editableTitle[] = "Hero";
    editableTitle[0] = 'Z';
    PrintCharacter(player, std::string_view(editableTitle));
}
```

`DefaultName`은 null 문자를 포함한 `const char` 배열이고, `defaultNamePointer`는 그 첫 요소를 가리킬 뿐 소유하지 않는다. `Character::name`은 전달된 문자 내용을 자신의 `std::string` 값으로 소유한다.

`PrintCharacter`와 `HasPrefix`는 호출 동안 문자열을 읽기만 하므로 `std::string_view`로 받는다. `Rename`은 새 이름을 저장해야 하므로 `std::string`을 값으로 받고 멤버로 이동한다.

`editableTitle`은 수정 가능한 문자 배열이며 string view로 전달하는 동안 배열이 살아 있다. `PrintCharacter`가 뷰를 저장하지 않으므로 호출이 끝난 뒤의 수명 문제도 만들지 않는다.

이 코드는 문자열의 소유권과 수명을 설명하는 예제이며 실제 실행 결과를 확인했다고 가정하지 않는다.

## 문자열을 다룰 때 확인할 기준

문자열 포인터와 배열을 사용할 때 다음 내용을 확인한다.

1. 현재 객체가 포인터인가, 문자 배열인가?
2. 문자 저장소를 누가 소유하는가?
3. 저장소는 포인터나 뷰를 사용하는 동안 살아 있는가?
4. 문자 배열이 유효한 범위 안에 null 문자를 포함하는가?
5. 배열 크기, 버퍼 용량과 현재 문자열 길이를 구분했는가?
6. 함수 매개변수에서 배열이 포인터로 조정돼 크기를 잃지는 않았는가?
7. 포인터 비교로 문자열 내용을 비교하고 있지는 않은가?
8. `c_str()` 또는 `data()`로 얻은 포인터의 무효화 조건을 확인했는가?
9. `std::string_view`가 대상 수명을 연장하거나 null 종료를 보장한다고 오해하지 않았는가?
10. 일반 문자열 소유가 필요하다면 `std::string`이 더 자연스럽지 않은가?

문자열에서 배열은 문자 저장 공간이고 포인터는 그 저장소를 가리키는 값이다. null 종료 문자열은 여기에 종료 조건까지 요구한다. 타입, 크기, 소유권과 수명을 함께 보지 않으면 같은 `[]` 문법만으로 두 대상을 구분할 수 없다.
