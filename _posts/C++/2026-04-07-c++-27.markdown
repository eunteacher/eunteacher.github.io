# [C++] 포인터와 배열의 동작 방식 비교 및 문자열 제어

배열의 이름이 포인터로 붕괴(Decay)되는 현상과 문자열 리터럴을 다룰 때 포인터와 배열이 갖는 메모리 할당의 근본적인 차이를 분석

## 1. 소스 코드 (Source Code)

```cpp
#include <iostream>
using namespace std;

// 1. 값 전달 방식 (Call by Value)
// 매개변수로 전달된 변수의 복사본이 생성되므로 원본은 변경되지 않음
void Test(int a)
{
    a++;
}

// 2. 배열 전달 방식 (Array Decay)
// 배열을 함수의 인자로 넘기면 컴파일러가 시작 주소를 가리키는 포인터로 자동 치환함
// 즉, 배열 전체 크기가 아닌 포인터(주소)만 전달되므로 함수 내부에서 원본 조작이 가능함
void Test(char a[])
{
    a[0] = 'x';
}

int main()
{
    // [문자열 리터럴과 문자 배열]
    // 큰따옴표로 묶인 문자열은 마지막에 널 문자('\0')가 자동으로 포함됨
    const char msg[] = { 'H', 'e', 'l', 'l', 'o', '\0' };
    cout << msg << '\n';

    // A. 포인터를 이용한 문자열 리터럴 참조 (Read-Only)
    // 컴파일러가 문자열 리터럴("Hello World")을 .rodata(읽기 전용) 영역에 할당함
    // test1 포인터 자체는 스택 영역에 8바이트(64비트 기준) 바구니로 생성되어 리터럴의 시작 주소를 가리킴
    const char* test1 = "Hello World";
    // test1[1] = 'R'; // 상수 데이터 영역을 가리키므로 역참조를 통한 수정 시도시 에러 발생

    // B. 배열을 이용한 문자열 초기화 (Read-Write)
    // 스택 영역에 배열 크기만큼의 연속된 메모리(바구니 모음)를 확보한 뒤, 문자열의 데이터를 복사해 옴
    // 스택에 복사된 독립적인 데이터이므로 자유롭게 수정이 가능함
    char test2[] = "Hello World";
    test2[0] = 'R';

    // 3. 함수 인자 전달 테스트 (값 전달 vs 포인터 붕괴)
    int a = 1;
    Test(a);
    // 값 복사이므로 원본 a는 여전히 1로 유지됨
    cout << "값 전달 후 a: " << a << '\n';

    char arr[] = "Hello World";
    // 배열 이름 'arr'는 배열의 시작 주소로 붕괴(Decay)되어 전달됨
    Test(arr);
    // 주소가 넘어갔으므로 배열의 첫 번째 원소가 'x'로 변경됨
    cout << "배열 전달 후 arr: " << arr << '\n';

    return 0;
}
```

## 2. 이론 정리 (Study Notes)

포인터와 배열은 인덱스 연산자(`[]`)를 통해 요소에 접근할 수 있다는 공통점이 있으나, 메모리에 할당되고 동작하는 본질적인 구조가 다름

### 포인터와 배열의 근본적 차이

| 구분 | 포인터 (Pointer) | 배열 (Array) |
| :--- | :--- | :--- |
| **데이터 본질** | 메모리 주소를 담는 단일 변수 (바구니) | 동일 타입의 데이터가 연속적으로 할당된 공간 (바구니 모음) |
| **할당 크기** | 아키텍처에 따라 고정된 크기 (4B 또는 8B) | 요소 개수에 비례하는 전체 데이터 크기 |
| **문자열 리터럴** | 데이터 영역의 읽기 전용 주소를 단순히 가리킴 | 스택 메모리를 할당받고 리터럴의 데이터를 복사함 |
| **주소 변경** | 런타임 중 다른 대상의 주소를 가리키도록 변경 가능 | 선언된 메모리 공간에 고정되어 다른 주소로 대입 불가 |

### 포인터 붕괴 (Array Decay)와 크기 연산

배열을 함수의 매개변수로 전달하거나 포인터 변수에 대입할 때, 배열의 전체 데이터와 크기 정보가 소실되고 첫 번째 요소의 시작 주소(`Type*`)로 변환되는 현상을 의미함
이에 따라 `sizeof` 연산자의 결과값은 상황에 따라 다음과 같이 계산됨

* **배열 원본에 대한 크기 연산:**
  $$Size = \text{Length} \times \text{sizeof(Type)}$$
* **붕괴된 배열(포인터 매개변수)에 대한 크기 연산:**
  $$Size = \text{sizeof(Type*)}$$

## 3. 종합 의견 (Review)

### 핵심 요약 및 주의사항

* **리터럴 상수화 명시:** 문자열 리터럴을 포인터로 가리킬 때는 반드시 `const char*`로 선언하여, 런타임에 읽기 전용 메모리를 수정하려다 발생하는 세그멘테이션 폴트(Segmentation Fault)를 예방해야 함
* **크기 정보 소실:** 함수 매개변수로 `char a[]`를 선언하더라도 컴파일러는 이를 `char* a`로 해석하므로, 함수 내부에서는 배열의 실제 길이를 알아낼 방법이 없음
* **Null 종결자:** 배열을 사용하여 문자열을 수동으로 초기화할 때는 배열의 마지막 여유 공간에 문자열의 끝을 알리는 `\0` 문자가 들어갈 자리가 있는지 확인해야 함

### Tip

* **모던 C++ 문자열 처리:** C스타일 문자열(`char*`, `char[]`)은 버퍼 오버플로우와 같은 보안 취약점을 유발하기 쉬우므로, 실무에서는 동적 크기 할당과 풍부한 메서드를 지원하는 `std::string`을 기본으로 사용하는 것이 안전함
* **배열 크기 보존 기법:** 함수로 배열을 넘길 때 붕괴 현상을 방지하고 크기 정보를 유지하려면, 템플릿 참조(`template<size_t N> void func(char (&arr)[N])`)를 사용하거나 `std::array` 컨테이너를 도입하는 방식이 권장됨
