앞에서는 배열의 요소 개수와 경계, 함수로 전달할 때 크기 정보가 사라지는 과정, `std::array`와 `std::span`의 역할을 살펴봤다. 이번에는 이 내용을 작은 로또 번호 생성기에 적용한다.

번호 여섯 개를 출력하는 것만으로 프로그램이 올바르다고 판단할 수는 없다. 각 숫자가 범위 안에 있는지, 중복이 없는지, 정렬 결과가 오름차순인지 각각 확인해야 한다. 생성·중복 검사·정렬·검증을 분리하면 어느 단계의 규칙이 깨졌는지 찾을 수 있다.

## 먼저 결과가 만족해야 할 조건을 정의한다

이번 예제의 요구사항은 다음과 같다.

- 숫자는 정확히 6개다.
- 각 숫자는 1 이상 45 이하다.
- 같은 숫자가 두 번 나오지 않는다.
- 최종 결과는 오름차순이다.

상수와 결과 타입으로 이 조건을 표현한다.

```cpp
#include <array>

constexpr int MinimumNumber = 1;
constexpr int MaximumNumber = 45;
constexpr std::size_t TicketSize = 6;

using LottoTicket = std::array<int, TicketSize>;
```

`LottoTicket` 타입 자체가 요소 6개라는 크기를 보존한다. 함수마다 숫자 6을 반복해서 적지 않고 `ticket.size()`로 요소 수를 확인할 수 있다.

```text
LottoTicket
┌─────┬─────┬─────┬─────┬─────┬─────┐
│ [0] │ [1] │ [2] │ [3] │ [4] │ [5] │
└─────┴─────┴─────┴─────┴─────┴─────┘
               요소 6개
```

## 작업을 네 단계로 분리한다

전체 흐름을 먼저 나눈다.

```text
후보 숫자 생성
      │
      ▼
이미 선택한 숫자와 중복 검사
      │
      ├─ 중복 ── 후보 버리고 다시 생성
      │
      └─ 새 숫자 ── 배열에 저장
                         │
                         ▼
                  6개가 되면 정렬
                         │
                         ▼
                  결과 조건 검증
```

각 단계의 책임은 다음과 같다.

| 단계 | 입력 | 결과 또는 보장 |
| :--- | :--- | :--- |
| 후보 생성 | 난수 엔진 | 1부터 45 사이의 숫자 하나 |
| 중복 검사 | 이미 채운 번호, 후보 | 같은 값이 있는지 여부 |
| 정렬 | 번호 6개 | 오름차순 배열 |
| 검증 | 최종 번호 | 범위·유일성·정렬 상태 |

번호 생성 함수 하나 안에 모든 반복문을 넣을 수 있지만 역할을 분리해야 개별 규칙을 직접 검사할 수 있다.

## 난수 상태를 전역 함수에 숨기지 않는다

기존 코드는 `srand`와 `rand`를 사용했다.

```cpp
// srand(static_cast<unsigned int>(time(nullptr)));
// int candidate = (rand() % 45) + 1;
```

이 방식에는 몇 가지 한계가 있다.

- 난수 상태가 전역으로 공유되어 함수의 실제 의존성이 선언에 나타나지 않는다.
- 테스트에서 원하는 난수 상태를 함수에 직접 제공하기 어렵다.
- `rand() % 45`는 `RAND_MAX + 1`이 45로 정확히 나누어지지 않으면 나머지 값의 빈도가 완전히 같지 않을 수 있다.
- 초 단위 시간을 시드로 사용하면 가까운 시점의 실행이 같은 시드를 가질 수 있다.

표준 난수 엔진을 객체로 만들고 필요한 함수에 참조로 전달한다.

```cpp
#include <random>

int DrawCandidate(std::mt19937& generator)
{
    std::uniform_int_distribution<int> distribution(MinimumNumber, MaximumNumber);
    return distribution(generator);
}
```

함수 선언을 보면 난수 엔진의 상태를 사용하고 변경한다는 의존성이 드러난다. 분포 객체는 1부터 45까지의 정수를 생성하도록 범위를 직접 표현한다.

## 실행용 시드와 테스트용 시드를 구분한다

일반 실행에서는 `std::random_device`에서 시드 재료를 얻어 엔진을 초기화할 수 있다.

```cpp
std::random_device seedSource;
std::mt19937 generator(seedSource());
```

`std::random_device`가 모든 구현에서 물리적인 비결정 난수를 제공한다고 보장되는 것은 아니다. 여기서는 실행용 초기 상태를 얻기 위한 표준 인터페이스로 사용한다.

테스트에서는 고정된 시드를 전달한다.

```cpp
std::mt19937 generator(12345);
```

같은 구현과 설정에서 실패한 입력 흐름을 다시 살펴보기 쉬워진다. `std::mt19937` 엔진의 알고리즘은 정해져 있지만 `std::uniform_int_distribution`이 엔진 값을 범위에 매핑하는 구체적인 결과 열까지 서로 다른 표준 라이브러리 구현에서 같다고 가정하지 않는다.

테스트가 특정 번호 여섯 개에 의존하기보다 생성 결과가 범위·유일성 조건을 만족하는지 확인하도록 작성하면 구현 차이에 덜 민감하다.

## 중복 검사는 이미 채운 구간만 확인한다

`LottoTicket ticket{}`으로 초기화하면 모든 요소가 0이다. 하지만 0은 아직 선택하지 않은 빈칸을 표시하기 위한 우연한 값일 뿐, 중복 검사 대상은 실제로 채운 구간이어야 한다.

```cpp
#include <span>

bool Contains(std::span<const int> values, int candidate)
{
    for (int value : values)
    {
        if (value == candidate)
        {
            return true;
        }
    }

    return false;
}
```

생성 중 세 개의 번호만 채웠다면 처음 세 요소만 span으로 전달한다.

```cpp
std::size_t filledCount = 3;
std::span<const int> selected(ticket.data(), filledCount);
bool duplicated = Contains(selected, candidate);
```

배열 전체를 검사하면 아직 사용하지 않은 0까지 불필요하게 확인한다. 현재 번호 범위에 0이 없으므로 당장은 결과에 영향을 주지 않을 수 있지만, 검사 범위를 실제 유효 데이터와 일치시키는 편이 정확하다.

`Contains`는 배열 전체 크기나 빈칸 표현을 알 필요 없이 전달받은 유효 범위에서 같은 숫자가 있는지만 판단한다.

## 새 후보일 때만 채운 개수를 증가시킨다

중복 없는 번호 여섯 개를 생성한다.

```cpp
LottoTicket GenerateTicket(std::mt19937& generator)
{
    LottoTicket ticket{};
    std::size_t filledCount = 0;

    while (filledCount < ticket.size())
    {
        int candidate = DrawCandidate(generator);
        std::span<const int> selected(ticket.data(), filledCount);

        if (Contains(selected, candidate))
        {
            continue;
        }

        ticket[filledCount] = candidate;
        ++filledCount;
    }

    return ticket;
}
```

반복문이 한 번 실행될 때마다 `filledCount`가 증가하는 것은 아니다.

```text
새 후보 생성
   │
   ├─ 기존 번호와 같음 ── filledCount 유지
   │
   └─ 기존 번호와 다름 ── 저장 후 filledCount 증가
```

`filledCount`는 다음에 쓸 인덱스이면서 현재 유효한 요소 개수다. 항상 `0 <= filledCount <= ticket.size()` 범위를 유지해야 한다.

## 거절 방식은 선택 가능한 숫자가 충분해야 끝난다

중복 후보를 버리고 다시 생성하는 방식을 거절 샘플링(Rejection sampling)이라고 볼 수 있다. 이번 설정에서는 45개 중 6개만 선택하므로 완료 가능한 조건이다.

일반화된 함수라면 요청 개수가 가능한 숫자 종류보다 많지 않은지 먼저 검사해야 한다.

```text
요청 개수 <= MaximumNumber - MinimumNumber + 1
```

이번 상수로 계산하면 다음과 같다.

```text
6 <= 45 - 1 + 1
6 <= 45
```

요청 개수가 46이라면 중복 없이 채울 수 없다. 단순한 `while` 반복은 영원히 완료되지 않으므로 입력 조건을 함수에 들어가기 전에 거절해야 한다.

현재 예제는 크기가 고정돼 있으므로 컴파일 시간에 조건을 확인할 수 있다.

```cpp
static_assert(TicketSize <= static_cast<std::size_t>(MaximumNumber - MinimumNumber + 1));
```

## 기존 정렬은 선택 정렬과 비슷하지만 교환 시점이 다르다

기존 코드는 더 작은 값을 발견할 때마다 즉시 교환했다.

```cpp
for (std::size_t current = 0; current < numbers.size(); ++current)
{
    for (std::size_t next = current + 1; next < numbers.size(); ++next)
    {
        if (numbers[current] > numbers[next])
        {
            std::swap(numbers[current], numbers[next]);
        }
    }
}
```

이 코드도 최종 결과를 오름차순으로 만들 수 있지만 한 위치를 처리하는 동안 여러 번 교환할 수 있다.

전형적인 선택 정렬(Selection sort)은 남은 구간에서 가장 작은 값의 위치를 먼저 찾고, 내부 반복이 끝난 뒤 현재 위치와 한 번만 교환한다.

```text
정렬된 앞 구간 | 아직 정렬하지 않은 뒤 구간
                └─ 최솟값 위치 탐색
                         │
                         ▼
                현재 위치와 한 번 교환
```

알고리즘 이름을 붙일 때는 결과만 비슷한지보다 실제 단계가 해당 알고리즘의 구조와 일치하는지 확인한다.

## 선택 정렬은 최솟값 위치를 찾은 뒤 교환한다

`std::span<int>`으로 수정할 번호 범위를 받는다.

```cpp
#include <utility>

void SelectionSort(std::span<int> numbers)
{
    if (numbers.size() < 2)
    {
        return;
    }

    for (std::size_t current = 0; current + 1 < numbers.size(); ++current)
    {
        std::size_t minimumIndex = current;

        for (std::size_t next = current + 1; next < numbers.size(); ++next)
        {
            if (numbers[next] < numbers[minimumIndex])
            {
                minimumIndex = next;
            }
        }

        if (minimumIndex != current)
        {
            std::swap(numbers[current], numbers[minimumIndex]);
        }
    }
}
```

바깥 반복이 한 번 끝날 때마다 현재 위치에는 남은 값 중 가장 작은 값이 놓인다.

```text
초기:  [18, 3, 27, 11, 42, 7]
1회:   [ 3,18, 27, 11, 42, 7]
2회:   [ 3, 7, 27, 11, 42,18]
3회:   [ 3, 7, 11, 27, 42,18]
4회:   [ 3, 7, 11, 18, 42,27]
5회:   [ 3, 7, 11, 18, 27,42]
```

이 배열은 알고리즘 흐름을 설명하기 위해 선택한 예시이며 난수 생성 결과라고 주장하는 값이 아니다.

## 선택 정렬의 비교 횟수와 교환 횟수를 구분한다

요소가 $N$개라면 선택 정렬의 비교 횟수는 다음과 같다.

$$
(N - 1) + (N - 2) + \cdots + 1 = \frac{N(N - 1)}{2}
$$

시간 복잡도는 $O(N^2)$이다. 여섯 개를 정렬하면 비교 횟수는 다음과 같다.

$$
\frac{6 \times 5}{2} = 15
$$

교환은 각 바깥 반복에서 최대 한 번 일어나므로 최대 5번이다. 기존 즉시 교환 방식은 비교 횟수는 같지만 조건을 만족할 때마다 교환해 최대 15번까지 교환할 수 있다.

로또 번호 6개에서는 어느 방식도 성능 문제가 되기 어렵다. 여기서 선택 정렬을 직접 구현하는 목적은 최솟값 탐색과 교환 단계를 이해하는 데 있다. 실제 정렬이 목적이라면 표준 `std::sort`를 우선 사용한다.

## 범위 조건은 별도 함수로 검증한다

각 숫자가 1부터 45 사이인지 검사한다.

```cpp
bool IsInRange(std::span<const int> numbers)
{
    for (int number : numbers)
    {
        if (number < MinimumNumber || number > MaximumNumber)
        {
            return false;
        }
    }

    return true;
}
```

빈 범위에서는 범위를 벗어난 원소가 없으므로 이 함수만 보면 `true`를 반환한다. 하지만 로또 티켓의 요소 개수 조건은 `LottoTicket` 타입이 6개로 고정해 표현한다.

## 유일성은 모든 원소 쌍을 비교해 검증한다

생성 함수가 중복을 거절하더라도 최종 결과를 별도로 확인할 수 있다.

```cpp
bool HasUniqueValues(std::span<const int> numbers)
{
    for (std::size_t first = 0; first < numbers.size(); ++first)
    {
        for (std::size_t second = first + 1; second < numbers.size(); ++second)
        {
            if (numbers[first] == numbers[second])
            {
                return false;
            }
        }
    }

    return true;
}
```

각 쌍을 한 번씩만 비교하므로 같은 위치를 자신과 비교하지 않고 `(first, second)`와 `(second, first)`를 중복 검사하지 않는다.

검증 함수가 생성 함수와 다른 구조를 사용하면 같은 실수를 그대로 반복할 가능성을 줄일 수 있다. 생성은 채운 앞 구간에서 후보 하나를 찾고, 검증은 완성된 배열의 모든 쌍을 비교한다.

## 정렬 상태는 인접한 원소를 비교해 검증한다

오름차순을 여기서는 같은 값도 허용하는 비감소 순서로 정의한다.

```cpp
bool IsSortedAscending(std::span<const int> numbers)
{
    for (std::size_t index = 1; index < numbers.size(); ++index)
    {
        if (numbers[index - 1] > numbers[index])
        {
            return false;
        }
    }

    return true;
}
```

로또 번호는 유일성 검사도 통과해야 하므로 최종적으로는 모든 앞 숫자가 뒤 숫자보다 작다. 하지만 정렬 검사는 정렬이라는 한 책임에 집중해 같은 값 자체를 실패로 처리하지 않는다.

```text
[3, 7, 11, 18, 27, 42]  정렬됨
[3, 7, 7, 18, 27, 42]   정렬됐지만 유일하지 않음
[3, 11, 7, 18, 27, 42]  정렬되지 않음
```

검증 조건을 분리하면 두 번째 배열이 어느 규칙을 위반했는지 정확히 말할 수 있다.

## 최종 유효성은 독립 조건을 조합한다

티켓 전체 조건을 조합한다.

```cpp
bool IsValidTicket(const LottoTicket& ticket)
{
    return IsInRange(ticket) && HasUniqueValues(ticket) && IsSortedAscending(ticket);
}
```

`LottoTicket`의 크기는 타입이 이미 6으로 고정한다. 함수는 값 범위, 유일성과 정렬 상태를 검사한다.

조건을 한 표현식으로 조합해도 각 세부 함수를 독립적으로 테스트할 수 있다. 문제가 생기면 어느 조건이 `false`인지 따로 확인한다.

## 검증용 고정 데이터로 각 조건을 확인한다

난수에 의존하지 않고 검증 함수 자체를 확인할 수 있다.

```cpp
#include <cassert>

void VerifyValidationRules()
{
    LottoTicket valid{3, 7, 11, 18, 27, 42};
    LottoTicket outOfRange{0, 7, 11, 18, 27, 42};
    LottoTicket duplicated{3, 7, 7, 18, 27, 42};
    LottoTicket unsorted{3, 11, 7, 18, 27, 42};

    assert(IsValidTicket(valid));
    assert(!IsInRange(outOfRange));
    assert(!HasUniqueValues(duplicated));
    assert(!IsSortedAscending(unsorted));
}
```

`assert`는 조건이 거짓일 때 진단하고 프로그램을 중단하는 디버깅 도구다. `NDEBUG`가 정의된 빌드에서는 검사식이 제거될 수 있으므로 사용자 입력 검증이나 반드시 실행해야 하는 오류 처리 수단으로 사용하지 않는다.

이 코드는 직접 실행을 완료했다는 결과가 아니라, 프로그램을 실행할 때 확인하도록 작성한 검증 시나리오다.

## 생성과 정렬을 연결한다

난수 엔진을 받아 티켓을 생성하고 정렬한다.

```cpp
LottoTicket CreateSortedTicket(std::mt19937& generator)
{
    LottoTicket ticket = GenerateTicket(generator);
    SelectionSort(ticket);
    return ticket;
}
```

함수 이름과 반환 타입에서 다음 계약을 기대할 수 있다.

- `GenerateTicket`은 범위 안의 중복 없는 번호 여섯 개를 만든다.
- `SelectionSort`는 전달받은 번호 순서를 오름차순으로 바꾼다.
- `CreateSortedTicket`은 두 단계를 조합해 정렬된 새 티켓을 반환한다.

검증 함수는 이 계약이 깨지지 않았는지 확인하는 별도 안전망이다.

## 출력은 계산과 검증이 끝난 결과만 사용한다

출력 함수는 티켓을 읽기만 한다.

```cpp
#include <iostream>

void PrintTicket(const LottoTicket& ticket)
{
    for (std::size_t index = 0; index < ticket.size(); ++index)
    {
        std::cout << '[' << index + 1 << "] " << ticket[index] << '\n';
    }
}
```

`std::endl` 대신 `\n`을 사용해 매 줄마다 불필요한 강제 flush를 요청하지 않는다. 즉시 출력이 필요한 대화형 상황에서는 별도로 flush할 수 있다.

출력 형식을 바꿔도 번호 생성과 정렬 함수는 수정하지 않는다.

## 전체 수동 구현

앞에서 분리한 함수를 하나의 파일로 구성한 예제다.

```cpp
#include <array>
#include <cassert>
#include <cstddef>
#include <iostream>
#include <random>
#include <span>
#include <utility>

constexpr int MinimumNumber = 1;
constexpr int MaximumNumber = 45;
constexpr std::size_t TicketSize = 6;

using LottoTicket = std::array<int, TicketSize>;

static_assert(TicketSize <= static_cast<std::size_t>(MaximumNumber - MinimumNumber + 1));

int DrawCandidate(std::mt19937& generator)
{
    std::uniform_int_distribution<int> distribution(MinimumNumber, MaximumNumber);
    return distribution(generator);
}

bool Contains(std::span<const int> values, int candidate)
{
    for (int value : values)
    {
        if (value == candidate)
        {
            return true;
        }
    }

    return false;
}

LottoTicket GenerateTicket(std::mt19937& generator)
{
    LottoTicket ticket{};
    std::size_t filledCount = 0;

    while (filledCount < ticket.size())
    {
        int candidate = DrawCandidate(generator);
        std::span<const int> selected(ticket.data(), filledCount);

        if (Contains(selected, candidate))
        {
            continue;
        }

        ticket[filledCount] = candidate;
        ++filledCount;
    }

    return ticket;
}

void SelectionSort(std::span<int> numbers)
{
    if (numbers.size() < 2)
    {
        return;
    }

    for (std::size_t current = 0; current + 1 < numbers.size(); ++current)
    {
        std::size_t minimumIndex = current;

        for (std::size_t next = current + 1; next < numbers.size(); ++next)
        {
            if (numbers[next] < numbers[minimumIndex])
            {
                minimumIndex = next;
            }
        }

        if (minimumIndex != current)
        {
            std::swap(numbers[current], numbers[minimumIndex]);
        }
    }
}

bool IsInRange(std::span<const int> numbers)
{
    for (int number : numbers)
    {
        if (number < MinimumNumber || number > MaximumNumber)
        {
            return false;
        }
    }

    return true;
}

bool HasUniqueValues(std::span<const int> numbers)
{
    for (std::size_t first = 0; first < numbers.size(); ++first)
    {
        for (std::size_t second = first + 1; second < numbers.size(); ++second)
        {
            if (numbers[first] == numbers[second])
            {
                return false;
            }
        }
    }

    return true;
}

bool IsSortedAscending(std::span<const int> numbers)
{
    for (std::size_t index = 1; index < numbers.size(); ++index)
    {
        if (numbers[index - 1] > numbers[index])
        {
            return false;
        }
    }

    return true;
}

bool IsValidTicket(const LottoTicket& ticket)
{
    return IsInRange(ticket) && HasUniqueValues(ticket) && IsSortedAscending(ticket);
}

void VerifyValidationRules()
{
    LottoTicket valid{3, 7, 11, 18, 27, 42};
    LottoTicket outOfRange{0, 7, 11, 18, 27, 42};
    LottoTicket duplicated{3, 7, 7, 18, 27, 42};
    LottoTicket unsorted{3, 11, 7, 18, 27, 42};

    assert(IsValidTicket(valid));
    assert(!IsInRange(outOfRange));
    assert(!HasUniqueValues(duplicated));
    assert(!IsSortedAscending(unsorted));
}

LottoTicket CreateSortedTicket(std::mt19937& generator)
{
    LottoTicket ticket = GenerateTicket(generator);
    SelectionSort(ticket);
    return ticket;
}

void PrintTicket(const LottoTicket& ticket)
{
    for (std::size_t index = 0; index < ticket.size(); ++index)
    {
        std::cout << '[' << index + 1 << "] " << ticket[index] << '\n';
    }
}

int main()
{
    VerifyValidationRules();

    std::random_device seedSource;
    std::mt19937 generator(seedSource());
    LottoTicket ticket = CreateSortedTicket(generator);

    if (!IsValidTicket(ticket))
    {
        std::cout << "Failed to create a valid ticket.\n";
        return 1;
    }

    PrintTicket(ticket);
}
```

이 코드는 C++20의 `std::span`을 사용한다. `LottoTicket`은 번호 여섯 개를 소유하고, span 매개변수는 해당 요소를 소유하지 않은 채 필요한 범위와 수정 권한만 전달한다.

실제 난수 출력값은 실행 환경과 시드에 따라 달라지므로 만들어내지 않는다. 검증 함수가 확인하는 것은 특정 번호 조합이 아니라 결과가 만족해야 하는 조건이다.

## 표준 알고리즘으로 수동 구현을 대체할 수 있다

직접 만든 `Contains`와 `SelectionSort`는 탐색과 정렬 원리를 학습하는 데 의미가 있다. 실제 프로그램에서는 표준 알고리즘을 사용해 의도를 더 직접적으로 표현할 수 있다.

```cpp
#include <algorithm>

bool Contains(std::span<const int> values, int candidate)
{
    return std::find(values.begin(), values.end(), candidate) != values.end();
}

void SortTicket(LottoTicket& ticket)
{
    std::sort(ticket.begin(), ticket.end());
}
```

표준 알고리즘은 일반적인 경계와 타입 조합에서 충분히 검토된 구현을 제공한다. 직접 구현보다 무조건 빠르다고 단정하기보다 코드의 목적이 알고리즘 학습인지 기능 구현인지 먼저 구분한다.

## 전체 후보를 섞으면 중복 검사가 필요 없다

1부터 45까지의 숫자를 한 번씩 가진 배열을 만들고 순서를 섞은 뒤 앞의 여섯 개를 선택할 수 있다.

```cpp
#include <algorithm>
#include <array>
#include <numeric>
#include <random>

LottoTicket GenerateTicketByShuffle(std::mt19937& generator)
{
    std::array<int, MaximumNumber - MinimumNumber + 1> pool{};
    std::iota(pool.begin(), pool.end(), MinimumNumber);
    std::shuffle(pool.begin(), pool.end(), generator);

    LottoTicket ticket{};
    std::copy_n(pool.begin(), ticket.size(), ticket.begin());
    std::sort(ticket.begin(), ticket.end());
    return ticket;
}
```

`std::iota`가 1부터 45까지 서로 다른 값을 채우므로 pool 자체가 유일성을 보장한다. `std::shuffle`은 원소의 순서만 바꾸고 값을 추가하거나 제거하지 않는다. 앞의 여섯 개도 자연스럽게 중복이 없다.

```text
1~45를 한 번씩 채움
        │
        ▼
전체 순서를 무작위로 섞음
        │
        ▼
앞의 6개 복사
        │
        ▼
6개만 오름차순 정렬
```

이 방식은 후보가 중복될 때 다시 뽑는 반복이 없다. 대신 45개짜리 pool 전체를 만들고 섞는다.

## 두 생성 방식을 요구사항에 따라 비교한다

| 기준 | 거절 샘플링 | 전체 후보 섞기 |
| :--- | :--- | :--- |
| 추가 저장 공간 | 결과 티켓 외에는 작음 | 가능한 숫자 전체 pool 필요 |
| 중복 처리 | 기존 선택과 비교해 중복 후보 거절 | pool이 처음부터 유일함 |
| 반복 횟수 | 중복 후보 수에 따라 달라짐 | pool 전체를 한 번 섞음 |
| 선택 수가 범위에 가까울 때 | 중복 재시도가 많아질 수 있음 | 상대적으로 예측 가능한 과정 |
| 학습할 개념 | 부분 범위 탐색, 반복 조건 | `iota`, `shuffle`, 부분 복사 |

45개 중 6개를 선택하는 작은 프로그램에서는 둘 다 충분히 사용할 수 있다. 가능한 범위가 매우 크고 선택 수가 작다면 전체 pool을 만드는 비용이 불필요할 수 있다. 반대로 가능한 값 대부분을 선택해야 한다면 거절 방식의 재시도가 크게 늘 수 있다.

알고리즘은 한 문장짜리 성능 순위가 아니라 입력 범위, 선택 개수, 메모리와 재현성 요구를 함께 보고 선택한다.

## 균등성은 생성 방식 전체를 기준으로 판단한다

`std::uniform_int_distribution`을 사용하면 지정 범위의 각 정수를 균등하게 생성하도록 의도를 표현할 수 있다. 중복 후보를 버리고 다시 뽑는 방식은 각 단계에서 남은 숫자들 사이의 대칭을 유지하므로 올바르게 구현하면 크기 6의 조합을 균등하게 선택할 수 있다.

전체 후보를 균등하게 섞고 앞의 여섯 개를 선택하는 방식도 각 조합을 같은 확률로 얻는다. 최종 정렬은 선택된 집합의 표시 순서만 바꾸며 어떤 숫자가 선택됐는지는 바꾸지 않는다.

하지만 난수 품질은 엔진, 시드와 분포 사용 방식에 영향을 받는다. 이 예제는 실제 복권 시스템의 보안·감사 요구사항을 만족하는 난수 설계가 아니라 배열과 알고리즘 학습을 위한 프로그램이다.

## 성능보다 먼저 종료와 정확성을 확인한다

작은 로또 생성기에서도 다음 오류가 더 중요하다.

- 선택 가능한 숫자보다 많은 고유 값을 요청한다.
- 아직 채우지 않은 배열 구간까지 유효한 데이터처럼 검사한다.
- 중복 후보에서도 채운 개수를 증가시킨다.
- 마지막 인덱스를 배열 크기와 혼동한다.
- 정렬 함수에 잘못된 범위를 전달한다.
- 출력만 보고 범위·유일성·정렬을 검증하지 않는다.

성능 비교는 이런 정확성 조건이 충족된 뒤에 의미가 있다. 번호 6개에서 선택 정렬의 15회 비교를 줄이는 것보다 무한 반복과 경계 밖 접근을 막는 것이 우선이다.

## 로또 생성기를 검토할 때 확인할 기준

1. 가능한 숫자 범위와 선택 개수가 명시돼 있는가?
2. 선택 개수가 가능한 고유 값의 수보다 크지 않은가?
3. 난수 엔진이 전역 상태에 숨지 않고 필요한 함수에 전달되는가?
4. 후보가 지정 범위 안에서 생성되는가?
5. 중복 검사가 이미 채운 구간에만 적용되는가?
6. 중복 후보에서는 저장 인덱스를 증가시키지 않는가?
7. 정렬이 의도한 알고리즘의 단계대로 구현됐는가?
8. 범위·유일성·정렬 조건을 각각 검증하는가?
9. 테스트용 고정 시드와 실행용 시드를 구분하는가?
10. 수동 구현이 필요한 학습 코드인지 표준 알고리즘을 사용할 기능 코드인지 구분했는가?

작은 배열 실습도 입력 조건, 각 단계의 보장과 검증 기준을 나누면 테스트 가능한 프로그램이 된다. 생성 결과 하나가 그럴듯하게 보인다는 사실보다 모든 가능한 실행에서 조건을 유지하는 구조가 중요하다.
