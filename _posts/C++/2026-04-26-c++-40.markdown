생성자의 목적은 객체를 사용할 수 있는 초기 상태로 만드는 것이다. 그런데 생성자 본문에서 멤버에 값을 대입하면 생성과 초기화를 마친 객체의 상태를 나중에 변경하는 과정이 된다.

멤버 초기화 목록(Member initializer list)을 사용하면 기반 클래스와 멤버 객체가 어떤 값으로 생성될지 직접 지정할 수 있다. `const`와 참조 멤버처럼 나중에 대입할 수 없는 대상에는 선택 사항이 아니라 필수다.

## 초기화와 대입은 실행 시점이 다르다

생성자 본문에서 멤버에 값을 넣는 코드가 있다.

```cpp
class Knight
{
public:
    Knight()
    {
        hp_ = 100;
    }

private:
    int hp_;
};
```

`hp_`의 초기화 단계는 생성자 본문보다 먼저 지나간다. 본문의 `hp_ = 100;`은 초기화가 아니라 대입이다.

멤버 초기화 목록을 사용하면 객체 수명이 시작될 때 원하는 값으로 직접 초기화한다.

```cpp
Knight::Knight() : hp_(100)
{
}
```

기본 정수 멤버에서는 두 코드의 최종 값만 보면 같아 보일 수 있다. 하지만 클래스 타입 멤버는 생성자 호출과 대입 연산이 서로 다른 작업이므로 차이가 명확해진다.

## 클래스 타입 멤버는 생성자 본문 전에 이미 만들어진다

`Knight`가 `Inventory`를 멤버로 가진다.

```cpp
class Inventory
{
public:
    Inventory();
    explicit Inventory(int capacity);
};

class Knight
{
private:
    Inventory inventory_;
};
```

생성자 본문에서 다음처럼 대입한다고 가정한다.

```cpp
Knight::Knight()
{
    inventory_ = Inventory{20};
}
```

실제 흐름은 다음과 같다.

```text
1. inventory_가 Inventory()로 기본 생성된다.
2. 생성자 본문에 진입한다.
3. Inventory{20} 임시 객체가 생성된다.
4. 이미 존재하는 inventory_에 임시 객체를 대입한다.
5. 전체 표현식이 끝나며 임시 객체가 소멸한다.
```

이 과정에서 기존 `inventory_` 객체가 소멸한 뒤 다시 생성되는 것은 아니다. 기존 객체는 그대로 존재하고 그 객체에 대입 연산이 수행된다.

처음부터 용량 20으로 생성하려면 초기화 목록을 사용한다.

```cpp
Knight::Knight() : inventory_(20)
{
}
```

이 경우 `inventory_`는 `Inventory(int)`로 한 번 직접 생성된다. 불필요한 기본 생성과 대입을 피할 뿐 아니라 “기사는 용량 20인 인벤토리를 가지고 시작한다”는 초기 조건도 생성자 선언에 드러난다.

## 초기화 목록은 콜론 뒤에 작성한다

생성자 정의에서 매개변수 목록과 본문 사이에 콜론을 붙이고 초기화할 대상을 나열한다.

```cpp
Knight::Knight(int hp, int capacity) : hp_(hp), inventory_(capacity)
{
}
```

각 항목은 함수를 호출하는 문장이 아니라 해당 기반 클래스 또는 멤버가 어떤 초기값으로 생성될지 지정하는 초기화 구문이다.

중괄호도 사용할 수 있다.

```cpp
Knight::Knight(int hp, int capacity) : hp_{hp}, inventory_{capacity}
{
}
```

중괄호 초기화는 축소 변환을 제한하는 특징이 있다. 프로젝트에서는 한 가지 표기만 기계적으로 강제하기보다 생성자 호출과 값 초기화의 의미가 분명하게 보이도록 일관된 방식을 선택한다.

## 기반 클래스 생성자도 초기화 목록에서 선택한다

`Knight`가 `Player`를 상속하고 `Player`에 기본 생성자가 없다고 가정한다.

```cpp
class Player
{
public:
    explicit Player(int id);
};
```

파생 생성자는 기반 클래스 부분을 만들 생성자를 지정해야 한다.

```cpp
Knight::Knight(int id, int hp, int capacity) : Player(id), hp_(hp), inventory_(capacity)
{
}
```

파생 생성자 본문에 진입했을 때는 기반 클래스 부분의 초기화가 이미 끝났다. 따라서 기반 생성자 선택을 본문으로 미룰 수 없다.

## const와 참조 멤버는 초기화 목록에서 연결한다

`const` 멤버는 초기화가 끝난 뒤 다른 값을 대입할 수 없다.

```cpp
class Knight
{
public:
    explicit Knight(int rank) : rank_(rank)
    {
    }

private:
    const int rank_;
};
```

참조 멤버는 생성될 때 참조할 대상을 정해야 한다.

```cpp
struct GameRules
{
    int maxHp;
};

class Knight
{
public:
    explicit Knight(GameRules& rules) : rules_(rules)
    {
    }

private:
    GameRules& rules_;
};
```

참조는 초기화된 뒤 다른 객체를 가리키도록 다시 연결할 수 없다. 또한 `Knight`보다 먼저 `GameRules`가 소멸하면 `rules_`가 무효한 대상을 참조하므로 외부 객체의 수명이 충분히 길어야 한다.

참조 멤버가 있는 클래스는 기본 복사 동작도 주의해야 한다. 복사된 객체의 참조 멤버는 원본이 참조하던 같은 객체를 계속 참조한다. 그것이 의도한 소유 관계인지 확인해야 한다.

## 작성 순서가 아니라 선언 순서로 초기화된다

초기화 목록의 순서를 바꿔도 멤버의 실제 초기화 순서는 바뀌지 않는다.

```cpp
class Knight
{
public:
    Knight() : attack_(hp_ / 10), hp_(100)
    {
    }

private:
    int hp_;
    int attack_;
};
```

이 클래스에서는 선언 순서에 따라 `hp_`가 먼저, `attack_`이 다음에 초기화된다. 따라서 위 코드는 결과적으로 동작하지만 초기화 목록의 표면적인 순서와 실제 순서가 달라 읽는 사람을 혼란스럽게 한다.

초기화 목록도 멤버 선언 순서와 맞춘다.

```cpp
Knight::Knight() : hp_(100), attack_(hp_ / 10)
{
}
```

전체 생성 순서는 다음과 같다.

```text
1. 가상 기반 클래스
2. 직접 기반 클래스
3. 멤버 선언 순서
4. 생성자 본문
```

이번 예제처럼 가상 상속이 없다면 직접 기반 클래스, 멤버, 생성자 본문 순서에 집중하면 된다. 소멸은 생성의 반대 순서로 진행되며 파생 클래스 소멸자 본문이 먼저 실행된 뒤 멤버와 기반 클래스 부분이 정리된다.

## 클래스 안의 기본 멤버 초기값은 생성자의 공통 기본값이다

C++11부터 데이터 멤버 선언과 함께 기본값을 지정할 수 있다.

```cpp
class Knight
{
private:
    int hp_ = 100;
    Monster* target_ = nullptr;
};
```

생성자가 해당 멤버를 초기화 목록에서 따로 지정하지 않으면 이 기본 멤버 초기값이 사용된다.

```cpp
Knight::Knight()
{
}
```

특정 생성자가 초기화 목록에서 값을 지정하면 그 값이 기본 멤버 초기값을 대신한다.

```cpp
Knight::Knight(int hp) : hp_(hp)
{
}
```

여러 생성자가 공유하는 기본값은 멤버 선언에 두고, 생성자마다 달라지는 값은 초기화 목록에서 지정하면 중복을 줄일 수 있다.

## 포함 관계는 has-a 관계를 표현한다

상속은 한 타입이 다른 타입의 한 종류인 is-a 관계에 사용한다.

```text
Knight is a Player.       → 상속 후보
Knight has an Inventory.  → 포함 후보
```

기사는 인벤토리의 한 종류가 아니라 인벤토리를 가진다. 따라서 `Inventory` 객체를 멤버로 포함하는 방식이 자연스럽다.

```cpp
class Knight : public Player
{
private:
    Inventory inventory_;
};
```

포함 관계에서는 `Knight`가 생성될 때 `inventory_`도 함께 생성되고, `Knight`의 수명이 끝날 때 자동으로 정리된다. 포인터로 별도 할당하지 않아도 두 객체의 수명을 하나로 묶을 수 있다.

멤버 객체의 공개 기능을 모두 외부에 그대로 노출할 필요도 없다. `Knight`가 필요한 인벤토리 동작만 자신의 인터페이스로 제공하면 내부 구현을 교체하기 쉽다.

## 전체 구현

`Player` 기반 클래스와 `Inventory` 멤버 객체가 어떤 순서로 생성되고 소멸하는지 확인하는 예제다.

```cpp
#include <algorithm>
#include <cassert>
#include <iostream>

struct GameRules
{
    int maxHp;
};

class Player
{
public:
    explicit Player(int id) : id_(id)
    {
        std::cout << "Player()\n";
    }

    ~Player()
    {
        std::cout << "~Player()\n";
    }

    int Id() const
    {
        return id_;
    }

private:
    int id_;
};

class Inventory
{
public:
    explicit Inventory(int capacity) : capacity_(std::max(0, capacity))
    {
        std::cout << "Inventory()\n";
    }

    ~Inventory()
    {
        std::cout << "~Inventory()\n";
    }

    int Capacity() const
    {
        return capacity_;
    }

private:
    int capacity_;
};

class Knight : public Player
{
public:
    Knight(GameRules& rules, int id, int inventoryCapacity, int rank) : Player(id), rules_(rules), hp_(std::max(0, rules_.maxHp)), inventory_(inventoryCapacity), rank_(rank)
    {
        std::cout << "Knight()\n";
    }

    ~Knight()
    {
        std::cout << "~Knight()\n";
    }

    int Hp() const
    {
        return hp_;
    }

    int InventoryCapacity() const
    {
        return inventory_.Capacity();
    }

    int Rank() const
    {
        return rank_;
    }

private:
    GameRules& rules_;
    int hp_;
    Inventory inventory_;
    const int rank_;
};

void VerifyKnight()
{
    GameRules rules{150};
    Knight knight{rules, 7, 20, 1};

    assert(knight.Id() == 7);
    assert(knight.Hp() == 150);
    assert(knight.InventoryCapacity() == 20);
    assert(knight.Rank() == 1);
}

int main()
{
    VerifyKnight();
}
```

생성 출력은 기반 클래스, 멤버 객체, 파생 클래스 생성자 본문의 순서를 보여준다.

```text
Player()
Inventory()
Knight()
```

`VerifyKnight`가 끝날 때는 파생 클래스 소멸자 본문이 먼저 실행되고, 멤버 객체와 기반 클래스가 반대 순서로 정리된다.

```text
~Knight()
~Inventory()
~Player()
```

`rules_`는 참조이고 `rank_`는 `const`이므로 생성 시점에 초기화해야 한다. `inventory_`도 원하는 용량을 생성자에 직접 전달하므로 기본 생성 후 대입하는 별도 과정이 없다.

## 생성 코드를 검토할 때 확인할 기준

1. 생성자 본문의 대입을 초기화라고 잘못 부르고 있지 않은가?
2. 클래스 타입 멤버를 기본 생성한 뒤 다시 대입하고 있지 않은가?
3. 기반 클래스가 사용할 생성자를 초기화 목록에서 지정했는가?
4. `const`와 참조 멤버를 생성과 동시에 초기화했는가?
5. 초기화 목록을 실제 멤버 선언 순서와 맞췄는가?
6. 다른 멤버의 값에 의존하는 초기화가 선언 순서상 안전한가?
7. 공통 기본값은 기본 멤버 초기값으로 둘 수 있는가?
8. is-a 관계에는 상속, has-a 관계에는 포함을 사용했는가?
9. 참조 멤버가 가리키는 외부 객체의 수명이 충분히 긴가?

멤버 초기화 목록은 생성자 코드를 짧게 만드는 문법이 아니다. 기반 클래스와 각 멤버가 어떤 상태로 수명을 시작할지 결정하고, 객체가 처음부터 유효한 상태가 되도록 만드는 장치다.
