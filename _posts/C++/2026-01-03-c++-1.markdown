C++ 공부의 첫 단계로 콘솔에 `Hello World!`를 출력한다.

코드는 네 줄 정도로 짧지만 그 안에는 헤더를 포함하는 전처리 지시어, 사용자 코드의 진입점, 표준 라이브러리의 출력 객체, 프로그램의 종료 상태가 모두 들어 있다. 작성한 소스가 바로 실행되는 것도 아니다. 전처리와 컴파일, 링크를 거쳐 실행 파일이 만들어져야 한다.

이번 글에서는 **각 코드가 맡은 역할**과 **소스 파일이 실행 파일로 바뀌는 과정**을 함께 살펴본다.

## 첫 C++ 프로그램

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello World!\n";
    return 0;
}
```

실행하면 표준 출력에 다음 문장이 나타난다.

```text
Hello World!
```

코드가 짧기 때문에 각 줄을 따로 떼어 살펴보기 좋다.

## `#include <iostream>`

`#include`는 컴파일 전에 처리되는 전처리 지시어다.

```cpp
#include <iostream>
```

`<iostream>`은 C++ 표준 입출력 스트림에 관한 선언을 제공하는 헤더다. 이 헤더를 포함하면 현재 소스 코드에서 `std::cout` 같은 이름이 무엇인지 컴파일러가 확인할 수 있다.

전통적인 전처리 모델에서는 지정한 헤더의 내용을 현재 소스에 포함한 것과 같은 결과를 만든다. 하지만 이것이 콘솔 출력의 모든 구현 코드가 그대로 소스 파일에 복사된다는 뜻은 아니다. 헤더를 통해 필요한 선언을 확인하고, 실제 표준 라이브러리 구현은 이후 링크 과정에서 결합될 수 있다.

헤더 이름을 감싸는 기호에 따라서도 일반적인 검색 방식이 달라진다.

```cpp
#include <iostream>     // 구현이 정한 표준 include 경로에서 검색
#include "Player.h"     // 보통 현재 프로젝트의 경로를 먼저 고려
```

구체적인 검색 순서는 컴파일러와 프로젝트 설정의 영향을 받지만, 표준 헤더와 프로젝트 헤더의 의도를 구분하는 기준으로 사용할 수 있다.

## 사용자 코드의 진입점 `main`

```cpp
int main()
{
}
```

일반적인 호스팅 환경에서 `main`은 C++ 사용자 코드가 시작되는 진입점이다.

운영체제가 함수 이름 `main`을 직접 찾아 호출하는 것은 아니다. 운영체제의 로더가 실행 파일에 기록된 실제 엔트리 포인트에서 프로그램을 시작하면, C++ 런타임이 필요한 초기화 작업을 수행한 뒤 `main`을 호출하는 구조가 일반적이다.

```text
운영체제가 실행 파일 로드
          ↓
런타임 초기화 코드 실행
          ↓
main 호출
          ↓
main의 종료 상태 전달
```

첫 학습 단계에서는 `main`을 “내가 작성한 C++ 코드의 시작점”으로 이해하면 충분하다. 실제 엔트리 포인트와 런타임 초기화 과정은 구현 환경에 따라 달라질 수 있다.

## `std::cout`과 표준 출력

```cpp
std::cout << "Hello World!\n";
```

`std::cout`은 C++ 표준 라이브러리가 제공하는 표준 출력 스트림 객체다. 일반적인 콘솔 프로그램에서는 터미널에 출력이 나타나지만, 프로그램을 실행하는 방식이나 출력 리디렉션에 따라 다른 대상으로 전달될 수도 있다.

이름을 부분별로 나누면 다음과 같다.

- `std`: C++ 표준 라이브러리의 이름들이 들어 있는 네임스페이스
- `::`: 특정 범위 안의 이름을 지정하는 범위 지정 연산자
- `cout`: 표준 출력 스트림 객체

네임스페이스는 서로 다른 라이브러리나 코드에서 같은 이름을 사용했을 때 충돌을 줄이는 역할을 한다. `std::cout`은 `std` 네임스페이스 안의 `cout`을 사용한다는 뜻이다.

첫 글에서는 `using namespace std;`를 사용하지 않고 `std::`를 직접 작성한다. 어떤 네임스페이스의 이름인지 코드에 드러나고, 불필요한 이름 충돌 가능성도 줄일 수 있다.

## `<<`가 문자열을 출력하는 과정

`std::cout`과 함께 사용한 `<<`는 스트림 삽입 연산자다.

```cpp
std::cout << "Hello World!\n";
```

오른쪽의 문자열을 왼쪽 출력 스트림으로 전달한다고 읽을 수 있다. 여러 값을 이어서 출력할 수도 있다.

```cpp
std::cout << "Level: " << 10 << '\n';
```

같은 `<<` 기호라도 항상 출력이라는 뜻은 아니다.

```cpp
std::cout << "Hello";    // 스트림 삽입
int value = 1 << 3;      // 정수의 비트를 왼쪽으로 이동
```

C++에서는 연산에 참여하는 타입과 문맥에 따라 같은 연산자 기호가 다른 의미를 가질 수 있다. 현재 코드는 왼쪽 피연산자가 출력 스트림이므로 스트림 삽입으로 해석된다.

## `\n`과 `std::endl`의 차이

문자열 안의 `\n`은 줄바꿈을 나타내는 이스케이프 시퀀스다.

```cpp
std::cout << "Hello World!\n";
```

`std::endl`도 줄을 바꿀 수 있지만 동작은 완전히 같지 않다.

```cpp
std::cout << "Hello World!" << std::endl;
```

- `\n`: 줄바꿈 문자 출력
- `std::endl`: 줄바꿈 문자를 출력하고 스트림을 flush

flush는 출력 버퍼에 남아 있는 내용을 출력 대상으로 즉시 전달하도록 요청하는 동작이다. 즉시 출력이 필요한 상황이라면 `std::endl`의 flush가 목적에 맞을 수 있지만, 단순히 줄만 바꾸려는 경우에는 `\n`이 의도를 더 직접적으로 표현한다.

`std::endl`이 언제나 나쁘거나 `\n`이 언제나 더 빠르다고 단정하기보다 출력 시점 제어가 필요한지를 기준으로 선택한다.

## `return 0;`과 종료 상태

`main` 앞의 `int`는 함수가 정수 값을 반환한다는 뜻이다.

```cpp
int main()
{
    return 0;
}
```

`return 0;`은 일반적으로 프로그램이 정상적으로 종료됐다는 상태를 실행 환경에 전달한다. 0이 아닌 값은 오류나 다른 종료 상태를 나타내는 데 사용할 수 있다.

`main` 함수는 끝까지 도달하면 `return 0;`을 작성한 것과 같은 의미가 된다.

```cpp
int main()
{
    std::cout << "Hello World!\n";
} // main에서는 0 반환으로 처리
```

이 규칙은 `main`에 적용되는 특별한 규칙이다. 일반적인 다른 `int` 반환 함수에서 반환문을 생략해도 자동으로 0을 반환하는 것은 아니다.

첫 예제에서는 반환형과 반환값의 관계가 코드에 직접 보이도록 `return 0;`을 명시한다.

## 세미콜론은 어디에 붙는가

예제의 다음 문장들은 세미콜론으로 끝난다.

```cpp
std::cout << "Hello World!\n";
return 0;
```

하지만 “C++의 모든 문장은 세미콜론으로 끝난다”라고 일반화할 수는 없다. 함수 정의와 제어문의 블록 자체에는 세미콜론을 붙이지 않는다.

```cpp
int main()
{
    if (true)
    {
        return 0;
    }
}
```

표현식 문장, 변수 선언, `return` 문 등 많은 문장이 세미콜론으로 끝난다고 이해하는 편이 정확하다. 이후 새로운 문법을 배울 때 각 문법의 종료 규칙을 함께 확인해야 한다.

## 소스 파일에서 실행 파일까지

작성한 `.cpp` 파일은 그대로 CPU가 실행할 수 있는 형식이 아니다. 빌드 도구는 대략 다음 과정을 거쳐 실행 파일을 만든다.

```text
C++ 소스 파일
    ↓ 전처리
전처리된 번역 단위
    ↓ 컴파일 및 어셈블
오브젝트 파일
    ↓ 링크
실행 파일
    ↓ 운영체제가 로드
프로그램 실행
```

### 전처리

`#include`, 조건부 컴파일, 매크로 같은 전처리 지시어를 처리한다. 현재 `.cpp` 파일과 포함된 헤더 내용이 하나의 번역 단위를 구성하는 기반이 된다.

### 컴파일과 어셈블

C++ 문법과 타입을 검사하고 대상 CPU가 실행할 기계어가 담긴 오브젝트 파일을 만든다. 실제 툴체인은 컴파일과 어셈블 과정을 하나의 명령 안에서 처리할 수 있다.

### 링크

여러 오브젝트 파일과 필요한 라이브러리의 정의를 연결해 실행 파일을 만든다. `std::cout`과 관련된 표준 라이브러리 구현도 이 과정에서 결합될 수 있다.

### 로드와 실행

운영체제의 로더가 실행 파일의 코드와 데이터를 프로세스의 가상 메모리에 배치하고 실제 엔트리 포인트에서 실행을 시작한다.

## 번역 단위와 개별 컴파일

C++ 프로젝트의 모든 `.cpp` 파일을 처음부터 하나의 거대한 파일로 합쳐 컴파일하는 것은 일반적인 모델이 아니다. 각 `.cpp` 파일은 포함된 헤더와 함께 전처리를 거쳐 하나의 번역 단위(Translation Unit)를 만든다.

```text
main.cpp + 포함된 헤더
          ↓
     번역 단위 A
          ↓ 컴파일
     main.obj

Player.cpp + 포함된 헤더
          ↓
     번역 단위 B
          ↓ 컴파일
     Player.obj

main.obj + Player.obj + 라이브러리
          ↓ 링크
       실행 파일
```

이 구조 덕분에 변경된 소스 파일만 다시 컴파일할 수 있다. 반대로 헤더를 수정하면 그 헤더를 포함하는 여러 번역 단위가 다시 컴파일될 수 있다.

번역 단위를 따로 컴파일하기 때문에 어떤 이름의 선언은 보이지만 실제 정의를 링크할 수 없는 상황도 발생할 수 있다.

## 컴파일 오류·링크 오류·런타임 오류

오류가 발생한 단계에 따라 원인을 찾을 위치도 달라진다.

### 컴파일 오류

```cpp
std::cout << "Hello World!\n"
```

세미콜론 누락, 잘못된 문법, 맞지 않는 타입처럼 컴파일러가 번역 단위를 처리하는 동안 발견한 문제다.

### 링크 오류

함수 선언을 보고 호출 코드는 만들었지만 최종 실행 파일을 구성할 때 함수 정의를 찾지 못하는 경우 등이 해당한다.

```cpp
void PrintMessage();

int main()
{
    PrintMessage();
}
```

어디에도 `PrintMessage`의 정의가 없다면 소스 컴파일은 진행될 수 있어도 링크 단계에서 해결할 수 없는 외부 심볼 오류가 발생할 수 있다.

### 런타임 오류

빌드에는 성공했지만 실행 중 잘못된 메모리에 접근하거나 0으로 나누는 것처럼 실제 실행 과정에서 발생하는 문제가 해당한다.

컴파일에 성공했다는 사실은 실행 파일을 만들 수 있었다는 뜻이지, 프로그램의 모든 동작이 올바르다는 보장은 아니다.

## Visual Studio의 Solution과 Project

Visual Studio는 코드를 다음과 같은 단위로 관리한다.

### Solution

솔루션은 하나 이상의 프로젝트를 묶어 관리하는 상위 단위다. `.sln` 파일에는 솔루션에 포함된 프로젝트와 구성 정보가 기록된다.

### Project

C++ 프로젝트는 소스 파일, 헤더, 빌드 설정, 출력 형식 등을 관리하는 빌드 단위다. Visual C++ 프로젝트는 일반적으로 `.vcxproj` 파일을 사용한다.

```text
Solution
├─ GameProject
├─ ToolProject
└─ TestProject
```

솔루션에 프로젝트가 여러 개 있다면 실행할 대상을 Startup Project로 지정해야 한다. F5와 Ctrl+F5는 해당 시작 프로젝트의 실행 파일을 대상으로 동작한다.

## 빌드·실행·디버깅의 차이

Visual Studio에서 자주 사용하는 기본 동작은 다음과 같다. 키 배치는 사용 중인 프로필이나 설정에 따라 달라질 수 있다.

| 동작 | 일반적인 단축키 | 의미 |
| :--- | :---: | :--- |
| Build Solution | `Ctrl + Shift + B` | 실행하지 않고 프로젝트 빌드 |
| Start Debugging | `F5` | 디버거를 연결해 실행 |
| Start Without Debugging | `Ctrl + F5` | 디버거 없이 실행 |
| Toggle Breakpoint | `F9` | 현재 줄의 중단점 설정·해제 |
| Step Over | `F10` | 현재 줄을 실행하고 다음 줄에서 정지 |
| Step Into | `F11` | 호출한 함수 내부로 들어가며 실행 |
| Step Out | `Shift + F11` | 현재 함수를 마치고 호출자에서 정지 |

- **빌드**: 소스에서 실행 파일을 만드는 과정
- **실행**: 만들어진 프로그램을 동작시키는 과정
- **디버깅**: 프로그램을 실행하면서 중단점, 변수, 호출 흐름 등을 관찰하는 과정

빌드와 실행은 같은 작업이 아니다. 이미 빌드된 실행 파일이 있다면 다시 빌드하지 않고 실행할 수도 있고, 빌드에 성공한 프로그램이 실행 중 오류를 일으킬 수도 있다.

## 중단점으로 출력 시점 확인하기

`std::cout` 줄에 중단점을 설정해 코드가 실행되는 시점을 관찰해 본다.

```cpp
std::cout << "Hello World!\n";
```

1. 해당 줄에 커서를 두고 F9로 중단점을 설정한다.
2. F5로 디버깅을 시작한다.
3. 프로그램이 출력문을 실행하기 전에 중단되는지 확인한다.
4. F10으로 한 줄을 실행한다.
5. 콘솔에 `Hello World!`가 나타나는지 확인한다.
6. Call Stack 창에서 현재 실행 위치가 `main` 안에 있는지 확인한다.

중단점은 코드가 “작성된 위치”가 아니라 실제 실행 흐름이 그 명령에 도달했을 때 멈춘다. 이후 조건문과 반복문을 공부할 때 어떤 줄이 실행되거나 건너뛰는지 확인하는 데 계속 사용하게 된다.

## 다음 학습: 값을 변수에 저장하기

이번 글에서 확인한 핵심은 다음과 같다.

- `<iostream>`은 `std::cout` 사용에 필요한 선언을 제공한다.
- 일반적인 환경에서는 런타임 초기화 후 `main`이 사용자 코드의 진입점으로 호출된다.
- `std::cout`은 표준 출력 스트림 객체다.
- `<<`는 현재 문맥에서 데이터를 출력 스트림에 삽입한다.
- `\n`은 줄바꿈이고 `std::endl`은 줄바꿈 후 flush까지 수행한다.
- `main`의 `return 0;`은 정상 종료 상태를 전달한다.
- 각 `.cpp` 파일은 헤더와 함께 번역 단위를 만들고 개별 컴파일된다.
- 링커는 오브젝트 파일과 라이브러리를 결합해 실행 파일을 만든다.
- 컴파일 성공과 프로그램의 올바른 동작은 서로 다른 문제다.
- Visual Studio의 Solution과 Project는 서로 다른 관리 단위다.
