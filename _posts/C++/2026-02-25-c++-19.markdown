# [C++] 컴파일러에는 선언을, 링커에는 정의를 제공한다

C++ 컴파일러의 순차적 해석 특성으로 발생하는 식별자 에러를 해결하기 위한 전방 선언(Forward Declaration) 기법과 호출 스택의 동작 원리 분석

## 사용 전에 함수의 형태 알려주기

```cpp
#include <iostream>
using namespace std;

// [함수 전방 선언 (Forward Declaration)]
// 컴파일러에게 함수의 존재와 시그니처(반환형, 매개변수)를 미리 알려줌
void NewFunction1();
void NewFunction2(int a, int b);
void NewFunction3(float a);

// 함수의 실제 구현부 (Definition)
void NewFunction1()
{
    cout << "Function1 호출" << endl;
    // NewFunction2의 선언이 상단에 있으므로 정상적으로 호출됨
    NewFunction2(1, 2);
}

void NewFunction2(int a, int b)
{
    cout << "Function2 호출" << endl;
    // Function3을 호출한다. 실제 인자 전달 방식은 호출 규약이 정한다.
    NewFunction3(9.0f);
}

void NewFunction3(float a)
{
    cout << "Function3 호출" << endl;
}

int main()
{
    cout << "Main 함수 시작" << endl;

    // 함수 선언이 없다면 C++ 컴파일러의 Top-Down 해석 방식에 의해 식별자 찾기 에러가 발생함
    // 전방 선언을 통해 에러 없이 정상적으로 함수 연쇄 호출이 가능함
    NewFunction1();

    return 0;
}
```

## 선언과 정의가 맡는 역할

C++ 컴파일러는 소스 코드를 위에서부터 아래로 순차적으로(Top-Down) 번역.

호출 위치에서 함수 선언을 볼 수 없다면 컴파일러는 이름과 매개변수 형식을 확인할 수 없다. 이 단계에서는 함수의 실제 주소를 알아야 하는 것이 아니라 올바른 선언이 필요하다.

### 2.1 함수 선언(Declaration)과 정의(Definition)

| 구분 | 역할 및 특징 | 비고 |
| :--- | :--- | :--- |
| **선언 (Declaration)** | 함수의 반환 타입, 이름, 매개변수 타입만 명시함 (함수 원형) | 식별자 에러 방지용 |
| **정의 (Definition)** | 중괄호 `{}` 내부에 함수의 실제 동작을 제공함 | 보통 하나의 정의가 링커에서 연결됨 |

### 2.2 호출 스택 (Call Stack) 메커니즘

호출 프레임에는 반환 위치, 보존할 레지스터, 지역 상태 등이 포함될 수 있다. 구체적인 구성은 플랫폼 ABI와 최적화에 따라 달라진다.

* **어셈블리 관점의 함수 호출 과정**:
  $$\text{Push Parameters} \rightarrow \text{Push Return Address} \rightarrow \text{Call Function (Jump)}$$
* 함수 실행이 완료되면 스택 프레임에 저장된 반환 주소를 참조하여 자신을 호출했던 원래 위치로 제어권을 돌려줌
* 이러한 구조 덕분에 디버깅 시 **호출 스택(Call Stack)** 창을 확인하면 $Main \rightarrow Function1 \rightarrow Function2$ 와 같이 함수가 어떤 경로로 호출되었는지 역추적할 수 있음

## 컴파일 오류와 링크 오류 구분하기

### 핵심 요약 및 주의사항
* C++에서는 함수를 사용하기 전에 반드시 그 존재를 컴파일러에게 알려야 하므로, 함수 정의를 위로 올리거나 상단에 전방 선언을 작성
* 여러 함수가 꼬리를 물고 호출되는 경우 스택 프레임이 계속 누적되므로, 무한 재귀 호출 시 스택 메모리가 초과되는 스택 오버플로우(Stack Overflow)에 주의
* 함수 호출 시 스택에 데이터를 Push하고 제어권을 넘기는 과정 자체가 오버헤드임을 인지

### Tip
* 실무에서는 소스 코드 파일(`.cpp`) 상단에 함수 선언을 나열하기보다, 헤더 파일(`.h`)에 선언을 모아두고 소스 파일에서 `#include` 하여 사용하는 **모듈화 패턴**이 표준
* 호출 스택 창은 현재 지점까지의 호출 경로를 추적하는 핵심 도구다. 최적화된 빌드에서는 인라인과 꼬리 호출 등으로 소스의 함수 구조와 다르게 보일 수 있다.

선언이 없거나 호출 형태가 맞지 않으면 주로 컴파일 오류가 발생한다. 선언은 보였지만 대응하는 정의가 링크 대상에 없으면 링크 오류가 발생한다. 둘을 구분하면 문제를 찾을 파일도 빨라진다.

## 마무리

헤더에는 여러 번 공유할 선언을, 소스 파일에는 정의를 두는 것이 기본 구조다. 호출 스택은 실행 중 흐름을 보여 주지만 선언·정의 문제는 빌드 단계별 오류 메시지로 구분한다.
