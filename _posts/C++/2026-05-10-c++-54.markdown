함수 포인터를 사용하면 검색 함수에 조건을 전달할 수 있지만 함수 주소 자체에는 “희귀도 3 이상” 같은 실행 중 값을 저장할 공간이 없다. 값을 전역 변수에 두면 여러 검색이 하나의 공유 상태에 의존한다.

함수 객체(Function object)는 `operator()`를 정의해 함수 호출 문법으로 사용할 수 있는 객체다. 일반 객체처럼 데이터 멤버와 생성자를 가지면서 `condition(item)`처럼 호출할 수 있으므로 동작에 필요한 상태를 함께 전달할 수 있다. Functor라는 이름으로도 부른다.

## operator()를 정의하면 객체를 함수처럼 호출할 수 있다

일반 클래스에 함수 호출 연산자를 정의한다.

```cpp
class Printer
{
public:
    void operator()() const
    {
        std::cout << "Hello from Printer\n";
    }
};
```

객체를 만든 뒤 함수 호출과 같은 문법을 사용한다.

```cpp
Printer printer;
printer();
```

이 표현은 멤버 함수 호출로 연결된다.

```cpp
printer.operator()();
```

함수 객체라는 별도 언어 타입이 존재하는 것이 아니다. 호출 연산자를 오버로딩한 클래스 객체를 함수처럼 사용하는 것이다.

## 함수 객체는 호출 사이에 상태를 유지할 수 있다

호출 횟수를 기록하는 객체를 만든다.

```cpp
class CallCounter
{
public:
    int operator()()
    {
        ++count_;
        return count_;
    }

    int Count() const
    {
        return count_;
    }

private:
    int count_ = 0;
};
```

같은 객체를 반복 호출하면 데이터 멤버가 유지된다.

```cpp
CallCounter counter;

assert(counter() == 1);
assert(counter() == 2);
assert(counter.Count() == 2);
```

다른 `CallCounter` 객체는 자신의 상태를 따로 가진다.

```cpp
CallCounter another;
assert(another.Count() == 0);
```

전역 변수 없이 콜백 인스턴스마다 상태를 독립적으로 구성할 수 있다.

## operator()도 일반 멤버 함수처럼 오버로딩할 수 있다

원본 `Functor`는 인자 없는 호출과 정수 하나를 받는 호출을 함께 제공한다.

```cpp
class Calculator
{
public:
    int operator()() const
    {
        return base_;
    }

    int operator()(int value) const
    {
        return base_ + value;
    }

private:
    int base_ = 10;
};
```

호출 인자에 맞는 오버로드가 선택된다.

```cpp
Calculator calculator;
assert(calculator() == 10);
assert(calculator(3) == 13);
```

함수 객체가 아무 시그니처로나 호출될 수 있다는 뜻은 아니다. 실제 호출식과 호환되는 `operator()`가 있어야 한다. 함수 포인터와 비교했을 때 하나의 클래스가 여러 오버로드와 템플릿 호출 연산자를 제공할 수 있다는 차이가 있다.

## 읽기만 하는 조건 함수에는 const 호출 연산자를 사용한다

아이템을 검사하는 조건 객체는 자신의 기준과 검사 대상 모두 변경하지 않아도 된다.

```cpp
class HasMinimumRarity
{
public:
    explicit HasMinimumRarity(int minimum) : minimum_(minimum)
    {
    }

    bool operator()(const Item& item) const
    {
        return item.rarity >= minimum_;
    }

private:
    int minimum_;
};
```

마지막 `const`는 `operator()` 호출이 조건 객체의 상태를 바꾸지 않는다는 뜻이다.

```cpp
const HasMinimumRarity isRare{3};
bool result = isRare(item);
```

표준 알고리즘이나 일반화된 검색 함수가 조건 객체를 `const` 관점에서 호출할 수 있으므로 상태 변경이 필요 없는 함수 객체에는 `const` 정확성을 적용한다.

호출 횟수처럼 실제로 상태를 변경해야 한다면 비상수 `operator()`를 제공하거나, 논리적으로 관찰 결과에 영향을 주지 않는 캐시에는 신중하게 `mutable` 멤버를 사용할 수 있다.

## 함수 포인터로 어려웠던 검색 기준을 객체에 저장한다

아이템 구조체가 있다.

```cpp
struct Item
{
    int id;
    int rarity;
    int ownerId;
};
```

최소 희귀도를 생성자로 받아 저장한다.

```cpp
class HasMinimumRarity
{
public:
    explicit HasMinimumRarity(int minimum) : minimum_(minimum)
    {
    }

    bool operator()(const Item& item) const
    {
        return item.rarity >= minimum_;
    }

private:
    int minimum_;
};
```

검색할 때 서로 다른 조건 객체를 만들 수 있다.

```cpp
HasMinimumRarity rareOrBetter{2};
HasMinimumRarity legendaryOnly{4};

const Item* rare = FindItem(items, rareOrBetter);
const Item* legendary = FindItem(items, legendaryOnly);
```

두 객체는 같은 코드인 `operator()`를 사용하지만 `minimum_` 값이 다르다. 전역 최소 희귀도를 변경하거나 희귀도마다 별도 자유 함수를 만들 필요가 없다.

## 콜백을 템플릿으로 받으면 여러 호출 가능 타입을 사용할 수 있다

지난 글의 `FindItem`은 콜백 타입을 함수 포인터로 고정했다.

```cpp
using ItemSelector = bool (*)(const Item&);
```

함수 객체는 각 클래스마다 타입이 다르므로 검색 함수를 호출 가능 타입에 대해 일반화한다.

```cpp
template <std::size_t Size, typename Predicate>
const Item* FindItem(const std::array<Item, Size>& items, Predicate predicate)
{
    for (const Item& item : items)
    {
        if (predicate(item))
        {
            return &item;
        }
    }

    return nullptr;
}
```

`predicate(item)`이 `bool` 조건으로 사용될 수 있으면 함수 객체뿐 아니라 호환되는 함수 포인터도 전달할 수 있다.

```cpp
const Item* rare = FindItem(items, HasMinimumRarity{3});
const Item* unowned = FindItem(items, IsUnowned);
```

컴파일러는 전달된 콜백 타입마다 필요한 함수 템플릿 인스턴스를 만든다. 함수 템플릿의 추론과 인스턴스화는 다음 글에서 자세히 다룬다.

## 값으로 받은 함수 객체는 복사본일 수 있다

위 `FindItem`의 `Predicate predicate`는 콜백을 값으로 받는다. 호출자의 함수 객체가 검색 함수 안으로 복사되거나 이동될 수 있다.

```cpp
CallCounter counter;
FindItem(items, counter);
```

검색 중 증가한 횟수는 `counter` 원본이 아니라 함수 안의 복사본에 기록될 수 있다. 호출 후 외부에서 변경된 상태를 관찰하려면 전달 방식을 의도적으로 정해야 한다.

```cpp
template <std::size_t Size, typename Predicate>
const Item* FindItem(const std::array<Item, Size>& items, Predicate& predicate);
```

참조로 받으면 원본 함수 객체를 호출한다. 읽기 전용 조건이라면 `const Predicate&`도 가능하지만 비상수 호출 연산자를 가진 상태형 객체는 호출할 수 없다.

현대의 범용 라이브러리 코드는 전달된 값 범주와 복사 비용을 보존하는 전달 참조를 사용하기도 한다. 지금 단계에서는 콜백의 상태 변화가 호출자에게 보여야 하는지, 독립 복사본이어야 하는지를 먼저 구분한다.

## 함수 객체를 작업 명령으로 사용할 수 있다

원본의 `MoveTask`는 플레이어 ID와 목표 좌표를 보관하고 실행 시 이동 작업을 수행한다.

```cpp
class MoveTask
{
public:
    MoveTask(int playerId, int x, int y) : playerId_(playerId), x_(x), y_(y)
    {
    }

    void operator()() const
    {
        std::cout << "Move player " << playerId_ << " to (" << x_ << ", " << y_ << ")\n";
    }

private:
    int playerId_;
    int x_;
    int y_;
};
```

작업에 필요한 데이터를 생성 시점에 저장하고 나중에 실행한다.

```cpp
MoveTask task{100, 5, 0};
task();
```

```text
생성 시점  플레이어 ID와 목표 좌표 저장
대기       작업 객체를 큐나 컨테이너에 보관 가능
실행 시점  operator()를 호출해 저장된 명령 수행
```

네트워크 패킷 처리나 작업 큐에서 유용한 형태지만 실제 객체 주소를 저장한다면 작업 실행 시점까지 대상이 살아 있는지 확인해야 한다. ID를 저장하고 실행할 때 유효한 객체를 다시 찾는 방식은 댕글링 포인터 위험을 줄일 수 있다.

## 상태와 실행 결과를 분리하면 테스트하기 쉽다

`MoveTask`가 콘솔 출력만 수행하면 실제 좌표 변경을 검증하기 어렵다. 플레이어 상태를 명시적으로 전달받아 변경할 수 있다.

```cpp
struct PlayerState
{
    int id;
    int x;
    int y;
};

class MoveTo
{
public:
    MoveTo(int x, int y) : x_(x), y_(y)
    {
    }

    void operator()(PlayerState& player) const
    {
        player.x = x_;
        player.y = y_;
    }

private:
    int x_;
    int y_;
};
```

```cpp
PlayerState player{100, 0, 0};
MoveTo move{5, 2};
move(player);

assert(player.x == 5);
assert(player.y == 2);
```

작업 객체는 목표 좌표를 소유하고 실제 대상은 호출할 때 받는다. 하나의 작업 정책을 여러 플레이어에 적용할 수도 있고 테스트에서 출력 문자열 대신 상태 변화를 직접 검증할 수 있다.

## 함수 객체의 크기와 복사 비용은 상태에 따라 달라진다

상태가 없는 함수 객체는 데이터 멤버가 없지만 C++ 객체는 서로 다른 객체의 주소를 구분하는 등의 이유로 일반적으로 0바이트 크기가 되지는 않는다. 컴파일러와 라이브러리는 빈 기반 클래스 최적화나 `[[no_unique_address]]` 같은 기법으로 저장 비용을 줄일 수 있다.

상태를 가진 함수 객체는 저장한 멤버만큼 복사 비용과 수명 책임이 생긴다.

```cpp
class LargeTask
{
private:
    std::array<int, 1024> data_;
};
```

콜백을 값으로 여러 번 전달하면 큰 상태가 반복 복사될 수 있다. 반대로 참조를 저장하거나 전달하면 원본의 수명과 변경 가능성을 관리해야 한다. 크기만 보고 선택하지 말고 소유권, 호출 빈도와 상태 독립성까지 고려한다.

함수 객체의 호출 코드는 구체 타입이 컴파일 시점에 알려지면 인라인화될 가능성이 있지만 실제 최적화 여부는 컴파일러와 코드에 따라 달라진다. 함수 포인터보다 무조건 빠르다고 단정하지 않고 필요한 환경에서 측정한다.

## 전체 구현

상태를 가진 아이템 조건과 이동 작업을 함께 검증한다.

```cpp
#include <algorithm>
#include <array>
#include <cassert>
#include <iostream>

struct Item
{
    int id;
    int rarity;
    int ownerId;
};

class HasMinimumRarity
{
public:
    explicit HasMinimumRarity(int minimum) : minimum_(std::max(0, minimum))
    {
    }

    bool operator()(const Item& item) const
    {
        return item.rarity >= minimum_;
    }

private:
    int minimum_;
};

class IsOwnedBy
{
public:
    explicit IsOwnedBy(int ownerId) : ownerId_(ownerId)
    {
    }

    bool operator()(const Item& item) const
    {
        return item.ownerId == ownerId_;
    }

private:
    int ownerId_;
};

template <std::size_t Size, typename Predicate>
const Item* FindItem(const std::array<Item, Size>& items, Predicate predicate)
{
    for (const Item& item : items)
    {
        if (predicate(item))
        {
            return &item;
        }
    }

    return nullptr;
}

struct PlayerState
{
    int id;
    int x;
    int y;
};

class MoveTo
{
public:
    MoveTo(int x, int y) : x_(x), y_(y)
    {
    }

    void operator()(PlayerState& player) const
    {
        player.x = x_;
        player.y = y_;
    }

private:
    int x_;
    int y_;
};

void VerifyFunctionObjects()
{
    std::array<Item, 4> items{{{1, 1, 10}, {2, 3, 20}, {3, 4, 10}, {4, 2, 0}}};

    const Item* rareItem = FindItem(items, HasMinimumRarity{3});
    const Item* ownedItem = FindItem(items, IsOwnedBy{10});
    const Item* missingItem = FindItem(items, IsOwnedBy{99});

    assert(rareItem != nullptr && rareItem->id == 2);
    assert(ownedItem != nullptr && ownedItem->id == 1);
    assert(missingItem == nullptr);

    PlayerState player{100, 0, 0};
    MoveTo move{5, 2};
    move(player);

    assert(player.x == 5);
    assert(player.y == 2);

    std::cout << "Rare item ID: " << rareItem->id << '\n';
    std::cout << "Player position: (" << player.x << ", " << player.y << ")\n";
}

int main()
{
    VerifyFunctionObjects();
}
```

실행 결과는 다음과 같다.

```text
Rare item ID: 2
Player position: (5, 2)
```

`HasMinimumRarity{3}`과 `IsOwnedBy{10}`은 서로 다른 기준값을 각 객체에 저장한다. 같은 `FindItem`은 콜백의 구체 타입을 몰라도 `predicate(item)` 호출식만 사용한다.

`MoveTo`는 목표 좌표를 저장하고 실행할 때 전달된 플레이어 상태를 변경한다. 작업 객체가 플레이어 주소를 장기간 보관하지 않으므로 대상 수명과 작업 수명의 결합도 줄어든다.

## 함수 객체를 검토할 때 확인할 기준

1. `operator()`의 매개변수와 반환 타입이 사용하려는 호출식에 맞는가?
2. 상태를 전역 변수 대신 함수 객체 인스턴스에 보관할 수 있는가?
3. 읽기 전용 조건 함수에 `const` 호출 연산자를 제공하는가?
4. 호출 연산자 오버로드가 서로 자연스럽고 예상 가능한 의미를 가지는가?
5. 콜백을 값으로 복사할지 참조로 공유할지 의도적으로 정했는가?
6. 상태 변경이 원본 함수 객체에 보여야 하는가, 복사본에만 남아도 되는가?
7. 함수 객체가 저장한 포인터와 참조의 대상 수명이 충분히 긴가?
8. 객체 주소 대신 안정적인 ID나 실행 시점의 매개변수를 저장할 수 있는가?
9. 큰 상태를 가진 함수 객체가 불필요하게 반복 복사되지 않는가?
10. 단순한 함수나 분기로 충분한데 복잡한 함수 객체 계층을 만들고 있지 않은가?

함수 객체의 핵심은 함수 호출 모양을 흉내 내는 데 있지 않다. 나중에 실행할 동작과 그 동작에 필요한 상태를 하나의 값으로 묶어 독립적으로 전달하고 검증하는 데 있다.
