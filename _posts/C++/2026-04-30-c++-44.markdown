C++ 표현식에서는 서로 다른 타입의 값이 자주 만난다. 정수를 실수 변수에 저장할 때는 기본 타입 변환이 일어나고, 정수로 `Health` 객체를 만들 때는 생성자가 변환 경로로 사용될 수 있다.

타입 변환(Type conversion)은 단순히 값을 다른 크기의 바구니에 옮기는 작업이 아니다. 표현할 수 있는 값의 범위와 의미가 달라지며, 사용자 정의 타입에서는 클래스가 허용한 생성자와 변환 함수가 타입 사이의 관계를 결정한다.

## 암시적 변환과 명시적 변환은 의도 표현 방식의 차이다

컴파일러가 필요한 변환을 표현식 안에서 자동으로 적용하면 암시적 변환이다.

```cpp
int count = 10;
double preciseCount = count;
```

코드에 변환 의도를 직접 나타내면 명시적 변환이다.

```cpp
double ratio = 3.75;
int whole = static_cast<int>(ratio);
```

명시적이라고 해서 변환이 자동으로 안전해지는 것은 아니다. `double`에서 `int`로 바꾸면 소수 부분이 버려지고, 변환 후 값을 `int`가 표현할 수 없다면 올바른 결과를 기대할 수 없다.

```text
암시적·명시적  변환 의도를 코드에 어떻게 표현했는가?
안전·위험       변환 후 값과 프로그램 의미가 유지되는가?
```

두 기준을 별도로 판단해야 한다. 컴파일러가 허용한 암시적 변환에도 정보 손실이 있을 수 있고, 강제로 작성한 명시적 변환도 잘못될 수 있다.

## 숫자 타입의 크기만으로 안전성을 판단할 수 없다

작은 정수 타입에서 더 넓은 정수 타입으로 변환하면 원래 값을 표현할 수 있는 경우가 많다.

```cpp
int value = 123456789;
long long widened = value;
```

하지만 다음 변환들은 값을 바꿀 수 있다.

```cpp
int large = 123456789;
float approximate = large;
short narrowed = static_cast<short>(large);
unsigned int unsignedValue = static_cast<unsigned int>(-1);
```

- `int`에서 `float`로 변환하면 유효 자릿수 제한으로 정확한 정숫값을 잃을 수 있다.
- 넓은 정수 타입에서 좁은 정수 타입으로 변환하면 대상이 모든 값을 표현하지 못할 수 있다.
- 음의 정수를 부호 없는 타입으로 바꾸면 수학적으로 같은 음수 값이 유지되지 않는다.
- 부동소수점 값을 정수로 바꾸면 소수 부분이 0 방향으로 버려진다.

“작은 바구니에서 큰 바구니로 이동하면 항상 안전하다”는 설명도 타입의 부호와 표현 범위를 함께 보지 않으면 틀릴 수 있다. 실제 값이 대상 타입의 범위에 들어가는지 확인한다.

## 중괄호 초기화는 많은 축소 변환을 컴파일 단계에서 막는다

등호나 괄호를 사용하면 정보가 줄어드는 변환이 허용될 수 있다.

```cpp
double ratio = 3.75;
int truncated = ratio;
```

리스트 초기화는 축소 변환을 제한한다.

```cpp
// int rejected{ratio}; // double에서 int로 축소되므로 컴파일 오류
```

정보 손실이 의도된 경우에는 변환을 명시하고 범위 조건을 함께 확인한다.

```cpp
if (ratio >= 0.0 && ratio <= 100.0)
{
    int percentage = static_cast<int>(ratio);
}
```

중괄호가 모든 논리 오류를 막아 주는 것은 아니지만 의도하지 않은 축소 변환을 조기에 발견하는 데 도움이 된다.

## 변환 생성자는 다른 타입에서 현재 타입을 만든다

다른 타입의 인자로 `Health`를 만들 수 있는 생성자가 있다.

```cpp
class Health
{
public:
    Health(int value);
};
```

`explicit`가 없는 이 생성자는 직접 객체를 만드는 것뿐 아니라 정수에서 `Health`로 가는 암시적 변환에도 사용될 수 있다.

```cpp
Health first{100};
Health second = 100;
```

함수 호출에서도 임시 객체가 암시적으로 만들어질 수 있다.

```cpp
void PrintHealth(Health health);

PrintHealth(100);
```

이처럼 다른 타입의 인자를 이용해 현재 클래스 타입으로 변환될 수 있는 생성자를 변환 생성자(Converting constructor)라고 한다. 흔히 인자 하나를 받는 생성자로 배우지만, 기본 인자를 포함해 하나의 인자로 호출 가능한 생성자도 변환에 참여할 수 있다.

## explicit는 의도하지 않은 암시적 객체 생성을 막는다

정수와 체력 객체가 완전히 같은 의미가 아니라면 변환을 호출자가 명시하게 만드는 편이 안전하다.

```cpp
class Health
{
public:
    explicit Health(int value);
};
```

직접 초기화는 여전히 허용된다.

```cpp
Health first{100};
Health second(100);
```

암시적 변환과 복사 초기화는 허용되지 않는다.

```cpp
// Health third = 100;
// PrintHealth(100);
```

호출자는 객체 생성을 직접 표현해야 한다.

```cpp
PrintHealth(Health{100});
```

`explicit`는 생성자를 별도의 오버로드로 만들지 않는다. `Health(int)`와 `explicit Health(int)`를 함께 선언하면 같은 매개변수 목록의 생성자를 중복 선언한 것이다.

인자 하나를 받는 생성자는 기본적으로 `explicit`를 먼저 검토하고, 암시적 변환이 타입의 의미상 자연스럽고 오류 가능성을 낮출 때만 허용한다.

## 변환 함수는 현재 객체를 다른 타입의 값으로 만든다

클래스에서 다른 타입으로 나가는 변환도 정의할 수 있다.

```cpp
class Health
{
public:
    explicit operator int() const;
};
```

변환 함수(Conversion function)는 함수 이름 자리에 `operator`와 대상 타입을 적고 반환 타입을 따로 작성하지 않는다.

```cpp
Health::operator int() const
{
    return value_;
}
```

위 선언에는 `explicit`가 있으므로 정수로 자동 변환되지 않는다.

```cpp
Health health{80};
// int implicitValue = health;
int explicitValue = static_cast<int>(health);
```

단순히 내부 값을 읽는 목적이라면 이름이 있는 함수가 더 명확할 수도 있다.

```cpp
int Value() const;
```

변환 연산자는 대상 타입과 의미가 매우 자연스러울 때 사용하고, 단위 변경이나 정보 손실이 있다면 `ToSeconds`, `Value`처럼 의도가 드러나는 이름을 우선 검토한다.

## explicit operator bool은 조건식에서 자연스럽게 사용할 수 있다

객체가 유효한 상태인지 조건으로 확인하는 변환은 `bool`과 잘 맞을 수 있다.

```cpp
class Health
{
public:
    explicit operator bool() const
    {
        return value_ > 0;
    }
};
```

`explicit` 변환 함수지만 `if`, `while`, 논리 연산자처럼 문맥상 `bool`이 필요한 곳에서는 사용할 수 있다.

```cpp
Health health{50};

if (health)
{
    std::cout << "Alive\n";
}
```

반면 다른 숫자 타입으로 연쇄적인 암시적 변환이 일어나는 경로는 제한한다. 객체가 참인지 거짓인지만 제공하면서 정수처럼 취급되는 것을 막을 수 있다.

## 양쪽에 변환 경로를 무분별하게 추가하면 모호해진다

`Source`에서 `Target`을 만드는 생성자와 `Source`가 `Target`으로 변환되는 함수가 모두 같은 방향을 제공한다고 가정한다.

```cpp
class Target;

class Source
{
public:
    operator Target() const;
};

class Target
{
public:
    Target(const Source& source);
};
```

호출 상황에 따라 두 사용자 정의 변환 경로가 후보가 되어 모호한 표현식을 만들 수 있다. 타입 사이의 변환 책임을 어느 쪽에 둘지 정하고 필요한 방향만 제공한다.

원본 예제처럼 서로 관련 없는 `Knight`와 `Dog` 사이에 변환 생성자와 변환 연산자를 추가하면 문법적으로 변환할 수는 있다. 하지만 체력을 개의 나이로 옮기는 규칙이 도메인에서 자연스럽지 않다면 변환 자체를 제공하지 않는 편이 올바른 설계다.

## 잘못된 참조 캐스트는 값 변환이 아니다

원본에는 정수 객체를 실수 참조로 강제로 바라보는 코드가 있다.

```cpp
int number = 123456789;
// float& value = (float&)number;
```

이 코드는 정숫값을 의미가 같은 실숫값으로 계산해 바꾸지 않는다. `int` 객체의 저장 공간을 `float` 객체인 것처럼 접근하며 타입 별칭 규칙을 위반해 정의되지 않은 동작을 만들 수 있다.

서로 관련 없는 클래스 참조를 C 스타일 캐스트로 강제하는 코드도 실제 객체의 타입을 바꾸지 않는다.

```cpp
Knight knight;
// Dog& dog = (Dog&)knight;
```

강제된 참조를 통해 `Dog` 멤버에 접근하면 존재하지 않는 `Dog` 객체를 사용하게 된다. 명시적으로 캐스트를 작성했다는 사실은 객체를 대상 타입으로 만들어 주거나 안전성을 보장하지 않는다.

C 스타일 캐스트는 여러 종류의 변환을 한 문법에 숨긴다. 각 변환의 목적을 드러내는 C++ 명명 캐스트와 상속 관계의 안전한 변환은 이후 글에서 나눠 다룬다.

## 전체 구현

`Health`가 정수에서의 암시적 생성을 막고, 값과 생존 여부를 의도적으로 제공하는 예제다.

```cpp
#include <algorithm>
#include <cassert>
#include <iostream>

class Health
{
public:
    explicit Health(int value) : value_(std::clamp(value, 0, 100))
    {
    }

    int Value() const
    {
        return value_;
    }

    explicit operator int() const
    {
        return value_;
    }

    explicit operator bool() const
    {
        return value_ > 0;
    }

private:
    int value_;
};

void PrintHealth(Health health)
{
    std::cout << "HP: " << health.Value() << '\n';
}

void VerifyHealth()
{
    Health healthy{120};
    Health defeated{-10};

    assert(healthy.Value() == 100);
    assert(defeated.Value() == 0);
    assert(healthy);
    assert(!defeated);

    int rawValue = static_cast<int>(healthy);
    assert(rawValue == 100);

    PrintHealth(Health{70});

    // Health implicitHealth = 50;
    // PrintHealth(50);
    // int implicitValue = healthy;
}

int main()
{
    VerifyHealth();
}
```

실행 결과는 다음과 같다.

```text
HP: 70
```

120과 -10은 생성자 안에서 유효한 체력 범위인 0부터 100으로 제한된다. `explicit` 생성자 때문에 정수가 함수 호출 과정에서 몰래 `Health`로 바뀌지 않으며, 정숫값이 필요할 때도 변환 의도를 직접 작성한다.

`explicit operator bool` 덕분에 `assert(healthy)`와 조건문에서는 생존 여부를 자연스럽게 확인할 수 있지만 `Health` 객체를 일반 정수처럼 암시적으로 사용하는 것은 허용되지 않는다.

## 변환 코드를 검토할 때 확인할 기준

1. 변환 후에도 값의 의미와 범위가 유지되는가?
2. 암시적 변환에 정보 손실이나 예상하기 어려운 객체 생성이 없는가?
3. 축소 가능성이 있는 초기화에 중괄호를 사용할 수 있는가?
4. 인자 하나로 호출 가능한 생성자에 `explicit`가 필요한가?
5. 변환 연산자보다 이름이 있는 함수가 의도를 더 잘 드러내지 않는가?
6. 양쪽 타입이 같은 변환 방향을 중복 제공해 모호성을 만들지 않는가?
7. 관련 없는 타입 사이에 억지로 변환 경로를 추가하고 있지 않은가?
8. 명시적 캐스트를 작성했다는 이유만으로 안전하다고 판단하지 않는가?
9. 값 변환과 저장 공간을 다른 타입으로 해석하는 작업을 구분하는가?

타입 변환 설계의 목표는 가능한 변환을 최대한 늘리는 것이 아니다. 의미가 유지되는 경로만 열고, 정보 손실이나 도메인 규칙이 개입하는 변환은 호출자가 의도를 분명히 표현하게 만드는 것이다.
