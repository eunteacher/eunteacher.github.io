# [C++] 실수형 데이터와 부동 소수점의 원리

소수점이 있는 숫자(실수)를 컴퓨터가 저장하는 방식인 **부동 소수점(Floating Point)**의 개념과 메모리 구조(IEEE 754), 그리고 정밀도 문제에 대해 정리

---

## 1. 소스 코드 (Source Code)

`float`와 `double`의 선언과, 실수가 메모리에 어떻게 비트 단위로 저장되는지 분석한 코드

```cpp
#include <iostream>
using namespace std;

int main()
{
    // 실수형 데이터 타입
    // 3.14, 23.123 등 소수점이 있는 숫자
    float attackSpeed = 1.0f;       // 4바이트 (뒤에 f를 붙여 float임을 명시)
    double dashSpeed = 123.123;     // 8바이트 (기본 실수형)

    // 부동 소수점 원리
    // 3.1415926535... 를 어떻게 저장할까?
    // .을 유동적으로 움직여서 표현 (Floating Point)
    // 3.141592... = 0.3141592... * 10^1 = 314.1592... * 10^-2

    // 변환 실습: -3.375 저장하기
    // 목표: -3.375를 컴퓨터가 저장하는 2진수(IEEE 754)로 변환
    float Speed = -3.375f;

    // 1단계) 2진수 변환
    // 정수부: 3 -> 0b11
    // 소수부: 0.375 -> 0.5(x) + 0.25(o) + 0.125(o) -> 0b0.011
    // 합계: 0b11.011 (음수)

    // 2단계) 정규화 (Normalization)
    // 1.xxxx 형태가 되도록 소수점을 이동
    // 0b1.1011 * 2^1

    // 3단계) 메모리 비트 할당 (float 기준)
    // - 부호(1bit): 음수이므로 1
    // - 지수(8bit): 1(지수) + 127(Bias) = 128 -> 1000 0000
    // - 유효숫자(23bit): 소수점 뒤 1011 -> 1011000... (나머지 0 채움)

    // 예상 결과: 0b 1 10000000 10110000000000000000000

    // 주의사항
    // 실수는 '근사값'이다.
    // 특히 수가 커질수록 오차 범위도 커짐
    if (attackSpeed == 1.0f)
    {
        // 위험: 실수 2개를 등호(==)로 비교하는 것은 좋지 않음
    }

    return 0;
}
```

## 2. 이론 정리 (Study Notes)

### 1) 실수형 데이터 타입
정수와 달리 소수점을 표현하기 위해 사용되는 타입

* **float:** 4바이트 (32비트). 숫자 뒤에 `f`를 붙여서 초기화 (`3.14f`)
* **double:** 8바이트 (64비트). C++의 기본 실수 타입. `float`보다 정밀도가 훨씬 높음

### 2) 부동 소수점 (Floating Point)
소수점이 고정되어 있지 않고 둥둥 떠다닌다(Float)는 의미. 숫자를 **가수(유효숫자)**와 **지수(크기)**로 나누어 표현하는 방식

$$Value = (-1)^{Sign} \times 1.Mantissa \times 2^{Exponent-Bias}$$

* **구조 (IEEE 754 표준):**
  * **부호(Sign):** 양수(`0`) / 음수(`1`)
  * **지수(Exponent):** 소수점의 위치. `Unsigned Byte`로 취급하며 **Bias(127)**을 더해서 저장
  * **유효숫자(Mantissa):** 정규화된 소수점 아래 숫자들

### 3) 저장 구조 비교 (32bit vs 64bit)

| 타입 | 전체 크기 | 부호 | 지수 | 유효숫자 | Bias |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **float** | 32 bit | 1 bit | 8 bit | 23 bit | 127 |
| **double** | 64 bit | 1 bit | 11 bit | 52 bit | 1023 |

### 4) 변환 실습 상세 (-3.375)
코드 주석에 있는 `-3.375`가 메모리에 저장되는 과정

1.  **2진수 변환:** `3`(`11`) + `0.375`(`0.011`) = **`11.011`**
2.  **정규화 (Normalization):** 가장 앞의 1 바로 뒤로 소수점 이동
  * `1.1011` $\times$ $2^1$
3.  **값 채우기:**
  * **부호:** 음수니까 **1**
  * **지수:** 실제 지수(`1`) + Bias(`127`) = `128` -> **1000 0000**
  * **유효숫자:** 소수점 뒤 `1011`을 넣고 나머지는 0으로 채움 -> **1011000...**

## 3. 종합 의견 (Review)

* **실수는 근사값(Approximate):** 컴퓨터는 `0.1` 같은 숫자를 2진수로 완벽하게 표현할 수 없음 (무한 소수가 됨). 따라서 실수는 **정확한 값이 아닌 근사값**으로 저장됨을 명심해야 함
* **비교 연산 주의:** 실수 두 개를 `==` 로 비교하는 것은 매우 위험. `attackSpeed == 1.0f`가 `false`가 나올 수도 있음
  * **해결책:** 두 수의 차이가 아주 작은 값(**Epsilon**)보다 작은지로 판단해야 함 (`abs(a - b) < epsilon`)
* **성능:** 과거에는 `float`가 빨랐으나, 최신 CPU는 `double` 연산에 최적화되어 있어 속도 차이가 미미함. 메모리가 부족한 게 아니라면 정밀도가 높은 `double` 사용을 권장하는 추세
