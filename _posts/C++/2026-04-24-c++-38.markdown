클래스는 데이터와 함수를 한곳에 모으는 것만으로 완성되지 않는다. 외부 코드가 모든 데이터에 직접 접근할 수 있다면 객체가 지켜야 할 규칙을 우회할 수 있기 때문이다.

은닉성(Data hiding)은 외부에서 알 필요가 없는 구현을 감추고, 캡슐화(Encapsulation)는 서로 관련된 상태와 동작을 하나의 경계 안에 묶는다. 두 개념을 이용하면 객체가 허용한 인터페이스를 통해서만 상태가 바뀌게 만들 수 있다.

## 자동차 사용자는 엔진 내부를 직접 조작하지 않는다

자동차를 운전할 때 운전자는 핸들, 페달, 시동 장치처럼 공개된 조작 방법을 사용한다. 엔진 배선이나 분해 과정까지 직접 다룰 필요는 없다.

```cpp
class Car
{
public:
    void TurnKey();
    void PushPedal();
    void OpenDoor();

private:
    void RunEngine();
    void ConnectCircuit();
};
```

외부 코드는 공개 인터페이스인 `TurnKey`를 호출한다.

```cpp
Car car;
car.TurnKey();
```

`TurnKey`는 내부에서 필요한 순서에 따라 엔진을 작동시킨다.

```cpp
void Car::TurnKey()
{
    ConnectCircuit();
    RunEngine();
}
```

호출자는 내부 절차를 알 필요가 없고, 클래스는 잘못된 호출 순서를 막을 수 있다. 내부 구현이 바뀌더라도 공개 인터페이스가 유지되면 사용하는 코드에 미치는 영향도 줄어든다.

## 접근 지정자는 사용할 수 있는 코드의 범위를 정한다

C++ 클래스는 `public`, `protected`, `private` 접근 지정자를 제공한다.

```text
public     클래스 외부에서도 접근 가능
protected  해당 클래스와 파생 클래스의 멤버 등에서 접근 가능
private    해당 클래스의 멤버 등에서만 접근 가능
```

`protected`와 `private` 모두 일반 외부 코드에서는 접근할 수 없다. 차이는 파생 클래스가 직접 접근할 수 있는지에 있다.

```cpp
class Car
{
protected:
    void RunEngine();

private:
    void ConnectCircuit();
};

class SuperCar : public Car
{
public:
    void StartRemotely()
    {
        RunEngine();
        // ConnectCircuit(); // Car의 private 멤버이므로 직접 접근할 수 없음
    }
};
```

접근 지정자는 객체 안의 메모리를 보안 장치처럼 보호하는 기능이 아니다. 컴파일 과정에서 허용되지 않은 이름 접근을 막는 언어 규칙이다. 잘못된 코드 경로를 인터페이스 차원에서 제한하는 데 목적이 있다.

## class와 struct는 기본 접근 수준이 다르다

접근 지정자를 생략했을 때 `class`의 멤버는 기본적으로 `private`다.

```cpp
class Knight
{
    int hp_; // private
};
```

`struct`의 멤버는 기본적으로 `public`이다.

```cpp
struct Position
{
    int x; // public
    int y; // public
};
```

이 차이 외에도 `class`와 `struct`는 멤버 함수, 생성자와 상속 같은 기능을 모두 사용할 수 있다. 단순한 데이터 묶음에는 `struct`, 내부 규칙을 가진 객체에는 `class`를 사용하는 관례가 있지만 언어가 용도를 강제하지는 않는다.

## 데이터 멤버를 감추면 상태 변경 경로를 통제할 수 있다

체력이 0부터 최대 체력 사이여야 하는 클래스에서 체력을 공개하면 외부 코드가 규칙을 깨뜨릴 수 있다.

```cpp
class Berserker
{
public:
    int hp_ = 100;
};

Berserker berserker;
berserker.hp_ = -500;
```

데이터를 `private`으로 두고 상태를 바꾸는 동작을 제공하면 검사와 후속 처리를 한곳에 모을 수 있다.

```cpp
class Berserker
{
public:
    explicit Berserker(int maxHp);

    void TakeDamage(int damage);
    void Heal(int amount);
    int Hp() const;

private:
    void UpdateBerserkerMode();

    int hp_;
    int maxHp_;
    bool isBerserkerMode_;
};
```

이제 외부 코드는 `hp_`를 직접 대입하지 않고 의미가 드러나는 동작을 요청한다.

```cpp
berserker.TakeDamage(60);
berserker.Heal(20);
```

음수 피해 무시, 체력 범위 제한, 버서커 모드 갱신 같은 규칙은 클래스 내부에서 일관되게 처리할 수 있다.

## Getter와 Setter를 기계적으로 만들 필요는 없다

멤버를 `private`으로 바꾼 뒤 모든 멤버에 읽기·쓰기 함수를 그대로 추가하면 사실상 공개 데이터와 크게 다르지 않을 수 있다.

```cpp
int Hp() const;
void SetHp(int hp);
```

현재 체력을 보여줄 필요가 있다면 읽기 함수만 제공할 수 있다. 체력 변경은 `SetHp`보다 게임 규칙이 드러나는 동작으로 표현할 수 있다.

```cpp
int Hp() const;
void TakeDamage(int damage);
void Heal(int amount);
```

이 인터페이스는 호출 의도를 분명히 하고 각 상황에 맞는 규칙을 클래스가 적용하게 한다. Getter와 Setter는 반드시 한 쌍으로 존재해야 하는 문법이 아니다. 외부 코드에 실제로 필요한 권한만 제공한다.

## 버서커 모드는 값이 아니라 상태 전이로 다룬다

원본 예제는 체력이 50 이하일 때마다 버서커 모드 함수를 호출한다.

```cpp
void SetHp(int hp)
{
    hp_ = hp;

    if (hp_ <= 50)
    {
        SetBerserkerMode();
    }
}
```

이 코드는 체력이 이미 50 이하인데 다시 피해를 받으면 모드 진입 처리를 반복한다. 모드의 활성 여부를 상태로 저장하면 경계를 통과하는 순간을 구분할 수 있다.

```cpp
void Berserker::UpdateBerserkerMode()
{
    const bool shouldEnable = hp_ > 0 && hp_ <= maxHp_ / 2;

    if (shouldEnable == isBerserkerMode_)
    {
        return;
    }

    isBerserkerMode_ = shouldEnable;
    std::cout << (isBerserkerMode_ ? "Berserker mode enabled\n" : "Berserker mode disabled\n");
}
```

체력이 절반 이하로 내려가면 한 번 활성화되고, 회복해서 절반을 초과하면 비활성화된다. 객체가 상태와 전이 규칙을 함께 소유하므로 외부 코드마다 같은 조건문을 반복하지 않아도 된다.

## 상속 접근 지정자는 물려받은 인터페이스의 공개 수준을 바꾼다

클래스를 상속할 때 적는 `public`, `protected`, `private`는 멤버 접근 지정자와 역할이 다르다.

```cpp
class PublicCar : public Car
{
};

class PrivateCar : private Car
{
};
```

기반 클래스의 `private` 멤버는 어떤 상속 방식을 사용해도 파생 클래스가 직접 접근할 수 없다. 접근 가능한 기반 멤버의 수준은 다음처럼 바뀐다.

```text
public 상속:    public → public,    protected → protected
protected 상속: public → protected, protected → protected
private 상속:   public → private,   protected → private
```

일반적인 is-a 관계는 `public` 상속으로 표현한다. `private` 상속은 기반 구현을 이용하지만 외부에 기반 타입과의 관계를 공개하지 않으므로 공개 상속과 의미가 다르다. 단순 구현 재사용이 목적이라면 멤버 객체를 통한 포함이 더 명확한지도 함께 검토한다.

## 전체 구현

체력의 유효 범위와 버서커 모드 전환을 클래스 내부에서 관리하는 예제다.

```cpp
#include <algorithm>
#include <cassert>
#include <iostream>

class Berserker
{
public:
    explicit Berserker(int maxHp);

    void TakeDamage(int damage);
    void Heal(int amount);
    int Hp() const;
    int MaxHp() const;
    bool IsBerserkerMode() const;

private:
    void UpdateBerserkerMode();

    int hp_;
    int maxHp_;
    bool isBerserkerMode_;
};

Berserker::Berserker(int maxHp) : hp_(std::max(1, maxHp)), maxHp_(std::max(1, maxHp)), isBerserkerMode_(false)
{
}

void Berserker::TakeDamage(int damage)
{
    if (damage <= 0)
    {
        return;
    }

    hp_ = damage >= hp_ ? 0 : hp_ - damage;
    UpdateBerserkerMode();
}

void Berserker::Heal(int amount)
{
    if (amount <= 0)
    {
        return;
    }

    hp_ = amount >= maxHp_ - hp_ ? maxHp_ : hp_ + amount;
    UpdateBerserkerMode();
}

int Berserker::Hp() const
{
    return hp_;
}

int Berserker::MaxHp() const
{
    return maxHp_;
}

bool Berserker::IsBerserkerMode() const
{
    return isBerserkerMode_;
}

void Berserker::UpdateBerserkerMode()
{
    const bool shouldEnable = hp_ > 0 && hp_ <= maxHp_ / 2;

    if (shouldEnable == isBerserkerMode_)
    {
        return;
    }

    isBerserkerMode_ = shouldEnable;
    std::cout << (isBerserkerMode_ ? "Berserker mode enabled\n" : "Berserker mode disabled\n");
}

void VerifyBerserker()
{
    Berserker berserker{100};
    assert(berserker.Hp() == 100);
    assert(berserker.MaxHp() == 100);
    assert(!berserker.IsBerserkerMode());

    berserker.TakeDamage(49);
    assert(berserker.Hp() == 51);
    assert(!berserker.IsBerserkerMode());

    berserker.TakeDamage(1);
    assert(berserker.Hp() == 50);
    assert(berserker.IsBerserkerMode());

    berserker.TakeDamage(10);
    assert(berserker.Hp() == 40);
    assert(berserker.IsBerserkerMode());

    berserker.Heal(11);
    assert(berserker.Hp() == 51);
    assert(!berserker.IsBerserkerMode());

    berserker.Heal(1000);
    assert(berserker.Hp() == 100);
}

int main()
{
    VerifyBerserker();
}
```

외부 코드는 체력을 직접 변경할 수 없다. `TakeDamage`와 `Heal`이 입력을 검사하고 체력을 `0`부터 `maxHp_` 사이로 유지하며, 변경이 끝날 때마다 모드 전이를 확인한다.

검증 코드에서는 단순한 최종 체력뿐 아니라 경계값인 50에서 모드가 활성화되는지, 이미 활성화된 상태에서 처리가 반복되지 않는지, 회복 후 다시 비활성화되는지를 확인한다.

## 클래스의 경계를 검토할 때 확인할 기준

1. 외부 코드가 데이터 멤버를 직접 변경해야 할 이유가 있는가?
2. 객체가 항상 지켜야 하는 상태 조건은 무엇인가?
3. 상태를 변경하는 모든 경로에서 같은 검사가 실행되는가?
4. 단순한 Setter보다 의도가 드러나는 동작을 제공할 수 있는가?
5. 읽기 권한만 필요할 때 불필요한 쓰기 함수를 공개하지 않았는가?
6. 파생 클래스가 내부 표현에 지나치게 의존하도록 `protected` 데이터를 노출하지 않았는가?
7. 공개 인터페이스와 내부 구현의 역할이 명확히 나뉘는가?
8. 비공개 상속보다 포함 관계가 더 자연스럽지 않은가?

은닉성은 멤버 앞에 `private`를 붙이는 작업으로 끝나지 않는다. 외부에 어떤 동작을 허용할지 결정하고, 객체의 상태가 그 경로를 통해서만 바뀌도록 경계를 설계하는 과정이다.
