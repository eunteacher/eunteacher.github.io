함수 템플릿은 타입마다 반복되는 알고리즘을 하나의 규칙으로 만들었다. 저장할 데이터 타입에 따라 클래스 전체의 멤버 타입과 인터페이스가 달라져야 한다면 클래스 템플릿(Class template)을 사용할 수 있다.

클래스 템플릿은 타입뿐 아니라 컴파일 시점에 결정되는 값도 매개변수로 받을 수 있다. 이번 글에서는 `FixedBox<T, Size>`를 만들어 요소 타입과 고정 크기를 실제 저장 공간에 연결하고, 원본 `RandomBox`의 배열 범위 오류와 부분 특수화를 함께 살펴본다.

## 클래스 정의에서 달라지는 타입을 매개변수로 만든다

정수 상자와 실수 상자의 구조가 같고 요소 타입만 다르다고 가정한다.

```cpp
class IntBox
{
private:
    int data_[10];
};

class FloatBox
{
private:
    float data_[10];
};
```

요소 타입을 템플릿 매개변수 `T`로 바꾼다.

```cpp
template <typename T>
class Box
{
private:
    T data_[10]{};
};
```

사용할 때 구체 타입을 지정한다.

```cpp
Box<int> integerBox;
Box<float> floatBox;
```

`Box<int>`와 `Box<float>`는 같은 클래스 템플릿에서 만들어지지만 서로 다른 타입이다.

```cpp
// integerBox = floatBox; // 서로 다른 클래스 타입
```

클래스 템플릿은 실행 중 한 객체의 타입이 바뀌는 기능이 아니다. 컴파일 시점에 템플릿 인자 조합마다 구체 클래스 타입이 형성된다.

## 비타입 템플릿 매개변수는 컴파일 시점의 값을 받는다

고정 배열의 크기도 템플릿 인자로 받는다.

```cpp
template <typename T, std::size_t Size>
class FixedBox
{
private:
    T data_[Size]{};
};
```

`T`는 타입 템플릿 매개변수이고 `Size`는 비타입 템플릿 매개변수(Non-type template parameter)다.

```cpp
FixedBox<int, 10> smallBox;
FixedBox<int, 100> largeBox;
FixedBox<double, 10> preciseBox;
```

세 선언은 모두 서로 다른 타입을 만든다.

```text
FixedBox<int, 10>
FixedBox<int, 100>
FixedBox<double, 10>
```

`Size`는 클래스의 타입 일부이므로 실행 중 입력값을 그대로 사용할 수 없다.

```cpp
std::size_t size = ReadSize();
// FixedBox<int, size> box; // size는 컴파일 시간 상수가 아님
```

크기가 실행 중 결정돼야 한다면 `std::vector<T>` 같은 동적 크기 컨테이너가 더 자연스럽다.

## 크기 인자를 실제 저장 공간에 사용해야 한다

원본 `RandomBox`는 `SIZE`를 받지만 배열 크기는 10으로 고정한다.

```cpp
template <typename T, int SIZE>
class RandomBox
{
public:
    T GetRandomData()
    {
        int index = rand() % SIZE;
        return data_[index];
    }

private:
    T data_[10];
};
```

`RandomBox<float, 20>`에서는 인덱스가 0부터 19까지 나올 수 있지만 유효한 배열 범위는 0부터 9까지다.

```text
SIZE: 20
실제 요소 수: 10
가능 인덱스: 0~19
유효 인덱스: 0~9
```

10 이상으로 접근하면 배열 범위를 벗어나 정의되지 않은 동작이 발생한다. 템플릿 인자를 실제 배열 크기에 연결해야 한다.

```cpp
template <typename T, std::size_t Size>
class FixedBox
{
private:
    std::array<T, Size> data_{};
};
```

이제 저장 공간의 요소 수와 인덱스 계산에 사용하는 `Size`가 하나의 값에서 나온다.

## 0 크기를 허용할지 클래스 계약으로 결정한다

`std::array<T, 0>` 자체는 사용할 수 있지만 무작위 요소를 반환하는 상자는 요소가 하나 이상 있어야 한다.

```cpp
template <typename T, std::size_t Size>
class FixedBox
{
    static_assert(Size > 0, "FixedBox requires at least one element");
};
```

잘못된 타입은 컴파일 시점에 거부된다.

```cpp
// FixedBox<int, 0> emptyBox;
```

`static_assert`는 실행 중 조건문이 아니다. 해당 템플릿 인자 조합으로 클래스를 인스턴스화할 때 조건을 검사한다.

C++20에서는 템플릿 자체에 제약을 표현할 수도 있다.

```cpp
template <typename T, std::size_t Size>
requires (Size > 0)
class FixedBox;
```

두 방식 중 프로젝트의 표준 버전과 오류 메시지 가독성에 맞는 방식을 선택한다.

## std::array로 크기와 배열 인터페이스를 함께 보관한다

원시 배열 대신 `std::array`를 멤버로 사용한다.

```cpp
#include <array>

template <typename T, std::size_t Size>
class FixedBox
{
public:
    constexpr std::size_t SizeValue() const
    {
        return Size;
    }

private:
    std::array<T, Size> data_{};
};
```

`std::array<T, Size>`도 타입과 크기를 템플릿 인자로 받는 표준 클래스 템플릿이다. 고정 크기 배열을 감싸면서 반복자, `size`, `at` 같은 컨테이너 인터페이스를 제공한다.

`Size`는 객체마다 저장되는 일반 데이터 멤버가 아니다. 타입에 포함된 컴파일 시간 값이므로 다음처럼 정적 상수로 공개할 수도 있다.

```cpp
static constexpr std::size_t size = Size;
```

```cpp
static_assert(FixedBox<int, 10>::size == 10);
```

## 인덱스 접근의 검사 정책을 구분한다

검사 없는 접근과 검사하는 접근을 다른 함수로 제공할 수 있다.

```cpp
T& operator[](std::size_t index)
{
    return data_[index];
}

const T& operator[](std::size_t index) const
{
    return data_[index];
}
```

`operator[]`는 호출자가 유효한 인덱스를 전달한다는 전제를 가진다. 범위를 검사하려면 `at`을 사용한다.

```cpp
T& At(std::size_t index)
{
    return data_.at(index);
}

const T& At(std::size_t index) const
{
    return data_.at(index);
}
```

`std::array::at`은 범위를 벗어나면 `std::out_of_range` 예외를 던진다. 검사 여부를 함수 이름과 인터페이스에서 구분하면 호출자가 요구에 맞는 방식을 선택할 수 있다.

어느 방식을 사용해도 배열의 수명과 유효 인덱스 규칙이 사라지는 것은 아니다. 성능 차이가 중요하다면 실제 호출 환경과 최적화 결과를 측정한다.

## const 객체에는 const 참조를 반환한다

수정 가능한 상자는 요소를 수정할 수 있는 참조를 반환한다.

```cpp
T& At(std::size_t index)
{
    return data_.at(index);
}
```

상자가 `const`라면 읽기 전용 참조를 반환한다.

```cpp
const T& At(std::size_t index) const
{
    return data_.at(index);
}
```

```cpp
FixedBox<int, 3> box;
box.At(0) = 10;

const FixedBox<int, 3>& readOnlyBox = box;
int value = readOnlyBox.At(0);
// readOnlyBox.At(0) = 20; // const 요소 참조이므로 수정 불가
```

값으로 반환하면 큰 요소가 복사될 수 있고 원본 요소를 수정할 수도 없다. 컨테이너 성격의 클래스는 객체의 `const` 상태에 맞춰 참조 반환 오버로드를 제공하는 경우가 많다.

## 무작위 선택에는 인덱스 범위를 정확히 맞춘다

요소가 `Size`개라면 유효한 인덱스는 0부터 `Size - 1`이다.

```cpp
const T& RandomElement(std::mt19937& engine) const
{
    std::uniform_int_distribution<std::size_t> distribution(0, Size - 1);
    return data_[distribution(engine)];
}
```

난수 엔진은 외부에서 참조로 받는다. 함수 안에서 매번 현재 시간으로 시드를 만들지 않으므로 호출자가 재현 가능한 시드를 선택할 수 있다.

```cpp
std::mt19937 engine{12345};
const int& selected = box.RandomElement(engine);
```

같은 표준 라이브러리 구현과 같은 엔진 상태에서는 디버깅 중 선택 흐름을 재현하기 쉽다. 다만 `std::uniform_int_distribution`이 엔진 값을 결과에 매핑하는 정확한 방식까지 모든 표준 라이브러리 구현에서 동일하다고 가정하지 않는다.

검증에서는 특정 값 하나를 고정적으로 기대하기보다 반환된 참조가 상자 요소 중 하나인지 확인할 수 있다.

## 클래스 밖에서 멤버를 정의할 때 템플릿 정보를 반복한다

멤버 함수를 클래스 밖에 정의하려면 템플릿 매개변수 선언과 구체 클래스 표기를 함께 작성한다.

```cpp
template <typename T, std::size_t Size>
T& FixedBox<T, Size>::At(std::size_t index)
{
    return data_.at(index);
}
```

반환 타입, 클래스 이름과 매개변수에서 템플릿 매개변수를 사용할 수 있다.

```text
template <typename T, std::size_t Size>  템플릿 매개변수 선언
FixedBox<T, Size>::                       멤버가 속한 구체 클래스 패턴
```

클래스 템플릿의 정의도 사용하는 번역 단위에서 보여야 하는 경우가 일반적이므로 멤버 정의를 헤더에 두거나 헤더에서 별도 구현 파일을 포함하는 방식을 사용한다.

## 클래스 템플릿은 타입 추론 방식이 함수와 다르다

함수 템플릿은 호출 인자에서 타입을 자연스럽게 추론했다. 클래스 템플릿은 일반적으로 템플릿 인자를 직접 적는다.

```cpp
FixedBox<int, 5> box;
```

C++17부터 생성자 인자와 추론 가이드로 클래스 템플릿 인자 추론(CTAD)을 사용할 수 있는 경우가 있다.

```cpp
std::array values{1, 2, 3}; // std::array<int, 3>으로 추론
```

하지만 기본 생성만 하는 `FixedBox box;`에서는 `T`와 `Size`를 알아낼 정보가 없다.

```cpp
// FixedBox box; // T와 Size를 추론할 수 없음
```

추론이 가능하다는 사실과 명시적인 타입이 읽기 쉬운지는 별개다. 고정 크기 버퍼처럼 타입과 크기가 설계의 핵심이면 `FixedBox<int, 10>` 표기가 의도를 분명히 보여준다.

## 전체 특수화와 부분 특수화를 구분한다

기본 클래스 템플릿이 있다.

```cpp
template <typename T, std::size_t Size>
class FixedBox;
```

모든 템플릿 인자를 특정 조합으로 고정하면 전체 특수화다.

```cpp
template <>
class FixedBox<bool, 8>
{
    // bool 8개 조합에만 적용되는 구현
};
```

일부만 고정하고 나머지 매개변수를 유지하면 부분 특수화다.

```cpp
template <std::size_t Size>
class FixedBox<double, Size>
{
    // 모든 Size의 double 상자에 적용되는 구현
};
```

원본의 `RandomBox<double, SIZE>`는 `SIZE`가 여전히 매개변수이므로 “템플릿 특수화” 중에서도 부분 특수화다.

부분 특수화는 기본 템플릿 전체를 대체한다. 저장 배열, 범위 검사와 생성자 같은 코드를 다시 작성하면 기본 템플릿 수정이 특수화에 반영되지 않을 수 있다. 단순히 `double`일 때 로그 하나를 추가하려는 목적이라면 클래스 전체 부분 특수화는 중복이 크다.

공통 저장 구조는 그대로 두고 타입별 작은 동작을 별도 정책 함수나 오버로드로 분리하는 방법을 먼저 검토한다.

## 원본의 double 부분 특수화도 같은 범위 오류를 반복한다

원본 특수화에서도 배열은 10개지만 인덱스는 `SIZE`를 사용한다.

```cpp
template <int SIZE>
class RandomBox<double, SIZE>
{
private:
    double data_[10];
};
```

특수화는 기본 템플릿의 멤버를 상속하거나 자동 복사하지 않는다. 완전히 별도의 클래스 정의이므로 같은 버그가 반복된다.

또한 원본 `main`에는 같은 스코프에서 다음 이름을 두 번 선언하는 컴파일 오류가 있다.

```cpp
float value2 = floatBox.GetRandomData();
double value2 = doubleBox.GetRandomData(); // 같은 이름 재선언
```

변수 이름을 `floatValue`, `doubleValue`처럼 역할에 맞게 분리한다. 템플릿이 여러 타입의 코드를 만들어 주더라도 일반 C++의 이름 범위 규칙은 그대로 적용된다.

## 타입 별칭으로 자주 쓰는 조합에 이름을 붙인다

자주 사용하는 템플릿 인자 조합은 별칭으로 표현할 수 있다.

```cpp
using ItemIds = FixedBox<int, 100>;
using PartyNames = FixedBox<std::string, 4>;
```

```cpp
ItemIds itemIds;
PartyNames partyNames;
```

별칭은 새로운 클래스 정의가 아니라 해당 템플릿 특수화의 다른 이름이다. 도메인에서 크기 100과 4가 의미 있는 고정 정책이라면 매번 숫자를 반복하는 것보다 의도를 드러낼 수 있다.

크기 정책이 자주 바뀌거나 실행 설정에 따라 달라진다면 컴파일 시간 크기로 고정하는 것이 맞는지 다시 검토한다.

## 전체 구현

타입과 크기가 실제 저장 공간에 반영되는 고정 상자를 구현한다.

```cpp
#include <array>
#include <cassert>
#include <cstddef>
#include <iostream>
#include <random>
#include <stdexcept>
#include <string>

template <typename T, std::size_t Size>
class FixedBox
{
    static_assert(Size > 0, "FixedBox requires at least one element");

public:
    static constexpr std::size_t size = Size;

    T& operator[](std::size_t index)
    {
        return data_[index];
    }

    const T& operator[](std::size_t index) const
    {
        return data_[index];
    }

    T& At(std::size_t index)
    {
        return data_.at(index);
    }

    const T& At(std::size_t index) const
    {
        return data_.at(index);
    }

    const T& RandomElement(std::mt19937& engine) const
    {
        std::uniform_int_distribution<std::size_t> distribution(0, Size - 1);
        return data_[distribution(engine)];
    }

private:
    std::array<T, Size> data_{};
};

using ItemIds = FixedBox<int, 5>;
using PartyNames = FixedBox<std::string, 3>;

void VerifyFixedBox()
{
    ItemIds itemIds;
    static_assert(ItemIds::size == 5);

    for (std::size_t index = 0; index < ItemIds::size; ++index)
    {
        itemIds[index] = static_cast<int>(100 + index);
    }

    assert(itemIds.At(0) == 100);
    assert(itemIds.At(4) == 104);

    bool caughtOutOfRange = false;
    try
    {
        static_cast<void>(itemIds.At(5));
    }
    catch (const std::out_of_range&)
    {
        caughtOutOfRange = true;
    }
    assert(caughtOutOfRange);

    std::mt19937 engine{12345};
    const int* selected = &itemIds.RandomElement(engine);
    assert(selected >= &itemIds[0] && selected <= &itemIds[4]);

    PartyNames names;
    names[0] = "Knight";
    names[1] = "Archer";
    names[2] = "Mage";

    assert(names.At(1) == "Archer");

    std::cout << "Item box size: " << ItemIds::size << '\n';
    std::cout << "Party size: " << PartyNames::size << '\n';
    std::cout << "Second party member: " << names.At(1) << '\n';
}

int main()
{
    VerifyFixedBox();
}
```

실행 결과는 다음과 같다.

```text
Item box size: 5
Party size: 3
Second party member: Archer
```

`ItemIds`의 저장 공간과 반복 범위는 모두 크기 5를 사용한다. `At(5)`는 유효 범위를 벗어나므로 `std::out_of_range`가 발생하고 예제에서 이를 확인한다.

무작위 요소의 정확한 값은 출력에 고정하지 않는다. 반환된 참조 주소가 `itemIds`의 첫 요소부터 마지막 요소 사이에 있는지 확인해 유효한 요소를 선택했다는 조건을 검증한다.

`PartyNames`는 같은 클래스 템플릿에 `std::string`과 크기 3을 전달한 별도 타입이다. 클래스 구현을 복사하지 않고 서로 다른 요소 타입과 크기의 저장소를 만든다.

## 클래스 템플릿을 검토할 때 확인할 기준

1. 타입에 따라 클래스의 저장 구조와 동작이 실제로 같은 패턴인가?
2. 비타입 템플릿 크기가 실제 배열과 모든 인덱스 계산에 일관되게 사용되는가?
3. 0이나 허용하지 않을 값 조합을 컴파일 시점에 막는가?
4. 실행 중 바뀌는 크기를 템플릿 인자로 억지로 고정하고 있지 않은가?
5. 검사 없는 `operator[]`와 검사하는 `At`의 계약을 구분하는가?
6. `const` 객체 접근이 수정 가능한 참조를 노출하지 않는가?
7. 난수 범위가 정확히 `0`부터 `Size - 1`인가?
8. 클래스 밖 멤버 정의에 템플릿 매개변수와 클래스 인자를 빠뜨리지 않았는가?
9. 부분 특수화가 공통 구현을 복제해 버그 수정 경로를 나누지 않는가?
10. 자주 쓰는 조합에 별칭을 붙이는 것이 도메인 의미를 더 명확하게 만드는가?

클래스 템플릿의 목표는 비슷한 클래스를 무조건 하나로 합치는 것이 아니다. 타입과 컴파일 시간 값에 따라 달라지는 부분을 매개변수로 만들고, 저장 공간과 인터페이스가 그 인자와 끝까지 일관되게 연결되도록 하는 것이다.
