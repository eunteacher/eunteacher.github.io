# [C++] 배열(Array)의 메모리 구조와 포인터 연산의 이해

동일한 타입의 데이터를 연속된 메모리에 할당하여 관리하는 배열의 기초 문법과 배열 이름이 포인터로 붕괴(Decay)되는 원리를 분석

## 1. 소스 코드 (Source Code)

```cpp
#include <iostream>
using namespace std;

// 게임 캐릭터의 스탯을 관리하는 구조체 정의
struct FStat
{
    int hp = 0xAAAAAAAA;
    int attack = 0xBBBBBBBB;
    int defence = 0xDDDDDDDD;
};

int main()
{
    // 1. 배열의 선언
    // 배열의 크기는 반드시 컴파일 타임에 결정되는 상수(const)여야 함
    const int monsterCount = 10;
    FStat monsters[monsterCount];

    // 2. 배열 이름과 포인터의 관계
    // 배열의 이름은 해당 배열이 할당된 메모리의 '시작 주소'를 의미함
    // 즉, 내부적으로는 배열의 첫 번째 요소를 가리키는 포인터(FStat*)로 취급됨
    auto WhoAmI = monsters;
    FStat* monster_0 = monsters;

    monster_0->hp = 100;
    monster_0->attack = 10;
    monster_0->defence = 1;

    // 3. 포인터 산술 연산을 통한 배열 요소 접근
    // 포인터에 +1을 하면 지정된 타입(FStat)의 크기만큼 메모리 주소가 이동함
    FStat* monster_1 = monsters + 1;
    monster_1->hp = 200;
    monster_1->attack = 20;
    monster_1->defence = 2;

    // 4. 포인터와 참조(Reference)의 상호 변환
    // *(monsters + 2) 연산을 통해 3번째 요소의 원본에 접근하고 참조자를 부여함
    FStat& monster_2 = *(monsters + 2);
    monster_2.hp = 300;
    monster_2.attack = 30;
    monster_2.defence = 3;

    // [주의] 참조(&) 연산자 없이 대입하면 원본이 아닌 값의 '복사본'이 생성됨
    FStat temp = *(monsters + 2);
    temp.hp = 999; // 원본 배열(monsters)의 데이터는 변하지 않음

    // 5. 인덱스(Index) 연산자를 활용한 순회
    // 배열은 0번 인덱스부터 시작하며, arr[i]는 *(arr + i)와 완전히 동일한 연산임
    monsters[0].hp = 100;
    monsters[0].attack = 10;
    monsters[0].defence = 1;

    for (int i = 0; i < 10; i++)
    {
        monsters[i].hp = 100 * (i + 1);
        monsters[i].attack = 10 * (i + 1);
        monsters[i].defence = 1 * (i + 1);
    }

    // 6. 배열의 초기화 문법
    int numbers[5] = {};                                // 모든 요소를 0으로 초기화
    int numbers2[10] = { 1, 2, 3, 4, 5 };               // 명시된 요소 외의 나머지는 0으로 초기화
    int numbers3[] = { 1, 23, 4, 5, 6, 2, 333, 32 };    // 데이터 개수에 맞게 배열 크기가 자동 지정됨

    // 7. 문자열 배열 초기화
    // C스타일 문자열 배열의 마지막에는 반드시 문자열의 끝을 알리는 널 문자('\0')가 포함되어야 함
    char helloStr[] = { 'H', 'e', 'l', 'l', 'o', '\0' };

    return 0;
}
```

## 2. 이론 정리 (Study Notes)

배열은 다수의 동일한 데이터를 논리적이고 연속적인 메모리 공간에 배치하여 관리 효율성을 높이는 기초 자료구조임

### 배열(Array)의 주요 특성

| 특성 | 세부 설명 | 비고 |
| :--- | :--- | :--- |
| **메모리 연속성** | 모든 데이터가 메모리상에 빈틈없이 일렬로 배치됨 | 캐시 지역성(Cache Locality)이 우수하여 탐색 속도가 빠름 |
| **정적 할당** | 선언 시점에 크기가 고정되며, 실행 도중 크기를 변경할 수 없음 | 동적 확장이 필요한 경우 힙(Heap) 동적 할당을 사용해야 함 |
| **인덱스 접근** | 시작 주소로부터의 오프셋(Offset)을 계산하여 임의 접근(Random Access) 지원 | 시간 복잡도 $O(1)$ 보장 |

### 포인터 연산과 인덱스의 관계 수식

컴파일러는 개발자가 작성한 배열 인덱스 연산 `A[i]`를 내부적으로 포인터 산술 연산으로 변환하여 처리함
배열의 시작 주소(Base Address)를 기준으로 $i$번째 요소의 실제 메모리 주소를 계산하는 수식은 다음과 같음

$$\text{Address}(A[i]) = \text{Base Address} + (i \times \text{sizeof}(\text{Type}))$$

이러한 메모리 이동 원리 때문에 `A[i]`와 `*(A + i)`는 어셈블리 관점에서 완벽하게 동일한 명령어로 번역됨

## 3. 종합 의견 (Review)

### 핵심 요약 및 주의사항

* **상수 크기 지정**: C++ 표준에서 정적 배열의 크기는 반드시 컴파일 타임에 결정되는 리터럴 또는 상수(`const`, `constexpr`)여야 하며, 변수를 사용한 동적 크기 지정(VLA)은 표준을 위반하므로 주의해야 함
* **Out of Bounds 위험**: C/C++은 배열의 인덱스가 유효 범위를 벗어났는지(Bounds Checking) 런타임에 검사하지 않으므로, 잘못된 인덱스 접근 시 치명적인 메모리 오염(Memory Corruption)이나 세그멘테이션 폴트를 유발함
* **배열의 붕괴(Array Decay)**: 배열의 이름을 함수 매개변수로 전달하면 배열의 전체 크기 정보는 소실되고 오직 첫 번째 요소의 시작 주소(`Type*`)만 전달됨

### Tip

* **가독성을 위한 인덱스 사용**: 포인터 덧셈 연산 `*(arr + i)`를 직접 사용하는 것보다, 논리적으로 직관적인 인덱스 연산 `arr[i]`를 사용하는 것이 코드 가독성과 유지보수에 압도적으로 유리함
* **모던 C++ 컨테이너 권장**: 실무에서는 원시적인 C스타일 배열(`T arr[]`)의 한계와 포인터 붕괴 위험성을 극복하기 위해, 크기를 알 수 있고 경계 검사가 가능한 `std::array`(정적 크기) 또는 `std::vector`(동적 크기)의 사용을 최우선으로 고려해야 함
* **참조자 기반 순회**: 배열의 요소를 반복문으로 순회할 때 값을 복사하지 않고 원본을 직접 수정하려면 `for (auto& item : arr)` 형태의 범위 기반 for문(Range-based for loop)을 적극 활용하는 것이 좋음
