# [C++] 함수 호출은 제어권과 실행 문맥을 옮긴다
함수 호출 시 메모리 스택(Stack) 영역에 생성되는 스택 프레임의 개념과 데이터 처리 원리 분석

## 호출 전후의 값 추적하기

```cpp
#include <iostream>
using namespace std;

// 곱셈 연산을 수행하고 결과를 반환하는 함수
// 호출 시 매개변수 a, b와 지역 변수 c가 스택 프레임에 할당됨
int Mul(int a, int b)
{
    int c = a * b;
    return c;
}

int main()
{
    // main 함수의 지역 변수 선언 (main의 스택 프레임에 할당됨)
    int a = 4;
    int b = 2;

    // Mul 함수 호출 (제어권 이동 및 새로운 스택 프레임 생성)
    Mul(a, b);

    return 0;
}
```
---
## 호출 프레임에 담길 수 있는 정보

프로그램 실행 중 함수가 호출될 때 메모리의 스택(Stack) 영역에 할당되는 독립적인 공간을 **스택 프레임(Stack Frame)**이라고 하고,
함수의 실행이 완료되어 호출자에게 제어권을 반환하면 해당 함수의 스택 프레임은 메모리에서 자동으로 소멸

| 구성 요소 | 역할 및 특징 |
| :--- | :--- |
| **매개변수 (Parameters)** | 함수 호출 시 외부로부터 전달되는 인자(Argument) 값을 저장함 |
| **반환 주소 (Return Address)** | 함수 실행이 완료된 후 되돌아갈 호출자(Caller)의 코드 메모리 주소를 기록함 |
| **지역 변수 (Local Variables)** | 함수 내부에서 선언된 변수로, 함수 종료 시 스택 프레임과 함께 소멸함 |

**수식 표현:**

많은 환경에서 스택은 높은 주소에서 낮은 주소로 확장되지만 C++ 표준이 방향이나 구체적인 배치를 보장하지는 않는다.
함수 호출 시 새로운 스택 프레임을 구성하기 위해 스택 포인터($SP$)가 필요한 메모리 크기($Size$)만큼 이동하며 다음과 같이 표현
$$SP_{new} = SP_{old} - Size$$
함수 종료 시 호출 규약에 따라 호출자의 실행 문맥을 복원한다. 최적화된 코드는 프레임 포인터를 생략하거나 함수를 인라인해 별도 프레임을 만들지 않을 수도 있다.


## 디버거의 호출 스택과 최적화

### 핵심 요약 및 주의사항

* 함수가 호출될 때마다 고유한 스택 프레임이 생성되므로, 이름이 같은 지역 변수라도 다른 함수에 속해 있다면 완전히 독립된 메모리 공간을 가짐
* 개념적으로 호출은 중첩되지만 실제 프레임의 형태는 ABI와 최적화에 따라 달라진다.
* 재귀 함수(Recursive Function)를 구현할 때 명확한 탈출 조건(Base Case)이 없으면 스택 프레임이 무한히 쌓여 스택 메모리 한계를 초과하는 **스택 오버플로우(Stack Overflow)** 에러가 발생

### Tip

* 함수를 호출하고 스택 프레임을 생성/소멸하는 과정에는 CPU 레지스터 백업 등의 오버헤드(Overhead)가 발생
* `inline` 키워드는 주로 여러 번 정의 가능한 함수의 ODR 규칙과 관련된다. 실제 인라인 최적화 여부는 컴파일러가 판단하므로 호출 제거를 보장하지 않는다.
* 작은 타입은 값 전달이 단순하고 빠를 수 있다. 큰 객체를 읽기만 한다면 `const T&`를 고려하지만, 참조가 항상 더 빠르다고 단정하지 말고 객체 크기와 소유 관계를 함께 본다.

## 마무리

스택 프레임은 함수 호출을 이해하는 좋은 모델이지만 C++ 문법 자체가 특정 레지스터와 메모리 배치를 보장하지는 않는다. 디버거의 호출 스택은 흐름을 추적하는 도구로 사용하고, 실제 배치가 필요할 때는 대상 플랫폼의 ABI와 생성된 코드를 확인한다.
