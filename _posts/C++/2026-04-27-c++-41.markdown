정수는 `+`로 더하고 `==`로 비교할 수 있다. 직접 만든 `Position` 타입도 두 위치의 좌표를 더하거나 같은 위치인지 비교하는 연산이 자연스럽다면 같은 표기법을 제공할 수 있다.

연산자 오버로딩(Operator overloading)은 새로운 연산자 문법을 만드는 기능이 아니다. 기존 연산자가 사용자 정의 타입을 만났을 때 호출할 함수를 정의하는 기능이다. 문법을 짧게 만드는 것보다 그 연산이 타입의 의미와 잘 맞는지가 먼저다.

## 연산자 표현식은 함수 호출로 연결된다

`Position`에 멤버 `operator+`를 정의할 수 있다.

```cpp
class Position
{
public:
    Position operator+(const Position& other) const;
};
```

다음 두 표현은 같은 연산자 함수를 가리킨다.

```cpp
Position result = left + right;
Position sameResult = left.operator+(right);
```

이항 연산자를 멤버 함수로 만들면 왼쪽 피연산자는 호출 객체인 `*this`, 오른쪽 피연산자는 함수의 매개변수가 된다.

```text
left + right
left.operator+(right)
```

연산자 표기법을 사용할 때도 일반 함수와 마찬가지로 오버로드 해석을 통해 매개변수에 맞는 함수를 찾는다.

## 값처럼 동작하는 연산은 원본을 변경하지 않는다

두 위치를 더해 새로운 위치를 만든다면 일반적인 `+`의 기대처럼 양쪽 원본을 변경하지 않는 편이 자연스럽다.

```cpp
Position Position::operator+(const Position& other) const
{
    return Position{x_ + other.x_, y_ + other.y_};
}
```

오른쪽 피연산자는 읽기만 하므로 `const Position&`로 받고, 왼쪽 객체도 변경하지 않으므로 함수 뒤에 `const`를 붙인다. 결과는 새로운 값이므로 값으로 반환한다.

```cpp
Position left{1, 2};
Position right{3, 4};
Position result = left + right;
```

연산 후에도 `left`는 `(1, 2)`, `right`는 `(3, 4)`이고 `result`가 `(4, 6)`이 된다.

## 상태를 바꾸는 복합 대입은 자기 자신을 참조로 반환한다

`+=`는 왼쪽 피연산자의 상태를 변경한다.

```cpp
Position& Position::operator+=(const Position& other)
{
    x_ += other.x_;
    y_ += other.y_;
    return *this;
}
```

결과로 변경된 자기 자신을 참조 반환하면 일반적인 복합 대입처럼 연속해서 사용할 수 있다.

```cpp
Position total{0, 0};
Position first{1, 2};
Position second{3, 4};

total += first;
(total += second) += first;
```

`+`와 `+=`의 로직을 각각 구현하면 좌표 계산 규칙이 중복된다. 비멤버 `operator+`가 왼쪽 값을 복사한 뒤 `+=`를 호출하게 만들 수 있다.

```cpp
Position operator+(Position left, const Position& right)
{
    left += right;
    return left;
}
```

`left`는 값으로 받은 복사본이므로 변경해도 호출자의 원본에는 영향을 주지 않는다. 실제 덧셈 규칙은 `operator+=` 한곳에만 존재한다.

## 멤버 함수와 비멤버 함수는 왼쪽 피연산자에서 차이가 난다

멤버 연산자는 왼쪽 피연산자가 해당 클래스 객체여야 한다.

```cpp
Position Position::operator+(int offset) const;
```

이 선언은 다음 표현식을 처리할 수 있다.

```cpp
Position moved = position + 3;
```

하지만 `3 + position`에서는 왼쪽 피연산자가 `int`라서 `Position`의 멤버 함수를 호출할 수 없다. 양쪽 순서를 모두 자연스럽게 지원하려면 비멤버 함수를 제공할 수 있다.

```cpp
Position operator+(Position position, int offset)
{
    return Position{position.X() + offset, position.Y() + offset};
}

Position operator+(int offset, Position position)
{
    return position + offset;
}
```

두 번째 함수는 첫 번째 구현을 재사용한다. 교환 가능한 연산이라면 피연산자의 양쪽 변환 기회를 대칭적으로 제공하기 위해 비멤버 연산자가 유용하다.

모든 연산자를 비멤버로 만들 수 있는 것은 아니다. `operator=`, `operator[]`, `operator()`, `operator->`와 변환 함수 등은 멤버 함수로 정의해야 한다.

## 비멤버 연산자가 항상 friend일 필요는 없다

비멤버 함수는 클래스의 `private` 멤버에 직접 접근할 수 없다. 그래서 연산자를 무조건 `friend`로 선언해야 한다고 생각하기 쉽다.

공개 인터페이스만으로 구현할 수 있다면 `friend`가 필요 없다.

```cpp
Position operator+(Position left, const Position& right)
{
    left += right;
    return left;
}
```

이 함수는 공개된 `operator+=`만 사용한다. 출력 연산자도 좌표 읽기 함수를 이용할 수 있다.

```cpp
std::ostream& operator<<(std::ostream& output, const Position& position)
{
    return output << '(' << position.X() << ", " << position.Y() << ')';
}
```

`friend`는 비멤버 함수에 비공개 멤버 접근 권한을 부여해야 할 때 선택할 수 있다. 단순히 연산자라는 이유만으로 클래스 내부 표현을 공개할 필요는 없다.

## 비교 연산자는 객체를 변경하지 않는다

두 위치의 좌표가 모두 같을 때 같은 값으로 정의한다.

```cpp
bool Position::operator==(const Position& other) const
{
    return x_ == other.x_ && y_ == other.y_;
}
```

비교 과정은 양쪽 객체를 바꾸지 않는다. 오른쪽은 `const` 참조로 받고 멤버 함수도 `const`로 선언한다.

```cpp
Position first{2, 5};
Position second{2, 5};
bool same = first == second;
```

`==`가 좌표가 같은지를 의미한다면 `!=`도 반대 결과를 내야 한다. C++20에서는 적합한 `operator==`를 바탕으로 많은 `!=` 표현식을 재작성해 처리할 수 있다. 사용하는 언어 버전과 비교 의미를 확인해 일관된 연산 집합을 제공한다.

## 대입 연산자와 생성은 구분해야 한다

선언과 동시에 값을 주는 코드는 새 객체를 만든다.

```cpp
Position copied = original;
```

이 표현은 복사 초기화이며 기존 객체에 대한 대입이 아니다. 반면 두 객체가 이미 존재한 뒤의 등호는 복사 대입이다.

```cpp
Position copied;
copied = original;
```

복사 대입 연산자의 일반적인 형태는 다음과 같다.

```cpp
Position& operator=(const Position& other);
```

현재 `Position`처럼 정수 멤버만 가진 타입은 컴파일러가 제공하는 복사 대입으로 충분하다. 호출을 관찰할 특별한 이유가 없다면 직접 작성할 필요가 없다.

원본 예제에는 정수를 두 좌표에 대입하는 `operator=(int)`도 있다.

```cpp
position = 5;
```

문법적으로 구현할 수 있지만 이 표현이 “x와 y를 모두 5로 설정한다”는 의미를 자연스럽게 전달하는지는 별개의 문제다. `Set(5, 5)`나 `Position{5, 5}`가 더 명확하다면 연산자 오버로딩을 추가하지 않는 편이 낫다.

## 전위 증가와 후위 증가는 반환 의미가 다르다

전위 증가는 값을 먼저 변경한 뒤 변경된 자기 자신을 반환한다.

```cpp
Position& Position::operator++()
{
    ++x_;
    ++y_;
    return *this;
}
```

후위 증가 연산자는 사용하지 않는 `int` 매개변수로 전위 형태와 구분한다.

```cpp
Position Position::operator++(int)
{
    Position previous = *this;
    ++(*this);
    return previous;
}
```

후위 형태는 증가 전 값을 반환해야 하므로 복사본 `previous`를 값으로 반환한다.

```text
++position  증가한 position 자신을 참조 반환
position++  증가 전 값을 복사해 반환하고 position은 증가
```

후위 구현이 전위 구현을 호출하면 실제 증가 규칙을 한곳에 유지할 수 있다.

## 연산자 오버로딩이 바꾸지 못하는 규칙도 있다

사용자 정의 연산자를 추가해도 다음 언어 규칙은 바뀌지 않는다.

- 새로운 기호를 연산자로 만들 수 없다.
- 연산자의 우선순위와 결합 방향을 바꿀 수 없다.
- 연산자가 받는 피연산자 개수를 바꿀 수 없다.
- `::`, `.`, `.*`, `?:` 같은 일부 연산자는 오버로딩할 수 없다.
- 기본 타입끼리의 연산 의미를 다시 정의할 수 없다. 피연산자 중 하나 이상은 클래스나 열거형 같은 사용자 정의 타입이어야 한다.

연산자 안에 예상하기 어려운 부수 효과를 넣으면 짧은 표기법이 오히려 코드를 이해하기 어렵게 만든다. `+`는 새 값을 만들고 `+=`는 왼쪽을 변경한다는 기존 관례처럼 독자가 예상할 수 있는 의미를 유지한다.

## 전체 구현

`Position`의 덧셈, 복합 대입, 비교와 증감 연산을 검증하는 예제다.

```cpp
#include <cassert>
#include <iostream>

class Position
{
public:
    Position() : Position(0, 0)
    {
    }

    Position(int x, int y) : x_(x), y_(y)
    {
    }

    Position& operator+=(const Position& other)
    {
        x_ += other.x_;
        y_ += other.y_;
        return *this;
    }

    bool operator==(const Position& other) const
    {
        return x_ == other.x_ && y_ == other.y_;
    }

    Position& operator++()
    {
        ++x_;
        ++y_;
        return *this;
    }

    Position operator++(int)
    {
        Position previous = *this;
        ++(*this);
        return previous;
    }

    int X() const
    {
        return x_;
    }

    int Y() const
    {
        return y_;
    }

private:
    int x_;
    int y_;
};

Position operator+(Position left, const Position& right)
{
    left += right;
    return left;
}

Position operator+(Position position, int offset)
{
    return Position{position.X() + offset, position.Y() + offset};
}

Position operator+(int offset, Position position)
{
    return position + offset;
}

std::ostream& operator<<(std::ostream& output, const Position& position)
{
    return output << '(' << position.X() << ", " << position.Y() << ')';
}

void VerifyPosition()
{
    Position left{1, 2};
    Position right{3, 4};

    Position sum = left + right;
    assert(sum == Position(4, 6));
    assert(left == Position(1, 2));
    assert(right == Position(3, 4));

    Position shiftedRight = sum + 2;
    Position shiftedLeft = 2 + sum;
    assert(shiftedRight == Position(6, 8));
    assert(shiftedLeft == shiftedRight);

    Position& prefixResult = ++left;
    assert(&prefixResult == &left);
    assert(left == Position(2, 3));

    Position previous = left++;
    assert(previous == Position(2, 3));
    assert(left == Position(3, 4));

    std::cout << "sum: " << sum << '\n';
    std::cout << "current left: " << left << '\n';
}

int main()
{
    VerifyPosition();
}
```

실행 결과는 다음과 같다.

```text
sum: (4, 6)
current left: (3, 4)
```

`left + right`는 원본을 유지하고 새 좌표를 만든다. `++left`는 증가한 원본의 참조를 반환하고, `left++`는 증가 전 좌표를 복사해서 반환한다.

## 연산자를 설계할 때 확인할 기준

1. 해당 연산이 타입의 의미와 자연스럽게 연결되는가?
2. `+`와 `==`처럼 값을 관찰하는 연산이 원본을 변경하지 않는가?
3. `+=`와 대입처럼 상태를 변경하는 연산이 자기 자신을 참조 반환하는가?
4. 관련 연산자들이 서로 모순되지 않는 의미를 가지는가?
5. 공통 로직을 복합 대입이나 전위 연산에 모아 재사용할 수 있는가?
6. 왼쪽 피연산자의 타입과 암시적 변환을 고려해 멤버·비멤버 방식을 선택했는가?
7. 공개 인터페이스로 구현할 수 있는데 불필요하게 `friend`를 사용하지 않았는가?
8. 컴파일러가 제공하는 복사 대입으로 충분한 타입에 직접 구현을 추가하지 않았는가?
9. 함수 호출보다 의미가 불명확한 연산자 오버로딩을 만들고 있지 않은가?

연산자 오버로딩의 목표는 코드를 최대한 짧게 만드는 것이 아니다. 기본 타입에서 익숙한 연산의 의미를 사용자 정의 타입에서도 일관되게 표현해 코드를 자연스럽게 읽을 수 있도록 만드는 것이다.
