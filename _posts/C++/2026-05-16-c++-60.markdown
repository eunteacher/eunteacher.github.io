`std::vector`는 요소를 연속된 저장 공간에 배치한다. 인덱스로 빠르게 접근하고 순회할 때 캐시를 효율적으로 사용할 수 있지만, 중간에 요소를 삽입하거나 삭제하면 뒤쪽 요소를 이동해야 한다.

`std::list`는 각 요소를 독립적인 노드로 관리하는 연결 기반 컨테이너다. C++ 표준의 `list`는 양방향 연결 리스트의 성질을 제공하며, 특정 노드의 위치를 반복자로 이미 알고 있다면 주변 연결만 바꿔 삽입과 삭제를 수행할 수 있다.

중요한 조건은 **위치를 이미 알고 있을 때**다. 리스트는 임의 접근을 지원하지 않으므로 몇 번째 요소를 먼저 찾아야 한다면 탐색 비용이 추가된다.

## list는 요소를 연속해서 저장하지 않는다

개념적으로 각 노드는 값과 앞뒤 노드의 위치를 가진다.

```text
      ┌─────────┐    ┌─────────┐    ┌─────────┐
... ←│ 10      │←──→│ 20      │←──→│ 30      │→ ...
      └─────────┘    └─────────┘    └─────────┘
```

노드들이 메모리에서 서로 붙어 있을 필요는 없다. 하나의 노드를 삽입할 때 기존 요소 전체를 옮기는 대신 앞뒤 노드의 연결을 조정한다.

표준이 구현 내부의 구체적인 노드 타입이나 센티널 구조까지 공개하는 것은 아니다. `end()`를 표현하기 위해 머리 노드 같은 내부 구조를 사용하는 구현이 흔하지만, 프로그램이 그 모양에 의존해서는 안 된다.

## vector와 list는 강점이 다르다

두 컨테이너의 대표적인 차이는 다음과 같다.

| 기준 | `std::vector` | `std::list` |
|---|---|---|
| 저장 형태 | 연속 저장 | 노드 연결 |
| 인덱스 접근 | O(1) | 지원하지 않음 |
| 순회 | 캐시 지역성이 좋음 | 노드를 따라 이동 |
| 끝 삽입 | 분할 상환 O(1) | O(1) |
| 앞 삽입 | O(n) | O(1) |
| 중간 삽입·삭제 | 위치를 알아도 O(n) 이동 가능 | 위치를 알면 O(1) |
| 요소당 추가 공간 | 여유 capacity | 연결 정보와 할당 관리 비용 |
| 재할당 | 용량 부족 시 발생 | 컨테이너 전체 재할당 없음 |

`list`의 O(1) 삽입이 언제나 `vector`보다 실제 실행 시간이 짧다는 뜻은 아니다. 노드별 메모리 할당, 포인터 추적과 낮은 캐시 지역성 때문에 요소 수와 작업 패턴에 따라 벡터가 더 빠를 수 있다.

특별한 요구가 없다면 연속 저장과 단순한 메모리 구조를 가진 `vector`를 먼저 고려하고, 리스트의 반복자 안정성이나 연결 변경 기능이 실제로 필요할 때 `list`를 선택한다.

## 앞과 뒤에서 요소를 추가하고 제거한다

리스트는 양쪽 끝 삽입과 삭제를 지원한다.

```cpp
std::list<int> values;

values.push_back(20);
values.push_front(10);
values.push_back(30);

assert(values.front() == 10);
assert(values.back() == 30);
```

```text
values = [10, 20, 30]
```

`pop_front()`와 `pop_back()`은 요소를 제거하지만 제거한 값을 반환하지 않는다.

```cpp
int first = values.front();
values.pop_front();

int last = values.back();
values.pop_back();
```

두 함수는 리스트가 비어 있지 않을 때만 호출해야 한다. `front()`와 `back()`도 빈 리스트에서는 사용할 수 없다.

## list 반복자는 한 칸씩 양방향으로 이동한다

`std::list`의 반복자는 양방향 반복자(bidirectional iterator)다. `++`로 다음 노드, `--`로 이전 노드에 이동할 수 있다.

```cpp
for (auto it = values.begin(); it != values.end(); ++it)
{
    std::cout << *it << ' ';
}
```

벡터 반복자처럼 정수를 더해 한 번에 이동할 수는 없다.

```cpp
auto it = values.begin();
// it += 3; // list 반복자는 임의 접근을 지원하지 않음
```

세 번째 요소로 이동하려면 앞에서부터 반복해서 증가시킨다.

```cpp
auto third = values.begin();
std::advance(third, 2);
```

`std::advance`가 문법을 간단하게 만들 뿐 리스트에서 두 칸을 건너뛰는 특별한 지름길이 생기는 것은 아니다. 이동한 거리만큼 노드 연결을 따라간다.

## begin과 end의 경계를 넘지 않는다

`begin()`은 첫 요소를 가리키고 `end()`는 마지막 요소 다음의 경계를 나타낸다. `end()`는 실제 요소가 아니므로 역참조할 수 없다.

리스트가 비어 있지 않다면 `end()`를 한 번 감소시켜 마지막 요소에 도달할 수 있다.

```cpp
auto last = values.end();
--last;
assert(*last == values.back());
```

반대로 `end()`를 증가시키거나 `begin()`을 감소시키면 유효 범위를 벗어난다.

```cpp
// ++values.end();   // 잘못된 이동
// --values.begin(); // 잘못된 이동
```

빈 리스트에서는 `begin() == end()`이므로 `--end()`도 사용할 수 없다.

원본 코드의 다음 포인터는 각각 첫 요소와 마지막 요소를 가리킬 뿐 반복자 경계를 표현하지 않는다.

```cpp
int* firstElement = &values.front();
int* lastElement = &values.back();
```

특히 `lastElement`를 `end` 포인터라고 부르면 안 된다. `end()`는 역참조할 수 없는 경계지만 `&values.back()`은 실제 마지막 요소의 주소다.

## 위치를 알고 있다면 insert와 erase는 O(1)이다

삽입 위치를 가리키는 반복자가 있다면 `insert`는 그 위치 앞에 새 요소를 추가하고 새 요소를 가리키는 반복자를 반환한다.

```cpp
std::list<int> values{10, 20, 40};
auto position = values.begin();
std::advance(position, 2);

auto inserted = values.insert(position, 30);
assert(*inserted == 30);
```

```text
values = [10, 20, 30, 40]
```

`erase`는 반복자가 가리키는 요소를 제거하고 그 다음 요소를 가리키는 반복자를 반환한다.

```cpp
auto next = values.erase(inserted);
assert(*next == 40);
```

노드 하나의 앞뒤 연결만 변경하므로 단일 요소 삽입과 삭제 자체는 O(1)이다. 하지만 `position`을 찾기 위해 처음부터 이동했다면 탐색은 O(n)이다.

```text
50번째 요소 삭제

begin에서 50번째 위치 탐색 : O(n)
찾은 노드의 연결 해제      : O(1)
전체 과정                  : O(n)
```

“리스트의 중간 삭제는 빠르다”보다 “삭제할 노드의 반복자를 이미 가지고 있다면 삭제 자체가 빠르다”가 정확한 설명이다.

## 삽입은 기존 반복자를 무효로 만들지 않는다

리스트는 새 노드를 별도로 추가하므로 기존 노드가 이동하지 않는다. `insert`, `push_front`, `push_back`을 수행해도 기존 요소를 가리키는 반복자와 참조는 계속 유효하다.

```cpp
std::list<int> values{10, 20, 30};
auto twenty = std::next(values.begin());
int* address = &*twenty;

values.push_front(5);
values.insert(twenty, 15);

assert(*twenty == 20);
assert(&*twenty == address);
```

삭제에서는 **삭제된 요소를 가리키는 반복자와 참조만** 무효가 된다. 다른 노드의 반복자는 유지된다.

```cpp
auto thirty = std::next(twenty);
values.erase(twenty);

// twenty는 삭제된 요소를 가리켰으므로 더 이상 사용하지 않음
assert(*thirty == 30);
```

`clear()`는 모든 요소를 삭제하므로 모든 요소 반복자와 참조가 무효가 된다. 반복자 안정성이 좋다는 설명을 “어떤 삭제 뒤에도 반복자가 모두 유효하다”로 오해하면 안 된다.

## 순회 중 삭제할 때도 erase의 반환값을 사용한다

조건에 맞는 요소를 순회하면서 삭제할 때는 벡터와 마찬가지로 `erase`가 반환한 다음 위치를 받는다.

```cpp
for (auto it = values.begin(); it != values.end();)
{
    if (*it % 2 == 0)
    {
        it = values.erase(it);
    }
    else
    {
        ++it;
    }
}
```

리스트에서는 다른 요소의 반복자가 유지되지만, 방금 삭제한 노드를 가리키던 `it` 자체는 무효다. 반환값을 받지 않고 그 반복자를 증가시킬 수 없다.

특정 값과 같은 모든 요소를 지우려면 `remove`를 사용할 수 있다.

```cpp
values.remove(10);
```

`remove`는 첫 번째 요소만 지우는 함수가 아니라 값이 같은 요소를 모두 검사해 삭제한다. 전체 리스트를 순회하므로 O(n)이다. 조건 기반 삭제에는 `remove_if`를 사용할 수 있다.

## splice는 노드를 복사하지 않고 연결을 옮긴다

`list`의 특징적인 기능인 `splice`는 한 리스트의 노드를 다른 리스트로 옮긴다.

```cpp
std::list<int> active{10, 20};
std::list<int> waiting{30, 40};
auto moved = waiting.begin();

active.splice(active.end(), waiting, moved);

assert(*moved == 30);
assert(waiting.front() == 40);
assert(active.back() == 30);
```

요소 값을 복사하거나 이동하는 대신 노드의 연결을 변경한다. 옮겨진 요소를 가리키던 반복자와 참조는 유효하며 이제 목적지 리스트의 요소를 가리킨다.

서로 다른 리스트 사이의 `splice`에는 allocator 호환 조건이 있다. 기본 `std::allocator`를 사용하는 같은 타입의 일반적인 리스트에서는 자연스럽게 사용할 수 있지만, 사용자 지정 allocator를 쓴다면 전제 조건을 확인해야 한다.

## list가 항상 좋은 선택은 아니다

리스트 노드는 값 외에도 앞뒤 연결 정보가 필요하고 일반적으로 노드마다 별도의 할당 관리 비용이 든다. 순회할 때 다음 노드의 주소를 따라가므로 벡터보다 캐시 지역성이 떨어질 수 있다.

다음 조건이 실제로 중요할 때 리스트가 후보가 된다.

- 요소 중간의 위치를 반복자로 오래 보관한다.
- 그 위치에서 삽입과 삭제를 자주 수행한다.
- 다른 노드를 삽입해도 기존 요소의 반복자와 참조가 유지돼야 한다.
- `splice`로 노드를 복사 없이 다른 리스트에 옮기고 싶다.

반대로 인덱스 접근, 빠른 전체 순회, 작은 메모리 오버헤드가 중요하다면 `vector`가 더 자연스럽다. 요소가 많고 중간 삭제가 있다는 이유만으로 바로 `list`를 선택하지 않고 탐색 방식과 실제 접근 패턴을 함께 본다.

## 전체 구현

반복자 안정성, `erase` 반환값과 `splice`의 노드 이동을 확인한다.

```cpp
#include <cassert>
#include <iostream>
#include <iterator>
#include <list>

void VerifyStableIterator()
{
    std::list<int> values{10, 20, 30, 40};
    auto thirty = std::next(values.begin(), 2);
    int* address = &*thirty;

    values.push_front(5);
    auto inserted = values.insert(thirty, 25);

    assert(*thirty == 30);
    assert(&*thirty == address);
    assert(*inserted == 25);

    auto next = values.erase(thirty);

    // thirty는 무효가 됐지만 다른 노드의 반복자는 그대로 유효하다.
    assert(*inserted == 25);
    assert(*next == 40);

    std::cout << "Values after insert and erase:";

    for (int value : values)
    {
        std::cout << ' ' << value;
    }

    std::cout << '\n';
}

void VerifySplice()
{
    std::list<int> active{10, 20};
    std::list<int> waiting{30, 40};
    auto moved = waiting.begin();
    int* address = &*moved;

    active.splice(active.end(), waiting, moved);

    assert(*moved == 30);
    assert(&*moved == address);
    assert(active.back() == 30);
    assert(waiting.front() == 40);

    std::cout << "Active after splice:";

    for (int value : active)
    {
        std::cout << ' ' << value;
    }

    std::cout << '\n';
    std::cout << "Waiting after splice:";

    for (int value : waiting)
    {
        std::cout << ' ' << value;
    }

    std::cout << '\n';
}

void VerifyEraseWhileIterating()
{
    std::list<int> values{1, 2, 3, 4, 5, 6};

    for (auto it = values.begin(); it != values.end();)
    {
        if (*it % 2 == 0)
        {
            it = values.erase(it);
        }
        else
        {
            ++it;
        }
    }

    assert(values.size() == 3);

    std::cout << "Odd values:";

    for (int value : values)
    {
        std::cout << ' ' << value;
    }

    std::cout << '\n';
}

int main()
{
    VerifyStableIterator();
    VerifySplice();
    VerifyEraseWhileIterating();
}
```

실행 결과는 다음과 같다.

```text
Values after insert and erase: 5 10 20 25 40
Active after splice: 10 20 30
Waiting after splice: 40
Odd values: 1 3 5
```

`thirty` 앞에 요소를 삽입하고 리스트 앞에도 새 요소를 추가했지만 `thirty`의 값과 주소는 유지된다. `thirty`를 삭제한 뒤에는 해당 반복자를 더 이상 사용하지 않고 `erase`가 반환한 `next`로 다음 값 40을 확인한다.

`splice`에서는 값 30을 가진 노드가 `waiting`에서 `active`로 이동한다. 이동 전후 주소가 같고 기존 반복자 `moved`도 계속 그 노드를 가리킨다. 마지막 예제에서는 삭제 시마다 반환된 다음 반복자로 순회를 이어가 홀수만 남긴다.

## list를 사용할 때 확인할 기준

1. 임의 접근이 필요하지 않은가?
2. 삽입·삭제할 위치를 반복자로 이미 알고 있는가?
3. 위치 탐색 O(n)까지 포함한 전체 비용을 계산했는가?
4. 노드별 메모리와 할당 비용보다 반복자 안정성이 더 중요한가?
5. 삭제된 요소의 반복자는 무효라는 점을 지키는가?
6. `end()`와 마지막 요소의 주소를 혼동하지 않는가?
7. 순회 중 삭제할 때 `erase`의 반환값을 받는가?
8. `remove`가 값이 같은 모든 요소를 순회하며 삭제한다는 점을 아는가?
9. 노드를 다른 리스트로 옮길 때 `splice`가 요구사항에 맞는가?
10. 단순히 중간 삭제가 있다는 이유만으로 `vector`의 캐시 효율을 포기하지 않았는가?

`std::list`의 핵심은 “삽입과 삭제가 무조건 빠른 컨테이너”가 아니다. 노드 위치를 이미 알고 있을 때 요소를 이동하지 않고 연결만 변경할 수 있고, 그 대가로 임의 접근과 연속 저장의 장점을 포기하는 컨테이너다.
