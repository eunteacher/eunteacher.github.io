`Knight`와 `Mage`가 모두 체력, 공격력, 방어력과 공격 기능을 가진다면 각 클래스에 같은 코드를 반복할 수 있다. 상속(Inheritance)을 사용하면 공통 상태와 동작을 기반 클래스에 두고 각 타입의 고유한 부분만 파생 클래스에 추가할 수 있다.

하지만 코드가 비슷하다는 이유만으로 상속을 선택하면 클래스 사이의 결합만 강해질 수 있다. 이번 글에서는 `Player`와 직업 클래스의 관계를 통해 상속 문법뿐 아니라 객체가 구성되는 순서, 기반 클래스 함수와 같은 이름을 선언했을 때의 동작, 상속을 선택할 기준까지 살펴본다.

## 공통 상태를 기반 클래스에 모은다

기사와 마법사에 공통으로 필요한 상태를 `Player`에 둔다.

```cpp
class Player
{
public:
    Player();

    void Attack() const;

protected:
    int hp_;
    int attack_;
    int defense_;
};
```

`Player`를 상속하는 클래스는 클래스 이름 뒤에 기반 클래스를 적는다.

```cpp
class Knight : public Player
{
public:
    Knight();

private:
    int stamina_;
};

class Mage : public Player
{
public:
    Mage();

private:
    int mp_;
};
```

여기서 `Player`는 기반 클래스(Base class), `Knight`와 `Mage`는 파생 클래스(Derived class)다. `public` 상속은 파생 객체를 기반 타입의 한 종류로 다룰 수 있는 공개적인 관계를 표현한다.

```text
Player
├─ Knight
└─ Mage
```

`Knight`는 `Player`의 부분과 기사 고유의 부분이 합쳐진 하나의 객체다. 기반 클래스 객체가 따로 만들어져 기사 옆에 붙는 구조가 아니다.

## public 상속은 is-a 관계를 표현한다

상속을 선택할 때 먼저 다음 문장이 자연스러운지 확인한다.

```text
Knight is a Player.
Mage is a Player.
```

기사를 플레이어의 한 종류로 취급해도 의미가 유지된다면 공개 상속을 고려할 수 있다. 반대로 단순히 다른 객체를 기능 구현에 이용하는 관계라면 포함(Composition)이 더 자연스러울 수 있다.

```text
is-a 관계  → 상속 후보
has-a 관계 → 멤버 객체를 통한 포함 후보
```

코드 중복 제거는 상속의 결과일 수 있지만 그 자체가 충분한 설계 근거는 아니다. 파생 클래스가 기반 클래스가 약속한 의미를 지킬 수 있어야 한다.

## 파생 객체는 기반 클래스 부분부터 생성된다

`Knight` 객체를 생성하려면 내부의 `Player` 부분이 먼저 유효한 상태가 되어야 한다.

```cpp
Player::Player() : hp_(100), attack_(10), defense_(5)
{
    std::cout << "Player()\n";
}

Knight::Knight() : stamina_(50)
{
    std::cout << "Knight()\n";
}
```

`Knight knight;`를 실행하면 생성 순서는 다음과 같다.

```text
Player() → Knight()
```

파생 생성자 본문이 실행되기 전에 기반 클래스 생성자가 끝나야 한다. 그래야 파생 생성자에서 이미 만들어진 기반 클래스 부분을 안전하게 사용할 수 있다.

소멸 순서는 반대다.

```text
~Knight() → ~Player()
```

파생 클래스가 자신의 부분을 먼저 정리하고 마지막에 기반 클래스 부분의 수명이 끝난다. 생성자와 소멸자 안에서 기반 부분을 직접 먼저 만들거나 나중에 제거하는 코드를 작성하는 것이 아니라 언어가 이 순서를 보장한다.

## 기반 생성자는 초기화 목록에서 선택한다

파생 생성자가 기반 클래스에 특정 값을 전달해야 할 수 있다.

```cpp
class Player
{
public:
    Player();
    Player(int hp, int attack, int defense);
};

class Knight : public Player
{
public:
    explicit Knight(int stamina);
};
```

기반 생성자는 파생 생성자의 멤버 초기화 목록에서 선택한다.

```cpp
Knight::Knight(int stamina) : Player(150, 20, 8), stamina_(stamina)
{
    std::cout << "Knight(int)\n";
}
```

`Player(150, 20, 8)`이 기반 클래스 부분을 초기화하고 `stamina_(stamina)`가 기사 고유 멤버를 초기화한다. 실제 초기화 순서는 목록에 적은 순서가 아니라 다음 구조적 순서를 따른다.

```text
1. 기반 클래스
2. 파생 클래스의 멤버 선언 순서
3. 파생 클래스 생성자 본문
```

기반 생성자를 명시하지 않으면 호출할 수 있는 기반 클래스의 기본 생성자를 사용한다. 기반 클래스에 기본 생성자가 없다면 파생 생성자가 사용할 기반 생성자를 반드시 지정해야 한다.

```cpp
class Player
{
public:
    Player(int hp, int attack, int defense);
};

class Knight : public Player
{
public:
    Knight() : Player(100, 10, 5), stamina_(50)
    {
    }

private:
    int stamina_;
};
```

파생 생성자 본문에서 `hp_ = 100;`처럼 값을 대입하는 것은 기반 클래스 생성자를 선택하는 일이 아니다. 그 시점에는 기반 부분의 초기화가 이미 끝났다.

## 접근 지정자는 파생 클래스가 볼 수 있는 범위를 정한다

원본 예제는 학습을 위해 모든 멤버를 `public`으로 공개한다. 그러면 외부 코드도 값을 자유롭게 바꿀 수 있다.

```cpp
Knight knight;
knight.hp_ = -100;
```

이 방식은 객체가 지켜야 할 상태 조건을 우회한다. 실제 클래스에서는 데이터 멤버를 외부에 공개하기보다 필요한 동작을 통해 변경하도록 만드는 편이 안전하다.

```cpp
class Player
{
public:
    int Hp() const;
    void TakeDamage(int damage);

protected:
    int hp_;

private:
    int accountId_;
};
```

접근 범위는 다음처럼 구분된다.

```text
public    클래스 외부와 파생 클래스에서 접근 가능
protected 해당 클래스와 파생 클래스에서 접근 가능
private   해당 클래스의 멤버와 친구만 접근 가능
```

`protected`는 파생 클래스에 구현 세부 사항을 노출하므로 무조건적인 기본 선택은 아니다. 기반 클래스가 제공하는 `protected` 또는 `public` 멤버 함수를 통해 상태를 다루면 내부 표현을 변경하기 쉽다. 은닉성은 다음 글에서 더 자세히 다룬다.

## 같은 이름의 함수는 자동으로 다형적 재정의되지 않는다

원본 코드에는 기반 클래스와 파생 클래스에 각각 `Move`가 있다.

```cpp
class Player
{
public:
    void Move() const;
};

class Knight : public Player
{
public:
    void Move() const;
};
```

`Knight` 객체에서 `Move`를 호출하면 이름 탐색 과정에서 파생 클래스의 함수가 선택된다.

```cpp
Knight knight;
knight.Move();
```

하지만 기반 클래스의 `Move`가 `virtual`이 아니므로 이것을 런타임 다형성에 의한 재정의라고 보기는 어렵다. 파생 클래스의 선언이 기반 클래스의 같은 이름을 가리는 이름 숨김(Name hiding)에 가깝다.

기반 클래스 함수를 직접 지정할 수도 있다.

```cpp
knight.Player::Move();
```

기반 타입의 참조로 같은 객체를 바라보면 기반 클래스 함수가 호출된다.

```cpp
Player& player = knight;
player.Move();
```

```text
knight.Move()  → Knight::Move()
player.Move()  → Player::Move()
```

객체의 실제 타입에 따라 런타임에 함수를 선택하려면 기반 함수를 `virtual`로 선언하고 파생 함수에 `override`를 붙여야 한다. 가상 함수와 다형성은 이후 별도 글에서 다룬다.

## 전체 구현

생성·소멸 순서와 일반 멤버 함수의 이름 숨김을 한 번에 확인하는 예제다.

```cpp
#include <algorithm>
#include <cassert>
#include <iostream>

class Player
{
public:
    Player();
    Player(int hp, int attack, int defense);
    ~Player();

    void Move() const;
    void Attack() const;
    int Hp() const;

protected:
    int hp_;
    int attack_;
    int defense_;
};

class Knight : public Player
{
public:
    Knight();
    explicit Knight(int stamina);
    ~Knight();

    void Move() const;
    int Stamina() const;

private:
    int stamina_;
};

class Mage : public Player
{
public:
    Mage();
    ~Mage();

    int Mp() const;

private:
    int mp_;
};

Player::Player() : Player(100, 10, 5)
{
    std::cout << "Player()\n";
}

Player::Player(int hp, int attack, int defense) : hp_(std::max(0, hp)), attack_(std::max(0, attack)), defense_(std::max(0, defense))
{
    std::cout << "Player(int, int, int)\n";
}

Player::~Player()
{
    std::cout << "~Player()\n";
}

void Player::Move() const
{
    std::cout << "Player::Move()\n";
}

void Player::Attack() const
{
    std::cout << "Attack: " << attack_ << '\n';
}

int Player::Hp() const
{
    return hp_;
}

Knight::Knight() : Player(120, 15, 8), stamina_(50)
{
    std::cout << "Knight()\n";
}

Knight::Knight(int stamina) : Player(150, 20, 10), stamina_(std::max(0, stamina))
{
    std::cout << "Knight(int)\n";
}

Knight::~Knight()
{
    std::cout << "~Knight()\n";
}

void Knight::Move() const
{
    std::cout << "Knight::Move()\n";
}

int Knight::Stamina() const
{
    return stamina_;
}

Mage::Mage() : Player(80, 25, 3), mp_(100)
{
    std::cout << "Mage()\n";
}

Mage::~Mage()
{
    std::cout << "~Mage()\n";
}

int Mage::Mp() const
{
    return mp_;
}

void VerifyInheritance()
{
    Knight knight{70};
    assert(knight.Hp() == 150);
    assert(knight.Stamina() == 70);

    knight.Attack();
    knight.Move();
    knight.Player::Move();

    Player& player = knight;
    player.Move();
}

int main()
{
    VerifyInheritance();

    std::cout << "Create mage\n";
    Mage mage;
    assert(mage.Hp() == 80);
    assert(mage.Mp() == 100);
}
```

`Knight{70}`을 만들 때 `Player(int, int, int)`가 먼저 호출되고 `Knight(int)`가 이어진다. `VerifyInheritance`가 끝나면 `~Knight()`, `~Player()` 순서로 호출된다.

`knight.Move()`와 `player.Move()`의 결과가 다른 이유는 현재 예제의 함수가 가상 함수라서가 아니다. 호출 표현식의 정적 타입과 이름 탐색 결과가 다르기 때문이다.

## 상속 코드를 검토할 때 확인할 기준

1. 파생 클래스가 기반 클래스의 한 종류라는 관계가 자연스러운가?
2. 단순한 코드 중복만을 이유로 상속을 선택하지 않았는가?
3. 기반 클래스가 공통 상태와 동작에 대한 유효한 계약을 제공하는가?
4. 파생 생성자가 필요한 기반 생성자를 초기화 목록에서 선택하는가?
5. 생성은 기반 클래스부터, 소멸은 파생 클래스부터 진행된다는 점을 고려하는가?
6. 데이터 멤버를 불필요하게 `public` 또는 `protected`로 노출하지 않았는가?
7. 같은 이름의 일반 함수와 가상 함수 재정의를 혼동하지 않았는가?
8. 기반 타입을 통해 파생 객체를 사용할 때도 의미가 유지되는가?

상속은 부모의 코드를 자식이 복사해 가져오는 기능이 아니다. 파생 객체 안에 기반 클래스 부분을 구성하고, 파생 타입을 기반 타입의 한 종류로 사용할 수 있게 만드는 관계다. 따라서 문법보다 먼저 두 타입 사이에 정말 그런 관계가 존재하는지 판단해야 한다.
